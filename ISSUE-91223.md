Double-clicking the Sessions/Bots sidebar tab hides the tab strip with no way to restore it

**App:** Hermes desktop (Linux) · client v0.20.4 · repo `8794e5a` (2026-08-20)

**Steps to reproduce**
1. Open the Hermes desktop app on Linux.
2. In the left sidebar header, double-click the **Sessions** tab (two clicks within ~400 ms).
3. The entire tab strip collapses to zero height — the **Sessions**, **Bots**, and session-title tabs all disappear, and chat content jumps flush to the top edge. Double-clicking **Bots** does the same in reverse.

**Expected**
A double-click on Sessions/Bots is either inert (single-click already switches the sidebar view), or — if hiding the tab bar is intended — there must be an always-reachable way to show it again.

**Actual**
The strip is hidden with no reachable undo. The "Show header" item exists in code but renders only on the tab strip, so once the strip is gone there is nothing left to right-click to bring it back. The only recovery is opening a new session tab (Ctrl+T), which happens to reset `headerHidden`.

**Root cause**
- `apps/desktop/src/components/pane-shell/tree/renderer/tree-group.tsx` — `hideHeaderDoubleTap` → `setTreeGroupHeaderHidden(node.id, true)`
- `apps/desktop/src/components/pane-shell/tree/renderer/drag-session.ts` — `DOUBLE_TAP_MS = 400`
- `tree-group.tsx:161` — the "Show header" item, unreachable when the strip is hidden

**Proposed direction (for discussion, not a fix request)**
Make the gesture fail-closed: keep a header-restore affordance reachable even while the strip is hidden, or require an explicit confirm. Happy to open a PR if maintainers want it.
