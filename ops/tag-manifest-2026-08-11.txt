# Tag manifest -- agent-src -- 2026-08-11
#
# WHAT: every tag in this repo recorded as "<tier> <type> <tag> <sha> <date> <subject>",
#       so the tag -> commit mapping survives in COMMITTED HISTORY even if a tag ref is
#       lost. Companion in spirit to ~/.hermes/ops/salvage-tags-2026-08-10-manifest.txt
#       and ~/.hermes/ops/branch-sweep-2026-08-10-manifest.txt; agent-src had no
#       equivalent until now. Same filename shape on purpose, so a cross-repo
#       `ls ~/.hermes*/ops/*manifest*` finds all three.
#
# WHY THIS REPO NEEDS IT. agent-src HAS remotes (origin -> NousResearch/hermes-agent,
# daragao3 -> a public fork), which makes it look safer than the zero-remote ~/.hermes.
# It is not. Local `main` is diverged and nothing here is pushed. Verified 2026-08-11:
# every TAG-ONLY commit below returns "on NO remote" from `git branch -r --contains`.
# So for the tier that matters the effective durability is identical to a repo with no
# remote at all: the tag is the only thing standing between the commit and gc.
#
# THREE TIERS, classified by reachability rather than by name or age:
#   on-main    (25) commit is an ancestor of local main -> safe even if the tag is lost
#   other-ref   (5) reachable from some other branch/remote -> tag is not the sole holder
#   TAG-ONLY    (8) reachable from NOTHING but this tag -> LOAD-BEARING
#
# TAG-ONLY IS THE TIER THAT MATTERS. Those 8 tags are sole holders, and they hold more
# than 8 commits: counting ancestors, 11 commits in this repo are reachable only through
# a tag. The extra 3 are NOT tag tips and so appear in no row below -- they are held
# transitively:
#   10421ec9ee719a04e024d174b26a25473e6e0de6  "wip wip wip pluginify everything"
#       held by: merge-commit-backup, premerge-oh-god
#   7be02d11aa83bdee415848afdddd483f73c9fef0  "fix(events): add EVENT_TYPE_EMOJI icons
#                                              for all 12 DevFlow Delegation Plane types"
#       held by: archive/eventtype-coverage-guard-20260811
#   827f7f07825be57108cbea18325e8f5e9fb5d2f2  "fix(packaging): ship bundled plugin.yaml
#                                              manifests in wheel and sdist"
#       held by: v2026.5.29.2
# Do not read the 8 rows as "8 commits at risk". Deleting one tag can orphan a chain.
#
# FALSIFIER USED TO BUILD THE TIERS -- re-run it, do not trust these lines:
#     git for-each-ref --format='%(refname:short)|%(objectname)|%(*objectname)' refs/tags
#     git rev-list --no-walk <every tag commit> --not --branches --remotes
# Anything the second command prints is reachable from no branch and no remote.
# NOTE `--no-walk` does NOT suppress the walk once `--not` is present: the output
# includes ANCESTORS that are themselves unreachable, which is why it returns 11 and not
# 8. That is a feature here -- it is what surfaced the three commits listed above -- but
# it means the output is NOT a list of tag tips and must not be joined to the tag list
# as if it were. That mismatch is exactly what exposed them.

#   positive -- all four archive/eventtype-* tips must appear as TAG-ONLY   [held]
#   negative -- v2026.7.1 must NOT appear (it is an ancestor of main)       [held]
#
# RECOVER a commit whose tag was lost (object must still exist):
#     git -C ~/.hermes/agent-src tag <name> <sha>
# RECREATE a deleted branch from its archive tag:
#     git -C ~/.hermes/agent-src branch <name> archive/<topic>^{commit}
# INSPECT without restoring:
#     git -C ~/.hermes/agent-src show <sha>
#     git -C ~/.hermes/agent-src tag -n99 <tag>          # annotated tags carry rationale
#     git -C ~/.hermes/agent-src notes show <sha>        # some tips also carry a note
#
# THE archive/* TAGS ANSWER "IS THIS LANDED?" ON THEIR OWN:
#     git -C ~/.hermes/agent-src tag -l -n5 'archive/*'
