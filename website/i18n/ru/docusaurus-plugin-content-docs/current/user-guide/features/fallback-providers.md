# Резервные поставщики

Агент Hermes имеет три уровня устойчивости, которые поддерживают работу ваших сеансов, когда поставщики услуг сталкиваются с проблемами:

1. **[Пулы учетных данных](./credential-pools.md)** — чередование нескольких ключей API для *одного* провайдера (пробовано первым)
2. **Откат основной модели** — автоматически переключается на *другой* поставщик:модель при сбое основной модели.
3. **Откат вспомогательной задачи** — независимое разрешение поставщиком дополнительных задач, таких как зрение и сжатие.

Пулы учетных данных обрабатывают ротацию одного и того же поставщика (например, несколько ключей OpenRouter). На этой странице описан резервный вариант между поставщиками. Оба являются необязательными и работают независимо.

## Резервный вариант основной модели

Когда ваш основной провайдер LLM обнаруживает ошибки — ограничения скорости, перегрузку сервера, сбои аутентификации, разрывы соединения — Hermes может автоматически переключиться на резервного поставщика: пару моделей в середине сеанса, не теряя при этом разговор.

### Конфигурация

Самый простой путь — интерактивный менеджер:

```bash
hermes fallback
```

`hermes fallback` повторно использует средство выбора поставщика из `hermes model` — тот же список поставщиков, те же запросы учетных данных, та же проверка. Для управления цепочкой используйте подкоманды `add`, `list` (псевдоним `ls`), `remove` (псевдоним `rm`) и `clear`. Изменения сохраняются в списке `fallback_providers:` верхнего уровня в `config.yaml`.

Если вы предпочитаете редактировать YAML напрямую, добавьте список `fallback_providers` верхнего уровня в `~/.hermes/config.yaml`:

```yaml
fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4
```

Для каждой записи требуются как `provider`, так и `model`. Записи, в которых отсутствует какое-либо поле, игнорируются.

:::примечание `fallback_model` против `fallback_providers`
`fallback_providers` (множественное число, список) — это текущая форма конфигурации, поддерживающая несколько резервных вариантов, опробованных по порядку. `fallback_model` (единственное число) — это устаревший одинарный резервный ключ — Hermes по-прежнему учитывает его для обратной совместимости, но `hermes fallback` записывает текущий ключ `fallback_providers` и переносит устаревшую конфигурацию при записи. Если установлены оба параметра, приоритет имеет `fallback_providers`.
:::

### Пользовательский резервный вариант конечной точки

Для пользовательской конечной точки, совместимой с OpenAI, добавьте `base_url` и, при необходимости, `key_env`:

```yaml
fallback_providers:
  - provider: custom
    model: my-local-model
    base_url: http://localhost:8000/v1
    key_env: MY_LOCAL_KEY            # env var name containing the API key
```

### Когда срабатывает откат

Резервный вариант активируется автоматически в случае сбоя основной модели:

- **Ограничения скорости** (HTTP 429) — после исчерпания повторных попыток.
- **Ошибки сервера** (HTTP 500, 502, 503) — после исчерпания повторных попыток.
- **Ошибки аутентификации** (HTTP 401, 403) — немедленно (нет смысла повторять попытку).
- **Не найден** (HTTP 404) — немедленно
- **Недействительные ответы** — когда API повторно возвращает неверные или пустые ответы.

При срабатывании Гермес:

1. Разрешает учетные данные для резервного поставщика.
2. Создает новый клиент API.
3. Меняет модель, поставщика и клиента на месте.
4. Сбрасывает счетчик повторов и продолжает разговор.

Переключение происходит плавно — история разговоров, вызовы инструментов и контекст сохраняются. Агент продолжает работу с того места, на котором остановился, просто используя другую модель.

:::warning Fallback сбрасывает кэш подсказок
Кэши подсказок привязаны к модели (а у большинства провайдеров — к учетной записи), обслуживающей запрос. Когда срабатывает резервный вариант, новый поставщик:модель не имеет кэшированного префикса для вашего разговора, поэтому следующий запрос пересчитывает всю историю по полной цене входного токена вместо скидки ~75–90 % на кэширование. То же самое применимо, когда ход заканчивается и первичный сервер восстанавливается — этот первый запрос обратно на первичный сервер также является полным повторным чтением (если только срок TTL кэша первичного устройства не истек). Это неизбежно — это цена выживания в случае сбоя — но именно поэтому длительный сеанс, который переключается между поставщиками, может стоить заметно дороже, чем тот, который остается на месте.
:::

:::информация за ход, а не за сеанс
Резервное копирование осуществляется **по ходу**: каждое новое сообщение пользователя начинается с восстановления основной модели. Если основной терпит неудачу в середине хода, резервный вариант активируется только на этот ход. В следующем сообщении Гермес снова пробует использовать основной. В течение одного хода резервный вариант активируется не более одного раза — если резервный вариант также терпит неудачу, вступает в силу обычная обработка ошибок (повторные попытки, затем сообщение об ошибке). Это предотвращает каскадные циклы аварийного переключения в течение хода, в то же время давая основной модели новый шанс каждый ход.

Повторная попытка за ход учитывает **сброс**: когда учетные данные основного сообщают о времени сброса ограничения скорости, которое еще не истекло (окна подписки, такие как 5-часовые блоки Claude Pro/Max или еженедельные ограничения Кодекса, сообщают об этом как часы или дни), Гермес пропускает обреченную повторную попытку и остается в резервном режиме до тех пор, пока не пройдет сброс - избегая двух бессмысленных переключений провайдера (и двух аннулаций кэша подсказок) за ход. По истечении времени сброса следующий виток автоматически возвращается к основному. Переходные 429 без времени сброса сохраняют существующее поведение: короткое время восстановления, затем повторная попытка на каждом ходу.
:::

### Примеры

**OpenRouter как запасной вариант для Anthropic:**
```yaml
model:
  provider: anthropic
  default: claude-sonnet-4-6

fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4
```

**Nous Portal как запасной вариант для OpenRouter:**
```yaml
model:
  provider: openrouter
  default: anthropic/claude-opus-4

fallback_providers:
  - provider: nous
    model: nous-hermes-3
```

**Локальная модель как резерв для облака:**
```yaml
fallback_providers:
  - provider: custom
    model: llama-3.1-70b
    base_url: http://localhost:8000/v1
    key_env: LOCAL_API_KEY
```

**OAuth Кодекса как запасной вариант:**
```yaml
fallback_providers:
  - provider: openai-codex
    model: gpt-5.3-codex
```

### Где работает резервный вариант

| Контекст | Поддерживается резервный вариант |
|---------|-------------------|
| Сеансы CLI | ✔ |
| Шлюз обмена сообщениями (Telegram, Discord и т. д.) | ✔ |
| Делегирование субагента | ✔ (субагенты наследуют родительскую резервную цепочку) |
| Вакансии Cron | ✔ (агенты cron наследуют настроенных резервных поставщиков) |
| Вспомогательные задачи на `provider: auto` | ✔ (попробуйте резервный вариант для каждой задачи, затем основную цепочку резервных вариантов перед встроенным дополнительным обнаружением) |

:::совет
Для основной резервной цепочки нет переменных среды — настраивайте ее исключительно через `config.yaml` или `hermes fallback`. Это сделано намеренно: резервная конфигурация — это осознанный выбор, а не то, что устаревший экспорт оболочки должен переопределять.
:::

## Резервный вариант вспомогательной задачи

Гермес использует отдельные облегченные модели для побочных задач. Каждая задача имеет собственную цепочку разрешения поставщика, которая действует как встроенная резервная система.

### Задачи с разрешением независимого поставщика

| Задача | Что он делает | Конфигурационный ключ |
|------|-------------|-----------|
| Видение | Анализ изображений, скриншоты браузера | `auxiliary.vision` |
| Сжатие | Сводка по сжатию контекста | `auxiliary.compression` |
| Центр навыков | Поиск и открытие навыков | `auxiliary.skills_hub` |
| МКП | Вспомогательные операции MCP | `auxiliary.mcp` |
| Одобрение | Умная классификация одобрения команды | `auxiliary.approval` |
| Генерация заголовков | Краткое изложение названий сессий | `auxiliary.title_generation` |
| Обзор | `/review` субагент рецензента (полный агент, ни одного звонка LLM) | `auxiliary.review` |
| Спецификатор сортировки | Кнопка `hermes kanban specify` / приборная панель ✨ — превращает однострочную задачу сортировки в реальную спецификацию | `auxiliary.triage_specifier` |

### Цепочка автоматического обнаружения

Если поставщик задачи установлен на `"auto"` (по умолчанию), Hermes сначала пробует использовать основного поставщика + основную модель для этой вспомогательной задачи. Если этот маршрут недоступен или позже происходит сбой из-за ошибки типа емкости, Hermes теперь учитывает настроенную пользователем резервную политику перед использованием встроенной цепочки обнаружения:

```text
Main provider + main model → auxiliary.<task>.fallback_chain →
fallback_providers / fallback_model → built-in auxiliary discovery chain
```

Цепочка для конкретной задачи наиболее точна и выигрывает, если она присутствует. Цепочка `fallback_providers` верхнего уровня — это та же политика, которую использует основной агент, поэтому резервные правила «только бесплатно» или «от того же поставщика» применяются и к вспомогательным задачам на `auto`.

**Встроенная цепочка обнаружения текста (сжатие, веб-извлечение, создание заголовков и т. д.):**

```text
OpenRouter → Nous Portal → Custom endpoint → Codex OAuth →
API-key providers (z.ai, Kimi, MiniMax, Xiaomi MiMo, Hugging Face, Anthropic) → give up
```

**Встроенная цепочка обнаружения видения:**

```text
Main provider (if vision-capable) → OpenRouter → Nous Portal →
Codex OAuth → Anthropic → Custom endpoint → give up
```

Эти встроенные цепочки представляют собой удобный запасной вариант для пользователей, которые не объявили специфичную для задачи или основную резервную политику.

### Настройка вспомогательных поставщиков

Каждую задачу можно настроить независимо в `config.yaml`:

```yaml
auxiliary:
  vision:
    provider: "auto"              # auto | openrouter | nous | codex | main | anthropic
    model: ""                     # e.g. "openai/gpt-4o"
    base_url: ""                  # direct endpoint (takes precedence over provider)
    api_key: ""                   # API key for base_url

  compression:
    provider: "auto"
    model: ""
    fallback_chain:              # optional, task-specific fallback policy
      - provider: openrouter
        model: inclusionai/ring-2.6-1t:free

  skills_hub:
    provider: "auto"
    model: ""

  mcp:
    provider: "auto"
    model: ""
```

Все задачи, описанные выше, выполняются по одному и тому же шаблону **provider/model/base_url**. Каждая задача также может объявить свой собственный `fallback_chain`; если этот параметр опущен, `provider: auto` использует цепочку верхнего уровня `fallback_providers` перед встроенной вспомогательной цепочкой обнаружения Hermes.

Сжатие контекста настроено в `auxiliary.compression`:

```yaml
auxiliary:
  compression:
    provider: main                                    # Same provider options as other auxiliary tasks
    model: google/gemini-3-flash-preview
    base_url: null                                    # Custom OpenAI-compatible endpoint
```

И основная резервная цепочка использует:

```yaml
fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4
    # base_url: http://localhost:8000/v1             # Optional custom endpoint
```

Все три — вспомогательный, сжатие, резервный — работают одинаково: установите `provider`, чтобы выбрать, кто обрабатывает запрос, `model`, чтобы выбрать модель, и `base_url`, чтобы указать на пользовательскую конечную точку (переопределяет поставщика).

### Параметры поставщика для вспомогательных задач

Эти параметры применяются только к записям `auxiliary:`, `compression:` и `fallback_providers:` — `"main"` **не** является допустимым значением для вашего верхнего уровня `model.provider`. Для пользовательских конечных точек используйте `provider: custom` в разделе `model:` (см. [Поставщики AI](/integrations/providers)).

| Провайдер | Описание | Требования |
|----------|-------------|-------------|
| `"auto"` | Пробуйте поставщиков по порядку, пока один из них не заработает (по умолчанию) | Настроен хотя бы один провайдер |
| `"openrouter"` | Принудительно открыть OpenRouter | `OPENROUTER_API_KEY` |
| `"nous"` | Портал Форс Ноус | `hermes auth` |
| `"codex"` | Принудительный кодекс OAuth | `hermes model` → ChatGPT или подписка на Кодекс |
| `"main"` | Используйте любого поставщика, который использует основной агент (только вспомогательные задачи) | Активный основной провайдер настроен |
| `"anthropic"` | Сила антропного родного | `ANTHROPIC_API_KEY` или учетные данные Claude Code |

### Прямое переопределение конечной точки

Для любой вспомогательной задачи установка `base_url` полностью обходит разрешение поставщика и отправляет запросы непосредственно в эту конечную точку:

```yaml
auxiliary:
  vision:
    base_url: "http://localhost:1234/v1"
    api_key: "local-key"
    model: "qwen2.5-vl"
```

`base_url` имеет приоритет над `provider`. Гермес использует настроенный `api_key` для аутентификации, возвращаясь к `OPENAI_API_KEY`, если он не установлен. Он **не** повторно использует `OPENROUTER_API_KEY` для пользовательских конечных точек.

## Резервный резерв при ошибке вспомогательной емкости

Когда вы устанавливаете явный вспомогательный поставщик (например, `auxiliary.vision.provider: glm`), Hermes рассматривает это как ваш предпочтительный выбор, но если поставщик буквально не может обслужить запрос из-за **ошибки емкости** (требуется оплата HTTP 402, исчерпание ежедневной квоты HTTP 429, сбой соединения), Hermes возвращается через многоуровневую цепочку вместо того, чтобы молча терпеть неудачу:

1. **Основной дополнительный поставщик** — тот, который вы настроили (всегда пробовал первым)
2. **`auxiliary.<task>.fallback_chain`** — список переопределений для каждой задачи, если вы его написали.
3. **Основной поставщик агента + модель** — крайняя мера безопасности (всегда пробовал, даже если вы не писали цепочку)
4. **Предупреждение + повторное повышение** — если на каждом уровне произошел сбой, Hermes регистрирует `Auxiliary <task>: ... all fallbacks exhausted` на уровне ПРЕДУПРЕЖДЕНИЯ и повторно выдает исходную ошибку.

Временные ограничения скорости HTTP 429 (`Retry-After: ...`) рассматриваются как ограничения запросов, а не проблемы с пропускной способностью — они учитывают ваш явный выбор поставщика и **не** запускают резервную лестницу. Только исчерпание дневной/ежемесячной квоты, ошибки оплаты и сбои соединения обходят шлюз явного провайдера.

Для пользователей `provider: auto` (без явного дополнительного поставщика) вместо шагов 2–3 запускается существующая цепочка автоматического обнаружения. Его первым шагом уже является модель основного агента, поэтому пользователи `auto` получают тот же результат с нулевой конфигурацией.

### Необязательно: цепочка отката для каждой задачи

Если вам нужен другой резервный порядок, чем «сначала модель основного агента», настройте `fallback_chain` явно. Для каждой записи требуется как минимум `provider`; `model`, `base_url` и `api_key` являются необязательными.

```yaml
auxiliary:
  vision:
    provider: glm
    model: glm-4v-flash
    fallback_chain:
      - provider: openrouter
        model: google/gemini-3-flash-preview
      - provider: nous
        model: anthropic/claude-sonnet-4

  compression:
    provider: openrouter
    fallback_chain:
      - provider: openai
        model: gpt-4o-mini
        timeout: 240            # optional — this candidate's own deadline (seconds)
```

Вам **не** нужно настраивать `fallback_chain` для получения резервного варианта — сеть безопасности основного агента работает независимо. Используйте его только в том случае, если вам конкретно нужен порядок, отличный от установленного по умолчанию.

Каждая запись `fallback_chain` может также объявлять свои собственные `timeout` (секунды). Без него резервный кандидат наследует тайм-аут уровня задачи, который можно настроить для основного поставщика. Объявление `timeout` для каждой записи позволяет более медленному, но надежному резервному средству (например, сумматору с большим контекстом) получить бюджет, который ему действительно нужен, вместо того, чтобы умирать на часах основного.

### Ошибки квоты поставщика, вызывающие откат

Hermes считает, что они эквивалентны исчерпанию кредита 402 (а не временным ограничениям по ставкам):

- Коренная порода/LiteLLM: `Too many tokens per day`, `daily limit`, `tokens per day`
- Вершинный AI/GCP: `quota exceeded`, `resource exhausted`, `RESOURCE_EXHAUSTED`
– Общий: `daily quota`, `quota_exceeded`.

Если ваш провайдер возвращает другую фразу для исчерпания дневной квоты, а Hermes не запускает резервный вариант, это ошибка — откройте проблему с точной строкой ошибки.

## Резервное сжатие контекста

Сжатие контекста использует блок конфигурации `auxiliary.compression` для управления тем, какая модель и поставщик обрабатывают суммирование:

```yaml
auxiliary:
  compression:
    provider: "auto"                              # auto | openrouter | nous | main
    model: "google/gemini-3-flash-preview"
```

:::info Устаревшая миграция
Старые конфигурации с `compression.summary_model` / `compression.summary_provider` / `compression.summary_base_url` автоматически переносятся в `auxiliary.compression.*` при первой загрузке (версия конфигурации 17).
:::

Если ни один поставщик не доступен для сжатия, Hermes пропускает промежуточные разговоры, не создавая сводку, вместо того, чтобы завершить сеанс.

## Переопределение поставщика делегирования

Субагенты, порожденные `delegate_task`, наследуют основную резервную цепочку родительского агента. Вы по-прежнему можете направить субагентов к другой основной паре «поставщик:модель» для оптимизации затрат:

```yaml
delegation:
  provider: "openrouter"                      # override provider for all subagents
  model: "google/gemini-3-flash-preview"      # override model
  # base_url: "http://localhost:1234/v1"      # or use a direct endpoint
  # api_key: "local-key"
```

Подробные сведения о конфигурации см. в разделе [Делегирование субагента](/user-guide/features/delegation).

## Поставщики заданий Cron

Задания Cron наследуют настроенную цепочку `fallback_providers` (или устаревшую `fallback_model`) при создании агента. Чтобы использовать другого основного поставщика для задания cron, настройте переопределения `provider` и `model` в самом задании cron:

```python
cronjob(
    action="create",
    schedule="every 2h",
    prompt="Check server status",
    provider="openrouter",
    model="google/gemini-3-flash-preview"
)
```

Полную информацию о конфигурации см. в разделе [Запланированные задачи (Cron)](/user-guide/features/cron).

## Резюме

| Особенность | Резервный механизм | Расположение конфигурации |
|---------|-------------------|----------------|
| Модель главного агента | `fallback_providers` в config.yaml — пошаговое переключение при ошибках (первичное восстановление каждый ход) | `fallback_providers:` (список верхнего уровня) |
| Вспомогательные задачи (любые) — автопользователи | Полная цепочка автоматического обнаружения (сначала модель основного агента, затем цепочка поставщиков) ошибок емкости | `auxiliary.<task>.provider: auto` |
| Вспомогательные задачи (любые) — явный поставщик | `fallback_chain` (если установлено) → модель основного агента → предупреждение + повышение, только при ошибках емкости | `auxiliary.<task>.fallback_chain` |
| Видение | Многоуровневый (см. выше) + внутренняя повторная попытка OpenRouter | `auxiliary.vision` |
| Сжатие контекста | Слоистый (см. выше); сводится к отсутствию сводки, если все слои недоступны | `auxiliary.compression` |
| Центр навыков | Многослойный (см. выше) | `auxiliary.skills_hub` |
| Помощники MCP | Многослойный (см. выше) | `auxiliary.mcp` |
| Классификация одобрения | Многослойный (см. выше) | `auxiliary.approval` |
| Генерация титулов | Многослойный (см. выше) | `auxiliary.title_generation` |
| Спецификатор сортировки | Многослойный (см. выше) | `auxiliary.triage_specifier` |
| Делегация | Наследует родительскую цепочку `fallback_providers`; дополнительное переопределение поставщика/модели | `delegation.provider` / `delegation.model` |
| Вакансии Cron | Наследовать настроенную цепочку `fallback_providers`; необязательное переопределение поставщика для каждого задания | За задание `provider` / `model` |
