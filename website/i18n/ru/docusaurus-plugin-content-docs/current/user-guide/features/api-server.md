# API-сервер

Сервер API предоставляет агент Hermes как конечную точку HTTP, совместимую с OpenAI. Любой интерфейс, поддерживающий формат OpenAI — Open WebUI, LobeChat, LibreChat, NextChat, ChatBox и сотни других — может подключиться к hermes-agent и использовать его в качестве бэкэнда.

Ваш агент обрабатывает запросы, используя полный набор инструментов (терминал, файловые операции, веб-поиск, память, навыки) и возвращает окончательный ответ. При потоковой передаче индикаторы хода работы инструмента отображаются в строке, поэтому интерфейсы могут показывать, что делает агент.

:::tip Один бэкэнд охватывает модели и инструменты
Самому Hermes необходим настроенный поставщик и серверные инструменты, чтобы сервер API был полезен. Подписка на [Nous Portal](/user-guide/features/tool-gateway) обслуживает оба варианта — более 300 моделей плюс веб/изображение/TTS/браузер через Tool Gateway. Запустите `hermes setup --portal` один раз перед запуском сервера API, и интерфейсы, такие как Open WebUI или LobeChat, получат полностью оснащенный инструментами серверный интерфейс.
:::

## Быстрый старт

### 1. Включите сервер API

Добавьте в `~/.hermes/.env`:

```bash
API_SERVER_ENABLED=true
API_SERVER_KEY=change-me-local-dev
# Optional: only if a browser must call Hermes directly
# API_SERVER_CORS_ORIGINS=http://localhost:3000
```

### 2. Запустите шлюз

```bash
hermes gateway
```

Вы увидите:

```
[API Server] API server listening on http://127.0.0.1:8642
```

### 3. Подключите интерфейс

Наведите любой OpenAI-совместимый клиент на `http://localhost:8642/v1`:

```bash
# Test with curl
curl http://localhost:8642/v1/chat/completions \
  -H "Authorization: Bearer change-me-local-dev" \
  -H "Content-Type: application/json" \
  -d '{"model": "hermes-agent", "messages": [{"role": "user", "content": "Hello!"}]}'
```

Или подключите Open WebUI, LobeChat или любой другой интерфейс — пошаговые инструкции см. в [Руководстве по интеграции Open WebUI](/user-guide/messaging/open-webui).

## Конечные точки

### POST /v1/chat/completions

Стандартный формат завершения чата OpenAI. Без сохранения состояния — весь разговор включается в каждый запрос через массив `messages`.

**Запрос:**
```json
{
  "model": "hermes-agent",
  "messages": [
    {"role": "system", "content": "You are a Python expert."},
    {"role": "user", "content": "Write a fibonacci function"}
  ],
  "stream": false
}
```

**Ответ:**
```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1710000000,
  "model": "hermes-agent",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant", "content": "Here's a fibonacci function..."},
    "finish_reason": "stop"
  }],
  "usage": {"prompt_tokens": 50, "completion_tokens": 200, "total_tokens": 250}
}
```

**Встроенный ввод изображения:** пользовательские сообщения могут отправлять `content` в виде массива, состоящего из частей `text` и `image_url`. Поддерживаются как удаленные URL-адреса `http(s)`, так и URL-адреса `data:image/...`:

```json
{
  "model": "hermes-agent",
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "text", "text": "What is in this image?"},
        {"type": "image_url", "image_url": {"url": "https://example.com/cat.png", "detail": "high"}}
      ]
    }
  ]
}
```

Загруженные файлы (`file` / `input_file` / `file_id`) и URL-адреса `data:` без изображений возвращают `400 unsupported_content_type`.

**Потоковая передача** (`"stream": true`): возвращает события, отправленные сервером (SSE), с фрагментами ответа по токену. Для **Завершений чата** поток использует стандартные события `chat.completion.chunk` плюс специальное событие Hermes `hermes.tool.progress` для пользовательского интерфейса при запуске инструмента. Для **Ответов** поток использует типы событий ответов OpenAI, такие как `response.created`, `response.output_text.delta`, `response.output_item.added`, `response.output_item.done` и `response.completed`.

**Прогресс работы инструмента в потоках**:
- **Завершения чата**: Hermes выдает `event: hermes.tool.progress` для видимости запуска инструмента, не загрязняя сохраняемый текст помощника.
- **Ответы**: Hermes генерирует специальные элементы вывода `function_call` и `function_call_output` во время потока SSE, поэтому клиенты могут отображать структурированный пользовательский интерфейс инструмента в реальном времени.

### POST /v1/ответы

Формат API ответов OpenAI. Поддерживает состояние разговора на стороне сервера через `previous_response_id` — сервер хранит полную историю разговоров (включая вызовы инструментов и результаты), поэтому многоходовой контекст сохраняется без управления им со стороны клиента.

**Запрос:**
```json
{
  "model": "hermes-agent",
  "input": "What files are in my project?",
  "instructions": "You are a helpful coding assistant.",
  "store": true
}
```

**Ответ:**
```json
{
  "id": "resp_abc123",
  "object": "response",
  "status": "completed",
  "model": "hermes-agent",
  "output": [
    {"type": "function_call", "status": "completed", "name": "terminal", "arguments": "{\"command\": \"ls\"}", "call_id": "call_1"},
    {"type": "function_call_output", "status": "completed", "call_id": "call_1", "output": "README.md src/ tests/"},
    {"type": "message", "role": "assistant", "content": [{"type": "output_text", "text": "Your project has..."}]}
  ],
  "usage": {"input_tokens": 50, "output_tokens": 200, "total_tokens": 250}
}
```

Вызовы инструментов в массиве `output` уже выполнялись агентом Hermes на стороне сервера — они воспроизводятся с помощью `"status": "completed"` для структурированного пользовательского интерфейса инструмента, а не как ожидающие выполнения вызовы клиента.

**Ввод встроенного изображения:** `input[].content` может содержать части `input_text` и `input_image`. Поддерживаются как удаленные URL-адреса, так и URL-адреса `data:image/...`:

```json
{
  "model": "hermes-agent",
  "input": [
    {
      "role": "user",
      "content": [
        {"type": "input_text", "text": "Describe this screenshot."},
        {"type": "input_image", "image_url": "data:image/png;base64,iVBORw0K..."}
      ]
    }
  ]
}
```

Загруженные файлы (`input_file` / `file_id`) и URL-адреса `data:` без изображений возвращают `400 unsupported_content_type`.

#### Многоходовой режим с предыдущим_ответом_id

Цепочка ответов для поддержания полного контекста (включая вызовы инструментов) на протяжении хода:

```json
{
  "input": "Now show me the README",
  "previous_response_id": "resp_abc123"
}
```

Сервер восстанавливает полный диалог из сохраненной цепочки ответов — все предыдущие вызовы инструментов и результаты сохраняются. Связанные запросы также используют один и тот же сеанс, поэтому многоходовые разговоры отображаются как одна запись на панели мониторинга и в истории сеансов.

#### Именованные беседы

Используйте параметр `conversation` вместо идентификаторов ответов отслеживания:

```json
{"input": "Hello", "conversation": "my-project"}
{"input": "What's in src/?", "conversation": "my-project"}
{"input": "Run the tests", "conversation": "my-project"}
```

Сервер автоматически привязывается к последнему ответу в этом разговоре. Подобно команде `/title` для сеансов шлюза.

### GET /v1/responses/\{id\}

Получить ранее сохраненный ответ по идентификатору.

### DELETE /v1/responses/\{id\}

Удалить сохраненный ответ.

### ПОЛУЧИТЬ /v1/модели

Агент указан как доступная модель. По умолчанию объявленное имя модели имеет имя [profile](/user-guide/profiles) (или `hermes-agent` для профиля по умолчанию). Требуется большинством интерфейсов для обнаружения моделей.

`/v1/models` намеренно представляет собой дешевую поверхность, совместимую с OpenAI. Это **нет**
перечислить все проверенные комбинации поставщиков/моделей, к которым Hermes может направить маршрут,
и он не занимается ценообразованием или расширением возможностей.

### ПОЛУЧИТЬ /api/model/options

Клиенты, знающие о Hermes, могут запросить тот же инвентарь курируемого поставщика/модели, который используется.
по приборной панели и TUI. Этот маршрут использует обычный канал сервера API.
аутентификация и возврат строк поставщика, подсказки о возможностях модели и цены.
метаданные, которые не относятся к OpenAI-совместимому ответу `/v1/models`:

```bash
curl \
  -H "Authorization: Bearer $API_SERVER_KEY" \
  "http://127.0.0.1:8642/api/model/options"
```

Эта полезная нагрузка является той же подложкой, что и страница «Модели панели мониторинга» и TUI.
`model.options` Использование RPC. Он возвращает проверенных поставщиков, кураторскую модель.
списки, цены для каждой модели и подсказки о возможностях модели.

Обычные открытия намеренно консервативны для индивидуальных поставщиков: исследования Hermes
только **выбранная** в данный момент** пользовательская конечная точка, поэтому сохраняется устаревшая или автономная версия.
конечная точка не блокирует сборщик. Явное обновление переключается на полное зондирование
и разрушает кеш модели провайдера:

```bash
curl \
  -H "Authorization: Bearer $API_SERVER_KEY" \
  "http://127.0.0.1:8642/api/model/options?refresh=1"
```

Используйте `/v1/models`, когда OpenAI-совместимому клиенту требуется только имя модели для
отправить обратно в чат/запросы на ответы. Используйте `/api/model/options`, когда
аутентифицированному пользовательскому интерфейсу требуются более богатые метаданные средства выбора, специфичные для Hermes.

### ПОЛУЧИТЬ /v1/capabilities

Возвращает машиночитаемое описание стабильной поверхности сервера API для внешних пользовательских интерфейсов, оркестраторов и мостов подключаемых модулей.

```json
{
  "object": "hermes.api_server.capabilities",
  "platform": "hermes-agent",
  "model": "hermes-agent",
  "auth": {"type": "bearer", "required": true},
  "features": {
    "chat_completions": true,
    "responses_api": true,
    "run_submission": true,
    "run_status": true,
    "run_events_sse": true,
    "run_stop": true
  }
}
```

Используйте эту конечную точку при интеграции информационных панелей, пользовательских интерфейсов браузера или плоскостей управления, чтобы они могли узнать, поддерживает ли работающая версия Hermes запуски, потоковую передачу, отмену и непрерывность сеанса, не завися от частных внутренних компонентов Python.

## Управление расширениями браузера

Hermes может направлять инструменты браузера через аутентифицированное расширение, которое контролирует
сеанс браузера, связанный с текущим сеансом Hermes. Эта функция
отключен по умолчанию; установите для `browser.extension_control.enabled` значение `true`, чтобы согласиться:

```yaml
browser:
  extension_control:
    enabled: true
```

Для локального пути API также требуется ключ носителя сервера API. Контролер может
зарегистрируйтесь только для существующего сеанса сервера. Гермес получает контроллер
принципал из состояния аутентифицированного сервера; предоставленный клиентом `principal_id`
игнорируется.

Ознакомьтесь с действующим контрактом через `GET /v1/capabilities`.
Объект `browser_extension_control` сообщает, включена ли функция,
версия протокола, имена транспорта и точный список разрешенных возможностей:

```text
controller.noop
browser_back
browser_click
browser_navigate
browser_press
browser_screenshot
browser_scroll
browser_snapshot
browser_tab_activate
browser_tabs
browser_type
```

Запрошенные возможности за пределами этого списка отфильтровываются. Необработанный CDP, произвольный
оценка сценария, доступ к консоли, загрузка, извлечение изображений и видение не являются
часть протокола контроллера.

Если запрос не имеет связанного идентификатора контроллера или когда эта функция отключена,
Hermes сохраняет существующую серверную часть браузера. Как только шлюз привяжет
Принципал контроллера и транспортное семейство на запрос, эта добавочная полоса
является авторитетным: отсутствуют, неоднозначны, отключены или недееспособны контроллеры
закрыться при сбое вместо автоматического переключения на другой локальный/облачный браузер.
После выбора точного контроллера его результат или ошибка являются авторитетными и
Hermes никогда не повторяет одно и то же действие через другой сервер.

### Регистрация локального API

1. Отправьте `POST /v1/browser-control/register`, прошедший проверку подлинности, с помощью
   `protocol_version`, `session_id`, `controller_id`, `browser_profile_id` и
   запрошенный `capabilities`.
2. Hermes возвращает одноразовый билет с 30-секундным TTL и отфильтрованным,
   область действия контроллера, привязанного к серверу.
3. Откройте `GET /v1/browser-control/ws` с помощью обоих подпротоколов WebSocket:
   `hermes-browser-control-v1` и
   `hermes-browser-control-ticket.<ticket>`.

Билет никогда не принимается в строке запроса. Неизвестно, с истекшим сроком годности, повторно использованное или
некорректные билеты терпят неудачу до обновления WebSocket.

### Кадры контроллера

Hermes отправляет `browser.controller.command` кадров, содержащих `command_id`,
`action`, неизменяемый `arguments`, идентификаторы браузера/контроллера и исходный файл.
`tool_call_id`. Контроллер отвечает `browser.controller.result`,
тот же `command_id`, точное логическое значение `ok` и либо `result`, либо `error`.
Отмена и тайм-аут выдают `browser.controller.cancel`; поздние результаты
игнорируется.

Неожиданная потеря сокета переводит контроллер в автономный режим и сохраняет работу
уже в полете до установленного для каждой команды крайнего срока. Восстановление связи с
тот же принципал, профиль, сеанс, идентификатор контроллера, профиль браузера и транспорт
личность обновляет транспорт, не допуская новой работы перед любой отложенной работой.
отмены сбрасываются. Согласованные возможности могут измениться при повторном подключении; они
не являются полем идентификации. Другой идентификатор контроллера или профиль браузера в
та же полоса сеанса с аутентификацией является жесткой заменой: старая ожидающая работа
аннулируется до того, как преемник станет маршрутизируемым. Отправить
`browser.controller.detach` на транспорте аутентифицированного контроллера для
намеренное жесткое отключение — это немедленно отменяет ожидающую работу. Просто закрытие
сокет рассматривается как восстанавливаемое отключение.

Аутентифицированный транспорт информационной панели предоставляет ту же регистрацию, результат,
тактовый сигнал, возможности и семантика владения для RPC/события шлюза
канал. В обоих транспортах для отбора требуется одно однозначное точное совпадение
субъект, профиль, сеанс, контроллер, профиль браузера, семейство транспорта и
возможности. После выбора отказ контроллера является авторитетным и никогда не регистрируется.
повторная попытка через другую серверную часть браузера.

## Выбор модели по запросу

Аутентифицированные клиенты могут переопределить выбор модели Hermes по умолчанию для каждого запроса.
отправив:

- `model` — идентификатор целевой модели для этого хода.
- `provider` — пул провайдера Hermes для определения учетных данных/времени выполнения для этого хода.
- `model_options` — обоснование на уровне запроса/элементы управления на уровне служб.

Те же поля запроса принимаются:

- `POST /v1/chat/completions`
- `POST /v1/responses`
- `POST /v1/runs`
- `POST /api/sessions/{session_id}/chat`
- `POST /api/sessions/{session_id}/chat/stream`

Приоритет детерминирован:

1. Переопределение сеанса `/model`, если в этом сеансе он уже есть.
2. Статическое сопоставление `gateway.platforms.api_server.model_routes`, выбранное при
   `model` запроса — это настроенный псевдоним маршрута
3. Прямой запрос `model` / `provider`, когда ни один псевдоним маршрута не соответствует.
4. Конфигурация глобального шлюза/среда по умолчанию.

`model_options` остается в области запроса независимо от того, какая модель/поставщик победит.
Если запрос отправляет `provider`, который конфликтует с настроенным `model_routes`
псевдоним, Hermes отклоняет запрос с помощью `400` вместо молчаливого повторного смешивания маршрута
учетные данные у другого провайдера.

**Пустые значения `model` на конечных точках, совместимых с OpenAI, являются добровольными.** Общие значения
Клиенты OpenAI обычно жестко кодируют имена моделей (`gpt-4o`, ...) и существующие
развертывания полагаются на то, что они возвращаются к шлюзу по умолчанию. Вкл.
`POST /v1/chat/completions` и `POST /v1/responses`, отправлено значение `model`.
Таким образом, БЕЗ `provider` игнорируется, если вы не включите:

```yaml
gateway:
  platforms:
    api_server:
      direct_model_requests: true
```

Запросы, включающие явный `provider` — и родной для Hermes
`/v1/runs` и конечные точки сеансового чата — всегда соблюдайте запрошенную модель.
независимо от этого флага.

Пример:

```json
{
  "model": "MiniMax-M3",
  "provider": "minimax",
  "model_options": {
    "reasoning_effort": "high",
    "service_tier": "priority"
  },
  "messages": [
    {"role": "user", "content": "Summarize the repo status."}
  ]
}
```

### ПОЛУЧИТЬ /здоровье

Проверка здоровья. Возвращает `{"status": "ok"}`. Также доступно по адресу **GET/v1/health** для OpenAI-совместимых клиентов, которым требуется префикс `/v1/`.

### GET /health/detailed

Аутентифицированная проверка готовности плоскостей мониторинга и управления. Об этом сообщает
ограниченный статус для конфигурации активного профиля, базы данных состояний, настроен
модель, дисковое пространство, состояние шлюза/платформы, активные запуски API, ожидающий процесс

## Запускает API (альтернатива для потоковой передачи)

В дополнение к `/v1/chat/completions` и `/v1/responses` сервер предоставляет **runs** API для длинных сеансов, когда клиент хочет подписаться на события хода выполнения вместо того, чтобы самостоятельно управлять потоковой передачей.

### POST /v1/runs

Создайте новый запуск агента. Возвращает `run_id`, который можно использовать для подписки на события хода выполнения.

```json
{
  "run_id": "run_abc123",
  "status": "started"
}
```

Запуски принимают простую строку `input` и необязательные `session_id`, `instructions`, `conversation_history` или `previous_response_id`. Если указан `session_id`, Hermes отображает его в статусе выполнения, чтобы внешние пользовательские интерфейсы могли сопоставлять запуски со своими собственными идентификаторами разговоров.

### GET /v1/runs/\{run_id\}

Опрос текущего состояния выполнения. Это полезно для информационных панелей, которым требуется состояние без открытия соединения SSE, или для пользовательских интерфейсов, которые повторно подключаются после навигации.

```json
{
  "object": "hermes.run",
  "run_id": "run_abc123",
  "status": "completed",
  "session_id": "space-session",
  "model": "hermes-agent",
  "output": "Done.",
  "usage": {"input_tokens": 50, "output_tokens": 200, "total_tokens": 250}
}
```

Статусы сохраняются на короткое время после состояний терминала (`completed`, `failed` или `cancelled`) для опроса и согласования пользовательского интерфейса.

### GET /v1/runs/\{run_id\}/events

Поток событий, отправленных сервером, о ходе выполнения вызова инструмента, изменениях токенов и событиях жизненного цикла. Предназначен для информационных панелей и толстых клиентов, которые хотят подключаться/отсоединяться без потери состояния.

Когда агент делегирует работу фоновым подагентам, поток также передает
События жизненного цикла `subagent.start` и `subagent.complete`, чтобы клиенты могли
наблюдать за результатами делегирования, включая таймауты и сбои, вместо
бежать молча, пока ребенок работает. Полезная нагрузка `subagent.complete` несет в себе
статус ребенка, сводка, продолжительность, цифры жетонов/стоимости и
`child_session_id` для корреляции; поля со свободным текстом проходят обязательную секретность
редактирование перед выходом из процесса. Дочерние события для каждого инструмента
(`subagent.tool`, метки выполнения) намеренно **не** пересылаются — они
являются громким шумом пользовательского интерфейса; используйте файлы транскриптов для каждого ребенка для
игра за игрой.

Срок действия неиспользованных буферов событий истекает через пять минут, поэтому отключенный клиент не может
растить память бесконечно. Срок действия истекает только в транспортном состоянии: запуск, который
все еще выполняющийся остается видимым для опроса статуса, утверждения, контроля остановки и
учет параллелизма до фактического завершения работы его исполнителя. Подключенный SSE
абонент продолжает нормально расходовать воду.

### POST /v1/runs/\{run_id\}/stop

Прервите ход работающего агента. Конечная точка немедленно возвращается с `{"status": "stopping"}`, в то время как Hermes просит активный агент остановиться в следующей безопасной точке прерывания.
Выполнение отслеживается как `stopping` до тех пор, пока работа, поддерживаемая исполнителем, не завершится, а затем
рассчитывается как `cancelled`; запрос остановки никогда не скрывает работника, который все еще
бег.

### POST /v1/runs/\{run_id\}/approval

Устраните ожидающее утверждение для запуска, ожидающего решения человека (например, вызов инструмента, защищенный политикой утверждения). Орган принимает решение об утверждении; забег возобновляется после того, как решение будет записано. Эта конечная точка рекламируется в `/v1/capabilities` как функция `run_approval`, поэтому внешние пользовательские интерфейсы могут обнаружить поддержку до отображения запроса на одобрение.

## API заданий (фоновая запланированная работа)

Сервер предоставляет облегченную поверхность CRUD заданий для управления запланированными/фоновыми запусками агентов с удаленного клиента. Все конечные точки защищены одной и той же аутентификацией носителя.

### ПОЛУЧИТЬ /api/jobs

Перечислите все запланированные задания.

### POST /api/jobs

Создайте новое запланированное задание. Тело принимает ту же форму, что и `hermes cron` — приглашение, расписание, навыки, переопределение поставщика, цель доставки.

### GET /api/jobs/\{job_id\}

Получите определение одного задания и состояние последнего запуска.

### ПАТЧ /api/jobs/\{job_id\}

Обновите поля существующего задания (подсказка, расписание и т. д.). Частичные обновления объединены.

### DELETE /api/jobs/\{job_id\}

Удалить работу. Также отменяет любой запуск в полете.

### POST /api/jobs/\{job_id\}/pause

Приостановите задание, не удаляя его. Временные метки следующего запланированного запуска приостанавливаются до возобновления.

### POST /api/jobs/\{job_id\}/resume

Возобновите ранее приостановленную работу.

### POST /api/jobs/\{job_id\}/run

Запустите задание для немедленного запуска вне расписания.

## API сессий (управление сессиями через REST)

Внешние пользовательские интерфейсы могут управлять сеансами Hermes через REST, не поднимая панель управления. Все конечные точки контролируются `API_SERVER_KEY` и находятся под `/api/sessions/*`.

| Метод | Путь | Описание |
|--------|------|-------------|
| `GET` | `/api/sessions` | Список сеансов (постраничный — `limit`, `offset`, `source`, `include_children`) |
| `POST` | `/api/sessions` | Создать пустой сеанс |
| `GET` | `/api/sessions/{id}` | Чтение метаданных сеанса |
| `PATCH` | `/api/sessions/{id}` | Обновить заголовок или `end_reason` |
| `DELETE` | `/api/sessions/{id}` | Удалить сеанс |
| `GET` | `/api/sessions/{id}/messages` | История сообщений за сеанс |
| `POST` | `/api/sessions/{id}/fork` | Разветвить сеанс через линию `SessionDB` (соответствует семантике CLI `/branch`) |
| `POST` | `/api/sessions/{id}/chat` | Запустить один ход синхронного агента |
| `POST` | `/api/sessions/{id}/chat/stream` | Обертка SSE за один оборот — генерирует события `assistant.delta`, `tool.started`, `tool.completed`, `run.completed` |

`/v1/capabilities` рекламирует всю поверхность с помощью флагов функций `session_*` и записей `endpoints.session_*`, чтобы внешние пользовательские интерфейсы могли обнаружить поддержку и безопасно отступить. Встроенные изображения поддерживаются в полезных нагрузках `chat` и `chat/stream` (многомодальный путь).

```bash
# fork a session and run one turn
curl -X POST http://localhost:8642/api/sessions/$ID/fork \
  -H "Authorization: Bearer $API_SERVER_KEY" \
  -d '{"title": "explore alt path"}'

# stream a turn over SSE
curl -N -X POST http://localhost:8642/api/sessions/$ID/chat/stream \
  -H "Authorization: Bearer $API_SERVER_KEY" \
  -d '{"input": "what files changed in the last hour?"}'
```

## Открытие навыков и наборов инструментов

`GET /v1/skills` и `GET /v1/toolsets` позволяют внешним клиентам детерминированно перечислять возможности агента через REST, а не запрашивать модель. Оба доступны только для чтения и закрыты `API_SERVER_KEY`.

```bash
curl http://localhost:8642/v1/skills \
  -H "Authorization: Bearer $API_SERVER_KEY"
# → [{"name": "github-pr-workflow", "description": "...", "category": "..."}, ...]

curl http://localhost:8642/v1/toolsets \
  -H "Authorization: Bearer $API_SERVER_KEY"
# → [{"name": "core", "label": "...", "description": "...", "enabled": true,
#     "configured": true, "tools": ["read_file", "write_file", ...]}, ...]
```

`/v1/skills` возвращает те же метаданные, которые центр навыков использует внутри себя. `/v1/toolsets` возвращает наборы инструментов, разрешенные для платформы `api_server`, с конкретным списком `tools`, каждый из которых расширяется. Оба рекламируются под `endpoints.*` в `/v1/capabilities`.

## Обзор долговременной памяти (`X-Hermes-Session-Key`)

Многопользовательским интерфейсам, таким как Open WebUI, необходим стабильный идентификатор каждого канала для долговременной памяти (Honcho и т. д.), который **независим** от области транскрипта `X-Hermes-Session-Id` (который меняется на `/new`). Передайте `X-Hermes-Session-Key` на `/v1/chat/completions`, `/v1/responses` или `/v1/runs`, и Hermes передает его на `AIAgent(gateway_session_key=...)`, где поставщик памяти Honcho использует его для получения стабильной области видимости.

```http
POST /v1/chat/completions HTTP/1.1
Authorization: Bearer ***
X-Hermes-Session-Id: transcript-alpha
X-Hermes-Session-Key: agent:main:webui:dm:user-42
```

Правила: максимум 256 символов, управляющие символы (`\r`, `\n`, `\x00`) отклоняются, а значение возвращается в ответах (JSON + SSE). `/v1/capabilities` объявляет о поддержке через `"session_key_header": "X-Hermes-Session-Key"`. Без ключа стратегия Хончо `per-session` создает другую область действия для `session_id` — именно такое же поведение было у Гермеса раньше.

## Обработка системных запросов

Когда внешний интерфейс отправляет сообщение `system` (завершения чата) или поле `instructions` (API ответов), hermes-agent **помещает его поверх** основного системного приглашения. Ваш агент сохраняет все свои инструменты, память и навыки — системная подсказка интерфейса добавляет дополнительные инструкции.

Это означает, что вы можете настроить поведение каждого интерфейса без потери возможностей:
- Откройте системное приглашение WebUI: «Вы эксперт Python. Всегда включайте подсказки по типам».
- У агента по-прежнему есть терминал, файловые инструменты, веб-поиск, память и т. д.

## Аутентификация

Аутентификация токена носителя через заголовок `Authorization`:

```
Authorization: Bearer ***
```

Настройте ключ через `API_SERVER_KEY` env var. Если вам нужен браузер для прямого вызова Hermes, также установите `API_SERVER_CORS_ORIGINS` в явный список разрешений.

### Многопрофильная маршрутизация (`/p/<profile>/…`)

Когда [маршрутизация многопрофильного шлюза](/user-guide/multi-profile-gateways)
включен (`gateway.multiplex_profiles`), общий прослушиватель обслуживает каждый
профиль через префикс URL-адреса `/p/<profile>/` — и **аутентификация привязана
к маршрутизируемому профилю**:

– В запросах к `/p/<profile>/v1/...` необходимо указывать собственный профиль этого пользователя.
  `API_SERVER_KEY` (из `~/.hermes/profiles/<profile>/.env`). По умолчанию
  Ключ прослушивателя отклоняется для префиксов именованного профиля.
- Маршруты без префиксов и `/p/default/...` продолжают использовать ключ профиля по умолчанию.
- Именованный профиль без собственного `API_SERVER_KEY` не закрывается — его
  префикс недоступен, пока вы его не установите.

:::предупреждение Критические изменения (июль 2026 г.)
До этого исправления действительный ключ профиля по умолчанию принимался на любом
Префикс `/p/<profile>/`. Если вы использовали один общий ключ для всего профиля
префиксы, установите отдельный `API_SERVER_KEY` в `.env` каждого профиля — используется повторно
ключи по умолчанию для именованных префиксов теперь возвращают `401`.
:::

:::предупреждение безопасности
Сервер API предоставляет полный доступ к набору инструментов Hermes-agent, **включая команды терминала**. `API_SERVER_KEY` **требуется для каждого развертывания**, включая привязку обратной связи по умолчанию на `127.0.0.1`. Сохраняйте `API_SERVER_CORS_ORIGINS` узким, чтобы контролировать доступ браузера, когда вы явно разрешаете вызывающим браузерам.
:::

## Конфигурация

### Переменные среды

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `API_SERVER_ENABLED` | `false` | Включить сервер API |
| `API_SERVER_PORT` | `8642` | Порт HTTP-сервера |
| `API_SERVER_HOST` | `127.0.0.1` | Привязать адрес (по умолчанию только localhost) |
| `API_SERVER_KEY` | _(обязательно)_ | Токен на предъявителя для аутентификации |
| `API_SERVER_CORS_ORIGINS` | _(нет)_ | Разрешенные источники браузера, разделенные запятыми |
| `API_SERVER_MODEL_NAME` | _(имя профиля)_ | Название модели на `/v1/models`. По умолчанию используется имя профиля или `hermes-agent` для профиля по умолчанию. |

### конфиг.yaml

Те же настройки могут находиться в `~/.hermes/config.yaml` во вложенном разделе `gateway.api_server:`:

```yaml
gateway:
  api_server:
    enabled: true
    port: 8642
    host: 127.0.0.1
    key: your-secret-key
    cors_origins: http://localhost:3000
    model_name: my-hermes
    max_concurrent_runs: 10   # concurrent-run cap; 0 disables the limit
```

`port`, `key`, `host`, `cors_origins` и `model_name` автоматически подключаются к настройкам платформы `extra`, поэтому они ведут себя точно так же, как их аналоги `API_SERVER_*`, изменяемые в переменной среды. Переменные среды имеют приоритет над значениями `config.yaml`. Блок также принимается в разделе `gateway.platforms.api_server:` или разделе верхнего уровня `platforms.api_server:`.

### Ограничение одновременного запуска

Сервер API ограничивает количество запусков агента, которые могут выполняться одновременно в конечных точках, совместимых с OpenAI, и конечных точках Runs. Ограничение считывается из `gateway.api_server.max_concurrent_runs` (по умолчанию **10**; `0` отключает ограничение, отрицательные значения ограничиваются 0). При достижении ограничения новые запросы на запуск отклоняются с помощью **HTTP 429** `Too many concurrent runs (max N)` — клиентам следует отступить и повторить попытку.

## Заголовки безопасности

Все ответы включают заголовки безопасности:
- `X-Content-Type-Options: nosniff` — предотвращает перехват MIME-типа.
- `Referrer-Policy: no-referrer` — предотвращает утечку реферера

## КОРС

Сервер API **не** включает CORS браузера по умолчанию.

Для прямого доступа через браузер установите явный белый список:

```bash
API_SERVER_CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

Когда CORS включен:
- **Ответы перед полетом** включают `Access-Control-Max-Age: 600` (10-минутный кэш).
- **Ответы потоковой передачи SSE** включают заголовки CORS, поэтому клиенты EventSource браузера работают правильно.
— **`Idempotency-Key`** — разрешенный заголовок запроса — клиенты могут отправлять его на дедупликацию (ответы кэшируются по ключу в течение 5 минут)

Большинство документированных интерфейсов, таких как Open WebUI, подключаются между серверами и вообще не нуждаются в CORS.

## Многопользовательская настройка с профилями

Чтобы предоставить нескольким пользователям собственный изолированный экземпляр Hermes (отдельная конфигурация, память, навыки), используйте [profiles](/user-guide/profiles):

```bash
# Create a profile per user
hermes profile create alice
hermes profile create bob

# Configure each profile's API server on a different port. API_SERVER_* are env
# vars (not config.yaml keys), so write them to each profile's .env:
cat >> ~/.hermes/profiles/alice/.env <<EOF
API_SERVER_ENABLED=true
API_SERVER_PORT=8643
API_SERVER_KEY=alice-secret
EOF

cat >> ~/.hermes/profiles/bob/.env <<EOF
API_SERVER_ENABLED=true
API_SERVER_PORT=8644
API_SERVER_KEY=bob-secret
EOF

# Start each profile's gateway
hermes -p alice gateway &
hermes -p bob gateway &
```

Сервер API каждого профиля автоматически объявляет имя профиля в качестве идентификатора модели:

- `http://localhost:8643/v1/models` → модель `alice`
- `http://localhost:8644/v1/models` → модель `bob`

В Open WebUI добавьте каждое из них как отдельное соединение. В раскрывающемся списке моделей `alice` и `bob` показаны как отдельные модели, каждая из которых поддерживается полностью изолированным экземпляром Hermes. Подробности см. в [Руководстве по открытому веб-интерфейсу](/user-guide/messaging/open-webui#multi-user-setup-with-profiles).

## Ограничения

- **Хранилище ответов** — сохраненные ответы (для `previous_response_id`) сохраняются в SQLite и выдерживают перезапуск шлюза. Максимум 100 сохраненных ответов (выселение LRU).
- **Нет загрузки файлов** — встроенные изображения поддерживаются как на `/v1/chat/completions`, так и на `/v1/responses`, но загруженные файлы (`file`, `input_file`, `file_id`) и ввод документов, не являющихся изображениями, не поддерживаются через API.
- **Простые клиенты OpenAI по-прежнему видят псевдоним** — `/v1/models` рекламирует
  стабильный псевдоним Hermes (`hermes-agent` или имя активного профиля). Богаче
  клиенты могут отправлять явные переопределения `provider`/`model_options` по запросам.

## Режим прокси

Сервер API также служит серверной частью для **режима прокси-сервера**. Когда другой экземпляр шлюза Hermes настроен так, что `GATEWAY_PROXY_URL` указывает на этот сервер API, он пересылает все сообщения сюда вместо запуска собственного агента. Это позволяет разделять развертывания — например, контейнер Docker, обрабатывающий Matrix E2EE, который передает агенту на стороне хоста.

Полное руководство по настройке см. в разделе [Matrix Proxy Mode](/user-guide/messaging/matrix#proxy-mode-e2ee-on-macos).
