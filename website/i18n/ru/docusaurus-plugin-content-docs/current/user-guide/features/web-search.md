# Веб-поиск и извлечение

Агент Hermes включает в себя два вызываемых по модели веб-инструмента, поддерживаемых несколькими поставщиками:

- **`web_search`** — поиск в Интернете и получение ранжированных результатов.
- **`web_extract`** — получение и извлечение читаемого контента с одного или нескольких URL-адресов.

Оба настраиваются посредством единого выбора серверной части. Поставщики выбираются через `hermes tools` или задаются непосредственно в `config.yaml`.

## Бэкэнды

| Провайдер | Конверт Вар | Поиск | Экстракт | Уровень бесплатного пользования |
|----------|---------|--------|---------|-----------|
| **Firecrawl** (по умолчанию) | `FIRECRAWL_API_KEY` (опционально — без ключа, если выбрано) | ✔ | ✔ | 500 кредитов в месяц · Облако без ключа при выборе |
| **ИскатьXNG** | `SEARXNG_URL` | ✔ | — | ✔ Бесплатно (собственное размещение) |
| **Отважный поиск (уровень бесплатного пользования)** | `BRAVE_SEARCH_API_KEY` | ✔ | — | 2 000 запросов/мес |
| **DDGS (DuckDuckGo)** | — (нет ключа) | ✔ | — | ✔ Бесплатно |
| **Тавили** | `TAVILY_API_KEY` (необязательно) | ✔ | ✔ | ✔ Участник бесключевого доступа · 1 000 поисков/мес с бесплатным ключом |
| **Экса** | `EXA_API_KEY` (необязательно) | ✔ | ✔ | ✔ Член кольца без ключа · 1 000 поисков/мес с ключом |
| **Параллельно** | `PARALLEL_API_KEY` (необязательно) | ✔ | ✔ | ✔ Член кольца без ключа · оплата ключом |
| **Кинэйбл** | `KEENABLE_API_KEY` (необязательно) | ✔ | ✔ | ✔ Член кольца без ключа · оплата ключом |
| **xAI (Грок)** | `XAI_API_KEY` или `hermes auth add xai-oauth` | ✔ | — | Платный (SuperGrok или по токенам) |

Brave Search, DDGS и xAI предназначены **только для поиска** — соедините любой из них с Firecrawl/Tavily/Exa/Parallel, если вам также нужен `web_extract`. DDGS использует [`ddgs` пакет Python](https://pypi.org/project/ddgs/) под капотом; если он еще не установлен, запустите `pip install ddgs` (или позвольте Hermes отложенно установить его при первом использовании). xAI запускает серверный инструмент `web_search` Grok в API Responses — результаты генерируются LLM, а не индексируются, поэтому заголовки, описания и выбор URL-адресов — все это выходные данные модели (см. [предостережение модели доверия](#xai-grok) ниже).

**Разделение по возможностям:** вы можете использовать разных поставщиков для поиска и извлечения независимо друг от друга — например, SearXNG (бесплатно) для поиска и Firecrawl для извлечения. См. [Конфигурация по возможностям](#per-capability-configuration) ниже.

:::info Работает «из коробки» — ротация бесплатных уровней без ключа
Новая установка без учетных данных для Интернета `web_search` и `web_extract` работает прямо из коробки: запросы чередуются по циклическому алгоритму между общедоступными уровнями бесплатного пользования пяти поставщиков — **Exa, Parallel, Tavily, Firecrawl и Keenable** — распределяя нагрузку равномерно, а запрос с ограниченной скоростью автоматически повторяет попытку к следующему поставщику в кольце (многопереходный режим, пока один из них не будет обработан или все не будут ограничены). Ни регистрации, ни ключа. Этот уровень является исключительно последним — любой настроенный бэкэнд или существующий ключ API всегда выигрывает — и запросы не содержат идентификаторов пользователя (только случайный идентификатор сеанса для каждого процесса, меняющийся при перезапуске). Для гарантированного и неограниченного обслуживания настройте поставщика с ключами. Полностью отключите уровень бесключевого доступа с помощью `web.keyless_fallback: false`.
:::

**Явный выбор бесплатного или платного варианта:** в `hermes tools` Exa, Parallel и Keenable отображаются в виде двух строк — **Бесплатно (без ключа)** и **Платно (ключ API)**. Выбор бесплатных контактов анонимной конечной точки этого поставщика (даже если вы позже добавите ключ); выбор «Платный» закрепляет путь с ключом (отсутствует ключ, а затем возникают ошибки вместо автоматического перехода на бесплатный уровень). Выбор сохраняется как `web.provider_tier.<name>: free|paid`; оставьте его отключенным для автоматического режима (ключ присутствует → оплачено, иначе звонок без ключа).

:::tip Подписчики
Если у вас есть платная подписка на [Nous Portal](https://portal.nousresearch.com), веб-поиск и извлечение доступны через **[Tool Gateway](tool-gateway.md)** через управляемый Firecrawl — ключ API не требуется. Новые установки могут запускать `hermes setup --portal` для входа в систему и одновременного включения всех инструментов шлюза; существующие установки можно перевернуть только через Интернет через `hermes tools`.
:::

## Как `web_extract` обрабатывает длинные страницы

Бэкэнды возвращают необработанную разметку страницы, которая может быть огромной (темы форумов, сайты документации, новостные статьи со встроенными комментариями). Чтобы сохранить удобство использования вашего контекстного окна, `web_extract` применяет **детерминированный бюджет символов** — суммирование LLM не используется:

| Размер страницы (символов) | Что происходит |
|------------------------|--------------|
| На уровне бюджета или ниже (по умолчанию 15 000) | Возвращено целиком — полная скидка доходит до агента |
| За пределами бюджета | Окно «заголовок+завершение» (~75% «заголовок» / ~25% «завершение», вырезается по границам строки уценки) плюс явный нижний колонтитул `[TRUNCATED]`. Полный чистый текст сохраняется на диске, а нижний колонтитул сообщает агенту путь к файлу и точный вызов `read_file` страницы через пропущенную середину |
| Более 2 000 000 | Сохраняемый текст ограничен 2 МБ |

Бюджет на страницу настраивается через `web.extract_char_limit` в `config.yaml` (по умолчанию `15000`, ограничено до 2 000–500 000), и агент может повышать его для каждого вызова с помощью аргумента инструмента `char_limit`.

### Когда усечение мешает

Если вам конкретно нужен живой DOM, а не извлеченная уценка — например, страница с большим количеством JS, извлечение которой возвращает мало контента — используйте вместо этого `browser_navigate` + `browser_snapshot`. Инструмент браузера возвращает живое дерево доступности (с учетом собственного ограничения снимков на огромных страницах).

## Кэширование результатов

Повторные веб-вызовы в течение короткого окна обслуживаются из кеша, а не из платного бэкэнда — это экономит кредиты и задержку в двух шаблонах, где часто встречаются дубликаты: разветвление субагентов (несколько делегированных агентов, исследующих одну и ту же тему) и повторная проверка агентом страницы, которую он прочитал несколько минут назад.

| Позвонить | Кэш | Область применения |
|------|-------|-------|
| `web_search` — тот же запрос (без учета регистра и пробелов), тот же поставщик | Заметка в памяти | За процесс |
| `web_extract` — тот же URL, тот же формат, тот же провайдер | Полный текст хранится в папке `~/.hermes/cache/web/` | Совместно используется в процессах CLI, шлюза, cron и субагента |

Параллельные идентичные поисковые запросы (параллельный ответ субагента, запускающий один и тот же запрос одновременно) **объединяются в один внутренний запрос** — платит первый вызывающий абонент; остальные разделяют ответ. Запрошенные ограничения поиска группируются до 10/20/50/100, поэтому почти идентичные запросы (`limit=5` и `limit=8`) используют одну запись, при этом каждый вызывающий объект получает запрошенное количество.

Кэшируются только успешные ответы. При сбоях всегда выполняется повторная попытка бэкэнда, ответы, полученные при однократном восстановлении без ключа, никогда не кэшируются (следующий вызов снова пытается выбрать выбранный бэкэнд), а URL-адреса, соответствующие вашему `security.website_blocklist`, никогда не обслуживаются из кеша. Кэшированные извлечения повторно запускают обычный конвейер усечения, поэтому другой `char_limit` при втором вызове обрабатывает ту же сохраненную очистку.

**Локальные URL-адреса разработки никогда не кэшируются.** Все, что находится на `localhost`, `127.0.0.1`, `*.local`, однокомпонентных именах хостов локальной сети или диапазонах частных/локальных IP-адресов (`192.168.*`, `10.*`, `172.16-31.*`), полностью обходит кэш извлечения — серверы разработки, сборки с горячей перезагрузкой и предварительный просмотр артефактов чата в графическом интерфейсе меняются при каждом сохранении, и кэшированная копия покажет вам устаревшую сборку. Каждое обращение к локальной странице является активным. (Эти URL-адреса вообще доступны только при включении `security.allow_private_urls`.)

**Тестируете через общедоступный Интернет?** Промежуточные развертывания и URL-адреса туннелей являются общедоступными DNS, поэтому правило локальной разработки не может их перехватить — перечислите их в `web.cache_exempt_hosts`, и они тоже всегда будут доступны в реальном времени. Записи точно совпадают с подстановочным знаком `*.` или суффиксом домена (`mysite.dev` также охватывает `preview.mysite.dev`):

```yaml
# ~/.hermes/config.yaml
web:
  cache_exempt_hosts:
    - mysite.vercel.app
    - "*.ngrok-free.app"
```

```yaml
# ~/.hermes/config.yaml
web:
  cache_enabled: true      # default; set false to disable both caches
  cache_ttl_minutes: 20    # freshness window, clamped 1–1440
```

Если вы изучаете действительно актуальные данные (результаты, цены, последние новости) и хотите, чтобы каждый звонок был свежим, уменьшите TTL или установите `web.cache_enabled: false`.

## Настройка

### Быстрая настройка через `hermes tools`

Запустите `hermes tools`, перейдите к разделу **Веб-поиск и извлечение** и выберите поставщика. Мастер запрашивает необходимый URL-адрес или ключ API и записывает его в вашу конфигурацию.

```bash
hermes tools
```

---

### Firecrawl (по умолчанию)

Полнофункциональный поиск и извлечение. Рекомендуется для большинства пользователей.

```bash
# ~/.hermes/.env
FIRECRAWL_API_KEY=fc-your-key-here
```

Получите ключ на [firecrawl.dev](https://firecrawl.dev). Уровень бесплатного пользования включает 500 кредитов в месяц.

**Самостоятельный Firecrawl:** укажите свой собственный экземпляр вместо облачного API:

```bash
# ~/.hermes/.env
FIRECRAWL_API_URL=http://localhost:3002
```

Если установлен `FIRECRAWL_API_URL`, ключ API является необязательным (отключите аутентификацию сервера с помощью `USE_DB_AUTHENTICATION=false`).

---

### SearXNG (бесплатно, на собственном хостинге)

SearXNG — это метапоисковая система с открытым исходным кодом, уважающая конфиденциальность и объединяющая результаты более чем 70 поисковых систем. **Ключ API не требуется** — просто укажите Hermes на работающий экземпляр SearXNG.

SearXNG предназначен **только для поиска** — `web_extract` требует отдельного поставщика извлечений.

#### Вариант A — Самостоятельный хостинг с Docker (рекомендуется)

Это дает вам частный экземпляр без ограничений скорости.

**1. Создайте рабочий каталог:**

```bash
mkdir -p ~/searxng/searxng
cd ~/searxng
```

**2. Напишите `docker-compose.yml`:**

```yaml
# ~/searxng/docker-compose.yml
services:
  searxng:
    image: searxng/searxng:latest
    container_name: searxng
    ports:
      - "8888:8080"
    volumes:
      - ./searxng:/etc/searxng:rw
    environment:
      - SEARXNG_BASE_URL=http://localhost:8888/
    restart: unless-stopped
```

**3. Запустите контейнер:**

```bash
docker compose up -d
```

**4. Включите формат JSON API:**

SearXNG поставляется с отключенным по умолчанию выводом JSON. Скопируйте сгенерированную конфигурацию и включите ее:

```bash
# Copy the auto-generated config out of the container
docker cp searxng:/etc/searxng/settings.yml ~/searxng/searxng/settings.yml
```

Откройте `~/searxng/searxng/settings.yml`.
Если присутствует `use_default_settings: true`, файл содержит только ваши переопределения. Все остальные настройки наследуются от встроенных значений по умолчанию.
Чтобы включить ответы JSON для Hermes, добавьте следующее переопределение:

```yaml
search:
  formats:
    - html
    - json
```

Ваш `settings.yml` должен выглядеть примерно так:

```yaml
# Read the documentation before extending the defaults:
# https://docs.searxng.org/admin/settings/

use_default_settings: true

server:
  secret_key: "abcdef12345678"
  image_proxy: true

search:
  formats:
    - html
    - json
```

**5. Перезапустите, чтобы подать заявку:**

```bash
docker cp ~/searxng/searxng/settings.yml searxng:/etc/searxng/settings.yml
docker restart searxng
```

**6. Убедитесь, что это работает:**

```bash
curl -s "http://localhost:8888/search?q=test&format=json" | python3 -c \
  "import sys,json; d=json.load(sys.stdin); print(f'{len(d[\"results\"])} results')"
```

Вы должны увидеть что-то вроде `10 results`. Если вы получили `403 Forbidden`, формат JSON по-прежнему отключен — повторите шаг 4.

**7. Настроить Гермес:**

```bash
# ~/.hermes/.env
SEARXNG_URL=http://localhost:8888
```

Затем выберите SearXNG в качестве механизма поиска в `~/.hermes/config.yaml`:

```yaml
web:
  search_backend: "searxng"
```

Или установите через `hermes tools` → Веб-поиск и извлечение → SearXNG.

#### Соедините SearXNG с поставщиком экстрактов

SearXNG занимается поиском; вам нужен отдельный поставщик для `web_extract`. Используйте ключи для каждой возможности:

```yaml
# ~/.hermes/config.yaml
web:
  search_backend: "searxng"
  extract_backend: "firecrawl"   # or tavily, exa, parallel
```

В этой конфигурации Hermes использует SearXNG для всех поисковых запросов и Firecrawl для извлечения URL-адресов, сочетая бесплатный поиск с высококачественным извлечением.

### Тавили

Поиск и извлечение, оптимизированные с помощью искусственного интеллекта. Выберите Tavily в `hermes tools` (или установите `web.backend: tavily`), чтобы использовать его **без ключа** без учетной записи (ограничено по скорости). Установите ключ API, если вам нужны более высокие лимиты.

```bash
# optional — skip this for keyless access after selecting Tavily
# ~/.hermes/.env
TAVILY_API_KEY=tvly-your-key-here
```

Получите ключ на [app.tavily.com](https://app.tavily.com/home). См. [Tavily keyless](https://docs.tavily.com/documentation/keyless).

Пустые установки сохраняют Firecrawl как именованный вариант по умолчанию. Keyless Tavily не выбирается автоматически.

---

### Экза

Нейронный поиск с семантическим пониманием. Подходит для исследований и поиска концептуально связанного контента.

```bash
# ~/.hermes/.env
EXA_API_KEY=your-exa-key-here
```

Получите ключ на [exa.ai](https://exa.ai). Уровень бесплатного пользования включает 1 000 поисков в месяц.

---

### Параллельно

Поиск и извлечение данных с помощью искусственного интеллекта и глубокими исследовательскими возможностями.

```bash
# ~/.hermes/.env
PARALLEL_API_KEY=your-parallel-key-here
```

Получите доступ на [parallel.ai](https://parallel.ai).

### xAI (Грок) {#xai-grok}

Направляет `web_search` через серверный [инструмент web_search] (https://docs.x.ai/developers/tools/web-search) Grok в API ответов. Grok запускает фактический поиск и возвращает лучшие результаты в виде структурированного JSON.

Работает с любым путем учетных данных — без новых переменных среды, без нового мастера установки:

```bash
# ~/.hermes/.env (env-var path)
XAI_API_KEY=sk-xai-your-key-here
```

или для подписчиков SuperGrok:

```bash
hermes auth add xai-oauth
```

Затем выберите xAI в качестве механизма поиска:

```yaml
# ~/.hermes/config.yaml
web:
  backend: "xai"
```

**Дополнительные ручки:**

```yaml
web:
  backend: "xai"
  xai:
    model: grok-build-0.1        # reasoning model required by web_search (default)
    allowed_domains:             # optional, max 5 — mutex with excluded_domains
      - arxiv.org
    excluded_domains:            # optional, max 5
      - example-spam.com
    timeout: 90                  # seconds (default)
```

**Только поиск** – используйте Firecrawl/Tavily/Exa/Parallel, если вам также нужен `web_extract`. В коде 401 поставщик выполняет одно принудительное обновление токена OAuth и повторяет попытку (охватывает отзыв в середине окна и непрозрачные токены, которые упреждающая проверка срока действия не может декодировать); Учетные данные env-var пропускают повторную попытку.

:::осторожно Модель доверия
В отличие от провайдеров, поддерживаемых индексами (Brave, Tavily, Exa), которые возвращают дословные результаты поисковых систем, xAI — это LLM, который выбирает, какие URL-адреса отображать, и сам пишет заголовки и описания. *Содержимое* запроса влияет на выходные данные, поэтому вредоносный запрос (например, введенный через ненадежные входные данные, полученные агентом) в принципе может заставить Grok выдать URL-адреса, выбранные злоумышленником. Относитесь к возвращаемым URL-адресам так же, как к любой ссылке, созданной моделью: проверяйте ее перед получением, особенно если запрос поступил из ненадежных входных данных.
:::

## Конфигурация

### Одиночный бэкэнд

Установите одного поставщика для всех веб-возможностей:

```yaml
# ~/.hermes/config.yaml
web:
  backend: "searxng"   # firecrawl | searxng | brave-free | ddgs | tavily | exa | parallel | xai
```

### Конфигурация для каждой возможности

Используйте разных поставщиков для поиска и извлечения. Это позволяет вам комбинировать бесплатный поиск (SearXNG) с платным поставщиком извлечений или наоборот:

```yaml
# ~/.hermes/config.yaml
web:
  search_backend: "searxng"     # used by web_search
  extract_backend: "firecrawl"  # used by web_extract
```

Если ключи для каждой возможности пусты, оба попадают в `web.backend`. Только в том случае, если ни один веб-выбор никогда не был записан, серверная часть автоматически определяется по любому присутствующему ключу API или URL-адресу — как только выбор существует, среда выполнения всегда использует его, а добавление ключа в `.env` не перенаправляет веб-трафик.

**Приоритетный порядок (по возможности):**
1. `web.search_backend` / `web.extract_backend` (явно для каждой возможности)
2. `web.backend` (общий резервный вариант; `nous` = управляемый шлюз инструментов)
3. Автоматическое определение переменных среды (только для никогда не настраивавшихся установок)

### Автоопределение

Если ни один сервер **никогда** не был выбран (нет `web.backend` / ключа для каждой возможности, написанного вами или `hermes tools`), Hermes выбирает первый доступный сервер на основе установленных учетных данных:

| Подарок с полномочиями | Автоматически выбранный сервер |
|----|---------------------------------------|
| `TAVILY_API_KEY` | тавили |
| `EXA_API_KEY` | экса |
| `PARALLEL_API_KEY` | параллель |
| `FIRECRAWL_API_KEY` или `FIRECRAWL_API_URL` (или шлюз Nous Tool готов) | ползать |
| `SEARXNG_URL` | поиск |
| `BRAVE_SEARCH_API_KEY` | храбрый |
| `ddgs` пакет импортируемый | ддгс |
| *(вообще ничего не установлено)* | бесключевое кольцо: exa/параллельное/тавильное/пожарное/проточное (круговое) |

**Кольцо бесплатного уровня без ключа:** при *нет* указанных выше учетных данных запросы чередуются между общедоступными уровнями бесплатного пользования пяти поставщиков (Exa, Parallel, Tavily, Firecrawl, Keenable), поэтому веб-инструменты работают при новой установке без каких-либо настроек, а запрос с ограниченной скоростью автоматически передается следующему поставщику в кольце. Закрепите одного поставщика в `hermes tools`, чтобы остановить вращение (кольцо тогда используется только в качестве последовательности переключения при отказе на дросселях). Все уровни бесплатного пользования ограничены скоростью поставщика при пакетной нагрузке; длительное нормальное использование проходит нормально. Установите `web.keyless_fallback: false`, чтобы отключить уровень — если он отключен и нет учетных данных, веб-инструменты будут недоступны, пока не будет настроен поставщик.

**Однократное восстановление без ключа для бэкэндов с ключами:** когда выбранный/ключевой бэкэнд завершает неудачный вызов (неправильный ключ, сбой, восходящий 5xx), этот одиночный вызов автоматически повторяет вызов на бесплатном уровне без ключа вместо ошибки — в результате указывается, какой поставщик обслужил его и почему (`rescued_from` / `backend_error`). Отработка отказа никогда не бывает жесткой: уже следующий вызов `web_search`/`web_extract` снова попытается выполнить выбранный вами бэкэнд. Отключите с помощью `web.keyless_rescue: false` (также выключается, когда `keyless_fallback` выключен).

Веб-поиск xAI **не** включен в цепочку автоматического обнаружения — если установлен `XAI_API_KEY` (или вход в систему через xAI Grok OAuth) не происходит автоматическая маршрутизация веб-трафика через xAI, поскольку эти учетные данные также используются для вывода/TTS/генерации изображений, и пользователю может потребоваться другой бэкэнд для Интернета. Подтвердите свое согласие с помощью `web.backend: "xai"`.

## Устранение неполадок

### `web_search` возвращает `{"success": false}`

- Проверьте, доступен ли `SEARXNG_URL`: `curl -s "http://localhost:8888/search?q=test&format=json"`.
- Если вы получаете HTTP 403, формат JSON отключен — добавьте `json` в список `formats` в `settings.yml` и перезапустите.
- Если вы получаете ошибку подключения, возможно, контейнер не запущен: `docker ps | grep searxng`.

### `web_extract` говорит "серверная часть только для поиска"

SearXNG не может извлечь содержимое URL-адреса. Установите для `web.extract_backend` поставщика, поддерживающего извлечение:

```yaml
web:
  search_backend: "searxng"
  extract_backend: "firecrawl"  # or tavily / exa / parallel
```

### SearXNG возвращает 0 результатов

Некоторые общедоступные экземпляры отключают определенные поисковые системы или категории. Попробуйте:
- Другой запрос
- Другой публичный экземпляр из [searx.space](https://searx.space/)
- Самостоятельное размещение собственного экземпляра для надежных результатов.

### Скорость ограничена в общедоступном экземпляре

Переключитесь на автономный экземпляр (см. [Вариант A](#option-a--self-host-with-docker-recommended) выше). Благодаря Docker ваш собственный экземпляр не имеет ограничений по скорости.

### `web_extract` возвращает усеченное содержимое с нижним колонтитулом `[TRUNCATED]`

Это ожидается для страниц, превышающих бюджет персонажа. Нижний колонтитул называет файл на диске, содержащий полный чистый текст и точный вызов `read_file` для страницы через пропущенную середину. Чтобы увидеть больше встроенных данных, поднимите `web.extract_char_limit` в `config.yaml` или передайте больший `char_limit` при вызове.

## Дополнительный навык: `searxng-search`

Для агентов, которым необходимо использовать SearXNG напрямую через `curl` (например, в качестве запасного варианта, когда набор веб-инструментов недоступен), установите дополнительный навык `searxng-search`:

```bash
hermes skills install official/research/searxng-search
```

Это добавляет навык, который учит агента:
– Вызов API SearXNG JSON через `curl` или Python.
- Фильтровать по категориям (`general`, `news`, `science` и т. д.)
- Обрабатывать пагинацию и случаи ошибок.
- Грациозно отступайте, когда SearXNG недоступен.
