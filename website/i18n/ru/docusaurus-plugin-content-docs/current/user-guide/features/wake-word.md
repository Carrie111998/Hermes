# Слово пробуждения («Эй, Гермес»)

Слово пробуждения превращает Hermes в помощника без помощи рук через CLI, TUI и
настольное приложение: при включенной одной настройке Гермес в фоновом режиме слушает разговорную речь.
триггерная фраза. Скажите это, и Гермес начнет новый сеанс, откроет микрофон,
записывает вашу команду через обычный [голосовой конвейер](/user-guide/features/voice-mode),
и ответы — точно так же, как «Привет, Siri» или «Alexa». Используйте `surface`, чтобы выбрать, какой
человек слушает.

Обнаружение выполняется **полностью на устройстве**. Постоянно включенный слушатель наблюдает только за
фраза пробуждения; звук не покидает вашу машину, пока вы не произнесете команду
агенту.

## Как это работает

1. С `wake_word.enabled: true` (или после `/wake on`) — упрощенное горячее слово.
   детектор прослушивает настроенное вами устройство ввода или процесс по умолчанию.
   микрофон, когда `wake_word.input_device` не установлен.
2. Когда он слышит фразу пробуждения, он делает паузу (освобождая микрофон), запускает новую
   сеанса и записывает одно высказывание с обнаружением тишины в голосовом режиме.
3. Ваша речь расшифровывается и отправляется агенту. После того, как он ответит,
   прослушиватель автоматически возобновляет работу и ждет следующего слова пробуждения.

По умолчанию он **выключен** — ничего не прослушивается, пока вы его не включите.

В настольном приложении голосовой разговор в режиме громкой связи можно завершить, просто
**сказать «стоп»** (или «неважно», «до свидания», «отменить», «и все») —
голосовая команда завершает разговор, а не отправляется агенту. Только
Команда остановки всего высказывания совпадает, поэтому реальный запрос типа «остановить докер»
контейнер» по-прежнему проходит нормально.



## Удаленный рабочий стол (захват клиента)

Когда настольное приложение подключается к **удаленному** серверу Hermes (например,
безголовый хост Docker или машина в другой комнате), бэкэнд часто не имеет **нет
микрофон**. Затем на серверной стороне PortAudio происходит сбой с сообщением «Не удалось открыть
микрофон для пробуждения».

В этом случае Hermes поддерживает **захват клиента**:

1. Руки рабочего стола просыпаются с помощью `capture: client` (автоматически для графического интерфейса, когда
   серверная часть не имеет локального устройства ввода или задана явно ниже).
2. openWakeWord по-прежнему работает **на серверной части** (те же движки, те же модели).
3. На рабочем столе открывается **локальный микрофон Mac/ПК**, который выполняет повторную выборку в моно с частотой 16 кГц.
   int16 и передает короткие кадры через `wake.feed` RPC.
4. При обнаружении серверная часть выдает `wake.detected` как обычно; рабочий стол запускается
   обычный голосовой конвейер на клиентском микрофоне.

```yaml
wake_word:
  enabled: true
  capture: auto    # auto | local | client
  # auto   — local PortAudio unless the desktop arms with client_capture
  # local  — always open the backend mic (CLI/TUI default)
  # client — always expect wake.feed PCM from the desktop (remote-friendly)
```

Графический интерфейс рабочего стола всегда передает `client_capture: true` на `wake.start`, поэтому удаленный
серверные части без микрофона в клиентском режиме автоматически. CLI и TUI сохраняют локальность
захват, если вы явно не установили `capture: client`.

Примечание о конфиденциальности: при захвате клиента пробуждение PCM проходит через аутентифицированный
рабочий стол↔backend WebSocket (тот же канал, что и остальная часть сеанса). Обнаружение
по-прежнему не отправляет звук в сторонние API пробуждения; двигатель является локальным для
серверный процесс.

## Двигатели

| Двигатель | Стоимость | API-ключ | Заметки |
|--------|------|---------|-------|
| **openWakeWord** (по умолчанию) | Бесплатно | Нет | Локальные модели ONNX. Поставляется в комплекте с моделью **"эй, гермес"** (по умолчанию); также поддерживает `hey_jarvis`, `alexa`, `hey_mycroft`, … и пользовательские модели |
| **шерпа** | Бесплатно | Нет | **Открытый словарь** — обнаруживает ЛЮБУЮ набранную фразу без обучения. Небольшая английская модель загружается автоматически при первом использовании (~13 МБ) |
| **Дикобраз** | Бесплатный уровень / платный | `PORCUPINE_ACCESS_KEY` | Пиковый двигатель; встроенные ключевые слова + пользовательские файлы `.ppn` |

По умолчанию это фраза **"эй, гермес"** — ее модель поставляется с Hermes, поэтому
он работает «из коробки» без какого-либо обучения. (При первом использовании openWakeWord загружает
его общие модели извлечения признаков — небольшая разовая выборка.)

Оба устанавливаются лениво при первом включении слова пробуждения (на рабочем столе).
установки сделаны с помощью `--include-desktop`, предварительно установите их, чтобы ухо работало
мгновенно). Чтобы установить заранее:

```bash
cd ~/.hermes/hermes-agent && uv pip install -e ".[wake]"
```

## Быстрый старт

```bash
# In an interactive `hermes` session:
/wake on        # start listening (installs the engine on first use)
/wake status    # show phrase, provider, and state
/wake off       # stop listening
```

В настольном приложении щелкните значок уха в композиторе.

Переключатель — это настройка: включение или выключение слова пробуждения — через `/wake` или
кнопка уха на рабочем столе — также записывает `wake_word.enabled` на `~/.hermes/config.yaml`,
поэтому ваш выбор сохраняется на протяжении всего сеанса. Вы также можете перевернуть его вручную:

```yaml
wake_word:
  enabled: true
```

## Конфигурация

```yaml
wake_word:
  enabled: false
  surface: auto               # eligible surface: "auto" | "cli" | "tui" | "gui"
  input_device: null           # PortAudio input index or device-name substring; null = process default
  capture: auto               # auto | local | client — where PCM is captured (see Remote desktop)
  provider: openwakeword      # "openwakeword" (free, local) | "sherpa" (free, any phrase) | "porcupine"
  phrase: "hey hermes"        # cosmetic label only — detection is keyed by the model/keyword below
  sensitivity: 0.6            # 0.0-1.0 — higher = stricter (fewer false triggers), consistent across all engines
  confirmation_frames: 3      # openWakeWord only — consecutive over-threshold frames required to fire
  start_new_session: true     # start a fresh session on wake vs. continue the current one
  openwakeword:
    model: hey_hermes         # bundled default; OR a built-in name OR a path to a custom .onnx/.tflite
    inference_framework: ""   # "" (auto) | "onnx" | "tflite"
  porcupine:
    keyword: jarvis           # built-in keyword OR path to a custom .ppn
```

`sensitivity`, `phrase` и `start_new_session` применяются к обоим модулям.
Блоки `openwakeword` и `porcupine` выбирают фактическую модель обнаружения.

`input_device` передается непосредственно в PortAudio прослушивателя пробуждения.
(`sounddevice`) поток. Используйте либо числовой индекс устройства, либо однозначный
Подстрока имени устройства. Этот параметр изменяет только захват слов пробуждения; рабочий стол
Функция «нажми и говори» по-прежнему использует путь микрофона настольного приложения.

### Уменьшение количества ложных срабатываний окружающей речи

openWakeWord оценивает один короткий (~ 80 мс) аудиокадр за раз, поэтому случайная фонема
в фоновом разговоре иногда может появляться одиночный кадр поверх
порог и непреднамеренно активируйте слово пробуждения. Этим управляют две ручки:

- **`confirmation_frames`** (по умолчанию `3`, только openWakeWord) — сколько
  Перед срабатыванием следа требуются *последовательные* кадры превышения порога. Настоящий
  «эй, гермес» имеет высокий балл в нескольких кадрах; окружающий всплеск вспыхивает
  только один. Поднимите его (например, `4`–`5`), если вы по-прежнему получаете ложные срабатывания в шумной среде.
  комната; цена — несколько десятков миллисекунд дополнительной задержки. `1` восстанавливает
  старое поведение огня при первом кадре.
- **`sensitivity`** (по умолчанию `0.6`) — порог обнаружения, `0.0`–`1.0`.
  Чем выше, тем строже (меньше ложных срабатываний). Это направление является последовательным во всем
  **все** механизмы — для openWakeWord это необработанный порог оценки за кадр, для
  шерпа соответствует порогу ключевого слова, а для Porcupine он инвертирован
  внутри, так что «выше = строже» тоже сохраняется. По умолчанию `0.6` находится
  выше допустимого базового уровня `0.5` openWakeWord, что допускает такие промахи, как
  «эй, хор» до конца; поднимите в сторону `0.8`, если ложные срабатывания все еще происходят, опустите его
  если настоящие высказывания «эй, гермес» пропущены.

Механизмы `sherpa` и `porcupine` внутренне декодируют всю фразу, поэтому они
не сталкивайтесь с проблемой однокадрового всплеска и игнорируйте `confirmation_frames`
(но они по-прежнему чтят `sensitivity`).

`inference_framework` выбирает серверную часть openWakeWord. Оставьте это поле пустым (т.
по умолчанию), чтобы позволить Hermes выбирать для каждой платформы: **tflite на Apple Silicon**, onnx
везде еще. Серверная часть onnx openWakeWord возвращает почти нулевые оценки на macOS
ARM64 ([openWakeWord#336](https://github.com/dscripka/openWakeWord/issues/336)),
поэтому прослушиватель, прикрепленный к `onnx`, будет поставлен на охрану, будет отображаться как прослушиваемый, и никогда
огонь. Серверной части tflite требуется `ai-edge-litert` в macOS, который устанавливает Hermes.
по требованию наряду с другими службами пробуждения.

### Поверхности (CLI, TUI, GUI)

Слово пробуждения работает на всех трех поверхностях Hermes, а `surface` выбирает, какую именно.
владеет прослушивателем и открывает новый сеанс при его запуске:

| `surface` | Поведение |
|-----------|----------|
| `auto` (по умолчанию) | Допускаются все локальные поверхности; тот, кто первым активирует, владеет слушателем. |
| `cli` | Только классический интерфейс командной строки `hermes`. |
| `tui` | Всего `hermes --tui`. |
| `gui` | Только настольное приложение. |

Детектор встроен в устройство и имеет один микрофон, поэтому одновременно прослушивает только одна поверхность.
в том числе, когда поверхности Hermes выполняются в отдельных процессах. Право собственности закреплено:
первый правомочный заявитель удерживает прослушиватель до тех пор, пока он не остановится, не отключится или
его процесс завершается. Гермес не переваливается молча на другую открытую поверхность.
Установите `surface`, если вы хотите закрепить право собственности вместо использования выигрышей по первой претензии.
TUI и графический интерфейс рабочего стола используют один и тот же бэкенд Python (`tui_gateway`), который
запускает детектор на стороне сервера и передает микрофон для захвата голоса, пока
командные записи.

## Использование другой фразы

«Эй, Гермес» работает «из коробки» — встроенная модель openWakeWord.
(`model: hey_hermes`) — значение по умолчанию. Проснуться от чего-то другого, проще всего
path — это движок открытого словаря:

### Вариант А — шерпа (любая фраза, ноль обучения)

Введите нужную фразу; он токенизируется во время выполнения — «эй, кодер»,
«компьютер», «проснись, нео», что угодно:

```yaml
wake_word:
  enabled: true
  provider: sherpa
  phrase: "hey coder"        # detection key — just type your phrase
```

Небольшая английская модель KWS (~13 МБ) загружается один раз при первом использовании. Каждый
профиль может установить свою собственную фразу — «эй \<profile\>» для каждого запускаемого вами профиля.

### Пробуждение определенного профиля (рабочий стол)

С помощью механизма sherpa ОДИН слушатель может разбудить ЛЮБОЙ профиль. Каждый профиль
чей конфиг имеет `wake_word.enabled: true`, регистрируется автоматически; это
если фраза не установлена, по умолчанию используется `hey <profile name>`. Произнесите фразу профиля
и настольное приложение переключается на этот профиль в реальном времени, открывает новый сеанс
там, и начинает голос без помощи рук:

- «Эй, Гермес» → профиль по умолчанию
- «эй, кодер» → профиль `coder`
- «эй, трейдер» → профиль `trader`

Установите `wake_word.profile_routing: false` в профиле слушателя, чтобы отказаться от участия.
и слушать только свою собственную фразу. CLI и TUI однопрофильные.
процессы: фраза пробуждения, принадлежащая другому профилю, печатает переключатель
команда (`hermes -p <profile>`) вместо маршрутизации.

Имена акустически соответствуют звукам их английских подслов: два слова.
Фразы с четкими названиями, состоящими из двух и более слогов, работают лучше всего. Очень короткие имена, тяжелые
неанглийская фонология или два профиля со схожими по звучанию именами.
ухудшите точность — при необходимости настройте `sensitivity` для каждого профиля.

### Вариант Б — openWakeWord (бесплатная обученная модель)

Назовите встроенную модель (`hey_jarvis`, `alexa`, `hey_mycroft`, …) или обучите
пользовательская модель (≈75–90 минут на бесплатном графическом процессоре/Colab) для максимальной надежности, падение
файл `.onnx` где-нибудь и укажите на него ссылку:

```yaml
wake_word:
  enabled: true
  provider: openwakeword
  phrase: "computer"
  openwakeword:
    model: ~/.hermes/wakewords/computer.onnx   # or a built-in name like hey_jarvis
```

Ссылки на обучение:

- [openWakeWord](https://github.com/dscripka/openWakeWord)
- [обучение Colab в 2026 году](https://github.com/alfiedennen/openwakeword-colab-2026)

:::tip Выберите отличительную фразу
Фразы для бодрствования, которые не конфликтуют с повседневной речью, лучше всего обобщают. Два
слоги с необычным словом (подпадает под определение «Гермес») превосходят обычные слова, такие как
«Привет» или «Стоп».
:::

### Вариант C — Дикобраз (пользовательское ключевое слово в секундах)

Создайте ключевое слово «Эй, Гермес» в [Picovoice Console](https://console.picovoice.ai/),
скачайте `.ppn` и:

```yaml
wake_word:
  enabled: true
  provider: porcupine
  phrase: "hey hermes"
  porcupine:
    keyword: ~/.hermes/wakewords/hey_hermes.ppn
```

Установите ключ доступа в `~/.hermes/.env`:

```bash
PORCUPINE_ACCESS_KEY=your-key-here
```

## Требования

- Рабочий микрофон и аудиостек `sounddevice` + `numpy` (совместно с
  голосовой режим).
- Поставщик STT для расшифровки голосовой команды — локальный `faster-whisper`.
  работает «из коробки»; см. [Голосовой режим](/user-guide/features/voice-mode) для
  полный список провайдеров.
- Поставщик TTS для озвучивания ответа (по умолчанию `edge-tts` работает без
  ключ). Поток следа полностью свободен от рук, поэтому переключатель отказывается ставиться на охрану до тех пор, пока
  готовы как STT, так и TTS — их настраивает `hermes tools` (раздел Voice).
- Механизм пробуждения (устанавливается автоматически или `hermes-agent[wake]`).

`/wake status` точно сообщает, чего не хватает, если прослушиватель не запускается.

### «Слушаю», но никогда не просыпаюсь (macOS)

macOS предоставляет доступ к микрофону для каждого **процесса**. STT работает в настольном приложении
доказывает, что *рендерер* имеет доступ к микрофону — прослушиватель пробуждения работает на Python
*бэкенд*, которому нужен собственный грант. Без него CoreAudio передает серверной части
«рабочий» поток, который всегда обеспечивает тишину, поэтому ухо показывает, что слушаю
но эта фраза никогда не срабатывает. Гермес обнаруживает это (показывает `/wake status`
«микрофон передает только тишину»; подсказка уха на рабочем столе содержит тот же намек).
Исправление: Системные настройки → Конфиденциальность и безопасность → Микрофон → включить Гермес.
серверную часть (это может быть ваш терминал, `python` или Hermes), затем переключите
слово пробуждения выключается и включается.

### «Прослушивает», но слышит тишину (Windows)

Для настольных систем «Нажми и говори» и «Захват слов по пробуждению» используются разные пути микрофона.
Функция «Нажми и говори» использует захват браузера настольного приложения, в то время как
Прослушиватель пробуждающего слова открывает поток PortAudio в серверной части Python. Можно работать
в то время как другой выбирает тихий или непригодный для использования ввод Windows.

`/wake status` сообщает о выбранном устройстве ввода и API хоста аудио Windows.
Когда он сообщает о тишине, установите `wake_word.input_device` в числовой индекс или
однозначное имя рабочего входа PortAudio, затем переключите слово пробуждения:

```bash
hermes config set wake_word.input_device "Microphone Array"
```

Используйте `null`, чтобы вернуться к настройкам процесса по умолчанию:

```bash
hermes config set wake_word.input_device null
```

## Примечания и ограничения

- **Только локальные поверхности.** Слово пробуждения запускается в CLI, TUI и графическом интерфейсе рабочего стола —
  везде, где доступен локальный микрофон. Он не запускается в обмене сообщениями
  шлюз (Telegram, Discord, …), у которого нет микрофона.
- **По одному микрофону.** Детектор отпускает микрофон во время подачи команды.
  записывает и возвращает его после окончания хода, чтобы он не конфликтовал с захватом голоса.
- **Конфиденциальность.** Обнаружение горячих слов осуществляется локально. Установите `sensitivity` выше, если получите
