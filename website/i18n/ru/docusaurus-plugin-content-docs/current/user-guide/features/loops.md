# Повторяющиеся циклы (`/loop`)

`/loop` повторно запускает приглашение (или команду с косой чертой) с повторяющейся частотой **внутри текущего сеанса**. Каждое пробуждение — это настоящий поворот агента: Hermes заново считывает текущее состояние — последний результат CI, новейшую глубину очереди, текущий файл — выполняет работу, отчитывается и молчит до следующего тика.

Это вариант Гермеса **Клода Кода `/loop`** (и его псевдонима `/proactive`, который работает и здесь). Если [`/goal`](./goals.md) управляется судьей — «продолжайте работать, пока эта цель не будет достигнута» — `/loop` управляется таймером: «делайте это снова каждые N минут (или всякий раз, когда это имеет смысл), пока что-то не скажет «стоп».

## Когда это использовать

- **Опрос внешнего состояния.** «Наблюдайте за развертыванием/запуском CI/очередью и сообщайте мне, когда она изменится». Канонический вариант использования.
- **Итерировать до зеленого цвета.** «Запустите тесты, исправьте то, что не удалось, повторяйте, пока они не пройдут».
- **Мониторинг во время рабочего сеанса.** Следите за частотой ошибок или ходом выполнения долгой работы, одновременно занимаясь чем-то другим в том же разговоре.
- **Периодическая очистка.** Повторно запускайте проверку или сводку состояния каждые N минут во время длительного сеанса.

Если работа должна выполняться **автоматически** — в ночное время, по реальному расписанию, после перезапуска вашего терминала — вместо этого используйте [задание cron](./cron.md). `/loop` живет внутри сеанса; cron живет вне их всех. А когда задача представляет собой одну цель с определением выполненной, обычно лучше подходит [`/goal`](./goals.md).

## Быстрый старт

```
/loop 5m check the deploy status and tell me if it's live yet
```

Что вы увидите:

1. **Петля принята** — `↻ Loop set (every 5m): check the deploy status…`
2. **Первое пробуждение через 5 минут** — пока сеанс простаивает, Hermes вводит пробуждение и запускает обычный ход в соответствии с текущим состоянием.
3. **Повторять** — каждые 5 минут, пока не сработает условие остановки или пока вы не остановите его.

Выполните команду косой черты так же легко:

```
/loop 10m /recap
```

## Два режима частоты вращения педалей

**Фиксированный интервал — вы устанавливаете часы.** Укажите интервал (`30s`, `5m`, `2h`, `1h30m`), и цикл сработает по этому расписанию. Используйте его, когда объект, который вы смотрите, меняется на собственной временной шкале:

```
/loop 2m poll the build at ci.example.com/job/42 and ping me the moment it finishes
```

**Самостоятельный темп — Hermes устанавливает часы.** Опустите интервал, и цикл будет изменяться сам по себе: он начинается с пола (по умолчанию 1 минута), и, пока ответы агента перестают меняться, он отступает в геометрической прогрессии — 2 м, 4 м, 8 м, вплоть до потолка (15 минут по умолчанию). В тот момент, когда ответ отличается от предыдущего, ритм снова снижается. Обнаружение изменений — это локальное сравнение дайджестов (временные метки игнорируются), поэтому ожидание бездействия не требует дополнительных затрат:

```
/loop keep an eye on the migration and summarize progress
```

Эмпирическое правило: **фиксированный интервал, когда работа управляется внешними часами; в самостоятельном темпе, когда работа задает ритм.**

## Условия остановки

Цикл заканчивается, когда срабатывает любое из следующих событий:

| Состояние | Как |
|---|---|
| Агент решает, что дело сделано | Приглашение к пробуждению учит агента заканчивать свой ответ цифрой `LOOP_COMPLETE` на отдельной линии, когда задача завершена или не решена. |
| Кепка для бега | `--times N` — остановка после N пробуждений. |
| Доказательное состояние | `--until <condition>` — после каждого пробуждения тот же вспомогательный судья, который управляет `/goal`, проверяет ответ на соответствие вашему условию (открытие при отказе: сломанный судья никогда не вклинивает цикл). |
| Вы | `/loop stop` (или `/loop pause`, чтобы сохранить его). |
| Поддержка бюджета | `loops.max_ticks` (по умолчанию 100) приостанавливает цикл, чтобы автоматический сеанс не мог сжигать токены вечно. `0` = без ограничений. |

Примеры:

```
/loop 2m poll CI --times 30
/loop 5m watch the queue --until queue depth reaches zero
```

## Команды

| Команда | Что он делает |
|---|---|
| `/loop [interval] <prompt> [--times N] [--until <cond>]` | Запустите (или замените) цикл для этого сеанса. |
| `/loop` или `/loop status` | Покажите частоту шагов, срабатывание тиков и время до следующего пробуждения. |
| `/loop pause` | Прекратите стрельбу, не потеряв петлю. |
| `/loop resume` | Поднимите его обратно. |
| `/loop stop` | Завершите цикл. |
| `/proactive …` | Псевдоним для `/loop` (паритет кода Клода). |

Работает в CLI, TUI (`hermes --tui`), чате веб-панели, настольном приложении и каждой платформе шлюза (Telegram, Discord, Slack, WhatsApp,…). На платформах обмена сообщениями шлюз запускает пробуждения даже между вашими сообщениями — цикл принадлежит сеансу чата, и его результаты приходят в виде обычных ответов.

## Смешивание с `/goal`

Обе функции вводят синтетические повороты на границах простоя, поэтому они следуют одному правилу: **сеанс принадлежит активной цели.** Пока `/goal` активно движется (судья говорит «продолжить»), пробуждение цикла откладывается. Цикл возобновляется с использованием времени простоя, как только цель завершится, приостановится или припаркуется на барьере ожидания (`/goal wait` или автоматический вердикт судьи WAIT). Припаркованная цель плюс `/loop` — это естественная комбинация: цель ожидает большую асинхронную вещь, в то время как цикл поддерживает контрольный сигнал на чем-то другом.

Настоящее пользовательское сообщение всегда выигрывает у обоих — пробуждения срабатывают только во время бездействия сеанса и ничего из вашего не стоит в очереди.

## Подробности поведения

- **Пробуждение — это обычный поворот роли пользователя.** Никакой мутации системных подсказок, никакой замены набора инструментов — кэширование подсказок остается неизменным.
- **Выдерживает `/resume` и сжатие.** Состояние цикла сохраняется для каждого сеанса и мигрирует через границы контекстного сжатия, так же, как `/goal`.
- **Один цикл на сеанс.** Установка нового `/loop` заменяет старый. Запустите несколько циклов, запустив несколько сеансов (или используйте cron для множества расписаний).
- **Прерывание хода пробуждения (Ctrl+C) приостанавливает цикл** — это можно восстановить с помощью `/loop resume`, поэтому отмена фактически означает отмену.
- **Стоимость токена зависит от частоты вращения.** Каждый тик представляет собой полный ход агента. Сопоставьте интервал с тем, как часто на самом деле меняется состояние; предпочитаю самостоятельное ожидание в спокойном темпе.

## Конфигурация

```yaml
# ~/.hermes/config.yaml
loops:
  min_interval_seconds: 30       # floor for fixed intervals
  max_ticks: 100                 # backstop budget (0 = unlimited)
  self_paced_floor_seconds: 60   # self-paced starting cadence
  self_paced_ceiling_seconds: 900  # self-paced max backoff
```

Судья `--until` выполняет маршрутизацию через вспомогательную задачу `goal_judge`, поэтому переопределения `auxiliary.goal_judge.*` (поставщик, модель, max_tokens) также применяются к условиям цикла.

## `/loop` против `/goal` против cron

| | `/loop` | `/goal` | хрон |
|---|---|---|---|
| **Триггер** | Таймер (или самостоятельный темп) | Вердикт судьи после каждого хода | Расписание вне сеанса |
| **Живет** | Ваша текущая сессия | Ваша текущая сессия | Своя сессия за прогон |
| **Заканчивается, когда** | Стоп-условие/капс/вы | Цель достигнута / бюджет / вы | Вы удаляете работу |
| **Лучший вариант** | Опрос, мониторинг, периодические повторные выборы | Цель одна: повторять, пока не будет выполнено | Автоматические долгосрочные расписания |
