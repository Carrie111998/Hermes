# Использование компьютера

Агент Hermes может управлять вашим рабочим столом: щелкать мышью, печатать, прокручивать,
перетаскивание — в **фоновом режиме** на **macOS, Windows и Linux**. Ваш
курсор не перемещается, фокус клавиатуры не меняется, и ваш виртуальный
рабочие столы/пространства не включают вас. Вы и агент совместно работаете над
та же машина.

В отличие от большинства интеграций для использования на компьютере, это работает с **любыми инструментами, поддерживающими
модель** — Claude, GPT, Gemini или открытая модель на локальном сервере.
Конечная точка, совместимая с OpenAI. Нет никакой антропной схемы, о которой стоит беспокоиться.
о.

## Как это работает

Встроенный набор инструментов `computer_use` является рекомендуемой интеграцией Hermes. Это
говорит MCP через stdio с
[`cua-driver`](https://github.com/trycua/cua), фон с открытым исходным кодом.
драйвер для использования на компьютере. Каждая платформа использует соответствующую доступность +
входной стек под капотом:

| Платформа | Дерево доступности | Входная отправка |
|---|---|---|
| macOS | AX (частные SPI SkyLight) | `SLPSPostEventRecordTo` — с областью действия pid, без деформации курсора |
| Окна | Автоматизация пользовательского интерфейса | `SendInput` + `PostMessage` — нет кражи фокуса |
| Линукс | AT-SPI (X11 + Вейланд) | XTest (X11) / виртуальная клавиатура (Wayland) |

Результат один и тот же на каждой платформе: агент может прочитать
дерево доступности любого видимого окна И пост-синтезированные события
без вывода его на передний план, переключения виртуальных рабочих столов или перемещения
настоящий курсор ОС.

Для базового контракта — *почему* фоновый режим имеет значение,
инвариант без переднего плана, внутренние функции диспетчера щелчков — см.
**[cua.ai/docs/explanation/the-no-foreground-contract](https://cua.ai/docs/explanation/the-no-foreground-contract)**.

## Включение

**Новые установки уже содержат драйвер.** Установщик Hermes
(`install.sh` / `install.ps1`) предварительно устанавливает `cua-driver` (максимально возможное;
передайте `--skip-computer-use` / `-SkipComputerUse`, чтобы отказаться), чтобы включить
Использование компьютера — это просто изменение конфигурации:

- **`hermes tools`** → выберите `🖱️  Computer Use` — устанавливает драйвер
  автоматически, если он все еще отсутствует.
- **Панель управления/приложение для рабочего стола** → переключить набор инструментов «Использование компьютера» — если
  драйвер отсутствует, переключатель запускает установку в фоновом режиме
  автоматически (следите за прогрессом на панели набора инструментов).

**Откат вручную (старые установки, пропущенный этап установки):**

```
hermes computer-use install
```

При этом будет загружен и запущен установщик вышестоящего драйвера cua — `install.sh`.
в macOS/Linux, `install.ps1` в Windows. Используйте `hermes для использования компьютера
status`, чтобы проверить установку.

У вас уже есть cua-драйвер? Hermes повторно использует его, если он поддерживает среду выполнения 0.20.
контракт. Во время установки включение набора инструментов, `hermes update` и первый
`computer_use` вызова сеанса, Hermes проверяет локальную версию и
манифест. Он восстанавливает старую или неполную стандартную установку посредством
вышестоящий установщик (не более одного раза за сеанс во время выполнения). Бинарный файл
выбрано с `HERMES_CUA_DRIVER_CMD` пребыванием
под вашим контролем, поэтому Гермес сообщает о несовместимости и оставляет ее
без изменений.

Если вы сначала устанавливаете драйвер Cua, `cua-driver skills install` устанавливает драйвер Cua.
пакет навыков под `~/.cua-driver/skills/cua-driver`. Автоопределение Гермеса
запланировано продолжение cua-драйвера, поэтому в настоящее время укажите Hermes на этот каталог или
символически свяжите его с вашим пространством навыков. Вы также можете зарегистрировать необработанные инструменты Cua MCP как
собственный сервер MCP, но это альтернатива для пользователей, которым нужен низкоуровневый сервер.
интерфейс. Встроенный набор инструментов обеспечивает действия Hermes, настройку,
согласования и диагностика.

После установки, независимо от того, какой путь вы выбрали, предоставьте
Предварительные требования, соответствующие платформе:

| Платформа | Предварительные требования |
|---|---|
| **macOS** | Системные настройки → Конфиденциальность и безопасность → **Специальные возможности** + **Запись экрана**. Предоставьте удостоверение, названное `hermes computer-use doctor`. Стандартный режим использует CuaDriver.app; ограниченный и неограниченный режимы используют идентификатор хоста Hermes. |
| **Окна** | На момент установки нет. Если вы используете SSH (не RDP/консоль), вам нужен шаблон автозапуска — см. [cua.ai/docs/how-to-guides/driver/windows-ssh](https://cua.ai/docs/how-to-guides/driver/windows-ssh) для прокси-сервера сеанса 0 ↔ сеанса 1+. |
| **Линукс** | Доступный сервер отображения: `DISPLAY` установлен для X11 или `XDG_SESSION_TYPE=wayland`. Для захвата сеансов Wayland требуется мост XWayland. AT-SPI должен быть включен (по умолчанию в GNOME/KDE/Xfce). |

Затем запустите сеанс с включенным набором инструментов:

```
hermes -t computer_use chat
```

или добавьте `computer_use` в список доступных наборов инструментов в `~/.hermes/config.yaml`.

## Режимы разрешений и профили браузера для входа в систему

Hermes отображает существующий пользовательский интерфейс одобрения на неизменяемую среду выполнения cua-driver.
режимы. Режим разрешений, утверждение манифеста возможностей и существующий профиль
грант - это настройки запуска. Они не могут измениться после запуска среды выполнения:

| Сеанс Гермеса | режим cua-драйвера | Человеческое вмешательство | `existing_profile` |
|---|---|---|---|
| Ручное или интеллектуальное одобрение (по умолчанию) | `standard` | Обычные разрешения Hermes; Куа останавливается на своей охраняемой границе | Отказывается, если `computer_use.grant_existing_profile: true` (однократное согласие на настройку) |
| `computer_use.permission_mode: bounded` + проверенный манифест | частный демон `bounded` | Вы просматриваете и утверждаете манифест возможностей один раз при запуске | Разрешено только в пределах объявленных профилей/источников/инструментов манифеста; все остальное не работает закрыто |
| `--yolo`, `/yolo` или `approvals.mode: off` | частный демон `unrestricted` | Одно явное принятие риска Гермеса; нет подсказок Cua во время выполнения | Отказывается, если только `computer_use.grant_existing_profile: true`; YOLO не заменяет этот грант |

### Прикрепление к браузеру, в котором вы вошли в систему

Агент может управлять уже открытым окном Chrome/Edge, включая
зарегистрированный профиль — **без перезапуска браузера, копирования профиля или
касаясь вкладок**. Поскольку доступ к DevTools открывает доступ к этому профилю в реальном времени.
страниц, файлов cookie и хранилища, cua-драйвер требует явного человеческого разрешения, которое
Обычное одобрение инструмента не может заменить. Вы соглашаетесь один раз в config.yaml:

```yaml
computer_use:
  grant_existing_profile: true
```

Затем Hermes запускает среду выполнения cua-драйвера с правом доверенного запуска.
(`--grant existing-profile`) и
`cua_browser_prepare` с существующим профилем успешно справляется с точным
`(pid, window_id)` агент доказывает. Оставьте `false` (по умолчанию) и
вложение существующего профиля не закрывается; изолированные профили, принадлежащие драйверу, работают
в любом случае и являются тем, что предпочитает агент.

### Ограниченный режим для повторяемой автоматизации

Для периодической автоматизации браузера (задания cron, запланированные исследования по
приложение, прошедшее проверку подлинности), режим `bounded` использует манифест возможностей, который вы просматриваете один раз:

```yaml
# config.yaml
computer_use:
  permission_mode: bounded
  capability_manifest: ~/.hermes/cua-manifest.yaml
```

В манифесте указаны приложения, типы профилей браузера, разрешенные источники и
типизированные инструменты, которые может использовать сеанс (см.
[ссылка на режимы разрешений cua-driver](https://cua.ai/docs/reference/cua-driver/permission-modes)
за формат). Hermes запускает частную среду выполнения с
`--capability-manifest ... --approve-capability-manifest`; что-нибудь снаружи
манифест не закрывается внутри cua-драйвера. Отсутствующий или нечитаемый манифест
громкий сбой при запуске сеанса, а не тихое понижение версии. Сессия ЙОЛО
все еще переопределяет ограничение для этого одного сеанса.

В macOS демоны частного сеанса запускаются через установленную
`CuaDriver.app` Bundle (так что разрешение предоставляет атрибут собственному драйверу).
личность вместо сброса при каждой сборке Hermes), и Hermes проверяет
подпись кода пакета — точный идентификатор `com.trycua.driver` и
официальная команда подписантов — перед ее запуском. Если вы собираете cua-драйвер из
источник (без знака), явно согласитесь:

```yaml
# config.yaml
computer_use:
  allow_unsigned_driver: true   # local driver development only
```

Каждый транспорт MCP владеет частным сеансом жизненного цикла внутри своей среды выполнения. А
имя общедоступного сеанса — это всего лишь метка для идентификации курсора и области сеанса.
государство. Он не выбирает, не передает и не поддерживает среду выполнения. Выключение `/yolo`,
сброс или закрытие сеанса Hermes, очистка отмены или выход из процесса
закрывает этот транспортный сеанс. Hermes также останавливает частные среды выполнения, которые он
запускается для ограниченного, неограниченного доступа или доступа к существующему профилю. Один Гермес
диалог не может изменить режим или разрешения другой среды выполнения. В macOS
стандартная среда выполнения с грантом существующего профиля использует новый CuaDriver.app
демон в частном сокете. Ограниченный и неограниченный режимы используют частное
встроенный сервис под идентификатором хоста Hermes.

`smart` утверждение остается `standard`: классификация LLM не может заменять
проверенный манифест или грант во время запуска.

## `hermes computer-use doctor` — ваша первая сортировочная остановка

`hermes computer-use doctor` запускает структурированный драйвер cua-driver
`health_report` Инструмент MCP и печатает матрицу для каждой проверки. Это сингл
самый быстрый способ узнать, *почему* действие не работает.

```
$ hermes computer-use doctor
⚠️  cua-driver VERSION on darwin: degraded
  ✅ binary_version: cua-driver VERSION
  ✅ platform_supported: macOS 26.4.1 (arm64)
  ✅ session_active: MCP session is active.
  ❌ bundle_identity: Process has no CFBundleIdentifier.
      → Run the binary inside CuaDriver.app so TCC grants attribute correctly.
  ✅ tcc_accessibility: Accessibility is granted.
  ✅ tcc_screen_recording: Screen Recording is granted.
  ✅ ax_capability: AX is trusted and reachable.
  ✅ screen_capture_capability: ScreenCaptureKit reachable; 1 display(s) shareable.
```

- **Код выхода 0**, когда общее число `ok` — все подключено.
- **Код выхода 1** при `degraded` или `failed` — хотя бы одна проверка не удалась; подсказка к каждой ошибке подскажет, что исправить.
- **Код выхода 2**, когда сам двоичный файл cua-драйвера недоступен.

Полезные флаги:

- `--include CHECK` — запускать только перечисленные проверки (повторить несколько проверок)
- `--skip CHECK` — пропустить проверку (выигрывает `--include`)
- `--json` — выдает необработанную структурированную полезную нагрузку той же формы, что и
  `tools/call health_report` Ответ MCP

Матрица проверки зависит от платформы: `bundle_identity` / `tcc_*` — это
`skip` в Windows + Linux, потому что эти концепции неприменимы.
`ax_capability` проверяет AX в macOS, UIA в Windows, AT-SPI в Linux —
у каждого есть правильная диагностическая подсказка, когда он не может добраться.

## Курсор агента и сеансы

Когда агент начнет действовать, вы увидите скользящий **тонированный курсор**.
по экрану туда, где происходит каждый щелчок/набор/прокрутка. Настоящий
Курсор ОС никогда не перемещается. Наложение показывает, где действует агент. Каждый
Запуск Hermes объявляет общедоступный драйвер cua **имя сеанса** (что-то вроде
`hermes-3a7b9c14d2e8`). Имя обозначает идентификатор курсора и связанное с ним состояние, поэтому
одновременные запуски и субагенты получают отдельные курсоры. Компания MCP Transport владеет
частный сеанс жизненного цикла внутри среды выполнения; публичное имя — нет.

Накладной курсор носит косметический характер — захватывает, щелкает и печатает всю работу.
без этого. Гермес автоматически отключает его, если это известный сбой.
режим: macOS (загрузка ЦП в режиме ожидания), безголовый Linux/WSL2/контейнеры и
**Рабочие столы Linux X11** (наложение представляет собой полноэкранное окно, всегда расположенное сверху).
который может зависать в каждом рабочем пространстве после нечистого завершения сеанса,
заклинивание ввода с рабочего стола). Linux Wayland и Windows сохраняют наложение. Установить
`computer_use.no_overlay: false` в `config.yaml`, чтобы принудительно переместить курсор
(или `true`, чтобы отключить его) на любой платформе.

Настройте курсор с помощью флагов CLI `cua-driver` или среды выполнения.
`set_agent_cursor_style` Инструмент MCP — см.
[cua.ai/docs/how-to-guides/driver/personalize-cursor](https://cua.ai/docs/how-to-guides/driver/personalize-cursor)
для полного меню (встроенный силуэт `arrow` и `teardrop`, пользовательский
SVG/PNG/ICO через `--cursor-icon`, градиентные цвета во время выполнения, цветение
гало).

## Идем глубже — набор навыков cua-driver

Гермес сохраняет свои навыки упаковки (`skills/autonomous-ai-agents/computer-use/SKILL.md`)
сосредоточился на рабочем процессе `computer_use` со стороны Hermes и словаре действий. Для
сведения о платформе, семантика записи, взаимодействие со страницами браузера и другое.
глубокое поведение Cua, установите пакет навыков, который поставляется командой cua-driver, и
поддерживает непосредственно:

```
cua-driver skills install
```

Команда устанавливает пакет под `~/.cua-driver/skills/cua-driver`. Гермес
автоопределение — это запланированное продолжение cua-драйвера, поэтому в настоящее время укажите Hermes на
этот каталог или создайте символическую ссылку на него в своем пространстве навыков. Обертка остается
Уровень рабочего процесса и указывает на установленный Куа навык поведения водителя.
пакет содержит:

| Файл | Тема |
|---|---|
| `SKILL.md` | Кросс-платформенное ядро ​​(инвариант моментального снимка, контракт без переднего плана, диспетчеризация кликов, механика AX-дерева) |
| `MACOS.md` | Особенности macOS: контракт без переднего плана, навигация AXMenuBar, диспетчеризация кликов SkyLight, мост Apple Events JS |
| `WINDOWS.md` | Особенности Windows: дерево UIA, хостинг UWP/`ApplicationFrameHost`, изоляция сеанса 0, шаблон автозапуска |
| `LINUX.md` | Особенности Linux: дерево AT-SPI, X11/Wayland, обнаружение эмулятора терминала |
| `RECORDING.md` | Семантика траектории + видеозаписи |
| `WEB_APPS.md` | Советы по взаимодействию со страницей браузера |
| `TESTS.md` | Рабочий процесс воспроизведения по траектории |

Это **глубокие погружения на платформе, а не дубликаты навыка Гермеса** —
когда агент сообщает: «В Windows я нажал не на ту кнопку
элемент", он читает `WINDOWS.md` для контекста UIA/UWP, который
объясняет, почему и что делать по-другому.

`cua-driver skills status` показывает, что установлено и какой агент
жгуты, к которым он подключен. Сегодня список автоопределения охватывает Клода
Кодекс, Кодекс, OpenCode, OpenClaw и Антигравитация; **Гермес
автоматическое обнаружение планируется в качестве продолжения в `trycua/cua`** — до тех пор, пока
затем запустите `cua-driver skills install` один раз и направьте ремень безопасности на
результирующий каталог `~/.cua-driver/skills/cua-driver` (или символическая ссылка
его в ваше обычное пространство навыков).

## Быстрый пример

Подсказка пользователю: * «Найдите мое последнее письмо от Stripe и кратко изложите, что они от меня хотят».*

План агента (одинаковая форма на macOS/Windows/Linux —
модель заменяет идиоматический ярлык платформы и имя приложения):

1. `computer_use(action="capture", mode="som", app="Mail")` — получает
   снимок экрана приложения электронной почты со всеми элементами боковой панели, кнопками на панели инструментов,
   и строка сообщения пронумерована.
2. `computer_use(action="click", element=14)` — щелкает поле поиска.
3. `computer_use(action="type", text="from:stripe")`
4. `computer_use(action="key", keys="return", capture_after=True)` —
   отправьте и получите новый скриншот.
5. Нажмите на верхний результат, прочитайте текст, подведите итог.

При этом курсор остается там, где вы его оставили, а электронное письмо
приложение никогда не выходит на первый план.

## Получение фактического скриншота

### Весь экран и поверхность рабочего стола

Функция «Снимок экрана моего экрана» захватывает **все, что отображается в данный момент**.
составной захват всех видимых окон, например нажатие PrtScn. Это изображение имеет

## Безопасность

Гермес применяет многослойные ограждения:

- Деструктивные действия (нажмите, введите, перетащите, прокрутите, нажмите клавишу, focus_app)
  требуют одобрения — либо в интерактивном режиме через диалог CLI, либо через
  Кнопки одобрения платформы обмена сообщениями.
- Жестко заблокированные комбинации клавиш на уровне инструмента: очистка корзины, принудительное удаление,
  экран блокировки, выход из системы, принудительный выход.
- Шаблоны жестко заблокированных типов: `curl | bash`, `sudo rm -rf /`, вилка.
  бомбы и т. д.
- В системном приглашении агента явно указано: нет разрешения на нажатие.
  диалоговые окна, отсутствие ввода паролей, отсутствие следующих инструкций, встроенных в
  скриншоты.

Соединитесь с `approvals.mode: manual` в `~/.hermes/config.yaml`, если вы
хочу, чтобы каждое действие было подтверждено.

## Эффективность токена

Скриншоты стоят дорого. Hermes применяет четыре уровня оптимизации:

- **Выселение скриншотов** — адаптер Anthropic сохраняет только 3 самых
  последние скриншоты в контексте; старые становятся `[скриншот удален
  для сохранения контекста]` заполнители.
- **Отсечение сжатия на стороне клиента** — компрессор контекста обнаруживает
  результаты мультимодального инструмента и удаление частей изображения из старых.
- **Оценка токена с учетом изображений** — каждое изображение считается примерно за 1500.
  токены (фиксированная ставка Anthropic) вместо длины символов в кодировке Base64.
- **Редактирование контекста на стороне сервера (только Anthropic)** — когда оно активно,
  адаптер включает `clear_tool_uses_20250919` через `context_management`, поэтому
  API Anthropic очищает результаты старых инструментов на стороне сервера.

Сеанс из 20 действий на дисплее 1568×900 обычно стоит около 30 тысяч токенов.
контекста скриншота, а не ~600 тыс.

## Ограничения

- **Производительность.** Фоновый режим работает медленнее, чем передний план —
  События, маршрутизируемые доступностью, занимают ~ 5–20 мс в macOS, ~ 3–10 мс в
  Windows UIA, ~5–15 мс в Linux AT-SPI по сравнению с прямой публикацией HID. Не
  заметно при нажатии на скорости агента; заметно, если попытаться записать
  скоростной забег.
- **Не ввод пароля с клавиатуры.** На `type` включены шаблоны жесткой блокировки.
  полезные нагрузки командной оболочки; для паролей используйте автозаполнение системы
  (Связка ключей macOS/Диспетчер учетных данных Windows/Связка ключей GNOME/
  KWallet).
- **Некоторые приложения не предоставляют дерево специальных возможностей.** Современные приложения UWP на
  Windows, Electron &lt;28 в Linux и несколько приложений macOS с пользовательскими
  рисование (Logic, Final Cut, некоторые игры) имеет редкие или пустые деревья AX.
  Вернитесь к пиксельным координатам, если дерево пусто, или пропустите
  задача целиком.
- **Windows: окна с повышенными правами (администратора) нельзя запускать из обычных.
  агент.** Windows UIPI (изоляция привилегий пользовательского интерфейса) обеспечивает
  границы уровня целостности: процесс средней целостности (по умолчанию
  Агент Гермеса) не может перечислить дерево UIA или ввести ввод с помощью мыши.
  в окно, принадлежащее процессу высокой целостности (администратору).
  Признак: `capture(mode='som')` возвращает 0 элементов, а `click(...)`
  сообщает об успехе, ничего не делая, хотя на скриншоте
  рендерится нормально (захват GDI находится ниже проверки целостности). Клавиатура
  события частично обходят UIPI, поэтому Tab/Enter по-прежнему может перемещаться по
  повышенный диалог. Это ограничение ОС, а не ошибка драйвера cua.
  влияет на каждый стек автоматизации Windows. Чтобы управлять поднятыми окнами,
  запустить сам агент Гермес на уровне Высокой целостности (запуск из
  надземный терминал); в противном случае выберите окна без повышенных привилегий.
- **Ошибки развертывания, зависящие от платформы:**
  - **macOS** использует частные SPI SkyLight. Apple может изменить их в любом
    Обновление ОС. Hermes предупреждает, если установленный cua-драйвер старше
    версию, с которой он тестировался.
  - Сеансы **Windows** SSH выполняются в **сеансе 0**, который не имеет
    интерактивный рабочий стол. Управлять Гермесом изнутри RDP/консоли
    сеанс или настройте автозапуск запланированной задачи cua-driver —
    [windows-ssh](https://cua.ai/docs/how-to-guides/driver/windows-ssh)
    есть рецепт.
  - **Linux** требует доступного сервера отображения. Безголовые серверы
    нужен Xvfb (`Xvfb :99 -screen 0 1920x1080x24`) перед
    `computer_use` может захватывать или внедрять события. Сеансы Pure Wayland
    нужен мост XWayland для захвата экрана (cua-driver's Wayland
    путь вставки обрабатывает ввод независимо).

Для кроссплатформенной автоматизации графического интерфейса без затрат на рабочий стол (и
без настройки TCC/сеанса 0/X11), набор инструментов `browser` использует
настоящий безголовый Chromium и является правильным решением для веб-задач.

## Конфигурация

Режим разрешений и манифест (см.
[Режимы разрешений](#permission-modes-and-logged-in-browser-profiles) выше):

```yaml
computer_use:
  permission_mode: standard        # standard (default) | bounded
  capability_manifest: ""          # capability manifest path, required for bounded
  grant_existing_profile: false    # opt-in: attach in standard or unrestricted mode
```

Переопределить двоичный путь драйвера (тесты/CI/локальные сборки):

```
HERMES_CUA_DRIVER_CMD=/path/to/your/cua-driver
```

Полностью поменяйте бэкэнд (для тестирования):

```
HERMES_COMPUTER_USE_BACKEND=noop   # records calls, no side effects
```

### Телеметрия

cua-драйвер поставляется с анонимной телеметрией использования (PostHog), включенной по умолчанию.
вверх по течению. **Hermes отключает его для вас** — при каждом вызове драйвера cua
(бэкэнд MCP, `status`, `doctor` и установка) Наборы Hermes
`CUA_DRIVER_RS_TELEMETRY_ENABLED=0` в среде водителя.

Чтобы снова принять участие (позволить cua-драйверу использовать собственное значение по умолчанию и отправлять телеметрию), установите
это в `config.yaml`:

```yaml
computer_use:
  cua_telemetry: true   # default: false (telemetry off)
```

Когда он включен, `hermes computer-use doctor` сообщает `telemetry: enabled`;
когда выключено (по умолчанию), он сообщает: «телеметрия: отключена через
CUA_DRIVER_RS_TELEMETRY_ENABLED`.

## Тестирование на локальной сборке cua-драйвера

Когда вы разрабатываете сам cua-драйвер или хотите протестировать
невыпущенное исправление — вместо этого укажите Hermes на двоичный файл, который вы собрали из исходного кода.
опубликованного релиза. Гермес разрешает водителю с
`shutil.which("cua-driver")` и ** не применяется.
`HERMES_CUA_DRIVER_VERSION`**, поэтому локальная сборка (указанная как
`0.0.0-local-*`) принимается как есть. Два подхода:

### Вариант А — `install-local` (собрать + поместить в PATH)

На странице оформления заказа `trycua/cua` запустите локальный установщик исходной версии. Это
собирает серверную часть Rust в режиме выпуска и помещает `cua-driver` в
тот же макет установки, который использует производственный установщик, с добавлением каталога bin
к вашему ПУТИ:

```powershell
# Windows (PowerShell), from the cua repo root
./libs/cua-driver/scripts/install-local.ps1 -NoAutoStart
```

```bash
# macOS / Linux, from the cua repo root  (defaults to a debug build without --release)
./libs/cua-driver/scripts/install-local.sh --release
```

- Windows выполняет сборку под `%USERPROFILE%\.cua-driver\packages\…`.
  и перекрестки
  `%LOCALAPPDATA%\Programs\Cua\cua-driver\bin` (добавлен в список пользователей
  ПУТЬ) к нему. macOS/Linux символизирует `cua-driver` в `~/.local/bin`
  (переопределить с помощью `--bin-dir <path>`).
- `-NoAutoStart` пропускает регистрацию демона входа `cua-driver-serve`.
  — для тестирования Гермеса он вам не нужен (см. примечания).

Затем откройте новую оболочку (чтобы было видно изменение PATH) и подтвердите:

```
cua-driver --version                 # local builds report 0.0.0-local-release
# Windows:      (Get-Command cua-driver).Source
# macOS/Linux:  which cua-driver
```

### Вариант Б — направить Гермес прямо на встроенный двоичный файл (самый быстрый цикл)

Полностью пропустите церемонию установки: `cargo build` и установите
`HERMES_CUA_DRIVER_CMD` в полученный двоичный файл. Лучше всего для быстрого
редактировать/создавать/тестировать.

```bash
cargo build -p cua-driver            # add --release for a release build; run from libs/cua-driver/rust
```

```
# Windows (.env)
HERMES_CUA_DRIVER_CMD=C:\path\to\cua\libs\cua-driver\rust\target\debug\cua-driver.exe
# macOS / Linux (.env)
HERMES_CUA_DRIVER_CMD=/path/to/cua/libs/cua-driver/rust/target/debug/cua-driver
```

### Убедитесь, что Hermes использует вашу сборку

- `hermes computer-use status` печатает разрешенный двоичный путь и
  версия.
- `hermes computer-use doctor` подтверждает, что двоичный файл доступен и
  выполняет полный путь MCP от начала до конца.
- В сеансе `computer_use(action="capture")` тренирует порожденный
  `cua-driver mcp` дочерний процесс.

### Примечания и ошибки

- **Hermes создает прокси-сервер `cua-driver mcp` stdio.** В обычном сеансе
  прокси-сервер подключается (и может запускаться) к стандартному компьютерному демону. В явном виде
  Hermes YOLO, вместо этого Hermes владеет частным `cua-driver serve --embedded`
  дочерний элемент и указывает прокси на его частный сокет или именованный канал. Окна
  Шаблон autostart/UIAccess по-прежнему имеет значение для интерактивного ввода сеанса 1+.
  из SSH — см. раздел «Ограничения».
- **Заблокированный двоичный файл в Windows.** Работающий демон `cua-driver-serve` может
  удерживайте `cua-driver.exe` и заблокируйте перезапись при перестроении.
  `install-local.ps1` переименовывает заблокированный двоичный файл
  автоматически; если вы `cargo build` вручную (вариант Б), остановите это
  сначала с помощью `cua-driver autostart disable` (или `schtasks /End /TN
  cua-driver-serve`).
- **Цикл перестройки.** После редактирования исходного кода cua-драйвера перезапустите его.
  `install-local` (восстанавливает, переустанавливает, переворачивает соединение `current`)
  для Варианта А или просто повторно `cargo build` для Варианта Б — без Гермеса
  изменения необходимы в любом случае.
- **Локальные сборки пропускают проверку версии.** Hermes предупреждает, когда
  установленный драйвер cua старше, чем его базовый уровень, протестированный для каждой ОС, но
  исключает сборки `0.0.0-local-*` dev, поэтому ваша локальная сборка никогда не
  вызывает это предупреждение.

## Устранение неполадок

**Первое действие, если что-то не так: запустите `hermes computer-use doctor`.**
Структурированная матрица каждой проверки сообщает вам (и любому агенту, помогающему вам
отладка) что именно не так.

Конкретные режимы отказа, которые врач не улавливает:

**`computer_use backend unavailable: cua-driver is not installed`** —
Запустите `hermes computer-use install`, чтобы получить двоичный файл cua-драйвера, или
запустите `hermes tools` и включите набор инструментов «Использование компьютера».

**Кажется, что клики не оказывают никакого эффекта** — Запишите и проверьте. Модальный ты
не видел, возможно, блокирует ввод. Закройте его с помощью `escape` или закрытия
кнопка.

**Индексы элементов устарели** — индексы SOM действительны только до
следующий `capture`. Повторный захват после любого действия, изменяющего состояние.
оболочка содержит непрозрачные `element_token`s для обнаружения устаревших — вы
увидеть явную ошибку, а не неправильный щелчок.

**"заблокированный шаблон в текстовом виде"** — текст, который вы пытались `type`
соответствует списку шаблонов опасных оболочек. Прервите команду или
пересмотреть.

**Пустые записи в Linux** — `DISPLAY` не задано, или вы используете чистую версию
Wayland без моста XWayland. `hermes computer-use doctor` будет
отметьте это как `ax_capability: fail` с подсказкой `Set DISPLAY (X11)…`.

**Пустые снимки в Windows через SSH** — вы находитесь в сеансе 0 (
сеанс обслуживания). Управляйте напрямую из RDP/консоли или настройте
шаблон автозапуска — см.
[cua.ai/docs/how-to-guides/driver/windows-ssh](https://cua.ai/docs/how-to-guides/driver/windows-ssh).
