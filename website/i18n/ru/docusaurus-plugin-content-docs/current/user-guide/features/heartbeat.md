# Контрольных импульсов сеанса (`/heartbeat`)

`/heartbeat` дает **текущему сеансу** одну повторяющуюся инструкцию. Всякий раз, когда сеанс простаивает и интервал истек, подсказка срабатывает как обычный пользователь — тот же разговор, тот же контекст, тот же кэш подсказок.

```
/heartbeat every 10m Check the deployment and report meaningful changes
```

Вдохновлен `/heartbeat` Prime-Agent. Адаптация Hermes сохраняет строгие инварианты потока сообщений: пульс вводится только между ходами (никогда в середине запуска), как простое сообщение роли пользователя.

## Heartbeat против cron: какой мне нужен?

Они выглядят похоже, но выполняют разные задачи:

| | `/heartbeat` | [`hermes cron`](./cron) |
|---|---|---|
| Вбегает | **Этот разговор** — полный контекст, память об обсуждении | Новая изолированная сессия за тик |
| Выдерживает перезапуск процесса | Состояние выживает (SessionDB); стрельба возобновляется в следующий раз, когда начнется сессия | Да — полностью надежный планировщик |
| Сколько | Один за сеанс | Неограниченное количество рабочих мест |
| Лучшее для | «Следите за X *в этой теме*, пока мы работаем» | Постоянные работы, отчеты, контроль, поставки |

Эмпирическое правило: если повторяющемуся приглашению нужен контекст разговора, используйте `/heartbeat`. Если это автономная работа, используйте cron.

## Команды

| Команда | Что он делает |
|---|---|
| `/heartbeat every <interval> <prompt>` | Установите (или замените) пульс сеанса. Интервалы: `90s`, `10m`, `2h`, `1d` (минимум 60 секунд). |
| `/heartbeat` или `/heartbeat status` | Покажите сердцебиение, его интервал и время до следующего пожара. |
| `/heartbeat pause` | Прекратить стрельбу без очистки. |
| `/heartbeat resume` | Возобновить (повторно привязывает таймер — никакого мгновенного затхлого огня). |
| `/heartbeat clear` | Убрать сердцебиение. |

`/hb` — это псевдоним. Работает на платформах CLI и шлюза (в Slack используйте `/hermes heartbeat …`).

## Подробности поведения

- **Только на холостом ходу.** Сердцебиение никогда не прерывает беговой поворот. Если агент занят, когда наступает срок действия тика, он срабатывает при следующем опросе в режиме ожидания.
- **Пропущенные тики объединяются.** Если сеанс был занят (или процесс не выполнялся) в течение нескольких интервалов, вы получаете **один** контрольный ход, а не отставание. Таймер повторно закрепляется при каждом возгорании.
- **Пользовательские сообщения выигрывают.** Пользовательское сообщение в очереди всегда имеет приоритет; Heartbeat ожидает опустошения входной очереди.
- **Кэш-безопасно.** Введенное приглашение представляет собой обычное сообщение пользователя. Никакой системной мутации, никакого изменения набора инструментов.
- **Постоянство.** Состояние находится в `SessionDB.state_meta` с ключом `heartbeat:<session_id>` — оно сохраняется в `/resume` и перемещается при ротации сеансов сжатия контекста. Для запуска требуется запуск процесса-владельца (сеанса CLI или шлюза); для расписаний, которые должны пережить что-либо, используйте cron.
- **Защитник «Не изобретай работу».** Введенное приглашение предписывает агенту коротко ответить и остановиться, когда ничего значимого не изменилось, чтобы простое тактовое сообщение не приводило к занятию работой.

## Пример

```
You: /heartbeat every 15m Check whether the CI run for PR #1234 finished; summarize the result when it does

  ♥ Heartbeat set (every 15m): Check whether the CI run for PR #1234 finished; ...

[15 minutes of you working on other things in the same session]

Hermes: [Heartbeat — recurring instruction, fires every 15m]
  💻 gh pr checks 1234   (1.2s)
  CI is still running (14/37 checks complete). Nothing to report yet.
```

Когда ответ перестанет меняться, `/heartbeat clear` его — или пусть он наблюдает.
