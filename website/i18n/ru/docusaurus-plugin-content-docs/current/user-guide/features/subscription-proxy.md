# Прокси-сервер подписки

Прокси-сервер подписки — это локальный HTTP-сервер, который позволяет внешним приложениям:
OpenViking, Karakeep, Open WebUI, все, что поддерживает OpenAI.
завершения чата — используйте подписку провайдера, управляемую Hermes, в качестве
Конечная точка LLM. Прокси-сервер присоединяет правильные учетные данные (обновляет их).
автоматически), поэтому приложению никогда не понадобится статический ключ API.

Это отличается от [API-сервера](./api-server.md):

| | API-сервер | Подписка на прокси |
|---|---|---|
| Чему это служит | Ваш агент (полный набор инструментов, память, навыки) | Вывод необработанной модели |
| Вариант использования | «Используйте Hermes в качестве сервера чата» | «Использовать мою подписку на портале из другого приложения» |
| Авторизация | Ваш `API_SERVER_KEY` | Любой носитель (прокси присоединяет реальный) |
| Вызовы инструментов | Да — агент запускает инструменты | Нет — только транзит |

Используйте сервер API, если вам нужен **агент** в качестве бэкэнда. Используйте
прокси, когда вам просто нужна **модель** через подписку.

## Быстрый старт

### 1. Авторизуйтесь у своего провайдера (однократно)

```bash
hermes portal
```

Это откроет ваш браузер для потока OAuth Nous Portal. Магазины Гермес
токен обновления в `~/.hermes/auth.json` — там же, где и все Hermes
входы провайдера в реальном времени.

### 2. Запустите прокси

```bash
hermes proxy start
```

```
Starting Hermes proxy for Nous Portal
  Listening on:  http://127.0.0.1:8645/v1
  Forwarding to: (resolved per-request from your subscription)
  Use any bearer token in the client — the proxy attaches your real credential.
```

Оставьте это работающим на переднем плане. Используйте `tmux`, `nohup` или systemd.
unit, если вы хотите, чтобы он выдержал выход из системы.

### 3. Направьте на него свое приложение

Конфигурация любого OpenAI-совместимого приложения принимает одну и ту же тройку:

```
Base URL:   http://127.0.0.1:8645/v1
API key:    anything (e.g. "sk-unused")
Model:      Hermes-4-70B    # or Hermes-4.3-36B, Hermes-4-405B
```

Прокси игнорирует заголовок `Authorization` вашего приложения и прикрепляет
ваши настоящие учетные данные Портала для восходящего запроса. Обновления происходят
автоматически, когда срок действия носителя приближается к концу.

## Доступные поставщики

```bash
hermes proxy providers
```

В настоящее время поставляется: `nous` (Nous Portal) и `xai` (xAI / Grok). Подробнее
Поставщиков OAuth можно добавить, реализовав `UpstreamAdapter`
интерфейс в `hermes_cli/proxy/adapters/`.

## Проверить статус

```bash
hermes proxy status
```

```
Hermes proxy upstream adapters

  [nous    ] Nous Portal — ready (bearer expires 2026-05-15T06:43:21Z)
```

Если вы видите `not logged in`, запустите `hermes portal`. Если ты видишь
`credentials need attention`, ваш токен обновления был отозван (редко —
произойдет, если вы вышли из веб-интерфейса портала) — просто запустите заново
`hermes portal`.

## Разрешенные пути

Прокси-сервер пересылает только те пути, которые фактически обслуживает восходящий поток. Для Нуса
Портал:

| Путь | Цель |
|------|---------|
| `/v1/chat/completions` | Завершения чата (потоковое + непотоковое) |
| `/v1/completions` | Дополнение устаревших текстов |
| `/v1/embeddings` | Вложения |
| `/v1/models` | Список моделей |

Другие пути (`/v1/images/generations`, `/v1/audio/speech` и т. д.) возвращаются.
404 с явной ошибкой, указывающей на разрешенные пути. Это сбивает с толку
клиентов от утечки странных запросов в восходящий поток.

## Настройка OpenViking для использования портала

[OpenViking](https://github.com/volcengine/OpenViking) — это контекст
база данных, которой нужен поставщик LLM для своей VLM (модель видения/языка)
используется для извлечения воспоминаний) и встраивания модели. С помощью прокси вы можете
укажите его `vlm.api_base` на ваш локальный прокси:

Изменить `~/.openviking/ov.conf`:

```json
{
  "vlm": {
    "provider": "openai",
    "model": "Hermes-4-70B",
    "api_base": "http://127.0.0.1:8645/v1",
    "api_key": "unused-proxy-attaches-real-creds"
  }
}
```

Затем запустите прокси в терминале рядом с `openviking-server`:

```bash
# Terminal 1
hermes proxy start

# Terminal 2
openviking-server
```

Вызовы VLM OpenViking теперь проходят через вашу подписку на портал.
для встраивания модели по-прежнему нужен собственный провайдер — портал действительно обслуживает
`/v1/embeddings` но выбор модели зависит от вашего уровня
поддерживает; проверьте `portal.nousresearch.com/models`.

## Настройка Karakeep (или любого приложения закладок/сумматора)

[Karakeep](https://karakeep.app/) использует OpenAI-совместимый API для
обобщение закладок. В его конфиге:

```bash
# Karakeep .env
OPENAI_API_BASE_URL=http://127.0.0.1:8645/v1
OPENAI_API_KEY=any-non-empty-string
INFERENCE_TEXT_MODEL=Hermes-4-70B
```

Тот же шаблон работает для Open WebUI, LobeChat, NextChat или любого другого
OpenAI-совместимый клиент.

## Разоблачение по локальной сети

По умолчанию прокси-сервер привязывает `127.0.0.1` (только localhost). Чтобы позволить другим
машины в вашей сети используют его:

```bash
hermes proxy start --host 0.0.0.0 --port 8645
```

⚠ **Внимание:** любой пользователь вашей сети теперь может использовать ваш портал.
подписка. Прокси не имеет собственной авторизации — он принимает любого носителя.
Используйте брандмауэр, VPN или обратный прокси-сервер с надлежащей аутентификацией, если вы подвергаете риску
это за пределами вашей доверенной сети.

## Ограничения скорости

Ограничения RPM/TPM вашего уровня портала применяются ко всему прокси-серверу.
прокси-сервер не разветвляется и не объединяется — это один носитель с полным
квота подписки. Мониторинг использования на
[portal.nousresearch.com](https://portal.nousresearch.com).

## Архитектура

Прокси намеренно минимален. По запросу:

1. Получите `POST /v1/chat/completions` из своего приложения.
2. Найдите текущие учетные данные адаптера (обновите, если срок их действия истекает).
3. Перешлите тело запроса дословно, используя `Authorization: Bearer <minted-key>`.
4. Выполните потоковую передачу ответа без изменений (с сохранением SSE).

Никакой трансформации. Нет журналирования тел запросов. Нет агентского цикла.
прокси — это сквозной канал для прикрепления учетных данных.

## Будущее: больше поставщиков OAuth

Система адаптеров является подключаемой. Добавление нового провайдера (например.
HuggingFace, конечная точка чата GitHub Copilot, Anthropic через OAuth)
требует реализации `UpstreamAdapter` в
`hermes_cli/proxy/adapters/<provider>.py` и зарегистрировать его в
`adapters/__init__.py`. Провайдеры, которые не совместимы с OpenAI на данный момент
уровне протокола (например, API Anthropic Messages) потребуется
слой трансформации, который выходит за рамки текущей формы.
