# Интеграция хоста ACP

Агент Hermes может работать как сервер ACP, позволяя хостам, совместимым с ACP, взаимодействовать с
Гермес через стдио. Редакторы могут отображать:

- сообщения в чате
- инструментальная деятельность
- различия файлов
- команды терминала
- запросы на одобрение
- потоковые фрагменты мышления/ответа

Другие хосты могут использовать тот же протокол для маршрутизации событий совместной работы в
Гермес. ACP хорошо подходит, если вы хотите, чтобы Hermes сохранил свою существующую индивидуальность.
настройки поставщика, память, навыки и инструменты, в то время как другое приложение владеет
разговорный транспорт.

## Что Hermes показывает в режиме ACP

Hermes использует тщательно подобранный набор инструментов `hermes-acp`, предназначенный для рабочих процессов редактора. Он включает в себя:

- файловые инструменты: `read_file`, `write_file`, `patch`, `search_files`
- инструменты терминала: `terminal`, `process`
- инструменты веб/браузера
- память, задачи, поиск сеанса
- навыки
- выполнить_код и делегировать_задачу
- видение

Он намеренно исключает вещи, которые не соответствуют типичному пользовательскому интерфейсу редактора, такие как доставка сообщений и управление заданиями cron.

## Установка

Установите Hermes обычным способом, затем добавьте дополнительный ACP из окна установки:

```bash
cd ~/.hermes/hermes-agent && uv pip install -e '.[acp]'
```

Это устанавливает зависимость `agent-client-protocol` и позволяет:

- `hermes acp`
- `hermes-acp`
- `python -m acp_adapter`

## Запуск сервера ACP

Любое из следующих действий запускает Hermes в режиме ACP:

```bash
hermes acp
```

```bash
hermes-acp
```

```bash
python -m acp_adapter
```

Hermes регистрируется на stderr, поэтому стандартный вывод остается зарезервированным для трафика ACP JSON-RPC.

Для неинтерактивных проверок:

```bash
hermes acp --version
hermes acp --check
```

### Инструменты браузера (необязательно)

Инструменты браузера (`browser_navigate`, `browser_click` и т. д.) зависят от
`agent-browser` пакет npm и Chromium, которые не являются частью Python
колесо. Установите их с помощью:

```bash
hermes acp --setup-browser           # interactive (prompts before ~400 MB download)
hermes acp --setup-browser --yes     # accept the download non-interactively
```

Это отдельная команда. Поток аутентификации терминала (`hermes acp --setup`) также предлагает загрузку браузера в качестве дополнительного вопроса после выбора модели, поэтому большинству пользователей никогда не придется запускать `--setup-browser` напрямую.

Что он делает:

- Устанавливает Node.js 26 в `~/.hermes/node/`, если он отсутствует.
- `npm install -g agent-browser @askjo/camofox-browser` в этот префикс (sudo не требуется — `--prefix` `npm` указывает на записываемый пользователем узел, управляемый Hermes)
- Устанавливает Playwright Chromium или использует обнаруженный системный Chrome/Chromium, если он доступен.

Начальная загрузка идемпотентна — ее повторный запуск выполняется быстро и пропускает уже выполненную работу.

## Настройка хоста

### Buzz-каналы (релейный мост)

[Buzz](https://github.com/block/buzz) — платформа для совместной работы на базе Nostr.
для людей и агентов. Его жгут `buzz-acp` соединяет каналы Buzz с любым ACP.
агент через stdio:

```text
Buzz relay <-- WebSocket --> buzz-acp <-- ACP over stdio --> Hermes Agent
```

Это транспортная интеграция, а не вторая установка «Гермеса».
подпроцесс, запущенный `buzz-acp`, использует ту же конфигурацию Hermes,
учетные данные, память, навыки и состояние `hermes` на этом хосте.

(Это отличается от [управляемой среды выполнения Buzz Desktop](#buzz-desktop), которая
порождает Гермеса локально в качестве предустановленной упряжи. Релейный мост предназначен для подключения к Buzz.
*каналы* как идентификатор агента, обычно на сервере.)

Предпосылки:

- Завершите установку ACP и `hermes acp --check` выше.
- Создайте `buzz-acp` и интерфейс командной строки `buzz` из
  [Репозиторий Buzz](https://github.com/block/buzz)
  (`cargo build --release -p buzz-acp`).
- Создайте специальную пару ключей Nostr для Hermes (`buzz-admin generate-key`) и
  зарегистрируйте его как члена ретранслятора (`buzz-admin add-member`). Каждому агенту нужен
  свою собственную идентичность — не используйте повторно пару человеческих ключей.
– Добавьте это удостоверение в нужные каналы Живой ленты.

Запустите мост с помощью:

```bash
export BUZZ_RELAY_URL="wss://community.example.com"
export BUZZ_PRIVATE_KEY="..."
export BUZZ_API_TOKEN="..."
export BUZZ_ACP_AGENT_COMMAND="hermes"
export BUZZ_ACP_AGENT_ARGS="acp"

buzz-acp
```

`BUZZ_API_TOKEN` необходим только тогда, когда реле обеспечивает аутентификацию по токену.
Не фиксируйте и не вставляйте закрытый ключ или токен API.

Для постоянного развертывания сервера запустите `buzz-acp` под диспетчером служб как
тот же пользователь операционной системы, которому принадлежит предполагаемый дом Hermes. Настройка,
генерация ключей, обнаружение каналов и параметры каждого агента описаны в
[README buzz-acp](https://github.com/block/buzz/tree/main/crates/buzz-acp).

Мост обнаруживает все каналы Buzz, участником которых является личность Hermes.
и автоматически подписывается, когда его добавляют на другой канал. Живой канал
поэтому членство остается границей доступа; Гермесу не нужен
отдельный список каналов в своей конфигурации.

Чтобы открыть доступ к активности Hermes ACP в Buzz Desktop владельца, добавьте:

```bash
export BUZZ_ACP_RELAY_OBSERVER="true"
```

При этом публикуются зашифрованные кадры наблюдателя типа `24200`, адресованные агенту.
владелец (НИП-АО Buzz's). Desktop отображает жизненный цикл, инструмент, реакцию и
поток использования в **журнале активности** агента. Реле обрабатывает эти кадры как
эфемерный, поэтому рабочий стол должен быть онлайн до начала хода; его местный обозреватель
архив — это долговечная история на стороне владельца.

Безголовые мосты сами отвечают на запросы разрешений ACP, потому что нет редактора
присутствует для отображения диалогов утверждения — см.
[Оставлять Живую ленту только для владельцев агентов] (#keep-buzz-agents-owner-only). Обработать мост
в качестве привилегированной автоматизации: используйте выделенную учетную запись операционной системы, ограничьте
какие пользователи Живой ленты могут запрашивать агента (`buzz-acp` поддерживает
отвечать на шлюз через `BUZZ_ACP_AGENT_OWNER`) и предоставлять членство только в каналах
где, как ожидается, будет работать Гермес.

### VS-код

Установите расширение [ACP Client](https://marketplace.visualstudio.com/items?itemName=formulahendry.acp-client).

2. Выберите **Агент Hermes** из встроенного списка агентов.
3. Подключитесь и начните общаться.


### Живая лента для рабочего стола

[Buzz](https://github.com/block/buzz) поставляется с агентом Hermes в качестве предустановленной среды выполнения.
Если Hermes установлен обычным способом, Базз обнаруживает его автоматически —
откройте **Настройки → Среды выполнения**, и под вашими средами выполнения появится Hermes.

Если обнаружение не удалось (более старые установки), убедитесь, что средство запуска ACP разрешает
ПУТЬ к оболочке входа:

```bash
command -v hermes-acp || command -v hermes
```

В последних установках записываются программы запуска `hermes` и `hermes-acp` в
`~/.local/bin`; запуск `hermes update` добавляет программу запуска `hermes-acp` в
старые установки. В качестве запасного варианта вручную настройте команду агента Buzz как
`hermes` с аргументами `["acp"]`.

#### Выбор модели

Buzz Desktop (v0.5.1+) отображает полное меню модели Hermes во время выполнения агента.
настройки. Список исходит от самого Hermes через ACP: в нем указаны все модели.
от провайдеров, которых вы аутентифицировали в Hermes (тот же инвентарь, что и за
`hermes model` и команда `/model`), поэтому модель отсутствует в меню.
означает, что у его провайдера нет учетных данных, настроенных на стороне Hermes.

Идентификаторы записей имеют вид `provider:model` (например, `openrouter:z-ai/glm-5.1`) или
`custom:<name>:<model>` для пользовательских конечных точек, совместимых с OpenAI, определенных в
`config.yaml`. Выбор модели применяется к сеансу этого агента; это не так
измените настройки по умолчанию для Hermes — используйте для этого `hermes model`.

#### Доступ к агентам Живой ленты только для владельцев

Живая лента создает каждого агента с параметром **Кто может разговаривать с этим агентом**, имеющим значение `Owner only`.
Оставьте его там, если среда выполнения — Hermes.

На этом пути сочетаются два поведения. В набор инструментов `hermes-acp` входит `terminal`.
и `execute_code`, а мост ACP Базза отвечает на запросы разрешения Hermes
себя с помощью `allow_once`, а не отображать их. Агент Гермеса в Buzz
поэтому запускает команды оболочки на хосте без запроса. Я попросил одного бежать
`rm -rf` к рабочему каталогу и удалил его, нигде не было подсказки.

Выбор `Anyone` предоставляет доступ к той же оболочке каждому автору, который может связаться
канал. Живая лента не предупреждает, когда вы ее выбираете.

Ни одно из очевидных способов смягчения последствий сегодня не работает:

- `approvals.mode: manual` заставляет Гермеса подать запрос на разрешение, но
  Живая лента автоматически одобряет ее, и команда продолжает выполняться.
- `platform_toolsets.acp` не сужает набор инструментов ACP, поэтому его нельзя использовать
  чтобы удалить `terminal`.

`!shutdown` от владельца останавливает агента в любом режиме, а Базз игнорирует это
команда от всех остальных.

## Конфигурация и учетные данные

В режиме ACP используется та же конфигурация Hermes, что и в CLI:

- `~/.hermes/.env`
- `~/.hermes/config.yaml`
- `~/.hermes/skills/`
- `~/.hermes/state.db`

Для разрешения поставщика используется обычный преобразователь времени выполнения Hermes, поэтому ACP наследует настроенного в данный момент поставщика и учетные данные. Hermes также рекламирует метод аутентификации терминала (`--setup`) для клиентов ACP, запускаемых при первом запуске; откроется интерактивная настройка модели/поставщика Hermes.

## Интеграция с хостом

Эти переменные устанавливаются **хост-процессом ACP** (редактором или другим агентом).

не устанавливайте их вручную в `.env` или `config.yaml`.

| Переменная | Значение | Эффект |
|----------|-------|--------|
| `HERMES_ACP_SKIP_CONFIGURED_MCP` | `1` | Пропустите запуск **глобально настроенных** серверов MCP с `config.yaml` до начала цикла ACP JSON-RPC. |

Обычно Hermes запускает каждый сервер MCP, настроенный в `config.yaml`, перед его запуском.
входит в цикл ACP JSON-RPC. Хост, владеющий самим MCP, передавая
серверы сеанса явно через `session/new` — этот глобальный запрос не требуется.
запуск, а несвязанный медленный или интерактивный сервер MCP в противном случае задержал бы
`initialize`. Установка маркера точно на `1` позволяет такому хосту пропустить его.

Пропускается только глобальное обнаружение `config.yaml`. **Серверы MCP предоставлены
сеанс ACP через `session/new` все еще зарегистрирован**, поэтому хост теряет
нет возможности, которую он просил. Любое другое значение (неустановленное, пустое, `0`, `false`) сохраняется.
поведение по умолчанию, поэтому несвязанная правдивая строка не может молча
отключить МКП.

## Поведение сеанса

Сеансы ACP отслеживаются диспетчером сеансов адаптера ACP в памяти во время работы сервера.

Каждая сессия сохраняет:

- идентификатор сеанса
- рабочий каталог
- выбранная модель
- текущая история разговоров
- отменить мероприятие

Базовый `AIAgent` по-прежнему использует обычные пути сохранения/регистрации Hermes, но область действия ACP `list/load/resume/fork` ограничена текущим серверным процессом ACP.

## Поведение рабочего каталога

Сеансы ACP привязывают cwd редактора к идентификатору задачи Hermes, поэтому файловые и терминальные инструменты работают относительно рабочей области редактора, а не серверного процесса cwd.

## Утверждений

Опасные команды терминала могут быть перенаправлены обратно в редактор в виде запросов на одобрение. Варианты утверждения ACP проще, чем поток CLI:

- разрешить один раз
- разрешать всегда
- отрицать

Увидите ли вы подсказку на самом деле, зависит от хоста. Хозяин может ответить на
запросить программно вместо того, чтобы показывать его вам, и в этом случае эти
варианты существуют в сети, но никогда не доходят до человека. Buzz Desktop делает это, поэтому
рассматривайте этот путь как автоматическое выполнение независимо от настройки `approvals`.

В случае тайм-аута или ошибки мост утверждения отклоняет запрос.

### Автоматическое одобрение редактирования на уровне сеанса

ACP предоставляет третий уровень между *разрешить один раз* и *разрешить всегда*: **Разрешить сеанс**. Выбор его из запроса разрешения редактора записывает утверждение только внутри текущего сеанса ACP — каждая последующая команда сопоставления в этом сеансе выполняется без запроса, но новый сеанс ACP (или перезапуск редактора) сбрасывает список и повторяет запрос в первый раз.

| Вариант | Ярлык редактора | Область применения | Сохраняется после перезапуска |
|---|---|---|---|
| `allow_once` | Разрешить один раз | Этот вызов одного инструмента | Нет |
| `allow_session` | Разрешить сеанс | Все совпадающие вызовы в этом сеансе ACP | Нет — очищается после завершения сеанса |
| `allow_always` | Разрешить всегда | Все будущие сессии | Да (записывается в постоянный белый список Hermes) |
| `deny` | Запретить | Этот вызов одного инструмента | Нет |

`allow_session` — это правильное значение по умолчанию для рабочего процесса редактора, в котором вы доверяете агенту на время выполнения задачи, но не хотите предоставлять долгосрочную запись в белом списке. Компромисс с безопасностью прост: чем шире область применения, тем меньше редактор будет вас прерывать и тем больше вреда может нанести неправильный агент (или быстрое внедрение) прежде, чем вы это заметите. Для незнакомых команд начните с `allow_once`; повысьте уровень до `allow_session`, как только вы увидите, что агент несколько раз правильно выполнил один и тот же шаблон; зарезервируйте `allow_always` для действительно идемпотентных команд, которым вы доверяете навсегда (например, `git status`).

Мост ACP сопоставляет эти параметры с семантикой внутреннего утверждения Hermes — `allow_always` записывает постоянную запись в белый список так же, как это делает CLI, а `allow_session` влияет только на кэш утверждений в процессе для текущего сеанса ACP.

## Устранение неполадок

###Агент ACP не отображается в редакторе

Проверьте:

- Для ручной/локальной разработки убедитесь, что команда хоста указывает на `hermes acp`.
- Гермес установлен и находится на вашем пути.
- Установлено дополнение ACP (`cd ~/.hermes/hermes-agent && uv pip install -e '.[acp]'`).

### ACP запускается, но сразу возникает ошибка

Попробуйте эти проверки:

```bash
hermes acp --version
hermes acp --check
hermes doctor
hermes status
```

### Отсутствуют учетные данные

В режиме ACP используются существующие настройки провайдера Hermes. Настройте учетные данные с помощью:

```bash
hermes model
```

или отредактировав `~/.hermes/.env`. Поток аутентификации терминала (`hermes acp --setup`) также может инициировать интерактивную настройку поставщика/модели.
