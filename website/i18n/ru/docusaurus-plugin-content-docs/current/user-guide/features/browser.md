# Автоматизация браузера

Агент Hermes включает в себя полный набор инструментов для автоматизации браузера с несколькими опциями серверной части:

- **Использование браузера в облачном режиме** через [Использование браузера](https://browser-use.com) для управляемого Chromium со скрытыми, резидентными прокси, решением CAPTCHA и многоразовыми профилями браузера.
- **Облачный режим базы браузера** через [Browserbase](https://browserbase.com) в качестве альтернативного поставщика облачных браузеров с инструментами защиты от ботов.
- **Режим использования браузера** через [Browser Use CLI 3.0](https://github.com/browser-use/browser-use), драйвер браузера по умолчанию для локального Chrome и облачных браузеров с использованием браузера.
- **Облачный режим Firecrawl** через [Firecrawl](https://firecrawl.dev) для облачных браузеров со встроенным парсингом.
- **Локальный режим Camofox** через [Camofox](https://github.com/jo-inc/camofox-browser) для локального просмотра с защитой от обнаружения (подмена отпечатков пальцев на основе Firefox)
- **Локальный движок Lightpanda** через [Lightpanda](https://lightpanda.io) — автономный браузер, созданный с нуля в Zig для машин; мгновенный запуск, в 16 раз меньше памяти и в 9 раз быстрее, чем Chrome, с автоматическим откатом Chrome для действий, которые он еще не поддерживает
- **Локальный CDP семейства Chromium** — подключите инструменты браузера к своему экземпляру Chrome, Brave, Chromium или Edge с помощью `/browser connect`.
- **Режим локального браузера** через `agent-browser` CLI и локальную установку Chromium.

Во всех режимах агент может перемещаться по веб-сайтам, взаимодействовать с элементами страниц, заполнять формы и извлекать информацию.

## Обзор

Страницы представлены в виде **деревьев доступности** (текстовых снимков), что делает их идеальными для агентов LLM. Интерактивные элементы получают идентификаторы ссылок (например, `@e1`, `@e2`), которые агент использует для нажатия и ввода текста.

Ключевые возможности:

- **Облачное выполнение с участием нескольких поставщиков** — использование браузера, база браузера или Firecrawl — локальный браузер не требуется.
- **Локальная интеграция с семейством Chromium** — подключитесь к работающему браузеру Chrome, Brave, Chromium или Edge через CDP для практического просмотра.
- **Поддержка облачных антиботов** — Использование браузера Cloud включает в себя скрытность, резидентные прокси и решение CAPTCHA.
- **Постоянные облачные профили** — Использование браузера Cloud может повторно использовать файлы cookie, localStorage и сохраненные пароли между сеансами.
- **Изоляция сеанса** — для каждой задачи создается собственный сеанс браузера.
- **Автоматическая очистка** — неактивные сеансы закрываются по истечении таймаута.
- **Анализ зрения** — снимок экрана + анализ AI для визуального понимания

### Браузер Использовать облачный режим

Чтобы использовать Browser Use в качестве поставщика облачного браузера, добавьте:

```bash
# Add to ~/.hermes/.env
BROWSER_USE_API_KEY=***
```

Получите ключ API на странице [browser-use.com](https://browser-use.com).

Использование браузера Облако запускает управляемый Chromium со включенным по умолчанию [стелсом](https://docs.browser-use.com/cloud/browser/stealth) и [резидентными прокси](https://docs.browser-use.com/cloud/browser/proxies), включает решение CAPTCHA и поддерживает [постоянные Profiles](https://docs.browser-use.com/cloud/guides/authentication) для файлов cookie, localStorage и сохраненных паролей.

### Облачный режим базы браузера

Чтобы использовать облачные браузеры, управляемые Browserbase, добавьте:

```bash
# Add to ~/.hermes/.env
BROWSERBASE_API_KEY=***
BROWSERBASE_PROJECT_ID=your-project-id-here
```

Получите свои учетные данные на [browserbase.com](https://browserbase.com).

:::note Выбор провайдера
Ключи `.env` выше предоставляют **только учетные данные**. Активный облачный браузер выбирается путем выбора `browser.cloud_provider`, написанного `hermes tools` → Автоматизация браузера (`browserbase`, `browser-use`, `camofox` или `nous` для подписки Nous). После того, как выбор существует, добавление или удаление ключа не приводит к переключению поставщиков, а выбранный поставщик с отсутствующим ключом вызывает ошибки с инструкциями по запуску `hermes tools` вместо автоматического перенаправления. Никогда не настроенные настройки по-прежнему автоматически определяются по доступным учетным данным.
:::

### Режим использования браузера (по умолчанию)

В режиме использования браузера вместо встроенных инструментов браузера используется [Browser Use CLI 3.0](https://github.com/browser-use/browser-use). Агент пишет и выполняет Python в браузере, чтобы щелкать, печатать, перетаскивать, очищать веб-страницы и взаимодействовать с ними.

**Это режим браузера по умолчанию**: если `browser.backend` не настроен и интерфейс командной строки `browser-use` работает (установлен или доступен через `uvx`), агент получает единственный инструмент `browser_exec`. Если CLI не запускается, Hermes автоматически возвращается к встроенным инструментам браузера.

Этот режим представляет собой **драйвер**, который взаимодействует с настроенным серверным интерфейсом вашего браузера: он управляет вашим локальным Chrome, облачным браузером с подпиской Nous, браузерами Browserbase, Firecrawl или «Использование браузера» — в зависимости от того, какой источник браузера выбран в `hermes tools` → Автоматизация браузера. Единственным исключением является Camofox, у которого нет конечной точки CDP, к которой можно было бы прикрепить жгут; Настройки Camofox автоматически сохраняют встроенные инструменты браузера.

**Параллельные сеансы**: `browser_exec` принимает аргумент `session=<name>`, который изолирует работу браузера по имени на каждом серверном уровне. Каждое имя получает свой собственный управляющий демон (собственный сокет IPC, журнал и состояние), а на облачных серверах — свой собственный браузер — поэтому параллельные субагенты или одновременные чаты больше не блокируют одно общее соединение. Если опустить `session`, используется общий демон по умолчанию, который подходит для просмотра по одному.

Чтобы отказаться и принудительно использовать встроенные инструменты браузера, используйте `/browser use off` или:

```yaml
# Add to ~/.hermes/config.yaml
browser:
  backend: "off"
```

(`backend: "browser-use"` остается действительным для явного принудительного включения режима.)

Собственные облачные браузеры Browser Use требуют `browser-use auth login` или `BROWSER_USE_API_KEY`; другие источники браузера используют свои существующие учетные данные без изменений.

:::примечание
Поскольку в режиме использования браузера на вашем компьютере выполняется написанный на модели Python,
Инструмент `browser_exec` предлагается только для сеансов, в которых также есть терминал.
доступ. Платформы, настроенные без набора инструментов терминала (например, заблокированный
поверхность обмена сообщениями) вместо этого сохраните инструменты браузера по умолчанию.
:::

### Облачный режим Firecrawl

Чтобы использовать Firecrawl в качестве поставщика облачного браузера, добавьте:

```bash
# Add to ~/.hermes/.env
FIRECRAWL_API_KEY=fc-***
```

Получите ключ API на сайте [firecrawl.dev](https://firecrawl.dev). Затем выберите Firecrawl в качестве поставщика браузера:

```bash
hermes setup tools
# → Browser Automation → Firecrawl
```

Дополнительные настройки:

```bash
# Self-hosted Firecrawl instance (default: https://api.firecrawl.dev)
FIRECRAWL_API_URL=http://localhost:3002

# Session TTL in seconds (default: 300)
FIRECRAWL_BROWSER_TTL=600
```

### Гибридная маршрутизация: облако для общедоступных URL-адресов, локальная для локальной сети/локального хоста

Когда облачный провайдер настроен, Hermes автоматически создает **локальную версию Chromium**.
для URL-адресов, которые разрешаются в частный адрес, адрес обратной связи или локальную сеть (`localhost`, `127.0.0.1`,
`192.168.x.x`, `10.x.x.x`, `172.16-31.x.x`, `*.local`, `*.lan`, `*.internal`,
Шлейф IPv6 `::1`, локальный канал `169.254.x.x`). Публичные URL-адреса продолжают использовать
облачный провайдер в том же разговоре.

Это решает распространенный рабочий процесс «Я разрабатываю локально, но использую Browserbase» —
агент может сделать снимок экрана с вашей информационной панелью по адресу `http://localhost:3000` И сделать снимок экрана
`https://github.com` без смены поставщика услуг или отключения защиты SSRF.
Поставщик облачных услуг никогда не видит частный URL-адрес.

Эта функция включена **по умолчанию**. Чтобы отключить его (все URL-адреса переходят на настроенный
облачный провайдер, как и раньше):

```yaml
# ~/.hermes/config.yaml
browser:
  cloud_provider: browserbase
  auto_local_for_private_urls: false
```

Если автоматическая маршрутизация отключена, частные URL-адреса отклоняются с
`"Blocked: URL targets a private or internal address"`, если вы также не установите
`browser.allow_private_urls: true` (что позволяет поставщику облачных услуг их использовать —
обычно не работает, поскольку Browserbase и т. д. не могут подключиться к вашей локальной сети).

Требования: локальная коляска использует тот же интерфейс командной строки `agent-browser`, что и чисто локальная версия.
режим, поэтому вам необходимо установить его (`hermes setup tools → Browser Automation`
автоматически устанавливает его). Пост-навигация перенаправляет с общедоступного URL-адреса на частный
адрес по-прежнему заблокированы (вы не можете использовать трюк с перенаправлением на внутренний адрес, чтобы достичь
вашей локальной сети через общедоступный путь).

### Реальный просмотр профиля (используйте свои собственные логины)

По умолчанию локальный просмотр выполняется в чистом одноразовом профиле — агент
ни в чем не залогинился. Включите **реальный просмотр профиля**, чтобы агент мог просматривать его.
как *вы*, с вашими существующими логинами и файлами cookie:

```yaml
# ~/.hermes/config.yaml
browser:
  use_real_profile: true
```

Если эта функция включена, Hermes копирует **активный** профиль вашего браузера по умолчанию – тот, который
вы на самом деле просматриваете (`Local State → profile.last_used`) с сохраненными файлами cookie
логины и настройки — в управляемый снимок под
`~/.hermes/browser-profile/<browser>/`, а затем создает этот снимок с помощью
упакованный Хром. Ваш действующий профиль браузера **никогда не открывается напрямую**:
снимок — это отдельный каталог, поэтому он не мешает работающему браузеру за
блокировка профиля и обходит блокировку Chrome 136+ по удаленной отладке
каталог профиля по умолчанию. Файлы аутентификации (cookie/логины/настройки)
повторно синхронизируется с вашим реальным профилем при каждом запуске нового сеанса, поэтому вход в систему
вы в своем браузере показываетесь в сеансе агента. Только активный
профиль копируется — снимки других профилей Chrome никогда не создаются.

Когда вы снова выключите переключатель, Hermes удалит хранилище снимков.
(`~/.hermes/browser-profile/`) при следующем использовании браузера, поэтому скопированный
учетные данные не сохраняются после отзыва согласия.

:::Примечание Windows: браузер должен быть полностью закрыт
В Windows работающий Chrome/Edge/Brave хранит свои базы данных файлов cookie и входов в систему с помощью
эксклюзивную блокировку (запретить все), поэтому Hermes не может скопировать их, пока браузер открыт.
open — он быстро терпит неудачу с сообщением «полностью закройте браузер и повторите попытку».
чем зависать или создавать сеанс с выходом из системы. Просмотр реального профиля в Windows
поэтому требуется **полный выход** браузера, включая любой фон/трей.
(функция Chrome «продолжать работу фоновых приложений при закрытии» сохраняет
`chrome.exe` жив после закрытия окна). macOS и Linux могут копировать
профиль во время работы браузера.

Установите `browser.real_profile_autoclose: true`, чтобы Гермес ** предлагал закрыть
браузер для вас**, когда он хранит профиль. Даже в этом случае Гермес никогда не
закрывает его автоматически — при блокировке профиля он всегда останавливается и
агент спрашивает вас первым; только с вашего согласия он запускает браузер Hermes
close-profile` (завершает дерево процессов браузера, привязанное к этому профилю,
потеря несохраненных вкладок), затем повторяет попытку. Если после этого профиль все еще заблокирован
(например, перезапускается фоновый экземпляр/экземпляр трея), Гермес остается заблокированным и сообщает вам
чтобы полностью выйти из браузера — он не будет зацикливаться или завершать работу снова сам по себе.
:::

- **Поддерживаемые браузеры:** Chrome, Edge, Brave, Chromium (в зависимости от вашей ОС).
  по умолчанию). Стандартный вариант, отличный от Chromium (например, Firefox), не закрывается с прозрачным
  сообщение, а не предположение.
- **Работает на любом сервере.** На локальном сервере это происходит автоматически после переключения
  включен. В **облачном** браузере агент по-прежнему может открыть
  локальный сеанс реального профиля по требованию с помощью `local` инструмента `browser_exec`
  аргумент (инструмент предоставляет этот аргумент только тогда, когда этот переключатель включен) —
  облачный сервер продолжает обслуживать все остальное.
– **Система безопасности:** это удобство, основанное на согласии, а не изоляция.

### Локальный режим Camofox

[Camofox](https://github.com/jo-inc/camofox-browser) — это автономный сервер Node.js, обертывающий Camoufox (вилка Firefox с подменой отпечатков пальцев C++). Он обеспечивает локальный просмотр с защитой от обнаружения без облачных зависимостей.

```bash
# Clone the Camofox browser server first
git clone https://github.com/jo-inc/camofox-browser
cd camofox-browser

# Build and start with Docker using the default container settings
# (auto-detects arch: aarch64 on M1/M2, x86_64 on Intel)
make up

# Stop and remove the default container
make down

# Force a clean rebuild (for example, after upgrading VERSION/RELEASE)
make reset

# Just download binaries without building
make fetch

# Override arch or version explicitly
make up ARCH=x86_64
make up VERSION=135.0.1 RELEASE=beta.24
```

`make up` немедленно запускает контейнер по умолчанию. Если вам нужны пользовательские настройки времени выполнения, такие как большая куча узла, VNC или постоянный каталог профиля, сначала создайте образ, а затем запустите его самостоятельно:

```bash
# Build the image without starting the default container
make build

# Start with persistence, VNC live view, and a larger Node heap
mkdir -p ~/.camofox-docker
docker run -d \
  --name camofox-browser \
  --restart unless-stopped \
  -p 9377:9377 \
  -p 6080:6080 \
  -p 5901:5900 \
  -e CAMOFOX_PORT=9377 \
  -e ENABLE_VNC=1 \
  -e VNC_BIND=0.0.0.0 \
  -e VNC_RESOLUTION=1920x1080 \
  -e MAX_OLD_SPACE_SIZE=2048 \
  -v ~/.camofox-docker:/root/.camofox \
  camofox-browser:135.0.1-aarch64
```

При включенном VNC браузер работает в режиме заголовка, и его можно смотреть в прямом эфире в браузере по адресу `http://localhost:6080` (noVNC). Вы также можете подключить собственный клиент VNC к `localhost:5901`.

Если вы уже запустили `make up`, остановите и удалите этот контейнер по умолчанию, прежде чем запускать собственный:

```bash
make down
# then run the custom docker run command above
```

Затем установите в `~/.hermes/.env`:

```bash
CAMOFOX_URL=http://localhost:9377
```

Если Camofox работает в Docker и вы хотите, чтобы он открывал веб-приложения, обслуживаемые с хост-компьютера, включите перезапись обратной связи. `CAMOFOX_URL` по-прежнему должен указывать на опубликованный хостом API управления, но URL-адреса страниц, такие как `http://127.0.0.1:3000`, должны открываться изнутри контейнера как `http://host.docker.internal:3000`:

```yaml
# ~/.hermes/config.yaml
browser:
  camofox:
    rewrite_loopback_urls: true
    loopback_host_alias: host.docker.internal  # default; use a LAN IP if needed
```

Эквивалентные переменные окружения:

```bash
CAMOFOX_REWRITE_LOOPBACK_URLS=true
CAMOFOX_LOOPBACK_HOST_ALIAS=host.docker.internal
```

Перезапись применяется только к URL-адресам навигации по страницам с узлами обратной связи (`localhost`, `127.0.0.1`, `::1`). Это не меняет `CAMOFOX_URL`. Оставьте его отключенным для установок Camofox, отличных от Docker, где браузер уже работает на хосте и URL-адреса обратной связи верны.

Или настройте через `hermes tools` → Автоматизация браузера → Camofox.

Camofox выбирается так же, как и любой другой серверный интерфейс браузера: выберите **Camofox** в `hermes tools` → Автоматизация браузера, который записывает `browser.cloud_provider: camofox` в `config.yaml`. `CAMOFOX_URL` — это всего лишь адрес сервера — при его установке серверная часть больше не будет выбираться сама по себе, как только существует выбор браузера (никогда не настроенные настройки все равно автоматически определяют его).

#### Постоянные сеансы браузера

По умолчанию каждый сеанс Camofox получает случайный идентификатор — файлы cookie и логины не сохраняются после перезапуска агента. Чтобы включить постоянные сеансы браузера, добавьте следующее в `~/.hermes/config.yaml`:

```yaml
browser:
  camofox:
    managed_persistence: true
```

Затем полностью перезапустите Hermes, чтобы новая конфигурация была принята.

:::предупреждение Вложенный путь имеет значение
Гермес читает `browser.camofox.managed_persistence`, **не** `managed_persistence` верхнего уровня. Распространенной ошибкой является запись:

```yaml
# ❌ Wrong — Hermes ignores this
managed_persistence: true
```

Если флаг установлен на неправильном пути, Hermes автоматически возвращается к случайному эфемерному `userId`, и ваше состояние входа в систему будет теряться при каждом сеансе.
:::

##### Что делает Гермес
- Отправляет детерминированный профиль `userId` в Camofox, чтобы сервер мог повторно использовать один и тот же профиль Firefox в разных сеансах.
— Пропускает разрушение контекста на стороне сервера при очистке, поэтому файлы cookie и входы в систему сохраняются между задачами агента.
- Привязывает `userId` к активному профилю Hermes, поэтому разные профили Hermes получают разные профили браузера (изоляция профилей).

##### Чего не делает Гермес
- Это не приводит к принудительному сохранению на сервере Camofox. Гермес отправляет только стабильный `userId`; сервер должен соблюдать это, сопоставляя этот `userId` с постоянным каталогом профиля Firefox.
- Если ваша сборка сервера Camofox рассматривает каждый запрос как эфемерный (например, всегда вызывает `browser.newContext()` без загрузки сохраненного профиля), Hermes не сможет сохранить эти сеансы. Убедитесь, что вы используете сборку Camofox, которая реализует сохранение профиля на основе идентификатора пользователя.

##### Убедитесь, что все работает

1. Запустите Hermes и ваш сервер Camofox.
2. Откройте Google (или любой другой сайт входа) в задаче браузера и войдите в систему вручную.
3. Завершите задачу браузера обычным способом.
4. Запустите новую задачу браузера.
5. Откройте тот же сайт еще раз — вы все равно должны войти в систему.

Если на шаге 5 вы выйдете из системы, сервер Camofox не поддерживает стабильную версию `userId`. Дважды проверьте путь к конфигурации, убедитесь, что вы полностью перезапустили Hermes после редактирования `config.yaml`, и убедитесь, что ваша версия сервера Camofox поддерживает постоянные профили для каждого пользователя.

##### Где живет государство

Hermes извлекает стабильный `userId` из каталога области профиля `~/.hermes/browser_auth/camofox/` (или эквивалента в каталоге `$HERMES_HOME` для профилей, отличных от профилей по умолчанию). Фактические данные профиля браузера находятся на стороне сервера Camofox и хранятся под ключом `userId`. Чтобы полностью сбросить постоянный профиль, очистите его на сервере Camofox и удалите каталог состояния соответствующего профиля Hermes.

#### Сеансы Camofox с внешним управлением

Когда другое приложение управляет видимым браузером Camofox (помощник на рабочем столе, пользовательская интеграция, другой агент), настройте Hermes для работы внутри того же удостоверения, а не создания собственного изолированного профиля.

Три ручки управляют поведением:

| Настройка | Конверт вар | Эффект |
|---------|---------|--------|
| `browser.camofox.user_id` | `CAMOFOX_USER_ID` | Camofox `userId` Hermes использует при создании вкладок. Установка этого параметра переводит сеанс в режим «управляемого извне». |
| `browser.camofox.session_key` | `CAMOFOX_SESSION_KEY` | `sessionKey` (он же `listItemId`) отправляется при создании вкладки. Используется для сопоставления существующей вкладки во время внедрения. По умолчанию используется значение для каждой задачи, если оно не установлено. |
| `browser.camofox.adopt_existing_tab` | `CAMOFOX_ADOPT_EXISTING_TAB` | Если это правда, Hermes вызывает `GET /tabs?userId=<user_id>` при первом использовании и повторно использует существующую вкладку перед созданием новой. |

Переменные Env имеют приоритет над `config.yaml`. Любая форма работает:

```yaml
browser:
  camofox:
    user_id: shared-camofox
    session_key: visible-tab
    adopt_existing_tab: true
```

```bash
CAMOFOX_USER_ID=shared-camofox
CAMOFOX_SESSION_KEY=visible-tab
CAMOFOX_ADOPT_EXISTING_TAB=true
```

**Что меняется при установке `user_id`:**

- Hermes пропускает деструктивную очистку при завершении задачи (так же, как `managed_persistence: true`). Вкладка/файлы cookie/профиль другого приложения сохраняются.
- Hermes **не** вызывает `DELETE /sessions/<user_id>` — эта конечная точка стирает все пользовательские данные, поэтому в случае запуска она приведет к уничтожению сеанса внешнего приложения.

**Как работает внедрение вкладок (при `adopt_existing_tab: true`):**

1. При первом вызове инструмента браузера после запуска процесса Hermes выдает `GET /tabs?userId=<user_id>` (5-секундный тайм-аут).
2. Если какая-либо вкладка в ответе имеет `listItemId == session_key`, Hermes использует последнюю созданную в этой группе.
3. В противном случае Hermes примет для пользователя самую последнюю созданную вкладку (любую `listItemId`).
4. Если вкладки не существуют или запрос не выполнен, Hermes возвращается к созданию новой вкладки при следующей операции.

Усыновление срабатывает только до тех пор, пока для сеанса не будет заполнено `tab_id`. Если внешнее приложение закроет принятую вкладку во время работы, следующий вызов инструмента браузера выдаст ошибку Camofox — Hermes не будет повторно опрашивать новую вкладку при каждом вызове.

**Выбор `session_key`:** если вы хотите, чтобы Hermes надежно привязывался к *конкретной* существующей вкладке, установите для `session_key` значение `listItemId` внешнего приложения, использованного при ее создании. Если вы оставите `session_key` неустановленным и установите только `user_id`, Hermes создаст для каждой задачи `session_key` (`task_<id>`) — Hermes будет делиться файлами cookie и профилем с внешним приложением, но параллельно откроет собственную вкладку вместо того, чтобы повторно использовать ее.

**Примечание о параллельности:** внешнее приложение и Hermes могут одновременно управлять одним и тем же Camofox `userId`, но Camofox не координирует фокусировку на каждой вкладке между клиентами. Координируйте владение на уровне приложения (например, внешнее приложение приостанавливается, пока работает Hermes).

#### Просмотр в реальном времени VNC

Когда Camofox работает в режиме заголовка (с видимым окном браузера), он предоставляет порт VNC в ответе на проверку работоспособности. Hermes автоматически обнаруживает это и включает URL-адрес VNC в ответы навигации, чтобы агент мог поделиться ссылкой, чтобы вы могли посмотреть браузер в прямом эфире.

### Локальный движок Lightpanda

[Lightpanda](https://lightpanda.io) — это безголовый браузер с открытым исходным кодом, написанный с нуля. Он запускается мгновенно, работает в 9 раз быстрее и использует в 16 раз меньше памяти, чем Chrome, что важно для агентов, которые длительное время живут на небольших виртуальных машинах.

Lightpanda — это **локальный движок**, выбранный по локальному пути `agent-browser` (не облачный провайдер). Установите двоичный файл и поместите его на свой `PATH` (см. [Руководство по установке Lightpanda](https://lightpanda.io/docs)), затем установите:

```yaml
# Add to ~/.hermes/config.yaml
browser:
  engine: lightpanda
```

Или через переменную среды:

```bash
AGENT_BROWSER_ENGINE=lightpanda
```

Hermes управляет Lightpanda через `agent-browser` через CDP так же, как он управляет локальным Chrome.

**Автоматический резервный вариант Chrome.** Lightpanda пока не охватывает все, что делает Chrome, поэтому интеграция не прерывает работу: Lightpanda обрабатывает поддерживаемые действия, а Hermes прозрачно повторяет попытки в Chrome для всего, чего он не делает. Поддерживаемый набор охватывает основной рабочий процесс агента — навигацию, снимок, щелчок, ввод текста, прокрутку, назад, нажатие и оценку. Скриншоты также выполняются в Chrome, поскольку у Lightpanda нет графического средства визуализации; По той же причине `browser_vision` предварительно перенаправляется прямо в Chrome.

### Локальный браузер семейства Chromium через CDP (`/browser connect`)

Вместо облачного провайдера вы можете подключить инструменты браузера Hermes к своему собственному экземпляру Chrome, Brave, Chromium или Edge через протокол Chrome DevTools (CDP). Это полезно, если вы хотите видеть, что делает агент в режиме реального времени, взаимодействовать со страницами, для которых требуются ваши собственные файлы cookie/сессии, или избежать затрат на облачный браузер.

:::примечание
`/browser connect` — это **косая черта интерактивной команды CLI** — она не отправляется шлюзом. Если вы попытаетесь запустить его внутри чата WebUI, Telegram, Discord или другого шлюза, сообщение будет отправлено агенту в виде обычного текста, и команда не будет выполнена. Запустите Hermes с терминала (`hermes` или `hermes chat`) и введите там `/browser connect`.
:::

В CLI используйте:

```
/browser connect                 # Auto-launch/connect to a local Chromium-family browser at http://127.0.0.1:9222
/browser connect ws://host:port  # Connect to a specific CDP endpoint
/browser status                  # Check current connection
/browser disconnect              # Detach and return to cloud/local mode
```

Если в браузере еще не запущена функция удаленной отладки, Hermes попытается автоматически запустить поддерживаемый браузер семейства Chromium с помощью `--remote-debugging-port=9222`. Обнаружение включает Brave, Google Chrome, Chromium и Microsoft Edge с распространенными путями установки Linux, такими как `/opt/brave-bin/brave` и `/snap/bin/brave`.

:::совет
Чтобы запустить браузер семейства Chromium вручную с включенным CDP, используйте выделенный каталог пользовательских данных, чтобы порт отладки действительно появился, даже если браузер уже работает с вашим обычным профилем:

```bash
# Linux — Brave
brave-browser \
  --remote-debugging-port=9222 \
  --user-data-dir=$HOME/.hermes/chrome-debug \
  --no-first-run \
  --no-default-browser-check &

# Linux — Google Chrome
google-chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=$HOME/.hermes/chrome-debug \
  --no-first-run \
  --no-default-browser-check &

# macOS — Brave
"/Applications/Brave Browser.app/Contents/MacOS/Brave Browser" \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.hermes/chrome-debug" \
  --no-first-run \
  --no-default-browser-check &

# macOS — Google Chrome
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.hermes/chrome-debug" \
  --no-first-run \
  --no-default-browser-check &
```

Затем запустите интерфейс командной строки Hermes и запустите `/browser connect`.

**Почему `--user-data-dir`?** Без него запуск браузера семейства Chromium, когда обычный экземпляр уже запущен, обычно открывает новое окно существующего процесса, а этот существующий процесс не был запущен с `--remote-debugging-port`, поэтому порт 9222 никогда не открывается. Выделенный каталог пользовательских данных вызывает новый процесс браузера, который фактически прослушивает порт отладки. `--no-first-run --no-default-browser-check` пропускает мастер первого запуска нового профиля.

**Chrome 136+ делает выделенный профиль обязательным.** В целях повышения безопасности Chrome 136 и более поздние версии молча отказываются открывать порт удаленной отладки, когда `--remote-debugging-port` объединяется с *default* каталогом пользовательских данных — даже при холодном запуске, когда другой Chrome не работает. Браузер запускается нормально, но на 9222 ничего не прослушивается, поэтому `/browser connect` (и любой ручной `curl http://127.0.0.1:9222/json/version`) завершается сбоем и в соединении отказано. Сообщение об ошибке отсутствует. Исправление заключается в точности приведенных выше команд: всегда передавайте `--user-data-dir`, указывающий куда-то, кроме каталога вашего профиля по умолчанию (например, `$HOME/.hermes/chrome-debug`). Это относится к сборкам Chrome, Chromium, Edge и Brave, в которых учтены изменения.
:::

При подключении через CDP все инструменты браузера (`browser_navigate`, `browser_click` и т. д.) работают в активном экземпляре браузера, а не запускают облачный сеанс.

### WSL2 + Windows Chrome: предпочитайте MCP `/browser connect`

Если Hermes работает внутри WSL2, но окно Chrome, которым вы хотите управлять, работает на хосте Windows, `/browser connect` часто не лучший путь.

Почему:

- `/browser connect` ожидает, что сам Hermes достигнет пригодной для использования конечной точки CDP.
- современные сеансы динамической отладки Chrome часто предоставляют локальную конечную точку хоста, которая недоступна напрямую из WSL, так же, как классический порт `9222`.
- даже если Windows Chrome можно отлаживать, самая чистая интеграция часто заключается в том, чтобы позволить серверу MCP браузера на стороне Windows подключиться к Chrome и позволить Hermes взаимодействовать с этим сервером MCP.

Для этой настройки выберите `chrome-devtools-mcp` через поддержку Hermes MCP.

См. руководство MCP для практической настройки:

- [Использовать MCP с Hermes](../../guides/use-mcp-with-hermes.md#wsl2-bridge-hermes-in-wsl-to-windows-chrome)

### Режим локального браузера

Если вы **не** установили какие-либо облачные учетные данные и не используете `/browser connect`, Hermes по-прежнему сможет использовать инструменты браузера посредством локальной установки Chromium, управляемой `agent-browser`.

### Необязательные переменные среды

```bash
# Residential proxies for better CAPTCHA solving (default: "true")
BROWSERBASE_PROXIES=true

# Advanced stealth with custom Chromium — requires Scale Plan (default: "false")
BROWSERBASE_ADVANCED_STEALTH=false

# Session reconnection after disconnects — requires paid plan (default: "true")
BROWSERBASE_KEEP_ALIVE=true

# Custom session timeout in seconds (max 21600 = 6 hours) (default: project default)
# Examples: 600 (10min), 1800 (30min), 21600 (6h max)
BROWSERBASE_SESSION_TIMEOUT=1800

# Inactivity timeout before auto-cleanup in seconds (default: 120)
BROWSER_INACTIVITY_TIMEOUT=120

# Local browser engine. Applies to the built-in browser tools
# (agent-browser path). Equivalent to browser.engine in config.yaml.
#   auto       — agent-browser's default (currently Chrome)
#   lightpanda — Lightpanda
#   chrome     — force Chrome explicitly
AGENT_BROWSER_ENGINE=auto

# Extra Chromium launch flags (comma- or newline-separated). Hermes auto-injects
# `--no-sandbox,--disable-dev-shm-usage` when it detects root or AppArmor-restricted
# unprivileged user namespaces (Ubuntu 23.10+, DGX Spark, many container images),
# so most users don't need to set this. Set it manually only if you need a flag
# Hermes doesn't add automatically; setting it disables the auto-injection.
AGENT_BROWSER_ARGS=--no-sandbox
```

### Установка CLI агента-браузера

Вам не нужно ничего устанавливать — `agent-browser` разрешается автоматически через
`npx agent-browser` при первом использовании браузера. Чтобы избежать однократной выборки npx,
вы можете установить его глобально заранее (необязательно):

```bash
npm install -g agent-browser
```

:::информация
Набор инструментов `browser` должен быть включен в список `toolsets` вашей конфигурации или включен через `hermes config set toolsets '["hermes-cli", "browser"]'`.
:::

## Доступные инструменты

### `browser_navigate`

Перейдите к URL-адресу. Должен вызываться перед любым другим инструментом браузера. Инициализирует сеанс Browserbase.

```
Navigate to https://github.com/NousResearch
```

:::совет
Для простого поиска информации выбирайте `web_search` или `web_extract` — они быстрее и дешевле. Используйте инструменты браузера, когда вам нужно **взаимодействовать** со страницей (нажимать кнопки, заполнять формы, обрабатывать динамический контент).
:::

### `browser_snapshot`

Получите текстовый снимок дерева доступности текущей страницы. Возвращает интерактивные элементы с идентификаторами ссылок, например `@e1`, `@e2`, для использования с `browser_click` и `browser_type`.

- **`full=false`** (по умолчанию): компактное представление, показывающее только интерактивные элементы.
- **`full=true`**: полное содержимое страницы.

Снимки размером более `browser.snapshot_threshold` (по умолчанию 15 000 символов — тот же бюджет на страницу, что и `web_extract`) автоматически обрезаются по границам строк; никакое обобщение LLM не требуется. Когда это происходит, полный снимок сохраняется в `~/.hermes/cache/web/`, а выходные данные инструмента включают путь к файлу и готовый к использованию вызов `read_file`, поэтому агент может просматривать все дерево доступности, включая ссылки на элементы за пределами выреза, без повторного создания снимка.

Увеличьте порог для длинных страниц, на которых больше исходного контента должно достигать агента в режиме онлайн:

```yaml
# ~/.hermes/config.yaml
browser:
  snapshot_threshold: 30000
```

Вы также можете запустить `hermes config set browser.snapshot_threshold 30000`. Этот параметр применяется как к явным вызовам `browser_snapshot`, так и к автоматическим снимкам, возвращаемым после навигации, включая серверную часть Camofox (минимум 1000). Перезапустите текущий сеанс Hermes после его изменения, чтобы перезагрузить кэш конфигурации браузера.

### `browser_click`

Щелкните элемент, идентифицированный его идентификатором ссылки на снимке.

```
Click @e5 to press the "Sign In" button
```

### `browser_type`

Введите текст в поле ввода. Сначала очищает поле, затем вводит новый текст.

```
Type "hermes agent" into the search field @e3
```

### `browser_scroll`

Прокрутите страницу вверх или вниз, чтобы открыть больше контента.

```
Scroll down to see more results
```

### `browser_press`

Нажмите клавишу клавиатуры. Полезно для отправки форм или навигации.

```
Press Enter to submit the form
```

Поддерживаемые ключи: `Enter`, `Tab`, `Escape`, `ArrowDown`, `ArrowUp` и другие.

### `browser_back`

Вернитесь на предыдущую страницу истории браузера.

### `browser_get_images`

Перечислите все изображения на текущей странице с их URL-адресами и замещающим текстом. Полезно для поиска изображений для анализа.

### `browser_vision`

Сделайте снимок экрана и проанализируйте его с помощью Vision AI. Используйте это, когда текстовые снимки не фиксируют важную визуальную информацию — особенно полезно для CAPTCHA, сложных макетов или задач визуальной проверки.

Скриншот сохраняется постоянно, а путь к файлу возвращается вместе с анализом AI. На платформах обмена сообщениями (Telegram, Discord, Slack, WhatsApp) вы можете попросить агента поделиться снимком экрана — он будет отправлен как встроенное фото с помощью механизма `MEDIA:`.

```
What does the chart on this page show?
```

Снимки экрана хранятся в `~/.hermes/cache/screenshots/` и автоматически удаляются через 24 часа.

### `browser_console`

Получите выходные данные консоли браузера (сообщения журнала/предупреждений/ошибок) и неперехваченные исключения JavaScript с текущей страницы. Необходим для обнаружения скрытых ошибок JS, которые не отображаются в дереве доступности.

```
Check the browser console for any JavaScript errors
```

Используйте `clear=True`, чтобы очистить консоль после чтения, чтобы при последующих вызовах отображались только новые сообщения.

`browser_console` также оценивает JavaScript при вызове с аргументом `expression` — такая же форма, как у консоли DevTools, результат возвращается после анализа (объекты, сериализованные в формате JSON, становятся словарями; примитивные значения остаются примитивными).

```
browser_console(expression="document.querySelector('h1').textContent")
browser_console(expression="JSON.stringify(performance.timing)")
```

Когда супервизор CDP активен в текущем сеансе (типично для любого сеанса, который выполняется `browser_navigate` с серверной частью с поддержкой CDP), оценка выполняется через постоянный WebSocket супервизора — без затрат на запуск подпроцесса. В противном случае переходит к стандартному пути CLI агент-браузер. Поведение в любом случае идентично; меняется только задержка.

По умолчанию оценка не ограничена — агент может использовать `fetch`, читать хранилище, запрашивать значения формы и выполнять любое извлечение DOM. Запросы, нацеленные на частные/внутренние адреса, по-прежнему блокируются на нелокальных серверах (защита SSRF не зависит от этого параметра). Если вы просматриваете враждебные страницы с авторизованным профилем и хотите иметь строгий список запретов для конфиденциальных примитивов JS (файлы cookie, хранилище, буфер обмена, сетевые вызовы, значения форм), зарегистрируйтесь с помощью `browser.restrict_evaluate: true` в `config.yaml`. Обратите внимание, что список запретов соответствует примитивным *именам*, поэтому он также блокирует допустимые выражения, которые просто содержат такие слова, как `fetch` или `cookie`.

### `browser_cdp`

Сквозной протокол Raw Chrome DevTools — запасной выход для операций браузера, не охватываемых другими инструментами. Используйте для собственной обработки диалогов, оценки на уровне iframe, управления файлами cookie/сети или любого глагола CDP, который нужен агенту.

**Доступно только в том случае, если конечная точка CDP доступна в начале сеанса** — это означает, что `/browser connect` подключен к работающему браузеру Chrome, Brave, Chromium или Edge или `browser.cdp_url` установлен в `config.yaml`. Режим локального агента-браузера по умолчанию, Camofox и облачные провайдеры (Browserbase, Browser Use, Firecrawl) в настоящее время не предоставляют CDP для этого инструмента — облачные провайдеры имеют URL-адреса CDP для каждого сеанса, но маршрутизация в реальном времени является последующим шагом.

**Справочник по методу CDP:** https://chromedevtools.github.io/devtools-protocol/ — агент может `web_extract` страницу конкретного метода для поиска параметров и возврата формы.

Общие шаблоны:

```
# List tabs (browser-level, no target_id)
browser_cdp(method="Target.getTargets")

# Handle a native JS dialog on a tab
browser_cdp(method="Page.handleJavaScriptDialog",
            params={"accept": true, "promptText": ""},
            target_id="<tabId>")

# Evaluate JS in a specific tab
browser_cdp(method="Runtime.evaluate",
            params={"expression": "document.title", "returnByValue": true},
            target_id="<tabId>")

# Get all cookies
browser_cdp(method="Network.getAllCookies")
```

В методах уровня браузера (`Target.*`, `Browser.*`, `Storage.*`) `target_id` отсутствует. Методы уровня страницы (`Page.*`, `Runtime.*`, `DOM.*`, `Emulation.*`) требуют `target_id` из `Target.getTargets`. Каждый вызов без сохранения состояния независим — сеансы не сохраняются между вызовами.

**Интерфейсы iframe с перекрестным происхождением**: передайте `frame_id` (из `browser_snapshot.frame_tree.children[]`, где `is_oopif=true`), чтобы направить вызов CDP через живой сеанс супервизора для этого iframe. Вот как `Runtime.evaluate` внутри iframe с перекрестным происхождением работает в Browserbase, где соединения CDP без сохранения состояния достигают истечения срока действия подписанного URL-адреса. Пример:

```
browser_cdp(
  method="Runtime.evaluate",
  params={"expression": "document.title", "returnByValue": True},
  frame_id="<frame_id from browser_snapshot>",
)
```

Для iframe того же происхождения не требуется `frame_id` — вместо этого используйте `document.querySelector('iframe').contentDocument` из `Runtime.evaluate` верхнего уровня.

### `browser_dialog`

Отвечает на собственный диалог JS (`alert` / `confirm` / `prompt` / `beforeunload`). До появления этого инструмента диалоговые окна молча блокировали поток JavaScript на странице, а последующие вызовы `browser_*` зависали или выдавали ошибку; теперь агент видит ожидающие диалоги в выходных данных `browser_snapshot` и отвечает явно.

**Рабочий процесс:**
1. Позвоните по номеру `browser_snapshot`. Если диалоговое окно блокирует страницу, оно отображается как `pending_dialogs: [{"id": "d-1", "type": "alert", "message": "..."}]`.
2. Позвоните по номеру `browser_dialog(action="accept")` или `browser_dialog(action="dismiss")`. Для диалогов `prompt()` передайте `prompt_text="..."` для предоставления ответа.
3. Повторный снимок — `pending_dialogs` пуст; поток JS на странице возобновился.

**Обнаружение происходит автоматически** через постоянный супервизор CDP — один WebSocket на каждую задачу, которая подписывается на события Page/Runtime/Target. Супервизор также заполняет поле `frame_tree` в снимке, чтобы агент мог видеть структуру iframe текущей страницы, включая iframe перекрестного происхождения (OOPIF).

**Матрица доступности:**

| Бэкэнд | Обнаружение через `pending_dialogs` | Ответ (инструмент `browser_dialog`) |
|---|---|---|
| Локальный Chrome через `/browser connect` или `browser.cdp_url` | ✓ | ✓ полный рабочий процесс |
| База браузеров | ✓ | ✓ полный рабочий процесс (через введенный мост XHR) |
| Camofox / локальный браузер-агент по умолчанию | ✗ | ✗ (нет конечной точки CDP) |

**Как это работает в Browserbase.** Прокси-сервер CDP Browserbase автоматически отклоняет настоящие собственные диалоги на стороне сервера в течение примерно 10 мс, поэтому мы не можем использовать `Page.handleJavaScriptDialog`. Супервизор внедряет небольшой скрипт через `Page.addScriptToEvaluateOnNewDocument`, который переопределяет `window.alert`/`confirm`/`prompt` с помощью синхронного XHR. Мы перехватываем эти XHR через `Fetch.enable` — поток JS страницы остается заблокированным в XHR до тех пор, пока мы не вызовем `Fetch.fulfillRequest` с ответом агента. `prompt()` возвращает значения обратно на страницу JS без изменений.

**Политика диалога** настроена в `config.yaml` под `browser.dialog_policy`:

| Политика | Поведение |
|--------|----------|
| `must_respond` (по умолчанию) | Захватите, отобразите снимок, дождитесь явного вызова `browser_dialog()`. Безопасное автоматическое закрытие после `browser.dialog_timeout_s` (по умолчанию 300 с), чтобы агент с ошибками не мог простаивать вечно. |
| `auto_dismiss` | Схватить, немедленно уволить. Агент по-прежнему видит диалог в истории `browser_state`, но ему не обязательно предпринимать какие-либо действия. |
| `auto_accept` | Захватите, примите немедленно. Полезно при навигации по страницам с агрессивными подсказками `beforeunload`. |

**Дерево кадров** внутри `browser_snapshot.frame_tree` ограничено 30 кадрами и глубиной OOPIF 2, чтобы ограничить полезные данные на страницах с большим количеством рекламы. Флаг `truncated: true` появляется при достижении пределов; агенты, которым требуется полное дерево, могут использовать `browser_cdp` с `Page.getFrameTree`.

## Практические примеры

### Заполнение веб-формы

```
User: Sign up for an account on example.com with my email john@example.com

Agent workflow:
1. browser_navigate("https://example.com/signup")
2. browser_snapshot()  → sees form fields with refs
3. browser_type(ref="@e3", text="john@example.com")
4. browser_type(ref="@e5", text="SecurePass123")
5. browser_click(ref="@e8")  → clicks "Create Account"
6. browser_snapshot()  → confirms success
```

### Исследование динамического контента

```
User: What are the top trending repos on GitHub right now?

Agent workflow:
1. browser_navigate("https://github.com/trending")
2. browser_snapshot(full=true)  → reads trending repo list
3. Returns formatted results
```

## Запись сеанса

Автоматически записывать сеансы браузера в виде видеофайлов WebM:

```yaml
browser:
  record_sessions: true  # default: false
```

Если этот параметр включен, запись начинается автоматически в первый `browser_navigate` и сохраняется в `~/.hermes/browser_recordings/` при закрытии сеанса. Работает как в локальном, так и в облачном (браузерном) режимах. Записи старше 72 часов автоматически удаляются.

## Режим заголовка (видимое окно браузера)

По умолчанию локальный браузер работает в автономном режиме. Включите режим Head, чтобы получить видимое окно Chromium, которое вы можете просматривать и с которым можно взаимодействовать:

```yaml
browser:
  headed: true  # default: false
```

Или через переменную среды: `AGENT_BROWSER_HEADED=1`.

Режим Headed делает две вещи:

1. **Запускает Chromium с видимым окном** (передаёт `--headed` агенту-браузеру в локальном режиме).
2. **Окно остается открытым между ходами.** Обычно сеанс браузера очищается после каждого ответа агента; в режиме Head пропускается поочередная очистка, поэтому вы можете наблюдать за работой агента, вмешиваться вручную (проблемы входа в систему, CAPTCHA) и сохранять состояние входа в систему на протяжении всего разговора.

Бездействующие сеансы по-прежнему сохраняются после `browser.inactivity_timeout` (по умолчанию 120 секунд отсутствия активности браузера), и все сеансы закрываются при завершении работы. Режим Headed влияет только на локальный браузер — облачные сеансы (Browserbase) не затрагиваются.

## Особенности скрытности

Browserbase предоставляет автоматические возможности скрытности:

| Особенность | По умолчанию | Заметки |
|---------|---------|-------|
| Базовая скрытность | Всегда включен | Случайные отпечатки пальцев, рандомизация области просмотра, решение CAPTCHA |
| Резидентные прокси | Вкл | Маршруты через резидентные IP-адреса для лучшего доступа |
| Продвинутая скрытность | Выкл. | Пользовательская сборка Chromium, требуется Scale Plan |
| Оставайся в живых | Вкл | Переподключение сеанса после сбоев в сети |

:::примечание
Если платные функции недоступны в вашем плане, Hermes автоматически отступает — сначала отключая `keepAlive`, а затем прокси — поэтому просмотр по-прежнему работает на бесплатных планах.
:::

## Управление сеансами

- Каждая задача получает изолированный сеанс браузера через Browserbase.
- Сеансы автоматически очищаются после бездействия (по умолчанию: 2 минуты).
- Фоновый поток каждые 30 секунд проверяет наличие устаревших сеансов.
- Аварийная очистка запускается при выходе из процесса для предотвращения потерянных сеансов.
– Сеансы выпускаются через API браузера (статус `REQUEST_RELEASE`).

## Ограничения

- **Взаимодействие на основе текста** — основано на дереве доступности, а не на пиксельных координатах.
- **Размер снимка** — большие страницы обрезаются до `browser.snapshot_threshold` (по умолчанию 15 000 символов, что соответствует `web_extract`; без суммирования LLM); полный снимок сохраняется в `~/.hermes/cache/web/`, и выходные данные указывают на него для подкачки `read_file`.
- **Тайм-аут сеанса** — срок действия облачных сеансов зависит от настроек плана вашего провайдера.
- **Стоимость** — облачные сеансы потребляют кредиты провайдера; сеансы автоматически очищаются по завершении разговора или после бездействия. Используйте `/browser connect` для бесплатного локального просмотра.
- **Нет загрузки файлов** — невозможно загрузить файлы из браузера.
