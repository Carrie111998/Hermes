# Режим доставки

Когда агент Hermes работает внутри шлюза обмена сообщениями (Slack, Discord, Telegram,
WhatsApp, Signal и т. д.), он может доставлять сгенерированные файлы непосредственно в
чат — не как пути, которые пользователь должен копировать, а как собственные вложения.

Диаграмма отображается как встроенное изображение. Отчет в формате PDF отображается в виде файла.
скачать. Таблица загружается как `.xlsx`. Агенту не нужно
напишите тег `MEDIA:` или сделайте что-нибудь особенное — он просто сгенерирует файл
и упоминает в ответе его абсолютный путь. Шлюз выбирает путь
из текста, удаляет его из видимого сообщения и загружает
файл изначально.

## Как это работает

Три детали подходят друг к другу:

1. **У агента есть инструменты для создания файлов.** `execute_code` для диаграмм через
   matplotlib, навык `docx` для документов Word, навык `xlsx` для
   электронные таблицы, навыки `pdf` и `latex-pdf-report` для PDF-файлов,
   `powerpoint` навык для колод, `image_generate` для изображений,
   `text_to_speech` для аудио и т. д.

2. **Шлюз сканирует ответы агента на предмет путей к файлам.** Любой абсолютный путь.
   (`/tmp/...`) или домашний путь (`~/...`), заканчивающийся поддерживаемым
   расширение извлекается. Пути внутри блоков кода и встроенного кода
   игнорируется, поэтому примеры кода никогда не искажаются.

3. **Шлюз распределяет файлы по типам.** Изображения встраиваются в место, где находится
   платформа это поддерживает; видео встраиваются в строку; аудио маршруты к голосу/аудио
   вложения; все остальное загружается как вложение файла.

## Поддерживаемые расширения файлов

| Категория | Расширения | Доставка |
|---|---|---|
| Изображения | `.png .jpg .jpeg .gif .webp .bmp .tiff .svg` | Встроенная вставка |
| Видео | `.mp4 .mov .avi .mkv .webm .3gp` | Встроенное встраивание (если поддерживается) |
| Аудио | `.mp3 .m2a .wav .ogg .opus .m4a .flac` | Голосовое/аудио вложение |
| Документы | `.pdf .docx .doc .odt .rtf .txt .md .epub` | Загрузка файла |
| Данные | `.xlsx .xls .ods .csv .tsv .json .xml .yaml .yml` | Загрузка файла |
| Геопространственные | `.kmz .kml .geojson .gpx` | Загрузка файла |
| Презентации | `.pptx .ppt .odp .key` | Загрузка файла |
| Архивы | `.zip .tar .gz .tgz .bz2 .xz .7z .rar .apk .ipa` | Загрузка файла |
| Интернет | `.html .htm` | Загрузка файла |

`.py`, `.log` и другие расширения исходного файла намеренно исключены, поэтому
агент не отправляет автоматически произвольные исходные файлы; если вы хотите отправить код
пользователю используйте блок кода.

## Поощрение агента создавать артефакты

По умолчанию агент не обращается к артефактам — он должен знать об этом.
Два способа подтолкнуть его:

**За сеанс**: спросите явно («отправьте мне сравнение в виде диаграммы»),
«вернуть данные в формате CSV») или написать свои собственные инструкции/
запись о личности, склоняющая к ответам в стиле артефакта на
платформы обмена сообщениями.

**На уровне проекта**: добавьте смещение к `AGENTS.md` / `CLAUDE.md` /
`.cursorrules` в проекте, в котором работает агент, в вашем глобальном
персона в `~/.hermes/SOUL.md` или в виде именованного пресета в разделе
`agent.personalities` в `~/.hermes/config.yaml` (переключается для каждого сеанса)
через `/personality`).

Механика, которую должен использовать агент, проста: преобразовать файл в
абсолютный путь (например, `/tmp/q3-revenue.png`) и укажите этот путь как
обычный текст в ответе. Все остальное делает шлюз. Пути внутри
изолированные блоки кода или обратные кавычки игнорируются, поэтому примеры кода никогда не
изувеченный.

## Канбан: уведомления о завершении поездки с артефактами

Если вы используете многоагентный рабочий процесс канбана Hermes, сотрудники могут прикреплять
доставляемые файлы на их вызов `kanban_complete`:

```python
kanban_complete(
    summary="rendered Q3 revenue chart and report",
    artifacts=[
        "/tmp/q3-revenue.png",
        "/tmp/q3-report.pdf",
    ],
)
```

Когда уведомитель шлюза доставляет сообщение «задача выполнена» тому, кто
подписался на задачу в Slack/Telegram/и т.д., он же загружает каждый артефакт
как встроенное приложение к этому чату. Человек получает результат и
резюме в одном месте.

Файлы, которых нет на диске при запуске уведомителя, автоматически пропускаются.

## Подключение дополнительных услуг с помощью MCP

Помимо конвейера доставки артефактов, агент может обращаться к другим
услуги через MCP (протокол контекста модели). Экосистема MCP поставляется
серверы сообщества для большинства популярных инструментов — установите любой, который вам нужен:

| Сервис | Что он открывает |
|---|---|
| **Понятие** | Чтение/запись страниц Notion, баз данных, рабочей области запросов |
| **GitHub** | Проблемы, PR, комментарии, поиск репозиториев за пределами gh CLI |
| **Линейный** | Билеты, проекты, циклы |
| **Слабость** | Поиск по всему рабочему пространству, чтение других каналов |
| **Gmail** | Сортировка входящих сообщений, отправка почты, управление метками |
| **Сотрудники отдела продаж** | Лиды, возможности, данные аккаунта |
| **Снежинка/BigQuery** | SQL против хранилищ данных |
| **Google Диск** | Поиск файлов, содержимое, управление общим доступом |

Установите серверы MCP через `~/.hermes/config.yaml` под `mcp_servers`.
раздел. Полное руководство по установке см. в разделе [Интеграция MCP](./mcp.md).

## Сравнение с компьютером Perplexity в Slack

Интеграция Slack в Perplexity Computer построена на той же идее:
агент генерирует результат (диаграмма, PDF, слайд-шоу) и публикует его
вернуться в ветку как родное вложение. Результат агента Гермеса
mode обеспечивает тот же шаблон взаимодействия с пользователем локально:

— Генерация происходит в собственной венв/песочнице пользователя (без удаленного арендатора).
- Файлы попадают в чат через тот же API Slack `files.uploadV2`.
- Широта разъемов определяется через MCP, а не через тщательно подобранный каталог из 400
  размещенные интеграции — установите те, которые вы действительно используете.

Токены OAuth остаются на компьютере пользователя в `auth.json`/`.env`. Нет хостинга
хранилище токенов. Нет мультитенантной микроVM. Тот же конечный результат.
