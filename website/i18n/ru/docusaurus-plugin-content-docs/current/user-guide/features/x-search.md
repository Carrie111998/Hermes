# X (Твиттер) Поиск

Инструмент `x_search` позволяет агенту осуществлять прямой поиск в X сообщениях, профилях и темах (Twitter). Он поддерживается встроенным инструментом `x_search` xAI в API ответов на `https://api.x.ai/v1/responses` — Grok сам запускает поиск на стороне сервера и возвращает синтезированные результаты с цитатами на исходные сообщения.

**Используйте это вместо `web_search`**, если вам конкретно нужны текущие обсуждения, реакции или претензии **по X**. Для обычных веб-страниц продолжайте использовать `web_search` / `web_extract`.

## `x_search` против `xurl`

Hermes может отображать две разные поверхности X:

| Поверхность | Используйте его для | Не используйте его для |
|---------|------------|-------------------|
| `x_search` | Публичное открытие X только для чтения: текущее обсуждение, реакции, претензии, профили, темы и синтезированные ответы с цитатами. | Публикация, ответы, лайки, личные сообщения, загрузка мультимедиа, удаление или доказательство того, что аутентифицированная учетная запись X изменила состояние. |
| `xurl` навык | Точная или аутентифицированная работа X API: `post`, `reply`, `read`, `like`, `dm`, временные шкалы, упоминания, загрузка мультимедиа, чтение для конкретной учетной записи и необработанные конечные точки v2. | Широкое общедоступное исследование X, синтезированное Гроком, когда `x_search` доступен и контекст аутентифицированной учетной записи не требуется. |

В смешанных рабочих процессах используйте `x_search` для обнаружения общедоступных публикаций-кандидатов, а затем переключитесь на `xurl read` или другую точную команду `xurl` после того, как будет ясна целевая запись/пользователь/действие. Любое действие X, изменяющее состояние, должно быть подтверждено выходными данными `xurl` или ответом X API; ответ `x_search` никогда не является свидетельством того, что произошла запись.

:::совет
Если вы все равно платите Portal за модель xAI, Live Search выставляет счет на тот же ключ xAI, настроенный для чата. См. [Nous Portal](/integrations/nous-portal).
:::

## Аутентификация

`x_search` регистрируется, когда доступен **любой** путь к учетным данным xAI:

| Полномочия | Источник | Настройка |
|------------|--------|-------|
| **СуперГрок / X Премиум+ OAuth** | Вход в браузер: `accounts.x.ai`, обновляется автоматически | `hermes auth add xai-oauth` — см. [xAI Grok OAuth (SuperGrok / X Premium+)](../../guides/xai-grok-oauth.md) |
| **`XAI_API_KEY`** (предпочтительно) | Платный ключ API xAI | Действие происходит в `~/.hermes/.env` |

Оба достигают одной и той же конечной точки с одинаковой полезной нагрузкой — единственная разница — это токен-носитель. **Когда оба настроены, явный `XAI_API_KEY` побеждает** — носитель OAuth подписки авторизует `/v1/responses`, но отвечает на x_search в ухудшенном пояснительном режиме Grok без цитат, в то время как ключ API возвращает реальные сообщения. Обратите внимание, что это означает, что x_search работает с использованием измеренного выставления счетов API, когда установлен ключ; удалите `XAI_API_KEY`, чтобы вернуться к квоте подписки (с предупреждением об ухудшении качества ответа).

`check_fn` инструмента запускает преобразователь учетных данных xAI каждый раз, когда список инструментов модели перестраивается. Возврат `True` означает, что носитель доступен для выборки И не пуст И (если срок его действия истек) успешно обновлен. Отозванные токены с неудачным обновлением скрывают инструмент из схемы; модель просто не может этого увидеть.

## Включение инструмента

Автоматически включается при наличии учетных данных xAI (токен OAuth или `XAI_API_KEY`). Отключите явно через `hermes tools` → Поиск → x_search, если вы этого не хотите.

```bash
hermes tools
# → 🐦 X (Twitter) Search   (press space to toggle on)
```

Средство выбора предлагает два варианта учетных данных:

1. **xAI Grok OAuth (SuperGrok / Premium+)** — открывает браузер для `accounts.x.ai`, если вы еще не вошли в систему.
2. **Ключ API xAI** — запрашивается `XAI_API_KEY`.

Любой выбор удовлетворяет воротам. Вы можете выбрать любые учетные данные, которые у вас уже есть; инструмент работает одинаково с обоими. Если оба в конечном итоге настроены, OAuth предпочтителен во время вызова.

## Конфигурация

```yaml
# ~/.hermes/config.yaml
x_search:
  # xAI model used for the Responses call.
  # grok-4.5 is the recommended default; any Grok model
  # with x_search tool access works.
  model: grok-4.5

  # Optional reasoning effort: low, medium, high, or xhigh. When omitted,
  # the selected model's default applies. xhigh is supported only by
  # models that document it, such as grok-4.20-multi-agent.
  # reasoning_effort: low

  # Request timeout in seconds. x_search can take 60–120s for
  # complex queries — the default is generous. Minimum: 30.
  timeout_seconds: 180

  # Number of automatic retries on 5xx / ReadTimeout / ConnectionError.
  # Each retry backs off (1.5x attempt seconds, capped at 5s).
  retries: 2
```

`reasoning_effort` отправляется в API ответов xAI как
`reasoning: {effort: ...}`. Оставьте этот параметр отключенным для моделей, которые не поддерживают
настраиваемые рассуждения. Недопустимые значения завершаются ошибкой до того, как будет сделан запрос API.

## Параметры инструмента

Агент вызывает `x_search` со следующими аргументами:

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `query` | строка (обязательно) | Что искать на X. |
| `allowed_x_handles` | строковый массив | Необязательный список дескрипторов, которые можно включить **исключительно** (максимум 10). Ведущий `@` удален. |
| `excluded_x_handles` | строковый массив | Необязательный список дескрипторов для исключения (максимум 10). Взаимоисключающие с `allowed_x_handles`. |
| `from_date` | строка | Необязательная дата начала `YYYY-MM-DD`. |
| `to_date` | строка | Необязательная дата окончания `YYYY-MM-DD`. |
| `enable_image_understanding` | логическое | Попросите xAI проанализировать изображения, прикрепленные к совпадающим сообщениям. |
| `enable_video_understanding` | логическое | Попросите xAI проанализировать видео, прикрепленные к совпадающим публикациям. |

Инструмент возвращает JSON с:

- `answer` — синтезированный текстовый ответ от Грока
- `citations` — цитаты, возвращаемые полем верхнего уровня Responses API.
- `inline_citations` — `url_citation` аннотаций, извлеченных из тела сообщения (каждая с `url`, `title`, `start_index`, `end_index`)
- `degraded` — `true`, когда был установлен какой-либо сужающий фильтр (`allowed_x_handles`, `excluded_x_handles`, `from_date`, `to_date`) И оба канала цитирования вернулись пустыми. В этом случае `answer` был синтезирован на основе собственных знаний модели, а не индекса X, поэтому считайте его неисходным. `false` в противном случае (включая случай «фильтры не установлены» — общий ответ без источника — это просто ответ, а не промах фильтра)
- `degraded_reason` — короткая строка с указанием активных фильтров или `null`, если `degraded` равен `false`.
- `credential_source` — `"xai-oauth"`, если разрешен OAuth, `"xai"`, если разрешен ключ API.
- `model`, `query`, `provider`, `tool`, `success`

### Проверка даты

`from_date`/`to_date` проверяются на стороне клиента перед HTTP-вызовом:

- Оба, если они предусмотрены, должны анализироваться как `YYYY-MM-DD`.
- Если установлены оба параметра, `from_date` должен быть включен или раньше `to_date`.
- `from_date` не должно быть позднее сегодняшнего дня по всемирному координированному времени — в окне, которое еще не началось, сообщения не могут существовать, поэтому вызов гарантированно вернет нулевое цитирование.
- `to_date` в будущем разрешено (вызывающие абоненты могут законно запросить «со вчерашнего дня на завтра», чтобы перехватывать сообщения по мере их поступления).

Ошибки проверки проявляются в виде структурированного результата инструмента `{"error": "..."}`, а не в виде HTTP-вызова к xAI.

## Пример

Разговариваю с агентом:

> Что люди на X говорят о новых функциях изображения Grok? Сосредоточьтесь на ответах @xai.

Агент будет:

1. Позвоните `x_search` с помощью `query="reactions to new Grok image features"`, `allowed_x_handles=["xai"]`.
2. Получите синтезированный ответ и список цитат, связанных с конкретными сообщениями.
3. Ответить с ответом и ссылками.

Если следующим запросом пользователя является «ответить на лучшее сообщение» или «поставить лайк этому сообщению», агент должен переключиться на навык `xurl`, подтвердить точную целевую публикацию и использовать действие X API. `x_search` остается инструментом обнаружения.

## Устранение неполадок

### «Нет доступных учетных данных xAI»

Инструмент обнаруживает это, когда оба пути аутентификации терпят неудачу. Либо установите `XAI_API_KEY` в `~/.hermes/.env`, либо запустите `hermes auth add xai-oauth` и завершите вход в браузер. Затем перезапустите сеанс, чтобы агент перечитал реестр инструмента.

### «`x_search` не включен для этой модели»

Настроенный `x_search.model` не имеет доступа к серверному инструменту `x_search`. Переключитесь на `grok-4.5` (по умолчанию) или другую модель Grok, которая ее поддерживает. Текущий список можно найти в [документации xAI](https://docs.x.ai/).

### Инструмент не отображается в схеме

Две возможные причины:

1. **Набор инструментов не включен.** Запустите `hermes tools` и убедитесь, что `🐦 X (Twitter) Search` отмечен.
2. **Учетные данные xAI отсутствуют.** Функция check_fn возвращает значение False, поэтому схема остается скрытой. Запустите `hermes auth status`, чтобы подтвердить состояние входа в систему xai-oauth, и убедитесь, что установлен `XAI_API_KEY` (если вы используете путь к ключу API).

### `degraded: true` — ответ без цитат

Когда вы использовали `allowed_x_handles`, `excluded_x_handles` или диапазон дат и ответ возвращается с `degraded: true`, индекс X xAI не возвращал соответствующих сообщений, но Grok все равно выдавал синтезированный ответ на основе собственных обучающих данных. Ответ не имеет источника — не рассматривайте его как реальный результат X.

Причины, которые стоит проверить:

– **Опечатка в дескрипторе.** Удалите `@`, еще раз проверьте правописание и подтвердите существование учетной записи.
- **Диапазон дат слишком узок** или выходит за пределы сегодняшних публикаций; расширить и повторить попытку.
- **Разрыв в индексе xAI.** Некоторые активные учетные записи периодически не появляются в `x_search`, даже если они публикуют сообщения регулярно. Повторите попытку через несколько минут или используйте навык `xurl` для прямого чтения X API, когда вам нужна точная временная шкала дескриптора.
