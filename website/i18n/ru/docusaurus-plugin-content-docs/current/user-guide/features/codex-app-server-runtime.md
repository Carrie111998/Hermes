# Время выполнения сервера приложений Codex

При желании Hermes может передать повороты `openai/*` и `openai-codex/*` на [сервер приложений CLI Codex](https://github.com/openai/codex) вместо запуска собственного цикла инструментов. Если этот параметр включен, команды терминала, редактирование файлов, песочница и вызовы инструментов MCP выполняются внутри среды выполнения Кодекса — Hermes становится оболочкой вокруг него (сессии БД, команды слэша, шлюз, память и проверка навыков).

Это **только по согласию**. Поведение Hermes по умолчанию не изменится, если вы не перевернете флаг. Hermes никогда не перенаправляет вас в эту среду выполнения автоматически.

:::совет
Не используете Кодекс OpenAI? `hermes setup --portal` настраивает серверную часть, не относящуюся к Кодексу, с помощью Claude/Gemini/и т. д. за один шаг. См. [Nous Portal](/integrations/nous-portal).
:::

## Почему

- Запуск агента OpenAI против вашей **подписки ChatGPT** (ключ API не требуется), используя тот же поток аутентификации, который использует Codex CLI.
- Используйте **собственный набор инструментов и песочницу Кодекса** — `shell` для терминала/чтения/записи/поиска, `apply_patch` для структурированного редактирования, `update_plan` для планирования, и все это работает в изолированной программной среде с привязными ремнями и выходом к морю.
- **Плагины Codex** — Linear, GitHub, Gmail, Calendar, Canva и т. д., установленные через `codex plugin`, автоматически переносятся и активны в сеансе Hermes.
- **Появляются более богатые инструменты Hermes** — web_search, web_extract, автоматизация браузера, видение, генерация изображений, навыки и TTS работают через обратный вызов MCP. Кодекс обращается к Гермесу за инструментами, которых у него нет.
- **Подталкивание к памяти и навыкам продолжает работать** — события Кодекса проецируются в форму сообщения Гермеса, поэтому цикл самосовершенствования видит нормальную расшифровку.

## Какие инструменты на самом деле есть у модели

Это та часть, которую большинство пользователей хотят знать заранее. Когда эта среда выполнения включена, модель, выполняющая ваш ход, имеет три независимых источника инструментов:

### 1. Встроенный набор инструментов Кодекса (всегда включен)

Они поставляются вместе с самим `codex app-server` — без участия Hermes, без MCP или плагинов. Все пять доступны в момент запуска среды выполнения:

- **`shell`** — запускает произвольные команды оболочки внутри песочницы. Вот как модель читает файлы (`cat`, `head`, `tail`), записывает их (`echo > foo`, heredocs), выполняет поиск в них (`find`, `rg`, `grep`), перемещается по каталогам (`ls`, `cd`), запускает сборки, управляет процессами и делает все, что вы делаете в bash.
- **`apply_patch`** — применяет структурированный многофайловый дифференциал в формате патча Кодекса. Модель использует это для нетривиальных изменений кода (добавление функции, рефакторинг файлов); Heredoc оболочки по-прежнему доступен для однократной записи.
- **`update_plan`** — внутренний трекер дел/планов Кодекса. Эквивалент инструмента `todo` компании Hermes, но полностью управляется во время выполнения кодекса.
- **`view_image`** — загрузить в разговор локальный файл изображения, чтобы модель могла его увидеть.
- **`web_search`** — при настройке кодекс имеет встроенный веб-поиск. Hermes также предоставляет `web_search` (с поддержкой Firecrawl) через обратный вызов ниже; модель выбирает то, что предпочитает.

Итак, **все, что вы делаете через терминал — чтение/запись/поиск/найти/запуск — кодекс делает изначально**. Профиль песочницы (`:workspace` по умолчанию при включении среды выполнения) управляет тем, что доступно для записи.

### 2. Собственные плагины Кодекса (автоматически перенесены из вашей установки `codex plugin`)

Когда вы включаете среду выполнения, Hermes запрашивает `plugin/list` RPC кодекса и записывает запись `[plugins."<name>@openai-curated"]` для каждого установленного вами плагина. Сами плагины управляются кодексом и авторизуются один раз через собственный пользовательский интерфейс кодекса.

Примеры (те, которые в теме OpenClaw отмечены как «достойные видео на YouTube»):

- **Линейный** — проблемы с поиском/обновлением.
- **GitHub** — поиск кода, просмотр PR, комментирование
- **Gmail** — читать/отправлять почту.
- **Календарь Google** — создавать/находить мероприятия.
- **Календарь/электронная почта Outlook** — та же форма через соединитель Microsoft.
- **Canva** — создание дизайна
- ...что еще вы установили через `codex plugin marketplace add openai-curated` + `codex plugin install ...`

Что НЕ перенесено:
- Плагины, которые вы еще не установили — сначала установите их в Codex.
- Записи торговой площадки приложений ChatGPT (`app/list`) — они уже включены в кодексе на основании аутентификации вашей учетной записи.

### 3. Обратный вызов инструмента Hermes (сервер MCP, зарегистрированный в `~/.codex/config.toml`)

Гермес регистрируется как сервер MCP, поэтому кодекс может перезванивать для инструментов, которые не входят в комплект поставки. Доступно через обратный звонок:

- **`web_search`** / **`web_extract`** — с поддержкой Firecraw; имеет тенденцию быть более чистым, чем очистка структурированного контента.
- **`browser_navigate` / `browser_click` / `browser_type` / `browser_press` / `browser_snapshot` / `browser_scroll` / `browser_back` / `browser_get_images` / `browser_console` / `browser_vision`** — полная автоматизация браузера через Camofox или Browserbase.
- **`vision_analyze`** — вызов отдельной модели зрения для проверки изображения (отличается от `view_image` кодекса, которая загружает ее в диалог).
- **`image_generate`** — генерация изображений с помощью цепочки плагинов image_gen от Hermes.
- **`skill_view` / `skills_list`** — прочтите из библиотеки навыков Гермеса.
- **`text_to_speech`** — TTS через настроенного провайдера Hermes.

Когда модели требуется один из них, кодекс порождает подпроцесс `hermes_tools_mcp_server` через stdio MCP, вызов отправляется через `model_tools.handle_function_call()` (тот же путь кода, что и среда выполнения Hermes по умолчанию), и результат возвращается в кодекс, как и любой другой ответ MCP.

### Что НЕдоступно в этой среде выполнения

Этим четырем инструментам Hermes для отправки требуется работающий контекст AIAgent (состояние среднего цикла), и обратный вызов MCP без сохранения состояния не может управлять ими. Вернитесь к среде выполнения по умолчанию (`/codex-runtime auto`), когда какой-либо из них вам понадобится:

- **`delegate_task`** — создавать субагенты
- **`memory`** — хранилище постоянной памяти Гермеса.
- **`session_search`** — межсессионный поиск
- **`todo`** — магазин задач Hermes (код `update_plan` является эквивалентом во время выполнения)

## Функции рабочего процесса (`/goal`, kanban, cron)

### `/goal` (цикл Ральфа)

**Работает в этой среде выполнения.** Цели сохраняются в `state_meta` с ключом по идентификатору сеанса, приглашение на продолжение возвращается как обычное пользовательское сообщение через `run_conversation()`, и кодекс самостоятельно выполняет следующий ход. Судья ворот запускается через вспомогательный клиент (настроенный через `auxiliary.goal_judge` в config.yaml), независимо от того, какая среда выполнения активна. Вердикт судьи «заблокировано, требуется ввод данных пользователем» — это чистый выход из положения, если кодекс застопорится на одобрении.

**Одна вещь, о которой следует помнить:** каждое приглашение к продолжению — это новый поворот кодекса, а это означает, что кодекс заново оценивает политику утверждения команд. Если вы выполняете долгосрочную цель с большим количеством операций записи, ожидайте большего количества запросов на одобрение, чем при выполнении одной задачи в сеансе. Установите `default_permissions = ":workspace"` (который Hermes делает автоматически при включении среды выполнения), чтобы простые записи в рабочую область не требовали запроса.

### Канбан (многоагентная диспетчеризация рабочего дерева)

**Работает в этой среде выполнения с одной тонкой зависимостью.** Диспетчер канбана создает каждого работника как отдельный подпроцесс `hermes chat -q`, который считывает конфигурацию пользователя — это означает, что если `model.openai_runtime: codex_app_server` установлен глобально, работники также появляются во время выполнения кодекса.

Что работает внутри работника времени выполнения кодекса:
- Полный набор инструментов Кодекса (shell, apply_patch, update_plan, view_image, web_search) — рабочий выполняет свою фактическую задачу изначально.
- Перенесенные плагины кодекса — Linear, GitHub и т. д.
- Обратный вызов инструмента Hermes для браузера_*, видения, image_gen, навыков, TTS.

Что также работает, потому что обратный вызов MCP предоставляет их:
- **`kanban_complete` / `kanban_block` / `kanban_comment` / `kanban_heartbeat`** — инструменты передачи работнику. Они читают `HERMES_KANBAN_TASK` из окружения (установленного диспетчером), корректно получают доступ к воротам и записывают в базу данных SQLite для каждой платы, закрепленную `HERMES_KANBAN_DB`. Без них в обратном вызове рабочий процесс в этой среде выполнения мог бы выполнить свою задачу, но не смог бы сообщить об этом и зависал бы до тех пор, пока не истечет тайм-аут диспетчера.
- **`kanban_show` / `kanban_list`** — запросы к доске только для чтения, позволяющие воркеру проверить собственный контекст.
- **`kanban_create` / `kanban_unblock` / `kanban_link`** — операции только для оркестратора. Доступно для агентов оркестратора, работающих в среде выполнения кодекса, которым необходимо отправлять новые задачи.

Инструменты канбана контролируются переменной `HERMES_KANBAN_TASK` env, которую устанавливает диспетчер — эта переменная распространяется на подпроцесс codex (кодекс наследует env), а оттуда на порожденный подпроцесс сервера `hermes-tools` MCP. Таким образом, инструменты правильно видят правильный идентификатор задачи и ворота. Для работников сервера приложений Кодекса Hermes также передает узкие переопределения песочницы сервера приложений, когда присутствует `HERMES_KANBAN_TASK`: сохраните песочницу `workspace-write`, добавьте **каталог DB Board плюс каждый путь Канбана, закрепленный диспетчером** в качестве дополнительных корневых каталогов с возможностью записи (`HERMES_KANBAN_WORKSPACES_ROOT`, `HERMES_KANBAN_WORKSPACE`, устаревший `HERMES_KANBAN_ROOT` — дедуплицированный, сначала DB-dir) и оставьте сеть отключенной по умолчанию. Это позволяет избежать хрупкого обходного пути `:danger-no-sandbox`, позволяя `kanban_complete` / `kanban_block` обновлять базу данных платы **и** позволяя работникам писать отчеты/артефакты под монтированием рабочей области, которые находятся за пределами каталога базы данных (например, `/media/.../kanban-workspaces/...` на отдельном диске — [проблема #27941](https://github.com/NousResearch/hermes-agent/issues/27941)).

### Задания Cron

**Специально не проверялось.** Задания Cron выполняются через `cronjob` → `AIAgent.run_conversation`, тот же путь кода, что и в CLI. Если в конфигурации задания cron указано `openai_runtime: codex_app_server`, оно будет выполняться в кодексе. Применяются те же правила доступности инструментов — встроенные модули кодекса + плагины + обратный вызов MCP работают, а инструменты цикла агента (delegate_task, Memory, session_search, todo) — нет. Если ваше задание cron основано на них, ограничьте cron профилем, который использует среду выполнения по умолчанию.

### Живой дисплей

Несмотря на то, что цикл агента выполняется внутри подпроцесса Кодекса, среда выполнения
соединяет поток событий Кодекса с тем же путем отображения, что и среда выполнения по умолчанию.
использует:

- Живые ассистенты дельт, рассуждения (включая сводные дельты) и стабильный идентификатор
  События запуска/завершения инструмента отображаются в пользовательском интерфейсе, на рабочем столе и в системе обмена сообщениями.
  шлюзы по ходу хода. Проектор истории только для завершения остается
  отдельно, поэтому при возобновлении сеанса используются те же карты инструментов, которые были показаны во время
  очередь.
- Комментарий шлюза остается видимым, когда потоковая передача токенов отключена, и
  События живого инструмента пересылаются даже для уведомлений, истощенных перед
  запрос на одобрение. Комментарий отмечен `display.show_commentary`.

## Предварительные условия

1. **Установлен интерфейс командной строки Codex:**
   ```bash
   npm i -g @openai/codex
   codex --version   # 0.130.0 or newer
   ```
2. **Вход в систему Codex OAuth.** Подпроцесс кодекса имеет вид `~/.codex/auth.json`. Два способа его заполнения:
   ```bash
   codex login                  # writes tokens to ~/.codex/auth.json
   ```
   Собственный `hermes auth add openai-codex` Гермеса записывает в `~/.hermes/auth.json` — это отдельный сеанс. **Запустите `codex login` отдельно**, если вы еще этого не сделали.

3. **(Необязательно) Установите нужные плагины Кодекса.** Когда вы включаете среду выполнения, Hermes автоматически переносит выбранные вами плагины, которые вы уже установили, через интерфейс командной строки Codex:
   ```bash
   codex plugin marketplace add openai-curated
   # then via codex's TUI, install Linear / GitHub / Gmail / etc.
   ```
   Гермес обнаружит их и автоматически запишет `[plugins."<name>@openai-curated"]` записей в `~/.codex/config.toml`.

## Включение

В сеансе Гермеса:

```
/codex-runtime codex_app_server
```

Эта команда:
- Проверяет, что CLI `codex` установлен (в противном случае блокируется с подсказкой по установке).
- Сохраняет `model.openai_runtime: codex_app_server` в вашем config.yaml.
— Переносит пользовательские серверы MCP с `~/.hermes/config.yaml` на `~/.codex/config.toml`.
- **Обнаруживает и переносит установленные собственные плагины Кодекса** (Linear, GitHub, Gmail, Calendar, Canva и т. д.) путем запроса `plugin/list` RPC Кодекса.
- **Регистрирует собственные инструменты Hermes в качестве сервера MCP**, чтобы подпроцесс кодекса мог перезванивать для инструментов, которые не входят в состав кодекса.
- **Записывает `default_permissions = ":workspace"`**, поэтому песочница разрешает запись в рабочей области без запроса каждой операции.
- Сообщает вам, что было перенесено. Вступает в силу в **следующем** сеансе — текущий кэшированный агент сохраняет предыдущую среду выполнения, поэтому кэши подсказок остаются действительными.

Синонимы: `/codex-runtime on`, `/codex-runtime off`, `/codex-runtime auto`.

Чтобы проверить текущее состояние, ничего не меняя:
```
/codex-runtime
```

Вы также можете установить его вручную в `~/.hermes/config.yaml`:
```yaml
model:
  openai_runtime: codex_app_server   # default is "auto" (= Hermes runtime)
```

## Цикл самосовершенствования (память + улучшение навыков)

Фоновое самосовершенствование Гермеса вспыхивает на встречных порогах:

- Каждые 10 запросов пользователя → агент проверки просматривает разговор и решает, следует ли что-нибудь сохранить в памяти.
- Каждые 10 итераций инструмента за один ход → та же идея, но для навыков (пишет `skill_manage`).

**Оба продолжают работать в среде выполнения кодекса.** Путь кодекса проецирует каждый завершенный элемент `commandExecution` / `fileChange` / `mcpToolCall` / `dynamicToolCall` в синтетическое результирующее сообщение `assistant tool_call` + `tool`, поэтому к моменту запуска проверки он видит ту же форму, что и в среде выполнения Hermes по умолчанию.

Как проводка остается эквивалентной:

| | Среда выполнения по умолчанию | Среда выполнения Кодекса |
|---|---|---|
| `_turns_since_memory` приращений | для каждого пользователя, в предварительном цикле run_conversation | тот же путь кода, перед ранним возвратом |
| `_iters_since_skill` приращений | за итерацию инструмента в цикле завершения чата | `turn.tool_iterations` после возвращения хода кодекса |
| Триггер памяти (`_turns_since_memory >= _memory_nudge_interval`) | вычисляется в предварительном цикле, срабатывает после ответа | вычисляется в предварительном цикле и передается помощнику кодекса |
| Триггер навыка (`_iters_since_skill >= _skill_nudge_interval`) | вычисляется после цикла | вычисляется после поворота кодекса |
| `_spawn_background_review(messages_snapshot=..., review_memory=..., review_skills=...)` | вызывается при срабатывании любого триггера | вызывается одинаково при срабатывании любого триггера |

Одна деталь: сама вилка обзора должна вызывать инструменты агентного цикла Hermes (`memory`, `skill_manage`), которые требуют собственной отправки Hermes. Таким образом, когда родительский агент находится на `codex_app_server`, ветка проверки **понижается до `codex_responses`** — те же учетные данные OAuth, тот же поставщик `openai-codex`, но напрямую взаимодействует с API ответов OpenAI, поэтому Hermes владеет циклом, и инструменты цикла агента работают. Это незаметно для пользователя.

Конечный эффект: включите среду выполнения кодекса, и подталкивание вашей памяти + навыков продолжит работать точно так же, как и в противном случае.

## Как работают утверждения

Кодекс запрашивает одобрение перед выполнением команд или применением исправлений. Они переводятся в стандартную подсказку Гермеса «Опасная команда»:

```
╭───────────────────────────────────────╮
│ Dangerous Command                     │
│                                       │
│ /bin/bash -lc 'echo hello > foo.txt'  │
│                                       │
│ ❯ 1. Allow once                       │
│   2. Allow for this session           │
│   3. Deny                             │
│                                       │
│ Codex requests exec in /your/cwd      │
╰───────────────────────────────────────╯
```

- **Разрешить один раз** → утвердить эту единственную команду.
- **Разрешить этот сеанс** → Кодекс не будет повторно запрашивать аналогичные команды.
- **Запретить** → команда отклонена; Кодекс продолжает работать в режиме только для чтения.

Для утверждений `apply_patch` (редактирование файла) Hermes показывает сводку того, что изменилось (`1 add, 1 update: /tmp/new.py, /tmp/old.py`), когда кодекс предоставляет данные через соответствующий элемент `fileChange`.

## Профили разрешений

Кодекс имеет три встроенных профиля разрешений:
- `:read-only` — записи нет; каждая команда оболочки требует одобрения
- `:workspace` — запись в текущем рабочем пространстве разрешена без подсказок (по умолчанию Hermes при включении среды выполнения)
- `:danger-no-sandbox` — песочницы вообще нет (не используйте, если не понимаете)

Вы можете переопределить значение по умолчанию в `~/.codex/config.toml` за пределами управляемого блока Hermes:

```toml
default_permissions = ":read-only"
```

(Гермес сохранит ваше переопределение при повторной миграции, пока оно находится за пределами маркеров `# managed by hermes-agent`.)

## Вспомогательные задачи и стоимость токена подписки ChatGPT

Когда эта среда выполнения включена с поставщиком `openai-codex`, **вспомогательные задачи (генерация заголовков, сжатие контекста, автоматическое определение видения, вилка фонового самосовершенствования) также проходят через вашу подписку ChatGPT по умолчанию**, поскольку вспомогательный клиент Hermes использует основного поставщика/модель, когда не установлено переопределение для каждой задачи.

Это не относится только к `codex_app_server` — это справедливо и для существующего пути `codex_responses`, — но здесь это более заметно, поскольку вы явно соглашаетесь на оплату подписки.

Чтобы перенаправить определенные дополнительные задачи на более дешевую/другую модель, установите явные переопределения в `~/.hermes/config.yaml`:

```yaml
auxiliary:
  title_generation:
    provider: openrouter
    model: google/gemini-3-flash-preview
  compression:
    provider: openrouter
    model: google/gemini-3-flash-preview
  vision:
    provider: openrouter
    model: google/gemini-3-flash-preview
  goal_judge:
    provider: openrouter
    model: google/gemini-3-flash-preview
```

Вилка проверки самосовершенствования наследует основную среду выполнения через `_current_main_runtime()`, и Hermes автоматически понижает ее версию с `codex_app_server` до `codex_responses` (так что вилка действительно может вызывать `memory` и `skill_manage` — собственные инструменты Hermes для агентского цикла). Этот форк по-прежнему использует вашу аутентификацию по подписке, если вы не перенаправили дополнительные задачи в другое место.

## Безопасное редактирование `~/.codex/config.toml`

Hermes помещает все, что ему удается, между двумя комментариями-маркерами:

```toml
# managed by hermes-agent — `hermes codex-runtime migrate` regenerates this section
default_permissions = ":workspace"
[mcp_servers.filesystem]
...
[plugins."github@openai-curated"]
...
# end hermes-agent managed section
```

Все, что **за пределами** этого блока, принадлежит вам. Повторный запуск миграции (через `/codex-runtime codex_app_server` или всякий раз, когда вы включаете среду выполнения) заменяет управляемый блок на месте, но дословно сохраняет пользовательский контент выше и ниже него. Это означает, что вы можете:

- Добавьте свои собственные серверы MCP, о которых Гермес не знает.
– Замените `default_permissions` на `:read-only`, если вы предпочитаете получать подсказки.
- Настройка параметров только для кодекса (модель, поставщики, отель и т. д.)
- Добавление пользовательских профилей разрешений в таблицы `[permissions.<name>]`.

Все, что вы добавите **внутри** управляемого блока, будет уничтожено при следующей миграции. Если вам нужна настройка, требующая редактирования управляемого блока, сообщите о проблеме, и мы добавим ручку.

## Мультипрофильные/мультитенантные настройки

По умолчанию Hermes указывает подпроцессу кодекса на `~/.codex/` независимо от того, какой профиль Hermes активен. Это означает, что `hermes -p work` и `hermes -p personal` используют одну и ту же аутентификацию Кодекса, плагины и конфигурацию. Для большинства пользователей это правильное поведение — оно соответствует тому, что будет делать прямой запуск `codex` CLI.

Если вам нужна изоляция Кодекса для каждого профиля (отдельная проверка подлинности, отдельные установленные плагины, отдельная конфигурация), установите `CODEX_HOME` явно для каждого профиля. Самый чистый способ — указать каталог под вашим `HERMES_HOME`:

```bash
# Inside the work profile, you might wrap hermes:
CODEX_HOME=~/.hermes/profiles/work/codex hermes chat
```

Вам нужно будет повторно запустить `codex login` один раз с этим набором `CODEX_HOME`, чтобы токены OAuth попадали в местоположение на уровне профиля. После этого `hermes -p work` будет работать в изолированном состоянии Кодекса.

Мы не устанавливаем это автоматически, потому что перемещение `~/.codex/` существующего пользователя автоматически аннулирует его аутентификацию Codex CLI — любому, кто уже запустил `codex login`, придется пройти повторную аутентификацию. Согласие кажется безопаснее, чем удивлять пользователей.

## Передача переменной среды HOME

Hermes НЕ перезаписывает `HOME` при создании подпроцесса сервера приложений Codex (мы используем `os.environ.copy()` и накладываем только `CODEX_HOME` и `RUST_LOG`). Это означает:

- Команды кодекса выполняются с помощью инструмента `shell`, видят реального пользователя `HOME` и правильно находят `~/.gitconfig`, `~/.gh/`, `~/.aws/`, `~/.npmrc` и т. д.
- Внутреннее состояние Кодекса остается изолированным до `CODEX_HOME` (который по умолчанию указывает на `~/.codex/`).

Это соответствует границе, к которой пришел OpenClaw после некоторых ранних экспериментов: изолировать состояние Кодекса, оставить дом пользователя в покое. (См. openclaw/openclaw#81562.)

## Миграция сервера MCP

Конфигурация Hermes `mcp_servers` автоматически транслируется в формат TOML, ожидаемый Кодексом. Миграция запускается каждый раз, когда вы включаете среду выполнения, и является идемпотентной — повторные запуски заменяют управляемый раздел, но сохраняют любую конфигурацию Кодекса, отредактированную пользователем.

Что переводится:

| Гермес (`config.yaml`) | Кодекс (`config.toml`) |
|---|---|
| `command` + `args` + `env` | студия транспорта |
| `url` + `headers` | потоковый_http транспорт |
| `timeout` | `tool_timeout_sec` |
| `connect_timeout` | `startup_timeout_sec` |
| `enabled: false` | `enabled = false` |

Что не перенесено:
- Ключи, специфичные для Hermes, такие как `sampling` (клиент Codex MCP не имеет эквивалента — они удаляются с предупреждением для каждого сервера).

## Миграция собственного плагина Codex

Плагины, установленные через `codex plugin` (Linear, GitHub, Gmail, Calendar, Canva и т. д.), обнаруживаются с помощью RPC Codex `plugin/list`. Для каждого плагина, где есть `installed: true`, Hermes записывает блок `[plugins."<name>@openai-curated"]`, разрешающий его в вашем сеансе Hermes.

Это означает: когда ваш друг говорит: «У меня в CLI Codex настроены Calendar и GitHub» и он включает среду выполнения кодекса Hermes, Hermes активирует их автоматически. Никакой повторной настройки не требуется.

Что НЕ перенесено:
- Плагины, которые вы еще не установили — сначала установите их в Codex.
- Плагины, в которых кодекс сообщает `availability != AVAILABLE` (неработающая установка, истекший срок действия OAuth, удаленный из магазина и т. д.). Они пропускаются, чтобы избежать записи конфигурации, которая может привести к сбою во время активации.
- Записи торговой площадки приложений ChatGPT (результаты `app/list` для каждой учетной записи — они уже включены в кодексе на основании аутентификации вашей учетной записи).
- Плагин OAuth — вы авторизуете каждый плагин один раз в самом Кодексе; Гермес не трогает учетные данные.

## Обратный вызов инструмента Hermes (новый сервер MCP)

Встроенный набор инструментов Кодекса охватывает операции с оболочкой/файлами/исправлениями, но не имеет веб-поиска, автоматизации браузера, визуального представления, генерации изображений и т. д. Чтобы сохранить их пригодными для использования в ходе работы Кодекса, Hermes регистрируется как сервер MCP в `~/.codex/config.toml`:

```toml
[mcp_servers.hermes-tools]
command = "/path/to/python"
args = ["-m", "agent.transports.hermes_tools_mcp_server"]
env = { HERMES_HOME = "/your/.hermes", PYTHONPATH = "...", HERMES_QUIET = "1" }
startup_timeout_sec = 30.0
tool_timeout_sec = 600.0
```

Когда модель вызывает `web_search` (или другой доступный инструмент Hermes), кодекс порождает подпроцесс `hermes_tools_mcp_server` через stdio, запрос отправляется через `model_tools.handle_function_call()`, а результат проецируется обратно в кодекс, как и любой другой ответ MCP.

**Инструменты, доступные через обратный вызов:** `web_search`, `web_extract`, `browser_navigate`, `browser_click`, `browser_type`, `browser_press`, `browser_snapshot`, `browser_scroll`, `browser_back`, `browser_get_images`, `browser_console`, `browser_vision`, `vision_analyze`, `image_generate`, `skill_view`, `skills_list`, `text_to_speech`.

**Инструменты НЕ доступны:** `delegate_task`, `memory`, `session_search`, `todo`. Для их отправки требуется работающий контекст AIAgent (состояние среднего цикла), и обратный вызов MCP без сохранения состояния не может управлять ими. Используйте среду выполнения Hermes по умолчанию (`/codex-runtime auto`), когда она вам понадобится.

## Отключение

Переключитесь обратно в любое время:

```
/codex-runtime auto
```

Действует на следующем сеансе. Управляемый блок Кодекса остается в `~/.codex/config.toml`, поэтому вы можете повторно включить его позже, не теряя конфигурацию, или удалить его вручную, если хотите.

## Ограничения

Эта среда выполнения является **бета-версией**. Работает с Hermes Agent 2026.5 + Codex CLI 0.130.0:

- Многоходовые разговоры
- Утверждения `commandExecution` и `fileChange` (apply_patch) через пользовательский интерфейс Hermes.
- Вызовы инструментов MCP (проверено по `@modelcontextprotocol/server-filesystem` и новому обратному вызову `hermes-tools`)
- Миграция собственного плагина Codex (проверено по инвентарю Linear/GitHub/Calendar)
- Запретить/отменить пути
- Переключить цикл включения/выключения
- Счетчики подталкивания к памяти и навыкам (проверено в реальном времени с помощью интеграционных тестов)
- Hermes web_search через кодекс (проверено в реальном времени: «OpenAI Codex CLI – Начало работы» возвращено сквозным образом)

Известные ограничения:

- **Аутентификация Hermes и аутентификация Codex – это отдельные сеансы.** Вам нужны оба `codex login` И `hermes auth add openai-codex` для максимально чистого пользовательского интерфейса (среда выполнения использует сеанс codex для вызова LLM). Это осознанный выбор дизайна в `_import_codex_cli_tokens` Hermes — Hermes не будет делиться состоянием OAuth с CLI кодекса, чтобы избежать помех друг другу при обновлении токена.
- **`delegate_task`, `memory`, `session_search`, `todo` недоступны в этой среде выполнения.** Им нужен работающий контекст AIAgent, который не может предоставить обратный вызов MCP без сохранения состояния. Используйте `/codex-runtime auto`, когда они вам нужны.
- **Нет встроенного предварительного просмотра исправлений в запросах на утверждение, если кодекс не отслеживает набор изменений.** Параметры утверждения `fileChange` Кодекса не всегда содержат набор изменений. Hermes кэширует данные из соответствующего уведомления `item/started`, когда это возможно, но если одобрение поступает до того, как элемент был передан в потоковую передачу, приглашение возвращается к тому, что предоставляет кодекс `reason`.
- **Отмена менее секунды не гарантируется.** Прерывания в середине потока (Ctrl+C во время ответа кодекса) отправляются через `turn/interrupt`, но если кодекс уже сбросил последнее сообщение, вы все равно получите ответ.

Если вы обнаружили ошибку, [откройте проблему](https://github.com/NousResearch/hermes-agent/issues) с выводом `hermes logs --since 5m`. Упомяните `codex-runtime` в заголовке, чтобы было легче сортировать.
