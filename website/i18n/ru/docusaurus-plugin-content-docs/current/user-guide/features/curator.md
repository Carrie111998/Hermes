# Куратор

Куратор — это фоновый пропуск для обслуживания **навыков, созданных агентом**. Он отслеживает, как часто каждый навык просматривается, используется и исправляется, перемещает давно неиспользуемые навыки через состояния `active → stale → archived` и периодически создает краткий обзор вспомогательной модели, который предлагает консолидацию или отклонение исправлений.

Он существует для того, чтобы навыки, созданные с помощью [цикла самосовершенствования](/user-guide/features/skills#agent-managed-skills-skill_manage-tool), не накапливались вечно. Каждый раз, когда агент решает новую задачу и сохраняет навык, этот навык попадает в `~/.hermes/skills/`. Без обслуживания вы получите десятки узких почти дубликатов, которые загрязняют каталог и тратят токены.

По умолчанию (`prune_builtins: true`) куратор может архивировать **неиспользуемые встроенные навыки** (поставляемые вместе с репозиторием) после `archive_after_days` неиспользования вместе с навыками, созданными агентом, которыми он в первую очередь управляет. Навыки, установленные в Hub (из [agentskills.io](https://agentskills.io)) всегда запрещены. Установите `curator.prune_builtins: false`, чтобы восстановить старое поведение, созданное только агентом, при котором связанные навыки никогда не затрагиваются. Куратор также **никогда не удаляет автоматически** — худший результат — архивирование в `~/.hermes/skills/.archive/`, которое можно восстановить.

Треки [выпуск № 7816] (https://github.com/NousResearch/hermes-agent/issues/7816).

## Как это работает

Куратор запускается проверкой неактивности, а не демоном cron. При запуске сеанса CLI и при повторяющемся тике внутри потока cron-ticker шлюза Hermes проверяет:

1. С момента последнего запуска куратора прошло достаточно времени (`interval_hours`, по умолчанию **7 дней**), и
2. Агент простаивал достаточно долго (`min_idle_hours`, по умолчанию **2 часа**).

Если оба варианта верны, возникает фоновая вилка `AIAgent` — тот же шаблон, который используется для подталкивания к самосовершенствованию памяти/навыков. Форк работает в собственном кэше подсказок и никогда не затрагивает активный диалог.

:::info Поведение при первом запуске
При новой установке (или при первой установке предварительного куратора после `hermes update`) куратор **запускается не сразу**. Первое наблюдение помещает `last_run_at` в «сейчас» и откладывает первый реальный проход на один полный `interval_hours`. Это дает вам полный интервал, чтобы просмотреть свою библиотеку навыков, закрепить что-нибудь важное или полностью отказаться от нее, прежде чем куратор ее коснется.

Если вы хотите увидеть, что *сделал бы* куратор, прежде чем он заработает по-настоящему, запустите `hermes curator run --dry-run` — он создаст тот же отчет о проверке без изменения библиотеки.
:::

Забег состоит из двух этапов:

1. **Автоматические переходы** (детерминированные, без LLM). Навыки, неиспользованные для `stale_after_days` (30), становятся `stale`; навыки, неиспользованные для `archive_after_days` (90), перенесены в `~/.hermes/skills/.archive/`. Это постоянное поведение сокращения — оно запускается всякий раз, когда включен куратор, без затрат на дополнительную модель.
   - **Закрепленные навыки** и **навыки, на которые ссылается любое задание cron** (включая приостановленные/отключенные задания), полностью пропускаются — рассматриваются как закрепление для автопереходов, поэтому медленное или приостановленное расписание не может заархивировать навык из-под задания. Консолидация также перезаписывает ссылки на навыки cron при объединении зонтиков.
   - **Никогда не используемые навыки** (`use_count == 0`) получают льготный уровень: они не архивируются, пока им не исполнится `stale_after_days`. Нулевое использование — это отсутствие доказательств, а не доказательство того, что навык одноразовый.
2. **Консолидация LLM** (один проход вспомогательной модели с высоким потолком итераций — полная проверка обычно требует 50–100 вызовов API) — **Выключено по умолчанию**. Когда `curator.consolidate: true`, разветвленный агент просматривает созданные агентом навыки, может прочитать любой из них с помощью `skill_view` и решает для каждого навыка, следует ли сохранять, исправлять (через `skill_manage`), объединять перекрывающиеся навыки в зонтики на уровне класса или архивировать с помощью инструмента терминала. При консолидации навык рассматривается как полный пакет: если навык имеет `references/`, `templates/`, `scripts/`, `assets/` или относительные ссылки на эти пути, куратор должен либо оставить его автономным, переместить необходимые файлы поддержки и переписать пути, либо заархивировать весь пакет без изменений, а не сводить только `SKILL.md` в файл `references/` другого навыка.

:::info Консолидация является добровольной
По умолчанию куратор только **удаляет** — детерминированный проход по бездействию отмечает устаревшие навыки и архивирует давно неиспользуемые навыки. Упрямый проход **консолидации** LLM (построение зонтика, объединение пересекающихся навыков) по умолчанию отключен, поскольку он требует жетонов дополнительной модели при каждом запуске и вносит значительные структурные изменения в вашу библиотеку. Включите его с помощью `curator.consolidate: true` или запустите один раз по требованию с помощью `hermes curator run --consolidate`.
:::

Закрепленные навыки недоступны как для автопереходов куратора, так и для собственного инструмента `skill_manage` агента. См. раздел [Закрепление навыка](#pinning-a-skill) ниже.

## Конфигурация

Все настройки хранятся в `config.yaml` под `curator:` (не `.env` — это не секрет). По умолчанию:

```yaml
curator:
  enabled: true
  interval_hours: 168          # 7 days
  min_idle_hours: 2
  stale_after_days: 30
  archive_after_days: 90
  consolidate: false           # LLM umbrella-building pass — opt-in (prune-only by default)
  prune_builtins: true         # archive unused bundled built-in skills too (hub skills always exempt)
```

Чтобы полностью отключить, установите `curator.enabled: false`. Чтобы сохранить постоянное сокращение, но включить консолидацию LLM, установите `curator.consolidate: true`.

### Делаем обзор более дешевой модели AUX

Проход кураторской проверки LLM — это обычный слот вспомогательной задачи — `auxiliary.curator` — наряду с Vision, Compression, Session Search и т. д. «Авто» означает «использовать мою основную модель чата»; переопределить слот, чтобы вместо этого закрепить конкретного поставщика + модель для прохода проверки.

**Самый простой — `hermes model`:**

```bash
hermes model                   # → "Auxiliary models — side-task routing"
                               # → pick "Curator" → pick provider → pick model
```

Тот же инструмент выбора доступен на веб-панели управления на вкладке **Модели**.

**Прямой файл config.yaml (эквивалент):**

```yaml
auxiliary:
  curator:
    provider: openrouter
    model: google/gemini-3-flash-preview
    timeout: 600               # generous — reviews can take several minutes
```

Если оставить `provider: auto` (по умолчанию), проверка будет проходить через любую модель основного чата, соответствующую поведению всех остальных вспомогательных задач.

:::обратите внимание на устаревшую конфигурацию
В более ранних выпусках использовался одноразовый блок `curator.auxiliary.{provider,model}`. Этот путь все еще работает, но выдает строку журнала устаревания — перейдите на `auxiliary.curator` выше, чтобы куратор использовал ту же сантехнику (`hermes model`, вкладка «Модели панели мониторинга», `base_url`, `api_key`, `timeout`, `extra_body`), что и все остальные дополнительные задачи.
:::

## интерфейс командной строки

```bash
hermes curator status         # last run, counts, pinned list, LRU top 5
hermes curator run            # trigger a run now (blocks until done). Prune-only unless curator.consolidate: true
hermes curator run --consolidate # force the LLM consolidation pass on for this run, overriding the config default
hermes curator run --background  # fire-and-forget: start the run in a background thread
hermes curator run --dry-run  # preview only — report without any mutations
hermes curator backup         # take a manual snapshot of ~/.hermes/skills/
hermes curator rollback       # restore from the newest snapshot
hermes curator rollback --list     # list available snapshots
hermes curator rollback --id <ts>  # restore a specific snapshot
hermes curator rollback -y         # skip the confirmation prompt
hermes curator pause          # stop runs until resumed
hermes curator resume
hermes curator pin <skill>    # never auto-transition this skill
hermes curator unpin <skill>
hermes curator adopt <skill>    # hand an unmanaged skill to the curator
hermes curator adopt --all-unmanaged   # hand over every unmanaged skill
hermes curator list-unmanaged   # itemize skills with no provenance marker
hermes curator restore <skill>  # move an archived skill back to active
hermes curator list-archived    # list skills currently in ~/.hermes/skills/.archive/
hermes curator archive <skill>  # manually archive a single skill now
hermes curator prune [--days N] # bulk-archive agent-created skills idle >= N days (default 90)
hermes curator ledger           # list the per-mutation audit ledger (all actors)
hermes curator ledger --skill <name> --limit 50  # filter/paginate ledger entries
hermes curator rollback <entry-id>  # undo a single mutation from the ledger
hermes curator purge [--days N] [--dry-run]  # delete archived skills older than the TTL (explicit only)
```

## Резервные копии и откат

Перед каждым настоящим куратором Hermes делает снимок `~/.hermes/skills/` в `~/.hermes/skills/.curator_backups/<utc-iso>/skills.tar.gz` в формате tar.gz. Если проход архивирует или объединяет что-то, что вы не хотели трогать, вы можете отменить весь проход с помощью одной команды:

```bash
hermes curator rollback        # restore newest snapshot (with confirmation)
hermes curator rollback -y     # skip the prompt
hermes curator rollback --list # see all snapshots with reason + size
```

Сам откат обратим: перед заменой дерева навыков Гермес делает еще один снимок с тегом `pre-rollback to <target-id>`, поэтому ошибочный откат можно отменить, откатившись к нему с помощью `--id`.

Вы также можете в любое время делать снимки вручную с помощью `hermes curator backup --reason "before-refactor"`. Строка `--reason` попадает в `manifest.json` снимка и отображается в `--list`.

Снимки сокращаются до `curator.backup.keep` (по умолчанию 5), чтобы ограничить использование диска:

```yaml
curator:
  backup:
    enabled: true
    keep: 5
```

Установите `curator.backup.enabled: false`, чтобы отключить автоматическое создание снимков. Ручная команда `hermes curator backup` по-прежнему работает, когда резервное копирование отключено, только если вы сначала установили `enabled: true` — флаг ограничивает оба пути симметрично, поэтому невозможно случайно пропустить предварительный снимок при мутирующих запусках.

`hermes curator status` также перечисляет пять навыков, которые использовались реже всего — быстрый способ увидеть, какие навыки могут устареть в следующий раз.

Те же подкоманды доступны, что и косая черта `/curator` внутри работающего сеанса (CLI или платформы шлюза).

## Аудит реестра и откат при однократном редактировании

Полные снимки отвечают «отменить все, что сделал последний проход куратора», но иногда вы хотите знать *кто что изменил* и отменить ровно одну мутацию. Каждая мутация навыка — автоматические переходы куратора, вызовы агента `skill_manage` и ваш собственный архив/восстановление/очистка CLI – добавляет одну запись в реестр JSONL, предназначенный только для добавления, по адресу `~/.hermes/skills/.curator_ledger.jsonl`:

- **актёр** — `curator` (вилка фонового просмотра/автопереходы), `agent` (вызовы инструментов агента на переднем плане) или `user` (команды CLI)
- **действие** — `create`, `edit`, `patch`, `delete`, `write_file`, `remove_file`, `archive`, `restore`, `purge`, `rollback`
- **evidence** — намерение удалить (`absorbed_into` для консолидаций, пусто для чернослива, и обрабатывает ли это путь восстанавливаемого архива), активируя идентификатор сеанса, если он доступен.
- **до/после** — манифест `{path, sha256}` для каждого файла. Содержимое файла хранится с адресацией по содержимому (с дедупликацией по хэшу) под `~/.hermes/.curator_backups/blobs/`, поэтому сто записей, касающихся одного и того же неизмененного файла, стоят одного большого двоичного объекта.

```bash
hermes curator ledger                  # newest 20 entries
hermes curator ledger --skill my-skill --limit 50
hermes curator rollback <entry-id>     # restore that one mutation's before-state
```

Откат с однократной записью восстанавливает именно те файлы, которых затронула мутация (и удаляет созданные ею файлы) из хранилища больших двоичных объектов — больше ничего в дереве навыков не перемещается. Как и при откате всего дерева, он сначала принимает запись в книге безопасности о текущем состоянии и **закрывается с ошибкой**: если запись безопасности не может быть записана, ничего не меняется. Поскольку удаления на переднем плане также регистрируются, `hermes curator rollback <entry-id>` может воскресить окончательно удаленный навык.

Реестр — это телеметрия, а не ворота: если запись не удалась, мутация все равно произойдет. Отключите его с помощью:

```yaml
skills:
  ledger: false
```

## Очистка архива TTL

По умолчанию заархивированные навыки сохраняются навсегда. Если вы хотите ограничить `~/.hermes/skills/.archive/`, установите TTL и очистку явно — очистка никогда не запускается автоматически, и каждый очищенный навык сначала фиксируется в реестре (с большими двоичными объектами), поэтому даже очистка оставляет проверяемый и восстанавливаемый след:

```yaml
curator:
  archive_ttl_days: 180   # 0 (default) = never purge
```

```bash
hermes curator purge --dry-run   # preview what would be deleted
hermes curator purge             # delete archives older than the TTL (with confirmation)
hermes curator purge --days 90   # one-off TTL override
```

## Что означает «создано агентом»

Куратор управляет только навыками, явно помеченными как **созданные** в
`~/.hermes/skills/.usage.json`. Навык считается квалифицированным, если ВСЕ из следующих условий
верны:

1. Его имени **нет** в `~/.hermes/skills/.bundled_manifest` (навыки, включенные в набор, поставляются вместе с репозиторием).
2. Его имени **нет** в `~/.hermes/skills/.hub/lock.json` (навыки, установленные в хабе).
3. Его запись `.usage.json` имеет `"created_by": "agent"` или `"agent_created": true`.

В настоящее время этот маркер устанавливается только **вилкой фонового самосовершенствования**.
— когда он создает новый зонтичный навык во время периодического прохода проверки (~каждые 10
агент поворачивается). Фоновая вилка работает с источником записи `"background_review"`.
(через `tools/skill_provenance.py`), это единственный путь, который запускает
`mark_agent_created()` позвоните `skill_manage`.

Навыки, которые агент переднего плана создает через `skill_manage(action="create")` во время
беседы **не** помечаются как созданные агентом — они считаются
направляются пользователями, и куратор намеренно оставляет их в покое.

:::предупреждение Ваши навыки рукописного письма НЕ курируются
Если вы вручную создали `SKILL.md` или указали Гермесу внешний навык
каталоге, этот навык будет иметь запись `.usage.json` с `created_by: null`
(или поле отсутствует). Куратор его не тронет. То же самое относится и к
навыки, созданные агентом переднего плана по вашему запросу.

**Чтобы узнать, какими навыками на самом деле управляет куратор**, запустите `hermes curator status`.
Если счетчик созданных агентом равен 0, у куратора в данный момент нет навыков.
юрисдикция — этап проверки LLM пропускается, и в отчете будет показано
`Model: (not resolved) via (not resolved)` с `Duration: 0s`.
:::

### Принятие неуправляемых навыков

`hermes curator status` сообщает о количестве **неуправляемых** наряду с управляемыми
один:

```
curator-managed skills: 43 total  (agent-created=43  bundled=0)
  active     41
  stale       2
  archived    0

unmanaged (no provenance marker): 112 total
  pre-dates marker    34
  foreground-created  78
  never auto-staled or archived — `hermes curator adopt <name>` hands one over
```

Эти 112 человек имеют право на курирование, но навсегда невидимы для жизненного цикла.
по одной из двух причин:

- **маркер предшествующей даты** — запись была написана до существования `created_by`, поэтому
  он вообще не несет в себе никакого сигнала о происхождении. Авторство действительно неизвестно
  из записи.
- **foreground-created** — передний план `skill_manage(create)` покинул маркер
  не установлено намеренно, поскольку навыки, которые вы запрашиваете, принадлежат вам.

Таким образом, большая библиотека может выглядеть полностью курируемой, в то время как большая ее часть не используется.
неприкасаемый. `adopt` закрывает этот пробел с помощью **объявления**:

```bash
hermes curator list-unmanaged                    # itemize them, with reasons
hermes curator adopt <name> [<name> ...]         # hand specific skills over
hermes curator adopt --all-unmanaged --dry-run   # preview the full list
hermes curator adopt --all-unmanaged             # hand over everything (prompts)
hermes curator adopt --all-unmanaged --yes       # skip the prompt
```

Принятие пишет тот же маркер `created_by: agent` в вилке фонового обзора.
пишет. Он **не** сбрасывает таймер неактивности — принятый навык сохраняет свое значение.
существующий `last_activity_at`, поэтому передачу библиотеки вы уже прекратили
использование не дает ему новое 90-дневное окно. Ожидайте, что приобретенные навыки длительного простоя
пройдите `stale` (или `archived`) на следующем проходе; в этом вся суть.

Усыновление также является тем, что разблокирует автономное *улучшение*. Обзор предыстории
форк отказывается исправлять навык, не управляемый куратором, поэтому, если он его заметит
ваши навыки устарели, он об этом скажет и порекомендует принять, а не
отредактируйте его. Редактирование на переднем плане (под руководством пользователя) никогда не затрагивается — вы и
Агент всегда может редактировать ваши собственные навыки по запросу.

:::note `created_by` — это флаг политики, а не заявление о происхождении.
Сохраненное поле называется `created_by`, но оно используется как «может быть автономным».
куратор прикоснется к этому?» — а не «кто написал этот файл». Это разные
вопросы, а для записей, предшествующих маркеру, ответ об авторстве просто
безвозвратно. Имя сохраняется, поскольку оно уже есть на диске в каждом
`.usage.json`; читайте это как политику. `hermes curator adopt` меняет политику и
ничего не говорит о том, кто является автором файла.
:::

:::примечание. Происхождение заявлено, но не предполагается.
Усыновление намеренно осуществляется вручную. Телеметрия не может установить авторство: навык
тысячи патчей доказывают, что агент **поддерживает** его, а не то, что агент
**написал** — Hermes постоянно редактирует навыки, созданные пользователями, от вашего имени. Ан
автоматическая эвристика «выглядит созданной агентом, примите это» в конечном итоге заархивирует
что-то, что вы написали от руки. `adopt` отказывается от комплектных, установленных на концентраторе, внешних и
защищенные встроенные навыки, у которых есть владелец, отличный от вас.
:::

Навыки, созданные агентом, проходят полный жизненный цикл:

- `active` → (30 дней не используется) `stale` → (90 дней не используется) `archived`
- Закрепленные навыки обходят все автопереходы.
- Архивы можно восстановить через `hermes curator restore <name>`.

Если вы хотите защитить определенный навык от какого-либо прикосновения — например,
навык, написанный вручную, на который вы полагаетесь — используйте `hermes curator pin <name>`. Смотрите следующий
раздел.

## Закрепление навыка

Закрепление защищает навык от удаления — как автоматические проходы архива куратора, так и вызов инструмента `skill_manage(action="delete")` агента. После закрепления навыка:

- **Куратор** пропускает его во время автопереходов (`active → stale → archived`), и его проход проверки LLM требует оставить его в покое.
- **Инструмент `skill_manage` агента** отклоняет `delete`, указывая пользователю на `hermes curator unpin <name>`. Исправления и изменения по-прежнему сохраняются, поэтому агент может улучшить содержимое закрепленного навыка по мере возникновения ловушек без танцев «закрепить/открепить/повторно закрепить».

Закрепить и открепить с помощью:

```bash
hermes curator pin <skill>
hermes curator unpin <skill>
```

Флаг хранится как `"pinned": true` в записи навыка в `~/.hermes/skills/.usage.json`, поэтому он сохраняется во время сеансов.

Навыки, указанные в списке `skills:` любого задания cron, защищены одинаково для **автопереходов** (куратор никогда не устаревает и не архивирует их, пока сохраняется ссылка), даже если задание приостановлено или отключено. Предпочитайте явный PIN-код, если вы также хотите заблокировать `skill_manage delete`.

Можно закрепить только **созданные агентом** навыки — `hermes curator pin` отказывается от объединенных и установленных в хабе навыков с пояснительным сообщением, если вы попытаетесь это сделать. Навыки, установленные в хабе, никогда не подлежат мутации куратором. Встроенные навыки в пакете затрагиваются только при `curator.prune_builtins: true` (по умолчанию), и даже в этом случае они архивируются только после `archive_after_days` неиспользования — никогда не исправляются, не объединяются и не удаляются. Установите `curator.prune_builtins: false`, чтобы полностью исключить связанные навыки.

Небольшой набор **защищенных встроенных модулей** жестко запрограммирован как не подлежащий архивированию и консолидации, независимо от `curator.prune_builtins`, состояния контактов или оценки LLM. Эти обратные несущие нагрузку UX — например, `plan` обеспечивают поток косых команд `/plan` — поэтому тихое архивирование одного из них превратит его косую черту в ошибку «Неизвестная команда» без какого-либо сигнала для вас. Защищенные встроенные модули полностью отфильтровываются из списка кандидатов куратора, поэтому этап консолидации их никогда не видит.

Если вам нужна более надежная гарантия, чем «не удалять» — например, полная заморозка содержимого навыка, пока агент его читает, — отредактируйте `~/.hermes/skills/<name>/SKILL.md` непосредственно в своем редакторе. Защита контактов защищает удаление с помощью инструмента, а не доступ к вашей собственной файловой системе.

## Телеметрия использования

Куратор поддерживает коляску по адресу `~/.hermes/skills/.usage.json` с одной записью на каждый навык:

```json
{
  "my-skill": {
    "use_count": 12,
    "view_count": 34,
    "last_used_at": "2026-04-24T18:12:03Z",
    "last_viewed_at": "2026-04-23T09:44:17Z",
    "patch_count": 3,
    "last_patched_at": "2026-04-20T22:01:55Z",
    "created_at": "2026-03-01T14:20:00Z",
    "state": "active",
    "pinned": false,
    "archived_at": null
  }
}
```

Счетчики увеличиваются, когда:

- `view_count`: оператор вызывает `skill_view` по навыку.
- `use_count`: навык загружается в подсказку разговора.
- `patch_count`: `skill_manage patch/edit/write_file/remove_file` использует навык.

Наборы навыков и навыки, установленные в концентраторе, явно исключаются из записи телеметрии.

## Отчеты по каждому запуску

Каждый запуск куратора записывает каталог с отметкой времени под `~/.hermes/logs/curator/`:

```
~/.hermes/logs/curator/
└── 20260429-111512/
    ├── run.json      # machine-readable: full fidelity, stats, LLM output
    └── REPORT.md     # human-readable summary
```

`REPORT.md` — это быстрый способ увидеть, что произошло в данном прогоне — какие навыки были изменены, что сказал рецензент LLM, какие навыки были исправлены. Подходит для аудита без необходимости использования grep `agent.log`.

:::note Нет кандидатов? В отчете показано `(not resolved)`
Если у куратора **нет навыков, созданных агентом** для проверки, проверка LLM считается пройденной.
пропускается полностью. В заголовке отчета будет показано
`Model: (not resolved) via (not resolved)` с `Duration: 0s` — это **нет**
указывают на ошибку конфигурации или сбой разрешения модели. Это просто означает, что есть
не было кандидатов, поэтому ни одна модель никогда не использовалась. Фаза автоперехода все еще
работает и сообщает о своих результатах нормально.
:::

### Переименование карты в сводке

Если в ходе прогона несколько навыков были объединены под одной крышей (или были объединены почти дубликаты), видимая пользователю сводка, напечатанная в конце прогона, включает в себя явную карту переименования, показывающую каждую пару `old-name → new-name`, примененную куратором. Это в дополнение к линиям перехода для каждого навыка, поэтому, когда приходит волна переименований, вы можете сразу заметить их, не меняя отчет JSON. Подсказка также отображается под `hermes curator pin`, поэтому вы можете сразу же закрепить имя зонтика, если хотите закрепить новую метку.

## Восстановление заархивированного навыка

Если куратор заархивировал что-то, что вам еще нужно:

```bash
hermes curator restore <skill-name>
```

При этом навык перемещается обратно из `~/.hermes/skills/.archive/` в активное дерево и сбрасывает его состояние на `active`. Восстановление отклоняется, если с тех пор установленный в комплекте навык или навык, установленный через концентратор, был установлен под тем же именем (будет затенен вышестоящим).

## Отключение для каждой среды

Куратор включен по умолчанию. Чтобы отключить его:

- **Только для одного профиля:** отредактируйте `~/.hermes/config.yaml` (или конфигурацию активного профиля) и установите `curator.enabled: false`.
- **Только за один запуск:** `hermes curator pause` — пауза сохраняется между сеансами; используйте `resume` для повторного включения.

Куратор также отказывается запускаться, если `min_idle_hours` не истек, поэтому на активной машине разработчика он, естественно, запускается только во время тихих периодов.
