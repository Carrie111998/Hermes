# Смесь агентов

Mixture of Agents — поставщик виртуальных моделей. Каждый именованный набор настроек MoA отображается как выбираемая модель у поставщика `moa`.

Когда вы выбираете пресет MoA, агрегатором пресета является действующая модель. Именно модель записывает ответ помощника и отправляет вызовы инструментов. Эталонные модели запускаются первыми и предоставляют анализ для использования агрегатором.

Используйте MoA, когда сложная задача выгодна с точки зрения нескольких моделей, но все еще требует обычного цикла агента Hermes: вызовы инструментов, последующие итерации, прерывания, сохранение расшифровки и тот же контекст сеанса, что и любое другое сообщение.

## Выберите пресет MoA в качестве модели.

Вы можете выбрать предустановку с помощью обычных поверхностей выбора модели:

```bash
/model default --provider moa
/model review --provider moa
```

Предустановки MoA можно выбрать на **каждой поверхности Hermes**, поскольку MoA является обычным поставщиком в системе моделей:

- **CLI/шлюз/TUI `/model`** — `/model <preset> --provider moa` или `/model --provider moa` для предустановки по умолчанию. Простой `/model <preset>` также работает, когда имя точно соответствует настроенному пресету.
- **`hermes model`** и **Выбор модели на панели мониторинга** — появляется строка поставщика `Mixture of Agents` с именами ваших предустановок в качестве моделей.
- **Приложение с графическим интерфейсом для ПК** — в раскрывающемся списке модели отображается раздел `MoA presets`; выбор одного (`MoA: <preset>`) переключает активную модель на этот пресет. Панель настроек рабочего стола также позволяет создавать и редактировать пресеты.

Таким образом, настроенные пресеты отображаются везде, где бы вы ни выбрали любую другую модель.

## Ярлык команды Slash

`/moa` — это сахар для одноразового использования. Он запускает один запрос через предустановку MoA **по умолчанию**, а затем восстанавливает ту модель, на которой вы работали:

```bash
/moa design and implement a migration plan for this flaky test cluster
```

Гермес временно переключается на предустановку MoA по умолчанию на этот один ход, отправляет подсказку, а затем восстанавливает предыдущую модель. Весь аргумент — это приглашение — `/moa` больше не интерпретирует его как имя предустановки.

```bash
/moa
```

Голый `/moa` (без подсказки) просто печатает информацию об использовании.

Чтобы **переключиться** на предустановку MoA до конца сеанса, выберите ее в средстве выбора модели — предустановки MoA отображаются под поставщиком `Mixture of Agents` на каждой поверхности выбора модели (см. выше). `/moa` намеренно не используется для переключения модели, поэтому обычное приглашение никогда не сможет случайно изменить вашу модель.

## Как это работает в цикле агента

Для каждого вызова основной модели при выборе поставщика `moa` компания Hermes:

1. разрешает выбранный пресет по имени;
2. запускает настроенные эталонные модели без схем инструментов (они получают только текст разговора пользователя/помощника, а не системное приглашение Hermes или стенограмму вызова инструмента), поэтому вызовы ссылок остаются дешевыми и позволяют избежать строгих отклонений со стороны поставщика);
3. добавляет эталонные выходные данные в качестве частного контекста для агрегатора;
4. вызывает настроенный агрегатор с обычной схемой инструмента Hermes;
5. рассматривает ответ агрегатора как реальный ответ модели;
6. если агрегатор вызывает инструменты, Hermes выполняет эти инструменты в обычном режиме;
7. на следующей итерации модели тот же процесс MoA снова запускается для обновленного диалога, включая результаты инструмента.

Поскольку MoA выбирается через обычную модельную систему, он автоматически компонуется с `/goal`, сеансами шлюза, сеансами TUI и чатом на рабочем столе.

## Настройка пресетов

Вы можете настроить именованные предустановки MoA следующим образом:

- Панель инструментов → Модели → Настройки модели → Смесь агентов.
- Приложение для ПК → Настройки → Модель → Смесь агентов.
- `hermes moa configure [name]`
- `config.yaml`

В конфигурации хранятся явные пары поставщик/модель, поэтому вы можете смешивать поставщиков и использовать несколько моделей от одного и того же поставщика:

```yaml
moa:
  default_preset: default
  presets:
    default:
      reference_models:
        - provider: openai-codex
          model: gpt-5.5
        - provider: openrouter
          model: deepseek/deepseek-v4-pro
      aggregator:
        provider: openrouter
        model: anthropic/claude-opus-4.8
      # Optional: pin sampling temperatures. When omitted (the default),
      # temperature is NOT sent and each model uses its provider default —
      # the same behavior as a single-model Hermes agent.
      # reference_temperature: 0.6
      # aggregator_temperature: 0.4
      max_tokens: 4096
      enabled: true
```

Предустановка по умолчанию:

- ссылка: `openai-codex:gpt-5.5`
- ссылка: `openrouter:deepseek/deepseek-v4-pro`
- агрегатор/действующая модель: `openrouter:anthropic/claude-opus-4.8`

### Настройка скорости советника с помощью `reference_max_tokens`

На каждом ходу MoA параллельно запускает эталонные модели (советники), а затем
действует агрегатор. Генерация советников — это доминирующая задержка за ход.
время стены сильно коррелирует с количеством токенов, которые эмитируют советники, потому что
очередь ждет, пока самый медленный советник закончит писать. Советники по умолчанию
**не ограничены** (`reference_max_tokens` не установлены), поэтому они могут писать долго,
совет по длине эссе.

Установите `reference_max_tokens` в предустановке, чтобы ограничить вывод советника и дать краткую информацию.
вместо этого совет. Агрегатору нужна только суть каждого советника.
суждение, поэтому ограничение (например, `600`) заметно сокращает время стены за ход с небольшими затратами.
качественный эффект. Он ограничивает **только советников** — выходные данные действующего агрегатора (
видимый пользователю ответ) никогда не ограничивается.

```yaml
moa:
  presets:
    fast:
      reference_models:
        - provider: openrouter
          model: anthropic/claude-opus-4.8
        - provider: openrouter
          model: openai/gpt-5.5
      aggregator:
        provider: openrouter
        model: anthropic/claude-opus-4.8
      reference_max_tokens: 600   # concise advice → faster turns
```

Оставьте его неустановленным (или `0`/пустым), чтобы сохранить предыдущее неограниченное поведение.

### Частота советника с `fanout`

По умолчанию советники запускаются **один раз за ход пользователя** (`fanout: user_turn`) —
они синтезируют рекомендации на уровне плана для первого сообщения хода, затем для
Действующий агрегатор работает только на оставшейся части цикла инструмента. Это
самая дешевая частота кадров: стоимость советника не умножается на количество инструментов
звонит по очереди. Две альтернативные каденции меняют стоимость свежести совета:

- `fanout: per_iteration` — советники перезапускаются при **каждой итерации инструмента**, поэтому
  их советы всегда отслеживают последние результаты инструментов — за счет
  умножив задержку и расходы советника на количество вызовов инструментов в
  поворот.
- `fanout: every_n:3` — золотая середина: советники запускаются **первым**
  итерация каждого оборота пользователя, а затем каждая **3-я** итерация инструмента (любая
  `N >= 2` работает). Итерации между ними повторно используют кэшированные рекомендации из
  последний запуск советника, поэтому агрегатор по-прежнему получает советы по каждому шагу — это
  просто обновлял каждые N шагов, а не каждый шаг. Счетчик сбрасывается
  каждое новое сообщение пользователя, поэтому каждый ход начинается со свежего совета. Отображение
  форма `fanout: {mode: every_n, n: 3}` также принимается и нормализуется до
  строковая форма.

```yaml
moa:
  presets:
    fresh:
      reference_models:
        - provider: openrouter
          model: anthropic/claude-opus-4.8
      aggregator:
        provider: openrouter
        model: openai/gpt-5.5
      fanout: per_iteration   # advisors refresh on every tool iteration
```

Неизвестные или неверные значения возвращаются к `user_turn`.

:::note Изменение по умолчанию
До июля 2026 года частота шагов по умолчанию составляла `per_iteration`. Значение по умолчанию:
сейчас `user_turn` — самая дешевая частота шагов с наименьшим воздействием — до каждого режима
контрольные показатели оправдывают более дорогостоящий дефолт. Предустановки, требующие пошаговых рекомендаций
обратно установить `fanout: per_iteration` явно.
:::

### Фильтр конфиденциальности для выходных данных советника

Выходные данные советника могут отражать конфиденциальные данные из разговора — электронные письма,
форматированные номера телефонов, ключи API, JWT — в справочные блоки, показанные на
пользовательский интерфейс, сохраненные трассировки MoA и приглашение агрегатора. `moa.privacy_filter`
(выключено по умолчанию) редактирует эти поверхности:

```yaml
moa:
  privacy_filter: display   # or: full
```

- `display` — редактирует **только видимые пользователю поверхности**: помеченную ссылку.
  блоки, отображаемые в пользовательском интерфейсе, и записи, написанные `save_traces`.
  агрегатор по-прежнему получает необработанный текст советника, поэтому качество ответа
  незатронутый.
- `full` — дополнительно редактирует текст советника, внедренный в
  приглашение агрегатора (и одноразовый вход синтеза `/moa`).

Формы учетных данных (префиксы API-ключей, JWT, закрытые ключи, подключение к базе данных)
строки) маскируются центральным секретным редактором Гермеса; фильтр MoA добавляет
электронная почта и четко отформатированное редактирование номера телефона сверху. Шаблоны
намеренно консервативен для рекомендаций в стиле проверки кода:
номера, временные метки, git SHA и IP-адреса никогда не затрагиваются — только
Форматы телефонов с разделителями, такие как `(555) 123-4567` или `555-123-4567`, соответствуют.

### Усилия по рассуждению для каждого слота

Слоты ссылки и агрегатора также могут устанавливать `reasoning_effort`. Используйте это, когда
вы хотите, чтобы одна и та же модель вносила вклад на разной глубине или когда
агрегатору следует подумать внимательнее, чем рекомендательные ссылки. Допустимые значения совпадают
Обычные элементы управления рассуждением Гермеса: `none`, `minimal`, `low`, `medium`, `high`,
`xhigh`, `max` и `ultra`.

```yaml
moa:
  presets:
    deep_review:
      reference_models:
        - provider: openai-codex
          model: gpt-5.6-sol
          reasoning_effort: low
        - provider: openai-codex
          model: gpt-5.6-sol
          reasoning_effort: xhigh
        - provider: xai-oauth
          model: grok-4.5
      aggregator:
        provider: openai-codex
        model: gpt-5.6-sol
        reasoning_effort: high
```

Опустите `reasoning_effort`, чтобы использовать значение по умолчанию поставщика/Hermes для этого слота.

## Тесты

На HermesBench предустановка MoA из двух моделей — `claude-opus-4.8`, агрегирующая по ссылке `gpt-5.5`, — превосходит любую модель, запущенную отдельно:

| Модель | Результаты HermesBench |
|---|---|
| **Агрегатор опусов (опус-4.8 + ссылка на gpt-5.5) — МОА** | **0,8202** |
| `anthropic/claude-opus-4.8` | 0,7607 |
| `openai/gpt-5.5` | 0,7412 |

Конфигурация MoA превосходит свой самый сильный компонент (opus-4.8) примерно на 6 баллов, подтверждая, что объединение второй точки зрения повышает качество сложных задач, а не просто усреднение двух.

## Быстрое кэширование

MoA построен таким образом, что **кэш подсказок основного диалога никогда не нарушается**. Выбор предустановки MoA — это обычный выбор модели: он не изменяет прошлый контекст, не меняет наборы инструментов и не перестраивает системное приглашение в середине разговора. История разговоров, системные подсказки и схема инструментов остаются стабильными по байтам, поэтому кэшированный префикс, на который опирается каждая другая модель, сохраняется точно так же, как и для простой модели. Переключение на предустановку MoA или отключение от нее требует такой же аннулирования кэша, как и любое другое переключение `/model` — не более того.

Оба типа внутренних вызовов обычно кэшируются:

- **Эталонные модели** получают усеченное, детерминированное представление разговора (системное приглашение и стенограмма инструмента удалены — см. цикл выше). Поскольку это представление является стабильной функцией стабильной истории, префикс приглашения эталонной модели обычно повторяется на итерациях и в кэше. Рекомендации представляют собой короткие консультативные звонки без каких-либо инструментов.
- **Агрегатор** — действующая модель. Справочные выходные данные добавляются в *конец* последнего хода пользователя в качестве частного руководства. Поскольку этот текст находится в хвосте — под всем стабильным префиксом (системное приглашение + предыдущая история) — он не делает недействительным ни один кэшированный префикс: агрегатор получает попадание в кеш всего, что находится выше инъекции, и только недавно добавленный хвост является новым. Именно так ведет себя каждый обычный ход, когда каждое новое сообщение пользователя также представляет собой некэшированные хвостовые токены.

Таким образом, MoA не жертвует кэшированием запросов ни для одного из типов вызовов. Единственная реальная цена — это дополнительные вызовы ссылок на итерацию — вы платите за несколько перспектив модели, а не за сломанные кэши. Долговечный префикс разговора, общий с остальным Гермесом, полностью нетронут.

## Примечания

- МОА больше не указано в списке `hermes tools`; нет набора инструментов `moa`, который можно было бы включить.
- Установка `enabled: false` для пресета отключает эталонное разветвление для этого пресета: агрегатор действует самостоятельно, точно так же, как если бы вы выбрали его в качестве простой модели. Это переключатель отключения для каждой предустановки, который отображается в настройках приборной панели и рабочего стола.
— Агрегатор пресета не может быть другим пресетом MoA. Рекурсивные деревья MoA намеренно блокируются.
- Сбои учетных данных на одной эталонной модели не прерывают ход. Hermes включает ошибку в эталонный контекст и продолжает работу с возвращаемыми моделями.
- MoA увеличивает количество вызовов моделей. Одна итерация модели может включать несколько вызовов ссылок плюс вызов агрегатора.
