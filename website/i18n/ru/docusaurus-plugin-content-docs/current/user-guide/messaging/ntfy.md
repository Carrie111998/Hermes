# нтфй

[ntfy](https://ntfy.sh/) — это простая служба уведомлений pub-sub на основе HTTP. Он работает с бесплатным общедоступным сервером `ntfy.sh` или любым локальным экземпляром и поддерживает любого клиента, который может отправлять HTTP-запросы — телефоны, браузеры, сценарии, часы.

ntfy создает отличный легкий push-канал для Hermes: подпишитесь на тему из [мобильного приложения ntfy](https://ntfy.sh/docs/subscribe/phone/), отправляйте сообщения в эту тему, чтобы поговорить с агентом, получите ответ на свой телефон.

> Запустите `hermes gateway setup` и выберите **ntfy** для пошагового руководства.

## Предварительные условия

- Название темы (любая уникальная строка — `hermes-myname-2026` подойдет)
- [Мобильное приложение ntfy](https://ntfy.sh/docs/subscribe/phone/) установлено и подписано на эту тему.
- Необязательно: автономный сервер ntfy или токен учетной записи `ntfy.sh` для частных/зарезервированных тем.

Вот и все. Ни SDK, ни демона, ни Node.js. Адаптер использует `httpx`, который уже является зависимостью Hermes.

## Настройка Гермеса

### Через мастер настройки

```bash
hermes gateway setup
```

Выберите **ntfy** и следуйте инструкциям.

### Через переменные среды

Добавьте это в `~/.hermes/.env`:

```
NTFY_TOPIC=hermes-myname-2026
NTFY_ALLOWED_USERS=hermes-myname-2026
NTFY_HOME_CHANNEL=hermes-myname-2026
```

| Переменная | Требуется | Описание |
|---|---|---|
| `NTFY_TOPIC` | Да | Тема для подписки (входящие сообщения) |
| `NTFY_SERVER_URL` | Необязательно | URL-адрес сервера (по умолчанию: `https://ntfy.sh`) — указывает на локальный ntfy для обеспечения конфиденциальности |
| `NTFY_TOKEN` | Необязательно | Токен носителя (например, `tk_xyz`) или `user:pass` для базовой аутентификации |
| `NTFY_PUBLISH_TOPIC` | Необязательно | Другая тема для исходящих ответов (по умолчанию `NTFY_TOPIC`) |
| `NTFY_MARKDOWN` | Необязательно | Настройте `true` для отправки ответов с заголовком `X-Markdown: true` |
| `NTFY_ALLOWED_USERS` | Рекомендуется | Разрешены названия тем, разделенные запятыми (расцениваются как идентификаторы пользователей; см. ниже) |
| `NTFY_ALLOW_ALL_USERS` | Необязательно | Установите `true`, чтобы разрешить каждому издателю — безопасно только для частных тем с токенами чтения |
| `NTFY_HOME_CHANNEL` | Необязательно | Тема по умолчанию для cron/доставки уведомлений |
| `NTFY_HOME_CHANNEL_NAME` | Необязательно | Человеческий ярлык для домашнего канала |

## Модель идентификации — прочтите это перед развертыванием

ntfy не имеет встроенной аутентификации пользователя. Поле `title` в опубликованном сообщении **контролируется издателем** и может содержать все, что пожелает отправитель. Адаптер Hermes НЕ использует `title` для авторизации — он позволит любому издателю, знающему тему, подделать разрешенного пользователя.

Вместо этого **имя темы само по себе является идентификатором**. Каждое сообщение, опубликованное в теме, рассматривается как исходящее от одного и того же логического пользователя (темы). Таким образом, `NTFY_ALLOWED_USERS` обычно представляет собой просто название темы — белый список с одной записью, который ограничивает весь канал.

Это означает, что **любой, кто знает тему, может поговорить с агентом**. Чтобы сделать это настоящей границей доверия:

- **Самостоятельно разместите ntfy** и заблокируйте тему с помощью [Контроля доступа](https://docs.ntfy.sh/config/#access-control). Публиковать могут только авторизованные клиенты с токеном чтения/записи.
- Или **используйте личную тему на ntfy.sh** ([зарезервированные темы](https://docs.ntfy.sh/publish/#reserved-topics) требуют учетной записи) и защитите ее с помощью `NTFY_TOKEN`.
- Или **выберите длинное, неугадываемое название темы** (`hermes-7d4f9c8b-2026`) и относитесь к нему как к общему секрету. Это самая простая настройка, но название темы просачивается через любые журналы или снимки экрана.

В любом случае не помещайте конфиденциальные данные через ntfy, если доступ к основной теме не контролируется.

## Быстрый старт — поговорите со своим агентом с телефона

1. Выберите название темы: `hermes-myname-2026`.
2. На телефоне: установите [ntfy app](https://ntfy.sh/docs/subscribe/phone/), нажмите **+**, введите `hermes-myname-2026`.
3. На хосте:
   ```bash
   echo 'NTFY_TOPIC=hermes-myname-2026' >> ~/.hermes/.env
   echo 'NTFY_ALLOWED_USERS=hermes-myname-2026' >> ~/.hermes/.env
   hermes gateway restart
   ```
4. Из приложения ntfy отправьте сообщение в тему. Ответ агента приходит в виде push-уведомления.

## Использование ntfy с заданиями cron

После установки `NTFY_HOME_CHANNEL` задания cron могут доставляться в ntfy:

```python
cronjob(
    action="create",
    schedule="every 1h",
    deliver="ntfy",          # uses NTFY_HOME_CHANNEL
    prompt="Check for alerts and summarise."
)
```

Или выберите конкретную тему явно через поле `deliver:` задания cron или из сценария оболочки с помощью [`hermes send` CLI](/guides/pipe-script-output):

```bash
hermes send ntfy:alerts-channel "Done!"
```

Это работает, даже когда cron запускается вне процесса шлюза — плагин регистрирует `standalone_sender_fn`, который открывает собственное HTTP-соединение.

## Самостоятельный хостинг ntfy

Если вы хотите полный контроль:

```bash
# Docker
docker run -p 80:80 -it binwiederhier/ntfy serve

# Native
go install heckel.io/ntfy/v2@latest
ntfy serve
```

Затем укажите на него Гермеса:

```
NTFY_SERVER_URL=https://ntfy.mydomain.com
NTFY_TOPIC=hermes
NTFY_TOKEN=tk_abc123  # if you've set up access control
```

Самостоятельный хостинг дает вам контроль доступа к темам, политики сохранения сообщений, вложения и теги эмодзи. См. [документацию сервера ntfy](https://docs.ntfy.sh/install/).

## Форматирование Markdown

Клиенты ntfy отображают уценку, когда издатель устанавливает заголовок `X-Markdown: true`. Чтобы включить исходящие ответы Hermes:

```
NTFY_MARKDOWN=true
```

Или в `config.yaml`:

```yaml
platforms:
  ntfy:
    extra:
      markdown: true
```

Мобильное приложение поддерживает подмножество CommonMark — жирный шрифт, курсив, списки, ссылки, изолированные блоки кода. Точный набор см. в [документации по уценке ntfy](https://docs.ntfy.sh/publish/#markdown-formatting).

## Настройка только исходящих сообщений (уведомления без входящих)

Если вы хотите, чтобы Hermes только *передавал* уведомления в ntfy (сводки cron, оповещения) и никогда не принимал сообщения обратно, установите для `NTFY_TOPIC` и `NTFY_PUBLISH_TOPIC` одно и то же значение и полностью пропустите `NTFY_ALLOWED_USERS`. Без списка разрешенных агент никогда не отвечает на входящие сообщения — push-уведомления получает ваш телефон, но разговор является односторонним.

## Ограничения

- **Размер сообщения**: ntfy ограничивает длину тела сообщения 4096 символами. Гермес усекает с предупреждением, когда это превышено.
- **Нет индикаторов ввода**: протокол их не раскрывает; `send_typing` неактивен.
- **Никаких тем и вложений**: ntfy — это обычные push-уведомления. Длинные ответы остаются в теле сообщения, без разветвления цепочки.
- **Нет собственной идентификации пользователя**: см. раздел о модели идентификации выше.

## Устранение неполадок

**Ошибка аутентификации / 401** — `NTFY_TOKEN` неверен, или у токена нет прав публикации/подписки на эту тему. Адаптер останавливает цикл повторного подключения на коде 401, и в статусе выполнения шлюза отображается `fatal: ntfy_unauthorized`. Исправьте токен и перезапустите шлюз.

**Тема не найдена / 404** — `NTFY_TOPIC` не существует на настроенном сервере. Для ntfy.sh темы создаются автоматически при первой публикации, поэтому 404 означает, что вы указываете на автономный сервер, на котором не подготовлена ​​​​тема. Адаптер прекращает цикл повторного подключения с помощью `fatal: ntfy_topic_not_found`.

**Подключено, но сообщений нет** – убедитесь, что `NTFY_ALLOWED_USERS` содержит само название темы. В модели идентификации ntfy темой является пользователь; если оставить белый список пустым, все будет отклонено.

**Повторное подключение каждые 60 секунд** – время поддержания активности потока по умолчанию составляет 55 секунд; ntfy может иметь периодические проблемы с сетью. Адаптер применяет экспоненциальную задержку (2 → 5 → 10 → 30 → 60 с) и сбрасывает значение в 0, как только поток остается активным в течение ≥60 с.
