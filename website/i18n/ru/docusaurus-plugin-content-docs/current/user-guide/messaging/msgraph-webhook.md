# Прослушиватель веб-перехватчика Microsoft Graph

Платформа шлюза `msgraph_webhook` является прослушивателем входящих событий. Именно так Hermes получает **уведомления об изменениях** от Microsoft Graph — «собрание Teams завершено», «в этом чате появилось новое сообщение», «это событие календаря было обновлено». В отличие от платформы `teams` (которая используется пользователями чат-бота) — здесь M365 сообщает Гермесу, что что-то произошло, а не человек.

В настоящее время основным потребителем является конвейер сводки собраний Teams: Graph уведомляет, когда собрание создает стенограмму, конвейер извлекает ее, а Hermes отправляет сводку обратно в Teams. Другие ресурсы Graph (`/chats/.../messages`, `/users/.../events`) используют тот же прослушиватель — потребители конвейера получают свои собственные PR.

## Предварительные условия

- Учетные данные приложения Microsoft Graph — [Зарегистрируйте приложение Microsoft Graph](/guides/microsoft-graph-app-registration)
– **общедоступный URL-адрес HTTPS**, к которому может обратиться Microsoft Graph (Graph не вызывает частные конечные точки). Туннель разработки предназначен для тестирования; для производства нужен реальный домен с действующим сертификатом.
— Надежный общий секрет, который можно использовать в качестве значения `clientState`. Создайте с помощью `openssl rand -hex 32` и поместите его в `~/.hermes/.env` как `MSGRAPH_WEBHOOK_CLIENT_STATE`.

## Быстрый старт

Минимум `~/.hermes/config.yaml`:

```yaml
platforms:
  msgraph_webhook:
    enabled: true
    extra:
      host: 127.0.0.1
      port: 8646
      client_state: "replace-with-a-strong-secret"
      accepted_resources:
        - "communications/onlineMeetings"
```

Или через переменные окружения в `~/.hermes/.env` (автоматически объединяются при запуске):

```bash
MSGRAPH_WEBHOOK_ENABLED=true
MSGRAPH_WEBHOOK_PORT=8646
MSGRAPH_WEBHOOK_CLIENT_STATE=<generate-with-openssl-rand-hex-32>
MSGRAPH_WEBHOOK_ACCEPTED_RESOURCES=communications/onlineMeetings
```

Примечание. Хост привязки считывается из `extra.host` в `config.yaml` (см. пример выше); нет переопределения env-var `MSGRAPH_WEBHOOK_HOST`.

Запустите шлюз: `hermes gateway run`. Слушатель раскрывает:

- `POST /msgraph/webhook` — уведомления об изменении из графика
- `GET /msgraph/webhook?validationToken=...` — подтверждение подписки на график.
- `GET /health` — проверка готовности со счетчиками принятых/дублированных

Открыть прослушиватель публично (обратный прокси, туннель разработки, вход). URL-адрес уведомлений для подписок Graph — это ваш общедоступный источник HTTPS, за которым следует `/msgraph/webhook`:

```
https://ops.example.com/msgraph/webhook
```

## Конфигурация

Все настройки находятся в разделе `platforms.msgraph_webhook.extra`:

| Настройка | По умолчанию | Описание |
|---------|---------|-------------|
| `host` | не установлено (двойной стек: все интерфейсы, IPv4+IPv6) | Привязка адреса для HTTP-прослушивателя. Для привязок без обратной связи требуется `allowed_source_cidrs`; петля (`127.0.0.1` / `::1`) — это самая простая настройка dev-туннеля/обратного прокси-сервера. |
| `port` | `8646` | Привязать порт. |
| `webhook_path` | `/msgraph/webhook` | URL-путь для графических POST. |
| `health_path` | `/health` | Конечная точка готовности. |
| `client_state` | — | Общий секретный график отображается в каждом уведомлении. По сравнению с `hmac.compare_digest` — генерировать с помощью `openssl rand -hex 32`. |
| `accepted_resources` | `[]` (принять все) | Белый список путей/шаблонов ресурсов Graph. Завершающий `*` действует как совпадение префикса. Ведущий `/` допускается. Пример: `["communications/onlineMeetings", "chats/*/messages"]`. |
| `max_seen_receipts` | `5000` | Размер кэша дедупликации для идентификаторов уведомлений. Самые старые записи удаляются при достижении ограничения. |
| `allowed_source_cidrs` | `[]` | Требуется для привязок без обратной связи. Оставьте пустым только в том случае, если прослушиватель привязан к шлейфу и находится под управлением локального туннеля/обратного прокси-сервера. |

Большинство настроек также имеют эквивалентную переменную среды (`MSGRAPH_WEBHOOK_*`), которая объединяется с конфигурацией при запуске шлюза (исключением является `host`, которая доступна только для конфигурации — см. примечание выше) — см. [ссылку на переменные среды](/reference/environment-variables#microsoft-graph-teams-meetings).

## Усиление безопасности

### clientState — основная проверка аутентификации.

Каждое уведомление Graph включает строку `clientState`, под которой зарегистрирована ваша подписка. Прослушиватель отклоняет любое уведомление, `clientState` которого не соответствует, используя безопасное по времени сравнение. Это документированный механизм Microsoft — относитесь к значению как к надежному общему секрету.

Если `client_state` не установлен, прослушиватель отказывается запускаться.

### Белый список исходных IP-адресов (рабочие развертывания)

В рабочей среде ограничьте прослушиватель опубликованными диапазонами IP-адресов источника веб-перехватчика Graph, опубликованными Microsoft. Microsoft документирует исходящие диапазоны в разделе [Веб-служба IP-адресов и URL-адресов Office 365] (https://learn.microsoft.com/en-us/microsoft-365/enterprise/urls-and-ip-address-ranges). Настройте их как:

```yaml
platforms:
  msgraph_webhook:
    enabled: true
    extra:
      host: 0.0.0.0
      client_state: "..."
      allowed_source_cidrs:
        - "52.96.0.0/14"
        - "52.104.0.0/14"
        # ...add the current Microsoft 365 "Common" + "Teams" category egress ranges
```

Или как переменная окружения:

```bash
MSGRAPH_WEBHOOK_ALLOWED_SOURCE_CIDRS="52.96.0.0/14,52.104.0.0/14"
```

Привязка хоста без обратной связи, такого как `0.0.0.0`, `::`, или IP-адреса локальной сети без `allowed_source_cidrs`, отклоняется при запуске. Если вы используете туннель разработки или обратный прокси-сервер на том же компьютере, привяжите Hermes к `127.0.0.1` или `::1` и оставьте там белый список пустым. Недопустимые строки CIDR регистрируют предупреждение и игнорируются. **Просматривайте список IP-адресов Microsoft ежеквартально** — он меняется.

### Завершение HTTPS

Слушатель говорит на простом HTTP. Завершите TLS на своем обратном прокси-сервере (Caddy, Nginx, Cloudflare Tunnel, AWS ALB) и прокси-сервере для прослушивателя через локальную сеть. Graph отказывается доставлять данные на конечные точки, не поддерживающие HTTPS, поэтому незашифрованный трафик не может достичь вас из самого Graph.

### Гигиена реагирования

В случае успеха прослушиватель возвращает `202 Accepted` с пустым телом — внутренние счетчики не участвуют в проводном ответе. Операторы могут наблюдать за подсчетом через `/health`, который защищен теми же правилами исходного IP-адреса, что и путь веб-перехватчика.

Таблица кодов состояния:

| Результат | Статус |
|---------|--------|
| Уведомления приняты или удалены | 202 |
| Подтверждение связи (GET с `validationToken`) | 200 (повторяет жетон) |
| Ошибка каждого элемента в пакете clientState | 403 |
| Неверный формат JSON/отсутствует массив `value`/неизвестный ресурс | 400 |
| Исходный IP-адрес не в белом списке | 403 |
| Голый GET без `validationToken` | 400 |

## Устранение неполадок

| Проблема | Что проверить |
|---------|---------------|
| Проверка подписки на график не удалась | Общедоступный URL-адрес доступен, путь `/msgraph/webhook` совпадает, GET с `validationToken` дословно отображает токен как `text/plain` в течение 10 секунд. |
| Уведомления POST, но ничего не загружается | `client_state` соответствует тому, под которым вы зарегистрировали подписку. Перезапустите `openssl rand -hex 32` и создайте новую подписку, если значение изменилось. Проверьте, что `accepted_resources` включает путь к ресурсу, который отправляет Graph. |
| Каждое уведомление 403 | `clientState` несоответствие (поддельное или подписка зарегистрирована с другим значением). Повторно создайте подписку с помощью `hermes teams-pipeline subscribe --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE" ...` (поставляется с PR среды выполнения конвейера). |
| Прослушиватель отказывается запускаться на `0.0.0.0` | Установите `allowed_source_cidrs` в текущие исходящие диапазоны веб-перехватчика Microsoft или привяжите Hermes к `127.0.0.1` / `::1` за туннелем или обратным прокси-сервером. |
| Прослушиватель запускается, но `curl http://localhost:8646/health` зависает | Коллизия привязки портов. Проверьте `ss -tlnp \| grep 8646` и при необходимости измените `port:`. |
| Запросы Real Graph от Microsoft получают 403 | Белый список исходных IP-адресов слишком узок. Расширьте список, включив в него текущие исходящие диапазоны Microsoft. Если вы все еще проверяете путь туннеля, привяжите Hermes к шлейфу и позвольте туннелю обрабатывать доступ общественности. |
