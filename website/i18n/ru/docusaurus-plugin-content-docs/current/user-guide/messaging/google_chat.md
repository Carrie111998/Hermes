# Настройка чата Google

Подключите агента Hermes к Google Chat в качестве бота. Интеграция использует Cloud Pub/Sub.
подписки по запросу для входящих событий и API REST чата для исходящих сообщений.
Эргономика, эквивалентная режиму Slack Socket или длинному опросу Telegram: ваш Hermes
процессу не требуется общедоступный URL-адрес, туннель или сертификат TLS. Это соединяет,
аутентифицируется и прослушивает подписку — так же, как прослушивает бот Telegram
на жетоне.

> Запустите `hermes gateway setup` и выберите **Google Chat** для пошагового руководства.

:::примечание Версия Workspace
Google Chat является частью Google Workspace. Вы можете использовать эту интеграцию с
личное рабочее пространство (`@yourdomain.com` зарегистрированное через Google) или рабочее
Рабочая область, в которой у вас есть права администратора для публикации приложения. Аккаунты только для Gmail
не может размещать приложения чата.
:::

## Обзор

| Компонент | Значение |
|-----------|-------|
| **Библиотеки** | `google-cloud-pubsub`, `google-api-python-client`, `google-auth` |
| **Входящий транспорт** | Подписка по запросу на Cloud Pub/Sub (без общедоступной конечной точки) |
| **Выездной транспорт** | REST API чата (`chat.googleapis.com`) |
| **Аутентификация** | Учетная запись службы JSON с `roles/pubsub.subscriber` в подписке |
| **Идентификация пользователя** | Названия ресурсов чата (`users/{id}`) + адрес электронной почты |

---

## Шаг 1. Создайте или выберите проект GCP

Вам нужен проект Google Cloud для размещения темы Pub/Sub. Если у вас его нет,
создайте его на [console.cloud.google.com](https://console.cloud.google.com) —
личные учетные записи получают бесплатный уровень, который легко покрывает трафик ботов.

Запишите идентификатор проекта (например, `my-chat-bot-123`). Вы будете использовать его в каждом последующем
шаг.

---

## Шаг 2. Включите два API

В консоли перейдите в **API и службы → Библиотека** и включите:

- **API Чата Google**
- **API Cloud Pub/Sub**

Оба бесплатны для объемов, которые генерирует личный бот.

---

## Шаг 3. Создайте учетную запись службы

**IAM и администрирование → Учетные записи служб → Создать учетную запись службы.**

- Имя: `hermes-chat-bot`
– Пропустите шаг «Предоставить этому сервисному аккаунту доступ к проекту». IAM по конкретному
  подписка — это все, что вам нужно — **НЕ** предоставляйте роли Pub/Sub на уровне проекта.

После создания откройте SA, перейдите в **Ключи → Добавить ключ → Создать новый ключ → JSON** и
скачать файл. Сохраните его где-нибудь, где сможет прочитать только Гермес (например,
`~/.hermes/google-chat-sa.json`, `chmod 600`).

:::внимание! Роли «Вызывающий чат-бот» НЕТ.
Распространенной ошибкой является поиск роли IAM, специфичной для Chat, и предоставление ее на
уровень проекта. Этой роли не существует. Авторитет чат-бота обусловлен тем, что он
установлен в пространстве, а не из IAM. Все, что вам нужно для SA, — это подписка на Pub/Sub.
подписку, которую вы создадите на следующем шаге.
:::

---

## Шаг 4. Создайте тему Pub/Sub и подписку.

**Pub/Sub → Темы → Создать тему.**

- Идентификатор темы: `hermes-chat-events`
- Для всего остального оставьте значения по умолчанию.

После создания на странице сведений о теме появляется вкладка **Подписки**. Создайте один:

- Идентификатор подписки: `hermes-chat-events-sub`
- Тип доставки: **Потянуть**
- Срок хранения сообщений: **7 дней** (чтобы невыполненная работа сохранялась после перезапуска Hermes).
- Остальное оставьте по умолчанию.

---

## Шаг 5: привязка IAM к теме (критично)

В **теме** (не в подписке) добавьте субъект IAM:

- Директор: `chat-api-push@system.gserviceaccount.com`
- Роль: `Pub/Sub Publisher`

Без этого Google Chat не сможет публиковать события по вашей теме, и ваш бот будет
никогда ничего не получайте.

---

## Шаг 6. Привязка IAM к подписке

В **подписке** добавьте свой собственный сервисный аккаунт в качестве основного:

- Директор: `hermes-chat-bot@<your-project>.iam.gserviceaccount.com`
- Роль: `Pub/Sub Subscriber`

Также предоставить `Pub/Sub Viewer` по той же подписке — звонки Hermes
`subscription.get()` при запуске в качестве проверки доступности.

---

## Шаг 7. Настройте приложение чата

Перейдите в раздел **API и службы → Google Chat API → Конфигурация**.

- **Название приложения**: все, что вы хотите, чтобы пользователи видели («Гермес» разумно).
- **URL-адрес аватара**: любой общедоступный PNG (у Google есть некоторые значения по умолчанию).
- **Описание**: короткое предложение, отображаемое в каталоге приложения.
- **Функциональность**: включите **Получать сообщения 1:1** и **Присоединяться к группам и группам.
  разговоры**.
- **Настройки подключения**: выберите **Cloud Pub/Sub**, введите название темы.
  `projects/<your-project>/topics/hermes-chat-events`.
- **Видимость**: ограничьте свое рабочее пространство (или определенных пользователей) — не публикуйте.
  всем, пока вы тестируете.

Сохранять.

---

## Шаг 8: Установите бота в тестовом пространстве

Откройте Google Chat в браузере. Начните DM со своим приложением, выполнив поиск по его названию.
в меню **+ Новый чат**. Когда вы впервые отправляете сообщение, Google отправляет
`ADDED_TO_SPACE` событие, которое Hermes использует для кэширования собственных `users/{id}` бота для
фильтрация собственных сообщений.

---

## Шаг 9: Настройте Гермес

Добавьте раздел Google Chat в `~/.hermes/.env`:

```bash
# Required
GOOGLE_CHAT_PROJECT_ID=my-chat-bot-123
GOOGLE_CHAT_SUBSCRIPTION_NAME=projects/my-chat-bot-123/subscriptions/hermes-chat-events-sub
GOOGLE_CHAT_SERVICE_ACCOUNT_JSON=/home/you/.hermes/google-chat-sa.json

# Authorization — paste the emails of people allowed to talk to the bot
GOOGLE_CHAT_ALLOWED_USERS=you@yourdomain.com,coworker@yourdomain.com

# Optional
GOOGLE_CHAT_HOME_CHANNEL=spaces/AAAA...         # default delivery destination for cron jobs
GOOGLE_CHAT_MAX_MESSAGES=1                      # Pub/Sub FlowControl; 1 serializes commands per session
GOOGLE_CHAT_MAX_BYTES=16777216                  # 16 MiB — cap on in-flight message bytes
```

Идентификатор проекта также возвращается к `GOOGLE_CLOUD_PROJECT`, а путь SA падает.
вернемся к `GOOGLE_APPLICATION_CREDENTIALS` — используйте любое соглашение, которое вы предпочитаете.

Установите зависимости адаптера Google Chat с помощью поддерживаемого установщика.
Он применяет те же закрепленные уровни безопасности, которые используются при проверках во время выполнения:

```bash
python -m plugins.platforms.google_chat.oauth --install-deps
```

Запускаем шлюз:

```bash
hermes gateway
```

Вы должны увидеть строку журнала вроде:

```
[GoogleChat] Connected; project=my-chat-bot-123, subscription=<redacted>,
             bot_user_id=users/XXXX, flow_control(msgs=1, bytes=16777216)
```

Отправьте «hola» в тестовый Директ. Бот размещает маркер «Гермес думает…», а затем
редактирует то же самое сообщение на месте реального ответа — никаких «сообщений удалено»
надгробия.

### Настройка маркера рабочего состояния

Текст маркера настраивается через `typing_status_text` в
`~/.hermes/config.yaml` — например. котёнок-помощник по имени Ада:

```yaml
platforms:
  google_chat:
    # Custom working-state marker text (default: "Hermes is thinking…").
    typing_status_text: "is pouncing… 🐾"
```

В отличие от эфемерной строки состояния Slack, это **настоящее опубликованное сообщение**, которое
редактируется вместе с ответом — так что вкратце все, что вы здесь зададите
появляется в чате как обычное сообщение. Установите `typing_indicator: false` на
полностью отключить маркер.

## Форматирование и возможности

Google Chat отображает ограниченное подмножество уценок:

| Поддерживается | Не поддерживается |
|-----------|----------------|
| `*bold*`, `_italic_`, `~strike~`, `` `code` `` | Рубрики, списки |
| Встроенные изображения через URL | Кнопки интерактивной карты v2 (v1 этого шлюза) |
| Собственные вложения файлов (после `/setup-files` — см. шаг 10) | Встроенные голосовые заметки/круговые видеозаметки |

Системное приглашение агента включает в себя подсказку, специфичную для Google Chat, поэтому он знает эти
ограничивает и избегает форматирования, которое не отображается.

Ограничение размера сообщения: 4000 символов на сообщение. Более длинные ответы агента
автоматически разделяется на несколько сообщений.

Поддержка потоков: когда пользователь отвечает внутри потока, Hermes обнаруживает
`thread.name` и публикует свой ответ в той же ветке, так что каждая ветка получает
отдельный сеанс Гермеса.

### Разъясняйте вопросы в виде интерактивных карточек

Когда агент задает уточняющий вопрос с несколькими вариантами ответов, адаптер отображает его
как родная **Card v2** с одной кнопкой на выбор плюс
**Кнопка «Другое / введите ответ»** вместо простого нумерованного текстового списка.
Нажатие кнопки дает прямой ответ на вопрос (маршрут событий `CARD_CLICKED`).
выбор обратно в сеанс ожидания). Если карту не удалось отправить или
вопрос не имеет фиксированных вариантов выбора, адаптер возвращается к стандартному тексту
уточнить. Никакой конфигурации не требуется.

## Шаг 10. Доставка встроенных вложений (необязательно)

В стандартной комплектации бот может публиковать текст, встроенные изображения по URL-адресу и загружать карточки.
для аудио/видео/документов. Чтобы доставить **собственные** вложения чата — то же самое
файловый виджет, который вы получаете, когда человек перетаскивает файл — каждый пользователь авторизуется
бот один раз через поток OAuth для каждого пользователя.

### Зачем отдельный поток

Конечная точка `media.upload` Google Chat жестко отклоняет аутентификацию сервисного аккаунта:

> Этот метод не поддерживает аутентификацию приложения с помощью учетной записи службы.
> Выполните аутентификацию с помощью учетной записи пользователя.

Не существует роли или области IAM, которая бы это исправила. Конечная точка принимает только пользователя
учетные данные. Таким образом, бот должен действовать *как пользователь* всякий раз, когда он загружает файл —
в частности, как пользователь, запросивший файл.

### Единоразовая настройка (для каждого профиля)

1. Перейдите в раздел **API и сервисы → Учетные данные** в том же проекте GCP.
2. **Создайте учетные данные → Идентификатор клиента OAuth → Настольное приложение**.
3. Загрузите JSON. Переместите его на хост, на котором работает Hermes.
4. Зарегистрируйте клиента в Hermes (запустите его под нужным профилем):

```bash
# Default profile:
python -m plugins.platforms.google_chat.oauth \
    --client-secret /path/to/client_secret.json

# A named profile gets its own separate registration:
hermes -p <profile> python -m plugins.platforms.google_chat.oauth \
    --client-secret /path/to/client_secret.json
```

При этом секрет клиента будет записан в домашнюю страницу Hermes активного профиля (например,
`~/.hermes/google_chat_user_client_secret.json` для профиля по умолчанию).
секрет клиента **распространяется на профиль и не используется несколькими профилями** — каждый профиль
регистрирует свое. Это сделано намеренно: профили представляют собой изолированные границы аутентификации, поэтому
два профиля могут указывать на разные приложения/аккаунты Google OAuth. Зарегистрируйте это
один раз для каждого профиля, которому требуется доставка вложений Google Chat.

### Индивидуальная авторизация (в чате)

Каждый пользователь запускает поток один раз в своем личном сообщении с ботом:

1. Они отправляют боту `/setup-files`. Он отвечает статусом и следующим
   шаг.
2. Они отправляют `/setup-files start`. Бот отвечает URL-адресом OAuth.
3. Они открывают URL-адрес, нажимают **Разрешить** и видят, что браузер не загружается.
   `http://localhost:1/?...&code=...`. Ожидается этот сбой — авторизация
   код находится в строке URL.
4. Они копируют неверный URL-адрес (или просто значение `code=...`) и вставляют его обратно.
   в чат под именем `/setup-files <PASTED_URL>`. Бот обменивает его на
   обновить токен.

Токен приземлится по адресу `~/.hermes/google_chat_user_tokens/<sanitized_email>.json`.
Последующие запросы файлов в DM этого пользователя используют *их* токен, поэтому бот
загружается по мере их загрузки, и сообщение попадает в их пространство.

Чтобы отозвать позже: `/setup-files revoke` удаляет только токен этого пользователя. Другое
токены пользователей остаются нетронутыми.

### Область применения

Поток запрашивает ровно одну область: `chat.messages.create`. Это охватывает оба
`media.upload` и `messages.create`, которые ссылаются на загруженный
`attachmentDataRef`. Ни Диска, ни более широких возможностей Чата — это минимум привилегий.
специально.

### Многопользовательское поведение

Когда у спрашивающего еще нет токена для каждого пользователя, бот возвращается к устаревшему варианту.
однопользовательский токен по адресу `~/.hermes/google_chat_user_token.json` (если присутствует из
пред-многопользовательская установка). Если ни то, ни другое недоступно, бот публикует ясное сообщение.
текстовое уведомление, предлагающее запрашивающему запустить `/setup-files`.

Пользователь, отменяющий подписку, очищает только свой слот. 401/403 от токена одного пользователя
удаляет только кеш этого пользователя. Пользователи не мешают друг другу.

## Устранение неполадок

**Бот молчит после отправки «привет».**

1. Убедитесь, что в консоли подписки Pub/Sub есть недоставленные сообщения.
   Если это так, значит, Гермес не прошел аутентификацию — проверьте `GOOGLE_CHAT_SERVICE_ACCOUNT_JSON`.
   и что SA указан в подписке как `Pub/Sub Subscriber`.
2. Если в подписке нет сообщений, Google Chat не публикует.
   Дважды проверьте привязку IAM в **теме**:
   `chat-api-push@system.gserviceaccount.com` должен иметь `Pub/Sub Publisher`.
3. Проверьте журналы `hermes gateway` на наличие `[GoogleChat] Connected`. Если ты видишь
   `[GoogleChat] Config validation failed`, в сообщении об ошибке будет указано, какой
   env var, чтобы исправить.

**Бот отвечает, но вместо ответа агента появляется сообщение об ошибке.**

Проверьте журналы для `[GoogleChat] Pub/Sub stream died` — если они повторяются, ваш SA
учетные данные могли быть заменены или подписка удалена. После 10 попыток
адаптер становится фатальным.

**"403 Запрещено" в каждом исходящем сообщении.**

Бот был удален из пространства, или вы отозвали его в консоли Chat API.
Переустановите его в пространстве (следующее событие `ADDED_TO_SPACE` снова включит
автоматический обмен сообщениями).

**Слишком много предупреждений о превышении лимита скорости.**

Квоты Chat API по умолчанию допускают 60 сообщений на место в минуту. Если ваш
агент выдает длинные потоковые ответы, которые превышают это значение, адаптер повторяет попытку
с экспоненциальной задержкой — но вы все равно увидите задержку, видимую пользователем. Рассмотрим
краткие ответы или повышение квоты в консоли GCP.

**Бот продолжает публиковать уведомление «/setup-files» вместо файлов.**

У аскера нет токена OAuth для каждого пользователя, и нет устаревшего резервного варианта. Беги
`/setup-files` в личном сообщении и следуйте шагу 10. После завершения обмена
следующий запрос файла загружается автоматически без перезапуска шлюза.

**`/setup-files start` говорит: «Учетные данные клиента не сохранены».**

Одноразовая настройка не была выполнена *для этого профиля* (секрет клиента
на уровне профиля, поэтому регистрация под одним профилем не будет видна другому).
Из терминала запустите его под профилем, который использует шлюз:

```bash
# Default profile:
python -m plugins.platforms.google_chat.oauth \
    --client-secret /path/to/client_secret.json

# Named profile:
hermes -p <profile> python -m plugins.platforms.google_chat.oauth \
    --client-secret /path/to/client_secret.json
```

Затем отправьте `/setup-files start` еще раз.

**`/setup-files <PASTED_URL>` сообщает: «Ошибка обмена токенов».**

Код авторизации является одноразовым и недолговечным (обычно несколько минут). Отправить
`/setup-files start`, чтобы получить новый URL-адрес и повторить попытку.

## Примечания по безопасности

- **Область учетной записи службы**: адаптер запрашивает области `chat.bot` и `pubsub`.
  IAM должен быть фактическим обеспечением соблюдения требований — предоставьте вашему SA минимум
  (`roles/pubsub.subscriber` + `roles/pubsub.viewer` по подписке), а не
  Роли Pub/Sub на уровне проекта или организации.
- **Защита от загрузки вложений**: Hermes прикрепит только носитель SA.
  токен для URL-адресов, хост которых соответствует короткому белому списку доменов, принадлежащих Google.
  (`googleapis.com`, `drive.google.com`, `lh[3-6].googleusercontent.com` и
  несколько других). Любой другой хост отклоняется до HTTP-запроса, чтобы
  защитить от сценариев SSRF, в которых созданное событие может перенаправить
  токен носителя для службы метаданных GCE.
- **Редактирование**: электронные письма сервисных учетных записей, пути подписки и пути к темам.
  удаляются из вывода журнала `agent/redact.py`. Дамп отладочного конверта
  (`GOOGLE_CHAT_DEBUG_RAW=1`) проходит через тот же фильтр редактирования и
  журналы на уровне DEBUG.
- **Соответствие**: если вы планируете подключить этого бота к регулируемой рабочей области.
  (что-либо с политикой размещения данных или управления ИИ), получите это одобрение
  перед первой установкой.
- **Область действия OAuth пользователя**: *только* запросы потока вложений для каждого пользователя.
  `chat.messages.create` — минимум, охватывающий `media.upload` плюс
  продолжение `messages.create`. Токены сохраняются в виде простого JSON по адресу
  `~/.hermes/google_chat_user_tokens/<sanitized_email>.json` (файловая система
  разрешения — это защита — та же модель, что и файл ключа SA). Каждый
  токен принадлежит ровно одному пользователю; revoke распространяется на этого пользователя.
