# Настройка матрицы

Hermes Agent интегрируется с Matrix, открытым федеративным протоколом обмена сообщениями. Matrix позволяет вам запустить собственный домашний сервер или использовать общедоступный, такой как Matrix.org — в любом случае вы сохраняете контроль над своими коммуникациями. Бот подключается через `mautrix` Python SDK, обрабатывает сообщения через конвейер агента Hermes (включая использование инструментов, память и рассуждения) и отвечает в режиме реального времени. Он поддерживает текст, вложения файлов, изображения, аудио, видео и дополнительное сквозное шифрование (E2EE).

Hermes работает с любым домашним сервером Matrix — Synapse, Conduit, Dendrite или Matrix.org.

Прежде чем приступить к настройке, вот что большинство людей хотят знать: как ведет себя Hermes после подключения.

## Как ведет себя Гермес

| Контекст | Поведение |
|---------|----------|
| **DM** | Гермес отвечает на каждое сообщение. `@mention` не требуется. У каждого DM есть своя сессия. Установите `MATRIX_DM_MENTION_THREADS=true`, чтобы начать обсуждение, когда бот `@mentioned` в личном сообщении. |
| **Номера** | По умолчанию для ответа Hermes требуется `@mention`. Установите `MATRIX_REQUIRE_MENTION=false` или добавьте идентификаторы комнат к `MATRIX_FREE_RESPONSE_ROOMS` для комнат с бесплатными ответами. Приглашения в комнаты принимаются автоматически. |
| **Темы** | Hermes поддерживает потоки Matrix (MSC3440). Если вы отвечаете в теме, Hermes сохраняет контекст темы изолированным от основной временной шкалы комнаты. Темы, в которых уже участвовал бот, упоминания не требуют. |
| **Автоматическая обработка** | По умолчанию Hermes автоматически создает цепочку сообщений для каждого сообщения, на которое отвечает в комнате. Это делает разговоры изолированными. Установите `MATRIX_AUTO_THREAD=false` для отключения. Установите `MATRIX_DM_AUTO_THREAD=true` (по умолчанию false), чтобы также автоматически создавать потоки для сообщений DM — это отличается от `MATRIX_DM_MENTION_THREADS`, который запускает поток только тогда, когда бот находится `@mentioned` в DM. |
| **Команды** | Hermes принимает обычные `/commands`, когда их отправляет ваш клиент Matrix. Если ваш клиент резервирует `/` для локальных команд, используйте вместо него `!commands`; Hermes нормализует известные псевдонимы `!command` до `/command`. |
| **Интерактивное управление** | Утверждение опасной команды и выбор `/model` могут использовать реакции Matrix. Реакция одобрения может быть ограничена пользователем, запросившим действие. |
| **Мышление и инструментальная деятельность** | Matrix использует связанные, редактируемые панели мышления/действия инструментов, когда включен прогресс шлюза, поэтому обновления не заполоняют временную шкалу основной комнаты. |
| **Общие комнаты с несколькими пользователями** | По умолчанию Hermes изолирует историю сеансов каждого пользователя внутри комнаты. Два человека, разговаривающие в одной комнате, не будут использовать одну стенограмму, если вы явно не отключите ее. |

:::совет
Бот автоматически присоединяется к комнатам по приглашению. Просто пригласите пользователя Matrix бота в любую комнату, и он присоединится и начнет отвечать.
:::

### Модель сеанса в матрице

По умолчанию:

- каждый DM получает свой сеанс
- каждый поток получает собственное пространство имен сеанса
- каждый пользователь в общей комнате получает свой собственный сеанс внутри этой комнаты

Это контролируется `config.yaml`:

```yaml
group_sessions_per_user: true
```

Установите значение `false` только в том случае, если вы явно хотите, чтобы один общий разговор был для всей комнаты:

```yaml
group_sessions_per_user: false
```

Общие сеансы могут быть полезны для совместной комнаты, но они также означают:

- пользователи разделяют рост контекста и стоимость токенов
- длительная и трудоемкая задача, выполняемая одним человеком, может раздуть контекст остальных
- бег одного человека в полете может прервать наблюдение другого человека в той же комнате

### Упоминание и конфигурация потоков

Вы можете настроить упоминание и поведение автоматической потоковой обработки с помощью переменных среды или `config.yaml`:

```yaml
matrix:
  require_mention: true           # Require @mention in rooms (default: true)
  allowed_users:                  # Matrix users allowed to trigger agent turns
    - "@alice:matrix.org"
  allowed_rooms:                  # Matrix rooms allowed to trigger agent turns
    - "!abc123:matrix.org"
  free_response_rooms:            # Rooms exempt from mention requirement
    - "!abc123:matrix.org"
  ignore_user_patterns:           # Bridge/appservice ghost users to ignore
    - "^@telegram_"
    - "^@whatsapp_"
  process_notices: false          # Ignore m.notice by default
  session_scope: room             # auto|room|thread; room is recommended for project rooms
  auto_thread: true               # Auto-create threads for responses (default: true)
  dm_mention_threads: false       # Create thread when @mentioned in DM (default: false)
  max_message_length: 16000       # Outbound chunk size in chars (default: 16000, max: 65535)
```

Или через переменные среды:

```bash
MATRIX_REQUIRE_MENTION=true
MATRIX_ALLOWED_USERS=@alice:matrix.org
MATRIX_ALLOWED_ROOMS=!abc123:matrix.org
MATRIX_FREE_RESPONSE_ROOMS=!abc123:matrix.org,!def456:matrix.org
MATRIX_IGNORE_USER_PATTERNS='^@telegram_,^@whatsapp_'
MATRIX_PROCESS_NOTICES=false
MATRIX_SESSION_SCOPE=room       # recommended for stable project-room context
MATRIX_AUTO_THREAD=true
MATRIX_DM_MENTION_THREADS=false
MATRIX_REACTIONS=true          # default: true — emoji reactions during processing
MATRIX_ALLOW_ROOM_MENTIONS=false
```

:::tip Отключение реакций
`MATRIX_REACTIONS=false` отключает эмодзи-реакции жизненного цикла обработки (👀/ ✅/❌), которые бот публикует на входящие сообщения. Полезно для комнат, где события реакции шумные или не поддерживаются всеми участвующими клиентами.
:::

:::tip Упоминания по всей комнате
Hermes отправляет структурированные упоминания пользователей Matrix для явных идентификаторов Matrix, таких как `@alice:example.org`. Уведомления `@room` для всей комнаты отключены по умолчанию; устанавливайте `MATRIX_ALLOW_ROOM_MENTIONS=true` только в комнатах, где боту разрешено уведомлять всех.
:::

:::примечание
Если вы обновляетесь с версии, в которой не было `MATRIX_REQUIRE_MENTION`, бот ранее отвечал на все сообщения в комнатах. Чтобы сохранить это поведение, установите `MATRIX_REQUIRE_MENTION=false`.
:::

### Изоляция помещения проекта

Если вы используете одного и того же бота Matrix в нескольких комнатах проекта, настройте стабильную
сеансы в помещении:

```bash
MATRIX_SESSION_SCOPE=room
MATRIX_AUTO_THREAD=false
```

`MATRIX_SESSION_SCOPE` принимает:

| Область применения | Поведение |
|-------|----------|
| `auto` | Обратная совместимость по умолчанию. Существующее поведение `MATRIX_AUTO_THREAD` управляет синтетическими потоками. |
| `room` | Незакрепленные сообщения комнаты остаются в одном стабильном сеансе комнаты. Потоки Real Matrix по-прежнему используют свой корень потока. |
| `thread` | Сообщения комнаты без цепочки синтезируют поток/сеанс на основе идентификатора инициирующего события. |

Гермес теперь включает текущее название комнаты Матрицы, идентификатор комнаты, тему, идентификатор сообщения,
и примечание о границе комнаты Матрицы в подсказке агента. `/status` также показывает
текущая область комнаты/сеанса Matrix, и `/resume` не будет автоматически возобновлять
именованный сеанс из другой комнаты Matrix, если вы явно не используете
`/resume --cross-room <session name>`.

`MATRIX_SESSION_SCOPE=room` управляет комнатой/полосой потока. Существующие
Параметр `group_sessions_per_user` по-прежнему контролирует, будут ли пользователи находиться внутри этой комнаты.
поделитесь полосой. Используя `group_sessions_per_user: true` (по умолчанию), Алиса и Боб получают
отдельные сессии проекта B. С `group_sessions_per_user: false` в комнате есть
одна общая стенограмма проекта B.

Это руководство проведет вас через весь процесс настройки — от создания учетной записи бота до отправки первого сообщения.

## Шаг 1: Создайте учетную запись бота

Для работы бота вам понадобится учетная запись пользователя Matrix. Есть несколько способов сделать это:

### Вариант А: зарегистрируйтесь на своем домашнем сервере (рекомендуется)

Если вы используете собственный домашний сервер (Synapse, Conduit, Dendrite):

1. Используйте API администратора или инструмент регистрации, чтобы создать нового пользователя:

```bash
# Synapse example
register_new_matrix_user -c /etc/synapse/homeserver.yaml http://localhost:8008
```

2. Выберите имя пользователя, например `hermes` — полный идентификатор пользователя будет `@hermes:your-server.org`.

### Вариант Б: используйте Matrix.org или другой публичный домашний сервер

1. Перейдите в [Element Web](https://app.element.io) и создайте новую учетную запись.
2. Выберите имя пользователя для своего бота (например, `hermes-bot`).

### Вариант C: использовать свою учетную запись

Вы также можете запустить Hermes как свой собственный пользователь. Это означает, что бот публикует сообщения от вашего имени — полезно для личных помощников.

## Шаг 2. Получите токен доступа

Гермесу нужен токен доступа для аутентификации на домашнем сервере. У вас есть два варианта:

### Вариант A: токен доступа (рекомендуется)

Самый надежный способ получить токен:

**Через элемент:**
1. Войдите в [Element](https://app.element.io) под учетной записью бота.
2. Откройте **Настройки** → **Справка и информация**.
3. Прокрутите вниз и разверните **Дополнительно** — там отображается токен доступа.
4. **Скопируйте немедленно.**

**Через API:**

```bash
curl -X POST https://your-server/_matrix/client/v3/login \
  -H "Content-Type: application/json" \
  -d '{
    "type": "m.login.password",
    "user": "@hermes:your-server.org",
    "password": "your-password"
  }'
```

В ответе есть поле `access_token` — скопируйте его.

:::предупреждение[Храните свой токен доступа в безопасности]
Токен доступа дает полный доступ к учетной записи бота Matrix. Никогда не делитесь им публично и не передавайте его в Git. В случае взлома отмените его, выйдя из всех сеансов этого пользователя.
:::

### Вариант Б: Вход с паролем

Вместо предоставления токена доступа вы можете предоставить Hermes идентификатор пользователя и пароль бота. Гермес автоматически войдет в систему при запуске. Это проще, но означает, что пароль хранится в вашем файле `.env`.

```bash
MATRIX_USER_ID=@hermes:your-server.org
MATRIX_PASSWORD=your-password
```

## Шаг 3. Найдите свой идентификатор пользователя Matrix

Агент Hermes использует ваш идентификатор пользователя Matrix, чтобы контролировать, кто может взаимодействовать с ботом. Идентификаторы пользователей Matrix имеют формат `@username:server`.

Чтобы найти свой:

1. Откройте [Element](https://app.element.io) (или предпочитаемый вами клиент Matrix).
2. Нажмите на свой аватар → **Настройки**.
3. Ваш идентификатор пользователя отображается в верхней части профиля (например, `@alice:matrix.org`).

:::совет
Идентификаторы пользователей Matrix всегда начинаются с `@` и содержат `:`, за которым следует имя сервера. Например: `@alice:matrix.org`, `@bob:your-server.com`.
:::

## Шаг 4. Настройка агента Hermes

### Вариант A: Интерактивная настройка (рекомендуется)

Запустите команду управляемой настройки:

```bash
hermes gateway setup
```

При появлении запроса выберите **Матрица**, а затем укажите URL-адрес домашнего сервера, токен доступа (или идентификатор пользователя + пароль) и разрешенные идентификаторы пользователей, когда его спросят.

### Вариант Б: Настройка вручную

Добавьте следующее в ваш файл `~/.hermes/.env`:

**Использование токена доступа:**

```bash
# Required
MATRIX_HOMESERVER=https://matrix.example.org
MATRIX_ACCESS_TOKEN=***

# Optional: user ID (auto-detected from token if omitted)
# MATRIX_USER_ID=@hermes:matrix.example.org

# Security: restrict who can interact with the bot
MATRIX_ALLOWED_USERS=@alice:matrix.example.org

# Optional: restrict which rooms can trigger the bot
MATRIX_ALLOWED_ROOMS=!abc123:matrix.example.org

# Multiple allowed users (comma-separated)
# MATRIX_ALLOWED_USERS=@alice:matrix.example.org,@bob:matrix.example.org
```

**Использование пароля для входа:**

```bash
# Required
MATRIX_HOMESERVER=https://matrix.example.org
MATRIX_USER_ID=@hermes:matrix.example.org
MATRIX_PASSWORD=***

# Security
MATRIX_ALLOWED_USERS=@alice:matrix.example.org
```

## Усиление защиты при частном развертывании

Для частных развертываний Matrix задайте белые списки пользователей и комнат. Если
`MATRIX_ALLOWED_USERS` не настроен, любой отправитель, который может связаться с ботом в присоединенном
комната может вызвать ход агента. Если `MATRIX_ALLOWED_ROOMS` не установлен, любая комната,
Присоединение ботов может вызвать смену агента. При заблокированном развертывании должны быть установлены оба:

```bash
MATRIX_ALLOWED_USERS=@alice:matrix.example.org,@bob:matrix.example.org
MATRIX_ALLOWED_ROOMS=!ops:matrix.example.org,!dmroom:matrix.example.org
```

Развертывания мостов и служб приложений требуют дополнительной защиты от петель. Гермес всегда
игнорирует свои собственные события, пользователей в стиле службы приложений Matrix, чья локальная часть запускается
с `_`, повторяющиеся идентификаторы событий, старые события запуска, изменения событий замены и
`m.notice` событий по умолчанию. Добавляйте шаблоны призраков мостов, специфичные для развертывания, когда
ваш мост использует другое соглашение об именах:

```bash
MATRIX_IGNORE_USER_PATTERNS='^@telegram_,^@slack_,^@whatsapp_'
```

Включайте уведомления только тогда, когда доверенный рабочий процесс действительно отправляет `m.notice`:

```bash
MATRIX_PROCESS_NOTICES=true
```

Исходящие уведомления для всей комнаты по умолчанию отключены. Держите
`MATRIX_ALLOW_ROOM_MENTIONS=false`, если боту явно не разрешено пробуждение
всю комнату с `@room`.

Полезные данные диагностики и отладки редактируют токены доступа Matrix, ключи восстановления,
идентификаторы устройств и тела сообщений. Загрузка мультимедиа ограничена Matrix
`mxc://` URI контента и отклоняются, когда они превышают `MATRIX_MAX_MEDIA_BYTES`.
Рассматривайте объединенные комнаты и ненадежные домашние серверы как ненадежные входные данные: сохраняйте место
строгие списки разрешенных, отдавайте предпочтение личным сообщениям или отдельным комнатам для трудоемкой работы и избегайте
авторизация призраков моста или марионеток службы приложений в качестве разрешенных пользователей.

Дополнительные настройки поведения в `~/.hermes/config.yaml`:

```yaml
group_sessions_per_user: true
```

- `group_sessions_per_user: true` изолирует контекст каждого участника внутри общих комнат.

### Запуск шлюза

После настройки запустите шлюз Matrix:

```bash
hermes gateway
```

Бот должен подключиться к вашему домашнему серверу и начать синхронизацию в течение нескольких секунд. Отправьте ему сообщение — либо в DM, либо в комнату, к которой он присоединился — для проверки.

:::совет
Вы можете запустить `hermes gateway` в фоновом режиме или в качестве службы systemd для постоянной работы. Подробности см. в документации по развертыванию.
:::

## Сквозное шифрование (E2EE)

Hermes поддерживает сквозное шифрование Matrix, поэтому вы можете общаться со своим ботом в зашифрованных комнатах.

### Требования

Для E2EE требуется библиотека `mautrix` с дополнительными функциями шифрования и библиотека `libolm` C:

```bash
# Install mautrix with E2EE support
pip install 'mautrix[encryption]'

# Or install with hermes extras
cd ~/.hermes/hermes-agent && uv pip install -e ".[matrix]"
```

Вам также необходимо установить `libolm` в вашей системе:

```bash
# Debian/Ubuntu
sudo apt install libolm-dev

# macOS
brew install libolm

# Fedora
sudo dnf install libolm-devel
```

### Включить E2EE

Добавьте в свой `~/.hermes/.env`:

```bash
MATRIX_E2EE_MODE=required
```

`MATRIX_E2EE_MODE` принимает:

| Режим | Поведение |
|------|----------|
| `off` | Не инициализируйте матрицу E2EE. |
| `optional` | Попробуйте E2EE, когда зависимости доступны, но сохраняйте работу незашифрованных комнат, если криптографическая система не может инициализироваться. |
| `required` | Сбой закрытия, если зависимости E2EE или настройка шифрования недоступны. |

Дополнительный режим может вернуться к работе без E2EE, если настройка шифрования недоступна. Обязательный режим не закрывается вместо тихого перехода на более раннюю версию.

В целях обратной совместимости `MATRIX_ENCRYPTION=true` по-прежнему обеспечивает необходимое поведение E2EE.

Когда E2EE включен, Hermes:

- Хранит ключи шифрования в `~/.hermes/platforms/matrix/store/` (старые версии: `~/.hermes/matrix/store/`).
- Загружает ключи устройства при первом подключении
- Расшифровывает входящие сообщения и автоматически шифрует исходящие сообщения.
- Автоматическое присоединение к зашифрованным комнатам по приглашению

### Инструменты и элементы управления матрицы

В разговорах о Матрице Гермес предоставляет агенту инструменты, специфичные для Матрицы:

- `matrix_send_reaction`
- `matrix_redact_message`
- `matrix_create_room`
- `matrix_invite_user`
- `matrix_fetch_history`
- `matrix_set_presence`

Эти инструменты привязаны к контекстам Matrix и недоступны в наборах инструментов, отличных от Matrix. Инструменты администрирования по умолчанию отключены: для редактирования требуется `MATRIX_TOOLS_ALLOW_REDACTION=true`, для приглашений требуется `MATRIX_TOOLS_ALLOW_INVITES=true`, а для создания комнаты требуется `MATRIX_TOOLS_ALLOW_ROOM_CREATE=true`. Для создания общественной комнаты также требуется `MATRIX_ALLOW_PUBLIC_ROOMS=true`.
Если установлен `MATRIX_ALLOWED_ROOMS`, инструменты Matrix могут ориентироваться только на эти комнаты.

Для контроля реакции используются:

- ✅одобрить один раз
- ♾️ всегда одобряю
- ❌ отрицать
- числовые реакции на `/model` вариантов выбора

Установите `MATRIX_APPROVAL_REQUIRE_SENDER=false`, если вы намеренно хотите, чтобы любой авторизованный пользователь Matrix в комнате использовал запрос на утверждение/выбор модели. По умолчанию используется привязка к запрашивающему, когда Hermes знает, кто запросил действие.

### Ограничения по медиа

Hermes загружает и скачивает изображения, файлы, аудио и видео Matrix через медиа-API Matrix. Несколько сгенерированных изображений отправляются как один упорядоченный логический пакет, сохраняя заголовки и контекст потока во всем пакете.

По умолчанию носители Matrix размером более 100 МБ отклоняются перед загрузкой/выгрузкой. Переопределить с помощью:

```bash
MATRIX_MAX_MEDIA_BYTES=104857600
```

Входящие медиафайлы должны использовать URI контента Matrix `mxc://`. Гермес отвергает произвол
URL-адреса мультимедиа HTTP(S) в событиях Matrix, чтобы избежать превращения объединенной комнаты в
неограниченный загрузчик.

### Проверка перекрестной подписи (рекомендуется)

Если в вашей учетной записи Matrix включена перекрестная подпись (по умолчанию в Element), установите ключ восстановления, чтобы бот мог самостоятельно подписывать свое устройство при запуске. Без этого другие клиенты Matrix могут отказаться делиться сеансами шифрования с ботом после смены ключа устройства.

```bash
MATRIX_RECOVERY_KEY=EsT... your recovery key here
```

**Где его найти:** В Element выберите **Настройки** → **Безопасность и конфиденциальность** → **Шифрование** → ваш ключ восстановления (также называемый «Ключ безопасности»). Это ключ, который вас попросили сохранить при первой настройке перекрестной подписи.

При каждом запуске, если установлен `MATRIX_RECOVERY_KEY`, Hermes импортирует ключи перекрестной подписи из безопасного секретного хранилища домашнего сервера и подписывает текущее устройство. Это идемпотентно, и его можно безопасно оставить включенным навсегда.

Если Hermes загружает новый ключ восстановления Matrix, он никогда не регистрирует необработанный ключ. Установить
`MATRIX_RECOVERY_KEY_OUTPUT_FILE=/secure/path/matrix-recovery-key.txt` раньше
запуск для однократной записи сгенерированного ключа в файловом режиме `0600`; файл не
перезаписано, если оно уже существует.

:::предупреждение[Удаление криптохранилища]
Если вы удалите `~/.hermes/platforms/matrix/store/crypto.db`, бот потеряет свою шифровальную идентификацию. Простой перезапуск с тем же идентификатором устройства **не** полностью восстановится — домашний сервер по-прежнему хранит одноразовые ключи, подписанные старым ключом идентификации, а одноранговые узлы не могут устанавливать новые сеансы Olm.

Hermes обнаруживает это состояние при запуске и отказывается включать E2EE, записывая в журнал: `device XXXX has stale one-time keys on the server signed with a previous identity key`.

**Самое простое восстановление: создайте новый токен доступа** (который получает новый идентификатор устройства без устаревшей истории ключей). См. раздел «Обновление предыдущей версии с помощью E2EE» ниже. Это наиболее надежный путь, позволяющий избежать вмешательства в базу данных домашнего сервера.

**Восстановление вручную** (расширенное — сохраняет тот же идентификатор устройства):

1. Остановите Synapse и удалите старое устройство из его базы данных:
   ```bash
   sudo systemctl stop matrix-synapse
   sudo sqlite3 /var/lib/matrix-synapse/homeserver.db "
     DELETE FROM e2e_device_keys_json WHERE device_id = 'DEVICE_ID' AND user_id = '@hermes:your-server';
     DELETE FROM e2e_one_time_keys_json WHERE device_id = 'DEVICE_ID' AND user_id = '@hermes:your-server';
     DELETE FROM e2e_fallback_keys_json WHERE device_id = 'DEVICE_ID' AND user_id = '@hermes:your-server';
     DELETE FROM devices WHERE device_id = 'DEVICE_ID' AND user_id = '@hermes:your-server';
   "
   sudo systemctl start matrix-synapse
   ```
   Или через API администратора Synapse (обратите внимание на идентификатор пользователя в URL-адресе):
   ```bash
   curl -X DELETE -H "Authorization: Bearer ADMIN_TOKEN" \
     'https://your-server/_synapse/admin/v2/users/%40hermes%3Ayour-server/devices/DEVICE_ID'
   ```
   Примечание. Удаление устройства через API администратора также может привести к аннулированию связанного токена доступа. Возможно, после этого вам придется сгенерировать новый токен.

2. Удалите локальный криптомагазин и перезапустите Hermes:
   ```bash
   rm -f ~/.hermes/platforms/matrix/store/crypto.db*
   # restart hermes
   ```

Другие клиенты Matrix (Element, Matrix-Commander) могут кэшировать старые ключи устройства. После восстановления введите `/discardsession` в Element, чтобы принудительно запустить новый сеанс шифрования с ботом.
:::

:::информация
Если `mautrix[encryption]` не установлен или `libolm` отсутствует, бот автоматически переключается на простой (незашифрованный) клиент. Вы увидите предупреждение в журналах.
:::

## Домашняя комната

Вы можете назначить «домашнюю комнату», куда бот будет отправлять упреждающие сообщения (например, выходные данные заданий cron, напоминания и уведомления). Есть два способа установить его:

### Использование команды косой черты

Введите `/sethome` в любой комнате Матрицы, где присутствует бот. Эта комната становится домашней комнатой.
Если ваш клиент Matrix перехватывает команды с косой чертой, введите вместо этого `!sethome`.

### Ручная настройка

Добавьте это в свой `~/.hermes/.env`:

```bash
MATRIX_HOME_ROOM=!abc123def456:matrix.example.org
```

## Белый список комнат (`allowed_rooms`)

Ограничьте работу бота фиксированным набором комнат Matrix. Если этот параметр установлен, бот **только** отвечает в комнатах, идентификатор которых указан в списке — сообщения из любой другой комнаты молча игнорируются, даже если бот упоминается.

**DM (прямые чаты) освобождены** от этого фильтра, поэтому авторизованные пользователи всегда могут связаться с ботом один на один.

```yaml
matrix:
  allowed_rooms:
    - "!abc123def456:matrix.example.org"
    - "!opsroom789:matrix.example.org"
```

Или через env var (через запятую):

```bash
MATRIX_ALLOWED_ROOMS="!abc123def456:matrix.example.org,!opsroom789:matrix.example.org"
```

Поведение:

- Пусто/не установлено → нет ограничений (по умолчанию).
- Непусто → идентификатор комнаты должен быть в списке. Проверка выполняется **перед** любой другой проверкой (упоминание требования, список разрешенных отправителей и т. д.).
– Используйте **внутренний идентификатор** комнаты (`!abc...:server`), а не ее псевдоним (`#room:server`). Внутренний идентификатор комнаты можно найти в Element через «Комната» → «Настройки» → «Дополнительно».

См. также: [разделение команд администратора и пользователя](../../reference/slash-commands.md#permissions-and-adminuser-split).


:::совет
Чтобы найти идентификатор комнаты: в Element перейдите в комнату → **Настройки** → **Дополнительно** → там отображается **Внутренний идентификатор комнаты** (начинается с `!`).
:::

## Команды в матрице

Hermes поддерживает в Matrix те же команды шлюза, что и в других
платформы обмена сообщениями, включая `/commands`, `/model`, `/stop`, `/queue`,
`/steer`, `/goal`, `/subgoal`, `/background`, `/bg`, `/btw`, `/tasks` и
`/yolo`.

Некоторые клиенты Matrix резервируют ведущий `/` для команд локального клиента и могут не
отправить в комнату неизвестные слэш-команды. В этом случае используйте `!` в качестве безопасного для Matrix.
псевдоним:

```text
!commands
!model
!model gpt-5.5 --provider openrouter
!queue continue with the next task
!stop
```

Hermes нормализует `!command` только тогда, когда команда известна шлюзу,
зарегистрированная команда плагина или установленная команда навыка. Обычные восклицания
такие как `!important`, остаются обычными сообщениями чата.

## Устранение неполадок

### Бот не отвечает на сообщения

**Причина**: бот не присоединился к комнате, `MATRIX_ALLOWED_USERS` не содержит вашего идентификатора пользователя, `MATRIX_ALLOWED_ROOMS` не включает комнату или в сообщении комнаты не упоминается бот.

**Исправление**: пригласите бота в комнату — он автоматически присоединяется по приглашению. Убедитесь, что ваш идентификатор пользователя имеет формат `MATRIX_ALLOWED_USERS` (используйте полный формат `@user:server`), а идентификатор комнаты — формат `MATRIX_ALLOWED_ROOMS`, если этот белый список настроен. В комнатах упоминайте бота или добавляйте комнату в `MATRIX_FREE_RESPONSE_ROOMS`. Перезапустите шлюз.

### Бот присоединяется к комнатам, но молча удаляет каждое сообщение (перекос часов)

**Причина**: системные часы хоста опережают реальное время. Адаптер Matrix применяет 5-секундный фильтр отсрочки запуска (`event_ts < startup_ts - 5`), чтобы игнорировать события, воспроизводимые при начальной синхронизации. Когда настенные часы идут впереди, каждое входящее событие выглядит «старее, чем запуск» и отбрасывается, не дойдя до обработчика сообщений — бот выглядит подключенным, но никогда не отвечает. См. [#12614](https://github.com/NousResearch/hermes-agent/issues/12614).

**Признак**: В журнале шлюза отображается `Matrix: dropped N live events as 'too old' more than 30s after startup`.

**Исправление**: синхронизируйте часы хоста с NTP и перезапустите бота:

```bash
# Debian/Ubuntu
sudo timedatectl set-ntp true
timedatectl status   # confirm "System clock synchronized: yes"

# macOS
sudo sntp -sS time.apple.com
```

### «Не удалось выполнить аутентификацию» / «Ошибка Whoami» при запуске

**Причина**: токен доступа или URL-адрес домашнего сервера неверен.

**Исправление**. Убедитесь, что `MATRIX_HOMESERVER` указывает на ваш домашний сервер (включая `https://`, без косой черты в конце). Убедитесь, что `MATRIX_ACCESS_TOKEN` действителен — попробуйте это с помощью Curl:

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://your-server/_matrix/client/v3/account/whoami
```

Если это вернет вашу информацию о пользователе, токен действителен. Если он возвращает ошибку, сгенерируйте новый токен.

### Ошибка «Маутрикс не установлен»

**Причина**: Пакет Python `mautrix` не установлен.

**Исправление**. Установите:

```bash
pip install 'mautrix[encryption]'
```

Или с дополнениями Hermes:

```bash
cd ~/.hermes/hermes-agent && uv pip install -e ".[matrix]"
```

### Ошибки шифрования / «не удалось расшифровать событие»

**Причина**: отсутствуют ключи шифрования, `libolm` не установлен или устройство бота не является доверенным.

**Исправление**:
1. Убедитесь, что `libolm` установлен в вашей системе (см. раздел E2EE выше).
2. Убедитесь, что `MATRIX_ENCRYPTION=true` установлен в вашем `.env`.
3. В клиенте Matrix (Element) перейдите в профиль бота -> Сеансы -> проверить/доверить устройству бота.
4. Если бот только что присоединился к зашифрованной комнате, он сможет расшифровать только сообщения, отправленные *после* его присоединения. Старые сообщения недоступны.

### Обновление предыдущей версии с помощью E2EE

:::совет
Если вы также удалили `crypto.db` вручную, см. предупреждение «Удаление криптохранилища» в разделе E2EE выше — существуют дополнительные шаги по удалению устаревших одноразовых ключей с домашнего сервера.
:::

Если вы ранее использовали Hermes с `MATRIX_ENCRYPTION=true` и обновляетесь до
версия, которая использует новое криптохранилище на базе SQLite, шифрование бота
личность изменилась. Ваш клиент Matrix (Element) может кэшировать старые ключи устройства.
и отказаться делиться сеансами шифрования с ботом.

**Симптомы**: Бот подключается и показывает в журналах сообщение «E2EE включено», но все
сообщения показывают «не удалось расшифровать событие», и бот никогда не отвечает.

**Что происходит**: старое состояние шифрования (из предыдущего `matrix-nio` или
серверная часть `mautrix` на основе сериализации) несовместима с новой криптографией SQLite.
магазин. Бот создает новый идентификатор шифрования, но ваш клиент Matrix все еще
имеет старые ключи в кэше и не будет делиться сеансом шифрования комнаты с
устройство, ключи которого изменились. Это функция безопасности Matrix. Клиенты относятся
изменены идентификационные ключи для того же устройства, что и подозрительное.

**Исправление** (однократный перенос):

1. **Создайте новый токен доступа**, чтобы получить новый идентификатор устройства. Самый простой способ:

   ```bash
   curl -X POST https://your-server/_matrix/client/v3/login \
     -H "Content-Type: application/json" \
     -d '{
       "type": "m.login.password",
       "identifier": {"type": "m.id.user", "user": "@hermes:your-server.org"},
       "password": "***",
       "initial_device_display_name": "Hermes Agent"
     }'
   ```

   Скопируйте новый `access_token` и обновите `MATRIX_ACCESS_TOKEN` в `~/.hermes/.env`.

2. **Удалить старое состояние шифрования**:

   ```bash
   rm -f ~/.hermes/platforms/matrix/store/crypto.db
   rm -f ~/.hermes/platforms/matrix/store/crypto_store.*
   ```

3. **Установите ключ восстановления** (если вы используете перекрестную подпись — так делает большинство пользователей Element). Добавьте в `~/.hermes/.env`:

   ```bash
   MATRIX_RECOVERY_KEY=EsT... your recovery key here
   ```

   Это позволяет боту самостоятельно подписывать ключи перекрестной подписи при запуске, поэтому Element сразу же доверяет новому устройству. Без этого Element может посчитать новое устройство непроверенным и отказаться от совместного использования сеансов шифрования. Найдите свой ключ восстановления в Element в разделе **Настройки** → **Безопасность и конфиденциальность** → **Шифрование**.

4. **Заставьте клиент Matrix сменить сеанс шифрования**. В Элементе,
   откройте комнату DM с ботом и введите `/discardsession`. Это заставляет Элемент
   чтобы создать новый сеанс шифрования и поделиться им с новым устройством бота.

5. **Перезапустите шлюз**:

   ```bash
   hermes gateway run
   ```

   Если установлен `MATRIX_RECOVERY_KEY`, в журналах вы должны увидеть `Matrix: cross-signing verified via recovery key`.

6. **Отправить новое сообщение**. Бот должен расшифровать и нормально ответить.

:::примечание
После миграции сообщения, отправленные *до* обновления, не могут быть расшифрованы — старые
ключи шифрования пропали. Это влияет только на переход; новые сообщения работают
нормально.
:::

:::совет
**Новые установки не затрагиваются.** Эта миграция необходима только в том случае, если у вас
работающая установка E2EE с предыдущей версией Hermes и обновляется.

**Для чего нужен новый токен доступа?** Каждый токен доступа Matrix привязан к определенному устройству.
идентификатор. Повторное использование того же идентификатора устройства с новыми ключами шифрования приводит к тому, что другие Matrix
клиенты не доверяют устройству (они рассматривают изменение ключей идентификации как потенциальную
нарушение безопасности). Новый токен доступа получает новый идентификатор устройства без устаревшего ключа.
историю, поэтому другие клиенты сразу же ей доверяют.
:::

## Режим прокси (E2EE в macOS)

Для Matrix E2EE требуется `libolm`, который не компилируется в macOS ARM64 (Apple Silicon). Дополнительный модуль `hermes-agent[matrix]` предназначен только для Linux. Если вы используете macOS, режим прокси позволяет запускать E2EE в контейнере Docker на виртуальной машине Linux, в то время как фактический агент работает в macOS с полным доступом к вашим локальным файлам, памяти и навыкам.

### Как это работает

```
macOS (Host):
  └─ hermes gateway
       ├─ api_server adapter ← listens on 0.0.0.0:8642
       ├─ AIAgent ← single source of truth
       ├─ Sessions, memory, skills
       └─ Local file access (Obsidian, projects, etc.)

Linux VM (Docker):
  └─ hermes gateway (proxy mode)
       ├─ Matrix adapter ← E2EE decryption/encryption
       └─ HTTP forward → macOS:8642/v1/chat/completions
           (no LLM API keys, no agent, no inference)
```

Контейнер Docker обрабатывает только протокол Matrix + E2EE. Когда приходит сообщение, он расшифровывает его и пересылает текст хосту посредством стандартного HTTP-запроса. Хост запускает агент, вызывает инструменты, генерирует ответ и передает его обратно. Контейнер шифрует и отправляет ответ в Matrix. Все сеансы унифицированы — CLI, Matrix, Telegram и любая другая платформа используют одну и ту же память и историю разговоров.

### Шаг 1. Настройте хост (macOS)

Включите сервер API, чтобы хост принимал входящие запросы от контейнера Docker.

Добавьте в `~/.hermes/.env`:

```bash
API_SERVER_ENABLED=true
API_SERVER_KEY=your-secret-key-here
API_SERVER_HOST=0.0.0.0
```

— `API_SERVER_HOST=0.0.0.0` привязывается ко всем интерфейсам, чтобы контейнер Docker мог связаться с ним.
- `API_SERVER_KEY` требуется для привязки без обратной связи. Выберите сильную случайную строку.
- Сервер API по умолчанию работает на порту 8642 (при необходимости измените его на `API_SERVER_PORT`).

Запускаем шлюз:

```bash
hermes gateway
```

Вы должны увидеть, что сервер API запускается вместе с любыми другими настроенными вами платформами. Убедитесь, что он доступен с виртуальной машины:

```bash
# From the Linux VM
curl http://<mac-ip>:8642/health
```

### Шаг 2. Настройте Docker-контейнер (виртуальная машина Linux)

Контейнеру необходимы учетные данные Matrix и URL-адрес прокси-сервера. Ему НЕ нужны ключи API LLM.

**`docker-compose.yml`:**

```yaml
services:
  hermes-matrix:
    build: .
    environment:
      # Matrix credentials
      MATRIX_HOMESERVER: "https://matrix.example.org"
      MATRIX_ACCESS_TOKEN: "syt_..."
      MATRIX_ALLOWED_USERS: "@you:matrix.example.org"
      MATRIX_ENCRYPTION: "true"
      MATRIX_DEVICE_ID: "HERMES_BOT"

      # Proxy mode — forward to host agent
      GATEWAY_PROXY_URL: "http://192.168.1.100:8642"
      GATEWAY_PROXY_KEY: "your-secret-key-here"
    volumes:
      - ./matrix-store:/root/.hermes/platforms/matrix/store
```

**`Dockerfile`:**

```dockerfile
FROM python:3.11-slim

RUN apt-get update && apt-get install -y libolm-dev && rm -rf /var/lib/apt/lists/*
RUN cd ~/.hermes/hermes-agent && uv pip install -e ".[matrix]"

CMD ["hermes", "gateway"]
```

Это весь контейнер. Нет ключей API для OpenRouter, Anthropic или любого другого поставщика вывода.

### Шаг 3: Запустите оба

1. Сначала запустите хост-шлюз:
   ```bash
   hermes gateway
   ```

2. Запустите Docker-контейнер:
   ```bash
   docker compose up -d
   ```

3. Отправьте сообщение в зашифрованной комнате Матрицы. Контейнер расшифровывает его, пересылает хосту и отправляет ответ обратно.

### Справочник по конфигурации

Режим прокси настраивается на **стороне контейнера** (тонкий шлюз):

| Настройка | Описание |
|---------|-------------|
| `GATEWAY_PROXY_URL` | URL-адрес удаленного сервера API Hermes (например, `http://192.168.1.100:8642`) |
| `GATEWAY_PROXY_KEY` | Токен носителя для аутентификации (должен соответствовать `API_SERVER_KEY` на хосте) |
| `gateway.proxy_url` | То же, что `GATEWAY_PROXY_URL`, но в `config.yaml` |

Принимающей стороне необходимо:

| Настройка | Описание |
|---------|-------------|
| `API_SERVER_ENABLED` | Установить на `true` |
| `API_SERVER_KEY` | Токен на предъявителя (совместно с контейнером) |
| `API_SERVER_HOST` | Установите `0.0.0.0` для доступа к сети |
| `API_SERVER_PORT` | Номер порта (по умолчанию: `8642`) |

### Работает для любой платформы

Режим прокси не ограничивается Matrix. Его может использовать любой адаптер платформы — установите `GATEWAY_PROXY_URL` на любом экземпляре шлюза, и он будет перенаправляться удаленному агенту, а не запускать его локально. Это полезно для любого развертывания, когда адаптер платформы должен работать в среде, отличной от агента (сетевая изоляция, требования E2EE, ограничения ресурсов).

:::совет
Непрерывность сеанса поддерживается через заголовок `X-Hermes-Session-Id`. Сервер API хоста отслеживает сеансы по этому идентификатору, поэтому диалоги сохраняются между сообщениями так же, как и с локальным агентом.
:::

:::примечание
**Ограничения (версия 1):** Сообщения о ходе работы инструмента от удаленного агента не передаются обратно — пользователь видит только потоковый окончательный ответ, а не отдельные вызовы инструмента. Запросы на одобрение опасных команд обрабатываются на стороне хоста, а не передаются пользователю Matrix. Эти проблемы могут быть устранены в будущих обновлениях.
:::

### Бот подключается и отправляет, но игнорирует входящие сообщения

**Причина**: Обработчики событий Matrix срабатывают только тогда, когда полезные данные синхронизации передаются через
Машины `handle_sync()` Маутрикса. Необработанный опрос `client.sync()`, который никогда не вызывает
`handle_sync()` может оставить адаптер подключенным (отправка работает) во время входящего трафика
сообщения никогда не доходят до `_on_room_message`.

**Исправление**: Hermes использует явный цикл синхронизации, который вызывает `client.handle_sync()` в
как начальная синхронизация, так и каждый ответ дополнительной синхронизации. Это соответствует
диагноз в вышестоящем выпуске № 7914 и закрытом PR № 37807, но остается собственным Гермесом.
задачи фонового обслуживания (отслеживание присоединенных комнат, обработка приглашений, ключ E2EE
долю) вместо делегирования полного жизненного цикла `client.start()`. Если входящий
сообщения по-прежнему терпят неудачу после перезапуска шлюза, перед этим убедитесь, что обработчики зарегистрированы.
первая синхронизация и проверка журналов для `sync event dispatch error`.

### Проблемы с синхронизацией / бот отстает

**Причина**: длительное выполнение инструмента может задержать цикл синхронизации или домашний сервер работает медленно.

**Исправление**: В случае ошибки цикл синхронизации автоматически повторяется каждые 5 секунд. Проверьте журналы Hermes на наличие предупреждений, связанных с синхронизацией. Если бот постоянно отстает, убедитесь, что на вашем домашнем сервере достаточно ресурсов.

### Бот не в сети

**Причина**: шлюз Hermes не работает или не удалось подключиться.

**Исправление**. Убедитесь, что `hermes gateway` работает. Посмотрите на вывод терминала сообщения об ошибках. Распространенные проблемы: неправильный URL-адрес домашнего сервера, срок действия токена доступа истек, домашний сервер недоступен.

### «Пользователь не разрешен» / Бот вас игнорирует

**Причина**: вашего идентификатора пользователя нет в `MATRIX_ALLOWED_USERS`.

**Исправление**. Добавьте свой идентификатор пользователя в `MATRIX_ALLOWED_USERS` в `~/.hermes/.env` и перезапустите шлюз. Используйте полный формат `@user:server`.

### Бот игнорирует всю комнату

**Причина**: установлен `MATRIX_ALLOWED_ROOMS`, а текущий идентификатор комнаты не указан, или комната требует упоминания, а в сообщении не упоминается бот.

**Исправление**. Добавьте идентификатор комнаты в `MATRIX_ALLOWED_ROOMS` или удалите список разрешенных комнат, если это личное развертывание. Чтобы найти идентификатор комнаты в Element, откройте настройки комнаты и установите флажок **Дополнительно**.

### Сообщения моста зацикливаются или повторяются

**Причина**: Марионетка моста/службы приложений ретранслирует выходные данные бота обратно в виде нового сообщения пользователя, или мост использует нестандартные идентификаторы призрачных пользователей.

**Исправление**. Уберите призраки моста из `MATRIX_ALLOWED_USERS`, добавьте соответствующую запись `MATRIX_IGNORE_USER_PATTERNS` и оставьте `MATRIX_PROCESS_NOTICES=false`, если только уведомления не являются частью доверенного рабочего процесса.

## Безопасность

:::предупреждение
Всегда устанавливайте `MATRIX_ALLOWED_USERS`, а для общих/частных развертываний — `MATRIX_ALLOWED_ROOMS`. Без них любой, кто может отправить сообщение боту в объединенной комнате, может активировать агента. Авторизуйте только людей и комнаты, которым вы доверяете — авторизованные пользователи имеют полный доступ к возможностям агента, включая использование инструментов и доступ к системе.
:::

Дополнительную информацию о защите вашего агента Hermes см. в [Руководстве по безопасности](../security.md).

## Примечания

- **Любой домашний сервер**: работает с Synapse, Conduit, Dendrite, Matrix.org или любым домашним сервером Matrix, соответствующим спецификации. Никакого специального программного обеспечения для домашнего сервера не требуется.
- **Федерация**: если вы находитесь на федеративном домашнем сервере, бот может общаться с пользователями с других серверов — просто добавьте их полные идентификаторы `@user:server` в `MATRIX_ALLOWED_USERS`.
- **Автоматическое присоединение**: бот автоматически принимает приглашения в комнаты и присоединяется. Он начинает отвечать сразу после присоединения.
- **Поддержка мультимедиа**: Hermes может отправлять и получать изображения, аудио, видео и вложенные файлы. Медиафайлы загружаются на ваш домашний сервер с помощью API репозитория контента Matrix.
- **Встроенные голосовые сообщения (MSC3245)**: адаптер Matrix автоматически помечает исходящие голосовые сообщения флагом `org.matrix.msc3245.voice`. Это означает, что ответы TTS и голосовой звук отображаются как **собственные голосовые пузырьки** в Element и других клиентах, поддерживающих MSC3245, а не как обычные вложения аудиофайлов. Входящие голосовые сообщения с флагом MSC3245 также правильно идентифицируются и направляются на преобразование речи в текст. Никакой настройки не требуется — это работает автоматически.
