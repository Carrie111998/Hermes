# Настройка сигнала

Hermes подключается к Signal через демон [signal-cli](https://github.com/AsamK/signal-cli), работающий в режиме HTTP. Адаптер передает потоковые сообщения в режиме реального времени через SSE (события, отправленные сервером) и отправляет ответы через JSON-RPC.

Signal — это массовый мессенджер, наиболее ориентированный на конфиденциальность: по умолчанию используется сквозное шифрование, протокол с открытым исходным кодом, минимальный сбор метаданных. Это делает его идеальным для рабочих процессов агентов, чувствительных к безопасности.

:::info Нет новых зависимостей Python
Адаптер Signal использует `httpx` (уже является основной зависимостью Hermes) для всех коммуникаций. Никаких дополнительных пакетов Python не требуется. Вам просто нужно установить signal-cli извне.
:::

---

## Предварительные условия

- **signal-cli** — клиент Signal на основе Java ([GitHub](https://github.com/AsamK/signal-cli))
- **Среда выполнения Java 17+** — требуется для signal-cli
- **Номер телефона** с установленным Signal (для подключения в качестве дополнительного устройства)

### Установка signal-cli

```bash
# macOS
brew install signal-cli

# Linux (download latest release)
VERSION=$(curl -Ls -o /dev/null -w %{url_effective} \
  https://github.com/AsamK/signal-cli/releases/latest | sed 's/^.*\/v//')
curl -L -O "https://github.com/AsamK/signal-cli/releases/download/v${VERSION}/signal-cli-${VERSION}.tar.gz"
sudo tar xf "signal-cli-${VERSION}.tar.gz" -C /opt
sudo ln -sf "/opt/signal-cli-${VERSION}/bin/signal-cli" /usr/local/bin/
```

:::осторожно
signal-cli **нет** в репозиториях apt или snap. Указанная выше установка Linux загружается непосредственно из [выпусков GitHub] (https://github.com/AsamK/signal-cli/releases).
:::

## Шаг 1: Привяжите свою учетную запись Signal

Signal-cli работает как **связанное устройство** — как WhatsApp Web, но для Signal. Ваш телефон остается основным устройством.

```bash
# Generate a linking URI (displays a QR code or link)
signal-cli link -n "HermesAgent"
```

1. Откройте **Signal** на своем телефоне.
2. Откройте **Настройки → Связанные устройства**.
3. Нажмите **Привязать новое устройство**.
4. Отсканируйте QR-код или введите URI.

---

## Шаг 2. Запустите демон signal-cli

```bash
# Replace +1234567890 with your Signal phone number (E.164 format)
signal-cli --account +1234567890 daemon --http 127.0.0.1:8080
```

:::совет
Держите это в фоновом режиме. Вы можете использовать `systemd`, `tmux`, `screen` или запустить его как службу.
:::

Убедитесь, что он работает:

```bash
curl http://127.0.0.1:8080/api/v1/check
# Should return: {"versions":{"signal-cli":...}}
```

## Шаг 3: Настройте Гермес

Самый простой способ:

```bash
hermes gateway setup
```

Выберите **Сигнал** в меню платформы. Мастер:

1. Проверьте, установлен ли signal-cli.
2. Запросить URL-адрес HTTP (по умолчанию: `http://127.0.0.1:8080`).
3. Проверьте подключение к демону.
4. Попросите номер телефона вашего аккаунта.
5. Настройте разрешенных пользователей и политики доступа.

### Ручная настройка

Добавьте в `~/.hermes/.env`:

```bash
# Required
SIGNAL_HTTP_URL=http://127.0.0.1:8080
SIGNAL_ACCOUNT=+1234567890

# Security (recommended)
SIGNAL_ALLOWED_USERS=+1234567890,+0987654321    # Comma-separated E.164 numbers or UUIDs

# Optional
SIGNAL_GROUP_ALLOWED_USERS=groupId1,groupId2     # Enable groups (omit to disable, * for all)
SIGNAL_HOME_CHANNEL=+1234567890                  # Default delivery target for cron jobs
```

Затем запустите шлюз:

```bash
hermes gateway              # Foreground
hermes gateway install      # Install as a user service
sudo hermes gateway install --system   # Linux only: boot-time system service
```

## Контроль доступа

### Доступ в личные сообщения

Доступ к DM осуществляется по той же схеме, что и на всех других платформах Hermes:

1. **`SIGNAL_ALLOWED_USERS` set** → только эти пользователи могут отправлять сообщения
2. **Белый список не установлен** → неизвестные пользователи получают код сопряжения DM (одобрение через `hermes pairing approve signal CODE`)
3. **`SIGNAL_ALLOW_ALL_USERS=true`** → каждый может отправлять сообщения (используйте с осторожностью)

### Групповой доступ

Групповой доступ контролируется переменной окружения `SIGNAL_GROUP_ALLOWED_USERS`:

| Конфигурация | Поведение |
|---------------|----------|
| Не установлено (по умолчанию) | Все групповые сообщения игнорируются. Бот отвечает только на DM. |
| Установить с идентификаторами групп | Отслеживаются только перечисленные группы (например, `groupId1,groupId2`). |
| Установить на `*` | Бот отвечает в любой группе, в которой он состоит. |

## Особенности

### Вложения

Адаптер поддерживает отправку и получение мультимедиа в обоих направлениях.

**Входящие** (пользователь → агент):

- **Изображения** — PNG, JPEG, GIF, WebP (автоматически определяется с помощью магических байтов).
- **Аудио** — MP3, OGG, WAV, M4A (голосовые сообщения расшифровываются, если настроен Whisper)
- **Документы** — файлы PDF, ZIP и другие типы.

**Исходящие** (агент → пользователь):

Агент может отправлять медиафайлы с помощью тегов `MEDIA:` в ответах. Поддерживаются следующие способы доставки:

- **Изображения** — `send_multiple_images` и `send_image_file` отправляют PNG, JPEG, GIF, WebP как собственные вложения Signal.
- **Голосовой** — `send_voice` отправляет аудиофайлы (OGG, MP3, WAV, M4A, AAC) в виде вложений.
- **Видео** — `send_video` отправляет видеофайлы MP4.
- **Документы** — `send_document` отправляет файлы любого типа (PDF, ZIP и т. д.).

Все исходящие медиафайлы проходят через стандартный API вложений Signal. В отличие от некоторых платформ, Signal не различает голосовые сообщения и вложения файлов на уровне протокола.

Ограничение размера вложения: **100 МБ** (в обе стороны).
:::предупреждение
**Серверы Signal ограничивают скорость загрузки вложений**. Адаптер использует планировщик для отправки нескольких изображений, который группирует изображения в группы по 32 и регулирует загрузку в соответствии с политикой сервера Signal.
:::

### Собственное форматирование, кавычки в ответах и реакции

Сообщения Signal отображаются с использованием **собственного форматирования** вместо буквальных символов уценки. Адаптер преобразует символы уценки (`**bold**`, `*italic*`, `` `code` ``, `~~strike~~`, `||spoiler||`, headings) into Signal `bodyRanges` so the text shows up with real styling on the recipient's client rather than as visible `**` / `` ` `` символов.

**Кавычки для ответа.** Когда Hermes отвечает на определенное сообщение, он теперь публикует собственный ответ, в котором цитируется оригинал — то же самое, что пользователи Signal видят в пользовательском интерфейсе, когда сами используют «Ответить». Это происходит автоматически для ответов, созданных в ответ на входящее сообщение.

**Реакции.** Агент может реагировать на сообщения через стандартный API реакций; реакции отображаются в Signal как смайлики-реакции на указанное сообщение, а не как дополнительный текст.

Ничто из этого не требует дополнительной настройки — в последних сборках signal-cli оно включено по умолчанию. Если ваша версия `signal-cli` слишком старая, Hermes возвращается к доставке в виде открытого текста и регистрирует одноразовое предупреждение.

### Длинные сообщения

Signal ограничивает одно сообщение длиной **8000 символов**. Hermes автоматически разбивает более длинные ответы на пронумерованные фрагменты (`(1/3)`, `(2/3)`, …) вместо их усечения. Это применимо к каждому пути доставки — ответам в реальном времени, доставке заданий cron, вызовам `hermes send` и MCP `send_message` — а собственное форматирование (жирный, курсив, код, спойлеры) сохраняется через границы фрагментов.

### Индикаторы набора текста

Бот отправляет индикаторы набора текста во время обработки сообщений, обновляясь каждые 8 секунд.

### Отображение хода работы инструмента

Signal не поддерживает редактирование уже отправленных сообщений. Поэтому Hermes подавляет пузыри прогресса инструмента шлюза в Signal, даже если `/verbose` включен, и сохраняет для платформы режим, отличный от `off`.

Вы по-прежнему можете видеть активность инструмента в интерфейсе командной строки, а окончательные ответы Signal могут включать обычные выходные данные помощника. Если вам нужен живой прогресс каждого инструмента в чате, используйте платформу обмена сообщениями с поддержкой редактирования сообщений.

### Редактирование номера телефона

Все номера телефонов автоматически редактируются в журналах:
- `+15551234567` → `+155****4567`
- Это относится как к журналам шлюза Hermes, так и к глобальной системе редактирования.

### Примечание для себя (настройка одного номера)

Если вы запустите signal-cli как **связанное вторичное устройство** на своем собственном номере телефона (а не на отдельном номере бота), вы сможете взаимодействовать с Hermes через функцию Signal «Заметка для себя».

Просто отправьте себе сообщение со своего телефона — signal-cli подхватит его, и Hermes ответит в том же разговоре.

**Как это работает:**
- Сообщения «Заметка для себя» приходят в конвертах `syncMessage.sentMessage`.
- Адаптер определяет, когда они адресованы собственной учетной записи бота, и обрабатывает их как обычные входящие сообщения.
- Защита от обратного эха (отслеживание временных меток отправки) предотвращает бесконечные циклы — собственные ответы бота автоматически отфильтровываются.

**Дополнительная настройка не требуется.** Это работает автоматически, если `SIGNAL_ACCOUNT` соответствует вашему номеру телефона.

### Мониторинг здоровья

Адаптер контролирует соединение SSE и автоматически переподключается, если:
- Соединение обрывается (с экспоненциальной задержкой: 2 с → 60 с)
- Никакой активности не обнаружено в течение 120 секунд (проверяет сигнал signal-cli)

## Устранение неполадок

| Проблема | Решение |
|---------|----------|
| **"Невозможно связаться с signal-cli"** во время установки | Убедитесь, что демон signal-cli запущен: `signal-cli --account +YOUR_NUMBER daemon --http 127.0.0.1:8080` |
| **Сообщения не получены** | Убедитесь, что `SIGNAL_ALLOWED_USERS` содержит номер отправителя в формате E.164 (с префиксом `+`) |
| **"signal-cli не найден в PATH"** | Установите signal-cli и убедитесь, что он находится в вашем PATH, или используйте Docker |
| **Соединение продолжает падать** | Проверьте журналы signal-cli на наличие ошибок. Убедитесь, что установлена ​​Java 17+. |
| **Сообщения группы игнорируются** | Настройте `SIGNAL_GROUP_ALLOWED_USERS` с определенными идентификаторами групп или `*`, чтобы разрешить все группы. |
| **Бот никому не отвечает** | Настройте `SIGNAL_ALLOWED_USERS`, используйте сопряжение DM или явно разрешите всем пользователям с помощью политики шлюза, если вам нужен более широкий доступ. |
| **Повторяющиеся сообщения** | Убедитесь, что ваш номер телефона прослушивает только один экземпляр signal-cli |

## Безопасность

:::предупреждение
**Всегда настраивайте контроль доступа.** По умолчанию бот имеет доступ к терминалу. Без сопряжения `SIGNAL_ALLOWED_USERS` или DM шлюз отклоняет все входящие сообщения в целях безопасности.
:::

- Номера телефонов редактируются во всех выводах журнала.
- Используйте соединение DM или явные списки разрешений для безопасной регистрации новых пользователей.
– Оставляйте группы отключенными, если вам не нужна поддержка групп, или добавляйте в белый список только те группы, которым вы доверяете.
- Сквозное шифрование Signal защищает содержимое сообщения при передаче.
- Данные сеанса signal-cli в `~/.local/share/signal-cli/` содержат учетные данные учетной записи — защищайте их как пароль.

## Справочник по переменным среды

| Переменная | Требуется | По умолчанию | Описание |
|----------|----------|---------|-------------|
| `SIGNAL_HTTP_URL` | Да | — | конечная точка HTTP сигнала-cli |
| `SIGNAL_ACCOUNT` | Да | — | Номер телефона бота (E.164) |
| `SIGNAL_ALLOWED_USERS` | Нет | — | Телефонные номера/UUID, разделенные запятыми |
| `SIGNAL_GROUP_ALLOWED_USERS` | Нет | — | Идентификаторы групп для мониторинга или `*` для всех (пропустите, чтобы отключить группы) |
| `SIGNAL_ALLOW_ALL_USERS` | Нет | `false` | Разрешить любому пользователю взаимодействовать (пропустить белый список) |
| `SIGNAL_HOME_CHANNEL` | Нет | — | Цель доставки по умолчанию для заданий cron |
