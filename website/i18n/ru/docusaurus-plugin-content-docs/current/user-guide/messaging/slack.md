# Слабая настройка

Подключите агента Hermes к Slack в качестве бота, используя режим сокета. Режим сокетов использует WebSockets вместо
общедоступные конечные точки HTTP, поэтому ваш экземпляр Hermes не обязательно должен быть общедоступным — это работает
за брандмауэрами, на вашем ноутбуке или на частном сервере.

:::предупреждение Классические приложения Slack устарели
Классические приложения Slack (с использованием RTM API) **полностью устарели в марте 2025 года**. Гермес использует современную
Bolt SDK с режимом сокета. Если у вас есть старое классическое приложение, вам необходимо создать новое, выполнив следующие действия.
шаги ниже.
:::

## Обзор

| Компонент | Значение |
|-----------|-------|
| **Библиотека** | `slack-bolt`/`slack_sdk` для Python (режим сокета) |
| **Соединение** | WebSocket — общедоступный URL-адрес не требуется |
| **Требуются токены аутентификации** | Токен бота (`xoxb-`) + токен уровня приложения (`xapp-`) |
| **Идентификация пользователя** | Идентификаторы участников Slack (например, `U01ABC2DEF3`) |

## Шаг 1. Создайте приложение Slack

Самый быстрый путь — вставить манифест, который сгенерирует для вас Hermes. Это
объявляет каждую встроенную косую черту (`/btw`, `/stop`, `/model`, …),
все необходимые области OAuth, каждую подписку на события и включение Socket
Режим — все сразу.

### Вариант A: из манифеста, созданного Hermes (рекомендуется)

1. Создайте манифест. Новые приложения Slack должны использовать представление агента:
   ```bash
   hermes slack manifest --agent-view --write
   ```
   Это записывает `~/.hermes/slack-manifest.json` и печатает вставку.
   инструкции. Существующие приложения, которые до сих пор используют устаревшее представление Assistant Slack
   можно опустить `--agent-view`, пока они не будут готовы к миграции.

   Чтобы заполнить длинное описание приложения Slack из существующего текста UTF-8 или
   В файл Markdown добавьте `--long-description-file`:

   ```bash
   hermes slack manifest --agent-view \
     --long-description-file AGENTS.md --write
   ```

   Содержимое файла сохраняется точно в пределах 175–4000 символов Slack.
   диапазон. Вместо этого используйте `--long-description "..."` для встроенного текста; встроенный
   и параметры файла являются взаимоисключающими и не могут быть объединены с
   `--slashes-only`.
2. Перейдите по адресу [https://api.slack.com/apps](https://api.slack.com/apps) →
   **Создать новое приложение** → **Из манифеста приложения**
3. Выберите рабочее пространство, вставьте содержимое JSON, проверьте его и нажмите **Далее**.
   → **Создать**
4. Перейдите к **Шаг 6. Установка приложения в рабочую область**. Манифест
   обрабатывал области видимости, события и команды косой черты для вас.

### Вариант Б: С нуля (вручную)

1. Перейдите на [https://api.slack.com/apps](https://api.slack.com/apps)
2. Нажмите **Создать новое приложение**.
3. Выберите **С нуля**.
4. Введите название приложения (например, «Агент Гермес») и выберите рабочее пространство.
5. Нажмите **Создать приложение**.

Вы попадете на страницу **Основная информация** приложения. Продолжить с
Шаги 2–6 ниже.

## Шаг 2. Настройка областей действия токенов бота

Перейдите в раздел **Функции → OAuth и разрешения** на боковой панели. Прокрутите до **Области действия → Области действия токенов ботов** и добавьте следующее:

| Область применения | Цель |
|-------|---------|
| `chat:write` | Отправляйте сообщения как бот |
| `app_mentions:read` | Обнаруживать, когда @упоминание в каналах |
| `channels:history` | Читать сообщения в публичных каналах, в которых находится бот |
| `channels:read` | Список и получение информации об общедоступных каналах |
| `groups:history` | Читать сообщения в приватных каналах, куда приглашен бот |
| `im:history` | Прочитать историю прямых сообщений |
| `im:read` | Просмотр основной информации DM |
| `im:write` | Открывайте личные сообщения и управляйте ими |
| `mpim:history` | Прочитать историю групповых прямых сообщений (DM для нескольких человек) |
| `mpim:read` | Просмотр основной информации DM группы |
| `users:read` | Поиск информации о пользователе |
| `files:read` | Чтение и загрузка прикрепленных файлов, включая голосовые заметки/аудио |
| `files:write` | Загрузить файлы (изображения, аудио, документы) |

:::осторожно. Отсутствующие области = отсутствующие функции.
Без `channels:history` и `groups:history` бот **не будет получать сообщения в каналах** —
это будет работать только в личных сообщениях. Без `files:read` Hermes может общаться в чате, но **не может надежно читать вложения, загруженные пользователем**.
Это наиболее часто пропускаемые области.
:::

**Дополнительные области действия:**

| Область применения | Цель |
|-------|---------|
| `groups:read` | Список и получение информации о частных каналах |
| `assistant:write` | Отобразите строку статуса рабочего состояния («думает…») рядом с именем бота, пока он обрабатывает сообщение. Без этой области вызов `assistant.threads.setStatus` завершается автоматически, и вместо этого Slack показывает свои собственные вращающиеся общие заполнители («Поиск ответов…», «Просмотр результатов…», …) — Hermes никогда не контролирует текст. Требуется, чтобы `typing_status_text` имел какой-либо видимый эффект. |

## Шаг 3. Включите режим сокета

Режим сокета позволяет боту подключаться через WebSocket вместо использования общедоступного URL-адреса.

1. На боковой панели выберите **Настройки → Режим сокета**.
2. Установите для параметра **Включить режим сокета** значение ВКЛ.
3. Вам будет предложено создать **токен уровня приложения**:
   - Назовите его примерно так: `hermes-socket` (имя не имеет значения)
   - Добавьте область действия **`connections:write`**.
   – Нажмите **Создать**.
4. **Скопируйте токен** — он начинается с `xapp-`. Это ваш `SLACK_APP_TOKEN`

:::совет
Вы всегда можете найти или восстановить токены уровня приложения в разделе **Настройки → Основная информация → Токены уровня приложения**.
:::

## Шаг 4: Подпишитесь на события

Этот шаг имеет решающее значение — он определяет, какие сообщения может видеть бот.


1. На боковой панели выберите **Функции → Подписки на события**.
2. Установите для параметра **Включить события** значение ВКЛ.
3. Разверните **Подписаться на события ботов** и добавьте:

| Событие | Необходимый? | Цель |
|-------|-----------|---------|
| `message.im` | **Да** | Бот получает прямые сообщения |
| `message.mpim` | **Да** | Бот получает сообщения в **групповые DM** (многопользовательские DM), в которые он добавлен |
| `message.channels` | **Да** | Бот получает сообщения в **публичных** каналах, в которые он добавлен |
| `message.groups` | **Рекомендуется** | Бот получает сообщения в **частных** каналах, на которые его пригласили |
| `app_mention` | **Да** | Предотвращает ошибки Bolt SDK, когда бот @упоминается |

4. Нажмите **Сохранить изменения** внизу страницы.

:::опасность Отсутствие подписок на события — проблема настройки №1.
Если бот работает в личных сообщениях, но **не в каналах**, вы почти наверняка забыли добавить
`message.channels` (для общедоступных каналов) и/или `message.groups` (для частных каналов).
Без этих событий Slack просто никогда не доставляет боту сообщения канала.
:::

## Шаг 5. Включите вкладку «Сообщения»

Этот шаг позволяет отправлять прямые сообщения боту. Без него пользователи увидят **"Отправка сообщений в это приложение отключена"** при попытке отправить боту личное сообщение.

1. На боковой панели выберите **Функции → Главная страница приложения**.
2. Прокрутите до пункта **Показать вкладки**.
3. Установите для параметра **Вкладка «Сообщения» значение «ВКЛ.».
4. Установите флажок **Разрешить пользователям отправлять слэш-команды и сообщения с вкладки сообщений**.

:::danger Без этого шага DM полностью блокируются.
Даже при наличии всех правильных областей и подписок на события Slack не позволит пользователям отправлять прямые сообщения боту, если не включена вкладка «Сообщения». Это требование платформы Slack, а не проблема конфигурации Hermes.
:::

## Шаг 6. Установите приложение в рабочую область

1. На боковой панели выберите **Настройки → Установить приложение**.
2. Нажмите **Установить в рабочую область**.
3. Проверьте разрешения и нажмите **Разрешить**.
4. После авторизации вы увидите **Токен OAuth пользователя бота**, начинающийся с `xoxb-`.
5. **Скопируйте этот токен** — это ваш `SLACK_BOT_TOKEN`.

:::совет
Если вы позже измените области действия или подписки на события, вам **необходимо переустановить приложение** для внесения изменений.
чтобы вступило в силу. На странице установки приложения появится баннер с предложением сделать это.
:::

## Шаг 7. Найдите идентификаторы пользователей для белого списка

Hermes использует **идентификаторы участников** Slack (а не имена пользователей или отображаемые имена) для белого списка.

Чтобы найти идентификатор участника:

1. В Slack щелкните имя пользователя или аватар.
2. Нажмите **Просмотреть полный профиль**.
3. Нажмите кнопку **⋮** (подробнее).
4. Выберите **Копировать идентификатор участника**.

Идентификаторы участников выглядят как `U01ABC2DEF3`. Вам нужен как минимум собственный идентификатор участника.

## Шаг 8: Настройте Гермес

Добавьте в файл `~/.hermes/.env` следующее:

```bash
# Required
SLACK_BOT_TOKEN=xoxb-your-bot-token-here
SLACK_APP_TOKEN=xapp-your-app-token-here
SLACK_ALLOWED_USERS=U01ABC2DEF3              # Comma-separated Member IDs

# Optional
SLACK_HOME_CHANNEL=C01234567890              # Default channel for cron/scheduled messages
SLACK_HOME_CHANNEL_NAME=general              # Human-readable name for the home channel (optional)
```

Или запустите интерактивную настройку:

```bash
hermes gateway setup    # Select Slack when prompted
```

Затем запустите шлюз:

```bash
hermes gateway              # Foreground
hermes gateway install      # Install as a user service
sudo hermes gateway install --system   # Linux only: boot-time system service
```

:::совет Кодекса: безопасность рассуждений и усилий
Для каналов одноранговых агентов Slack, поддерживаемых Кодексом, выберите `agent.reasoning_effort: high` или ниже. `xhigh`
может провести весь ход в скрытых рассуждениях и никогда не создавать видимого вспомогательного текста; Гермес сейчас
подавляет предупреждения о незавершенном повороте из потока и сохраняет диагностику в журналах шлюза.
:::

---

## Шаг 9: Пригласите бота на каналы

После запуска шлюза вам необходимо **пригласить бота** в любой канал, на который вы хотите, чтобы он отвечал:

```
/invite @Hermes Agent
```

Бот **не** автоматически подключается к каналам. Вы должны пригласить его на каждый канал индивидуально.

## Слэш-команды

Каждая команда Гермеса (`/btw`, `/stop`, `/new`, `/model`, `/help`, ...)
— это встроенная слэш-команда Slack, точно так же, как она работает в Telegram.
и Дискорд. Введите `/` в Slack, и средство выбора автозаполнения отобразит все
Команда Гермеса с ее описанием.

Под капотом: Hermes поставляется с сгенерированным манифестом приложения Slack (см.
Шаг 1, вариант A), который объявляет каждую команду в
[`COMMAND_REGISTRY`](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/commands.py)
как слэш-команда. В режиме сокета Slack маршрутизирует командное событие
через WebSocket независимо от поля `url` манифеста.

### Опыт обмена сообщениями агента

Новые приложения Slack используют систему обмена сообщениями **Агент** Slack. Существующий Гермес
Приложения-помощники можно перенести, повторно создав манифест с помощью `--agent-view`:

```bash
hermes slack manifest --agent-view --write
```

Обновите манифест в разделе **Функции → Манифест приложения**, затем переустановите приложение, если
— спрашивает Слэк. Представление агента нельзя вернуть в представление Ассистента, и пользователям может потребоваться
для принудительного обновления Slack после переключения. Сгенерированный манифест агента подписывается
на `message.im`, `app_home_opened` и `app_context_changed`, чтобы Гермес мог
определить DM на вкладке «Сообщения» и получить активный контекст Slack пользователя с помощью
поворот. Hermes предоставляет этот контекст только в качестве ярлыка; он не читает просмотренное
история канала.

### Обновление команд слэша после обновлений

Когда Hermes добавляет новые команды (например, после `hermes update`), перегенерируйте
манифест и обновите приложение Slack:

```bash
hermes slack manifest --write
```

Затем в Slack:
1. Откройте [https://api.slack.com/apps](https://api.slack.com/apps) →
   ваше приложение Гермес
2. **Функции → Манифест приложения → Редактировать**
3. Вставьте новое содержимое `~/.hermes/slack-manifest.json`.
4. **Сохранить**. Slack предложит переустановить приложение, если область действия или косая черта
   команды изменились.

### Legacy `/hermes <subcommand>` все еще работает

Для обратной совместимости со старыми манифестами вы все равно можете ввести
`/hermes btw run the tests` — Гермес маршрутизирует его так же, как `/кстати
запусти тесты`. Free-form questions also work: `/hermes, что там
погода?» рассматривается как обычное сообщение.

### Использование команд внутри потоков (префикс `!cmd`)

Slack сам блокирует встроенные слэш-команды внутри ответов ветки — попробуйте
`/queue` в потоке, и Slack отвечает *"/queue не поддерживается
в темах. Извините!"* На стороне приложения нет настроек, которые могли бы повторно включить их;
Slack никогда не доставляет их в Hermes.

В качестве обходного пути Hermes распознает ведущий `!` в качестве альтернативного.
префикс команды, который работает в потоках (и где угодно еще). Тип
`!queue`, `!stop`, `!model gpt-5.4` и т. д. в качестве обычного ответа в теме —
Гермес обращается с ним так же, как и с косой чертой, и отвечает тем же.
нить.

Только первый токен проверяется на соответствие известному списку команд, поэтому
случайные сообщения, такие как `!nice work`, передаются агенту без изменений.
Форма взрыва также работает за упоминанием (`@Hermes !stop`) и с
ведущие пробелы — оба отправляются как команды в потоках.

Запросы на одобрение (опасная команда / одобрение `execute_code`) обычно
визуализируются в виде интерактивных кнопок. Когда кнопки не могут быть доставлены и
Гермес возвращается к текстовой подсказке, в которой вам предлагается ответить.
с `!approve`/`!deny` — формой, работающей внутри потоков.

### Ответы на слэш эфемерны.

Ответы на собственную команду с косой чертой (например, `/status`, `/help`) доставляются.
**эфемерно** — «Виден только вам» — поэтому выходные данные команды никогда не рассылают спам
канал. Заполнитель «Выполняется /cmd…» заменяется реальным ответом; длинный
ответы разбиваются на последующие эфемерные сообщения. Slack ограничивает ответ
поток на 5 сообщений, поэтому очень длинный вывод закрывается явным
уведомление об усечении, а не молча удаляется. Если основной эфемерный путь
терпит неудачу, Hermes повторяет попытку через второй эфемерный путь API — ответ с косой чертой никогда не
опубликовано публично на канале в качестве запасного варианта. (Команды вводятся как обычные
сообщения — `!cmd` в темах, `@Hermes /cmd` — ответ виден как обычно
вместо этого сообщения.)

### Уточняющие подсказки (кнопки быстрого запуска)

Когда агенту необходимо задать вам вопрос с несколькими вариантами ответов (`clarify`
инструмент), Slack отображает его как **Кнопки Block Kit** — одно нажатие на каждый параметр плюс
Кнопка «✏️ Другое…», которая переключает в режим произвольного текста (ваше следующее набранное сообщение
становится ответом). После касания сообщение обновляется, показывая, кто
ответил и что выбрали; дальнейшие щелчки по тому же запросу игнорируются.
Нажатия кнопок учитывают ту же авторизацию пользователя, что и сообщения, и срок их действия истек.
подсказки (перезапуск шлюза, тайм-аут) советуют вам повторить запрос, а не молчать
едят щелчок. Открытые уточняющие вопросы представляют собой простой вопрос и
принять ваш следующий напечатанный ответ. Никакой настройки не требуется — это работает независимо
настройки `rich_blocks`.

### Дополнительно: выдавать только массив слэш-команд

Если вы поддерживаете манифест Slack вручную и просто хотите использовать косую черту
список команд:

```bash
hermes slack manifest --slashes-only > /tmp/slashes.json
```

Вставьте этот массив в ключ `features.slash_commands` вашего
существующий манифест.

## Как реагирует бот

Понимание того, как Гермес ведет себя в разных контекстах:

| Контекст | Поведение |
|---------|----------|
| **DM** | Бот отвечает на каждое сообщение — @упоминание не требуется |
| **Каналы** | Бот **отвечает только при @упоминании** (например, `@Hermes Agent what time is it?`). В каналах Гермес отвечает в ветке, прикрепленной к этому сообщению. |
| **Темы** | Если вы @упомяните Гермеса в существующей теме, он ответит в той же теме. Как только у бота появится активный сеанс в теме, **последующие ответы в этой теме не требуют @mention** — бот естественным образом следит за беседой. |

:::совет
В каналах всегда @упоминайте бота, чтобы начать разговор. Как только бот станет активным в теме, вы сможете ответить в этой теме, не упоминая его. Вне потоков сообщения без @mention игнорируются, чтобы предотвратить шум в занятых каналах.
:::

## Параметры конфигурации

Помимо обязательных переменных среды из шага 8, вы можете настроить поведение бота Slack с помощью `~/.hermes/config.yaml`.

### Поведение темы и ответа

```yaml
platforms:
  slack:
    # Controls how multi-part responses are threaded
    # "off"   — never thread replies to the original message
    # "first" — first chunk threads to user's message (default)
    # "all"   — all chunks thread to user's message
    reply_to_mode: "first"

    extra:
      # Whether to reply in a thread (default: true).
      # When false, channel messages get direct channel replies instead
      # of threads. Messages inside existing threads still reply in-thread.
      reply_in_thread: true

      # Also post thread replies to the main channel
      # (Slack's "Also send to channel" feature).
      # Only the first chunk of the first reply is broadcast.
      reply_broadcast: false

      # Render agent messages as Slack Block Kit blocks (default: false).
      # When true, the final agent message is sent with structured blocks —
      # section headers, dividers, true nested lists (via rich_text), and
      # native Block Kit tables — instead of flat mrkdwn text. A plain-text
      # fallback is always sent alongside for notifications/accessibility.
      # Tables exceeding Slack's limits (100 rows / 20 cols / 10k chars)
      # gracefully fall back to aligned monospace.
      rich_blocks: false

      # Append Slack-native feedback controls to final Block Kit replies.
      # Requires rich_blocks: true. Default: false.
      feedback_buttons: false

      # Render live tool calls as Slack-native plan/task cards. This explicit
      # opt-in activates native progress even when text tool_progress is off.
      # If Slack rejects the native stream, Hermes keeps one editable text
      # fallback current for the rest of the turn.
      native_task_cards: false

      # Suggested prompts pinned at the top of Agent view's Messages tab.
      # Either a list of {title, message} rows, or a titled object:
      # {title: "Start here", prompts: [{title: "Plan", message: "..."}]}
      suggested_prompts: []

      # Title Agent/Assistant DM threads from the first user message.
      # Default: true. Set false to leave Slack's default thread titles.
      assistant_thread_titles: true

      # Accept messages posted by other Slack bots (default: "none").
      # "none" ignores bots, "mentions" accepts a bot message only when
      # that message itself @mentions Hermes, and "all" accepts every
      # other bot. Hermes always ignores its own bot user to prevent
      # self-echoes.
      allow_bots: "none"

      # Continuable-cron delivery surface (default: "thread").
      # "in_channel" delivers a continuable cron job FLAT into the channel
      # (no dedicated thread); pair with reply_in_thread: false (and
      # require_mention: false) so a plain reply continues the job.
      # See the cron guide → "Flat, in-channel continuation".
      cron_continuable_surface: thread
```

| Ключ | По умолчанию | Описание |
|-----|---------|-------------|
| `platforms.slack.reply_to_mode` | `"first"` | Режим потоков для сообщений, состоящих из нескольких частей: `"off"`, `"first"` или `"all"` |
| `platforms.slack.extra.reply_in_thread` | `true` | При `false` сообщения канала получают прямые ответы вместо цепочек. На сообщения внутри существующих тем по-прежнему отвечают внутри ветки. |
| `platforms.slack.extra.reply_broadcast` | `false` | Когда `true`, ответы ветки также публикуются в основном канале. Транслируется только первый фрагмент. |
| `platforms.slack.extra.rich_blocks` | `false` | При `true` сообщения агента отображаются как блоки [Block Kit](https://docs.slack.dev/block-kit/) (заголовки, разделители, настоящие вложенные списки и собственные таблицы). Всегда отправляется резервный вариант в виде простого текста. Таблицы, превышающие ограничения Slack, возвращаются к выровненному моноширинному пространству. Переустановка приложения не требуется — это изменение только на стороне отправки. |
| `platforms.slack.extra.feedback_buttons` | `false` | Когда `true` с `rich_blocks`, к окончательным ответам добавляются встроенные элементы управления обратной связью Slack. |
| `platforms.slack.extra.native_task_cards` | `false` | Когда `true`, вызовы инструментов в реальном времени отображаются как карты планов/задач Slack. Это явное согласие на прогресс, независимое от стандартного `tool_progress: off` Slack; Сбои встроенного API приводят к одному постоянно редактируемому текстовому обновлению. |
| `platforms.slack.extra.suggested_prompts` | `[]` | До четырех запросов `{title, message}` для точек входа DM агента/помощника; принимает либо список, либо `{title, prompts}`. |
| `platforms.slack.extra.assistant_thread_titles` | `true` | Если `true`, присваивает имена потокам DM агента/помощника из первого сообщения пользователя. |
| `platforms.slack.extra.allow_bots` | `"none"` | Управляет сообщениями от других ботов Slack: `"none"` игнорирует их, `"mentions"` принимает сообщение бота только тогда, когда **само это сообщение** @упоминает Гермеса, а `"all"` принимает все из них. Используйте `"mentions"` для самого безопасного режима совместной работы между роботами. См. [Прием сообщений от других ботов](#accepting-messages-from-other-bots-allow_bots). |
| `platforms.slack.extra.cron_continuable_surface` | `"thread"` | Поверхность доставки для [продолжаемых заданий cron](../features/cron.md#flat-in-channel-continuation-slack). `"thread"` открывает выделенный поток для каждой доставки (по умолчанию); `"in_channel"` отображается на временной шкале канала. Соедините `in_channel` с `reply_in_thread: false` (и `require_mention: false`), чтобы простой ответ канала продолжил работу. |

Эквивалентной переменной среды является `SLACK_ALLOW_BOTS=none|mentions|all`.
Если установлены оба параметра, приоритет имеет `platforms.slack.extra.allow_bots`. Избегайте
`all` когда одноранговые боты могут отвечать друг другу без явного упоминания, поскольку
их собственные политики ответа по-прежнему могут создавать циклы.

### Строка рабочего состояния

Пока агент обрабатывает сообщение, Slack отображает строку состояния рядом с ботом.
имя в теме. По умолчанию Hermes устанавливает значение `is thinking...`; настроить его
с `typing_status_text` — например. котёнок-помощник по имени Ада:

```yaml
platforms:
  slack:
    # Custom working-state status line (default: "is thinking...").
    typing_status_text: "is pouncing… 🐾"
```

| Ключ | По умолчанию | Описание |
|-----|---------|-------------|
| `platforms.slack.typing_status_text` | `"is thinking..."` | Текст строки состояния рабочего состояния, отображаемый во время обработки агентом сообщения. Требуется область `assistant:write` — без нее вызов состояния завершается автоматически, и Slack отображает свой собственный общий заполнитель, независимо от того, какое значение он установлен. Установите `typing_indicator: false`, чтобы полностью отключить строку состояния. |

:::note Где отображается статус
Пользовательский статус отображается в **нижнем колонтитуле под составителем ответа** («*BotName* думает…»), а не в списке сообщений. Встроенные строки «Генерация ответа…» / «Поиск ответов…», которые Slack показывает в области сообщений во время работы приложения AI, являются **собственными вращающимися индикаторами Slack** — `assistant.threads.setStatus` не контролирует их, и оба могут появляться одновременно.
:::

Тот же ключ настраивает видимое сообщение-маркер рабочего состояния Google Chat.
(`platforms.google_chat.typing_status_text`, по умолчанию `"Hermes is thinking…"`) —
обратите внимание, что в Google Chat это реально опубликованное сообщение, которое добавляется в
ответ, а не эфемерный статус.

### Текущий статус (для каждого инструмента)

По умолчанию строка состояния обновляется **по мере работы агента**: вместо
статический `is thinking...`, он показывает, что агент делает прямо сейчас — `есть
выполняет тесты pytest/…`, `читает документы/api.md…`, `ищет в Интернете
ограничения слабого API…`. Между вызовами инструмента он возвращается к статическому тексту. Это
использует существующую частоту обновления статуса, поэтому не требует дополнительного API Slack.
звонки, и это работает даже с `tool_progress: off` (по умолчанию в Slack) — в отличие от
пузыри прогресса, строка статуса эфемерна и ничего не оставляет после себя.
канал.

Управляйте им с помощью `display.live_status` (глобально или для каждой платформы):

```yaml
display:
  platforms:
    slack:
      # full = verb + argument ("is running pytest…")   [default]
      # verb = verb only ("is running…") — hides commands/paths,
      #        useful in shared or customer-facing channels
      # off  = static text (typing_status_text or "is thinking...")
      live_status: full
```

| Ключ | По умолчанию | Описание |
|-----|---------|-------------|
| `display.live_status` | `"full"` | Живая строка состояния для каждого инструмента. `full` показывает предварительный просмотр глагола + аргумента; `verb` показывает только команду (пути к файлам и команды не попадают в общие каналы); `off` восстанавливает статический текст. Требуется область `assistant:write`, такая же, как и статическая строка состояния. |

### Нативная потоковая передача (ответы в режиме реального времени)

Функция Slack [Агенты и приложения искусственного интеллекта](https://docs.slack.dev/ai/) поставляется в виде встроенной функции.
потоковая поверхность (`chat.startStream` / `chat.appendStream` /
`chat.stopStream`), который отображает ответ как сообщение, набираемое в реальном времени.
более плавно, чем прогрессивные обновления на основе редактирования, используемые в противном случае. Когда
`streaming.enabled` включен (транспорт `auto` или `draft`), Hermes использует собственный
автоматическая потоковая передача везде, где это доступно:

- Поток начинается с первого кадра и добавляет только дельты (API
  только добавление). Потоковое сообщение **является** последним сообщением — печати Гермеса
  это через `chat.stopStream` вместо публикации дубликата окончательного ответа.
- Если в вашем приложении Slack не включены функции искусственного интеллекта (или отсутствуют
  `assistant:write` область), первая ошибка кэшируется, и Гермес возвращается к работе.
  для потоковой передачи на основе редактирования с одним предупреждением журнала с указанием исправления.
- К запечатанному сообщению применяется комплект блокировки согласия (`rich_blocks: true`),
  то же, что и путь финализации на основе редактирования.

Никакой дополнительной настройки, кроме включения потоковой передачи, не требуется:

```yaml
streaming:
  enabled: true       # transport auto/draft lights up Slack native streaming
```

### Встроенные карточки задач (прогресс инструмента в реальном времени)

С `platforms.slack.extra.native_task_cards: true` визуализируются вызовы живых инструментов.
как родные для Slack **карты планов/задач** (тот же пользовательский интерфейс, который используется в собственных функциях искусственного интеллекта Slack)
вместо текстовых пузырей прогресса: одна карта за ход, одна строка за вызов инструмента,
с обновлением состояний выполнения/завершения/ошибки для каждой задачи.

```yaml
platforms:
  slack:
    extra:
      native_task_cards: true
```

- Это явное согласие на прогресс — оно работает, даже если Slack по умолчанию
  — `tool_progress: off` (каналы текстового спама; собственные карты — нет).
- Параллельные вызовы одного и того же инструмента коррелируются с реальным идентификатором вызова инструмента, поэтому
  Каждый из параллельных вызовов `web_search` получает свою собственную строку с правильным статусом.
- Если собственный поток не может запуститься или обновиться, Hermes возвращается к единственному потоку.
  постоянно редактируемое текстовое сообщение, поэтому прогресс сохраняется на протяжении всего хода.
- Поток карточек останавливается ровно один раз, когда завершается ход, в том числе
  при прерывании/отключении, поэтому не остается висящего индикатора активности.

### Изоляция сеанса

```yaml
# Global setting — applies to Slack and all other platforms
group_sessions_per_user: true
```

Если `true` (по умолчанию), каждый пользователь общего канала получает собственный изолированный сеанс разговора. Два человека, разговаривающие с Гермесом в `#general`, будут иметь разные истории и контексты.

Установите значение `false`, если вам нужен режим совместной работы, в котором весь канал использует один сеанс беседы. Имейте в виду, что это означает, что пользователи разделяют рост контекста и стоимость токенов, а `/reset` одного пользователя очищает сеанс для всех.

### Упоминание и триггерное поведение

```yaml
slack:
  # Require @mention in channels (this is the default behavior;
  # the Slack adapter enforces @mention gating in channels regardless,
  # but you can set this explicitly for consistency with other platforms)
  require_mention: true

  # Prevent thread auto-engagement: only reply to channel messages that
  # contain an explicit @mention. With this OFF (default), Slack can
  # "auto-engage" — remembering past mentions in a thread and following
  # up on bot-message replies, and resuming active sessions without a
  # fresh mention. With strict_mention ON, every new channel message
  # must @mention the bot before Hermes will respond.
  strict_mention: false

  # Ignore messages addressed to another user: when a channel or thread
  # message *opens* by @mentioning someone other than the bot (e.g.
  # "@rasha can you take this?"), stay silent unless the bot is also
  # mentioned. Only a *leading* mention counts as "addressed to" — a
  # message that references someone mid-sentence ("loop in @rasha")
  # still reaches the bot. Overrides free_response_channels and thread
  # auto-engagement. Opt-in; default off. Env: SLACK_IGNORE_OTHER_USER_MENTIONS.
  ignore_other_user_mentions: false

  # Require an explicit @mention for THREAD replies, while leaving
  # top-level channel messages governed by require_mention /
  # free_response_channels. Narrower than strict_mention: use it when a
  # free-response bot should not join every follow-up in busy threads.
  # Opt-in; default off. Env: SLACK_THREAD_REQUIRE_MENTION.
  thread_require_mention: false

  # Per-channel force-mention override — the opposite direction of
  # free_response_channels. Channels listed here ALWAYS require an
  # explicit @mention, even when require_mention is false globally.
  # Ongoing conversations still auto-follow (mentioned threads, active
  # sessions, bot-authored threads). Comma-separated IDs or a list.
  # Env: SLACK_REQUIRE_MENTION_CHANNELS.
  require_mention_channels: ""

  # Custom mention patterns that trigger the bot
  # (in addition to the default @mention detection)
  mention_patterns:
    - "hey hermes"
    - "hermes,"

  # Text prepended to every outgoing message
  reply_prefix: ""
```

:::tip Когда использовать `strict_mention`
Установите для этого параметра значение `true` в загруженных рабочих пространствах, где стандартное поведение Slack «бот запоминает эту ветку» удивляет пользователей — например, длинная ветка технической поддержки, в которой бот помогал с самого начала, и вы бы предпочли, чтобы он хранил молчание, пока явно не будет отправлен повторный запрос. DM и активные интерактивные сеансы не затрагиваются.
:::

:::tip Когда использовать `ignore_other_user_mentions`
Установите для этого параметра значение `true`, когда бот следует за занятыми потоками (посредством автоматического взаимодействия потоков или `free_response_channels`) и вмешивается в сообщения, которые люди адресуют друг другу. Это более узкий инструмент, чем `strict_mention`: простые последующие действия в заинтересованной теме по-прежнему дают ответы; пропускаются только сообщения, открывающиеся при @упоминании другого человека. **DM 1:1 не затрагивается**; групповые DM (MPIM) и каналы применяют его в соответствии с приведенной ниже политикой общей поверхности. Токены трансляции (`@here`, `@channel`) и ссылки на каналы относятся к комнате, а не к человеку, поэтому они никогда не пропускаются.
:::

:::информация
Slack поддерживает оба шаблона: `@mention` требуется для начала разговора по умолчанию, но вы можете отключить определенные каналы с помощью `SLACK_FREE_RESPONSE_CHANNELS` (идентификаторы каналов, разделенные запятыми) или `slack.free_response_channels` в `config.yaml`. Если у бота есть активный сеанс в потоке, последующие ответы в потоке не требуют упоминания. В **1:1 в личных сообщениях** бот всегда отвечает без упоминания.
:::

:::осторожно. Групповые DM (MPIM) — это общие поверхности, а не DM 1:1.
**Прямое сообщение 1:1** – это частный разговор с одним человеком, поэтому его упоминание не допускается. **Групповой DM (MPIM / многопользовательский DM)** — это *общая поверхность* — несколько человек могут видеть и запускать бота — поэтому он подчиняется тем же элементам управления оператора, что и канал: `require_mention`, `strict_mention`, `free_response_channels` и `allowed_channels` применяются, а бот добавляет реакции `:eyes:`/`:white_check_mark:` только тогда, когда это действительно так. `@mentioned`. Чтобы бот мог свободно отвечать в личных сообщениях конкретной группы, добавьте его идентификатор канала (начинается с `G`) в `free_response_channels`.
:::

#### Какой вариант упоминания мне нужен?

Варианты шлюзования составляют — каждый отвечает на отдельный вопрос:

| Вариант | Вопрос, на который он отвечает | По умолчанию | Область применения |
|--------|--------------------|---------|-------|
| `require_mention` | Нужно ли @упоминание **сообщениям канала верхнего уровня**? | `true` | Все каналы |
| `free_response_channels` | Какие каналы освобождены от `require_mention`? | нет | Перечисленные каналы |
| `require_mention_channels` | Какие каналы ВСЕГДА нуждаются в @упоминании, даже если `require_mention` — это `false` или на канале нет ответов? Победа над обоими. | нет | Перечисленные каналы |
| `thread_require_mention` | Нужно ли @упоминание для **ответов в теме**, даже если сообщения верхнего уровня этого не делают? Упомянутые темы не запоминаются. | `false` | Только темы |
| `strict_mention` | Нужно ли **каждому** сообщению канала (верхнего уровня и ветки) новое @упоминание? Отключает все автоматическое отслеживание: память упомянутых веток, отслеживание ответов бота, возобновление активного сеанса. | `false` | Все каналы + темы |
| `ignore_other_user_mentions` | Следует ли пропускать сообщение, которое **открывается при @упоминании кого-то другого** (`@rasha can you take this?`)? Отменяет свободный ответ и автоматическое отслеживание темы; ссылки в середине предложения все равно доходят до бота. | `false` | Каналы + групповые личные сообщения |

Эмпирические правила: `strict_mention` — самый широкий молоток; `thread_require_mention` успокаивает занятые потоки, не затрагивая шлюзование верхнего уровня; `require_mention_channels` повторно напрягает отдельные каналы бота, который в остальном не отвечает; `ignore_other_user_mentions` пропускает только сообщения, явно адресованные другому человеку. DM 1:1 всегда отвечают, и все это на них не влияет.

### Прием сообщений от других ботов (`allow_bots`)

По умолчанию Hermes игнорирует каждое сообщение, созданное другим ботом или приложением Slack (включая сообщения Workflow Builder). Для многоагентных рабочих пространств — нескольких экземпляров Hermes или одноранговых ботов, взаимодействующих в одном канале — выберите `allow_bots`:

```yaml
platforms:
  slack:
    extra:
      # "none" (default) — ignore all bot/app-authored messages
      # "mentions"       — accept a bot message only when THAT message
      #                    @mentions this bot
      # "all"            — accept every bot message (except the bot's own)
      allow_bots: mentions
```

Эквивалент Env: `SLACK_ALLOW_BOTS=none|mentions|all` (ключ конфигурации выигрывает, если установлены оба). Неизвестные значения обрабатываются как `none`.

Как работают ворота режима `mentions`:

- Сообщение однорангового бота принимается **только тогда, когда само сообщение содержит текущий `@mention` этого бота** — в его тексте или в блоках Block Kit. История тредов не учитывается: бот, упомянутый ранее в треде, отвечает на собственные сообщения бота, а активные сеансы треда **не** допускают более поздние неупомянутые сообщения однорангового бота. Это сделано намеренно — именно это разрывает циклы подтверждения/статуса между агентами.
- Человеческие сообщения не затрагиваются; К ним применяется обычное ограничение упоминаний.
- Гермес всегда игнорирует собственные сообщения в каждом режиме, чтобы предотвратить возникновение петель самоэха.

`mentions` — рекомендуемый режим для совместной работы ботов: каждый агент должен явно вызывать другого за ход. Избегайте `all`, если только собственная политика ответа каждого однорангового бота не является циклобезопасной — два бота, которые отвечают на все, будут отвечать друг другу вечно. Обнаружение охватывает помеченные сообщения ботов (`bot_id`, `subtype: bot_message`), события, происходящие в приложении, а также непомеченных *пользователей* ботов (проверяемых через `users.info`), поэтому одноранговые агенты Hermes фильтруются последовательно во всех рабочих областях.

Для строгого развертывания нескольких ботов используйте пары `require_mention: true` и `strict_mention: true` — см. профиль дымовой проверки ниже.

### Триггеры реакции (`reaction_triggers`)

По умолчанию реакции смайликов распознаются и удаляются — 👍 у бота.
сообщение ничего не делает. Установите `slack.reaction_triggers` для направления реакций в
цикл агента (требуется область `reactions:read` плюс
`reaction_added`/`reaction_removed` подписки на события ботов в вашем приложении Slack
манифест — регенерировать с помощью `hermes slack manifest`):

```yaml
slack:
  # Opt-in. false/absent (default) = reactions are acked and dropped.
  # true = any reaction ON THE BOT'S OWN MESSAGES routes to the agent.
  reaction_triggers: true
  # Or an explicit emoji allowlist — only these names route, and they may
  # target ANY message (emoji-handoff workflows, e.g. :task: to capture):
  # reaction_triggers: [white_check_mark, thumbsup, task]
  # Optional handoff target: respond in this channel (top-level) or thread
  # (C123:<thread_ts>) instead of the reacted-to message's thread.
  # reaction_trigger_target: C0123456789
```

Эквиваленты среды: `SLACK_REACTION_TRIGGERS` (`true`/`all` или
список, разделенный запятыми) и `SLACK_REACTION_TRIGGER_TARGET`.

Поведение:

- Реакция приходит как обычное обращение агента с текстом.
  `reaction:added:👍` / `reaction:removed:👍` (распространенные имена в Slack:
  переведен в Юникод; неизвестные имена передаются как есть, например.
  `reaction:added:custom-emoji`), продетый под
  сообщение, на которое отреагировали, чтобы агент видел, на что отреагировали, и
  поворот попадает в тот же сеанс, что и ответ.
- Реактор становится пользователем сообщения, поэтому **авторизация пользователя и
  `allowed_channels` шлюзование применяется точно так же, как и для печатных сообщений** —
  реакция случайного пользователя не может вызвать срабатывание агента в любом месте его сообщения
  не мог.
- При использовании `reaction_triggers: true` только реакции бота **собственные**.
  маршрут сообщений (утверждение/подтверждение потоков). С явным смайликом
  список разрешенных — список маршрутов смайлов из любого сообщения.
- Собственные реакции жизненного цикла бота (`:eyes:` и т. д.) никогда не возвращаются.
- Независимо от этого согласия, каждая человеческая реакция вызывает
  `reaction:added`/`reaction:removed` [перехватчики шлюза](../features/hooks.md#available-events)
  для наблюдателей, которым не нужна смена агентов.

### Проверка дыма однорангового агента

Для развертываний Slack с несколькими ботами, которые полагаются на строгое упоминание за ход, сохраните следующий профиль:

```yaml
slack:
  require_mention: true
  strict_mention: true
  allow_bots: mentions
  allowed_channels: ""
```

После изменения, развертывания или перезапуска конфигурации шлюза запустите эту искусственную цель дыма:

```bash
uv run --frozen pytest -q tests/gateway/test_slack_peer_agent_smoke.py -o addopts=''
```

Эта цель использует только внутрипроцессные синтетические события Slack. Он не отправляет живые сообщения Slack и по умолчанию не требует реальных токенов ботов.

Корзины отказов:

– `config:` `test_peer_agent_smoke_preflight_contract` обнаружил несоответствие профиля (`require_mention`, `strict_mention`, `allow_bots` или `allowed_channels`).
- `platform_connectivity:` адаптер/клиент не был инициализирован, поэтому маршрутизация дыма пока не является надежным сигналом.
- `bot_identity:` адаптер так и не разрешил свой идентификатор пользователя бота, поэтому проверки упоминаний в текущем сообщении не могут работать.
- `routing_logic:` адаптер Slack регрессировал в отношении одного из инвариантов однорангового агента (маршрутизация упоминаний человека, игнорирование однорангового бота, явное разрешение упоминания однорангового узла или пассивное подавление подтверждения/статуса/ошибки).

Если эта цель проходит успешно, но действующее рабочее пространство по-прежнему неправильно маршрутизирует сообщения, исследуйте подключение токена Slack к рабочему пространству и состояние развертывания во время выполнения за пределами самой логики маршрутизации.

### Белый список каналов (`allowed_channels`)

Ограничьте работу бота фиксированным набором каналов Slack — это полезно, когда бота приглашают на многие каналы, но он должен отвечать только на нескольких. Если этот параметр установлен, сообщения от каналов, НЕ входящих в этот список, **тихо игнорируются**, даже если это бот `@mentioned`.

**Письма 1:1 освобождаются** от этого фильтра, поэтому авторизованные пользователи всегда могут связаться с ботом в прямом сообщении. **Групповые DM (MPIM) не являются исключением** — как и каналы, MPIM должен быть в белом списке (его идентификатор начинается с `G`), иначе его сообщения будут удалены.

```yaml
slack:
  allowed_channels:
    - "C0123456789"   # #ops
    - "C0987654321"   # #incident-response
```

Или через env var (через запятую):

```bash
SLACK_ALLOWED_CHANNELS="C0123456789,C0987654321"
```

Поведение:

- Пусто/не установлено → нет ограничений (полная обратная совместимость).
- Непусто → идентификатор канала должен быть в списке, иначе сообщение будет удалено до запуска любого другого шлюза (упоминание требования, `free_response_channels` и т. д.).
– Идентификаторы каналов Slack начинаются с `C` (общедоступный), `G` (частный) или `D` (DM). Найдите их через панель «Сведения об открытом канале» → «О программе» пользовательского интерфейса Slack или через API.

См. также: [разделение команд администратора и пользователя](../../reference/slash-commands.md#permissions-and-adminuser-split).

### Обработка несанкционированных пользователей

```yaml
slack:
  # What happens when an unauthorized user (not in SLACK_ALLOWED_USERS) DMs the bot
  # "pair"   — prompt them for a pairing code (default)
  # "ignore" — silently drop the message
  unauthorized_dm_behavior: "pair"
```

Вы также можете установить это глобально для всех платформ:

```yaml
unauthorized_dm_behavior: "pair"
```

Специфическая для платформы настройка в разделе `slack:` имеет приоритет над глобальной настройкой.

### Транскрипция голоса

```yaml
# Global setting — enable/disable automatic transcription of incoming voice messages
stt_enabled: true
```

Если `true` (по умолчанию), входящие аудиосообщения автоматически расшифровываются с использованием настроенного поставщика STT перед обработкой агентом.

### Полный пример

```yaml
# Global gateway settings
group_sessions_per_user: true
unauthorized_dm_behavior: "pair"
stt_enabled: true

# Slack-specific settings
slack:
  require_mention: true
  unauthorized_dm_behavior: "pair"

# Platform config
platforms:
  slack:
    reply_to_mode: "first"
    extra:
      reply_in_thread: true
      reply_broadcast: false
```

## Домашний канал

Установите `SLACK_HOME_CHANNEL` для идентификатора канала, по которому Hermes будет доставлять запланированные сообщения,
результаты заданий cron и другие упреждающие уведомления. Чтобы найти идентификатор канала:

1. Щелкните правой кнопкой мыши имя канала в Slack.
2. Нажмите **Просмотреть сведения о канале**.
3. Прокрутите вниз — там указан идентификатор канала.

```bash
SLACK_HOME_CHANNEL=C01234567890
```

Убедитесь, что бот **приглашен на канал** (`/invite @Hermes Agent`).

### Таргетинг доставки Cron

Задания Cron (см. [руководство по cron](../features/cron.md#delivery-options)) могут быть нацелены на Slack тремя способами:

| `deliver:` значение | Где он приземляется |
|------------------|----------------|
| `slack` | Домашний канал (`SLACK_HOME_CHANNEL`) |
| `slack:C0123456789` | Конкретный канал по ID |
| `slack:U0123456789` | **DM** этого пользователя — пустой идентификатор пользователя автоматически преобразуется в диалог DM (требуется область `im:write`) |

Доставка работает, даже если процесс cron не совмещен со шлюзом — Hermes обращается к автономному отправителю веб-API, используя `SLACK_BOT_TOKEN`. Вложения `MEDIA:` в выходных данных cron загружаются как собственные общие файловые ресурсы Slack в ту же цель.

### Отправка сообщений и мультимедиа (`send_message`)

Инструмент `send_message` агента принимает одни и те же целевые формы: идентификатор канала (`C…`/`G…`), беседу DM (`D…`) или простой идентификатор пользователя (`U…`/`W…`), который разрешается в DM пользователя на каждом пути отправки — как текстовые, мультимедийные, так и интерактивные подсказки. `MEDIA:<path>` вложения (изображения, PDF-файлы, документы) загружаются как собственные общие папки; когда короткое сообщение сопровождает одно вложение, оно отображается как заголовок файла, а не как отдельное сообщение. Об отсутствующих файлах сообщается для каждого файла как предупреждение, а не как ошибка всей отправки.

## Поддержка нескольких рабочих пространств

Hermes может подключаться к **нескольким рабочим пространствам Slack** одновременно, используя один экземпляр шлюза. Каждое рабочее пространство аутентифицируется независимо с помощью собственного идентификатора пользователя бота.

### Конфигурация

Укажите несколько токенов бота в виде **списка, разделенного запятыми**, в `SLACK_BOT_TOKEN`:

```bash
# Multiple bot tokens — one per workspace
SLACK_BOT_TOKEN=xoxb-workspace1-token,xoxb-workspace2-token,xoxb-workspace3-token

# A single app-level token is still used for Socket Mode
SLACK_APP_TOKEN=xapp-your-app-token
```

Или в `~/.hermes/config.yaml`:

```yaml
platforms:
  slack:
    token: "xoxb-workspace1-token,xoxb-workspace2-token"
```

### Файл токена OAuth

Помимо токенов в среде или конфигурации, Hermes также загружает токены из **файла токенов OAuth** по адресу:

```
~/.hermes/slack_tokens.json
```

Этот файл представляет собой идентификаторы группы сопоставления объектов JSON с записями токенов:

```json
{
  "T01ABC2DEF3": {
    "token": "xoxb-workspace-token-here",
    "team_name": "My Workspace"
  }
}
```

Токены из этого файла объединяются с любыми токенами, указанными в `SLACK_BOT_TOKEN`. Дублирующиеся токены автоматически дедуплицируются.

### Как это работает

— **первый токен** в списке — это основной токен, используемый для подключения в режиме сокета (AsyncApp).
- Каждый токен аутентифицируется через `auth.test` при запуске. Шлюз сопоставляет каждый `team_id` со своими собственными `WebClient` и `bot_user_id`.
- При поступлении сообщения Hermes использует для ответа правильный клиент, специфичный для рабочего пространства.
– Первичный `bot_user_id` (из первого токена) используется для обратной совместимости с функциями, которые ожидают одного идентификатора бота.

## Подсказки для каждого канала

Назначайте временные системные подсказки конкретным каналам Slack. Приглашение вводится во время выполнения на каждом ходу и никогда не сохраняется в истории расшифровки, поэтому изменения вступают в силу немедленно.

```yaml
slack:
  channel_prompts:
    "C01RESEARCH": |
      You are a research assistant. Focus on academic sources,
      citations, and concise synthesis.
    "C02ENGINEERING": |
      Code review mode. Be precise about edge cases and
      performance implications.
```

Ключи — это идентификаторы каналов Slack (их можно найти в сведениях о канале → «О программе» → прокрутите вниз). Все сообщения в соответствующем канале получают приглашение в виде эфемерной системной инструкции.

## Привязки навыков для каждого канала

Автоматически загружайте навык всякий раз, когда начинается новый сеанс в определенном канале или DM. В отличие от подсказок для каждого канала (которые вводятся каждый ход), привязки навыков вводят содержимое навыка в виде пользовательского сообщения при **начале сеанса** — оно становится частью истории разговора и не требует перезагрузки на последующих ходах.

Это идеально подходит для личных сообщений или каналов со специальным назначением (карточки, бот вопросов и ответов для конкретной области, канал сортировки поддержки и т. д.), где вы не хотите, чтобы собственный селектор навыков модели решал, загружать ли его при каждом коротком ответе.

```yaml
slack:
  channel_skill_bindings:
    # DM channel — always runs in "german-flashcards" mode
    - id: "D0ATH9TQ0G6"
      skills:
        - german-flashcards
    # Research channel — preload multiple skills in order
    - id: "C01RESEARCH"
      skills:
        - arxiv
        - writing-plans
    # Short form: single skill as a string
    - id: "C02SUPPORT"
      skill: hubspot-on-demand
```

Примечания:
- Привязка соответствует идентификатору канала. Для связанных сообщений в связанном канале поток наследует привязку родительского канала.
- Навык загружается только при запуске сессии (новая сессия или после автосброса). Если вы измените привязку, запустите `/new` или дождитесь автоматического сброса сеанса, чтобы изменения вступили в силу.
- В сочетании с `channel_prompts` для получения тона/ограничений для каждого канала в дополнение к инструкциям по навыкам.

## Устранение неполадок

| Проблема | Решение |
|---------|----------|
| Бот не отвечает в личные сообщения | Убедитесь, что `message.im` включен в ваши подписки на мероприятия и приложение переустановлено |
| Бот работает в личных сообщениях, но не в каналах | **Наиболее распространенная проблема.** Добавьте `message.channels` и `message.groups` в подписку на события, переустановите приложение и пригласите бота на канал с помощью `/invite @Hermes Agent` |
| Бот не отвечает на @упоминания в каналах | 1) Убедитесь, что событие `message.channels` подписано. 2) Бота необходимо пригласить на канал. 3) Убедитесь, что добавлена ​​область `channels:history`. 4) Переустановите приложение после изменения области действия/события |
| Бот игнорирует сообщения в приватных каналах | Добавьте подписку на событие `message.groups` и область `groups:history`, затем переустановите приложение и `/invite` бота |
| Бот не отвечает в групповых личных сообщениях (мульти-личные сообщения) | Добавьте подписку на событие `message.mpim` и область `mpim:history` (плюс `mpim:read`), затем **переустановите** приложение. Без `message.mpim` Slack никогда не доставляет сообщения группового DM боту, даже несмотря на то, что DM 1:1 работают. |
| «Отправка сообщений в это приложение отключена» в личных сообщениях | Включите вкладку **Сообщения** в настройках App Home (см. шаг 5) |
| Ошибки «not_authed» или «invalid_auth» | Восстановите свой токен бота и токен приложения, обновите `.env` |
| Бот отвечает, но не может опубликовать сообщение в канале | Пригласить бота на канал с помощью `/invite @Hermes Agent` |
| Бот может общаться, но не может читать загруженные изображения/файлы | Добавьте `files:read`, а затем **переустановите** приложение. Hermes теперь отображает диагностику доступа к вложениям в чате, когда Slack возвращает ошибки области/авторизации/разрешения. |
| `missing_scope` ошибка | Добавьте необходимую область в OAuth & Permissions, затем **переустановите** приложение |
| Розетка часто отключается | Проверьте свою сеть; Bolt автоматически переподключается, но нестабильные соединения вызывают задержку |
| Изменены области/события, но ничего не изменилось | Вы **необходимо переустановить** приложение в своем рабочем пространстве после любого изменения объема или подписки на событие |

### Быстрый контрольный список

Если бот не работает в каналах, проверьте **все** следующее:

1. ✅ Подписано событие `message.channels` (для общедоступных каналов)
2. ✅ Подписано событие `message.groups` (для частных каналов)
3. ✅ Подписано событие `app_mention`
4. ✅ Добавлена область `channels:history` (для общедоступных каналов)
5. ✅ Добавлена область `groups:history` (для частных каналов)
6. ✅ Приложение было **переустановлено** после добавления областей/событий.
7. ✅ Бот **приглашен** на канал (`/invite @Hermes Agent`)
8. ✅ Вы **@упоминаете** бота в своем сообщении.

## Безопасность

:::предупреждение
**Всегда устанавливайте `SLACK_ALLOWED_USERS`** с идентификаторами участников авторизованных пользователей. Без этой настройки
шлюз по умолчанию **запрещает все сообщения** в качестве меры безопасности. Никогда не делитесь своими токенами бота —
относитесь к ним как к паролям.
:::

- Токены должны храниться в `~/.hermes/.env` (права доступа к файлу `600`).
- Периодическая ротация токенов через настройки приложения Slack.
- Проверьте, кто имеет доступ к вашему каталогу конфигурации Hermes.
- Режим сокетов означает, что общедоступная конечная точка не подвергается воздействию — на одну поверхность атаки меньше.
