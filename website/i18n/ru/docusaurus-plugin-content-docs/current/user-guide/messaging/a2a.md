# A2A (Агент-агенту)

[A2A](https://a2a-protocol.org) — это открытый протокол Agent2Agent (версия 1.0, управляемый Linux Foundation) для связи между независимыми агентами ИИ. Плагин Hermes A2A работает в **обаих направлениях**: ваш агент может вызывать других агентов A2A в качестве инструментов, а другие агенты могут отправлять задачи вашему Hermes через HTTP.

Он взаимодействует с любым A2A-совместимым одноранговым узлом — другим агентом Hermes, LangChain, CrewAI, Google ADK или чем-либо еще, созданным на основе официального `a2a-sdk`.

## Когда использовать A2A

- **Hermes ↔ Hermes на разных машинах** — пусть ваш настольный агент передает задачи Hermes на сервере или наоборот, каждый со своей собственной памятью, инструментами и учетными данными.
- **Делегирование полномочий специализированным агентам** — партнер, рекламирующий `web_search`/`research`/`coding` навыки на своей карточке агента, может быть обнаружен и вызван в середине разговора.
- **Является вызываемой службой** — откройте свой Hermes, чтобы агенты других платформ могли отправлять ему задачи.

Если вам нужно, чтобы несколько агентов находились на **одной машине**, отдайте предпочтение [делегированию](../features/delegation.md) (внутрипроцессные субагенты) или [канбан-доске](../features/kanban.md) (надежная многопрофильная рабочая очередь) — A2A предназначен для пересечения границ процесса/машины/фреймворка.

## Включить

```bash
hermes gateway setup      # pick A2A
```

Или в `~/.hermes/config.yaml`:

```yaml
gateway:
  platforms:
    a2a:
      enabled: true
      extra:
        port: 9900
```

Инструменты исходящего клиента поставляются как набор инструментов `a2a`, **по умолчанию отключен** — включите его для каждой платформы:

```bash
hermes tools enable a2a --platform cli        # CLI/TUI sessions
hermes tools enable a2a --platform telegram   # or any messaging platform
hermes tools enable a2a --platform a2a        # let inbound A2A tasks call peers (agent chaining)
```

Эти инструменты доступны для каждого типа процесса — CLI, TUI, шлюза и cron — без необходимости включения входящей платформы.

## Исходящие: вызов другим агентам

При включенном наборе инструментов `a2a` агент получает:

| Инструмент | Что он делает |
|---|---|
| `a2a_discover(url)` | Получение и суммирование карты агента партнера |
| `a2a_call(agent, message, context_id?)` | Отправьте задачу, получите ответ; многооборотный через `context_id` |
| `a2a_list()` | Настроенные пиры, сохраненные разговоры, метрики |
| `a2a_history(context_id)` | Вспомните продолжающийся разговор A2A |
| `a2a_orchestrate(capability, message, mode?)` | Распространите задачу среди всех участников, рекламирующих возможности (`all` / `first` / `best`) |

Настройте известные пиры в `config.yaml`:

```yaml
a2a_agents:
  researcher:
    url: "http://research-box.local:9900"
    auth: { type: bearer, token: "..." }
    timeout: 120
    capabilities: [web_search, research]
```

Затем просто спросите: * «Попросите агента-исследователя суммировать сегодняшние публикации arXiv». * Прямые URL-адреса тоже работают — `a2a_call` принимает любую конечную точку A2A.

## Входящий: возможность вызова

При включенной платформе Hermes обслуживает:

- **Карточка агента** по адресу `GET /.well-known/agent-card.json` (канонический путь версии 1.0; устаревший `agent.json` также отвечает) — сообщает имя вашего агента, его навыки (полученные из включенных наборов инструментов) и требования аутентификации.
- **JSON-RPC 2.0** по адресу `POST /` — канонические методы версии 1.0 (`SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, конфигурация push-уведомлений CRUD) плюс псевдонимы в стиле пути до версии 1.0 (`message/send`, …).
- **Потоковая передача SSE** для `SendStreamingMessage` с правильными по спецификациям кадрами в формате JSON-RPC.
- **Push-уведомления** (веб-перехватчики) для длительно выполняющихся задач, подписанные HMAC-SHA256.

Входящие задачи вводятся в **сеанс живого шлюза** — тот же агент, память и инструменты, которые обслуживают другие ваши каналы, — и окончательный ответ возвращается вызывающей стороне как результат задачи. Разговоры кодируются с помощью A2A `contextId`, поэтому партнер может проводить многооборотный обмен.

Совместимость проверяется на соответствие официальному Python `a2a-sdk` (разрешение карты, `SendMessage`, потоковая передача).

## Модель безопасности

Безопасно по умолчанию; каждый шаг расширения очевиден:

- **Нет токена ⇒ только локальный хост.** Сервер привязывает `127.0.0.1`. Для удаленного воздействия требуется токен на предъявителя **и** явный `A2A_HOST`.
- **Токены для каждого узла** — `A2A_PEER_TOKENS="alice:tok1,bob:tok2"` предоставляет каждому узлу свои собственные учетные данные; аутентифицированное имя обеспечивает ограничение скорости, доверие и аудит.
- **Фильтрация подсказок** — входящий текст фильтруется и оформляется как ненадежный одноранговый ввод. Удаленные узлы не могут вызывать команды оператора.
- **Исходящее редактирование** — строки учетных данных (ключи API, JWT, токены) удаляются из ответов.
- **Журнал аудита** — каждый обмен добавляется в `~/.hermes/a2a_audit.jsonl`.
- **Антизацикливание** — ограничение количества ходов для каждого контекста навсегда останавливает пинг-понг двух агентов.

## Справочник по конфигурации

| Конверт вар | По умолчанию | Значение |
|---|---|---|
| `A2A_PEER_TOKENS` | _(не установлено)_ | Учетные данные для каждого узла `name:token,…` (предпочтительно) |
| `A2A_BEARER_TOKEN` | _(не установлено)_ | Общий токен; идентичность возвращается к IP-адресу вызывающего абонента |
| `A2A_HOST` | `127.0.0.1` | Привязать хост — расширяется только при установке токена |
| `A2A_PORT` | `9900` | Входящий порт |
| `A2A_AGENT_NAME` | производное от имени хоста | Имя на карточке агента |
| `A2A_PUBLIC_URL` | _(не установлено)_ | Маршрутизируемый URL-адрес, рекламируемый на карте (обратные прокси/k8s) |
| `A2A_TRUSTED_PEERS` | _(не установлено)_ | Разрешенный список аутентифицированных личностей |
| `A2A_ALLOW_ALL_USERS` | `false` | Разрешить любой аутентифицированный узел (только для разработчиков) |
| `A2A_RATE_LIMIT` | `60` | Запросов/минуту на личность |
| `A2A_MAX_PINGPONG_TURNS` | `5` | Ограничение поворотов против зацикливания на контекст (максимум 20) |
| `A2A_REPLY_TIMEOUT` | `300` | Секунды ожидания ответа агента |
| `A2A_PUSH_SECRET` | токен на предъявителя | Секрет HMAC для подписания push-уведомлений |
| `A2A_ADVERTISED_TOOLSETS` | все зарегистрированы | Ограничить список навыков, отображаемых на карте агента |

За обратным прокси-сервером или службой Kubernetes установите `A2A_PUBLIC_URL` (или используйте `X-Forwarded-Host`/`X-Forwarded-Proto`), чтобы карта агента рекламировала URL-адреса, которые действительно могут перезвонить.

## Быстрый тест

```bash
# From another machine / agent:
curl http://your-host:9900/.well-known/agent-card.json

curl -X POST http://your-host:9900/ \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <token>' \
  -d '{"jsonrpc":"2.0","id":1,"method":"SendMessage",
       "params":{"message":{"messageId":"m1","role":"ROLE_USER",
                 "parts":[{"text":"What tools do you have?"}]}}}'
```

## Устранение неполадок

- **Пирам не удается получить доступ к URL-адресу карты** — карта рекламировала ваш адрес привязки; установите `A2A_PUBLIC_URL` в качестве URL-адреса с внешней маршрутизацией.
- **`401 Unauthorized`** — несовпадение токена; проверьте `A2A_PEER_TOKENS`/`A2A_BEARER_TOKEN` на сервере и блок `auth:` узла.
- **Сервер не будет привязывать нелокальный хост** — по задумке: сначала установите токен носителя, затем `A2A_HOST=0.0.0.0`.
- **Тайм-аут ответов на длительные задачи** — поднимите `A2A_REPLY_TIMEOUT` или попросите вызывающего абонента зарегистрировать конфигурацию push-уведомлений и опросить `GetTask`.
