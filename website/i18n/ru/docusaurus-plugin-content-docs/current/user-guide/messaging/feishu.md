# Настройка Фейшу/Жаворонка

Агент Hermes интегрируется с Feishu и Lark как полнофункциональный бот. После подключения вы можете общаться с агентом в прямых сообщениях или групповых чатах, получать результаты заданий cron в домашнем чате и отправлять текст, изображения, аудио и вложения файлов через обычный поток шлюза.

Интеграция поддерживает оба режима подключения:

- `websocket` — рекомендуется; Hermes открывает исходящее соединение, и вам не требуется общедоступная конечная точка веб-перехватчика.
- `webhook` — полезно, если вы хотите, чтобы Feishu/Lark отправлял события в ваш шлюз через HTTP.

## Как ведет себя Гермес

| Контекст | Поведение |
|---------|----------|
| Прямые сообщения | Гермес отвечает на каждое сообщение. |
| Групповые чаты | Hermes отвечает только тогда, когда бот @упоминается в чате. |
| Общие групповые чаты | По умолчанию история сеансов изолирована для каждого пользователя внутри общего чата. |

Такое поведение в общем чате контролируется `config.yaml`:

```yaml
group_sessions_per_user: true
```

Установите значение `false` только в том случае, если вы явно хотите, чтобы в каждом чате был один общий разговор.

## Шаг 1. Создайте приложение Feishu/Lark

### Рекомендуется: сканирование и создание (одна команда)

```bash
hermes gateway setup
```

Выберите **Feishu / Lark** и отсканируйте QR-код с помощью мобильного приложения Feishu или Lark. Hermes автоматически создаст бот-приложение с правильными разрешениями и сохранит учетные данные.

### Альтернатива: ручная настройка

Если сканирование для создания недоступно, мастер возвращается к ручному вводу:

1. Откройте консоль разработчика Feishu или Lark:
   - Фейшу: [https://open.feishu.cn/](https://open.feishu.cn/)
   - Жаворонок: [https://open.larksuite.com/](https://open.larksuite.com/)
2. Создайте новое приложение.
3. В разделе **Учетные данные и основная информация** скопируйте **Идентификатор приложения** и **Секрет приложения**.
4. Включите функцию **Бот** для приложения.
5. Запустите `hermes gateway setup`, выберите **Feishu/Lark** и введите учетные данные при появлении запроса.

:::предупреждение
Держите секрет приложения в тайне. Любой, у кого он есть, может выдать себя за ваше приложение.
:::

### Настройка разрешений

В консоли разработчика Feishu перейдите в раздел **Управление разрешениями** и добавьте следующие области. Вы можете массово импортировать их на странице разрешений.

**Необходимые разрешения:**

| Область применения | Цель |
|-------|---------|
| `im:message` | Получать и читать сообщения |
| `im:message:send_as_bot` | Отправляйте сообщения как бот |
| `im:resource` | Доступ к изображениям, файлам и аудио, отправленным пользователями |
| `im:chat` | Доступ к метаданным чата/группы |
| `im:chat:readonly` | Прочитать список чатов и членство |

**Рекомендуемые разрешения (для полной функциональности):**

| Область применения | Цель |
|-------|---------|
| `im:message.reactions:readonly` | Получайте события реакции на смайлики |
| `admin:app.info:readonly` | Автоматическое определение личности бота для @mention gating |
| `contact:user.id:readonly` | Разрешение идентификаторов пользователей для сопоставления с белым списком |

### Настройка событий

В разделе **События и обратные вызовы**:

1. Установите режим подключения **Длинное соединение (WebSocket)** (рекомендуется) или настройте URL-адрес веб-перехватчика.
2. В разделе **Конфигурация событий** подпишитесь на:
   - `im.message.receive_v1` — необходим для получения сообщений

### Опубликуйте приложение

После настройки разрешений и событий перейдите в раздел **Управление версиями** и опубликуйте новую версию приложения. Разрешения не вступят в силу, пока версия не будет опубликована и одобрена (для корпоративных приложений для этого может потребоваться одобрение администратора).

## Шаг 2. Выберите режим подключения

### Рекомендуется: режим WebSocket.

Используйте режим WebSocket, когда Hermes работает на вашем ноутбуке, рабочей станции или частном сервере. Публичный URL-адрес не требуется. Официальный Lark SDK открывает и поддерживает постоянное исходящее соединение WebSocket с автоматическим повторным подключением.

```bash
FEISHU_CONNECTION_MODE=websocket
```

**Требования:** Должен быть установлен пакет Python `websockets`. SDK управляет жизненным циклом соединения, контрольными сигналами и автоматическим повторным подключением внутри компании.

**Как это работает.** Адаптер запускает клиент WebSocket из Lark SDK в фоновом потоке исполнителя. Входящие события (сообщения, реакции, действия карты) отправляются в основной цикл asyncio. При отключении SDK попытается автоматически повторно подключиться.

### Необязательно: режим веб-перехватчика

Используйте режим веб-перехватчика только в том случае, если вы уже запускаете Hermes за доступной конечной точкой HTTP.

```bash
FEISHU_CONNECTION_MODE=webhook
```

В режиме веб-перехватчика Hermes запускает HTTP-сервер (через `aiohttp`) и обслуживает конечную точку Feishu по адресу:

```text
/feishu/webhook
```

**Требования:** Должен быть установлен пакет Python `aiohttp`.

Вы можете настроить адрес и путь привязки сервера веб-перехватчика:

```bash
FEISHU_WEBHOOK_HOST=127.0.0.1   # default: 127.0.0.1
FEISHU_WEBHOOK_PORT=8765         # default: 8765
FEISHU_WEBHOOK_PATH=/feishu/webhook  # default: /feishu/webhook
```

Когда Feishu отправляет запрос на проверку URL-адреса (`type: url_verification`), вебхук отвечает автоматически, и вы можете завершить настройку подписки в консоли разработчика Feishu. Ответ на запрос блокируется `FEISHU_VERIFICATION_TOKEN`, если он установлен — запросы на вызов с отсутствующим или несовпадающим токеном отклоняются, поэтому неаутентифицированный удаленный компьютер не может доказать контроль над конечной точкой, повторяя данные запроса, контролируемые злоумышленником.

## Шаг 3: Настройте Гермес

### Вариант А: Интерактивная настройка

```bash
hermes gateway setup
```

Выберите **Фейшу/Жаворонок** и заполните подсказки.

### Вариант Б: Настройка вручную

Добавьте следующее в `~/.hermes/.env`:

```bash
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=secret_xxx
FEISHU_DOMAIN=feishu
FEISHU_CONNECTION_MODE=websocket

# Optional but strongly recommended
FEISHU_ALLOWED_USERS=ou_xxx,ou_yyy
FEISHU_HOME_CHANNEL=oc_xxx
```

`FEISHU_DOMAIN` принимает:

- `feishu` для Feishu China
- `lark` для Lark International

## Шаг 4: Запустите шлюз

```bash
hermes gateway
```

Затем отправьте сообщение боту от Feishu/Lark, чтобы подтвердить, что соединение установлено.

## Домашний чат

Используйте `/set-home` в чате Feishu/Lark, чтобы пометить его как домашний канал для результатов заданий cron и кроссплатформенных уведомлений.

Вы также можете предварительно настроить его:

```bash
FEISHU_HOME_CHANNEL=oc_xxx
```

## Безопасность

### Белый список пользователей

Для производственного использования установите белый список Feishu Open ID:

```bash
FEISHU_ALLOWED_USERS=ou_xxx,ou_yyy
```

Если вы оставите белый список пустым, любой, кто сможет связаться с ботом, сможет им воспользоваться. В групповых чатах список разрешенных проверяется по open_id отправителя перед обработкой сообщения.

### Ключ шифрования вебхука

При работе в режиме веб-перехватчика установите ключ шифрования, чтобы включить проверку подписи входящих полезных данных веб-перехватчика:

```bash
FEISHU_ENCRYPT_KEY=your-encrypt-key
```

Этот ключ находится в разделе **Подписки на события** конфигурации вашего приложения Feishu. Если этот параметр установлен, адаптер проверяет каждый запрос веб-перехватчика с использованием алгоритма подписи:

```
SHA256(timestamp + nonce + encrypt_key + body)
```

Вычисленный хеш сравнивается с заголовком `x-lark-signature` с использованием сравнения по времени. Запросы с недействительными или отсутствующими подписями отклоняются с помощью HTTP 401.

:::совет
В режиме WebSocket проверка подписи выполняется самим SDK, поэтому `FEISHU_ENCRYPT_KEY` не является обязательным. В режиме веб-перехватчика настоятельно рекомендуется использовать его в рабочей среде.
:::

### Токен подтверждения

Дополнительный уровень аутентификации, который проверяет поле `token` внутри полезных данных веб-перехватчика:

```bash
FEISHU_VERIFICATION_TOKEN=your-verification-token
```

Этот токен также можно найти в разделе **Подписки на события** вашего приложения Feishu. Если этот параметр установлен, каждая входящая полезная нагрузка веб-перехватчика должна содержать соответствующий `token` в своем объекте `header`. Несовпадающие токены отклоняются с помощью HTTP 401.

И `FEISHU_ENCRYPT_KEY`, и `FEISHU_VERIFICATION_TOKEN` можно использовать вместе для глубокоэшелонированной защиты.

## Политика групповых сообщений

Переменная среды `FEISHU_GROUP_POLICY` определяет, будет ли Гермес отвечать в групповых чатах и каким образом:

```bash
FEISHU_GROUP_POLICY=allowlist   # default
```

| Значение | Поведение |
|-------|----------|
| `open` | Hermes отвечает на @упоминания любого пользователя в любой группе. |
| `allowlist` | Hermes отвечает только на @упоминания пользователей, перечисленных в `FEISHU_ALLOWED_USERS`. |
| `disabled` | Гермес полностью игнорирует все групповые сообщения. |

Во всех режимах бот должен быть явно @упомянут (или @all) в группе перед обработкой сообщения. Прямые сообщения всегда обходят эти ворота.

Установите `FEISHU_REQUIRE_MENTION=false`, чтобы Hermes мог читать весь групповой трафик без необходимости @mention:

```bash
FEISHU_REQUIRE_MENTION=false
```

Для управления каждым чатом установите `require_mention` для записи `group_rules` — см. [Групповой контроль доступа](#per-group-access-control) ниже.

### Идентификация бота

Hermes автоматически определяет `open_id` бота и отображаемое имя при запуске. Вам нужно установить их вручную только в том случае, если автоматическое обнаружение не может достичь Feishu API или когда ваше приложение использует идентификаторы пользователей на уровне клиента:

```bash
FEISHU_BOT_OPEN_ID=ou_xxx     # only when auto-detection fails
FEISHU_BOT_USER_ID=xxx        # required if your app uses sender_id_type=user_id
FEISHU_BOT_NAME=MyBot         # only when auto-detection fails
```

## Обмен сообщениями между ботами

По умолчанию Hermes игнорирует сообщения, отправленные другими ботами. Включите обмен сообщениями между ботами, если хотите, чтобы Hermes участвовал в оркестрации A2A или получал уведомления от других ботов в той же группе.

```bash
FEISHU_ALLOW_BOTS=mentions   # default: none
```

| Значение | Поведение |
|-------|----------|
| `none` | Игнорировать все сообщения от других ботов (по умолчанию). |
| `mentions` | Принимайте только тогда, когда одноранговый бот @упомянет Гермеса. |
| `all` | Принимайте каждое сообщение однорангового бота. |

Также можно настроить как `feishu.allow_bots` в `config.yaml` (env выигрывает, если установлены оба).

Одноранговые боты не нужно добавлять в `FEISHU_ALLOWED_USERS` — этот белый список применяется только к отправителям-людям.

Предоставьте область `application:bot.basic_info:read` для отображения имен одноранговых ботов; без него одноранговые боты по-прежнему маршрутизируются правильно, но отображаются как `open_id`.

## Действия с интерактивными картами

Когда пользователи нажимают кнопки или взаимодействуют с интерактивными карточками, отправленными ботом, адаптер маршрутизирует их как синтетические командные события `/card`:

- Нажатия кнопок становятся: `/card button {"key": "value", ...}`.
– Полезная нагрузка действия `value` из определения карты включается в формате JSON.
- Действия с картами дедуплицируются с 15-минутным окном для предотвращения двойной обработки.

В запросах обновления на основе шлюза используется собственная карта Feishu `Yes` / `No` вместо возврата к ответам в виде обычного текста. Когда `hermes update --gateway` требуется подтверждение, адаптер записывает выбранный ответ в файл Hermes `.update_response` и заменяет встроенную карточку разрешенным состоянием.

События действия карты отправляются с помощью `MessageType.COMMAND`, поэтому они проходят через обычный конвейер обработки команд.

Точно так же работает **утверждение команды**: когда агенту необходимо выполнить опасную команду, он отправляет интерактивную карточку с кнопками «Разрешить один раз» / «Сеанс» / «Всегда» / «Запретить». Пользователь нажимает кнопку, и обратный вызов действия карты возвращает агенту решение об утверждении.

### Требуемая конфигурация приложения Feishu

Для интерактивных карточек требуется **три** шага настройки в консоли разработчика Feishu. Отсутствие любого из них приводит к ошибке **200340**, когда пользователи нажимают кнопки карточек.

1. **Подпишитесь на событие действия карты:**
   В разделе **Подписки на события** добавьте `card.action.trigger` к событиям, на которые вы подписаны.

2. **Включите функцию интерактивной карты:**
   В разделе **Функции приложения > Бот** убедитесь, что переключатель **Интерактивная карта** включен. Это сообщает Фейшу, что ваше приложение может получать обратные вызовы действий карты.

3. **Настройте URL-адрес запроса карты (только в режиме веб-перехватчика):**
   В разделе **Функции приложения > Бот > URL-адрес запроса карточки сообщения** установите URL-адрес той же конечной точки, что и веб-перехватчик событий (например, `https://your-server:8765/feishu/webhook`). В режиме WebSocket это автоматически обрабатывается SDK.

:::предупреждение
Без всех трех шагов Feishu успешно *отправит* интерактивные карты (для отправки требуется только разрешение `im:message:send`), но нажатие любой кнопки вернет ошибку 200340. Кажется, карта работает — ошибка проявляется только тогда, когда пользователь взаимодействует с ней.
:::

## Комментарий к документу Интеллектуальный ответ

Помимо чата, адаптер также может отвечать на `@` упоминаний, оставленных в **документах Feishu/Lark**. Когда пользователь комментирует документ (выделение локального текста или комментарий ко всему документу) и @-упоминает бота, Hermes читает документ, а также ветку комментариев вокруг него, и публикует ответ LLM внутри ветки.

На основе события `drive.notice.comment_add_v1` обработчик:

- Параллельно извлекает содержимое документа и временную шкалу комментариев (20 сообщений для цепочек всего документа, 12 для цепочек локального выбора).
- Запускает агент с наборами инструментов `feishu_doc` + `feishu_drive`, ограниченными этим единственным сеансом комментариев.
- Чанки отвечают длиной 4000 символов и отправляют их обратно в виде цепочек ответов.
– Кэширует сеансы для каждого документа в течение 1 часа с ограничением в 50 сообщений, поэтому последующие комментарии к одному и тому же документу сохраняют контекст.

### 3-уровневый контроль доступа

Ответы на комментарии к документу доступны **только с явным разрешением** — неявного режима разрешения всех нет. Разрешения применяются в следующем порядке (победы в первом матче по каждому полю):

1. **Точный документ** — правило, ограниченное конкретным токеном документа.
2. **Подстановочный знак** — правило, соответствующее шаблону документов.
3. **Верхний уровень** — правило по умолчанию для рабочей области.

Для каждого правила доступны две политики:

- **`allowlist`** — статический список пользователей/арендаторов.
- **`pairing`** — статический список ∪ одобренных во время выполнения магазинов. Полезно для развертываний, когда модераторы могут предоставить доступ в реальном времени.

Правила живут в `~/.hermes/feishu_comment_rules.json` (разрешения на сопряжение в `~/.hermes/feishu_comment_pairing.json`) с горячей перезагрузкой, кэшируемой в mtime — изменения вступают в силу при следующем комментировании без перезапуска шлюза.

Интерфейс командной строки:

```bash
# Inspect current rules and pairing state
python -m gateway.platforms.feishu_comment_rules status

# Simulate an access check for a specific doc + user
python -m gateway.platforms.feishu_comment_rules check <fileType:fileToken> <user_open_id>

# Manage pairing grants at runtime
python -m gateway.platforms.feishu_comment_rules pairing list
python -m gateway.platforms.feishu_comment_rules pairing add <user_open_id>
python -m gateway.platforms.feishu_comment_rules pairing remove <user_open_id>
```

### Требуемая конфигурация приложения Feishu

Помимо уже предоставленных разрешений для чата/карточек добавьте событие комментария на диске:

- Подпишитесь на `drive.notice.comment_add_v1` в разделе **Подписки на мероприятия**.
— Предоставьте области `docs:doc:readonly` и `drive:drive:readonly`, чтобы обработчик мог читать содержимое документа.

## Приглашения на встречи

Вы можете пригласить бота Hermes Feishu/Lark на видеоконференцию так же, как вы приглашаете участника-человека. Когда бот получает приглашение на встречу, Hermes может автоматически начать очередь агента, который пытается присоединиться к встрече.

На основе события `vc.bot.meeting_invited_v1` поток выглядит следующим образом:

- Пользователь приглашает бота на видеовстречу Feishu/Lark.
- Фейшу/Жаворонок отправляет Гермесу приглашение на встречу.
- Hermes извлекает приглашенного, тему встречи и номер встречи.
- Если приглашающий авторизован обычным списком разрешений шлюза или политикой сопряжения, агент получает номер собрания и пытается присоединиться автоматически.
- Если приглашение имеет неверный формат или агент не может присоединиться, Hermes прекращает мероприятие или отвечает приглашающему краткое объяснение.

Неверно сформированные приглашения, не содержащие ни приглашающего, ни `meeting_no`, игнорируются.

### Требуемая конфигурация приложения Feishu

Помимо уже предоставленных разрешений для чата/карточки добавьте приглашение на видеособрание:

- Подпишитесь на `vc.bot.meeting_invited_v1` в разделе **Подписки на мероприятия**.
- Включите область разрешений видеоконференций, предложенную консолью разработчика Feishu/Lark для этого события.
– Оставьте `im:message` и `im:message:send_as_bot` включенными, чтобы Hermes мог ответить приглашающему.
– Убедитесь, что список разрешенных пользователей шлюза или политика сопряжения авторизуют приглашающего. Приглашения на собрания не обходят обычные проверки доступа к шлюзу.

## Медиа-поддержка

### Входящий (прием)

Адаптер получает и кэширует от пользователей следующие типы мультимедиа:

| Тип | Расширения | Как это обрабатывается |
|------|-----------|-------------------|
| **Изображения** | .jpg, .jpeg, .png, .gif, .webp, .bmp | Загружено через Feishu API и локально кэшировано |
| **Аудио** | .ogg, .mp3, .wav, .m4a, .aac, .flac, .opus, .webm | Загружено и кэшировано; небольшие текстовые файлы извлекаются автоматически |
| **Видео** | .mp4, .mov, .avi, .mkv, .webm, .m4v, .3gp | Загружено и кэшировано как документы |
| **Файлы** | .pdf, .doc, .docx, .xls, .xlsx, .ppt, .pptx и другие | Загружено и кэшировано как документы |

Медиафайлы из сообщений с форматированным текстом (постов), включая встроенные изображения и вложенные файлы, также извлекаются и кэшируются.

Для небольших текстовых документов (.txt, .md) содержимое файла автоматически вводится в текст сообщения, поэтому агент может прочитать его напрямую, без использования инструментов.

### Исходящие (отправка)

| Метод | Что он отправляет |
|--------|--------------|
| `send` | Текстовые или расширенные сообщения (определяются автоматически на основе содержимого уценки) |
| `send_image` / `send_image_file` | Загружает изображение в Feishu, а затем отправляет его как собственное изображение (с дополнительной подписью) |
| `send_document` | Загружает файл в Feishu API, а затем отправляет его как вложение |
| `send_voice` | Загружает аудиофайл как вложение файла Feishu |
| `send_video` | Загружает видео и отправляет как собственное медиа-сообщение |
| `send_animation` | GIF-файлы заменены вложенными файлами (у Feishu нет встроенного GIF-пузыря) |

Маршрутизация загрузки файлов осуществляется автоматически в зависимости от расширения:

- `.ogg`, `.opus` → загружено как аудио `opus`
- `.mp4`, `.mov`, `.avi`, `.m4v` → загружено как медиафайл `mp4`.
- `.pdf`, `.doc(x)`, `.xls(x)`, `.ppt(x)` → загружено с указанием типа документа.
- Все остальное → загружается как общий потоковый файл.

## Рендеринг Markdown и резервное копирование после

Если исходящий текст содержит форматирование уценки (заголовки, жирный шрифт, списки, блоки кода, ссылки и т. д.), адаптер автоматически отправляет его как сообщение Feishu **post** со встроенным тегом `md`, а не как обычный текст. Это обеспечивает богатый рендеринг в клиенте Feishu.

Если API Feishu отклоняет полезную нагрузку публикации (например, из-за неподдерживаемых конструкций уценки), адаптер автоматически возвращается к отправке в виде обычного текста с удаленной уценкой. Этот двухэтапный резервный вариант гарантирует, что сообщения всегда доставляются.

Обычные текстовые сообщения (уценка не обнаружена) отправляются как сообщение простого типа `text`.

## Обработка статусных реакций

Пока агент работает, бот показывает `Typing` реакцию на ваше сообщение. Он очищается при получении ответа или заменяется на `CrossMark`, если обработка не удалась.

Установите `FEISHU_REACTIONS=false`, чтобы отключить его.

## Защита от пакетов и пакетная обработка

Адаптер включает функцию устранения дребезга для быстрых пакетов сообщений, чтобы избежать перегрузки агента:

### Пакетная обработка текста

Когда пользователь отправляет несколько текстовых сообщений подряд, перед отправкой они объединяются в одно событие:

| Настройка | Конверт Вар | По умолчанию |
|---------|---------|---------|
| Тихий период | `HERMES_FEISHU_TEXT_BATCH_DELAY_SECONDS` | 0,6 с |
| Максимальное количество сообщений в пакете | `HERMES_FEISHU_TEXT_BATCH_MAX_MESSAGES` | 8 |
| Максимальное количество символов в пакете | `HERMES_FEISHU_TEXT_BATCH_MAX_CHARS` | 4000 |

### Пакетирование мультимедиа

Несколько мультимедийных вложений, отправленных быстро друг за другом (например, перетаскивание нескольких изображений), объединяются в одно событие:

| Настройка | Конверт Вар | По умолчанию |
|---------|---------|---------|
| Тихий период | `HERMES_FEISHU_MEDIA_BATCH_DELAY_SECONDS` | 0,8 с |

### Сериализация для каждого чата

Сообщения в одном чате обрабатываются последовательно (по одному) для обеспечения связности разговора. Каждый чат имеет свою блокировку, поэтому сообщения в разных чатах обрабатываются одновременно.

## Ограничение скорости (режим веб-перехватчика)

В режиме веб-перехватчика адаптер применяет ограничение скорости для каждого IP-адреса для защиты от злоупотреблений:

- **Окно:** 60-секундное скользящее окно.
- **Ограничение:** 120 запросов на окно на тройку (app_id, путь, IP).
- **Ограничение отслеживания:** отслеживается до 4096 уникальных ключей (предотвращает неограниченный рост памяти).

Запросы, превышающие лимит, получают HTTP 429 (слишком много запросов).

### Отслеживание аномалий веб-перехватчика

Адаптер отслеживает последовательные ответы об ошибках для каждого IP-адреса. После 25 последовательных ошибок с одного и того же IP-адреса в течение 6 часов регистрируется предупреждение. Это помогает обнаружить неправильно настроенные клиенты или попытки проверки.

Дополнительная защита вебхука:
- **Ограничение на размер тела:** максимум 1 МБ.
- **Тайм-аут чтения тела:** 30 секунд.
– **Принудительное соблюдение типов контента:** допускается только `application/json`.

## Настройка WebSocket

При использовании режима `websocket` вы можете настроить поведение повторного подключения и проверки связи:

```yaml
platforms:
  feishu:
    extra:
      ws_reconnect_interval: 120   # Seconds between reconnect attempts (default: 120)
      ws_ping_interval: 30         # Seconds between WebSocket pings (optional; SDK default if unset)
```

| Настройка | Конфигурационный ключ | По умолчанию | Описание |
|---------|-----------|---------|-------------|
| Интервал повторного подключения | `ws_reconnect_interval` | 120-е | Как долго ждать между попытками переподключения |
| Интервал пинга | `ws_ping_interval` | _(SDK по умолчанию)_ | Частота проверок активности WebSocket |

## Групповой контроль доступа

Помимо глобального `FEISHU_GROUP_POLICY`, вы можете установить детальные правила для группового чата, используя `group_rules` в config.yaml:

```yaml
platforms:
  feishu:
    extra:
      default_group_policy: "open"     # Default for groups not in group_rules
      admins:                          # Users who can manage bot settings
        - "ou_admin_open_id"
      group_rules:
        "oc_group_chat_id_1":
          policy: "allowlist"          # open | allowlist | blacklist | admin_only | disabled
          allowlist:
            - "ou_user_open_id_1"
            - "ou_user_open_id_2"
        "oc_group_chat_id_2":
          policy: "admin_only"
        "oc_group_chat_id_3":
          policy: "blacklist"
          blacklist:
            - "ou_blocked_user"
        "oc_free_chat":
          policy: "open"
          require_mention: false       # overrides FEISHU_REQUIRE_MENTION for this chat
```

| Политика | Описание |
|--------|-------------|
| `open` | Использовать бота может любой участник группы |
| `allowlist` | Бота могут использовать только пользователи из группы `allowlist` |
| `blacklist` | Использовать бота могут все, кроме пользователей в группе `blacklist` |
| `admin_only` | Бота в этой группе могут использовать только пользователи из глобального списка `admins` |
| `disabled` | Бот игнорирует все сообщения в этой группе |

Установите `require_mention: false` для записи `group_rules`, чтобы пропустить требование @-упоминания для этого конкретного чата. Если этот параметр опущен, чат наследует глобальное значение `FEISHU_REQUIRE_MENTION`.

Группы, не перечисленные в `group_rules`, возвращаются к `default_group_policy` (по умолчанию используется значение `FEISHU_GROUP_POLICY`).

## Дедупликация

Входящие сообщения дедуплицируются с использованием идентификаторов сообщений с 24-часовым сроком жизни. Состояние дедупликации сохраняется при перезапуске до `~/.hermes/feishu_seen_message_ids.json`.

| Настройка | Конверт Вар | По умолчанию |
|---------|---------|---------|
| Размер кэша | `HERMES_FEISHU_DEDUP_CACHE_SIZE` | 2048 записей |

## Поиск неисправностей

| Проблема | Исправить |
|---------|-----|
| `lark-oapi not installed` | Установите SDK: `pip install lark-oapi` |
| `websockets not installed; websocket mode unavailable` | Установите веб-сокеты: `pip install websockets` |
| `aiohttp not installed; webhook mode unavailable` | Установите aiohttp: `pip install aiohttp` |
| `FEISHU_APP_ID or FEISHU_APP_SECRET not set` | Установите обе переменные окружения или настройте через `hermes gateway setup` |
| `Another local Hermes gateway is already using this Feishu app_id` | Только один экземпляр Hermes может использовать один и тот же app_id одновременно. Сначала остановите другой шлюз. |
| Бот не отвечает в группах | Убедитесь, что бот @упомянут, проверьте `FEISHU_GROUP_POLICY` и убедитесь, что отправитель находится в `FEISHU_ALLOWED_USERS`, если политика `allowlist` |
| `Webhook rejected: invalid verification token` | Убедитесь, что `FEISHU_VERIFICATION_TOKEN` соответствует токену в конфигурации подписки на события вашего приложения Feishu |
| `Webhook rejected: invalid signature` | Убедитесь, что `FEISHU_ENCRYPT_KEY` соответствует ключу шифрования в конфигурации вашего приложения Feishu |
| Почтовые сообщения отображаются в виде обычного текста | API Feishu отклонил полезную нагрузку публикации; это нормальное поведение при отступлении. Проверьте журналы для получения подробной информации. |
| Изображения/файлы, не полученные ботом | Предоставьте области разрешений `im:message` и `im:resource` вашему приложению Feishu |
| Личность бота не определена автоматически | Обычно временная проблема с сетью достигает конечной точки информации о боте Фейшу. Установите `FEISHU_BOT_OPEN_ID` и `FEISHU_BOT_NAME` вручную в качестве обходного пути. |
| Сообщения одноранговых ботов по-прежнему игнорируются после включения `FEISHU_ALLOW_BOTS` | Гермес пока не может идентифицировать себя — установите `FEISHU_BOT_OPEN_ID` (и `FEISHU_BOT_USER_ID`, если ваше приложение использует `sender_id_type=user_id`). |
| Одноранговые боты отображаются как `ou_xxxxxx` вместо имени | Предоставьте область `application:bot.basic_info:read`. |
| Ошибка 200340 при нажатии кнопок одобрения | Включите функцию **Интерактивная карта** и настройте **URL-адрес запроса карты** в консоли разработчика Feishu. См. [Требуемая конфигурация приложения Feishu](#required-feishu-app-configuration) выше. |
| `Webhook rate limit exceeded` | Более 120 запросов в минуту с одного IP. Обычно это неправильная конфигурация или петля. |

## Набор инструментов

Feishu/Lark использует предустановку платформы `hermes-feishu`, которая включает в себя те же основные инструменты, что и Telegram и другие платформы обмена сообщениями на основе шлюза.
