# Настройка ЛИНИИ

Запустите Hermes Agent как бота [LINE](https://line.me/) через официальный API обмена сообщениями LINE. Адаптер существует в виде встроенного плагина платформы под `plugins/platforms/line/` — никаких изменений ядра, просто включите его, как любую другую платформу.

LINE — ведущее приложение для обмена сообщениями в Японии, Тайване и Таиланде. Если ваши пользователи живут там, именно так они и достигают вас.

> Запустите `hermes gateway setup` и выберите **LINE** для пошагового руководства.

## Как реагирует бот

| Контекст | Поведение |
|---------|----------|
| **Чат 1:1** (идентификаторы `U`) | Отвечает на каждое сообщение |
| **Групповой чат** (идентификаторы `C`) | Отвечает, когда группа находится в белом списке |
| **Многопользовательская комната** (`R` идентификаторов) | Отвечает, когда комната находится в белом списке |

Обрабатывается входящий текст, изображения, аудио, видео, файлы, наклейки и местоположения. Исходящий текст использует **токен бесплатного ответа в первую очередь** (одноразовый, окно ~60 секунд) и возвращается к дозированному API-интерфейсу Push по истечении срока действия токена.

---

## Шаг 1. Создайте канал LINE Messaging API

1. Перейдите в [Консоль разработчика LINE](https://developers.line.biz/console/).
2. Создайте поставщика, а затем под ним канал **Messaging API**.
3. На вкладке **Основные настройки** канала скопируйте **Секрет канала**.
4. На вкладке **Messaging API** прокрутите до пункта **Токен доступа к каналу (долгосрочный)** и нажмите **Выпустить**. Скопируйте токен.
5. На вкладке **API сообщений** также отключите **Сообщения автоответа** и **Приветственные сообщения**, чтобы они не противоречили ответам вашего бота.

---

## Шаг 2. Откройте доступ к порту веб-перехватчика

LINE предоставляет веб-перехватчики по общедоступному протоколу HTTPS. Порт по умолчанию — `8646`. При необходимости замените его на `LINE_PORT`.

```bash
# Cloudflare Tunnel (recommended for production — fixed hostname)
cloudflared tunnel --url http://localhost:8646

# ngrok (good for dev)
ngrok http 8646

# devtunnel
devtunnel create hermes-line --allow-anonymous
devtunnel port create hermes-line -p 8646 --protocol https
devtunnel host hermes-line
```

Скопируйте URL-адрес `https://...` — вы установите его в качестве URL-адреса веб-перехватчика ниже. **Оставьте туннель включенным** во время тестирования. Для рабочей среды настройте фиксированный туннель с именем Cloudflare, чтобы URL-адрес веб-перехватчика не менялся при перезапуске.

---

## Шаг 3: Настройте Гермес

Добавьте в `~/.hermes/.env`:

```env
LINE_CHANNEL_ACCESS_TOKEN=YOUR_LONG_LIVED_TOKEN
LINE_CHANNEL_SECRET=YOUR_CHANNEL_SECRET

# Allowlist — at least one of these (or LINE_ALLOW_ALL_USERS=true for dev)
LINE_ALLOWED_USERS=U1234567890abcdef...           # comma-separated U-prefixed IDs
LINE_ALLOWED_GROUPS=C1234567890abcdef...          # optional group IDs
LINE_ALLOWED_ROOMS=R1234567890abcdef...           # optional room IDs

# Required for image / audio / video sends — the public HTTPS base URL
# the tunnel resolves to.  Without it, send_image/voice/video will refuse.
LINE_PUBLIC_URL=https://my-tunnel.example.com
```

Затем в `~/.hermes/config.yaml`:

```yaml
gateway:
  platforms:
    line:
      enabled: true
```

Этого достаточно — сканирование встроенного плагина в `gateway/config.py` автоматически обнаруживает `plugins/platforms/line/`. Нет редактирования перечисления `Platform.LINE`, нет регистрации `_create_adapter`.

---

## Шаг 4. Установите URL-адрес веб-перехватчика

Вернёмся в консоль LINE:

1. Откройте свой канал → вкладка **Messaging API**.
2. В разделе **Настройки веб-перехватчика** → **URL-адрес веб-перехватчика** вставьте `https://<your-tunnel>/line/webhook` (обратите внимание на путь `/line/webhook` — адаптер прослушивает его).
3. Нажмите **Подтвердить**. LINE проверяет URL-адрес; вы должны увидеть 200.
4. Установите для параметра **Использовать веб-перехватчик** значение **Вкл.**.

---

## Шаг 5: Запустите шлюз

```bash
hermes gateway
```

В журнале агента показано:

```
LINE: webhook listening on * (all interfaces, IPv4+IPv6):8646/line/webhook (public: https://my-tunnel.example.com)
```

Добавьте бота в друзья из приложения LINE (отсканируйте QR на вкладке **Messaging API** канала) и отправьте ему сообщение.

## Медленные ответы LLM

Токен ответа LINE является одноразовым и истекает примерно через 60 секунд после входящего события. Медленные LLM не могут ответить вовремя, что обычно приводит к платному вызову Push API.

Когда LLM продолжает работать в течение `LINE_SLOW_RESPONSE_THRESHOLD` секунд (по умолчанию `45`), адаптер использует исходный токен ответа для отправки всплывающего сообщения **Кнопки шаблона**:

> 🤔Все еще думаю. Нажмите ниже, чтобы получить ответ, когда он будет готов.
>
> [Получить ответ]

Пользователь нажимает **Получить ответ**, когда ему удобно — в результате обратной передачи доставляется *свежий* токен ответа, который адаптер использует для отправки кэшированного ответа (по-прежнему бесплатно).

Конечный автомат: `PENDING → READY → DELIVERED` плюс `ERROR` для отмененных запусков (сиротский PENDING разрешается как «Выполнение было прервано до завершения». после `/stop`, поэтому постоянная кнопка не зацикливается).

Чтобы отключить кнопку обратной передачи и вместо этого всегда использовать Push-Fallback:

```env
LINE_SLOW_RESPONSE_THRESHOLD=0
```

Чтобы поток обратной передачи работал надежно, подавите болтовню, которая может использовать токен ответа до достижения порога:

```yaml
# ~/.hermes/config.yaml
display:
  interim_assistant_messages: false
  platforms:
    line:
      tool_progress: off
```

## Cron/доставка уведомлений

```env
LINE_HOME_CHANNEL=Uxxxxxxxxxxxxxxxxxxxx     # default delivery target
```

Задания Cron с маршрутом `deliver: line` к `LINE_HOME_CHANNEL`. Адаптер поставляется с автономным отправителем только для push-уведомлений, поэтому задания cron работают, даже если cron выполняется в отдельном от шлюза процессе.

## Ссылка на переменную среды

| Переменная | Требуется | По умолчанию | Описание |
|---|---|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | да | — | Долговечный токен доступа к каналу |
| `LINE_CHANNEL_SECRET` | да | — | Секрет канала (проверка веб-перехватчика HMAC-SHA256) |
| `LINE_HOST` | нет | не установлено (двойной стек: все интерфейсы, IPv4+IPv6) | Вебхук привязывает хост |
| `LINE_PORT` | нет | `8646` | Порт привязки вебхука |
| `LINE_PUBLIC_URL` | для СМИ | — | Общедоступный базовый URL-адрес HTTPS; требуется для отправки изображения/голоса/видео |
| `LINE_ALLOWED_USERS` | один из | — | Идентификаторы пользователей, разделенные запятыми (с префиксом U) |
| `LINE_ALLOWED_GROUPS` | один из | — | Идентификаторы групп, разделенные запятыми (с префиксом C) |
| `LINE_ALLOWED_ROOMS` | один из | — | Идентификаторы комнат, разделенные запятыми (с префиксом R) |
| `LINE_ALLOW_ALL_USERS` | только для разработчиков | `false` | Полностью пропустить белый список |
| `LINE_HOME_CHANNEL` | нет | — | Цель cron/доставки уведомлений по умолчанию |
| `LINE_SLOW_RESPONSE_THRESHOLD` | нет | `45` | За секунды до срабатывания кнопки обратной передачи (`0` = отключено) |
| `LINE_PENDING_TEXT` | нет | «🤔 Все еще думаю…» | Текст в виде всплывающей подсказки рядом с кнопкой обратной передачи |
| `LINE_BUTTON_LABEL` | нет | «Получить ответ» | Надпись на кнопке |
| `LINE_DELIVERED_TEXT` | нет | «Уже ответил ✅» | Ответить при повторном нажатии уже доставленной кнопки |
| `LINE_INTERRUPTED_TEXT` | нет | «Выполнение было прервано до завершения». | Ответить при нажатии потерянной кнопки `/stop` |

## Устранение неполадок

**"неверная подпись" при проверке веб-перехватчика.** `Channel secret` был скопирован неправильно, или ваш туннель переписал тело запроса. Сначала проверьте `curl -i https://<tunnel>/line/webhook/health` — должно вернуться `{"status":"ok","platform":"line"}`.

**Бот ничего не получает в группах.** Проверьте, что `LINE_ALLOWED_GROUPS` включает идентификатор группы `C...`. Чтобы найти идентификатор группы, отправьте тестовое сообщение и выполните команду grep `~/.hermes/logs/gateway.log` для `LINE: rejecting unauthorized source` — идентификаторы отклоненного источника есть.

**`send_image` завершается сбоем: «Необходимо установить LINE_PUBLIC_URL».** API обмена сообщениями LINE не принимает двоичную загрузку — изображения, аудио и видео должны быть доступными URL-адресами HTTPS. Установите `LINE_PUBLIC_URL` в качестве общедоступного имени хоста туннеля, и адаптер будет автоматически обслуживать файлы с `/line/media/<token>/<filename>`.

**Кнопка обратной передачи никогда не появляется.** Либо LLM ответил быстрее, чем `LINE_SLOW_RESPONSE_THRESHOLD`, либо другой пузырь (прогресс инструмента, потоковая передача) первым израсходовал токен ответа. См. блок подавления в разделе «Медленные ответы LLM».

**"уже используется другим профилем".** Тот же токен доступа к каналу привязан к другому работающему профилю Hermes. Остановите другой шлюз или используйте отдельный канал.

## Ограничения

* **Ограничения по длине и кружочкам.** Каждый текстовый кружок LINE ограничен 5000 символами. Более длинные ответы разумно разбиваются на фрагменты размером около 4500 символов в виде до 5 пузырьков на каждый ответный или push-вызов, разделяя их по естественным границам, где это возможно.
* **Нет встроенного редактирования сообщений.** В LINE нет API для редактирования сообщений — потоковые ответы всегда отправляют новые пузырьки, а не редактируют предыдущие.
* **Отрисовка Markdown отсутствует.** Жирный шрифт (`**`), курсив (`*`), границы кода и заголовки отображаются как буквальные символы. Адаптер удаляет их перед отправкой; URL-адреса сохраняются (`[label](url)` становится `label (url)`).
* **Индикатор загрузки доступен только в личных сообщениях.** LINE отклоняет API чата/загрузки для групп и комнат, поэтому индикатор ввода отображается только в чатах 1:1.
