# Настройка API WhatsApp Business Cloud

Hermes может подключиться к WhatsApp через **официальный** API WhatsApp Business Cloud от Meta. Это путь производственного уровня: без подпроцесса моста Node.js, без QR-кодов, без риска блокировки учетной записи.

В обмен:

- Вам нужен **аккаунт Meta Business** (не личный WhatsApp).
- Бот работает по выделенному рабочему номеру телефона, а не по вашему личному номеру.
– Шлюзу Hermes требуется **общедоступный URL-адрес HTTPS**, чтобы Meta могла доставлять входящие сообщения через веб-перехватчик.
- Для ответов более чем через 24 часа после последнего сообщения пользователя требуется предварительно утвержденный **шаблон** (это правило «окна обслуживания клиентов» Meta, а не ограничение Hermes).

Если эти ограничения не подходят для вашего варианта использования, альтернативой является [интеграция моста Baileys](./whatsapp.md) — личный аккаунт, общедоступный URL-адрес не требуется, но неофициальный и подверженный банам.

:::tip Какой из них мне следует использовать?
- **Облачный API (данное руководство)** — запуск настоящего бизнес-бота, нужна стабильность, подойдет мета-проверка + оформление шаблона
- **[Baileys Bridge](./whatsapp.md)** — личные проекты, быстрые демо, однопользовательские настройки, готовы рисковать аккаунтом номера телефона бота
:::

## Быстрый старт

```bash
hermes whatsapp-cloud
```

Мастер проведет вас через все учетные данные, проверяет каждый из них по мере их вставки (ловит ловушку настройки № 1 — вставку номера телефона в поле «Идентификатор номера телефона») и печатает точные последующие инструкции для тех частей, которые должны произойти вне мастера (запуск Cloudflared, настройка панели управления веб-перехватчика Meta).

Остальная часть этой страницы представляет собой справочную информацию по руководству.

## Предварительные условия

1. **Учётная запись Meta Business**.  Создайте его на странице [business.facebook.com](https://business.facebook.com/).
2. **Мета-приложение с включенным WhatsApp**.  См. «Создание мета-приложения» ниже.
3. **Способ открыть локальный порт общедоступному Интернету** с помощью HTTPS.  Рекомендуется Cloudflare Tunnel (`cloudflared`) — бесплатно, без переадресации портов и домена.  ngrok, ваш собственный домен с обратным прокси + TLS или VPS со шлюзом, напрямую привязанным к общедоступному IP-адресу, — все это тоже работает.
4. **Необязательно, но рекомендуется**: ffmpeg на `PATH`, чтобы исходящие голосовые сообщения отображались в виде пузырьков голосовых заметок WhatsApp (зеленая форма волны), а не в виде аудиовложений в формате MP3. Гермес изящно деградирует, если отсутствует.

## Создание мета-приложения

1. Перейдите на страницу [developers.facebook.com/apps](https://developers.facebook.com/apps) → **Создать приложение**.
2. Выберите вариант использования: ** «Общайтесь с клиентами через WhatsApp»** → **Далее**.
3. Выберите или создайте бизнес-портфолио.  Ознакомьтесь с требованиями к публикации.  Подтвердите → **Создать приложение**.
4. После создания вы перейдете к **Настроить вариант использования → Подключиться к WhatsApp → Быстрый старт**.  Нажмите **Начать использовать API** → вы находитесь на странице **Настройка API**.
5. Убедитесь, что учетная запись WhatsApp Business (WABA) связана.  Если вы создали новое портфолио на шаге 3, оно было создано автоматически.  Проверьте это на странице настройки API.

Вам потребуются эти значения с информационной панели — мастер запрашивает их в следующем порядке:

| Значение | Где в приборной панели | Форма поля | Заметки |
|---|---|---|---|
| **Идентификатор номера телефона** | Панель управления приложения → WhatsApp → Настройка API → под раскрывающимся списком «От» | Числовые, 15–17 цифр | **НЕ** сам номер телефона. Ошибка настройки №1 — вставить сюда реальный номер телефона. |
| **Токен доступа** | Панель управления приложения → WhatsApp → Настройка API → «Сгенерировать токен доступа» | Начинается с `EAA`, более 100 символов | Временные токены действуют 24 часа — информацию о производстве см. в разделе «Постоянные токены» ниже. |
| **Секрет приложения** | Панель управления приложения → Настройки → Основные → нажмите «Показать» рядом с секретом приложения | 32-значный шестнадцатеричный нижний регистр | Используется для проверки подписей входящих веб-перехватчиков.  Без него входящая доставка отклоняется с кодом 503. |
| **Идентификатор приложения** (необязательно) | Панель управления приложения → Настройки → Основные | Числовой, 15–16 цифр | Не требуется для обмена сообщениями, полезно для аналитики. |
| **Идентификатор WABA** (необязательно) | Панель управления приложения → WhatsApp → Настройка API → вверху | Числовой, более 15 цифр | Не требуется для обмена сообщениями, полезно для аналитики. |

## Постоянный токен (производство)

Срок действия токенов временного доступа истекает через **24 часа**. Это означает, что токен, созданный сегодня, перестанет работать завтра.  Для производственных развертываний используйте **постоянный токен системного пользователя**:

1. Перейдите на страницу [business.facebook.com/latest/settings](https://business.facebook.com/latest/settings) → **Пользователи системы** (левая боковая панель).
2. **Добавить** → имя (например, `hermes-bot`) → роль: **Администратор**.
3. Выберите нового пользователя → **Назначить активы**:
   – Выберите свое приложение → переключите **Управление приложением** в разделе «Полный контроль».
   - Выберите свою учетную запись WhatsApp → переключите **Управление учетными записями WhatsApp Business** в разделе «Полный контроль».
   – Нажмите **Назначить объекты**.
4. **Создать токен** со следующими разрешениями:
   - `business_management`
   - `whatsapp_business_messaging`
   - `whatsapp_business_management`
5. Установите **срок действия токена: Никогда**.
6. Скопируйте токен → обновите `WHATSAPP_CLOUD_ACCESS_TOKEN` в `~/.hermes/.env` → перезапустите шлюз.

Срок действия токенов системных пользователей не истекает, если вы явно не отзовете их.

## Разоблачение Гермеса в Интернете

Cloud API доставляет входящие сообщения через HTTPS POST на URL-адрес вашего веб-перехватчика — это означает, что шлюз Hermes должен быть доступен с серверов Meta.  Три распространенных способа:

### Cloudflare Tunnel (рекомендуется)

Бесплатно, без переадресации портов, работает на Windows/macOS/Linux.  Запускается как отдельный процесс рядом со шлюзом.

**Установить:**

```bash
# Windows
winget install Cloudflare.cloudflared

# macOS
brew install cloudflared

# Linux
# Download the binary from https://github.com/cloudflare/cloudflared/releases
```

**Запустите быстрый туннель** (учетная запись Cloudflare не требуется — вы получаете URL-адрес `https://<random>.trycloudflare.com`):

```bash
cloudflared tunnel --url http://localhost:8090
```

Обратите внимание на напечатанный URL — это то, что вы дадите Meta.

:::предупреждение Быстрые туннели вращаются
URL-адрес бесплатного быстрого туннеля меняется каждый раз при перезапуске `cloudflared`.  Чтобы получить стабильный URL-адрес, войдите в систему с помощью `cloudflared tunnel login` и создайте именованный туннель.  Бесплатные учетные записи Cloudflare получают неограниченное количество именованных туннелей — см. [документацию Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) для рабочего процесса с именованными туннелями.
:::

### нгрок

```bash
ngrok http 8090
```

На бесплатном уровне при каждом перезапуске отображается другой URL-адрес.  Платный уровень дает вам стабильный поддомен.

### Свой домен + обратный прокси

Если у вас уже есть сервер с сертификатом TLS (Caddy, nginx и т. д.), укажите маршрут по адресу `localhost:8090`.  Это наиболее стабильный вариант производства, но требует наличия существующей инфраструктуры.

## Настройка вебхука на стороне Meta

Как только ваш туннель заработает:

1. Обратите внимание на общедоступный URL-адрес, напечатанный вашим туннелем, — скажем, `https://abc123.trycloudflare.com`.
2. Создайте ** токен проверки** — мастер сделает это за вас с помощью `secrets.token_urlsafe(32)`; если вы настраиваете вручную, запустите:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   Сохраните его как `WHATSAPP_CLOUD_VERIFY_TOKEN` в `~/.hermes/.env`.
3. Запустите шлюз Hermes: `hermes gateway`.
4. На панели управления мета-приложением → **WhatsApp → Конфигурация** (или **Случаи использования → Настройка → Конфигурация** в зависимости от версии пользовательского интерфейса) → нажмите **Изменить** в разделе Вебхук.
5. Заполните:
   - **URL обратного вызова**: `https://abc123.trycloudflare.com/whatsapp/webhook`
   - **Verify Token**: строка из шага 2 (должна точно совпадать).
6. Нажмите **Проверить и сохранить**.  Meta обращается к вашему URL-адресу с помощью запроса GET, шлюз повторяет запрос, и Meta помечает вебхук как проверенный.
7. В разделе **Поля вебхука** нажмите **Управление** → подпишитесь на поле **сообщения**.  Это то, что заставляет Meta доставлять входящие сообщения на ваш вебхук.

**Чтобы проверить контур вручную** (с третьего терминала):

```bash
TUNNEL="https://abc123.trycloudflare.com"
VERIFY="<your verify token>"

# Should print HTTP 200 with body "hello"
curl -i "$TUNNEL/whatsapp/webhook?hub.mode=subscribe&hub.verify_token=$VERIFY&hub.challenge=hello"

# Health endpoint — should show verify_token_configured: true and app_secret_configured: true
curl "$TUNNEL/health"
```

## Белый список получателей (мета-сторона)

В режиме разработки (до того, как ваше приложение пройдет проверку приложения) Meta ограничивает номера, которые ваш бот может отправлять:

1. Панель управления приложения → WhatsApp → Настройка API → раскрывающийся список **Кому**.
2. Нажмите **Управление списком номеров телефонов**.
3. Добавьте номера телефонов, по которым хотите отправить сообщение (ваш, вашей команды, дружественных тестировщиков).  Meta отправляет каждому 6-значный код подтверждения по SMS или WhatsApp.

До 5 номеров в режиме разработки.  Переход к обзору приложений снимает это ограничение.

---

## Белый список (сторона Hermes)

В дополнение к белому списку получателей Meta, у Hermes есть собственный белый список для каждой платформы, который контролирует **какие входящие сообщения обрабатывает агент**.  Добавьте в `~/.hermes/.env`:

```bash
# Comma-separated phone numbers, country code, no '+' / spaces / dashes
WHATSAPP_CLOUD_ALLOWED_USERS=15551234567,15557654321

# Or allow everyone (only safe in combination with Meta's recipient whitelist)
# WHATSAPP_CLOUD_ALLOW_ALL_USERS=true
```

Мастер устанавливает это на шаге 6. Без списка разрешенных **каждое входящее сообщение отклонено** — это сделано намеренно, поэтому бот не может быть вызван случайными числами, если белый список получателей когда-либо будет ослаблен.

## Полировка профиля вашего бота в WhatsApp

WhatsApp отображает **имя и изображение профиля** вашего бота в заголовке чата и списке контактов. Их нельзя настроить через Cloud API — они находятся в Бизнес-менеджере Meta.

Как только ваш бот заработает, перейдите на страницу **[business.facebook.com/wa/manage/phone-numbers](https://business.facebook.com/wa/manage/phone-numbers/)**, щелкните свой номер телефона, и вы найдете:

| Что | Где | Заметки |
|---|---|---|
| **Отображаемое имя** | Верхняя часть страницы с телефонными номерами | Изменения проходят процедуру проверки имени Meta (~ 24–48 часов). |
| **Изображение профиля** | Верхняя часть страницы с телефонными номерами | Квадратное изображение, рекомендуется ≥640×640 пикселей. Обновления немедленно. |
| **О себе/описание/сайт/электронная почта/часы работы/категория** | Кнопка «Редактировать профиль» | Они появляются на информационной панели, когда пользователь нажимает на имя бота. Косметический. |
| **Значок проверенного** (зеленая галочка) | Бизнес-менеджер → Центр безопасности → Начать проверку | Требуется отдельный процесс проверки бизнеса Meta. |

Мастер `hermes whatsapp-cloud` распечатает эти ссылки в конце установки. Ничего из этого не требуется для работы бота — это чистая доработка того, как ваш бот выглядит для пользователей.

## Справочник по конфигурации

Все настройки хранятся в `~/.hermes/.env`.  Обязательные значения выделены **жирным**.

| Переменная | По умолчанию | Описание |
|---|---|---|
| **`WHATSAPP_CLOUD_PHONE_NUMBER_ID`** | — | 15–17-значный идентификатор из настройки API.  **Не** номер телефона. |
| **`WHATSAPP_CLOUD_ACCESS_TOKEN`** | — | Мета-токен доступа (начинается с `EAA`).  Временная температура 24 часа или постоянный пользователь системы. |
| **`WHATSAPP_CLOUD_APP_SECRET`** | — | 32-значный шестнадцатеричный код в меню «Настройки» → «Основные».  Без него входящий сигнал отклоняется с кодом 503. |
| **`WHATSAPP_CLOUD_VERIFY_TOKEN`** | — | Общий секрет для рукопожатия GET.  Создается автоматически мастером. |
| **`WHATSAPP_CLOUD_ALLOWED_USERS`** | — | Разделенные запятыми идентификаторы wa_ids позволяют отправлять сообщения боту. |
| `WHATSAPP_CLOUD_ALLOW_ALL_USERS` | `false` | Установите значение `true`, чтобы обойти белый список. |
| `WHATSAPP_CLOUD_APP_ID` | — | Необязательно, для будущей интеграции аналитики. |
| `WHATSAPP_CLOUD_WABA_ID` | — | Необязательно, для будущей интеграции аналитики. |
| `WHATSAPP_CLOUD_WEBHOOK_HOST` | не установлено (двойной стек: все интерфейсы, IPv4+IPv6) | Интерфейс, к которому привязывается сервер веб-перехватчика. |
| `WHATSAPP_CLOUD_WEBHOOK_PORT` | `8090` | Порт, к которому привязан сервер веб-перехватчика.  Должен соответствовать порту вашего туннеля. |
| `WHATSAPP_CLOUD_WEBHOOK_PATH` | `/whatsapp/webhook` | URL-адрес мета-публикаций. |
| `WHATSAPP_CLOUD_API_VERSION` | `v20.0` | Версия API Meta Graph. Переопределять только в том случае, если в документации Meta рекомендуется более новая версия. |
| `WHATSAPP_CLOUD_HOME_CHANNEL` | — | wa_id для использования в качестве домашнего канала бота (для заданий cron и т. д.). |

Вы можете включить **оба** адаптеры Baileys (`whatsapp`) и Cloud (`whatsapp_cloud`) одновременно, ориентируясь на разные телефонные номера.

## Особенности

### Входящий

- **Текстовые сообщения** — передаются прямо агенту.
- **Изображения** — автоматически загружаются и прикрепляются к входу агента. Модели с собственным зрением (Клод, GPT-4o, Близнецы и т. д.) считывают изображение напрямую; Модели без зрения получают автоматически созданное текстовое описание.
- **Голосовые заметки** — автоматически загружаются как `.ogg`, расшифровываются через настроенного вами провайдера STT (локальный fast-whisper, OpenAI/Nous, Groq и т. д.), а затем передаются агенту в виде текста.
- **Документы** — загружаются автоматически. Небольшие текстовые файлы (`.txt`, `.md`, `.json`, `.py`, `.csv` и т. д.) размером до 100 КБ встраиваются во входные данные агента, поэтому он может читать их без вызова инструмента. Файлы большего размера кэшируются локально, чтобы к ним могли получить доступ другие инструменты агента.
- **Нажатие кнопки** — когда пользователь нажимает кнопку, отправленную ботом ранее (уточнение выбора, одобрение команды, подтверждение команды с косой чертой), нажатие перенаправляется непосредственно к правому обработчику. Устаревшие нажатия снова рассматриваются как обычный ввод текста.
- **Контекст ответа** — когда пользователь отвечает на предыдущее сообщение бота, агент видит исходное сообщение как контекст.

### Исходящий

- **Текст** — уценка автоматически преобразуется в специальный синтаксис WhatsApp (`**bold**` → `*bold*`, `~~strike~~` → `~strike~`, заголовки → жирный, `[link](url)` → `link (url)`). Длинные сообщения разделяются по 4096 символов на фрагмент.
- **Изображения** — поддерживаются как созданные агентом изображения, так и локальные файлы изображений, которые доставляются в виде собственных вложений фотографий.
- **Голосовые сообщения** — преобразование текста в речь преобразуется с помощью ffmpeg в встроенную голосовую заметку WhatsApp (зеленая волна). Без установленного ffmpeg возвращается к аудио-вложению MP3. См. раздел «Голосовые сообщения» ниже.
- **Видео/документы** — оба поддерживаются, отправляются как собственные вложения.

### Интерактивный UX

Когда агент вызывает любой из этих потоков, Hermes использует собственные интерактивные сообщения WhatsApp — кнопки «нажми, чтобы ответить» вместо подсказок «ответить по номеру»:

– **`clarify` инструмент** — вопросы с несколькими вариантами ответов отображаются в виде кнопок быстрого ответа (1–3 варианта выбора) или листа списка, открываемого нажатием (более 4 вариантов). Выбор «✏️ Другое» позволяет пользователю ввести ответ в свободной форме, который агент получает в качестве решения.
- **Утверждения опасных команд** — когда терминал/при выполнении кода агента попадает на закрытую команду, пользователь видит кнопки `✅ Approve`/`❌ Deny` вместо необходимости вводить `/approve` или `/deny`.
- **Подтверждения косой черты** — привилегированные команды, такие как `/reload-mcp`, отображают кнопки `✅ Approve Once` / `🔒 Always` / `❌ Cancel`.

Все интерактивные подсказки корректно преобразуются в обычный текст, если кнопки не отображаются (например, в устаревших клиентах WhatsApp).

### Квитанции о прочтении и индикатор ввода

Гермес немедленно подтверждает входящие сообщения:

- Ваше сообщение будет отмечено **синими двойными галочками**, как только шлюз его получит.
- Имя бота в вашем чате WhatsApp отображается как **"вводит..."**, пока агент готовит ответ.
- Индикатор набора текста автоматически исчезает при поступлении первого ответного сообщения бота.

Это делает очевидным, когда бот увидел ваше сообщение, а не когда он все еще работает над ответом.

### Голосовые сообщения

WhatsApp различает «голосовую заметку» (зеленый пузырь) и обычное вложение аудиофайла. Разница заключается исключительно в кодеке: голосовые заметки должны быть `audio/ogg` с кодировкой `opus`.

Hermes TTS производит MP3. Два пути:

- **С ffmpeg в PATH** (рекомендуется) — исходящий TTS преобразуется и поступает в виде правильной голосовой заметки. Установить:
  - Окна: `winget install Gyan.FFmpeg`
  - macOS: `brew install ffmpeg`
  - Linux: менеджер пакетов
- **Без ffmpeg** — исходящий TTS поступает в виде аудиовложения в формате MP3. Воспроизводится нормально, просто не похоже на голосовую заметку. В журнале шлюза срабатывает одноразовое предупреждение, чтобы вы знали.

Вы можете проверить, нашел ли шлюз ffmpeg через конечную точку работоспособности:

```bash
curl http://localhost:8090/health
# look for "ffmpeg_present": true
```

## Известные ограничения

### 24-часовое окно разговора

Meta допускает отправку **сообщений в свободной форме** только в течение 24 часов после последнего входящего сообщения пользователя. За пределами этого окна единственное, что принимает API Meta, — это предварительно одобренный **шаблон сообщения**.

**Что это означает на практике:**

- Реактивный чат (личные сообщения пользователя → ответы бота в течение 24 часов → ответы пользователей → ...) работает вечно. Это охватывает >95% обычного использования ботов.
- **Задания Cron, которые доставляются в WhatsApp** после перерыва > 24 часов, завершаются сбоем с кодом ошибки Graph `131047` («Сообщение о повторном взаимодействии»).
- **Длительные асинхронные результаты `delegate_task`**, которые занимают более 24 часов, завершаются таким же образом.
- **Подписчики вебхука**, которые перенаправляют внешние события в WhatsApp, терпят неудачу, если пользователь недавно не отправлял DM боту.

Hermes предупреждает агента об этом окне в системной подсказке, чтобы модель знала, что нужно упомянуть об этом при планировании отложенных сообщений.

Поддержка шаблонов сообщений (обходной путь отправки из внешнего окна) еще не реализована в Hermes. Если вам это нужно, пожалуйста, [откройте вопрос](https://github.com/NousResearch/hermes-agent/issues) — это запланировано, но ожидается четкий сигнал спроса.

### Групповые чаты

Cloud API имеет ограниченную групповую поддержку (уровень возможностей, контролируемый Meta).  Адаптер Hermes `whatsapp_cloud` в настоящее время обрабатывает **только прямые сообщения** в версии 1.  Если вам нужны групповые чаты, используйте мост Бейлис.

### Ограничение исходящей скорости

Пропускная способность Meta по умолчанию составляет **80 сообщений в секунду на номер рабочего телефона**, доступны обновления.  Hermes в настоящее время не обеспечивает соблюдение этого требования на стороне клиента — отправка очень большого объема может достичь предела Meta.

## Поиск неисправностей

### Проверка установки не удалась («URL-адрес не может быть проверен») на мета-панели.

Почти всегда одно из:

- **URL-адрес туннеля неправильный или устаревший** — быстрые туннели с облачным расширением меняются.  Получите новый URL-адрес и обновите `.env` и панель управления Meta.
- **Проверьте несоответствие токена** — токен в `WHATSAPP_CLOUD_VERIFY_TOKEN` `~/.hermes/.env` должен точно соответствовать тому, что вы ввели на панели управления Meta.  Запустите тест скручивания, описанный выше, чтобы убедиться, что подтверждение подтверждения шлюза сначала работает локально.
- **Шлюз не работает** — проверьте, что `hermes gateway` работает.
- **Секрет приложения не установлен** — без него Hermes отклоняет входящие POST-запросы с кодом 503. Мета интерпретирует это как «невозможно проверить».

### `graph error 100`: Объект с идентификатором '...' не существует

Вы вставили свой номер телефона (10–11 цифр) в `WHATSAPP_CLOUD_PHONE_NUMBER_ID` вместо идентификатора номера телефона (15–17-значный внутренний идентификатор Meta).  Еще раз проверьте страницу настройки API — идентификатор номера телефона отображается *ниже* раскрывающегося списка «От».

Мастер теперь улавливает это с помощью валидатора, но об этом стоит знать, если вы настраиваете вручную.

### `graph error 190`: Ошибка аутентификации

Ваш токен доступа недействителен.  Субкоды:

- `subcode 463` — срок действия токена истек.  Временные токены действуют 24 часа.  Восстановите или переключитесь на постоянный токен системного пользователя (см. выше).
- `subcode 467` — токен недействителен (отозван или пароль изменен).
- Другое 190 — токен не имел необходимых разрешений при создании.  Убедитесь, что выбраны все три (`business_management`, `whatsapp_business_messaging`, `whatsapp_business_management`).

### `graph error 131047`: Сообщение о повторном взаимодействии

Срок действия 24-часового окна беседы истек (см. «Известные ограничения»).  Либо:

– Попросите пользователя сначала отправить сообщение боту, чтобы снова открыть окно.
- Подождите, пока поддержка шаблонов появится в Hermes.

### Входящее сообщение: `media metadata fetch failed (status=401)`

Те же основные причины ошибки 401, что и для исходящего трафика (`graph error 190`) — токен доступа недействителен или срок его действия истек.  Исправьте токен.

### Ответы ботов отображаются в виде необработанного JSON или утечки вызовов инструментов

Общая причина: в наборе инструментов, настроенном для `whatsapp_cloud`, отсутствуют инструменты, которые агент хочет вызвать.  Проверьте `hermes tools list` и убедитесь, что платформа использует `hermes-whatsapp` (набор инструментов облачного адаптера по умолчанию, такой же, как у Baileys).

Если модель выдает текст в форме вызова инструмента вместо структурированного вызова, это обычно означает, что набор инструментов фактически пуст.  См. `hermes_cli/platforms.py` для сопоставления платформы → набора инструментов по умолчанию.

### STT (транскрипция голосовой заметки) возвращает пустой ответ/"не удалось расшифровать"

Для `stt.provider: local` по умолчанию требуется `pip install faster-whisper`.  Если вы являетесь подписчиком Nous, вместо этого вы можете маршрутизировать STT через управляемый шлюз — выберите **Nous Subscription** для преобразования речи в текст в `hermes tools` или установите его напрямую:

```bash
hermes config set stt.provider nous
hermes gateway restart
```

При этом используется ваш токен доступа к Nous Portal вместо отдельного ключа OpenAI. (В более старых документах предлагалось `stt.use_gateway true` — этот флаг является устаревшим; теперь маршрутизацию контролирует только выбор провайдера.)

## Примечания по безопасности

- **Относитесь к секрету приложения как к паролю** — любой, кто обладает им, может подделать полезные данные веб-перехватчика, которые Hermes примет как подлинные.
- **Токен проверки является общим секретом** — утечки менее значимы (в худшем случае кто-то может повторно подписаться на веб-перехватчик Meta на другой свой URL-адрес), но все равно избегайте их совершения.
- **Токен доступа – это идентификатор вашего бота**. Токены пользователей системы эквивалентны долгоживущим ключам API.  Немедленно произведите ротацию, если развертывание будет скомпрометировано.
- **Конечная точка веб-перехватчика принимает только подписанные запросы, если установлен `WHATSAPP_CLOUD_APP_SECRET`** — оставьте его установленным даже в стадии разработки.  Без него шлюз отклоняет входящую доставку по протоколу HTTP 503.
- **Конечная точка `/health` не аутентифицирована** — ее безопасно раскрывать, поскольку она сообщает только логические значения присутствия конфигурации, а не сами значения.  Но если вы не хотите раскрывать это, ограничьте доступ на уровне обратного прокси/туннеля.

## Сравнение с мостом Бейлис

| | Бейлис (`hermes whatsapp`) | Облачный API (`hermes whatsapp-cloud`) |
|---|---|---|
| Тип счета | Персональный | Бизнес |
| Настройка | Сканирование QR-кода | Мета-приложение + WABA + токен |
| Зависимости | Node.js + npm | Чистый Python (httpx + aiohttp) |
| Процесс | Подпроцесс управляемого узла | сервер веб-перехватчиков aiohttp |
| Нужен общедоступный URL-адрес? | Нет | Да |
| Риск блокировки аккаунта | Да (неофициальный API) | Нет (официально поддерживается) |
| Входящие | Мост узла опроса | Вебхук POST из Meta |
| Исходящие | Местный мост → Бейлис | HTTPS для входа в Graph.facebook.com |
| Группы | Полная поддержка | Только DM (v1) |
| 24-часовое окно | Нет ограничений | Жесткое правило — шаблоны необходимы после |
| Голосовые заметки (выход) | Родной | Встроенная версия с ffmpeg, в противном случае резервный вариант MP3 |
| Читать квитанции | Нет | Да (двойные синие галочки) |
| Индикатор набора текста | Нет | Да (автоматически закрывается при ответе) |
| Интерактивные кнопки | Только резервный текст | Родной (уточнить, утвердить, косая черта-подтвердить) |
| Использование продукции | Рискованно (Мета может забанить) | Создан для этого |

Большинство пользователей, использующих Hermes для личных проектов, предпочитают Baileys. Большинство пользователей, использующих ботов для работы с клиентами, предпочитают Cloud API.
