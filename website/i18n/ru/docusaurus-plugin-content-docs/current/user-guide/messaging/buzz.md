# Обновление

Адаптер Buzz подключает Hermes к сообществу [Buzz](https://github.com/block/buzz) — платформе Block для совместной работы человека и агента с открытым исходным кодом, построенной на протоколе Nostr, — и передает сообщения между каналами Buzz (или DM) и агентом. Исходящий трафик передается в двоичный файл CLI `buzz` («входящий JSON, исходящий JSON»); входящий трафик использует собственную подписку Nostr WebSocket (через уже включенный пакет `websockets`) с опросом CLI в качестве резервного варианта. **Дополнительных пакетов Python не требуется** — только двоичный файл `buzz`.

Buzz отображает уценку, поэтому ответы агентов сохраняют свое форматирование. Изображения доставляются в виде загрузок (локальные файлы) или ссылок (URL-адреса). Ответы могут быть связаны с существующим сообщением через его идентификатор события.

Входящие сообщения поступают по постоянной подписке Nostr WebSocket с проверкой подлинности NIP-42 по умолчанию (почти мгновенная доставка) с автоматическим возвратом к опросу CLI, если WebSocket не может быть установлен. Исходящие сообщения всегда проходят через интерфейс командной строки `buzz`. Управляйте им с помощью `transport` / `BUZZ_TRANSPORT`: `auto` (по умолчанию), `websocket` (требуется WS, в противном случае произойдет сбой) или `poll`. Если ваше членство в ретрансляторе использует аттестацию владельца NIP-OA, установите для `BUZZ_AUTH_TAG` четырехстрочный тег аутентификации JSON.

> Запустите `hermes gateway setup` и выберите **Buzz** для пошагового руководства.

## Предварительные условия

– Бинарный файл CLI `buzz` на вашем `PATH` (или укажите на него `BUZZ_CLI_PATH`) — создайте его из [репозитория Buzz](https://github.com/block/buzz) с помощью `cargo build --release -p buzz-cli`.
– URL-адрес ретранслятора сообщества Живой ленты (например, `https://mycommunity.communities.buzz.xyz`).
- Закрытый ключ Nostr (nsec или шестнадцатеричный), личность которого уже является **членом** этого сообщества.

## Настройка Гермеса

Вы можете настроить Buzz двумя способами — с помощью блока `gateway` в `config.yaml` (канонический) или с помощью переменных среды (которые переопределяют его). Закрытый ключ является **секретным** и всегда принадлежит `~/.hermes/.env`.

### Вариант А — config.yaml

```yaml
gateway:
  platforms:
    buzz:
      enabled: true
      extra:
        relay_url: https://mycommunity.communities.buzz.xyz
        channels:                  # channel UUIDs to watch (empty = all joined)
          - ccc2bc1a-7a82-5a8f-8c4e-57a070cbe7cd
        home_channel: ccc2bc1a-7a82-5a8f-8c4e-57a070cbe7cd
        poll_interval: 4           # seconds between inbound poll sweeps
        cli_path: ""               # buzz binary (default: PATH, then ~/bin/buzz)
        credentials_file: ""       # JSON file with the nsec (BUZZ_PRIVATE_KEY fallback)
        allowed_users: []          # empty = allow all; hex pubkeys or npubs
```

Плюс в `~/.hermes/.env`:

```
BUZZ_PRIVATE_KEY=nsec1...
```

### Вариант Б — переменные среды

| Переменная | Требуется | Описание |
|----------|:--------:|-------------|
| `BUZZ_RELAY_URL` | ✅ | Базовый URL-адрес ретранслятора сообщества |
| `BUZZ_PRIVATE_KEY` | ✅ | Закрытый ключ Nostr (nsec или hex) — единственный секрет |
| `BUZZ_CHANNELS` | — | UUID каналов, разделенных запятыми, для просмотра (по умолчанию: все присоединенные каналы) |
| `BUZZ_HOME_CHANNEL` | — | UUID канала для cron/доставки уведомлений (по умолчанию первый просматриваемый канал) |
| `BUZZ_ALLOWED_USERS` | — | Разделенные запятыми npub или шестнадцатеричные pubkeys разрешены для общения с агентом |
| `BUZZ_ALLOW_ALL_USERS` | — | Разрешить любому участнику сообщества разговаривать с агентом |
| `BUZZ_POLL_INTERVAL` | — | Секунды между входящими опросами (по умолчанию: 4) |
| `BUZZ_CLI_PATH` | — | Путь к двоичному файлу `buzz` (по умолчанию: `buzz` в PATH, затем `~/bin/buzz`) |
| `BUZZ_CREDENTIALS_FILE` | — | Файл учетных данных JSON, содержащий nsec, используемый, когда `BUZZ_PRIVATE_KEY` не установлен |

## Рекомендуемые настройки по умолчанию

При подключении Buzz установите эти значения по умолчанию в `config.yaml`, чтобы поддерживать чистоту канала и сосредоточить внимание агента на конечных результатах, а не на журнале выполнения внутреннего инструмента. Они соответствуют поведению в Telegram и электронной почте, которые уже подавляют вывод промежуточных инструментов.

```yaml
display:
  platforms:
    buzz:
      interim_assistant_messages: false   # suppress intermediate tool results, reasoning comments, and progress updates — only the final response reaches the channel
      tool_progress: off                  # suppress tool progress bubbles (e.g., "Running terminal command...", "Reading file...")
gateway:
  platforms:
    buzz:
      enabled: true
      extra:
        relay_url: https://mycommunity.communities.buzz.xyz
        channels:                         # channel UUIDs to watch (empty = all joined)
          - ccc2bc1a-7a82-5a8f-8c4e-57a070cbe7cd
        home_channel: ccc2bc1a-7a82-5a8f-8c4e-57a070cbe7cd
        poll_interval: 4                  # seconds between inbound poll sweeps (default 4 — balances latency vs. relay load)
        cli_path: ""                      # buzz binary (default: PATH, then ~/bin/buzz)
        credentials_file: ""              # JSON file with the nsec (BUZZ_PRIVATE_KEY fallback)
        allowed_users: []                 # empty = allow all if allow_all_users is true; otherwise restrict to listed npubs/hex pubkeys
        require_mention: true             # in channels: only respond when addressed (@name, npub, or hex pubkey); DMs always dispatch regardless
        allow_all_users: false            # set true for community mode (everyone can chat, only owner is admin); false for private mode (only allowed_users)
```

**Почему эти значения по умолчанию:**

- `interim_assistant_messages: false` — предотвращает публикацию промежуточных результатов инструмента, поясняющих комментариев и обновлений хода выполнения в виде отдельных сообщений на канале. На канал поступает только окончательный ответ.
- `tool_progress: off` — подавляет всплывающие сообщения о ходе работы инструмента (например, «Выполнение команды терминала...», «Чтение файла...»). Позволяет каналу сосредоточиться на реальных результатах, а не на процессе.
- `poll_interval: 4` — балансирует задержку входящего сообщения (задержка до 4 с) и нагрузку на реле. Более низкие значения увеличивают частоту опроса; более высокие значения уменьшают его.
- `allowed_users: []` + `allow_all_users: false` — приватный режим по умолчанию. Взаимодействовать могут только зарегистрированные пользователи. Установите `allow_all_users: true` для режима сообщества, в котором каждый может общаться (уровень администратора по-прежнему ограничен владельцем).
- `require_mention: true` — в каналах агент отвечает только при обращении. DM всегда отправляют сообщения независимо от этого параметра.

**Обоснование.** Каналы предназначены для окончательных результатов и разговоров, а не для внутреннего журнала выполнения инструментов агента. Пользователи видят окончательный ответ, а не шаги, предпринятые для его достижения. Это соответствует поведению в Telegram и электронной почте, у которых уже есть эти настройки по умолчанию.

**Исключение:** Если вы хотите, чтобы пользователи видели ход работы инструмента (например, при длительных операциях), установите `tool_progress: all`, но `interim_assistant_messages` по-прежнему должно быть `false`, чтобы избежать спама при каждом результате работы инструмента.

## Упоминания, каналы и личные сообщения

- В общих каналах агент отвечает только при **адресации** — по `@name`, его npub или шестнадцатеричному публичному ключу. Все остальное игнорируется.
- Прямые сообщения всегда доходят до агента, упоминание не требуется.
- Собственные сообщения агента никогда не отправляются обратно ему (подавление самоэха с помощью публичного ключа), и каждое событие дедуплицируется по идентификатору события по верхней отметке для каждого канала.

## Контроль доступа

По умолчанию список разрешенных пуст, что означает, что каждый участник сообщества, упоминающий агента, получит ответ только в том случае, если `BUZZ_ALLOW_ALL_USERS=true`; в противном случае ограничьте доступ, указав npub или шестнадцатеричные публичные ключи в `BUZZ_ALLOWED_USERS` (или `allowed_users` в config.yaml). Членство в сообществе само по себе обеспечивается ретранслятором — только участники могут публиковать сообщения.

Задания и уведомления Cron (`deliver=buzz`) доставляются на **домашний канал** — `BUZZ_HOME_CHANNEL`, если он установлен, в противном случае — на первый просматриваемый канал — и работают, даже когда cron запускается вне процесса шлюза.

## Запускаем шлюз

```bash
hermes gateway start
```

Проверьте статус с помощью `hermes gateway status` — здесь сообщается о состоянии подключения Buzz, в том числе для настроек только для env.

## Примечания и ограничения

- **Входящие данные опрашиваются, а не передаются в потоковом режиме.** `buzz` CLI представляет собой запрос/ответ, поэтому адаптер опрашивает `buzz messages get` для каждого просматриваемого канала каждые `poll_interval` секунд (по умолчанию 4). Ожидайте до одного интервала задержки для входящих сообщений. Будущая оптимизация — это транспорт через веб-сокеты (репозиторий Buzz содержит `buzz-ws-client` для настоящей потоковой передачи).
- При (повторном) подключении адаптера устанавливается его верхняя отметка из новейших событий, поэтому история канала никогда не воспроизводится в агенте.
- Новые разговоры в DM обнаруживаются автоматически (каждые несколько опросов).
— Закрытый ключ передается в CLI через среду подпроцесса — он никогда не появляется в argv или журналах.
