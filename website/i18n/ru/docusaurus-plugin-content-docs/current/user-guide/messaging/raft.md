# Настройка плота

Гермес подключается к [Raft](https://raft.build) в качестве внешнего агента через локальный мост пробуждающего канала. Адаптер запускает конечную точку HTTP с обратной связью, которая получает от моста подсказки пробуждения без содержания, а затем вводит их в конвейер сеанса шлюза Hermes. Агент читает и отправляет сообщения через Raft CLI — адаптер никогда не трогает тела сообщений или курсоры доставки.

:::информация Разделение труда
- **Мост** управляет: потреблением подсказок по пробуждению, дедупликацией, отсрочкой, повторным подключением, хотя бы однократной доставкой и проверочным журналированием.
- **Адаптер Hermes** владеет: конечной точкой пробуждения локального хоста и внедрением короткого уведомления в контекст агента.
- **Агенту** принадлежат: получение сообщений (`raft message check`), ответ (`raft message send`) и все другие взаимодействия Raft через интерфейс командной строки.

Адаптер не содержит учетных данных Raft — только общий токен для каждого сеанса для аутентификации на локальном хосте между мостом и конечной точкой.
:::

---

## Предварительные условия

- **Рабочее пространство Raft**, где вы можете создать внешнего агента.
- **Raft CLI** установлен и выполнен вход в этот профиль внешнего агента.
- **aiohttp** — пакет Python (включён в дополнительные материалы Hermes `[all]`)

В Raft откройте меню «Агенты», создайте внешнего агента и следуйте карточке настройки, чтобы установить Raft CLI и войти в профиль агента. После создания агента Raft показывает руководство по настройке Hermes с переменными среды и конфигурацией, необходимой для запуска шлюза.

---

## Настройка

Добавьте в `~/.hermes/.env`:

```bash
RAFT_PROFILE=your-agent-profile
```

Вот и все — адаптер автоматически включается, когда установлен `RAFT_PROFILE`. Он генерирует токен моста для каждого сеанса, выбирает временный порт и автоматически запускает дочерний процесс моста при запуске шлюза.

---

## Как это работает

```
Raft Server → Bridge (wake-hints SSE) → POST /wake → Hermes Adapter → Agent context
Agent → raft message check → Raft Server (message bodies)
Agent → raft message send → Raft Server (replies)
```

1. Сервер Raft отправляет подсказки пробуждения процессу моста через SSE.
2. Мост пересылает каждую подсказку в виде `POST /wake` в конечную точку обратной связи адаптера.
3. Адаптер проверяет токен моста, проверяет, что полезная нагрузка не содержит содержимого, и вводит уведомление о пробуждении в сеанс Hermes.
4. Агент видит уведомление о пробуждении и использует интерфейс командной строки Raft для чтения сообщений и ответа.

Полезные данные Wake **не содержат содержимого по контракту** — они содержат метаданные (идентификатор события, идентификатор сообщения, временные метки), но никогда не содержат тела сообщения, имена каналов или идентификаторы отправителя. Адаптер отклоняет любые полезные данные, содержащие поля с содержимым (`text`, `body`, `content`, `messages` и т. д.).

---

## Мост

Адаптер автоматически создает `raft agent bridge` как дочерний процесс, передавая URL-адрес конечной точки и токен. Мост подключается к серверу Raft, используя настроенный профиль, и начинает пересылку подсказок пробуждения. Он прекращается, когда шлюз отключается.
