# УБЛИТЕРАТУС Навык

## Что внутри

9 методов CLI, 28 модулей анализа, 116 предустановок моделей на 5 уровнях вычислений, оценка турниров и рекомендации на основе телеметрии.

Удалите отказное поведение (ограждения) из LLM с открытым весом без переподготовки или тонкой настройки. Использует методы механистической интерпретации, в том числе разницу в средних, SVD, отбеливание SVD, стирание концепции LEACE, разложение SAE, проекцию байесовского ядра и многое другое, чтобы идентифицировать и хирургическим путем исключить направления отказа из весов модели, сохраняя при этом возможности рассуждения.

**Предупреждение о лицензии:** OBLITERATUS — это AGPL-3.0. НИКОГДА не импортируйте его как библиотеку Python. Всегда вызывайте через CLI (команда `obliteratus`) или подпроцесс. Это сохраняет лицензию MIT агента Hermes в чистоте.

Запускается, когда пользователь:
- Хочет «снять цензуру» или «уничтожить» LLM.
- Спрашивает об удалении отказов/ограждений с модели.
- Хочет создать версию Llama, Qwen, Mistral и т. д. без цензуры.
- Упоминает «отказ от удаления», «аблитерацию», «проекцию веса».
- Хочет проанализировать, как работает механизм отказа модели
- Ссылки на OBLITERATUS, аблитератор или указания отказа.

## Шаг 4: выберите метод

### Руководство по выбору метода
**По умолчанию/рекомендуется для большинства случаев: `advanced`.** Он использует многонаправленное SVD с сохраняющей норму проекцией и хорошо протестирован.

| Ситуация | Рекомендуемый метод | Почему |
|:----------------------------------|:-------------------|:-----------------------------------------|
| По умолчанию/большинство моделей | `advanced` | СВД разнонаправленная, нормоустойчивая, надежная |
| Быстрое тестирование/прототипирование | `basic` | Быстро, просто, достаточно хорошо, чтобы оценить |
| Плотная модель (Лама, Мистраль) | `advanced` | Разнонаправленный, с соблюдением норм |
| Модель МО (DeepSeek, Mixtral) | `nuclear` | Экспертно-детализированный, справляется со сложностью MoE |
| Модель рассуждения (дистилляция R1) | `surgical` | Поддержка CoT, сохранение цепочки мыслей |
| Упорные отказы продолжаются | `aggressive` | Отбеленная СВД + операция на голове + побег из тюрьмы |
| Хотите обратимых изменений | Использовать направляющие векторы (см. раздел «Анализ») |
| Максимальное качество, время без возражений | `optimized` | Байесовский поиск лучших параметров |
| Экспериментальное автоматическое обнаружение | `informed` | Автоматически определяет тип выравнивания — экспериментальный, не всегда может превосходить расширенный |

### 9 методов CLI
- **basic** — однократное направление отказа через различные средства. Быстро (~5-10 минут для 8Б).
- **расширенный** (ПО УМОЛЧАНИЮ, РЕКОМЕНДУЕТСЯ) — несколько направлений SVD, проекция, сохраняющая норму, 2 прохода уточнения. Средняя скорость (~10-20 мин).
- **агрессивный** — Отбеленная СВД + джейлбрейк-контраст + операция на голове. Более высокий риск нарушения когерентности.
- **spectral_cascade** — разложение DCT в частотной области. Исследования/новаторский подход.
- **информирован** — анализ выполняется ВО ВРЕМЯ удаления для автоматической настройки. Экспериментальный — медленнее и менее предсказуемый, чем продвинутый.
- **хирургический** — особенности САЭ + маскирование нейронов + операция на голове + выбор эксперта. Очень медленно (~1-2 часа). Лучше всего подходит для моделей рассуждений.
- **оптимизирован** — байесовский поиск гиперпараметров (Optuna TPE). Самое продолжительное время работы, но находит оптимальные параметры.
- **inverted** — меняет направление отказа. Модель становится активно желающей.
- **ядерное** — комбинация максимальной силы для упрямых моделей МО. Экспертно-гранулированный.

### Методы извлечения направлений (флаг --direction-method)
- **diff_means** (по умолчанию) — простая разница в средних значениях между отклоненными и выполненными активациями. Крепкий.
- **svd** — Многонаправленное извлечение СВД. Лучше для сложного выравнивания.
- **leace** — LEACE (линейное стирание посредством оценки в закрытой форме). Оптимальное линейное стирание.

### 4 метода только для Python-API
(НЕдоступно через CLI — требуется импорт Python, что нарушает границы AGPL. Упоминайте об этом пользователю, только если он явно хочет использовать OBLITERATUS в качестве библиотеки в своем собственном проекте AGPL.)
- фейлспай, габлитерация, еретик, рдо

## Шаг 5: Запустите аблитерацию

### Стандартное использование
```bash
# Default method (advanced) — recommended for most models
obliteratus obliterate <model_name> --method advanced --output-dir ./abliterated-models

# With 4-bit quantization (saves VRAM)
obliteratus obliterate <model_name> --method advanced --quantization 4bit --output-dir ./abliterated-models

# Large models (70B+) — conservative defaults
obliteratus obliterate <model_name> --method advanced --quantization 4bit --large-model --output-dir ./abliterated-models
```

### Точная настройка параметров
```bash
obliteratus obliterate <model_name> \
  --method advanced \
  --direction-method diff_means \
  --n-directions 4 \
  --refinement-passes 2 \
  --regularization 0.1 \
  --quantization 4bit \
  --output-dir ./abliterated-models \
  --contribute  # opt-in telemetry for community research
```

### Ключевые флаги
| Флаг | Описание | По умолчанию |
|:-----|:------------|:--------|
| `--method` | Метод аблитерации | продвинутый |
| `--direction-method` | Направление добычи | diff_means |
| `--n-directions` | Количество направлений отказа (1-32) | зависимый от метода |
| `--refinement-passes` | Итеративные проходы (1-5) | 2 |
| `--regularization` | Сила регуляризации (0,0-1,0) | 0,1 |
| `--quantization` | Загрузить в 4-битном или 8-битном формате | нет (полная точность) |
| `--large-model` | Консервативные значения по умолчанию для 120B+ | ложный |
| `--output-dir` | Где сохранить удаленную модель | ./уничтоженная_модель |
| `--contribute` | Поделитесь анонимными результатами исследований | ложный |
| `--verify-sample-size` | Количество тестовых запросов на проверку отказа | 20 |
| `--dtype` | Тип модели (float16, bfloat16) | авто |

### Другие режимы выполнения
```bash
# Interactive guided mode (hardware → model → preset)
obliteratus interactive

# Web UI (Gradio)
obliteratus ui --port 7860

# Run a full ablation study from YAML config
obliteratus run config.yaml --preset quick

# Tournament: pit all methods against each other
obliteratus tourney <model_name>
```

## Шаг 6: Проверка результатов

После аблитерации проверьте выходные метрики:

| Метрическая | Хорошее соотношение цены и качества | Предупреждение |
|:-------|:-----------|:--------|
| Уровень отказов | &lt; 5% (в идеале ~0%) | > 10% означает, что отказы продолжаются |
| Изменение недоумения | &lt; 10% увеличение | > 15% означает повреждение когерентности |
| КЛ дивергенция | &lt; 0,1 | > 0,5 означает значительный сдвиг распределения |
| Согласованность | Высокий / проходит качественную проверку | Униженные ответы, повторение |

### Если отказы сохраняются (> 10%)
1. Попробуйте метод `aggressive`.
2. Увеличьте `--n-directions` (например, 8 или 16).
3. Добавьте `--refinement-passes 3`
4. Попробуйте `--direction-method svd` вместо diff_means.

### Если согласованность нарушена (увеличение недоумения > 15%)
1. Уменьшите `--n-directions` (попробуйте 2)
2. Увеличьте `--regularization` (попробуйте 0,3).
3. Уменьшите `--refinement-passes` до 1.
4. Попробуйте метод `basic` (более щадящий).

## Стратегии абляции

## Распространенные ошибки

1. **Не используйте `informed` по умолчанию** — это экспериментальный вариант и медленнее. Используйте `advanced` для получения надежных результатов.
2. **Модели ниже ~1B плохо реагируют на аблитерацию** — их отказное поведение поверхностно и фрагментировано, что затрудняет извлечение чистого направления. Ожидайте частичных результатов (осталось 20-40% отказов). Модели 3B+ имеют более четкие инструкции по отказу и гораздо лучше реагируют (часто отказ 0% с `advanced`).
3. **`aggressive` может усугубить ситуацию** — на маленьких моделях это может нарушить согласованность и фактически увеличить процент отказов. Используйте его только в том случае, если `advanced` оставляет > 10% отказов на модели 3B+.
4. **Всегда проверяйте степень недоумения** — если она превышает 15 %, модель повреждена. Уменьшите агрессивность.
5. **Модели MoE требуют особого обращения** — используйте метод `nuclear` для Mixtral, DeepSeek-MoE и т. д.
6. **Квантованные модели не могут быть повторно квантованы** — удалите модель полной точности, а затем квантовайте выходные данные.
7. **Оценка видеопамяти приблизительная** — 4-битный квант помогает, но пиковое использование может резко возрасти во время извлечения.
8. **Модели рассуждения чувствительны** — используйте `surgical` для дистиллятов R1, чтобы сохранить цепочку мыслей.
9. **Отметьте `obliteratus recommend`** — данные телеметрии могут иметь лучшие параметры, чем значения по умолчанию.
10. **Лицензия AGPL** — никогда не используйте `import obliteratus` в проектах MIT/Apache. Только вызов CLI.
11. **Большие модели (70B+)** — всегда используйте флаг `--large-model` для консервативных значений по умолчанию.
12. **Спектральная сертификация RED распространена** — спектральная проверка часто помечается как «неполная», даже если практический процент отказов составляет 0%. Проверьте фактическое количество отказов, а не полагайтесь только на спектральную сертификацию.
