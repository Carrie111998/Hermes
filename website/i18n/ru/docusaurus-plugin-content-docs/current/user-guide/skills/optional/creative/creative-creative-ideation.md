# Креативная идея

Библиотека методов формирования идей для любой области. Прочтите ситуацию пользователя, найдите соответствующий метод, примените и сгенерируйте конкретные и неочевидные результаты. Методы — это инструменты: выбирайте тот, который подходит к ситуации, а не применяйте их все.

## Когда использовать

Любой открытый порождающий или выборочный вопрос: «Я хочу что-то сделать/построить/написать/начать», «Я застрял», «вдохновить меня», «сделать это еще страннее», «помогите мне выбрать», «Мне нужно изобрести X», «дайте мне исследовательский вопрос».

## Правила эксплуатации

1. **Ограничение плюс направление — это творчество.** Нет ограничений = нет тяги. Нет направления = нет формы. Методы обеспечивают и то, и другое.
2. **Откажитесь от первых трёх идей.** Это отстой. Генерировать, отбросить, возродить. См. `references/anti-slop.md`.
3. **Один метод на каждый ответ, если вас об этом не спросят.** Не суммируйте.
4. **Специфика над абстракцией.** Реальные имена собственные, реальные материалы, реальные механизмы. «Приложение для X» — это отстой; «200-строчный инструмент CLI, который печатает Y, когда Z» — это направление. Именование стека технологий — это не специфика — назовите механизм.
5. **Странное должно быть также хорошо.** Целью является разрушение рамок, но странная идея, не имеющая реальной ситуации, механизма или причины для существования, сама по себе является формой неудачи. Каждый набор идей должен включать в себя хотя бы одну, которую действительно *можно реализовать/реализовать уже сейчас* — неочевидную, но обоснованную, с реальным первым шагом. Не меняйте всю полезность на сюрприз.
6. **Назовите метод, который вы использовали, и кто его изобрел.** Атрибуция требует дисциплины.
7. **Когда пользователь выберет один, создайте его.** Не продолжайте создавать после того, как он выбрал.

## Маршрутизация — 4-этапная процедура

Сделайте это *перед* созданием любого вывода. Сбои маршрутизации приводят к сбоям.

Вы можете пропустить описание шагов маршрутизации, если это будет понятнее, но **никогда не сжимайте за счет глубины каждой идеи**: конкретный механизм каждой идеи, ситуационная привязка и честный режим отказа — вот что делает результаты хорошими (измеренными) — они не являются каркасом, не сокращайте их.

### Шаг 1 — Извлеките три сигнала из подсказки

### Шаг 2. Примените переопределения (наивысший приоритет, сначала активируйте)

Правила переопределения превосходят таблицу маршрутизации:

- **Сигнал настроения** — пользователь говорит «странно», «странно», «удивительно», «менее очевидно», «более интересно» → `references/methods/lateral-provocations.md` или `references/methods/pataphysics.md`, независимо от домена.
- **Пользователь называет метод** — используйте его.
- **Пользователь запрашивает рекомендацию метода** («какой метод») → предложите 2–3 кандидата, написав по одной строке каждый, и спросите, какой метод применить. Не делайте молчаливых дефолтов.
- **Высокая местность** — «Идеи искусственного интеллекта», «Идеи для стартапов», «Отслеживание привычек», «Приложение для продуктивности/здоровья/фитнеса/еды/путешествий» → заставьте `references/methods/lateral-provocations.md` или `references/methods/pataphysics.md` использовать очевидный метод. Откажитесь от первых **5** идей, а не от 3.

### Шаг 4. Устраните двусмысленность и противоречия

- **Возможно несколько путей** → выберите тот, который ближе всего соответствует фактической формулировке пользователя. Не выбирайте самый интересный метод, чтобы показаться сложным.
- **Действительно двусмысленно** → задайте ОДИН уточняющий вопрос, а не гадайте молча. Примеры: *"Вы генерируете идеи или выбираете между теми, которые у вас есть?"* / *"Это для художественной литературы, эссе или чего-то еще?"*
– **Сигналы противоречат** (например, «странные идеи стартапа» → предметная область продукта + странное настроение) → **явно объединяйте два метода**. Расскажите, что вы делаете: *"Используйте `jobs-to-be-done` для обрамления продукта + `lateral-provocations`, чтобы нарушить очевидную форму."*
- **Нет совпадения** → отправка ограничения (`references/full-prompt-library.md`) является безопасным запасным вариантом.
- **Снова задан тот же вопрос** → переключите методы. Разница в методе = разница в распространении идей.

### Проверка по умолчанию (выполняется перед генерацией)

— Собираетесь написать «Вот 5 идей:» или голый нумерованный список? → СТОП. Сначала выберите метод.
- Собираетесь по умолчанию использовать общий мозговой штурм в режиме LLM? → СТОП. Выберите путь выше.
- Результаты выглядят так, как если бы LLM не работал без маршрутизации? → маршрутизация не удалась, повторите.

Режим LLM по умолчанию — это именно то, для чего существует этот навык. Если вы генерируете без маршрутизации, вы победили навык.

Более глубокие пограничные случаи (сигналы настроения, суммирование, антипаттерны) см. в `references/heuristics.md`.

## Формат вывода

Для пути по умолчанию для отправки ограничений:

```
## Constraint: [Name] — from [Source]
> [The constraint, one sentence]

### Ideas

1. **[One-line pitch]**
   [2-3 sentences — what specifically is made, why it's interesting]
   ⏱ [weekend/week/month]  •  🔧 [stack/medium/materials]

2. ...
3. ...
```

Для других методов используйте формат, указанный в методе (ТРИЗ производит анализ противоречий; OuLiPo выдает ограниченный текст; Oblique Strategies выдает одну примененную карту → следующий ход). Не принудительно помещайте каждый метод в шаблон ограничений.

**Каждый набор идей, независимо от метода:**
- Назовите использованный метод. На слякотной местности назовите очевидные идеи, от которых вы отказались.
- Дайте каждой идее конкретный механизм и ее честный способ отказа/компромисс/для кого она предназначена. Именно эта глубина делает идеи приземленными — размеренными, а не декоративными.
- Отметьте хотя бы одну идею как **обоснованную** — реализуемую/реализуемую уже сейчас, неочевидную, но с реальным первым шагом. Остальные могут бежать дальше навстречу странному; это должно быть действительно выполнимо. Не позволяйте всему набору быть странным, но непрактичным.

## Карта файлов

- `references/full-prompt-library.md` — библиотека ограничений, разбитая по доменам (Общие, Программное обеспечение, Физические, Социальные, Списки). Путь по умолчанию для SPECIFICITY=NONE.

- `references/anti-slop.md` — антиотстойные правила; применить к каждому выводу
- `references/exercises.md` — упражнения с ограничением по времени (5 минут/30 минут/1 час/день/неделя)
