# Навык Unreal Engine MCP

Сопутствующий навык для записи `unreal-engine` в каталоге Hermes MCP.
Сервер MCP (официальный экспериментальный плагин Epic «Unreal MCP», внутренний идентификатор
`ModelContextProtocol`) запускает ВНУТРИ процесса Unreal Editor и предоставляет
функциональность редактора как печатных инструментов. Этот навык учит, как хорошо на нем водить:
обнаружение рабочей поверхности инструмента, безопасная последовательность вызовов, перевод
простой английский спрашивает о сценах, которые действительно выглядят хорошо, и проверяет работу
визуально. Пользователю никогда не придется прикасаться к редактору, кроме его запуска.

## Когда использовать

Используйте, когда пользователь хочет что-то сделать в Unreal Engine: построить или одеть
уровень, создавать/перемещать/удалять актеров, настраивать освещение и атмосферу, создавать или
настраивать экземпляры материала, кадрировать снимок камеры, делать снимки экрана или рендеры,
импортируйте ресурсы, проверяйте сцену или пользовательский интерфейс, запускайте тесты автоматизации или создайте скрипты
редактор. Работает для одиночных действий («сделать солнечный час золотым») и для
выполнять многоэтапные проекты («построй мне угрюмую лесную полянку с
у костра и сфотографировать его»).

Не используйте для: моделирования/скульптинга сетки в стиле DCC (модель в Blender и
импортировать результат) или для редактирования исходного кода проекта Unreal C++ (это нормально
работа с кодом — используйте терминал; этот навык касается живого редактора).

## Предварительные условия

Две половинки в таком порядке: сторона редактора должна быть поднята до подключения Гермеса.

### Одноразовый, на стороне редактора

1. Unreal Editor **5.8+** с открытым проектом. (macOS: полный Xcode должен быть
   установлен и его лицензия принята — редактор закрывается при первом запуске
   без этого; увидеть подводные камни.)
2. **Правка > Плагины** — включите **Unreal MCP** (его реестр набора инструментов).
   автоматическое включение зависимостей). Перезапустите редактор при появлении запроса.
3. Типизированные наборы инструментов поставляются отдельно от сервера: также включите
   Плагин **AllToolsets** в том же браузере плагинов. Unreal MCP поставляется НЕТ
   сами инструменты — AllToolsets предоставляет поставляемые наборы инструментов (SceneTools,
   ActorTools, MaterialInstanceTools, ObjectTools,…); пропусти это и
   сервер подключается, но агенту не к чему позвонить.
4. **Редактировать > Настройки редактора > Общие > Протокол контекста модели** — включить.
   **Автозапуск сервера**. Привязка по умолчанию: `http://127.0.0.1:8000/mcp`.
   (порт/путь настраивается на той же панели; имя сервера — `unreal-mcp`).
   Чтобы запустить вручную, запустите `ModelContextProtocol.StartServer` в
   консоль редактора (клавиша обратной галочки).

### Одноразовый, сторона Гермеса

    Hermes McP устанавливает Unreal Engine

При этом будет записана HTTP-запись `mcp_servers.unreal-engine`, указывающая на
`http://127.0.0.1:8000/mcp` и проверяет работающий сервер на наличие его инструментов. Запусти это
пока редактор + сервер работают, чтобы зонд видел реальную поверхность. Если
пользователь изменил порт/путь в настройках редактора, отредактируйте `url` в
`~/.hermes/config.yaml` под `mcp_servers.unreal-engine` для соответствия.

НЕ используйте `ModelContextProtocol.GenerateClientConfig` для Hermes — это
записывает файлы в стиле `.mcp.json` для Claude Code/Cursor/etc. Гермес соединяет
с `config.yaml` через запись в каталоге.

### Каждый сеанс

1. Запустите Unreal Editor, дождитесь завершения загрузки проекта; подтвердить
   сервер запущен (Журнал вывода показывает адрес привязки или запустите
   `ModelContextProtocol.StartServer` вручную).
2. Запустите сеанс Гермеса. Инструменты регистрируются как `mcp_unreal_engine_*`. Если
   их нет: редактор не был запущен первым — запустите его, затем откройте новый
   Сеанс Гермеса.
3. Проверка работоспособности: позвоните по номеру `mcp_unreal_engine_list_toolsets` и подтвердите наборы инструментов.
   вернись.

## Панель инструментов: обнаружение, а не фиксированный список

По умолчанию плагин работает в **режиме поиска инструментов**: `tools/list` возвращает только
три мета-инструмента, и каждый настоящий инструмент доступен через них. Через Гермеса
они появляются как:

| Инструмент Гермес | Цель |
|---|---|
| `mcp_unreal_engine_list_toolsets` | Названия и описания каждого зарегистрированного набора инструментов |
| `mcp_unreal_engine_describe_toolset` | Полные схемы JSON для инструментов одного именованного набора инструментов |
| `mcp_unreal_engine_call_tool` | Вызов именованного инструмента с аргументами, получение результата |

Открытие, всегда в следующем порядке:

1. `list_toolsets` → посмотрите, какие группы возможностей на самом деле есть в этом проекте.
   (поверхность зависит от проекта: включенные плагины, плагины игровых функций,
   и любые пользовательские наборы инструментов вносят свой вклад). Имена возвращаются ПОЛНОСТЬЮ КВАЛИФИЦИРОВАННЫМИ
   (`editor_toolset.toolsets.scene.SceneTools`,
   `EditorToolset.EditorAppToolset`) — используйте их дословно как `toolset_name`.
2. `describe_toolset` на нужной вам группе → читаем реальный параметр
   схемы. Никогда не угадывайте имена параметров — схемы — это контракт.
3. `call_tool` с полным именем набора инструментов, КРАТКИМ именем инструмента.
   (`find_actors`, а не в форме с точками) и аргументы, соответствующие схеме.

Кэшируйте то, что вы узнаете для сеанса; повторный список только после стороны редактора
изменения (включен новый плагин, создан набор инструментов, запущен `RefreshTools`).

Альтернативный режим нетерпеливости (`Enable Tool Search` отключен в настройках редактора)
рекламирует каждый инструмент как отдельную запись `mcp_unreal_engine_<tool>`. Открытие
затем вместо этого происходит в `hermes mcp install`/`configure` время. Инструмент-поиск
режим является значением по умолчанию и что предполагает этот навык; он также хранит токены схемы
из каждого вызова API, поэтому предпочитайте его.

См. `references/tool-surface.md` поставляемый каталог набора инструментов.
пользовательские наборы инструментов и полный справочник по настройке плагинов и консольным командам.

## Рабочий цикл

Каждая задача Unreal следует одному и тому же циклу:

1. **Сначала проверьте.** Перечислите наборы инструментов, затем запросите состояние сцены/уровня, прежде чем
   касаясь чего-либо. Никогда не принимайте пустой уровень или уровень по умолчанию. В
   незнакомый проект, также проверьте зарегистрированные в проекте навыки агента
   (`call_tool` → `AgentSkillToolset.ListSkills`): соответствующий навык проекта
   инструкции переопределяют общие настройки этого навыка по умолчанию.
2. **Действуйте небольшими одноцелевыми вызовами.** Один логический шаг на `call_tool`.
   Сервер выполняет инструменты **последовательно в игровом потоке** — большая
   монолитная операция замораживает пользовательский интерфейс редактора до его завершения и рискует
   таймауты клиента. Исключение: для циклов более 5 однородных операций,
   ОДИН `ProgrammaticToolset.execute_tool_script` вызывает их в пакетном режиме
   на стороне сервера без нарушения последовательного правила
   (`references/advanced-workflows.md`).
3. **НИКОГДА не отправляйте перекрывающиеся вызовы.** Не группируйте несколько вызовов.
   `mcp_unreal_engine_*` звонит за один ход — Hermes выполняет пакетные звонки
   одновременно и параллельные вызовы против взаимоблокировки игрового потока или
   провалиться. Строго один звонок, ожидание результата, следующий звонок. Это отменяет
   общее руководство по вызову параллельных инструментов.
4. **Прочитайте каждый результат.** Множество инструментов (компиляция чертежей, редактирование материалов,
   создание виджета) сообщать об успехе/неуспехе в теле ответа без каких-либо
   исключение уровня протокола. Все, что не является явным успехом, является
   остановись и диагностируй, а не пожимай плечами. После записи свойства прочитайте значение
   назад — несколько путей записи молча и без операций (см. подводные камни).
5. **Проверьте визуально и структурно.** После каждого этапа подтвердите состояние.
   путем запроса актеров/свойств, которые вы изменили, и захвата области просмотра
   снимок экрана, когда композиция имеет значение (см. `references/tool-surface.md` для
   варианты захвата; `vision_analyze` образ — ты и есть искусство
   режиссер, судите сами).
6. **Часто сохраняйте.** Изменения редактора сохраняются в памяти до тех пор, пока не будут готовы пакеты/уровни.
   сохранен; при сбое редактора теряется все, что было с момента последнего сохранения, и MCP
   изменения не могут быть полностью отменены. Сохраняйте до И после любого массового изменения,
   и после каждого этапа.
7. **Сообщайте конкретно.** Ярлыки актеров, пути к активам (`/Game/...`), файл
   места захвата/рендеринга.

Правила мира во время работы:

- Единицы измерения: **сантиметры**; оси — **Z-вверх**, X-вперед; ротации
  градусов (Вращатель: вращение вокруг X, наклон вокруг Y, отклонение вокруг Z). Человеческий глаз
  рост ≈ 165 см; дверь ≈ 210×90 см. Полные таблицы в
  `references/scene-craft.md`.
– В путях к содержимому используются длинные имена пакетов: `/Game/Folder/Asset.Asset` для
  содержимое проекта, `/Engine/BasicShapes/Cube.Cube` для примитивов движка.
- **метки субъектов** (то, что вы видите в Outliner, настраиваемые, неуникальные)
  а не **имена** актеров (внутренние, уникальные). Предпочитайте разрешение актеров с помощью
  запросы метки/класса, а затем удерживайте любой дескриптор, возвращаемый инструментом.
- Предпочитайте физически правдоподобные значения освещенности (люкс/кандела/Кельвин)
  произвольные значения яркости, но СНАЧАЛА прочитайте существующие значения яркости Солнца.
  интенсивность изучения условий калибровки сцены; шаблонные миры
  часто калибруются около `intensity: 10`, и физические значения зашкаливают
  их (у `references/scene-craft.md` есть цифры,
  `references/pitfalls.md` #12b содержит правило калибровки).

## От простого английского к сцене

Пользователь выражает намерение, а не спецификации. Переведите, прежде чем строить:

1. **Извлечение брифа.** Тематика, настроение, время суток, интерьер/экстерьер,
   стиль, результат (скриншот? рендер? играбельный уровень?). Спроси максимум один
   раунд уточняющих вопросов, а затем фиксация — вы технический специалист
   директор; не передавайте пользователю жаргон Unreal.
2. **Спланируйте порядок сборки.** Рабочий порядок: уровень/оболочка среды →
   блокировка (основная геометрия/сетки на месте) → освещение + атмосфера →
   материалы → декорации/детали → камера → захват/рендер. Опубликовать план
   в качестве списка задач для многоэтапных сборок.
3. **Создавайте с использованием описанного выше цикла**, по одному этапу за раз, снимок экрана:
   каждая веха.
4. **Арт-директ самостоятельно.** Сравните каждый скриншот с кратким описанием:
   читаемый силуэт? правдоподобное направление/интенсивность света? горизонт нет
   мертвая точка? масштаб верен относительно человеческого роста? Исправить раньше
   двигаемся дальше.
5. **Доставить**. Скриншоты/рендеринги в виде файлов (путь `MEDIA:`), а также короткий
   краткое изложение того, что существует на уровне и где оно было сохранено.

`references/recipes.md` имеет законченные проработанные сборки (внешняя сцена дневного света,
угрюмый интерьер, кинематографический золотой час + рендеринг, импорт и размещение ресурсов)
с точной последовательностью вызовов и значениями.

## Подводные камни (самое главное — полный список в references/pitfalls.md)

- **Порядок запуска имеет значение.** Сначала включается редактор + сервер, затем Hermes.
  сессия. Отсутствуют `mcp_unreal_engine_*` инструментов = неправильный порядок.
- **Один звонок за раз.** Серийная ветка игры; без пакетной обработки, без перекрытия.
- **Интерфейс редактора зависает при каждом вызове.** Это задумано (тема игры).
  исполнение). Предупреждать пользователя при длительных операциях; делайте звонки небольшими.
- **Модальные диалоги блокируют все.** Вызов инструмента, который открывает (или сталкивает
  с) диалоговое окно модального редактора зависает, пока человек не закроет его. Если звонок
  зависает на неопределенный срок, попросите пользователя проверить редактор на наличие диалогового окна.
- **Тайм-ауты при длительных операциях.** Значение по умолчанию для каждого вызова Hermes составляет 120 с; актив
  импорт, сохранение больших уровней и рендеринг могут превысить его. Поднять
  `mcp_servers.unreal-engine.timeout` в `~/.hermes/config.yaml` для
  сеансы рендеринга/импорта.
- **Устаревшие схемы инструментов.** После создания/горячей перезагрузки наборов инструментов или включения
  плагин, запустите `ModelContextProtocol.RefreshTools` в консоли редактора
  и повторно `list_toolsets`. Новым C++ `UFUNCTION` требуется полный перезапуск редактора —
  Live Coding не обнажит их.
- **Экспериментальный плагин.** API и формы инструментов могут меняться в зависимости от движка.
  версии; доверяйте `describe_toolset` памяти, включая этот навык
  примеры. Когда документы и действующая схема расходятся во мнениях, действующая схема побеждает.
- **Не выставляйте сервер за пределы локального хоста.** Только петлевая проверка, без аутентификации, автор:
  дизайн. Никогда не предлагайте связывать его шире.
- **Примечание о лицензировании.** Сервер регистрируется при запуске: данные передаются через
  Плагин к подключенному сервису LLM является лицензированной технологией в соответствии с UE.
  Лицензионное соглашение (§6(e)) — пользователь несет ответственность за обеспечение своего поставщика LLM
  не тренируется на этом. Покажите это, если пользователь спрашивает об обработке данных.
