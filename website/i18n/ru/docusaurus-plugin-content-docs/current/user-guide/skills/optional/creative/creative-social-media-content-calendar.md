# Календарь контента в социальных сетях

Спланируйте конкретный календарь для выбранных социальных платформ. Этот навык владеет структурой кампании, краткими публикациями, адаптацией канала, утверждениями и проверкой публикации; навыки работы с платформой, такие как `xurl` собственные команды API. Для платформ без соединителя проверенная передача заканчивается после утверждения черновиков для планировщика пользователя — скажите об этом, а не требуйте публикации.

## Когда использовать

- «Составьте социальный календарь на следующий месяц».
— «Превратите этот запуск в публикации для X, LinkedIn, Instagram и TikTok».
- «Составить и запланировать кампанию».
- «Используйте эти статьи/видео в социальных сетях».

Не используйте для: отдельных публикаций (используйте навыки платформы напрямую).

## Процедура

### 1. Определите ограничения кампании

Запишите цель, аудиторию, предложение/сообщение, платформы, диапазон дат, ритмичность, голос, обязательные/запрещенные утверждения, ссылки, соглашение об отслеживании, локализацию и полномочия утверждения/публикации. Готово, если каждая предлагаемая должность имеет четкую деловую цель.

### 2. Исходный материал инвентаризации

Собирайте проверенные факты о продуктах, выпусках, статьях, СМИ, отзывах с разрешения, активах бренда и ключевых датах, используя `read_file` и `web_extract`. Отметьте владельцев претензий и срок их действия. Выполняется, когда видны неподтвержденные претензии и недостающие активы.

### 3. Создавайте темы и ячейки календаря

Создайте сбалансированное сочетание, такое как образование, доказательства, продукт, сообщество, событие, закулисное общение и разговор. Учитывайте частоту работы платформы и основные этапы кампании. Готово, когда даты, платформы, темы и цели образуют единый календарь, а не дублируют перекрестные публикации.

### 4. Напишите краткие описания для конкретной платформы

Для каждого сообщения укажите привязку, основное сообщение, формат, длину копии, призыв к действию, ссылку, размеры/контент ресурса, текст доступности, теги/упоминания и показатель успеха. Адаптируйтесь, а не копируйте и вставляйте между платформами. Готово, если автор может создать ресурс без скрытого контекста.

### 5. Черновик и ресурсы

Загрузите `humanizer` для голоса; создавайте визуальные эффекты с помощью инструмента `image_generate` там, где необходимы ресурсы. Сохраняйте фактические утверждения и общую идентичность кампании, соблюдая при этом нормы платформы. Готово, когда каждый слот календаря имеет статус черновика и актива.

### 6. Проведите редакционную проверку и анализ рисков

Проверьте фактическую точность, тон, повторение, права/разрешения, доступность, раскрытие информации, назначение ссылки, актуальность даты и чувствительность к кризису. Отметьте `draft`, `needs review` или `approved`; не публиковать из черновика. Готово, если у каждого сообщения есть расположение и владелец.

### 7. Расписание или передача

Предоставить одобренную партию. Публикуйте/планируйте только утвержденные публикации, используя доступные навыки работы с платформой (`xurl` для X); для платформ без соединителя доставьте утвержденный пакет (копию, ресурсы, время) для инструмента планирования пользователя и отметьте эти слоты как переданные, а не опубликованные. Прочитайте запланированное время, учетную запись, предварительный просмотр контента и идентификатор публикации/задания поставщика для всего, что действительно опубликовано. Готово, когда в календаре отображается подтвержденный статус публикации или передачи для каждого слота.

## Подводные камни

- Идентичная копия на каждой платформе.
- Заполнение каденции малоценными повторяющимися сообщениями.
- Публикация непроверенных показателей, отзывов или будущих претензий.
- Путаница завершения создания созданного актива с запланированной публикацией.
- Заявление «запланировано» для платформ, где передача завершилась на драфте.

## Проверка

- [ ] Каждое сообщение связано с целью кампании и проверенным инвентарем претензий.
- [ ] Ни одно сообщение не было опубликовано из штата `draft` или `needs review`.
- [ ] Опубликованные слоты имеют идентификаторы, подтвержденные провайдером; слоты для передачи помечены как таковые.
- [ ] Права, разрешения и раскрытие информации проверяются перед публикацией.
