# Наблюдатели

Опрашивайте внешние источники по интервалу и реагируйте только на новинки. Три готовых скрипта плюс общий помощник по водяным знакам; подключите их к заданию cron (или запустите их с терминала).

## Когда использовать

- Пользователь хочет смотреть канал RSS/Atom и получать уведомления о новых записях.
- Пользователь хочет наблюдать за проблемами/извлечениями/выпусками/фиксациями репозитория GitHub.
- Пользователь хочет опросить произвольную конечную точку JSON и получать уведомления о новых элементах.
- Пользователь запрашивает «наблюдатель за X» или «сообщить мне, когда X изменится».

## Ментальная модель

Наблюдатель — это просто скрипт, который:

1. Получает данные из внешнего источника.
2. Сравнивается с файлом водяных знаков ранее просмотренных идентификаторов.
3. Записывает новый водяной знак обратно.
4. Печатает новые элементы в стандартный вывод (или ничего без изменений)

Сценарии ниже обрабатывают все три. Агент запускает их через инструмент терминала — из задания cron, веб-перехватчика или интерактивного чата — и сообщает, что нового.

## Готовые скрипты

После установки навыка все трое живут в `$HERMES_HOME/skills/devops/watchers/scripts/`. Каждый читает `WATCHER_STATE_DIR` (по умолчанию `$HERMES_HOME/watcher-state/`) для своего файла состояния, ключ которого указан в аргументе `--name`.

| Скрипт | Что он смотрит | Ключ дедупликации |
|---|---|---|
| `watch_rss.py` | URL-адрес канала RSS 2.0 или Atom | `<guid>` / `<id>` |
| `watch_http_json.py` | Любая конечная точка JSON, возвращающая список объектов | Настраиваемое поле идентификатора |
| `watch_github.py` | GitHub выдает/извлекает/выпускает/фиксирует для репозитория | `id` / `sha` |

Все трое:

– При первом запуске записывается базовый уровень — существующий фид не воспроизводится.
- Водяной знак представляет собой ограниченный набор идентификаторов (максимум 500) для ограничения памяти.
– Формат вывода: `## <title>\n<url>\n\n<optional body>` за элемент.
- Пустой стандартный вывод для no-new — вызывающая сторона воспринимает это как молчание.
- Ненулевой выход при ошибках выборки.

## Использование

Запустите наблюдатель прямо из инструмента терминала:

```bash
python $HERMES_HOME/skills/devops/watchers/scripts/watch_rss.py \
  --name hn --url https://news.ycombinator.com/rss --max 5
```

Посмотрите репозиторий GitHub (установите `GITHUB_TOKEN` в `${HERMES_HOME:-~/.hermes}/.env`, чтобы избежать ограничения анонимной скорости в 60 запросов в час):

```bash
python $HERMES_HOME/skills/devops/watchers/scripts/watch_github.py \
  --name hermes-issues --repo NousResearch/hermes-agent --scope issues
```

Опрос произвольного JSON API:

```bash
python $HERMES_HOME/skills/devops/watchers/scripts/watch_http_json.py \
  --name api --url https://api.example.com/events \
  --id-field event_id --items-path data.events
```

## Подключение к cron

Попросите агента запланировать задание cron с помощью подсказки типа:

> Каждые 15 минут запускайте `watch_rss.py --name hn --url https://news.ycombinator.com/rss`. Если он что-нибудь напечатает, суммируйте заголовки и доставьте их. Если он ничего не печатает, молчите.

Агент вызывает сценарий через инструмент терминала внутри цикла агента задания cron; никаких изменений во встроенном флаге `--script` cron не требуется.

## Файлы состояния

Каждый наблюдатель пишет `$HERMES_HOME/watcher-state/<name>.json`. Осмотрите:

```bash
cat $HERMES_HOME/watcher-state/hn.json
```

Принудительное воспроизведение (следующий запуск считается первым опросом):

```bash
rm $HERMES_HOME/watcher-state/hn.json
```

## Пишем свой собственный

Все три скрипта используют один и тот же шаблон: загрузка водяного знака, выборка, сравнение, сохранение, выброс. `scripts/_watermark.py` — общий помощник; импортируйте его, чтобы получить атомарные записи + набор ограниченных идентификаторов + базовый уровень при первом запуске бесплатно. Посмотрите любой из трех справочных сценариев, чтобы узнать, насколько мало для этого требуется шаблонного кода.

## Распространенные ошибки

1. **Печать заголовка «Нет новых элементов» каждый тик.** Вызывающие программы полагаются на пустой стандартный вывод = молчащий. Если вы напечатаете что-нибудь на пустой дельте, вы спамите канал. Поставляемые сценарии справляются с этой задачей; пользовательские сценарии тоже должны.
2. **Ожидается, что при первом запуске будут выданы элементы.** Это не так — при первом запуске записывается базовый уровень. Если вам нужен первоначальный дайджест, удалите файл состояния после первого запуска или добавьте флаг `--prime-with-latest N` в свой собственный скрипт.
3. **Неограниченный рост водяных знаков.** Максимальное количество общих вспомогательных идентификаторов — 500. Поднимите его, если каналы часто посещаются; опустите его в ограниченных файловых системах.
4. **Размещение каталога состояния, в котором песочница агента не может писать.** `$HERMES_HOME/watcher-state/` всегда доступен для записи. Серверные части Docker/Modal могут не видеть произвольные пути к хостам.
