# ФастMCP

Создавайте серверы MCP на Python с помощью FastMCP, проверяйте их локально, устанавливайте в клиенты MCP и развертывайте в качестве конечных точек HTTP.

## Когда использовать

Используйте этот навык, когда задача состоит в том, чтобы:

— создать новый сервер MCP на Python
- обернуть API, базу данных, интерфейс командной строки или рабочий процесс обработки файлов инструментами MCP.
- предоставлять ресурсы или подсказки в дополнение к инструментам
- провести дымовое тестирование сервера с помощью FastMCP CLI перед подключением его к Hermes или другому клиенту.
- установить сервер в Claude Code, Claude Desktop, Cursor или аналогичный клиент MCP.
- подготовить репозиторий сервера FastMCP для развертывания HTTP.

Используйте `native-mcp`, если сервер уже существует и его нужно только подключить к Hermes. Используйте `mcporter`, если целью является специальный доступ CLI к существующему серверу MCP вместо его создания.

## Предварительные условия

Сначала установите FastMCP в рабочую среду:

```bash
pip install fastmcp
fastmcp version
```

Для шаблона API установите `httpx`, если он еще не установлен:

```bash
pip install httpx
```

## Включенные файлы

### Шаблоны

- `templates/api_wrapper.py` — оболочка REST API с поддержкой заголовка аутентификации.

### Скрипты

- `scripts/scaffold_fastmcp.py` – скопировать начальный шаблон и заменить заполнитель имени сервера.

## Рабочий процесс

### 1. Выберите наименьшую жизнеспособную форму сервера

Сначала выберите самую узкую полезную площадь поверхности:

- Оболочка API: начните с 1–3 важных конечных точек, а не со всего API.
- сервер базы данных: предоставляет возможность самоанализа только для чтения и ограниченный путь запроса.
- файловый процессор: предоставляет детерминированные операции с явными аргументами пути.
- подсказки/ресурсы: добавляйте только тогда, когда клиенту нужны повторно используемые шаблоны подсказок или доступные для обнаружения документы.

Предпочитайте тонкий сервер с хорошими именами, строками документации и схемами большему серверу с неясными инструментами.

### 2. Леска из шаблона

Скопируйте шаблон напрямую или воспользуйтесь помощником по созданию шаблонов:

```bash
python ~/.hermes/skills/mcp/fastmcp/scripts/scaffold_fastmcp.py \
  --template api_wrapper \
  --name "Acme API" \
  --output ./acme_server.py
```

Доступные шаблоны:

```bash
python ~/.hermes/skills/mcp/fastmcp/scripts/scaffold_fastmcp.py --list
```

При копировании вручную замените `__SERVER_NAME__` реальным именем сервера.

### 3. Сначала внедрите инструменты

Прежде чем добавлять ресурсы или подсказки, начните с функций `@mcp.tool`.

Правила оформления инструмента:

- Дайте каждому инструменту конкретное имя, основанное на глаголе.
- Напишите строки документации в виде описаний инструментов, доступных пользователю.
- Сохраняйте параметры явными и типизированными.
– По возможности возвращайте структурированные данные, безопасные в формате JSON.
- Заблаговременная проверка небезопасных входных данных.
- По умолчанию для первых версий предпочитается режим только для чтения.

Примеры хороших инструментов:

- `get_customer`
- `search_tickets`
- `describe_table`
- `summarize_text_file`

Примеры слабых инструментов:

- `run`
- `process`
- `do_thing`

### 4. Добавляйте ресурсы и подсказки только тогда, когда они помогают

Добавьте `@mcp.resource`, если клиент получает выгоду от получения стабильного контента, доступного только для чтения, такого как схемы, документы политики или созданные отчеты.

Добавьте `@mcp.prompt`, если сервер должен предоставить повторно используемый шаблон приглашения для известного рабочего процесса.

Не превращайте каждый документ в подсказку. Предпочитаю:

- инструменты для действий
- ресурсы для поиска данных/документов
- запрашивает многоразовые инструкции LLM

### 5. Протестируйте сервер перед его куда-либо интеграцией

Используйте FastMCP CLI для локальной проверки:

```bash
fastmcp inspect acme_server.py:mcp
fastmcp list acme_server.py --json
fastmcp call acme_server.py search_resources query=router limit=5 --json
```

Для быстрой итеративной отладки запустите сервер локально:

```bash
fastmcp run acme_server.py:mcp
```

Чтобы протестировать HTTP-транспорт локально:

```bash
fastmcp run acme_server.py:mcp --transport http --host 127.0.0.1 --port 8000
fastmcp list http://127.0.0.1:8000/mcp --json
fastmcp call http://127.0.0.1:8000/mcp search_resources query=router --json
```

Всегда запускайте хотя бы один настоящий `fastmcp call` для каждого нового инструмента, прежде чем утверждать, что сервер работает.

### 6. Установка на клиент после прохождения локальной проверки

FastMCP может зарегистрировать сервер с поддерживаемыми клиентами MCP:

```bash
fastmcp install claude-code acme_server.py
fastmcp install claude-desktop acme_server.py
fastmcp install cursor acme_server.py -e .
```

Используйте `fastmcp discover` для проверки именованных серверов MCP, уже настроенных на компьютере.

Когда целью является интеграция Hermes, либо:

- настроить сервер в `~/.hermes/config.yaml`, используя навык `native-mcp`, или
- продолжайте использовать команды FastMCP CLI во время разработки, пока интерфейс не стабилизируется.

### 7. Развертывание после стабилизации локального контракта

Для управляемого хостинга Prefect Horizon — это наиболее прямой путь к документам FastMCP. Перед развертыванием:

```bash
fastmcp inspect acme_server.py:mcp
```

Убедитесь, что репо содержит:

— файл Python с серверным объектом FastMCP.
- `requirements.txt` или `pyproject.toml`
- любая документация по переменным среды, необходимая для развертывания.

Для общего HTTP-хостинга сначала проверьте HTTP-транспорт локально, а затем разверните его на любой Python-совместимой платформе, которая может предоставить порт сервера.

## Общие шаблоны

### Шаблон оболочки API

Используйте при предоставлении REST или HTTP API в качестве инструментов MCP.

Рекомендуемый первый кусочек:

- один путь чтения
- один список/путь поиска
- дополнительная проверка здоровья

Замечания по реализации:

- сохранять аутентификацию в переменных среды, а не жестко запрограммировать
- централизовать логику запроса в одном помощнике
- выявление ошибок API с кратким контекстом
- нормализовать противоречивые восходящие полезные данные перед их возвратом

Начните с `templates/api_wrapper.py`.

### Шаблон базы данных

Используйте при предоставлении возможностей безопасного запроса и проверки.

Рекомендуемый первый кусочек:

- `list_tables`
- `describe_table`
- один инструмент запросов на чтение с ограничениями

Замечания по реализации:

- по умолчанию доступ к БД только для чтения
- отклонять SQL, отличный от `SELECT`, в ранних версиях
- ограничить количество строк
- возвращать строки плюс имена столбцов

Начните с `templates/database_server.py`.

### Шаблон файлового процессора

Используйте, когда серверу необходимо проверять или преобразовывать файлы по требованию.

Рекомендуемый первый кусочек:

- суммировать содержимое файла
- поиск по файлам
- извлекать детерминированные метаданные

Замечания по реализации:

- принимать явные пути к файлам
- проверка отсутствия файлов и ошибок кодирования
- предварительный просмотр шапок и подсчет результатов
- избегайте раскошеливаний, если не требуется специальный внешний инструмент

Начните с `templates/file_processor.py`.

## Панель качества

Прежде чем передать сервер FastMCP, проверьте все следующее:

- сервер импортирует чисто
- `fastmcp inspect <file.py:mcp>` успешно
- `fastmcp list <server spec> --json` успешно
- у каждого нового инструмента есть хотя бы один настоящий `fastmcp call`
- переменные среды документированы
- поверхность инструмента достаточно мала, чтобы можно было разобраться без догадок

## Устранение неполадок

### Команда FastMCP отсутствует

Установите пакет в активную среду:

```bash
pip install fastmcp
fastmcp version
```

### `fastmcp inspect` не работает

Проверьте это:

- файл импортируется без побочных эффектов, приводящих к сбою
- экземпляр FastMCP назван правильно в `<file.py:object>`
- установлены дополнительные зависимости из шаблона

### Инструмент работает на Python, но не через CLI

Запустить:

```bash
fastmcp list server.py --json
fastmcp call server.py your_tool_name --json
```

Обычно это приводит к несоответствию имен, отсутствию обязательных аргументов или несериализуемым возвращаемым значениям.

### Гермес не видит развернутый сервер

Часть по созданию сервера может быть правильной, а вот конфигурация Hermes — нет. Загрузите навык `native-mcp` и настройте сервер в `~/.hermes/config.yaml`, затем перезапустите Hermes.
