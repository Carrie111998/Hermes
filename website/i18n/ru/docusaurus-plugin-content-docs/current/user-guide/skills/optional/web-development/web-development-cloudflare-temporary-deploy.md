# Навык временного развертывания Cloudflare

Разверните Cloudflare Worker на действующем URL-адресе `workers.dev` без настройки учетной записи, используя `wrangler deploy --temporary`. Cloudflare предоставляет одноразовую учетную запись, развертывает и печатает URL-адрес заявки, действительный в течение 60 минут; невостребованные аккаунты автоматически удаляются. Это дает агенту четкий цикл записи → развертывания → проверки без какого-либо OAuth, регистрации или копирования-вставки токенов.

Этот навык НЕ распространяется на производственные развертывания (для них используйте `wrangler login` + постоянную учетную запись), а также на продукты Cloudflare, не относящиеся к Worker, за пределами ограничений для временных учетных записей, указанных ниже.

## Когда использовать

Загрузите этот навык, когда пользователь хочет:

- **Отправляйте написанный агентом код на действующий URL** без предварительного создания учетной записи Cloudflare — «разверните это и дайте мне ссылку».
- **Итерация в фоновом/автономном сеансе**, когда шаг OAuth браузера будет жесткой остановкой.
- **Быстро создавайте прототипы или оценивайте Workers** с помощью одноразовой, доступной цели.
- **Создайте цикл развертывания с самопроверкой** — разверните, `curl` действующий URL-адрес, подтвердите, что выходные данные соответствуют коду, повторите развертывание.

## Когда НЕ использовать

- **Производство или CI/CD** → используйте постоянную учетную запись (`wrangler login` или `CLOUDFLARE_API_TOKEN`). `--temporary` выдает ошибку, если присутствуют какие-либо учетные данные.
- **Wrangler уже прошел аутентификацию** → `--temporary` возвращает ошибку по умолчанию. Сначала запустите `wrangler logout` только в том случае, если пользователь явно хочет одноразового развертывания.
- **Долговечный хостинг** → временные развертывания удаляются через 60 минут, если не заявлено.

## Предварительные условия

- **Wrangler 4.102.0 или новее.** В этой версии появился `--temporary`. В более ранних версиях его нет. Подтвердите с помощью `npx wrangler@latest --version`.
- **Узел 18+ / npm** (или `npx`, `yarn`, `pnpm`). Глобальная установка не требуется — `npx wrangler@latest` работает.
- **Учетные данные Cloudflare отсутствуют.** `--temporary` работает только в том случае, если Wrangler не прошел проверку подлинности: нет входа в систему OAuth, нет переменной окружения `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_API_KEY`, нет кэшированного OAuth `~/.wrangler`/`~/.config/.wrangler`. Используйте среду инструмента `terminal` как есть; не устанавливайте эти переменные.
- Выход из сети на `cloudflare.com` и `workers.dev`.
– Использование `--temporary` означает принятие Условий обслуживания и Политики конфиденциальности Cloudflare.

## Как бежать

Используйте инструмент `terminal` на каждом этапе. Всегда закрепляйте версию (`wrangler@latest` или `wrangler@4.102.0` или новее), чтобы случайно не запустить старый глобальный Wrangler, у которого отсутствует флаг.

1. ** Создайте минимальный Worker** (пропустите, если проект уже существует). Работнику необходим `wrangler.toml` (или `wrangler.jsonc`) и сценарий входа. Минимальный пример TypeScript — напишите его с помощью `write_file`:

   `wrangler.jsonc`:
   ```jsonc
   {
     "name": "hello-agent",
     "main": "src/index.ts",
     "compatibility_date": "2025-01-01"
   }
   ```

   `src/index.ts`:
   ```typescript
   export default {
     async fetch(): Promise<Response> {
       return new Response("hello cloudflare");
     },
   };
   ```

2. **Разверните с помощью `--temporary`** из каталога проекта:
   ```
   npx wrangler@latest deploy --temporary
   ```
   Проверка подтверждения работы добавляет небольшую автоматическую задержку. В случае успеха Wrangler печатает строку `Account: <name> (created)` (или `(reused)`), `Claim URL` и действующий URL-адрес `https://<worker>.<account>.workers.dev`.

3. **Проанализируйте URL-адреса** на основе этих выходных данных. Запустите помощник, чтобы надежно извлечь их, а не просматривать на глаз:
   ```
   npx wrangler@latest deploy --temporary 2>&1 | python3 scripts/parse_deploy_output.py
   ```
   (Преобразуйте `scripts/parse_deploy_output.py` в абсолютный путь этого навыка.) Он печатает JSON: `{"live_url", "claim_url", "account", "account_state", "expires_minutes", "deployed"}`.

4. **Убедитесь, что развертывание действительно активно** — не доверяйте только журналу развертывания. `curl` действующий URL-адрес и убедитесь, что тело соответствует тому, что возвращает код:
   ```
   curl -sS <live_url>
   ```

5. **Итерация.** Отредактируйте код, повторно разверните его с тем же `npx wrangler@latest deploy --temporary`. В течение 60 минут Wrangler повторно использует кэшированную временную учетную запись (`Account: <name> (reused)`), поэтому URL-адрес остается стабильным. `curl` еще раз, чтобы подтвердить изменение.

6. **Передайте URL-адрес заявки пользователю.** Скажите ему: откройте его в течение 60 минут, чтобы сохранить развертывание и все ресурсы; если они не заявят об этом, все автоматически удаляется. Считайте URL-адрес заявки секретным — он предоставляет право собственности на учетную запись.

## Подводные камни

- **`--temporary` отсутствует в `wrangler deploy --help` и не является глобальным флагом.** Он намеренно скрыт и отображается динамически: при сбое неаутентифицированного `wrangler deploy` Wrangler печатает «повторное выполнение с `--temporary`». Не делайте вывод, что флаг отсутствует только потому, что `--help` его опускает — вместо этого проверьте версию.
- **Старый глобальный Wrangler.** Устаревший глобально установленный `wrangler` (`< 4.102.0`) молчаливо не имеет флага. Всегда вызывайте `npx wrangler@latest` (или закрепленный `>=4.102.0`), чтобы контролировать версию.
- **Аутентификация присутствует → серьезная ошибка.** Если `wrangler login` когда-либо запускался или установлен `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_API_KEY`, возникает ошибка `--temporary`. Либо отключите переменную для этой оболочки, либо `wrangler logout`. Никогда не лишайте настоящие учетные данные пользователя, не сообщая ему об этом.
- **Ограничение скорости.** Слишком быстрое создание временных учетных записей не удается. Повторно используйте кэшированную учетную запись (просто повторно разверните ее) в течение 60 минут вместо принудительного создания новой; если скорость ограничена, подождите или используйте постоянную учетную запись.
- **Жесткий срок действия — 60 минут, без возможности продления.** Если развертывание должно продолжаться час, пользователь должен потребовать его. Ясно обсудите это.
- **`curl` может некоторое время обслуживать старое тело после повторного развертывания.** `workers.dev` имеет короткий пограничный кэш; строка `(reused)` плюс новый `Current Version ID` подтверждают успешное развертывание, даже если `curl` показывает устаревший контент в течение нескольких секунд. Повторно сверните или добавьте строку запроса очистки кеша, прежде чем сделать вывод о сбое повторного развертывания.
- **Не регистрируйте URL-адрес заявки в общих стенограммах как «просто ссылку».** Это эквивалент учетных данных.

## Проверка

- `npx wrangler@latest --version` возвращает `>= 4.102.0`.
– `npx wrangler@latest deploy --temporary` печатает действующий URL-адрес `workers.dev` и URL-адрес заявки `claim-preview?claimToken=`.
- `curl -sS <live_url>` возвращает точное тело, созданное кодом Worker.
– При втором развертывании сообщается `Account: <name> (reused)`, а активный URL-адрес не изменяется.
- Самотестирование скрипта парсера пройдено: `python3 scripts/parse_deploy_output.py --selftest`.
