# Фактические навыки настройки компьютера

Настраивает [actual.inc](https://actual.inc) (Настоящий компьютер) как вывод Гермеса.
провайдер. Actual превращает собственное оборудование пользователя в частный кластер вывода.
и предоставляет OpenAI-совместимый API двумя способами:
реле на `https://api.actual.inc` (аутентифицировано ключом `ac_`) и локальный
демон на устройстве по адресу `http://127.0.0.1:8080` (нет аутентификации при обратной связи). Этот навык
не устанавливает демон Actual для пользователя — требуется авторизация устройства
человек в браузере.

## Когда использовать

- Пользователь хочет добавить actual.inc в качестве поставщика логических выводов (облачного ретранслятора или локального).
- У пользователя есть ключ `ac_`, и он хочет, чтобы Hermes направлялся через его фактический кластер.
- Пользователь хочет получить полностью локальный вывод на устройстве через демон Actual.
- Устранение неполадок: реальные запросы завершаются с ошибкой с загадочными 400 или пустыми потоками.

## Предварительные условия

- Hermes имеет **первоклассную поддержку поставщика услуг `actual`** (идентификатор поставщика `actual`,
  псевдонимы `actual-computer`, `actualcomputer`, `aci`). НЕ настраивайте Фактический
  как запись `custom_providers` / `providers.actual.*` в текущем Гермесе —
  встроенный поставщик владеет именем и обрабатывает нормализацию базового URL-адреса,
  Ответы передаются и локальная аутентификация выполняется автоматически.
- Режим реле: фактическая учетная запись и ключ вывода `ac_` из
  https://actual.inc/user/keys.
- Локальный режим: пользователь установил демон
  (`curl -fsSL "https://actual.inc/install" | bash`) и готовое устройство
  авторизацию, запустив `actual` один раз и открыв распечатанный файл.
  `https://actual.inc/device?code=...` URL-адрес в браузере. Передайте этот URL-адрес
  пользователя и ПОДОЖДИТЕ — никогда не придумывайте адрес электронной почты и не авторизовывайтесь от его имени. Коды
  истекает через 5 минут; повторно запустите `actual`, чтобы получить новый.

## Как бежать

### Режим реле/API

1. Поместите ключ в `.env` (только секреты — никогда config.yaml):
   добавьте `ACTUAL_API_KEY=ac_...` к `~/.hermes/.env`.
2. Проверьте ключ и найдите модели с помощью `terminal`:
   ```bash
   curl -s https://api.actual.inc/v1/models -H "Authorization: Bearer $ACTUAL_API_KEY"
   ```
3. Выберите поставщика + модель:
   ```bash
   hermes config set model.provider actual
   hermes config set model.default "MODEL_ID_FROM_DISCOVERY"
   ```
4. Проверьте сквозную проверку:
   ```bash
   hermes chat -Q -q "Reply with exactly: ACTUAL_OK" --provider actual -m MODEL_ID
   ```

### Локальный режим

1. Человек установил + авторизовал демон (см. Предварительные условия).
2. Загрузите и загрузите модель (с возможностью создания сценария после авторизации):
   ```bash
   actual models search "qwen2.5 0.5b instruct gguf" --limit 8 --no-prompt
   # Downloads REQUIRE an explicit quantization (409 ambiguous_model_download otherwise):
   actual models download "Qwen/Qwen2.5-0.5B-Instruct-GGUF/Q4_K_M"
   actual models list        # note the INSTALLED name (differs from download id)
   actual models load "qwen2.5-0.5b-instruct-q4_k_m"   # load by installed name
   ```
3. Направьте Гермеса на демона. `ACTUAL_BASE_URL` с хостом обратной связи переворачивает
   встроенный провайдер автоматически переходит в локальный режим без аутентификации — ключ не требуется:
   добавьте `ACTUAL_BASE_URL=http://127.0.0.1:8080` к `~/.hermes/.env`, затем:
   ```bash
   hermes config set model.provider actual
   hermes config set model.default "INSTALLED_MODEL_NAME"
   ```
4. Проверьте (сокращенный набор инструментов — см. ошибку контекстного окна ниже):
   ```bash
   hermes chat -Q -q "Reply with exactly: LOCAL_OK" --provider actual -m INSTALLED_NAME -t file,web
   ```

## Краткий справочник

| Вещь | Значение |
|---|---|
| Хостинг-реле | `https://api.actual.inc/v1` (автоматически нормализуется с чистого хоста) |
| Локальный демон | `http://127.0.0.1:8080/v1` (нет аутентификации при обратной связи) |
| Ключ окружения var | `ACTUAL_API_KEY` (`ac_...`) |
| Базовый URL-адрес env var | `ACTUAL_BASE_URL` (хост обратной связи ⇒ локальный режим без аутентификации) |
| Идентификатор/псевдонимы провайдера | `actual` / `actual-computer`, `actualcomputer`, `aci` |
| Транспорт | API ответов (`codex_responses`) — встроенный, не переопределять |
| Закрепление кластера | `X-Cluster-ID` через `providers.actual.extra_headers` в config.yaml |
| Руководство по размерам моделей | 0,5Б Q4_K_M ~470МБ (игрушка), 7-8Б Q4_K_M ~4,5ГБ (ежедневный драйвер), 32Б ~20ГБ |

## Подводные камни

1. **ловушка рассуждения_усилия (управляется Гермесом как первоклассным поставщиком).**
   Серверные части Actual SGLang/vLLM принимают только `none/low/medium/high/max`;
   `xhigh`/`ultra` раньше давал сбой с загадочным
   `Expecting value: line 1 column 1 (char 0)` (обернутый HTTP 400).
   встроенный провайдер зажимает `xhigh→high` и `ultra→max` на проводе. Если
   запросите еще 400 на старом Гермесе, установите ограничение для каждой модели:
   `agent.reasoning_overrides.<model>: high` в config.yaml.
2. **Переполнение контекстного окна на небольших локальных моделях.** Набор инструментов Hermes по умолчанию
   это ~26 тыс. токенов схем плюс ~9 тыс. токенов системного приглашения. Модель загружена
   с переполнением контекста 32 тыс. перед первым поворотом и семейством llama.cpp
   серверы излучают голый `data: [DONE]` — сообщает Hermes
   `Provider returned an empty stream with no finish_reason`. Это НЕ
   Ошибка SSE. Исправления: ограничить инструменты (`-t file,web`), загрузить модель с
   увеличить `n_ctx` или выбрать модель с контекстом >=64 тыс. для полного набора инструментов.
   Отслеживание исходящих сообщений: #51448 (не сообщайте о новых проблемах; добавляйте туда доказательства).
   Родственные, но разные: #65631 (HTTP-200 SSE с номером 400), #56516.
   (потоки только рассуждения).
3. **Идентификаторы загрузки и установленные имена.** `actual models download` занимает
   `repo/QUANT` и 409 без явного квантования;
   `actual models load` берет УСТАНОВЛЕННОЕ имя из `actual models list`.
4. **Модели рассуждений, возвращающие пустой контент.** Варианты рассуждений GLM/Qwen
   выделяет мышление в отдельное `reasoning` поле и может сжечь небольшой
   `max_tokens` полностью на рассуждениях. Раздайте щедрые max_tokens заранее
   предполагая неудачу.
5. **Не создавайте собственный поставщик с именем `actual`.** Старые руководства по установке
   (предварительная первоклассная поддержка) написал `providers.actual.*` блоков конфигурации. Вкл.
   нынешний Гермес, встроенный провайдер, завоевывает свое имя; устаревшие пользовательские блоки
   игнорируются или конфликтуют. Удалите их и используйте env vars + model.provider.
   поток выше.

## Проверка

```bash
# Relay:
hermes chat -Q -q "Reply with exactly: ACTUAL_OK" --provider actual -m MODEL
# Local (small model — reduced toolset):
hermes chat -Q -q "Reply with exactly: LOCAL_OK" --provider actual -m MODEL -t file,web
# Provider status (local no-auth shows key_source=local-offline):
hermes status
```
