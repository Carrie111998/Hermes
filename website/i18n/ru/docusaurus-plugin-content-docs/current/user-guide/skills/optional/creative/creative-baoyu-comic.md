# Создатель комиксов знаний

Адаптировано из [baoyu-comic](https://github.com/JimLiu/baoyu-skills) для экосистемы инструментов Hermes Agent.

Создавайте оригинальные комиксы знаний, используя гибкие комбинации художественного стиля и тона.

## Когда использовать

Активируйте этот навык, когда пользователь просит создать познавательный/познавательный комикс, биографический комикс, обучающий комикс или использует такие термины, как «知识漫画», «教育漫画» или «стиль Logicomix». Пользователь предоставляет контент (текст, путь к файлу, URL-адрес или тему) и при необходимости указывает художественный стиль, тон, макет, соотношение сторон или язык.

## Справочные изображения

Инструмент Hermes `image_generate` работает **только с подсказками** — он принимает текстовое приглашение и соотношение сторон, а также возвращает URL-адрес изображения. Он **НЕ** принимает эталонные изображения. Когда пользователь предоставляет эталонное изображение, используйте его для **извлечения характеристик из текста**, которые встраиваются в каждое приглашение на странице:

**Прием**. Принимайте пути к файлам, когда пользователь их предоставляет (или вставляет изображения в разговор).
– Путь к файлу → скопируйте в `refs/NN-ref-{slug}.{ext}` вместе с выводом комикса для проверки происхождения.
– Вставленное изображение без пути → запросите у пользователя путь через `clarify` или извлеките особенности стиля устно в качестве резервного текста.
- Нет ссылки → пропустите этот раздел.

**Режимы использования** (по ссылке):

| Использование | Эффект |
|-------|--------|
| `style` | Извлеките характеристики стиля (обработка линий, текстура, настроение) и добавьте их в тело подсказки каждой страницы |
| `palette` | Извлекайте шестнадцатеричные цвета и добавляйте их в тело приглашения каждой страницы |
| `scene` | Извлеките композицию сцены или примечания к теме и добавьте их на соответствующие страницы |

**Запишите в заголовке каждой страницы**, если ссылки существуют:

```yaml
references:
  - ref_id: 01
    filename: 01-ref-scene.png
    usage: style
    traits: "muted earth tones, soft-edged ink wash, low-contrast backgrounds"
```

Согласованность символов обеспечивается **текстовыми описаниями** в `characters/characters.md` (написанными на шаге 3), которые встроены в каждое приглашение на странице (шаг 5). Дополнительный лист символов PNG, созданный на шаге 7.1, представляет собой артефакт проверки, ориентированный на человека, а не входные данные для `image_generate`.

## Структура файла

Выходной каталог: `comic/{topic-slug}/`
- Слизень: 2–4 слова кебаб-кебаб из темы (например, `alan-turing-bio`)
– Конфликт: добавьте временную метку (например, `turing-story-20260118-143052`).

**Содержание**:
| Файл | Описание |
|------|-------------|
| `source-{slug}.md` | Сохраненное исходное содержимое (ссылка на кебаб-кебаб соответствует выходному каталогу) |
| `analysis.md` | Контент-анализ |
| `storyboard.md` | Раскадровка с разбивкой панелей |
| `characters/characters.md` | Определения персонажей |
| `characters/characters.png` | Справочный лист персонажа (загружен с `image_generate`) |
| `prompts/NN-{cover\|page}-[slug].md` | Генерация подсказок |
| `NN-{cover\|page}-[slug].png` | Сгенерированные изображения (загружены с `image_generate`) |
| `refs/NN-ref-{slug}.{ext}` | Предоставленные пользователем эталонные изображения (необязательно, для указания происхождения) |

## Обработка языка

**Приоритет обнаружения**:
1. Язык, указанный пользователем (явный вариант)
2. Язык общения пользователя
3. Язык исходного контента

**Правило**: используйте язык ввода пользователя для ВСЕХ взаимодействий:
- Контуры раскадровки и описания сцен.
- Подсказки по созданию изображений
- Параметры выбора пользователя и подтверждения
- Обновления прогресса, вопросы, ошибки, сводки

Технические термины остаются на английском языке.

### Вопросы пользователей

Используйте инструмент `clarify` для подтверждения параметров. Поскольку `clarify` обрабатывает по одному вопросу за раз, сначала задайте самый важный вопрос и действуйте последовательно. Полный набор вопросов для Шага 2 см. в [references/workflow.md](https://github.com/NousResearch/hermes-agent/blob/main/optional-skills/creative/baoyu-comic/references/workflow.md).

**Обработка тайм-аута (КРИТИЧЕСКИЙ)**: `clarify` может возвращать `"The user did not provide a response within the time limit. Use your best judgement to make the choice and proceed."` — это НЕ согласие пользователя использовать все по умолчанию.

– Считайте это значением по умолчанию **только для этого одного вопроса**. Продолжайте последовательно задавать оставшиеся вопросы Шага 2; каждый вопрос представляет собой независимую точку согласия.
- **Покажите пользователю значение по умолчанию на видном месте** в следующем сообщении, чтобы у него была возможность его исправить: например. `"Style: defaulted to ohmsha preset (clarify timed out). Say the word to switch."` — несообщенный дефолт неотличим от того, что вы никогда не спрашивали.
- НЕ сворачивайте шаг 2 в один проход «использовать все значения по умолчанию» после одного тайм-аута. Если пользователь действительно отсутствует, он будет одинаково отсутствовать по всем пяти вопросам, но он сможет исправить видимые значения по умолчанию, когда вернется, и не сможет исправить невидимые.

### Шаг 7: Создание изображения

Используйте встроенный инструмент Hermes `image_generate` для рендеринга всех изображений. Его схема принимает только `prompt` и `aspect_ratio` (`landscape` | `portrait` | `square`); он **возвращает URL**, а не локальный файл. Поэтому каждую сгенерированную страницу или лист символов необходимо загрузить в выходной каталог.

**Требование к файлу подсказки (жесткое)**: запишите полное и окончательное подсказку для каждого изображения в отдельный файл под именем `prompts/` (имя: `NN-{type}-[slug].md`) ПЕРЕД вызовом `image_generate`. Файл подсказки представляет собой запись воспроизводимости.

**Соотношение сторон** — поле `aspect_ratio` раскадровки сопоставляется с форматом `image_generate` следующим образом:

| Соотношение раскадровки | `image_generate` формат |
|------------------|-------------------------|
| `3:4`, `9:16`, `2:3` | `portrait` |
| `4:3`, `16:9`, `3:2` | `landscape` |
| `1:1` | `square` |

**Шаг загрузки** — после каждого вызова `image_generate`:
1. Прочтите URL-адрес из результата инструмента.
2. Получите байты изображения, используя **абсолютный** путь вывода, например
   `curl -fsSL "<url>" -o /abs/path/to/comic/<slug>/NN-page-<slug>.png`
3. Прежде чем переходить к следующей странице, убедитесь, что файл существует и не пуст по этому точному пути.

**Никогда не полагайтесь на постоянство CWD оболочки для путей `-o`.** CWD постоянной оболочки терминального инструмента может меняться между пакетами (истечение срока действия сеанса, `TERMINAL_LIFETIME_SECONDS`, сбой `cd`, из-за которого вы попадаете в неправильный каталог). `curl -o relative/path.png` — это бесшумный пистолет: если CWD сместился, файл без ошибок попадет в другое место. **Всегда передавайте полный абсолютный путь к `-o`** или `workdir=<abs path>` в инструмент терминала. Инцидент, апрель 2026 г.: страницы 06–09 10-страничного комикса оказались в корне репозитория вместо `comic/<slug>/`, поскольку пакет 3 унаследовал устаревший CWD от пакета 2, а `curl -o 06-page-skills.png` записал не в тот каталог. Затем агент несколько ходов утверждал, что файлы существуют там, где их нет.

**7.1 Лист персонажа** — сгенерируйте его (для `characters/characters.png`, аспект `landscape`), если комикс многостраничный с повторяющимися персонажами. Пропустите простые настройки (например, четырехпанельный минимализм) или одностраничные комиксы. Файл приглашения по адресу `characters/characters.md` должен существовать до вызова `image_generate`. Отрисованный PNG — это **артефакт просмотра с человеческим лицом** (поэтому пользователь может визуально проверить дизайн персонажа) и ссылка для последующих регенераций или ручного редактирования подсказок — он **не** влияет на шаг 7.2. Подсказки страницы уже написаны на шаге 5 из **текстовых описаний** в `characters/characters.md`; `image_generate` не может принимать изображения в качестве визуальных данных.

**7.2 Страницы** — подсказка каждой страницы ДОЛЖНА уже находиться по адресу `prompts/NN-{cover|page}-[slug].md` перед вызовом `image_generate`. Поскольку `image_generate` предназначен только для запроса, согласованность символов обеспечивается путем **встраивания описаний символов (полученных из `characters/characters.md`) в строку каждого приглашения на странице на этапе 5**. Встраивание выполняется одинаково независимо от того, создается ли лист PNG в версии 7.1 или нет; PNG — это всего лишь средство просмотра/восстановления.

**Правило резервного копирования**: существующие файлы `prompts/…md` и `…png` → переименуйте с суффиксом `-backup-YYYYMMDD-HHMMSS` перед повторным созданием.

Полный пошаговый рабочий процесс (анализ, раскадровка, шлюзы проверки, варианты регенерации): [references/workflow.md](https://github.com/NousResearch/hermes-agent/blob/main/optional-skills/creative/baoyu-comic/references/workflow.md).

## Изменение страницы

| Действие | Шаги |
|--------|-------|
| **Изменить** | **Обновить файл запроса ПЕРВЫМ** → восстановить изображение → загрузить новый PNG |

## Подводные камни

- Генерация изображения: 10-30 секунд на страницу; автоматический повтор один раз в случае неудачи
- **Всегда загружайте** URL-адрес, возвращаемый `image_generate`, в локальный PNG — последующие инструменты (и обзор пользователя) ожидают файлы в выходном каталоге, а не эфемерные URL-адреса.
- **Используйте абсолютные пути для `curl -o`** — никогда не полагайтесь на CWD постоянной оболочки между пакетами. Тихая стрельба: файлы попадают не в тот каталог, и последующее `ls` по намеченному пути ничего не показывает. См. шаг 7 «Шаг загрузки».
- Используйте стилизованные альтернативы для чувствительных общественных деятелей.
- **Требуется подтверждение шага 2** - не пропускать
- **Шаги 4 и 6 условные** – только по запросу пользователя на шаге 2.
- **Лист персонажа шага 7.1** — рекомендуется для многостраничных комиксов, необязательно для простых пресетов. PNG — это средство просмотра/восстановления; В подсказках страниц (написанных на шаге 5) используются текстовые описания в формате `characters/characters.md`, а не PNG. `image_generate` не принимает изображения в качестве визуальных данных.
- **Удалить секреты** — сканируйте исходный контент на наличие ключей API, токенов или учетных данных перед записью любого выходного файла.
