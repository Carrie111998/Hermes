# Простой английский: пишите как руководство по аэрокосмической отрасли

Напишите технический текст по правилам ASD-STE100 Simplified Технический английский. STE — это контролируемый язык, который производители аэрокосмической и оборонной промышленности используют для документации по техническому обслуживанию. Правила существуют для того, чтобы уставший читатель, не являющийся носителем английского языка, не мог неправильно прочитать инструкцию. В качестве побочного эффекта они удаляют обычные признаки текста, сгенерированного ИИ: длинные предложения, ротацию синонимов, изгороди, заполнители и декоративные предложения.

Пишите для этого уставшего читателя. Каждое предложение должно пережить одно прочтение.

## Как использовать это в Гермесе

Текст обычно приходит одним из трех способов:

1. **Встроенный.** Пользователь вставляет текст в сообщение. Перепишите его на место и ответьте о результате.
2. **Файл.** Пользователь указывает на файл (README, Runbook, страницу документации). Используйте `read_file`, чтобы загрузить его, затем `patch` для целевой перезаписи раздела или `write_file` для полной перезаписи. Никогда не трогайте блоки кода, идентификаторы или ошибки в кавычках (см. Неприкасаемые).
3. **Режим проверки.** Пользователь просит проверить текст на соответствие STE, а не переписывать его. Сообщайте о каждом нарушении, указывая номер правила + оскорбительный текст + переписывание в соответствии с требованиями, используя `references/checklist.md`.

Этот навык отличается от `humanizer`: гуманизатор восстанавливает естественный человеческий голос; Simple-English обеспечивает контролируемый язык технических инструкций. Этот навык можно использовать для документов, модулей Runbook и сообщений об ошибках. Для сообщений в блогах, эссе и личных писем используйте Humanizer. Не применяйте оба варианта к одному и тому же тексту.

## Ваша задача

Когда просят написать или переписать технический текст:

1. **Выберите режим** (прагматичный или строгий, см. ниже).
2. **Классифицируйте каждый отрывок** как процедурный или описательный. От этого зависит любое другое правило.
3. **Исправьте свой словарный запас перед составлением.** В строгом режиме используйте `make sure that` для концепции проверки/проверки/подтверждения/обеспечения — словарь отклоняет все четыре глагола. В прагматическом режиме выберите один и сохраните его. Выберите ОДНО существительное для конфигурации/настроек (все являются допустимыми техническими существительными — выберите одно и сохраните его). Не используйте никаких других слов для обозначения этих понятий во всем документе.
4. **Примените правила** из каталога ниже.
5. **Проведите самопроверку** перед доставкой. Этот шаг не является обязательным.
6. **Никогда не трогайте код**, идентификаторы, команды или ошибки в кавычках (см. Неприкасаемые).

Когда вас попросят ПРОВЕРИТЬ текст, а не писать его, сообщите о каждом нарушении, указав: номер правила, оскорбительный текст, переписывание в соответствии с требованиями. Указывайте только номера правил, которые существуют в этом файле. Не приводите номера правил по памяти: нумерация неинтуитивна, и ее придумывают модели (проверено — агент без этого файла приводил «Правило 3.1: короткие предложения»; настоящее Правило 3.1 — о формах глаголов).

## Два режима

| Режим | Когда | Что вы применяете |
|---|---|---|
| **Прагматичный** (по умолчанию) | Документы, файлы README, сообщения об ошибках — пользователю нужен открытый текст | Все структурные правила. Доменные слова остаются («идемпотент», «вебхук»). |
| **Строгий** | Имя пользователя STE, ASD-STE100 или соответствие | Структурные правила + полная словарная дисциплина и сообщают пользователю, что для полного соблюдения необходим официальный словарь (бесплатно на asd-ste100.org). |

## Шаг 1: Классифицируйте текст

| | Процедурные (инструкции) | Описательное (пояснения) |
|---|---|---|
| Цель | Расскажите читателю, что делать | Объясните, что это за вещь или что она делает |
| Глагольная форма | Императив: «Установить насос». | Простое настоящее/прошлое/будущее |
| Предел предложения | **20 слов** (Правило 5.1) | **25 слов** (Правило 6.3) |
| Правило единицы | Одна инструкция на предложение (5.2) | Одна тема в абзаце (6.5), максимум шесть предложений в абзаце (6.6) |

Не смешивайте эти два понятия в одном проходе. Раздел «Начало работы» является процедурным. Раздел «Архитектура» носит описательный характер. Примечание внутри процедуры носит описательный характер (не более 25 слов, без императива).

| 1,3 | Используйте одобренное слово только с его утвержденным значением. |
| 1,4 | Используйте только разрешенные формы глаголов и прилагательных. |

| 1,6 | Используйте неутвержденное слово только в том случае, если оно является техническим существительным или его частью. |
| 1,7 | Не используйте технические существительные в качестве глаголов. |
| 1,8 | Используйте технические существительные, относящиеся к вашему проекту или отрасли. |
| 1,9 | Когда вы выбираете техническое существительное, выбирайте короткое и ясное. |

| 1.12 | Вы можете использовать предметные глаголы в качестве технических глаголов («развертывание», «компиляция», «слияние»). |
| 1.13 | Не используйте технические глаголы в качестве существительных. |
| 1.14 | Используйте правописание американского английского языка. |

В прагматическом режиме правила 1.5, 1.8 и 1.12 выполняют тяжелую работу: ваш предметный словарь является законным. Агенты ломают 1.7, 1.11 и 1.13.

**До:** вы можете перехватить событие, а затем выполнить развертывание.
**После**. Отправьте событие в вебхук. Затем разверните службу.

| Правило | Инструкция |
|---|---|
| 2.1 | Напишите многословные существительные, состоящие из трех слов или меньше. |
| 2.2 | Если для технического существительного требуется более трех слов, напишите его полностью один раз, затем дайте краткую форму или расставьте единицы через дефис. |

Разрывайте длинные цепочки существительных предлогами (of, on, in, for):

**До:** значение конфигурации тайм-аута пула соединений.
**После:** значение тайм-аута для пула соединений.

### Раздел 3 — Глаголы (Правила 3.1–3.7)

| Правило | Инструкция |
|---|---|
| 3.1 | Используйте только те глагольные формы, которые дает словарь. |
| 3.2 | Используйте только: инфинитив, повелительное наклонение, простое настоящее, простое прошедшее, простое будущее, причастие прошедшего времени как прилагательное. |
| 3.3 | Используйте причастие прошедшего времени только как прилагательное («кэшированный ответ»). |
| 3,4 | Никаких вспомогательных глаголов для сложных конструкций. Никакого настоящего совершенства, никакого «должно быть установлено». |
| 3,5 | Используйте форму «-ing» только в качестве технического существительного или внутри него («регистрация», «монтажный кронштейн») и никогда в качестве глагола. |
| 3,6 | Активный голос. В описательном тексте пассив допустим только тогда, когда агент неизвестен. |
| 3,7 | Описывайте действие глаголом, а не существительным («сжать файл», а не «выполнить сжатие файла»). |

**Утвержденные модальные окна: can, will, must. Запрещено: следует, бы, можно, могло бы, могло бы.**
Стандарт отвергает «могло» даже как возможность: пишите «взрыв может произойти», никогда «могло произойти». Вместо «должен»: требование становится «должным»; предложение констатируется как факт или удаляется. Для инструкций агента это имеет двойное значение: в моделях слово «следует» считается необязательным.

**До:** Миграция завершена, и таблица перестраивается.
**После:** Миграция завершена. База данных перестраивает таблицу.

**До:** Флаг можно установить в файле конфигурации, что делает перезагрузку ненужной.
**После:** Вы можете установить флаг в файле конфигурации. Тогда перезагрузка не потребуется.

**До:** Необходимо отрегулировать температуру.
**После:** Отрегулируйте температуру.

### Раздел 4. Предложения (Правила 4.1–4.5)

| Правило | Инструкция |
|---|---|
| 4.1 | Пишите короткие и четкие предложения. |
| 4.2 | Не пропускайте слова и не используйте сокращения для сокращения предложений. Сохраняйте статьи, сохраняйте «то». |
| 4.3 | Используйте вертикальный список для сложного текста. |
| 4.4 | Используйте соединительные слова между предложениями по смежным темам («Тогда», «В результате»). |
| 4,5 | Поставьте артикль (the, a, an) или указательное прилагательное (this, эти) перед существительными, где это применимо. |

Правило 4.2 — это правило недопустимости краткости. СТЭ — это короткие предложения с полной грамматикой, а не телеграфным стилем:

**Неправильное сокращение:** Перед запуском убедитесь, что файл существует.
**STE:** Прежде чем запускать команду, убедитесь, что файл существует.

## СЛОВАРНАЯ ДИСЦИПЛИНА

Официальный словарь (~900 одобренных слов, ~1200 запрещенных слов с альтернативами) защищен авторскими правами ASD и здесь не воспроизводится. Его механика применима и без него: **одно слово, одно значение, одна часть речи.**

Известные постановления о части речи, полезные в качестве шаблонов:

| Слово | Постановление |
|---|---|
| тест, проверка, работа | Только существительное. «Проведите тест», а не «проверьте насос». «Проверьте, что X» становится «убедитесь, что X». |
| масло | Только техническое существительное (TN). Для глагола словарь дает «смазываться»: «Смазывать тягу маслом». |
| помощь | Только глагол. Для существительного в словаре указано «помощь»: «с помощью». |

## За пределами документации

Те же правила, разные цели. Полные адаптации в `references/use-cases.md`:

- **Сообщения об ошибках**: укажите, что произошло (простое прошлое), причину, если она известна, а затем обязательно устраните ее. Никаких «Упс», никаких «Пожалуйста, подтвердите», никаких извинений.
- **Runbooks**: родная территория STE. Обязательные шаги, сначала условия, предупреждения перед шагом.
- **Отчеты об инцидентах**: только прошлое. «Мы выявили проблему, которая могла повлиять» становится «Между 14:02 и 14:31 UTC 12% запросов завершились неудачно».
- **Примечания к выпуску**: критические изменения следуют шаблону предупреждения — сначала команда, потом риск.
- **Инструкции агента (подсказки, AGENTS.md)**: системная подсказка — это процедура для читателя, который не может задавать вопросы. Одна инструкция на предложение, никаких слов «следует», сначала условие.
- **Подготовка к переводу**: оригинальная работа STE. Одно значение каждого слова плюс полная грамматика устраняют большую часть двусмысленности перевода.

## Самопроверка перед доставкой

Этот шаг не является обязательным. Запустите эти четыре проверки вашего черновика:

1. Подсчитайте слова в трех самых длинных предложениях. Превышение лимита 20/25 → разделите их.
2. Найдите в черновике следующие слова: `'ll`, `'re`, `'s` (сокращение), `has been`, `have been`, `should`, `-ing` глаголов после запятой и точки с запятой.
3. Найдите все `if` и `when`. Каждый из них стоит в НАЧАЛЕ своего предложения, перед командой. «Увеличьте таймаут, если сеть медленная» → «Если сеть медленная, увеличьте таймаут».
4. Найдите глаголы, которые вы НЕ выбрали на шаге 3 вашей задачи (набор «проверить/проверить/подтвердить»). Замените каждое попадание выбранным вами глаголом.

Исправьте то, что найдете, а затем доставьте. Для полной проверки запустите `references/checklist.md`.

## Полный пример

**До (реальный неотредактированный результат ИИ):**

> **Тайм-ауты соединения.** Если sqlpipe зависает или выходит из строя с помощью `dial tcp: i/o timeout`, убедитесь, что хост, на котором работает sqlpipe, может достичь порта Postgres (обычно 5432) — часто это группа безопасности или правило брандмауэра, блокирующее соединение. Если вы подключаетесь к управляемой базе данных (RDS, Cloud SQL и т. д.), убедитесь, что экземпляр разрешает подключения с IP-адреса sqlpipe. Вы также можете попробовать увеличить `source.connect_timeout_seconds` в своей конфигурации, поскольку медленный сетевой путь может привести к отключению тайм-аута по умолчанию, даже если соединение в конечном итоге будет успешным.

**После (классифицированный процедурный, глагол = «убедиться», сначала условия, одна инструкция на предложение):**

> **Тайм-ауты соединения.** sqlpipe останавливается с `dial tcp: i/o timeout`, когда не может достичь порта Postgres (по умолчанию 5432).
>
> 1. Убедитесь, что хост, на котором работает sqlpipe, может получить доступ к порту Postgres. Брандмауэр или группа безопасности обычно блокируют его.
> 2. Если база данных управляемая (RDS, Cloud SQL), убедитесь, что экземпляр принимает соединения с IP-адреса sqlpipe.
> 3. Если сеть медленная, увеличьте `source.connect_timeout_seconds` в конфигурации.

## Ограничения

STE предназначен для технических фактов и инструкций. Не применяйте его к маркетинговому тексту, голосу в блоге или написанию бренда — он удаляет убеждение по замыслу. Когда пользователь запрашивает STE в маркетинговом тексте, скажите об этом и вместо этого предложите его для документации.

Этот навык является неофициальной помощью. Он не связан и не одобрен ASD или STEMG, и ни один инструмент не может гарантировать соответствие STE. ASD-STE100 является зарегистрированной торговой маркой ASD. Официальный стандарт можно бесплатно загрузить на asd-ste100.org.
