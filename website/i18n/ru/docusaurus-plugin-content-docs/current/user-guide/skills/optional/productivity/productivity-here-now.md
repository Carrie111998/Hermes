# здесь.сейчас

here.now позволяет агентам публиковать веб-сайты и хранить личные файлы на облачных дисках.

Используйте here.now для двух задач:

- **Сайты**: публикуйте веб-сайты и файлы на `{slug}.here.now`.
- **Диски**: храните файлы частного агента в облачных папках.

## Требования

- Требуемые двоичные файлы: `curl`, `file`, `jq`.
– Необязательная переменная среды: `$HERENOW_API_KEY`.
– Дополнительная переменная токена Диска: `$HERENOW_DRIVE_TOKEN`.
– Дополнительный файл учетных данных: `~/.herenow/credentials`.
- Пути помощников по навыкам:
  - `${HERMES_SKILL_DIR}/scripts/publish.sh` для сайтов публикации
  – `${HERMES_SKILL_DIR}/scripts/drive.sh` для частного хранилища на Диске.

## Создать сайт

```bash
PUBLISH="${HERMES_SKILL_DIR}/scripts/publish.sh"
bash "$PUBLISH" {file-or-dir} --client hermes
```

Выводит действующий URL-адрес (например, `https://bright-canvas-a7k2.here.now/`).

По сути, это трехэтапный процесс: создание/обновление -> загрузка файлов -> финализация. Сайт не работает до тех пор, пока не завершится успешно.

Без ключа API создается **анонимный сайт**, срок действия которого истекает через 24 часа.
При сохраненном ключе API сайт становится постоянным.

**Структура файла.** Для сайтов HTML размещайте `index.html` в корне публикуемого каталога, а не внутри подкаталога. Содержимое каталога становится корнем сайта. Например, опубликуйте `my-site/` там, где существует `my-site/index.html` — не публикуйте родительскую папку, содержащую `my-site/`.

Вы также можете публиковать необработанные файлы без HTML. Отдельные файлы получают богатую функцию автоматического просмотра (изображения, PDF, видео, аудио). Для нескольких файлов автоматически создается список каталогов с навигацией по папкам и галереей изображений.

## Обновить существующий сайт

```bash
PUBLISH="${HERMES_SKILL_DIR}/scripts/publish.sh"
bash "$PUBLISH" {file-or-dir} --slug {slug} --client hermes
```

Скрипт автоматически загружает `claimToken` из `.herenow/state.json` при обновлении анонимных сайтов. Передайте `--claim-token {token}` для переопределения.

Для обновлений, прошедших проверку подлинности, требуется сохраненный ключ API.

## Используйте диск

Используйте Диск, если пользователю нужно частное облачное хранилище для файлов агента: документов, контекста, памяти, планов, ресурсов, мультимедиа, исследований, кода и всего остального, что должно сохраняться без публикации на веб-сайте.

Каждая учетная запись, в которую выполнен вход, имеет Диск по умолчанию с именем `My Drive`.

```bash
DRIVE="${HERMES_SKILL_DIR}/scripts/drive.sh"
bash "$DRIVE" default
bash "$DRIVE" ls "My Drive"
bash "$DRIVE" put "My Drive" notes/today.md --from ./notes/today.md
bash "$DRIVE" cat "My Drive" notes/today.md
bash "$DRIVE" share "My Drive" --perms write --prefix notes/ --ttl 7d
```

Используйте токены Диска с ограниченной областью действия для передачи обслуживания от агента к агенту. Если вы получили общий блок `herenow_drive`, используйте его `token` как `Authorization: Bearer <token>` против `api_base`, соблюдайте `pathPrefix`, если он присутствует, и сохраняйте ETags при записи. `pathPrefix` из `null` означает полный доступ к Диску. Если навык доступен, отдайте предпочтение `drive.sh`; в противном случае вызовите перечисленные операции API напрямую.

## Хранилище ключей API

Скрипт публикации считывает ключ API из этих источников (выигрывает первое совпадение):

1. Флаг `--api-key {key}` (только CI/скрипты — избегать интерактивного использования)
2. Переменная среды `$HERENOW_API_KEY`.
3. Файл `~/.herenow/credentials` (рекомендуется для агентов)

Чтобы сохранить ключ, запишите его в файл учетных данных:

```bash
mkdir -p ~/.herenow && echo "{API_KEY}" > ~/.herenow/credentials && chmod 600 ~/.herenow/credentials
```

**ВАЖНО**: Получив API-ключ, немедленно сохраните его — выполните команду выше себя. Не просите пользователя запустить его вручную. Избегайте передачи ключа через флаги CLI (например, `--api-key`) в интерактивных сеансах; файл учетных данных является предпочтительным методом хранения.

Никогда не передавайте учетные данные или файлы локального состояния (`~/.herenow/credentials`, `.herenow/state.json`) в систему управления версиями.

## Получение API-ключа

Чтобы перейти с анонимного (24 часа) на постоянный сайт:

1. Попросите пользователя указать адрес электронной почты.
2. Запросите одноразовый код входа:

```bash
curl -sS https://here.now/api/auth/agent/request-code \
  -H "content-type: application/json" \
  -d '{"email": "user@example.com"}'
```

3. Скажите пользователю: «Проверьте свой почтовый ящик на наличие кода входа отсюда.сейчас и вставьте его сюда».
4. Проверьте код и получите ключ API:

```bash
curl -sS https://here.now/api/auth/agent/verify-code \
  -H "content-type: application/json" \
  -d '{"email":"user@example.com","code":"ABCD-2345"}'
```

5. Сохраните возвращенный `apiKey` самостоятельно (не просите это сделать пользователя):

```bash
mkdir -p ~/.herenow && echo "{API_KEY}" > ~/.herenow/credentials && chmod 600 ~/.herenow/credentials
```

## Файл состояния

После каждого создания/обновления сайта скрипт записывает данные в `.herenow/state.json` в рабочем каталоге:

```json
{
  "publishes": {
    "bright-canvas-a7k2": {
      "siteUrl": "https://bright-canvas-a7k2.here.now/",
      "claimToken": "abc123",
      "claimUrl": "https://here.now/claim?slug=bright-canvas-a7k2&token=abc123",
      "expiresAt": "2026-02-18T01:00:00.000Z"
    }
  }
}
```

Прежде чем создавать или обновлять сайты, вы можете проверить этот файл, чтобы найти предыдущие пули.
Считайте `.herenow/state.json` только внутренним кешем.
Никогда не указывайте этот локальный путь к файлу как URL-адрес и никогда не используйте его в качестве источника достоверных данных для режима аутентификации, истечения срока действия или URL-адреса утверждения.

## Что сказать пользователю

Для опубликованных сайтов:

- Всегда делитесь `siteUrl` из текущего запуска сценария.
– Прочитайте и следуйте `publish_result.*` строкам из стандартного кода сценария, чтобы определить режим аутентификации.
– При `publish_result.auth_mode=authenticated`: сообщите пользователю, что сайт **постоянный** и сохранен в его учетной записи. URL-адрес заявки не требуется.
– Когда `publish_result.auth_mode=anonymous`: сообщите пользователю, что срок действия сайта **срок действия истекает через 24 часа**. Поделитесь URL-адресом заявки (если `publish_result.claim_url` не пуст и начинается с `https://`), чтобы они могли сохранить его навсегда. Предупреждаем, что токены претензий возвращаются только один раз и не могут быть восстановлены.
– Никогда не просите пользователя проверить `.herenow/state.json` на предмет URL-адресов утверждений или статуса аутентификации.

Для приводов:

– Не называйте файлы Диска общедоступными URL-адресами.
– Сообщите пользователю, что содержимое диска является конфиденциальным, если только оно не предоставлено токену с ограниченной областью действия.
– При совместном доступе с другим агентом отдавайте предпочтение токену с ограниченной областью действия с узким `pathPrefix` и коротким сроком жизни.

## параметры публикации.sh

| Флаг | Описание |
| ---------------------- | -------------------------------------------- |
| `--slug {slug}` | Обновите существующий сайт вместо создания |
| `--claim-token {token}`| Переопределить токен утверждения для анонимных обновлений |
| `--title {text}` | Название просмотра (сайты, не использующие HTML) |
| `--description {text}` | Описание программы просмотра |
| `--ttl {seconds}` | Установить срок действия (только для аутентификации) |
| `--client {name}` | Имя агента для атрибуции (например, `hermes`) |
| `--base-url {url}` | Базовый URL-адрес API (по умолчанию: `https://here.now`) |
| `--allow-nonherenow-base-url` | Разрешить отправку аутентификации не по умолчанию `--base-url` |
| `--api-key {key}` | Переопределение ключа API (предпочитает файл учетных данных) |
| `--spa` | Включить маршрутизацию SPA (обслуживать index.html для неизвестных путей) |
| `--forkable` | Разрешить другим создавать форк этого сайта |
