# нарисуйте свой шрифт

Фото рукописных букв → устанавливаемый шрифт. Ты видишь
(найти и обозначить буквы, оценить качество); CLI выполняет всю геометрию (трассировку,
метрики, сборка шрифтов). Никогда не редактируйте пути или координаты SVG самостоятельно.

## Настройка в Гермесе (один раз за сеанс)

CLI — это закрепленный пакет npm `draw-your-font@0.1.0` — запустите его через npx (требуется узел ≥ 18, глобальная установка не требуется):

```bash
npx -y draw-your-font@0.1.0 --help
```

Если в приведенных ниже примерах показано `$DYF`, используйте `npx -y draw-your-font@0.1.0`. Переменные оболочки не сохраняются между вызовами инструментов, поэтому каждый раз вставляйте полную команду. Все работает локально; почерк пользователя никогда не покидает машину.

Фотографии поступают в Hermes либо в виде пути к файлу в сообщении, либо через кэш изображений шлюза — используйте фактический путь к файлу с помощью CLI. Когда фотография попадает в диалог без пути, запросите у пользователя файл (интерфейсу командной строки нужен реальный файл, а не ваша память об изображении).

Выполните визуальные действия (контактные листы, предварительный просмотр, листы глифов), загрузив PNG с помощью `vision_analyze`.

## Определите поток

- **У пользователя пока нет фотографии** → предложите шаблон: распечатайте, напишите, сфотографируйте.
- **Пользователь делится фотографиями, написанными от руки** → основной поток ниже.
- **Пользователь вставил изображение, но путь к файлу отсутствует** → вы можете его увидеть, но
  CLI нужен файл. Попросите их перетащить файл изображения в терминал (который
  вставляет свой путь) или укажите путь напрямую. Не исходите из памяти.
- **Пользователь хочет внести изменения в шрифт, созданный в этом сеансе** → раздел «Уточнить».

## Последовательность шаблонов (лучшее качество)

```bash
$DYF template -o template.pdf --charset minimal   # or: spanish
```

Скажите пользователю: распечатайте его, напишите по одному символу в каждом поле темной ручкой.
(0,5 мм+), держите букву на сплошной линии, затем сфотографируйте каждую.
страницу сверху при хорошем освещении и поделитесь путями к файлам. Сетка печатается в
светло-серые и исчезают при обработке — выживают только их чернила.

## Основной поток: фото → шрифт

**1. Segment.** Работает как для страниц шаблонов, так и для фотографий произвольной формы:

```bash
$DYF segment photo1.jpg photo2.jpg -d work
```

**2. Посмотрите и пометьте.** Загрузите `work/contact-1.png` с `vision_analyze` (по одному на фотографию): каждые
обнаруженный BLOB-объект пронумерован. На этом этапе ваши глаза имеют значение — проверьте:

- Каждому написанному персонажу досталось ровно по одной коробочке? Письмо, нарисованное с помощью
  отдельные штрихи могут отображаться в виде двух прямоугольников (переименование обрабатывает это: дайте основной
  закрасьте символ и отметьте фрагмент `""`), и две трогательные буквы могут
  поделитесь одним ящиком (попросите пользователя переснять только их или согласитесь с пробелом).
- Ненужные поля (тени, разлинованные линии, пятна, края страницы) → пометьте их `""`.

Затем напишите `work/labels.json` идентификатор BLOB-объекта → символ, например.
`{"0": "A", "1": "B", "7": "", "8": "a"}`:

- Страница шаблона: порядок — это порядок кодировки, напечатанный в шаблоне. Проверьте.
  против листа вместо того, чтобы слепо доверять ему. минимальный порядок: A–Z, a–z,
  0–9, затем `.,;:!?'"-()@#&+/$`; испанский добавляет `ÑñÁÉÍÓÚáéíóúü¿¡`.
- Свободная форма: определите каждую букву из контактного листа. Прописные буквы против
  строчные буквы для двойников формы (S/s, O/o, C/c, X/x…) определяются относительным размером
  и положение - сравните с соседями, в которых вы уверены.
- Пользователь рассказал вам, что написал (например, «ABC, затем abc»)? Поверьте, составьте карту
  порядок чтения (сначала верхний ряд, слева направо) и проверьте визуально.
- Одна и та же буква появляется дважды → отметьте ту, которая нарисована лучше, а другую `""`.

**3. Построить.**

```bash
$DYF build -d work --labels work/labels.json --name "Dan's Hand"
```

Назовите шрифт в честь пользователя (если неясно, спросите — максимум один короткий вопрос).

**4. Оцените перед доставкой.** Загрузите `work/preview.png` и `work/glyphs.png` с помощью `vision_analyze`.
и критикуй как арт-директор:

- Буквы с прерывистыми или пятнистыми буквами (плохой след) → часто слабый росчерк пера; попробуй
  `--weight 1` или попросите переснять это письмо.
- Все слишком тонкое/толстое → перестроить с помощью `--weight 1`/`--weight -1`.
- Неровные края → перестроить с помощью `--smooth 1.5` (до 2).
- Буква расположена неправильно (например, `g` не по убыванию) → обычно неправильная метка;
  исправьте labels.json и перестройте.
- Заполненные миски (b, o, g выглядят сплошными): этого никогда не должно происходить. Если это происходит,
  урожай размазан; попросить переснять.

Перестройки дешевы и безопасны для повторения. Сначала исправьте то, что можете сами;
Беспокоите пользователя о повторных съемках только в том случае, если проблема связана с исходными чернилами.

**5. Доставить.** Шрифт располагается по адресу `<workdir>/<NameWithoutSpaces>.ttf` (
выходные данные сборки печатают точный путь). Укажите этот путь и как установить:
macOS — двойной клик → «Установить шрифт»; Windows - клик правой кнопкой мыши → «Установить».
Упомяните, чего не хватает (в сборке печатаются непокрытые буквы) и предложите:
не нажимая:

– Веб-форматы + CSS: перестроить с помощью `--formats ttf,woff,woff2,css`.
- Прочтите разборчивость (ниже).
- Их следующая фотография, чтобы заполнить недостающие символы: перезапустите сегмент со ВСЕМИ.
  фотографии (старые и новые) в новую рабочую папку — `$DYF сегмент p1.jpg p2.jpg -d
  work2` — затем измените метку на новые контактные листы (идентификаторы больших двоичных объектов перенумеруются;
  старый labels.json не переносится) и создайте его из нового рабочего каталога.

## Уточнить (диалоговая итерация)

| Пользователь говорит | Делать |
|---|---|
| «более гладкий/круглый» | `build … --smooth 1.5` (максимум 2) |
| "толще/смелее" | `build … --weight 1` (максимум 2) |
| «тоньше/легче» | `build … --weight=-1` (для отрицательного результата требуется форма `=`) |
| «g выглядит плохо» | покажите им `work/crops/<id>.png` для этого письма; предлагаем перестрелку или сглаживание |
| «неправильная буква» / поменять местами | отредактировать labels.json, перестроить |
| "дайте мне woff2/web" | `build … --formats ttf,woff,woff2,css` |
| пользовательский текст предварительного просмотра | `$DYF preview -d work --text "…"` (после сборки) |

Все команды уточнения восстанавливаются из сохраненных данных — без повторного фотографирования.
необходимо, если только чернила сами по себе не являются проблемой.

## Отчет о разборчивости (предложение после доставки)

```bash
$DYF preview -d work --text "minimum mill rn m cl d I l 1 O 0 quick brown fox" -o work/legibility.png
```

Прочтите его и прочитайте честно и любезно: 10 баллов за использование основного текста,
2–3 пары букв, которые могут сбить с толку (rn→m, cl→d, I/l/1, O/0), и одна
или два конкретных исправления (перепишите эти буквы крупнее, с большим интервалом). Обратите внимание, что
Использование отображения (заголовков, примечаний) более щадящее, чем абзацев. Никогда не ворота
доставка по этому поводу - это совет, а не блокировщик.
