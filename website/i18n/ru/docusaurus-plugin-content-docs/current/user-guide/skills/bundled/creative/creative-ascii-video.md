# Конвейер видеопроизводства ASCII

## Когда использовать

Используйте, когда пользователи запрашивают: видео ASCII, видео с текстовой иллюстрацией, видео в стиле терминала, анимацию изображений персонажей, визуализацию ретро-текста, визуализатор звука в ASCII, преобразование видео в графику ASCII, эффекты в матричном стиле или любой анимированный вывод ASCII.

## Что внутри

Конвейер производства художественного видео ASCII — любого формата. Преобразует видео/аудио/изображения/генеративный входной сигнал в цветной видеовыход символов ASCII (MP4, GIF, последовательность изображений). Обложки: преобразование видео в ASCII, аудиореактивные музыкальные визуализаторы, генеративная художественная анимация ASCII, гибридное видео + аудио, наложение текста/текста, рендеринг терминала в реальном времени.

## Креативный стандарт

Это визуальное искусство. Символы ASCII являются средой; кино — это стандарт.

**Прежде чем писать одну строку кода**, сформулируйте креативную концепцию. Какое настроение? Какую визуальную историю это рассказывает? Что отличает ЭТОТ проект от любого другого видео ASCII? Подсказка пользователя — это отправная точка — интерпретируйте ее творчески, а не буквально.

**Превосходство при первом рендеринге не подлежит обсуждению.** Результат должен быть поразительным визуально и не требовать доработок. Если что-то выглядит стандартным, плоским или похожим на «искусство ASCII, созданное искусственным интеллектом», это неправильно — переосмыслите креативную концепцию перед отправкой.

**Выходите за рамки справочного словаря.** Каталоги эффектов, наборы настроек шейдеров и библиотеки палитр в справочниках представляют собой начальный словарь. Для каждого проекта комбинируйте, изменяйте и изобретайте новые шаблоны. Каталог — это палитра красок — вы пишете картину.

**Проявляйте творческий подход.** Расширяйте словарный запас навыков, когда этого требует проект. Если ссылки не соответствуют требованиям видения, создайте его. Включите хотя бы один визуальный момент, который пользователь не просил, но который он оценит — переход, эффект, выбор цвета, который возвышает весь фрагмент.

**Сплоченная эстетика важнее технической правильности.** Все сцены в видео должны быть связаны единым визуальным языком — общей цветовой температурой, связанной палитрой персонажей, единым словарем движений. Технически правильное видео, в котором в каждой сцене используется случайный эффект, является эстетическим провалом.

**Плотный, многослойный, продуманный.** Каждый кадр должен быть вознагражден за просмотр. Никогда не используйте плоский черный фон. Всегда многосеточная композиция. Всегда вариации для каждой сцены. Всегда намеренный цвет.

## Конвейерная архитектура

Каждый режим следует одному и тому же шестиэтапному конвейеру:

```
INPUT → ANALYZE → SCENE_FN → TONEMAP → SHADE → ENCODE
```

1. **ВХОД** — Загрузка/декодирование исходного материала (видеокадры, аудиосэмплы, изображения или ничего)
2. **АНАЛИЗ** — Извлечение покадровых характеристик (аудиополосы, яркость/границы видео, векторы движения)
3. **SCENE_FN** — функция сцены выполняет рендеринг на пиксельном холсте (`uint8 H,W,3`). Составляет несколько сеток символов с помощью режимов наложения `_render_vf()` + пикселей. См. `references/composition.md`.
4. **TONEMAP** — адаптивная нормализация яркости на основе процентилей. См. `references/composition.md` § Адаптивная карта тонов.
5. **SHADE** — Постобработка с помощью `ShaderChain` + `FeedbackBuffer`. См. `references/shaders.md`.
6. **ENCODE** — передача необработанных кадров RGB в ffmpeg для кодирования H.264/GIF.

### Варианты для каждого раздела

Никогда не используйте одну и ту же конфигурацию для всего видео. Для каждого раздела/сцены:
- **Различный фоновый эффект** (или составьте 2–3)
- **Разная палитра персонажей** (соответствует настроению)
- **Другая цветовая стратегия** (или, как минимум, другой оттенок)
- **Изменяйте интенсивность шейдера** (больше цветения во время пиков, больше зернистости в тишине)
- **Различные типы частиц**, если частицы активны.

## Критические замечания по реализации

### Яркость — используйте `tonemap()`, а не линейные множители

Это визуальная проблема №1. ASCII на черном по своей сути темный. **Никогда не используйте множители `canvas * N`** — они отсекают светлые участки. Используйте адаптивную карту тонов:

```python
def tonemap(canvas, gamma=0.75):
    f = canvas.astype(np.float32)
    lo, hi = np.percentile(f[::4, ::4], [1, 99.5])
    if hi - lo < 10: hi = lo + 10
    f = np.clip((f - lo) / (hi - lo), 0, 1) ** gamma
    return (f * 255).astype(np.uint8)
```

Трубопровод: `scene_fn() → tonemap() → FeedbackBuffer → ShaderChain → ffmpeg`

Гамма для каждой сцены: по умолчанию 0,75, соляризация 0,55, постеризация 0,50, яркие сцены 0,85. Используйте смесь `screen` (не `overlay`) для темных слоев.

### Высота ячейки шрифта

Подушка macOS: `textbbox()` возвращает неправильную высоту. Используйте `font.getmetrics()`: `cell_height = ascent + descent`. См. `references/troubleshooting.md`.

### тупик канала ffmpeg

Никогда `stderr=subprocess.PIPE` с длительно работающим ffmpeg — буфер заполняется до 64 КБ и возникают взаимоблокировки. Перенаправление в файл. См. `references/troubleshooting.md`.

### Совместимость шрифтов

Не все символы Юникода отображаются во всех шрифтах. Проверка палитр при инициализации — визуализируйте каждый символ, проверяйте пустой вывод. См. `references/troubleshooting.md`.

### Архитектура каждого клипа

Для сегментированных видео (цитаты, сцены, главы) визуализируйте каждое видео как отдельный файл клипа для параллельного рендеринга и выборочного повторного рендеринга. См. `references/scenes.md`.

## Креативное расхождение (используйте только тогда, когда пользователь запрашивает экспериментальный/креативный/уникальный результат)

Если пользователь требует творческого, экспериментального, неожиданного или нетрадиционного результата, выберите стратегию, которая лучше всего подходит, и проанализируйте ее шаги ПЕРЕД созданием кода.

- **Принудительные соединения** — когда пользователь хочет получить междоменное вдохновение («сделать его органичным», «промышленную эстетику»).
- **Концептуальное смешение** — когда пользователь называет два предмета, которые нужно объединить («океан встречается с музыкой», «космос + каллиграфия»).
- **Наклонные стратегии** — когда пользователь максимально открыт («удивите меня», «то, чего я никогда не видел»)

### Принудительные подключения
1. Выберите область, не связанную с визуальной целью (погодные системы, микробиология, архитектура, гидродинамика, текстильное плетение).
2. Перечислите его основные визуальные/структурные элементы (эрозия → постепенное раскрытие; митоз → расщепление-дублирование; переплетение → переплетающиеся узоры).
3. Сопоставьте эти элементы с символами ASCII и шаблонами анимации.
4. Синтезируйте — как выглядит «эрозия» или «кристаллизация» в сетке символов?

### Концептуальное смешение
1. Назовите два различных визуальных/концептуальных пространства (например, океанские волны + ноты).
2. Соответствия карты (гребни = высокие ноты, впадины = паузы, пена = стаккато)
3. Смешивайте выборочно — сохраняйте самые интересные сопоставления, отбрасывайте принудительные
4. Развивайте новые свойства, которые существуют только в смеси.

### Косвенные стратегии
1. Нарисуйте один: «Чти свою ошибку как скрытое намерение» / «Используй старую идею» / «Что бы сделал твой самый близкий друг?» / «Подчеркнуть недостатки» / «Перевернуть» / «Только часть, а не целое» / «Перевернуть»
2. Интерпретируйте директиву для текущей задачи анимации ASCII.
3. Примените нестандартный подход к визуальному дизайну перед написанием кода.
