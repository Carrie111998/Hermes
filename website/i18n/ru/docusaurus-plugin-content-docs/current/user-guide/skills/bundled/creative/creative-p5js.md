# p5.js Производственный конвейер

## Когда использовать

Используйте, когда пользователи запрашивают: эскизы p5.js, творческое кодирование, генеративное искусство, интерактивные визуализации, анимацию холста, визуальное искусство на основе браузера, визуализацию данных, эффекты шейдеров или любой проект p5.js.

## Что внутри

Производственный конвейер для интерактивного и генеративного визуального искусства с использованием p5.js. Создает эскизы на основе браузера, генеративное искусство, визуализацию данных, интерактивные возможности, 3D-сцены, аудиореактивные визуальные эффекты и анимационную графику — экспортируемые в форматы HTML, PNG, GIF, MP4 или SVG. Охватывает: 2D/3D-рендеринг, системы шума и частиц, поля потока, шейдеры (GLSL), манипуляции с пикселями, кинетическую типографику, сцены WebGL, анализ звука, взаимодействие мыши и клавиатуры и безголовый экспорт в высоком разрешении.

## Креативный стандарт

Это визуальное искусство, отображаемое в браузере. Холст — это среда; алгоритм — кисть.

**Прежде чем писать одну строку кода**, сформулируйте креативную концепцию. Что сообщает это произведение? Что заставляет зрителя перестать прокручивать? Что отличает это от примера руководства по коду? Подсказка пользователя — это отправная точка — интерпретируйте ее творчески.

**Превосходство при первом рендеринге не подлежит обсуждению.** Результат должен быть впечатляющим визуально при первой загрузке. Если это похоже на учебное упражнение по p5.js, конфигурацию по умолчанию или «творческое кодирование, созданное искусственным интеллектом», это неправильно. Подумайте еще раз перед отправкой.

**Выйдите за рамки справочного словаря.** Шумовые функции, системы частиц, цветовые палитры и шейдерные эффекты в справочниках представляют собой начальный словарь. Для каждого проекта комбинируйте, наслаивайте и изобретайте. Каталог — это палитра красок — вы пишете картину.

**Проявляйте творческий подход.** Если пользователь просит «систему частиц», предоставьте систему частиц с возникающим стеканием, следящими призрачными эхо, глубинным туманом со смещенной палитрой и фоновым шумовым полем, которое дышит. Добавьте хотя бы одну визуальную деталь, которую пользователь не просил, но которую он оценит.

**Плотный, многослойный, продуманный.** Каждый кадр должен быть вознагражден за просмотр. Никогда не используйте плоский белый фон. Всегда композиционная иерархия. Всегда намеренный цвет. Всегда микродетали, которые видны только при внимательном рассмотрении.

**Сплоченная эстетика важнее количества функций.** Все элементы должны служить единому визуальному языку — общей цветовой температуре, единообразному словарному запасу толщины штрихов, гармоничной скорости движения. Эскиз с десятью несвязанными эффектами хуже, чем эскиз с тремя взаимосвязанными эффектами.

### Примечание к версии

**p5.js 1.x** (1.11.3) — версия по умолчанию — стабильная, хорошо документированная, с самой широкой совместимостью библиотек. Используйте это, если проект не требует функций 2.x.

**p5.js 2.x** (2.2+) добавлено: `async setup()` вместо `preload()`, цветовые режимы OKLCH/OKLAB, `splineVertex()`, API шейдера `.modify()`, переменные шрифты, `textToContours()`, события указателя. Требуется для p5.brush. См. `references/core-api.md` § p5.js 2.0.

## Трубопровод

Каждый проект следует одному и тому же шестиэтапному пути:

```
CONCEPT → DESIGN → CODE → PREVIEW → EXPORT → VERIFY
```

1. **КОНЦЕПЦИЯ** — Сформулируйте творческое видение: настроение, цветовой мир, словарный запас движений, что делает это уникальным.
2. **ДИЗАЙН** — выберите режим, размер холста, модель взаимодействия, цветовую систему, формат экспорта. Сопоставьте концепцию с техническими решениями
3. **КОД** — напишите отдельный HTML-файл со встроенным p5.js. Структура: глобальные переменные → `preload()` → `setup()` → `draw()` → помощники → классы → обработчики событий.
4. **ПРОСМОТР** — откройте в браузере, проверьте качество изображения. Тестируйте при целевом разрешении. Проверьте производительность
5. **ЭКСПОРТ** — Захват выходных данных: `saveCanvas()` для PNG, `saveGif()` для GIF, `saveFrames()` + ffmpeg для MP4, Puppeteer для обезглавленного пакета.
6. **ПРОВЕРИТЬ** — Соответствуют ли выходные данные концепции? Поражает ли он визуально при предполагаемом размере дисплея? Вы бы подставили это?

### Правила изменения для каждого проекта

Никогда не используйте конфигурации по умолчанию. Для каждого проекта:
- **Пользовательская цветовая палитра** — никогда необработанная `fill(255, 0, 0)`. Всегда продуманная палитра из 3-7 цветов.
- **Пользовательский словарь толщины штрихов** — тонкие акценты (0,5), средняя структура (1–2), жирный акцент (3–5).
- **Фоновое лечение** — никогда не используйте обычные `background(0)` или `background(255)`. Всегда текстурированный, градиентный или многослойный
- **Разнообразие движений** — разные скорости для разных элементов. Первичный при 1x, вторичный при 0,3x, окружающий при 0,1x
- **Как минимум один изобретенный элемент** — собственное поведение частиц, новое применение шума, уникальный отклик взаимодействия.

### Изобретение, специфичное для проекта

Для каждого проекта придумайте хотя бы одно из:
- Пользовательская цветовая палитра, соответствующая настроению (не предустановленная)
- Новая комбинация шумового поля (например, шум скручивания + деформация домена + обратная связь)
- Уникальное поведение частиц (нестандартные силы, нестандартные следы, нестандартное появление)
- Механика взаимодействия, которую пользователь не запрашивал, но которая повышает качество произведения.
- Композиционный прием, создающий визуальную иерархию.

### Философия проектирования параметров

Параметры должны возникать из алгоритма, а не из общего меню. Спросите: «Какие свойства *этой* системы должны быть настраиваемыми?»

**Хорошие параметры** раскрывают характер алгоритма:
- **Количества** — сколько частиц, ветвей, ячеек (управляет плотностью)
- **Scale** — частота шума, размер элемента, интервал (управляет текстурой)
- **Rates** — скорость, скорость роста, затухание (управляет энергией)
– **Пороги** – когда поведение меняется? (контролирует драму)
- **Соотношения** — пропорции, баланс сил (управляет гармонией)

**Неверные параметры** — это общие элементы управления, не связанные с алгоритмом:
- «цвет1», «цвет2», «размер» — бессмысленно без контекста.
- Тумблеры для несвязанных эффектов
- Параметры, которые меняют только косметику, а не поведение

Каждый параметр должен менять то, как алгоритм *думает*, а не только то, как он *выглядит*. Параметр «турбулентности», меняющий октавы шума — это хорошо. Ползунок «размера частиц», который меняет только радиус `ellipse()`, неглубокий.

## Рабочий процесс

### Шаг 1: Креативное видение

Перед любым кодом сформулируйте:

- **Настроение/атмосфера**: что должен чувствовать зритель? Созерцательный? Энергичный? Неспокойно? Игривый?
- **Визуальная история**: что происходит со временем (или при взаимодействии)? Строить? Разлагаться? Трансформировать? Колебаться?
- **Мир цветов**: теплый/прохладный? Монохромный? Дополняющий? Какой оттенок преобладает? Акцент?
- **Язык форм**: органические кривые? Четкая геометрия? Точки? Линии? Смешанный?
- **Словарь движений**: Медленный дрейф? Взрывной взрыв? Дыхательный пульс? Механическая точность?
- **Чем ЭТО отличается**: Что делает этот эскиз уникальным?

Сопоставьте подсказку пользователя с эстетическим выбором. «Расслабляющий генеративный фон» требует всего отличного от «визуализации данных».

### Шаг 2: Техническое проектирование

- **Режим** — какой из 7 режимов из таблицы выше
- **Размер холста** — альбомная 1920x1080, портретная 1080x1920, квадратная 1080x1080 или адаптивный `windowWidth/windowHeight`.
- **Renderer** — `P2D` (по умолчанию) или `WEBGL` (для 3D, шейдеров, расширенных режимов наложения)
- **Частота кадров** — 60 кадров в секунду (интерактивная), 30 кадров в секунду (окружающая анимация) или `noLoop()` (статическая генеративная).
- **Объект экспорта** — отображение в браузере, кадр PNG, цикл GIF, видео MP4, вектор SVG.
- **Модель взаимодействия** — пассивная (без ввода), управление с помощью мыши, управление с помощью клавиатуры, звуковая реакция, управление с помощью прокрутки.
- **Интерфейс просмотра** — для интерактивного генеративного искусства начните с `templates/viewer.html`, который обеспечивает навигацию по начальным значениям, ползунки параметров и загрузку. Для простых эскизов или экспорта видео используйте чистый HTML.

### Шаг 3: Напишите код эскиза

Для **интерактивного генеративного искусства** (исследование семян, настройка параметров): начните с `templates/viewer.html`. Сначала прочтите шаблон, сохраните фиксированные разделы (исходная навигация, действия), замените элементы управления алгоритмом и параметрами. Это дает пользователю начальное число prev/next/random/jump, ползунки параметров с обновлением в реальном времени и загрузку PNG — все это подключено.

- **Объекты на основе классов**: частицы, агенты, формы как классы с методами `update()` + `display()`.
- **Закадровые буферы**: `createGraphics()` для многослойной композиции, следов и масок.

## Критические замечания по реализации

### Производительность — сначала отключите FES

Дружественная система ошибок (FES) увеличивает накладные расходы в 10 раз. Отключите его в каждом производственном эскизе:

```javascript
p5.disableFriendlyErrors = true;  // BEFORE setup()

function setup() {
  pixelDensity(1);  // prevent 2x-4x overdraw on retina
  createCanvas(1920, 1080);
}
```

В горячих циклах (частицы, пиксельные операции) используйте `Math.*` вместо оберток p5 — заметно быстрее:

```javascript
// In draw() or update() hot paths:
let a = Math.sin(t);          // not sin(t)
let r = Math.sqrt(dx*dx+dy*dy); // not dist() — or better: skip sqrt, compare magSq
let v = Math.random();        // not random() — when seed not needed
let m = Math.min(a, b);       // not min(a, b)
```

Никогда не `console.log()` внутри `draw()`. Никогда не манипулируйте DOM в `draw()`. См. `references/troubleshooting.md` § Производительность.

### Начальная случайность — всегда

Каждый генеративный эскиз должен быть воспроизводимым. То же семя, тот же результат.

```javascript
function setup() {
  randomSeed(CONFIG.seed);
  noiseSeed(CONFIG.seed);
  // All random() and noise() calls now deterministic
}
```

Никогда не используйте `Math.random()` для генеративного контента — только для критически важного к производительности невизуального кода. Всегда `random()` для визуальных элементов. Если вам нужно случайное начальное число: `CONFIG.seed = floor(random(99999))`.

### Поддержка платформы генеративного искусства (fxhash/Art Blocks)

Для платформ генеративного искусства замените PRNG p5 детерминированным случайным числом платформы:

```javascript
// fxhash convention
const SEED = $fx.hash;              // unique per mint
const rng = $fx.rand;               // deterministic PRNG
$fx.features({ palette: 'warm', complexity: 'high' });

// In setup():
randomSeed(SEED);   // for p5's noise()
noiseSeed(SEED);

// Replace random() with rng() for platform determinism
let x = rng() * width;  // instead of random(width)
```

См. `references/export-pipeline.md` § Экспорт платформы.

### Цветовой режим — используйте HSB

С HSB (Цветовой тон, Насыщенность, Яркость) значительно проще работать, чем с RGB для генеративного искусства:

```javascript
colorMode(HSB, 360, 100, 100, 100);
// Now: fill(hue, sat, bri, alpha)
// Rotate hue: fill((baseHue + offset) % 360, 80, 90)
// Desaturate: fill(hue, sat * 0.3, bri)
// Darken: fill(hue, sat, bri * 0.5)
```

Никогда не кодируйте необработанные значения RGB жестко. Определите объект палитры, процедурно получите варианты. См. `references/color-systems.md`.

### Шум — многооктавный, не сырой

Необработанный `noise(x, y)` выглядит как гладкие капли. Слой октав для естественной текстуры:

```javascript
function fbm(x, y, octaves = 4) {
  let val = 0, amp = 1, freq = 1, sum = 0;
  for (let i = 0; i < octaves; i++) {
    val += noise(x * freq, y * freq) * amp;
    sum += amp;
    amp *= 0.5;
    freq *= 2;
  }
  return val / sum;
}
```

Для плавных органических форм используйте **деформацию домена**: верните выходной шум в качестве входных координат шума. См. `references/visual-effects.md`.

### createGraphics() для слоев — необязательно

Плоский однопроходный рендеринг выглядит плоским. Используйте закадровые буферы для композиции:

```javascript
let bgLayer, fgLayer, trailLayer;
function setup() {
  createCanvas(1920, 1080);
  bgLayer = createGraphics(width, height);
  fgLayer = createGraphics(width, height);
  trailLayer = createGraphics(width, height);
}
function draw() {
  renderBackground(bgLayer);
  renderTrails(trailLayer);   // persistent, fading
  renderForeground(fgLayer);  // cleared each frame
  image(bgLayer, 0, 0);
  image(trailLayer, 0, 0);
  image(fgLayer, 0, 0);
}
```

### Производительность — векторизация, где это возможно

Вызовы отрисовки p5.js стоят дорого. Для тысяч частиц:

```javascript
// SLOW: individual shapes
for (let p of particles) {
  ellipse(p.x, p.y, p.size);
}

// FAST: single shape with beginShape()
beginShape(POINTS);
for (let p of particles) {
  vertex(p.x, p.y);
}
endShape();

// FASTEST: pixel buffer for massive counts
loadPixels();
for (let p of particles) {
  let idx = 4 * (floor(p.y) * width + floor(p.x));
  pixels[idx] = r; pixels[idx+1] = g; pixels[idx+2] = b; pixels[idx+3] = 255;
}
updatePixels();
```

См. `references/troubleshooting.md` § Производительность.

### Режим экземпляра для нескольких эскизов

Глобальный режим загрязняет `window`. Для производства используйте режим экземпляра:

```javascript
const sketch = (p) => {
  p.setup = function() {
    p.createCanvas(800, 800);
  };
  p.draw = function() {
    p.background(0);
    p.ellipse(p.mouseX, p.mouseY, 50);
  };
};
new p5(sketch, 'canvas-container');
```

Требуется при встраивании нескольких эскизов на одну страницу или интеграции с фреймворками.

### Проблемы с режимом WebGL

- `createCanvas(w, h, WEBGL)` — начало координат в центре, а не в левом верхнем углу.
- Ось Y инвертирована (положительный Y идет вверх в WEBGL, вниз в P2D)
- `translate(-width/2, -height/2)` для получения координат в формате P2D.
- `push()`/`pop()` вокруг каждого преобразования — стек матрицы переполняется автоматически
- `texture()` до `rect()`/`plane()` — не после
- Пользовательские шейдеры: `createShader(vert, frag)` — протестируйте в нескольких браузерах.

### Экспорт — соглашение о привязке клавиш

Каждый эскиз должен включать в `keyPressed()` следующее:

```javascript
function keyPressed() {
  if (key === 's' || key === 'S') saveCanvas('output', 'png');
  if (key === 'g' || key === 'G') saveGif('output', 5);
  if (key === 'r' || key === 'R') { randomSeed(millis()); noiseSeed(millis()); }
  if (key === ' ') CONFIG.paused = !CONFIG.paused;
}
```

### Экспорт видео без головы — используйте noLoop()

Для безголового рендеринга с помощью Puppeteer эскиз **должен** использовать `noLoop()` в настройке. Без него цикл отрисовки в p5 работает свободно, в то время как скриншоты работают медленно — эскиз мчится вперед, и вы получаете пропущенные/дублирующиеся кадры.

```javascript
function setup() {
  createCanvas(1920, 1080);
  pixelDensity(1);
  noLoop();                    // capture script controls frame advance
  window._p5Ready = true;      // signal readiness to capture script
}
```

Входящий в комплект `scripts/export-frames.js` обнаруживает `_p5Ready` и вызывает `redraw()` один раз за захват для точного соответствия кадров 1:1. См. `references/export-pipeline.md` § Детерминированный захват.

Для видео с несколькими сценами используйте архитектуру для каждого клипа: один HTML-код на сцену, рендеринг независимо, сшивка с помощью `ffmpeg -f concat`. См. `references/export-pipeline.md` § Архитектура каждого клипа.

### Рабочий процесс агента

При создании скетчей p5.js:

1. **Напишите HTML-файл** — отдельный автономный файл, весь код встроен в него.
2. **Открыть в браузере** — `open sketch.html` (macOS) или `xdg-open sketch.html` (Linux).
3. **Локальным ресурсам** (шрифтам, изображениям) требуется сервер: `python3 -m http.server 8080` в каталоге проекта, затем откройте `http://localhost:8080/sketch.html`.
4. **Экспорт PNG/GIF** — добавьте ярлыки `keyPressed()`, как показано выше, сообщите пользователю, какую клавишу нажимать.
5. **Безголовый экспорт** — `node scripts/export-frames.js sketch.html --frames 300` для автоматического захвата кадров (эскиз должен использовать `noLoop()` + `_p5Ready`)
6. **Рендеринг MP4** — `bash scripts/render.sh sketch.html output.mp4 --duration 30`
7. **Итеративное уточнение** — редактируйте HTML-файл, пользователь обновляет браузер, чтобы увидеть изменения.
8. **Загружать ссылки по требованию** — используйте `skill_view(name="p5js", file_path="references/...")` для загрузки определенных справочных файлов по мере необходимости во время реализации.

## Креативное расхождение (используйте только тогда, когда пользователь запрашивает экспериментальный/креативный/уникальный результат)

Если пользователь требует творческого, экспериментального, неожиданного или нетрадиционного результата, выберите стратегию, которая лучше всего подходит, и проанализируйте ее шаги ПЕРЕД созданием кода.

- **Концептуальное смешение** — когда пользователь называет две вещи, которые нужно объединить, или хочет создать гибридную эстетику.
- **SCAMPER** — когда пользователь хочет изменить известный шаблон генеративного искусства.
- **Ассоциация с расстоянием** — когда пользователь дает единую концепцию и хочет исследовать («сделать что-нибудь о времени»).

### Концептуальное смешение
1. Назовите две различные зрительные системы (например, физика элементарных частиц + почерк).
2. Соответствия карты (частицы = капли чернил, силы = давление пера, поля = формы букв)
3. Смешивайте выборочно — сохраняйте сопоставления, которые создают интересные визуальные эффекты.
4. Кодируйте смесь как единую систему, а не как две системы, стоящие бок о бок.

### СКАМПЕР Трансформация
Возьмите известный генеративный паттерн (поле потока, система частиц, L-система, клеточные автоматы) и систематически преобразуйте его:
- **Заменить**: заменить круги текстовыми символами, линии градиентами.
- **Объединить**: объединить два шаблона (поле потока + вороной).
- **Адаптация**: применение 2D-шаблона к 3D-проекции.
- **Изменить**: увеличить масштаб, исказить координатное пространство.
- **Цель**: использовать физический симулятор для типографики, алгоритм сортировки по цвету.
- **Устранить**: удалить сетку, удалить цвет, удалить симметрию.
- **Обратный**: запустить моделирование в обратном направлении, инвертировать пространство параметров.

### Ассоциация Дистанций
1. Закрепите концепцию пользователя (например, «одиночество»).
2. Сформируйте ассоциации на трех расстояниях:
   - Близко (очевидно): пустая комната, одинокая фигура, тишина.
   - Средний (интересный): одна рыбка в косяке плывёт не в ту сторону, телефон без уведомлений, разрыв между вагонами метро.
   - Далеко (аннотация): простые числа, асимптотические кривые, цвет 3 утра.
3. Развивайте ассоциации на среднем расстоянии — они достаточно конкретны, чтобы их можно было визуализировать, но достаточно неожиданны, чтобы быть интересными.
