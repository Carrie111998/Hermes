# Конвейер собраний команд

Используйте этот навык всякий раз, когда пользователь задает вопросы о сводках собраний Microsoft Teams, стенограммах, записях, элементах действий, подписках на графики или любой рабочий вопрос о конвейере собраний Teams. Работает на любом языке. Триггеры ниже являются примерами, а не исчерпывающим списком.

Все, что касается оператора, — это подкоманда `hermes teams-pipeline`, запускаемая через инструмент терминала. Для этого конвейера нет новых инструментов модели — CLI — это поверхность.

## Когда использовать этот навык

Пользователь просит:
- подводить итоги собрания Teams/извлекать элементы действий/извлекать заметки о собрании
- проверить состояние конвейера, проверить сохраненное задание на собрание или просмотреть последние собрания.
- воспроизвести/перезапустить сохраненное задание, которое не удалось или требует свежей сводки
- проверьте настройку Microsoft Graph после изменения среды или конфигурации.
- Устранение неполадок «сводка собрания не получена» или «новые собрания не принимаются»
- управлять подписками на веб-перехватчики Graph (создавать, обновлять, удалять, проверять)
- настроить автоматическое продление подписки (см. подводный камень ниже)

Примеры многоязычных триггеров (не исчерпывающие):
- Английский: «подвести итоги собрания Teams», «состояние конвейера», «воспроизвести задание X».
- Турецкий: «Команды встречаются özetle», «пункт действия çıkar», «toplantı notu», «конвейер дуруму», «повторить задание».

## Предварительные условия

Прежде чем использовать конвейер, убедитесь, что они установлены в `${HERMES_HOME:-~/.hermes}/.env`:

```bash
MSGRAPH_TENANT_ID=...
MSGRAPH_CLIENT_ID=...
MSGRAPH_CLIENT_SECRET=...
```

Если какие-либо из них отсутствуют, направьте пользователя к руководству по регистрации приложений Azure по адресу `/docs/guides/microsoft-graph-app-registration` — им необходима регистрация приложения Azure AD с разрешениями приложения Graph, согласованными с администратором, прежде чем конвейер заработает.

## Справочник команд

### Статус и проверка (начните здесь)

```bash
hermes teams-pipeline validate              # config snapshot — run first after any change
hermes teams-pipeline token-health          # Graph token status
hermes teams-pipeline token-health --force-refresh   # force a fresh token acquisition
hermes teams-pipeline list                  # recent meeting jobs
hermes teams-pipeline list --status failed  # only failed jobs
hermes teams-pipeline show <job-id>         # full detail of one job
hermes teams-pipeline subscriptions         # current Graph webhook subscriptions
```

### Перезапуск/отладка

```bash
hermes teams-pipeline run <job-id>          # replay a stored job (re-summarize, re-deliver)
hermes teams-pipeline fetch --meeting-id <id>   # dry-run: resolve meeting + transcript without persisting
hermes teams-pipeline fetch --join-web-url "<url>"   # dry-run by join URL
hermes teams-pipeline fetch --join-web-url "<url>" --organizer-user-id <id>   # organizer-scoped lookup (required for /meet/ short URLs)
```

### Управление подпиской

```bash
hermes teams-pipeline subscribe \
  --resource communications/onlineMeetings/getAllTranscripts \
  --notification-url https://<your-public-host>/msgraph/webhook \
  --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE"

hermes teams-pipeline renew-subscription <sub-id> --expiration <iso-8601>
hermes teams-pipeline delete-subscription <sub-id>
hermes teams-pipeline maintain-subscriptions            # renew near-expiry ones
hermes teams-pipeline maintain-subscriptions --dry-run  # show what would be renewed
```

## Дерево решений для часто задаваемых вопросов

- Пользователь спрашивает: «Почему я не получил резюме сегодняшней встречи?» → начните с `list --status failed`, затем `show <job-id>` в соответствующей строке. Если задание вообще не существует, проверьте `subscriptions` — возможно, срок действия вебхука истек (см. ошибку ниже).
- Пользователь спрашивает: «Настройка работает?» → `validate`, затем `token-health`, затем `subscriptions`. Если все три пройдены, запросите тестовую встречу и проверьте `list` на наличие новой строки.
- Пользователь запрашивает «перезапустить сводку для собрания X» → `list`, чтобы найти идентификатор задания, `run <job-id>` для воспроизведения. Если снова произойдет сбой, `show <job-id>` для проверки ошибки и `fetch --meeting-id` для пробного устранения артефактов.
- Пользователь запрашивает «добавить собрание X в конвейер» → обычно вы этого не делаете — конвейер основан на подписке, а не на собраниях. Если они хотят подвести итоги конкретной прошлой встречи, используйте `fetch` для получения стенограммы + `run` после создания задания.

## Критическая ошибка: срок действия подписки на график истекает через 72 часа.

Microsoft Graph ограничивает подписку на веб-перехватчик 72 часами и **не будет ее автоматически продлевать**. Если `maintain-subscriptions` не запланировано, уведомления о собраниях автоматически перестанут приходить через 3 дня после создания подписки вручную.

Когда пользователь сообщает: «Вчера конвейер работал, но сегодня ничего не поступает»:
1. Запустите `hermes teams-pipeline subscriptions` — если он пуст или все записи в прошлом показывают `expirationDateTime`, причина в этом.
2. Воссоздайте с помощью `subscribe`, как показано выше.
3. **Немедленно настройте автоматическое продление** через `hermes cron add`, системный таймер или простой файл crontab. Runbook оператора в `/docs/guides/operate-teams-meeting-pipeline#automating-subscription-renewal-required-for-production` имеет все три параметра. 12-часовой интервал безопасен (6-кратный запас по сравнению с пределом в 72 часа).

## Другие подводные камни

- **Стенограмма пока недоступна.** После завершения собрания Teams требуется некоторое время для создания артефакта стенограммы. `fetch --meeting-id` на только что завершившейся встрече может вернуться пустым. Подождите 2–5 минут и повторите попытку или позвольте веб-перехватчику Graph естественным образом управлять приемом данных.
- **Несоответствие режима доставки.** Если сводки создаются (`list` показывает успех), но ничего не попадает в Teams, проверьте `platforms.teams.extra.delivery_mode` и соответствующую целевую конфигурацию (`incoming_webhook_url` OR `chat_id` OR `team_id`+`channel_id`). Модуль записи считывает их из переменных config.yaml или `TEAMS_*` env.
- **Разрешения приложения Graph.** Токен получается без ошибок (`token-health` проходит), но вызовы API Graph возвращают код 401/403, если разрешения были добавлены, но согласие администратора не было предоставлено повторно. Попросите пользователя повторно посетить регистрацию приложения на портале Azure и еще раз нажать «Предоставить согласие администратора».
