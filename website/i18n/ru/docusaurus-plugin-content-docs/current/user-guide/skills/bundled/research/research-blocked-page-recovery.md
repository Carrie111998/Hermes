# Восстановление заблокированной страницы

Когда страница не загружается — 403/429, Cloudflare «Минуточку...», платный доступ,
или межстраничное объявление для обнаружения ботов — не сдавайтесь и не зацикливайтесь на том же
URL-адрес. Сторонние службы часто хранят **копию** страницы. Работайте над этим
лестница, сначала самая дешевая.

## Лестница

```
1. Wayback Machine  — archive.org "available" API  (snapshot + timestamp)
2. archive.today    — domain rotation: archive.ph → .md → .li → .is
3. Jina Reader      — only if JINA_API_KEY is set  (live server-side render)
4. API-first pivot  — look for /api/, /graphql, .json, or RSS on the same host
5. Real browser     — browser tool as the last, most expensive resort
```

Запустите его за один раз с помощью прилагаемого скрипта:

```bash
python3 scripts/recover_page.py "https://example.com/blocked-article" --json
```

Скрипт пробует каждый маршрут по порядку, проверяет каждое тело (см.
успехи» ниже) и печатает первый настоящий хит своего происхождения.

## Дисциплина происхождения (не подлежит обсуждению)

Каждая восстановленная копия имеет происхождение, которое вы ДОЛЖНЫ сохранять при цитировании:

| Маршрут | Провенанс | Как цитировать |
|-------|-----------|-------------|
| Wayback / archive.today | `snapshot` | Цитируйте С датой снимка: «в архиве: 6 августа 2026 г.». Никогда не представляйте снимок как живую страницу — он может быть устаревшим. |
| Джина Ридер | `live` | Серверный повторный рендеринг живой страницы; цитируйте нормально. |
| Загрузка в реальном времени / браузер | `live` | Цитируйте нормально. |

Если пользователю нужны *текущие* данные (цены, наличие, последние новости),
снимок — это контекст, а не ответ — скажите об этом прямо и обратите внимание на его возраст.

## Маршруты вручную

### 1. Wayback Machine (лучшее происхождение, попробуйте сначала)

```bash
# Discovery: returns closest snapshot URL + timestamp as JSON
curl -sL "https://archive.org/wayback/available?url={URL}"
# Then fetch archived_snapshots.closest.url
```

Для подсчета множества снимков (или восстановления удаленных страниц) индекс CDX:

```bash
curl -sL "https://web.archive.org/cdx/search/cdx?url={URL}&output=json&limit=10"
```

CDX периодически возвращает 503 под нагрузкой — если это так, вернитесь к
`available` API; не пытайтесь повторить - забейте его.

Подходит для: любого общедоступного URL-адреса. Не подходит для: сайтов, заблокированных роботами,
никогда не сканируемые URL-адреса, SPA только для JS (снимки не отображаются).

### 2. archive.today (платный доступ, удаленный контент)

Архивы, предоставленные пользователями — часто содержат платные новостные статьи, которых нет в Wayback.
Активно ограничивает скорость (429) и ротирует домены, поэтому повторяйте:

```bash
for d in archive.ph archive.md archive.li archive.is; do
  curl -sL --max-time 20 "https://$d/newest/{URL}" -o /tmp/page.html \
    -w "%{http_code}" && break
done
```

**Проверяйте тело, а не код состояния** — 429 по-прежнему отправляет несколько КБ
HTML-код с ограничением скорости, который выглядит успешным только при проверке размера.

### 3. Jina Reader (требуется JINA_API_KEY)

`r.jina.ai` повторно отображает живую страницу на стороне сервера реального браузера и
возвращает уценку. Анонимный доступ отключен (401 → Турникет); ключ это
требуется:

```bash
curl -s -H "Authorization: Bearer $JINA_API_KEY" "https://r.jina.ai/{URL}"
```

Обрабатывает JS SPA, которые не поддерживаются архивами. Полностью пропустите этот маршрут, когда env
var не установлен.

### 4. API-первый поворот

WAF защищают поверхность HTML гораздо более агрессивно, чем конечные точки данных.
за этим. После 2-3 заблокированных попыток входа на сайт прекратите борьбу с HTML и
ищите:

– `/api/...`, `/graphql` или `.json` вариантов URL страницы.
- Канал RSS/Atom (`/feed`, `/rss`, `<link rel="alternate">` в любой копии)
  ты выздоровел)
– Карта сайта (`/sitemap.xml`), показывающая канонические URL-адреса, которые не могут быть закрыты.

## Фальшивые успехи — маршруты, которые ЛОЖЬ

Они возвращают HTTP 200 с вероятным телом, которое НЕ является страницей. Сценарий
автоматически отклоняет их; отклонить их также вручную:

- **Кэш Google не работает** (с середины 2024 г.). `webcache.googleusercontent.com`
  возвращает 200+ десятков КБ, но это межстраничное объявление Google Search с JS
  редирект, а не кеш. Никогда не используйте его.
- **Кэши AMP** (`*.cdn.ampproject.org`) в основном возвращают ~300-байтовые данные.
  `<title>Redirecting</title>` заглушка метаобновления, указывающая на
  исходный (заблокированный) URL. Если рассматривать это как успех, возникает цикл выборки.
- **Тела с ограничением скорости**: archive.today 429 страниц представляют собой HTML-код размером несколько КБ. Проверьте
  фактическое содержимое цели (слова заголовка, ожидаемые строки), а не только размер.

Эвристика обнаружения, которую применяет сценарий: тело под минимальным количеством байтов для каждого маршрута;
заглушки метаобновления/JS-перенаправления, целью которых является исходный хост; межстраничный
заголовки («Минутку», «Перенаправление», «Поиск в Google», «Требуется внимание»).

## Прокси-реле: нет

Общие ретрансляторы «веб-прокси» по своей конструкции являются посредниками. Никогда не отправлять
файлы cookie или заголовки авторизации через один и не используйте их ни для чего.
на что будет полагаться пользователь — происхождение невозможно проверить. Предпочитаю архивы, которые в
наименьшую временную метку своих копий.
