# Претекст Креативные демонстрации

## Обзор

[`@chenglou/pretext`](https://github.com/chenglou/pretext) — это библиотека TypeScript размером 15 КБ с нулевой зависимостью от Cheng Lou (ядро React, ReasonML, Midjourney) для **изменения и макетирования многострочного текста без DOM**. Он делает одно: учитывая `(text, font, width)`, возвращает разрывы строк, ширину каждой строки, позиции каждой графемы и общую высоту — все через измерение холста, без перекомпоновки.

Это похоже на водопровод. Это не. Поскольку он быстрый и геометрический, это **творческий примитив**: вы можете перекомпоновать абзацы вокруг движущегося спрайта со скоростью 60 кадров в секунду, создавать игры, геометрия уровней которых состоит из реальных слов, пропускать логотипы ASCII через прозу, разбивать текст на частицы с точными начальными позициями для каждой графемы или упаковывать многострочный пользовательский интерфейс в термоусадочную пленку без каких-либо `getBoundingClientRect` помех.

Этот навык существует для того, чтобы Hermes мог создавать с его помощью **классные демо** — такие добрые люди публикуют сообщения в X. См. `pretext.cool` и `chenglou.me/pretext`, чтобы ознакомиться с корпусом демонстраций сообщества.

## Когда использовать

Используйте, когда пользователь запрашивает:
- «Демо-предлог» / «крутая штука с предлогом» / «текст как-X»
- Текст обтекает движущуюся фигуру (главные разделы, редакционные макеты, анимированные длинные страницы).
- ASCII-арт-эффекты с использованием **реальных слов или прозы**, а не моноширинных растров.
- Игры, в которых игровое поле/препятствия/кирпичики состоят из текста (Тетрис из букв, Прорыв прозы)
- Кинетическая типографика с физикой каждого глифа (разбиение, разброс, стекание, поток)
- Типографское генеративное искусство, особенно с нелатинским или смешанным шрифтом.
- Многострочный пользовательский интерфейс с термоусадочной пленкой (наименьшая ширина контейнера, которая по-прежнему умещается в тексте)
- Все, что требует знания разрывов строк *перед* рендерингом.

Не используйте для:
- Статические страницы SVG/HTML, где CSS уже решает макет — просто используйте CSS.
- Редакторы расширенного текста, общие механизмы встроенного форматирования (предтекст намеренно узкий)
- Изображение → текст (используйте навыки `ascii-art` / `ascii-video`)
- Чистое генеративное искусство на холсте без текстовой роли — используйте `p5js`.

## Креативный стандарт

Это визуальное искусство, отображаемое в браузере. Предтекст возвращает числа; **ты** рисуешь эту штуку.

- **Не выпускайте демо-версию «Hello World».** Шаблон `hello-orb-flow.html` — это *отправная* точка. Каждая представленная демонстрация должна намеренно добавлять цвет, движение, композицию и одну визуальную деталь, которую пользователь не просил, но которая оценит.
- **Темный фон, теплые основные цвета, продуманная палитра.** Классический янтарный на черном (ЭЛТ/терминал) работает, но также работает холодный белый на угле (редакционный) и ненасыщенные пастельные тона (ризограф). Выберите один и зафиксируйте.
- **Главное — пропорциональные шрифты.** Вся атмосфера Pretext — «не моноширинная» — опирайтесь на нее. Используйте Iowan Old Style, Inter, JetBrains Mono, Helvetica Neue или другой шрифт. Никогда не используйте стандартный sans.
- **Реальный источник/текст, а не lorem ipsum.** Корпус должен что-то означать. Короткие манифесты, поэзия, реальный исходный код, найденный текст, собственный README библиотеки — никогда `lorem ipsum`.
- **Превосходство первой покраски.** Никаких состояний загрузки и пустых рамок. Демо-версия должна выглядеть готовой к отправке в момент ее открытия.

## Стек

Один отдельный HTML-файл для каждой демо-версии. Нет этапа сборки.

| Слой | Инструмент | Цель |
|-------|------|---------|
| Ядро | `@chenglou/pretext` через `esm.sh` CDN | Измерение текста + расположение линий |
| Рендеринг | HTML5 Холст 2D | Рендеринг глифов, покадровая композиция |
| Сегментация | `Intl.Segmenter` (встроенный) | Разбиение графемы для эмодзи/CJK/комбинирования знаков |
| Взаимодействие | Необработанные события DOM | Мышь/сенсор/колесо — без рамок |

```html
<script type="module">
import {
  prepare, layout,                   // use-case 1: simple height
  prepareWithSegments, layoutWithLines,  // use-case 2a: fixed-width lines
  layoutNextLineRange, materializeLineRange, // use-case 2b: streaming / variable width
  measureLineStats, walkLineRanges,  // stats without string allocation
} from "https://esm.sh/@chenglou/pretext@0.0.6";
</script>
```

Закрепите версию. `@0.0.6` на момент написания — проверьте [npm](https://www.npmjs.com/package/@chenglou/pretext) на наличие последних обновлений, если демо-версия отключена.

## Два варианта использования

Почти все сводится к одной из этих двух форм. Изучите оба.

### Вариант использования 1 — измерение, а затем рендеринг с помощью CSS/DOM

```js
const prepared = prepare(text, "16px Inter");
const { height, lineCount } = layout(prepared, 320, 20);
```

Вы по-прежнему позволяете браузеру рисовать текст. Предтекст просто сообщает вам, какой высоты будет блок при заданной ширине, **без** чтения DOM. Используйте для:
- Виртуализированные списки, строки которых содержат переносимый текст.
- Кладка с точной высотой карты
- «Подходит ли эта этикетка?» проверки во время разработки
- Предотвращение смещения макета при загрузке удаленного текста.

**Сохраняйте `font` и `letterSpacing` в точной синхронизации с вашим CSS.** Формат холста `ctx.font` (например, `"16px Inter"`, `"500 17px 'JetBrains Mono'"`) должен соответствовать отображаемому CSS, иначе измерения будут отклоняться.

### Вариант использования 2 — измерить *и* визуализировать себя

```js
const prepared = prepareWithSegments(text, FONT);
const { lines } = layoutWithLines(prepared, 320, 26);
for (let i = 0; i < lines.length; i++) {
  ctx.fillText(lines[i].text, 0, i * 26);
}
```

Здесь живет творчество. Рисунок принадлежит вам, поэтому вы можете:
- Рендеринг в холст, SVG, WebGL или любую другую систему координат.
- Замена преобразований для каждого глифа (вращение, дрожание, масштаб, непрозрачность)
- Использовать метаданные линии (ширину, положение графемы) в качестве геометрии.

Для потока **переменной ширины строки** (текст вокруг фигуры, текст в кольцевой полосе, текст в непрямоугольном столбце):

```js
let cursor = { segmentIndex: 0, graphemeIndex: 0 };
let y = 0;
while (true) {
  const lineWidth = widthAtY(y);  // your function: how wide is the corridor at this y?
  const range = layoutNextLineRange(prepared, cursor, lineWidth);
  if (!range) break;
  const line = materializeLineRange(prepared, range);
  ctx.fillText(line.text, leftEdgeAtY(y), y);
  cursor = range.end;
  y += lineHeight;
}
```

Это самый важный шаблон во всей библиотеке. Это то, что открывает «текст, обтекающий перетаскиваемый спрайт» — демоверсию, которая стала вирусной на X.

### Помощники, о которых стоит знать

- `measureLineStats(prepared, maxWidth)` → `{ lineCount, maxLineWidth }` — самая широкая линия, т.е. ширина многострочной термоусадочной пленки.
- `walkLineRanges(prepared, maxWidth, callback)` — перебирать строки без выделения строк. Используйте для статистики/физики вместо графем, когда символы вам не нужны.
- `@chenglou/pretext/rich-inline` — та же система, но для абзацев смешиваются шрифты/фишки/упоминания. Импорт из подпути.

## Шаблоны демонстрационных рецептов

Корпус сообщества (см. `references/patterns.md`) группируется в несколько устойчивых шаблонов. Выберите одну и придумайте рифф — не изобретайте новую категорию, если вас об этом не попросят.

| Узор | Ключевой API | Пример идеи |
|---|---|---|
| **Перекомпоновка вокруг препятствия** | `layoutNextLineRange` + функция ширины каждой строки | Редакционный абзац, который разделяется вокруг спрайта перетаскиваемого курсора |
| **Игра «Текст как геометрия»** | `layoutWithLines` + прямоугольники столкновений по строкам | Прорыв, где каждый кирпичик — измеренное слово |
| **Расколы/частицы** | `walkLineRanges` → пографема (x,y) → физика | Предложение, которое при нажатии распадается на буквы |
| **Типографика препятствий ASCII** | `layoutNextLineRange` + измеренное расстояние между препятствиями для каждого ряда | Растровый логотип ASCII, морфы фигур и перетаскиваемые проволочные объекты, которые открывают текст вокруг их фактической геометрии |
| **Редакционная многоколонка** | `layoutNextLineRange` на столбец + общий курсор | Анимированный разворот журнала с цитатами |
| **Кинетический тип** | `layoutWithLines` + построчное преобразование с течением времени | «Звездные войны»: ползание, волнение, подпрыгивание, сбой |
| **Многострочная термоусадочная упаковка** | `measureLineStats` | Котировочная карточка, которая автоматически подстраивается под самый тесный контейнер |

См. `templates/donut-orbit.html` и `templates/hello-orb-flow.html` для работы с однофайловыми пускателями.

## Рабочий процесс

1. **Выберите шаблон** из таблицы выше, основываясь на задании пользователя.
2. **Начать с шаблона**:
   - `templates/hello-orb-flow.html` — обтекание текста вокруг движущегося шара (шаблон обтекания препятствий)
   - `templates/donut-orbit.html` — расширенный пример: измеренные препятствия с логотипом ASCII, перетаскиваемая проволочная сфера/куб, морфинг полей формы, выбираемый текст DOM и элементы управления, доступные только для разработчиков.
   - `write_file` на новый `.html` в `/tmp/` или в рабочей области пользователя.
3. **Замените корпус** на что-то специальное для задания. Настоящая проза, 10-100 предложений, без лорем.
4. **Настройте эстетику** — шрифт, палитру, композицию, взаимодействие. Это работа; не пропускай это.
5. **Проверьте локально**:
   ```sh
   cd <dir-with-html> && python3 -m http.server 8765
   # then open http://localhost:8765/<file>.html
   ```
6. **Проверьте консоль** — претекст выдастся, если `prepareWithSegments` вызывается с неверной строкой шрифта; `Intl.Segmenter` доступен в каждом современном браузере.
7. **Покажите пользователю путь к файлу**, а не только код — он хочет его открыть.

## Примечания по производительности

- `prepare()` / `prepareWithSegments()` — дорогой вызов. Сделайте это **один раз** для каждой пары текст+шрифт. Кэшируйте дескриптор.
- При изменении размера повторно запускайте только `layout()` / `layoutWithLines()` — никогда не выполняйте повторную подготовку.
- Для покадровой анимации, где текст не меняется, но меняется геометрия, `layoutNextLineRange` в узком цикле достаточно дешев, чтобы обрабатывать каждый кадр со скоростью 60 кадров в секунду для абзацев нормальной длины.
- При рендеринге масок ASCII для каждого кадра сохраняйте буфер ячеек (`Uint8Array`/типизированные массивы), извлекайте измеренные интервалы препятствий для каждой строки из ячеек или проецируемой геометрии, объединяйте интервалы, а затем передайте эти интервалы в `layoutNextLineRange` перед рисованием текста.
- Сохраняйте связь между визуальной анимацией и анимацией макета. Если сфера превращается в куб, между отображаемым буфером ячеек и диапазоном препятствий будет одно и то же значение; в противном случае демо-версия выглядит нарисованной, а не физически перекомпонованной.
- Для затухания отдавайте предпочтение непрозрачности слоя, а не изменению интенсивности глифа или масштаба препятствия. Поместите временные спрайты ASCII на отдельный холст и затемните холст с помощью непрозрачности CSS/GSAP, чтобы геометрия не сжималась.
- Настройка Canvas `ctx.font` происходит на удивление медленно; установите его **один раз** для каждого кадра, если шрифт не меняется, а не для каждого вызова `fillText`.

## Распространенные ошибки

1. **Смещение строк шрифта CSS/canvas.** `ctx.font = "16px Inter"` измерено, но CSS показывает `font-family: Inter, sans-serif; font-size: 16px`. Хорошо, *если* «Интер» загрузится. Если Inter 404, CSS возвращается к шрифту без засечек, и измерения отклоняются на 5–20%. Всегда `preload` шрифт или используйте семейство, безопасное для Интернета.

2. **Повторная подготовка внутри цикла анимации.** Только `layout*` стоит дешево. Повторный вызов `prepare` в каждом кадре приведет к снижению производительности. Сохраните подготовленный дескриптор в области модуля.

3. **Забываем `Intl.Segmenter` для разделения графем.** Эмодзи, объединение знаков, CJK — `"é".split("")` дает вам два символа. Используйте `new Intl.Segmenter(undefined, { granularity: "grapheme" })` при выборке отдельных видимых глифов.

4. **`break: 'never'` чипы без `extraWidth`.** В `rich-inline`, если вы используете `break: 'never'` для атомарного чипа/упоминания, вы также должны указать `extraWidth` для заполнения таблетки — в противном случае чип-хром переполнит контейнер.

5. **Использование `@chenglou/pretext` из `unpkg` с записью только для TypeScript.** Используйте `esm.sh` — он автоматически компилирует экспорт TS в готовый к использованию в браузере ESM. `unpkg` выдаст ошибку 404 или предоставит необработанный TS.

6. **Моноширинные резервные варианты, молча стирающие всю суть.** Пользователи, видящие моноширинный вывод, часто имеют CSS `font-family`, который перешел на `monospace`. Проверьте фактически отображаемый шрифт с помощью DevTools.

7. **Пропуск строк вместо регулировки ширины** при обтекании фигуры. Если коридор в этой строке слишком узок, чтобы вместить строку, *пропустите строку* (`y += lineHeight; continue;`) вместо того, чтобы передавать крошечный maxWidth в `layoutNextLineRange` — pretext вернет строки из одной графемы, которые выглядят прерывистыми.

8. **Доставка холодной демо-версии.** Первая отрисовка по умолчанию выглядит как учебное пособие. Добавьте: виньетку, тонкую развертку, автоматическое движение в режиме ожидания, один тщательно выбранный интерактивный ответ (перетаскивание, наведение, прокрутка, щелчок). Без них «крутая демонстрация предлога» будет выглядеть как «стажерская копия README».

## Контрольный список проверки

- [ ] Демо представляет собой отдельный автономный файл `.html` — открывается двойным щелчком мыши или `python3 -m http.server`.
- [ ] `@chenglou/pretext` импортирован через `esm.sh` с закрепленной версией.
- [ ] Corpus — это настоящая проза, а не lorem ipsum, и соответствует концепции демо-версии.
- [ ] Строка шрифта, переданная в `prepare`, точно соответствует шрифту CSS.
- [ ] `prepare()` / `prepareWithSegments()` вызывается один раз, а не для каждого кадра
- [ ] Темный фон + продуманная палитра — не белый холст по умолчанию
- [ ] По крайней мере один интерактивный ответ (перетаскивание/наведение/прокрутка/щелчок) или простое автоматическое движение
- [ ] Протестировано локально с помощью `python3 -m http.server` и не подтверждено отсутствие ошибок консоли.
- [ ] 60 кадров в секунду на ноутбуке среднего уровня (или задокументировано постепенное ухудшение)
- [ ] Одна дополнительная деталь, которую пользователь не запросил
