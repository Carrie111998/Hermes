# Создание навыков Hermes-Agent (в репозитории)

## Обзор

Есть два места, где может жить SKILL.md:

1. **Локальный пользователь:** `~/.hermes/skills/<maybe-category>/<name>/SKILL.md` — личный, не общий. Создано с помощью `skill_manage(action='create')`.
2. **В репозитории (этот навык относится к данному случаю):** `skills/<category>/<name>/SKILL.md` или `optional-skills/<category>/<name>/SKILL.md` внутри репозитория Hermes-Agent — зафиксировано, поставляется вместе с пакетом. Используйте `write_file` + `git add`. `skill_manage(action='create')` НЕ нацелен на это дерево.

Навыки работы в репозитории должны соответствовать **жестким стандартам автора** (см. AGENTS.md, «Стандарты создания навыков (HARDLINE)» — этот раздел является источником истины; этот навык представляет собой пошаговое руководство). Рецензенты отклоняют PR, которые их нарушают, поэтому встреча с ними заранее обходится дешевле, чем позже.

## Когда использовать

- Пользователь просит добавить навык "в этой ветке/репо/коммите"
- Вы фиксируете рабочий процесс многократного использования, который должен поставляться с агентом Hermes.
- Вы редактируете существующий навык под `skills/` или `optional-skills/` (используйте `patch` для небольших правок, `write_file` для переписывания; `skill_manage` по-прежнему работает для исправлений навыков в репозитории, но не для `create`).
– Не используйте для: личных навыков в `~/.hermes/skills/` (просто используйте `skill_manage`).

## Сначала определите уровень: в комплекте или по желанию

- **В комплекте (`skills/<category>/`)** — ежедневное поведение водителя, широко полезное для многих типов пользователей, мало занимающее место. Жесткая полоса: вы можете с невозмутимым выражением лица сказать: «Пользователь будет загружать это более 5 сеансов в месяц».
- **Необязательно (`optional-skills/<category>/`)** — ниша, специфичная для конкретной отрасли (блокчейн, игры, финансы, одно приложение), навыки повторяющейся работы/задачи или что-то тяжелое. Установлен через `hermes skills install official/<category>/<skill>`.

**Если есть сомнения, необязательно.** Продвинуться по службе позже легко; понижение в должности — это отток. «Было бы полезно всем, кому это когда-либо понадобится» — это аргумент необязательного уровня, а не встроенный.

Выбирайте категорию по тому, что представляет собой инструмент, а не по тому, как он ощущается (интерфейс командной строки AI-агента входит в `autonomous-ai-agents/`, даже если он «чувствует продуктивность»). Подтвердите существующие категории с помощью `search_files(pattern='*', target='files', path='skills')` и не создавайте случайно новые категории верхнего уровня.

**Нет навыков маршрутизатора/индекса/концентратора.** Навык, основным содержимым которого является таблица маршрутизации, указывающая на одноуровневые навыки, добавляет переход косвенного направления и дублирует собственные триггеры `When to Use` братьев и сестер. Если навык будет пустым без указателей «загрузить навык X вместо этого», не записывайте его — каталог и триггеры каждого родственного элемента уже выполняют эту работу.

## Требуется фронтмен

Источник истины валидатора: `tools/skill_manager_tool.py::_validate_frontmatter`. Жесткие требования к валидатору:

– Начинается с `---` в качестве первых байтов (без начальной пустой строки).
- Закрывается с помощью `\n---\n` перед телом.
- Анализирует как отображение YAML.
- Поле `name` присутствует.
- Поле `description` присутствует (максимальное значение валидатора — 1024 символа — но см. жесткую линию репозитория ниже, которая намного строже).
- Непустое тело после закрытия `---`.

Форма стандарта репо (ожидаются все поля, даже если валидатор не применяет их):

```yaml
---
name: my-skill-name               # lowercase, hyphens, ≤64 chars (MAX_NAME_LENGTH)
description: Concise capability statement, under sixty chars.
version: 0.1.0                    # semver; new skills start at 0.1.0
author: Real Name (github-handle), Hermes Agent
license: MIT
platforms: [linux, macos, windows]   # audit, don't guess — see Platform Gating
metadata:
  hermes:
    tags: [Short, Descriptive, Tags]
    related_skills: [other-in-repo-skill]
---
```

### `description` правила (HARDLINE — 1024 валидатора НЕ является стандартом)

- **≤ 60 символов.** Одно предложение. Заканчивается точкой.
- Укажите возможность, а не реализацию, и не повторяйте название навыка.
- Никаких маркетинговых слов («мощный», «комплексный», «бесшовный», «продвинутый»).
— Индекс навыка системной подсказки усекается до 57 символов + «...» — триггер/возможность должны быть автономными в этом окне.
– Если описание содержит `:`, заключите его в двойные кавычки, иначе YAML анализирует его как сопоставление, и генератор документов аварийно завершает работу. Котировки не учитываются при расчете 60.

Хорошо: `Track named companies for material news with cited digests.`
Плохо: `Use when a user asks to monitor named competitors or companies for product launches, pricing changes, funding, ...` (240 символов — отклонено на рассмотрении)

### `author` правила

- Сначала укажите **человека**, затем "Агента Гермеса" как вторичного соавтора: `Ben Barclay (benbarclay), Hermes Agent`.
- Никогда не используйте `author: Hermes Agent` в одиночку за предоставленные навыки — отдавайте должное человеку, а не инструменту, даже (особенно), когда текст писал агент.
- Навыки, созданные сопровождающим: `Teknium (teknium1), Hermes Agent`.

### `related_skills` правила

- Каждая запись должна соответствовать существующему навыку **в репозитории** в том же состоянии дерева, что и ваш PR. Не ссылайтесь на навыки, которые были только запланированы, существуют в другом PR или существуют только в `~/.hermes/skills/`.
– Проверьте каждую запись: `search_files(pattern='<name>', target='files', path='skills')` (и `optional-skills/`).

## Платформа Gating: проверяйте, не доверяйте

`platforms:` контролирует загрузку ОС хоста. Установите его на основе того, что на самом деле вызывает текст и сценарии навыка:

| Навык использует только… | `platforms:` |
|---|---|
| Инструменты Hermes + stdlib Python + кроссплатформенные интерфейсы командной строки | `[linux, macos, windows]` |
| конвейеры bash, цепочки `grep`/`awk`/`sed`, Heredocs | `[linux, macos]` |
| `osascript`, `defaults`, `pmset` | `[macos]` |
| `apt`/`systemctl`/`/proc` | `[linux]` |

Сигналы только для POSIX для поиска в `scripts/`: `fcntl`, `termios`, `pty`, `os.fork`, `os.killpg`, `signal.SIGKILL`, `os.kill(pid, 0)` проверки работоспособности, жестко запрограммированные `/tmp` `/proc` `/etc`. Положение по умолчанию: сначала исправить кроссплатформенность (`tempfile.gettempdir()`, `pathlib.Path`, `psutil.pid_exists`); ворота уже, только если зависимость действительно привязана к платформе, и скажите, почему в `## Pitfalls`.

## Ограничения размера

- Полный SKILL.md: принудительное использование ≤ 100 000 символов (`MAX_SKILL_CONTENT_CHARS`), но целевое значение **~100 строк для простого навыка и ~200 для сложного**. Навыки сверстников составляют 8–14 тыс. символов.
- Объемные или отраслевые материалы помещаются в `references/*.md`, `templates/` или `scripts/` — на них указывает SKILL.md, а не встроено.
- Не ждите, что модель будет выполнять встроенные анализаторы или нетривиальную логику при каждом вызове — отправьте вспомогательный скрипт в `scripts/` и ссылайтесь на него по пути.

## Структура тела (современный порядок разделов)

```
# <Skill> Skill
2-3 sentence intro: what it does, what it doesn't do, dependency stance.

## When to Use          — bulleted triggers (+ "Don't use for:" counter-triggers)
## Prerequisites        — exact env vars, installs, API key sourcing
## How to Run           — canonical invocation through the `terminal` tool
## Quick Reference      — flat command list, no narration
## Procedure            — numbered steps, each with a checkable completion criterion
## Pitfalls             — known limits, things that look broken but aren't
## Verification         — how to prove the skill worked
```

Не каждый раздел применим к каждому навыку (навык задачи чистой процедуры может не иметь краткого справочника), но «Когда использовать + основная часть действия + подводные камни + проверка» — это минимум. Сократите маркетинговые вступления, ненужные операции «Проверка установки» и повторные объяснения переменных окружения, которые уже есть в «Предварительных требованиях».

### Ссылка на инструменты Hermes, а не на сырую оболочку

Если для навыка требуется возможность, назовите соответствующий инструмент Hermes в обратных кавычках: `terminal`, `read_file`, `write_file`, `patch`, `search_files`, `web_search`, `web_extract`, `browser_navigate`, `vision_analyze`, `delegate_task`, `cronjob`. НЕ называйте утилиты оболочки, которые уже упакованы агентом (`grep` → `search_files`, `cat` → `read_file`, `sed`/`awk` → `patch`, `find`/`ls` → `search_files target='files'`). Навык CLI-оболочки должен оформлять вызовы как `terminal(command="<tool> ...", timeout=...)` — пустая строка оболочки («запустить `foo --version`») является несоответствием, блокирующим проверку. Если навык зависит от сервера MCP, назовите его и задокументируйте настройку в разделе «Предварительные условия».

### Никогда не используйте локальные пути компьютера

Напишите относительные пути к репозиторию (`skills/...`, `tools/skill_manager_tool.py`). Путь `/home/<you>/...`, встроенный в зафиксированные нарушения навыков для каждого другого пользователя, является флажком мгновенной проверки.

## Написание принципов качества

Существует навык, позволяющий сделать процесс работы агента более предсказуемым — агент надежно следует той же полезной дисциплине.

1. **Оптимизация для обеспечения предсказуемости процесса.** Если линия не меняет поведение, обрежьте ее.
2. **Выберите правильную контекстную нагрузку.** Описание оплачивается за каждый поворот; Подробности указаны в тексте или связанных ссылках.
3. **Завершайте этапы критериями завершения.** Проверяемые и, когда это важно, исчерпывающие: «каждый измененный файл» превосходит «обобщение изменений».
4. **Сопоставьте правила с концепцией, которой они регулируют.**
5. **Используйте сильные ведущие слова** («жесткий цикл», «основная причина», «регрессионный тест») в длинных повторяющихся объяснениях.
6. **Устранение дублирования и отсутствия операций.** «Будьте осторожны» и «используйте лучшие практики» не меняют поведение модели — замените проверяемым критерием или удалите.

## Тесты и документы (требуются для навыков репо)

1. **Тесты** доступны по адресу `tests/skills/test_<skill>_skill.py` — только stdlib + pytest + `unittest.mock`, без активной сети. Запустите через `scripts/run_tests.sh tests/skills/test_<skill>_skill.py -q`. (Общее прохождение `tests/tools/test_skill_manager_tool.py` ничего не доказывает о ВАШИХ навыках.)
2. **Регенерация документов:** запустите `python3 website/scripts/generate-skill-docs.py`, затем примените дисциплину области — генератор перезаписывает КАЖДУЮ страницу автоматического создания. `git checkout --` все, что не твое; окончательный результат сравнения должен отображать только ваш SKILL.md, страницу документации по каждому навыку, однострочную строку каталога и однострочную вставку `website/sidebars.ts` (проверьте с помощью `search_files(pattern='<your-slug>', path='website/sidebars.ts')` — ровно одно попадание, иначе страница останется потерянной).
3. **`.env.example`** (только если навыку нужны новые переменные окружения): один четко ограниченный блок с комментариями; больше ничего не трогайте в файле.

## Рабочий процесс

1. **Опросите коллег** в целевой категории с помощью `search_files(target='files')` и прочитайте 2–3 файла SKILL.md коллег, чтобы подобрать тон и структуру. Предпочитайте расширение существующего навыка созданию узкого брата или сестры.
2. **Определите уровень и категорию** (см. выше). Если вы сомневаетесь, необязательно — спросите, прежде чем нажимать, а не нарушать дефолт.
3. **Черновик** с `write_file` по `skills/<category>/<name>/SKILL.md` (или `optional-skills/...`).
4. **Проверить локально**:
   ```python
   import yaml, re, pathlib
   content = pathlib.Path("skills/<category>/<name>/SKILL.md").read_text()
   assert content.startswith("---")
   m = re.search(r'\n---\s*\n', content[3:])
   fm = yaml.safe_load(content[3:m.start()+3])
   assert "name" in fm and "description" in fm
   assert len(fm["description"]) <= 60, f"description {len(fm['description'])} chars — hardline is 60"
   assert fm["description"].endswith(".")
   assert "platforms" in fm
   assert len(content) <= 100_000
   ```
   Также убедитесь, что каждая запись `related_skills` существует в репозитории.
5. **Добавьте тесты + обновите документацию** (предыдущий раздел).
6. **Git add + commit** в активной ветке; открыть пиар.
7. **Примечание.** Загрузчик навыков ТЕКУЩЕГО сеанса кэшируется — `skill_view` / `skills_list` не увидит новый навык до начала нового сеанса. Это ожидаемо, а не ошибка.

## Редактирование существующих навыков в репозитории

- **Небольшое исправление:** `skill_manage(action='patch', ...)` работает с навыками в репозитории, как и `patch`.
- **Крупная переработка:** `write_file` весь SKILL.md.
- **Вспомогательные файлы:** от `write_file` до `references/`, `templates/` или `scripts/` в каталоге навыков.
- **Всегда фиксировать** — навыки в репозитории являются исходным состоянием, а не состоянием времени выполнения. Перезапустите генератор документов, когда заголовок изменится.

## Распространенные ошибки

1. **Использование `skill_manage(action='create')` для навыка в репозитории.** Он записывается в `~/.hermes/skills/`, а не в дерево репозитория. Используйте `write_file`.
2. **Доверие к ограничениям валидатора как стандарту.** Валидатор допускает описания длиной 1024 символа; проверка отклоняет все, что превышает 60. Валидатор не проверяет `platforms:`, формат автора, тесты или документацию — проверка проверяет.
3. **`author: Hermes Agent` по дополнительному навыку.** Сначала отдайте должное человеку.
4. **Ведние пробелы перед `---`.** Проверка завершается неудачно для любой ведущей пустой строки или спецификации.
5. **Описание слишком общее или триггер скрыт за символом 57.**
6. **`related_skills` указывает на навыки, которых нет в репозитории** (локально для пользователя, запланировано или в одноуровневом PR).
7. **Дублирование коллег.** Сначала изучите категорию; extend rather than sibling.
8. **Пропуск генератора документации или его несвязанное смещение.** Оба направления неверны: нет регенерации = потерянный навык без страницы документации; Слепая регенерация = раздутая разница, полная дрейфа других навыков.
9. **Ожидается, что в текущем сеансе появится новый навык.** Загрузчик инициализируется в начале сеанса.
10. **Позвольте навыкам накапливать осадок.** При добавлении правила удалите старую формулировку, которую оно заменяет.

## Контрольный список проверки

- [ ] Уровень выбран сознательно (пакетный план: 5+ сеансов в месяц; иначе `optional-skills/`)
- [ ] File at `skills/<category>/<name>/SKILL.md` or `optional-skills/<category>/<name>/SKILL.md`
- [ ] Frontmatter начинается с байта 0 с `---` и заканчивается `\n---\n`.
- [ ] `name`, `description`, `version`, `author`, `license`, `platforms`, `metadata.hermes.{tags, related_skills}` все присутствуют
- [ ] Описание ≤ 60 символов, одно предложение, заканчивается точкой, без маркетинговых слов.
- [ ] `author` первым указывает автора-человека
- [ ] `platforms:` проверено на соответствие реальным текстам/скриптам, а не скопировано с родного брата или сестры
- [ ] Каждая запись `related_skills` разрешается в репозитории.
- [ ] Тело соответствует современному порядку разделов; commands framed through Hermes tools
- [ ] В файле нет локальных путей к машине
- [ ] Каждый упорядоченный шаг имеет проверяемый критерий завершения.
- [ ] Тесты в `tests/skills/test_<skill>_skill.py` проходят под `scripts/run_tests.sh`.
- [ ] Docs regenerated with scope discipline; sidebar has exactly one entry for the slug
- [ ] `git add` + совершить фиксацию в намеченной ветке; PR открыт
