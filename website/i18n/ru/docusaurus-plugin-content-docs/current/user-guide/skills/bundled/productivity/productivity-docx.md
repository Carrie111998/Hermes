# Навык работы с документами

Создавайте, читайте, редактируйте и шаблонизируйте файлы Microsoft Word `.docx` с помощью
python-docx через четыре небольших интерфейса командной строки. Он обрабатывает текст, стили, списки, таблицы,
изображения, верхние и нижние колонтитулы и шаблоны `{{token}}`. Он не рендерится
документы в PDF, редактировать устаревшие двоичные файлы `.doc` или принимать/отклонять отслеживаемые
изменения (он их только обнаруживает — см. «Подводные камни»).

## Когда использовать

- Пользователь просит сформировать документ Word (отчет, письмо, договор).
– Вам нужен текст, контур, стили или встроенные изображения `.docx`.
– Необходимо изменить существующий `.docx`: заменить текст, отредактировать ячейки таблицы,
  вставлять/удалять абзацы, применять стили.
– У вас есть шаблон `.docx` с `{{placeholders}}` для заполнения данными.
– Не для: `.doc` (устаревшая версия), `.odt`, преобразования PDF или работы с макетами WYSIWYG.

## Предварительные условия

- Python 3.10+ с установленным `python-docx`:
  `pip install python-docx` (имя импорта — `docx`).
- Для блоков изображений: файлы изображений должны существовать локально (PNG/JPEG).

## Как бежать

Все помощники живут в `scripts/` рядом с этим файлом. Запустите их с помощью
инструмент `terminal`; каждый поддерживает `--help` и выводит JSON на стандартный вывод.

```bash
python scripts/docx_create.py spec.json out.docx
python scripts/docx_read.py out.docx --text
python scripts/docx_edit.py replace out.docx --find old --replace new
python scripts/docx_template.py tpl.docx values.json filled.docx
```

## Краткий справочник

| Задача | Команда |
| --- | --- |
| Создать на основе спецификации JSON | `docx_create.py spec.json out.docx` |
| Полный текст (тело+таблицы+верхние/нижние колонтитулы) | `docx_read.py f.docx --text` |
| Контур заголовка + формы таблицы | `docx_read.py f.docx --structure` |
| Фактически используемые стили | `docx_read.py f.docx --styles` |
| Извлечение встроенных изображений | `docx_read.py f.docx --images outdir/` |
| Обнаружение отслеживаемых изменений/комментариев | `docx_read.py f.docx --revisions` |
| Найти/заменить (форматирование сохраняется) | `docx_edit.py replace f.docx --find A --replace B -o out.docx` |
| Установить ячейку таблицы | `docx_edit.py set-cell f.docx --table 0 --row 1 --col 2 --text X` |
| Вставить абзац перед индексом N | `docx_edit.py insert f.docx --index N --text X --style Normal` |
| Удалить пункт N | `docx_edit.py delete f.docx --index N` |
| Применить стиль к абзацу N | `docx_edit.py style f.docx --index N --style "Heading 1"` |
| Заполните `{{tokens}}` | `docx_template.py tpl.docx values.json out.docx --strict` |

## Процедура

1. **Создайте.** Напишите спецификацию JSON с помощью `write_file`, затем запустите
   `scripts/docx_create.py`. Спецификация поддерживает: `page` (размер + поля в
   мм), строки `header`/`footer`, `styles` (настраиваемые стили абзацев с
   шрифт, размер, полужирный/курсив, шестнадцатеричный `color`) и `blocks` — `heading`
   (уровни 1–9), `paragraph` (либо `text`, либо список `runs`, где каждый запуск
   можно установить `bold`/`italic`/`underline`), `bullet_list`, `numbered_list`,
   `table` (строка `header` выделена жирным шрифтом, `rows`, дополнительная встроенная таблица
   `style`, например `Table Grid`), `image` (`path`, необязательный `width_mm`),
   и `page_break`. Полный формат спецификации описан в верхней части
   `scripts/docx_create.py` — прочитайте его с помощью `read_file` при написании.
2. **Чтение.** Используйте `scripts/docx_read.py` ровно с одним флагом режима.
   `--text` возвращает абзацы тела, весь текст ячеек таблицы и
   текст верхнего/нижнего колонтитула в формате JSON. `--structure` возвращает структуру заголовка
   плюс количество абзацев/таблиц/разделов. `--images DIR` копирует каждый файл
   под `word/media/` из пакета.
3. **Изменить.** Используйте `scripts/docx_edit.py`. `replace` ходит тело, столы
   (включая вложенные), верхние и нижние колонтитулы, а также сохраняет форматирование прогона;
   добавьте `--body-only`, чтобы пропустить верхние и нижние колонтитулы. Передайте `-o out.docx`, чтобы сохранить
   оригинал; опустите его, чтобы редактировать на месте. Индексы абзацев для
   `insert`/`delete`/`style` относятся к порядку корпуса `--structure`/`--text`.
4. **Шаблон.** Поместите в документ токены в стиле `{{name}}` (буквы,
   цифры, `_`, `.`, `-`; необязательные внутренние пробелы, такие как `{{ name }}`, являются
   принято). Запустите `scripts/docx_template.py` с объектом JSON вида
   ценности. Используйте `--strict` для сбоя, когда токены остаются незаполненными; JSON
   выходные списки `filled` считаются и `unfilled_tokens` в любом случае.
5. **Проверка** (всегда): перечитайте вывод с помощью `--text` или
   `--structure` и убедитесь, что ожидаемый контент присутствует.

## Подводные камни

- **Токены разделяются по сериям.** Word часто фрагментирует `{{name}}` на
  несколько пробегов. Помощники замены решают эту проблему, сворачивая прогоны;
  замена наследует форматирование серии, в которой найдено совпадение
  начинается. Таким образом, изменения форматирования среднего токена сглаживаются.
- **Отслеживание изменений.** `--revisions` *обнаруживает* только вставки,
  удаления, изменения формата и комментарии. Извлечение текста возвращает
  тело «как есть» (вставки включены, удаления опущены, т. е. примерно
  принятое представление), но этот навык не может принимать/отклонять изменения или читать
  текст комментария. Скажите это пользователю, а не гадайте.
- **Имена стилей должны существовать.** Применение стиля, не определенного в файле
  документ вызывает `KeyError`. Встроенные модули, такие как `Heading 1`, `List Bullet`,
  `List Number`, `Table Grid` существуют в шаблоне по умолчанию; обычай
  стили должны быть сначала объявлены в спецификации создания.
- **Перезапуск нумерованных списков.** `List Number` использует настройки Word по умолчанию.
  нумерация; отдельные списки в одном документе могут продолжать нумерацию
  вместо перезапуска. Приемлемо для простых документов; предупреждать пользователей о необходимости
  точная нумерация нескольких списков.
- **Запись ячейки заменяет форматирование.** `set-cell` использует `cell.text = ...`,
  который сбрасывает пробеги в этой ячейке в простое форматирование.
- **Кодировка.** Все файлы спецификаций/значений JSON явно читаются как UTF-8;
  никогда не полагайтесь на настройки локали по умолчанию при написании собственного связующего кода.
- **Не разархивируйте и не сохраняйте XML.** Редактируйте с помощью сценариев (или
  python-docx); замена необработанного текста в `document.xml` повреждает файлы
  легко. Используйте `patch`/`write_file` только для входных данных JSON, а не для
  `.docx` сам.

## Проверка

- После создания/редактирования/шаблона запустите `docx_read.py out.docx --text` и
  проверьте появление ожидаемых строк (а старые строки исчезли).
– Для шаблонов, запускаемых с `--strict`, или отметьте `unfilled_tokens == []`.
– Проверка структуры: `--structure` должен отображать ожидаемый заголовок.
  контуры и формы таблиц; `--styles` подтверждает применение пользовательских стилей.
- Действительный `.docx` открывается с `Document(path)` без исключения —
  чтение сценария с выходом из 0 само по себе является проверкой работоспособности.
