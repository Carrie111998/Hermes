# Тестовая версия: систематическое тестирование качества веб-приложений

## Обзор

Этот навык поможет вам провести систематическое исследовательское тестирование веб-приложений с использованием набора инструментов браузера. Вы будете перемещаться по приложению, взаимодействовать с элементами, собирать доказательства проблем и составлять структурированный отчет об ошибках.

## Предварительные условия

– Должен быть доступен набор инструментов браузера (`browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_vision`, `browser_console`, `browser_scroll`, `browser_back`, `browser_press`).
– Целевой URL-адрес и область тестирования, предоставленные пользователем.

## Входы

Пользователь предоставляет:
1. **Целевой URL** — точка входа для тестирования.
2. **Объем** — на каких областях/функциях следует сосредоточиться (или «полный сайт» для всестороннего тестирования).
3. **Каталог вывода** (необязательно) — куда сохранять скриншоты и отчет (по умолчанию: `./dogfood-output`).

## Рабочий процесс

Следуйте этому 5-этапному систематическому рабочему процессу:

### Этап 1: План

1. Создайте структуру выходных каталогов:
<!-- ascii-guard-ignore -->
   ```
   {output_dir}/
   ├── screenshots/       # Evidence screenshots
   └── report.md          # Final report (generated in Phase 5)
   ```
<!-- ascii-guard-ignore-end -->
2. Определите объем тестирования на основе данных пользователя.
3. Создайте приблизительную карту сайта, определив, какие страницы и функции нужно протестировать:
   - Лендинг/домашняя страница
   - Навигационные ссылки (шапка, подвал, боковая панель)
   - Ключевые потоки пользователей (регистрация, вход в систему, поиск, оформление заказа и т. д.)
   - Формы и интерактивные элементы
   - Пограничные случаи (пустые состояния, страницы ошибок, 404).

### Этап 2: Исследование

Для каждой страницы или функции вашего плана:

1. **Перейдите** на страницу:
   ```
   browser_navigate(url="https://example.com/page")
   ```

2. **Сделайте снимок**, чтобы понять структуру DOM:
   ```
   browser_snapshot()
   ```

3. **Проверьте консоль** на наличие ошибок JavaScript:
   ```
   browser_console(clear=true)
   ```
   Делайте это после каждой навигации и после каждого значимого взаимодействия. Незаметные ошибки JS — это ценные результаты.

4. **Сделайте аннотированный скриншот**, чтобы визуально оценить страницу и определить интерактивные элементы:
   ```
   browser_vision(question="Describe the page layout, identify any visual issues, broken elements, or accessibility concerns", annotate=true)
   ```
   Флаг `annotate=true` накладывает метки с номерами `[N]` на интерактивные элементы. Каждый `[N]` соответствует ссылке `@eN` для последующих команд браузера.

5. **Систематически тестируйте интерактивные элементы**:
   – Нажимайте кнопки и ссылки: `browser_click(ref="@eN")`.
   - Заполните формы: `browser_type(ref="@eN", text="test input")`
   - Тестовая навигация с помощью клавиатуры: `browser_press(key="Tab")`, `browser_press(key="Enter")`.
   – Пролистывать контент: `browser_scroll(direction="down")`
   - Проверка тестовой формы с неверными входными данными.
   - Тестируйте пустые материалы.

6. **После каждого взаимодействия** проверяйте:
   - Ошибки консоли: `browser_console()`.
   - Визуальные изменения: `browser_vision(question="What changed after the interaction?")`
   - Ожидаемое и фактическое поведение

### Этап 3: Сбор доказательств

По каждой найденной проблеме:

1. **Сделайте снимок экрана**, показывающий проблему:
   ```
   browser_vision(question="Capture and describe the issue visible on this page", annotate=false)
   ```
   Сохраните `screenshot_path` из ответа — вы будете ссылаться на него в отчете.

2. **Запишите детали**:
   - URL-адрес, по которому возникает проблема.
   - Шаги по воспроизведению
   - Ожидаемое поведение
   - Реальное поведение
   - Ошибки консоли (если есть)
   - Путь к скриншоту

3. **Классифицируйте проблему**, используя таксономию проблемы (см. `references/issue-taxonomy.md`):
   - Уровень серьезности: критический/высокий/средний/низкий.
   - Категория: Функционал/Визуализация/Доступность/Консоль/UX/Контент

### Этап 4: Классификация

1. Просмотрите все собранные проблемы.
2. Дедупликация — объединение проблем, которые представляют собой одну и ту же ошибку, проявляющуюся в разных местах.
3. Присвойте каждой проблеме окончательную серьезность и категорию.
4. Отсортируйте по серьезности (сначала критический, затем высокий, средний, низкий).
5. Подсчитайте проблемы по серьезности и категориям для сводного обзора.

### Этап 5: Отчет

Создайте окончательный отчет, используя шаблон по адресу `templates/dogfood-report-template.md`.

Отчет должен включать:
1. **Краткий обзор** с указанием общего количества проблем, разбивкой по серьезности и объему тестирования.
2. **Разделы по выпускам**:
   - Номер и название выпуска.
   - Значки серьезности и категории
   - URL-адрес, где он наблюдается
   - Описание проблемы
   - Шаги по воспроизведению
   - Ожидаемое и фактическое поведение
   – Ссылки на скриншоты (используйте `MEDIA:<screenshot_path>` для встроенных изображений).
   - Ошибки консоли, если применимо.
3. **Сводная таблица** всех выпусков.
4. **Заметки по тестированию** — что проверялось, что нет, нет ли блокировщиков.

Сохраните отчет в `{output_dir}/report.md`.

## Справочник по инструментам

| Инструмент | Цель |
|------|---------|
| `browser_navigate` | Перейти по URL |
| `browser_snapshot` | Получить снимок текста DOM (дерево доступности) |
| `browser_click` | Щелкните элемент по ссылке (`@eN`) или тексту |
| `browser_type` | Введите в поле ввода |
| `browser_scroll` | Прокрутить страницу вверх/вниз |
| `browser_back` | Вернуться в историю браузера |
| `browser_press` | Нажмите клавишу клавиатуры |
| `browser_vision` | Скриншот + анализ AI; используйте `annotate=true` для меток элементов |
| `browser_console` | Получение вывода и ошибок консоли JS |

## Советы

– **Всегда проверяйте `browser_console()` после навигации и после важных взаимодействий.** Незаметные ошибки JS – одни из наиболее ценных выводов.
- **Используйте `annotate=true` с `browser_vision`**, когда вам нужно рассуждать о положении интерактивных элементов или когда ссылки на снимки неясны.
- **Тестируйте как с действительными, так и с недействительными входными данными** — ошибки проверки формы встречаются часто.
- **Прокручивайте длинные страницы** – контент ниже сгиба может иметь проблемы с рендерингом.
- **Проверьте потоки навигации** — пройдите через многоэтапные процессы от начала до конца.
– **Проверьте отзывчивость**, отметив любые проблемы с макетом, видимые на скриншотах.
- **Не забывайте о крайних случаях**: пустые состояния, очень длинный текст, специальные символы, быстрое нажатие.
– Сообщая пользователю о снимках экрана, укажите `MEDIA:<screenshot_path>`, чтобы он мог видеть доказательства в режиме онлайн.
