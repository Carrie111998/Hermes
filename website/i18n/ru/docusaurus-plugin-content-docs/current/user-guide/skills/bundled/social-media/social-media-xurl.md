# xurl — X (Twitter) API через официальный интерфейс командной строки

`xurl` — это официальный интерфейс командной строки платформы разработчиков X для X API. Он поддерживает быстрые команды для общих действий И необработанный доступ в стиле Curl к любой конечной точке версии 2. Все команды возвращают JSON в стандартный вывод.

Используйте этот навык для:
- размещение, ответы, цитирование, удаление сообщений
- поиск необработанных сообщений (фактические сообщения в формате JSON с идентификаторами, с которыми вы можете взаимодействовать) и чтение хронологий/упоминаний.
- лайк, репост, добавление в закладки
- подписка, отписка, блокировка, отключение звука
- прямые сообщения
- Загрузка мультимедиа (изображений и видео)
- необработанный доступ к любой конечной точке X API v2
- рабочие процессы с несколькими приложениями и несколькими учетными записями

Этот навык заменяет старый навык `xitter` (который включал сторонний интерфейс командной строки Python). `xurl` поддерживается командой разработчиков платформы X, поддерживает OAuth 2.0 PKCE с автоматическим обновлением и охватывает значительно большую поверхность API.

## Секретная безопасность (ОБЯЗАТЕЛЬНО)

Критические правила при работе внутри сеанса агента/LLM:

– **Никогда** не читайте, не распечатывайте, не анализируйте, не обобщайте, не загружайте и не отправляйте `~/.xurl` в контекст LLM.
- **Никогда** не просите пользователя вставить учетные данные/токены в чат.
- Пользователь должен заполнить `~/.xurl` секретами вручную на своем компьютере. В Docker это должен быть `~`, видимый подпроцессами инструмента Hermes; см. примечание Docker ниже.
- **Никогда** не рекомендуйте и не выполняйте команды аутентификации со встроенными секретами в сеансах агента.
- **Никогда** не используйте `--verbose` / `-v` в сеансах агента — они могут предоставлять заголовки/токены аутентификации.
– Чтобы проверить существование учетных данных, используйте только: `xurl auth status`.

Запрещенные флаги в командах агента (они принимают встроенные секреты):
`--bearer-token`, `--consumer-key`, `--consumer-secret`, `--access-token`, `--token-secret`, `--client-id`, `--client-secret`

Регистрация учетных данных приложения и ротация учетных данных должны выполняться пользователем вручную вне сеанса агента. После регистрации учетных данных пользователь проходит аутентификацию с помощью `xurl auth oauth2` — также вне сеанса агента. Токены сохраняются до `~/.xurl` в YAML. Каждое приложение имеет изолированные токены. Токены OAuth 2.0 обновляются автоматически.

## Установка

Выберите ОДИН метод. В Linux проще всего использовать сценарий оболочки или `go install`.

```bash
# Shell script (installs to ~/.local/bin, no sudo, works on Linux + macOS)
curl -fsSL https://raw.githubusercontent.com/xdevplatform/xurl/main/install.sh | bash

# Homebrew (macOS)
brew install --cask xdevplatform/tap/xurl

# npm
npm install -g @xdevplatform/xurl

# Go
go install github.com/xdevplatform/xurl@latest
```

Проверьте:

```bash
xurl --help
xurl auth status
```

Если `xurl` установлен, но `auth status` не показывает ни приложений, ни токенов, пользователю необходимо выполнить аутентификацию вручную — см. следующий раздел.

## Одноразовая пользовательская настройка (пользователь запускает ее вне агента)

Эти шаги должны выполняться непосредственно пользователем, а НЕ агентом, поскольку они включают вставку секретов. Направьте пользователя в этот блок; не выполняйте это за них.

1. Создайте или откройте приложение по адресу https://developer.x.com/en/portal/dashboard.
2. Установите URI перенаправления `http://localhost:8080/callback`.
3. Скопируйте идентификатор клиента и секрет клиента приложения.
4. Зарегистрируйте приложение локально (его запускает пользователь):
   ```bash
   xurl auth apps add my-app --client-id YOUR_CLIENT_ID --client-secret YOUR_CLIENT_SECRET
   ```
5. Аутентификация (укажите `--app`, чтобы привязать токен к вашему приложению):
   ```bash
   xurl auth oauth2 --app my-app
   ```
   (Откроется браузер для потока OAuth 2.0 PKCE.)

   Если X возвращает ошибку `UsernameNotFound` или 403 при поиске `/2/users/me` после OAuth, передайте свой дескриптор явно (xurl v1.1.0+):
   ```bash
   xurl auth oauth2 --app my-app YOUR_USERNAME
   ```
   Это привяжет токен к вашему дескриптору и пропустит неработающий вызов `/2/users/me`.
6. Установите приложение по умолчанию, чтобы все команды использовали его:
   ```bash
   xurl auth default my-app
   ```
7. Проверьте:
   ```bash
   xurl auth status
   xurl whoami
   ```

После этого агент сможет использовать любую команду ниже без дальнейшей настройки. Токены OAuth 2.0 обновляются автоматически.

> **Распространенная ошибка:** Если вы опустите `--app my-app` в `xurl auth oauth2`, токен OAuth будет сохранен во встроенном профиле приложения `default`, который не имеет идентификатора клиента или секрета клиента. Команды завершатся ошибкой из-за ошибок аутентификации, даже если поток OAuth прошел успешно. Если вы нажмете это, перезапустите `xurl auth oauth2 --app my-app` и `xurl auth default my-app`.

> **Ошибка Docker HOME:** В официальном макете Hermes Docker `/opt/data` — это `HERMES_HOME`, но подпроцессы инструмента Hermes используют `/opt/data/home` как `HOME`. Это означает, что `~/.xurl` разрешается в `/opt/data/home/.xurl` для команд `xurl`, запускаемых Hermes, а не в `/opt/data/.xurl`. Запускаем настройку пользователя с тем же HOME:
> ```bash
> HOME=/opt/data/home xurl auth apps add my-app --client-id YOUR_CLIENT_ID --client-secret YOUR_CLIENT_SECRET
> HOME=/opt/data/home xurl auth oauth2 --app my-app YOUR_USERNAME
> HOME=/opt/data/home xurl auth default my-app YOUR_USERNAME
> HOME=/opt/data/home xurl auth status
> ```
> Если `HOME=/opt/data xurl auth status` завершается успешно, но `HOME=/opt/data/home xurl auth status` не показывает ни приложений, ни токенов, вызовы инструментов Hermes не увидят учетные данные.

## Подробности команды

### Публикация

```bash

xurl quote 1234567890 "Adding my thoughts"
xurl delete 1234567890
```

### Чтение и поиск

`xurl search` запрашивает индекс X как вашу аутентифицированную учетную запись и возвращает необработанные объекты сообщений — идентификаторы, авторов, полный текст — поэтому можно сразу же использовать результаты (ответ, лайк, репост, цитата). Используйте его, когда вам нужны реальные сообщения, а не краткий ответ по теме.

```bash
xurl read 1234567890
xurl read https://x.com/user/status/1234567890

xurl search "golang"
xurl search "from:elonmusk" -n 20
xurl search "#buildinpublic lang:en" -n 15
```

Для статей X используйте режим сырого API вместо ярлыка `read`. `xurl read`
ожидает идентификатор публикации или URL-адрес публикации; не ставьте `read` перед `/2/tweets/...`
конечная точка. Запросите поле твита `article` и вставьте `data.article.plain_text`
из ответа JSON:

```bash
xurl --app APP_NAME '/2/tweets/2057909493250539891?expansions=author_id,attachments.media_keys,referenced_tweets.id&tweet.fields=created_at,lang,public_metrics,context_annotations,entities,possibly_sensitive,conversation_id,in_reply_to_user_id,referenced_tweets,article'
```

## Доступ к необработанному API

Ярлыки охватывают общие операции. Для всего остального используйте режим необработанного стиля завитка для любой конечной точки X API v2:

```bash
# GET
xurl /2/users/me

# POST with JSON body
xurl -X POST /2/tweets -d '{"text":"Hello world!"}'

# DELETE / PUT / PATCH
xurl -X DELETE /2/tweets/1234567890

# Custom headers
xurl -H "Content-Type: application/json" /2/some/endpoint

# Force streaming
xurl -s /2/tweets/search/stream

# Full URLs also work
xurl https://api.x.com/2/users/me
```

## Обработка ошибок

- Ненулевой код выхода при любой ошибке.
— Ошибки API по-прежнему выводятся в формате JSON на стандартный вывод, поэтому вы можете их проанализировать.
- Ошибки аутентификации → пользователю необходимо повторно запустить `xurl auth oauth2` вне сеанса агента.
- Команды, которым требуется идентификатор пользователя вызывающего абонента (например, репост, закладка, подписка и т. д.), будут автоматически получать его через `/2/users/me`. Ошибка аутентификации там проявляется как ошибка аутентификации.

## Рабочий процесс агента

1. Проверьте необходимые условия: `xurl --help` и `xurl auth status`.
2. Прежде чем использовать `xurl search`, проверьте намерение. Используйте его, когда задаче нужны реальные объекты сообщений, аутентифицированный контекст учетной записи или приводит к действию X-записи — это подходящая поверхность, когда пользователю нужны сообщения, с которыми он может взаимодействовать, а не просто краткое изложение темы.
3. **Проверьте, есть ли у приложения по умолчанию учетные данные.** Проанализируйте выходные данные `auth status`. Приложение по умолчанию отмечено `▸`. Если приложение по умолчанию показывает `oauth2: (none)`, но в другом приложении есть действительный пользователь oauth2, попросите пользователя запустить `xurl auth default <that-app>`, чтобы исправить это. Это самая распространенная ошибка при настройке — пользователь добавил приложение со своим именем, но не установил его по умолчанию, поэтому xurl продолжает пытаться использовать пустой профиль `default`.
4. Если аутентификация отсутствует полностью, остановите и направьте пользователя в раздел «Одноразовая настройка пользователя» — НЕ пытайтесь регистрировать приложения или передавать секреты самостоятельно.
5. Начните с дешевого чтения (`xurl whoami`, `xurl user @handle`, `xurl search ... -n 3`), чтобы подтвердить достижимость.
6. Подтвердите целевой пост/пользователя и намерение пользователя перед любым действием по написанию (публикация, ответ, лайк, репост, DM, подписка, блокировка, удаление).
7. Только выходные данные команды `xurl` (или необработанный ответ X API) доказывают, что произошло действие X, изменяющее состояние. Никогда не сообщайте о выполненной записи на основе любого другого источника — результатов поиска, сводок или предыдущего контекста.
8. Используйте вывод JSON напрямую — каждый ответ уже структурирован.
9. Никогда не вставляйте содержимое `~/.xurl` обратно в разговор.

## Поиск неисправностей

| Симптом | Причина | Исправить |
| --- | --- | --- |
| Ошибки аутентификации после успешного прохождения OAuth | Токен сохранен в приложении `default` (без идентификатора клиента/секрета) вместо вашего именованного приложения | `xurl auth oauth2 --app my-app`, затем `xurl auth default my-app` |
| `unauthorized_client` во время OAuth | Тип приложения установлен на «Нативное приложение» на панели управления X | Измените на «Веб-приложение, автоматизированное приложение или бот» в настройках аутентификации пользователя |
| `UsernameNotFound` или 403 на `/2/users/me` сразу после OAuth | X не возвращает имя пользователя надежно из `/2/users/me` | Перезапустите `xurl auth oauth2 --app my-app YOUR_USERNAME` (xurl v1.1.0+), чтобы явно передать дескриптор |
| 401 по каждому запросу | Срок действия токена истек или неправильное приложение по умолчанию | Проверьте `xurl auth status` — убедитесь, что `▸` указывает на приложение с токенами oauth2 |
| `client-forbidden` / `client-not-enrolled` | Проблема регистрации на платформе X | Панель управления → Приложения → Управление → Перейти к пакету «Оплата по факту использования» → Производственная среда |
| `CreditsDepleted` | Баланс в размере 0 долларов США на X API | Покупайте кредиты (минимум 5 долларов США) в консоли разработчика → Оплата |
| `media processing failed` при загрузке изображения | Категория по умолчанию: `amplify_video` | Добавьте `--category tweet_image --media-type image/png` |
| Два значения «Секрет клиента» на панели управления X | Ошибка пользовательского интерфейса — сначала идет Client ID | Подтвердите действие на странице «Ключи и токены»; Идентификатор заканчивается на `MTpjaQ` |

## Примечания

- **Ограничения скорости:** X устанавливает ограничения скорости для каждой конечной точки. 429 означает подождать и повторить попытку. Конечные точки записи (публикация, ответ, лайк, репост) имеют более жесткие ограничения, чем чтение.
– **Области действия.** Токены OAuth 2.0 имеют широкую область действия. Ошибка 403 при определенном действии обычно означает, что у токена отсутствует область действия — попросите пользователя повторно запустить `xurl auth oauth2`.
- **Обновление токена.** Токены OAuth 2.0 обновляются автоматически. Нечего делать.
- **Несколько приложений:** каждое приложение имеет отдельные учетные данные/токены. Переключитесь с помощью `xurl auth default` или `--app`.
– **Несколько учетных записей в одном приложении:** выберите с помощью `-u / --username` или установите значение по умолчанию с помощью `xurl auth default APP USER`.
- **Хранилище токенов:** `~/.xurl` — это YAML. В Docker используйте подпроцесс Hermes HOME (`/opt/data/home` в официальном образе), чтобы токены попадали под `/opt/data/home/.xurl`. Никогда не читайте и не отправляйте этот файл в контекст LLM.
- **Стоимость.** Доступ к X API обычно оплачивается за эффективное использование. Многие сбои связаны с проблемами плана/разрешений, а не с проблемами кода.
