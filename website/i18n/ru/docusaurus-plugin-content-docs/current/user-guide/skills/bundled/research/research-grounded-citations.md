# Обоснованные цитаты

Каждое утверждение, взятое из внешнего источника, получает встроенную пронумерованную ссылку и
Список `Sources:`, в стиле недоумения. Скрипт реестра владеет сопоставлением `url → [n]`.
поэтому числа и URL-адреса берутся из поиска, а не из памяти — только модель
когда-либо выдает небольшие целые числа, которые были переданы.

Для работы с высокими ставками один и тот же реестр служит цепочкой проверки фактов: дословно
к каждому источнику прилагаются цитаты (отклоняются, если они не указаны буквально в
извлеченный текст страницы), претензии на основе знаний модели помечаются как `[unverified]`,
и `verify --evidence` проваливает любой проект, цитируемые источники которого не содержат доказательств.

Этот навык охватывает ответы в чате, письменные документы (уценка, PDF, docx,
слайды) и исследовательские отчеты. Он не охватывает академические конвейеры BibTeX —
для докладов на конференциях используйте навык `research-paper-writing`, который этот навык
каналы (см. `references/citation-formats.md`).

## Когда использовать

Используйте всякий раз, когда ответ или артефакт основан на полученной вами информации, а не на
знал:

- Исследования, сравнения, сводки новостей, «каково текущее состояние X»
- Любой результат, который вы записываете на диск, который цитирует, перефразирует или сообщает.
  внешние факты — отчеты, сводки, документы, колоды, вики-страницы.
- Факты, где пользователь захочет проверить вашу работу
- Синтез из нескольких источников, при котором необходимо приписать противоречивые источники.

Пропускать встроенные цитаты, если поиск не связан с другой задачей.
быстрый поиск синтаксиса/версии в процессе написания кода, непринужденная беседа, творческое письмо.
Упоминайте URL-адрес только в том случае, если пользователь действительно хочет получить ссылку.

## Предварительные условия

Ничего сверх стандартного набора инструментов. `scripts/sources.py` — это Python 3, поддерживающий только стандартную библиотеку.
Получение происходит из того, что настроено: `web_search`, `web_extract`,
`browser_navigate` или `terminal` (curl, CLI).

Местоположение реестра: `$HERMES_HOME/cache/citations/ledger.json` (с учетом профиля).
Переопределить задачу с помощью `--ledger <path>` или `HERMES_CITATION_LEDGER`.

## Как бежать

```bash
S=~/.hermes/skills/research/grounded-citations/scripts/sources.py

python3 "$S" reset                                  # start a clean ledger
python3 "$S" add https://example.com/a --title "A"  # prints: [1]
python3 "$S" add https://example.com/b --title "B"  # prints: [2]
python3 "$S" list                                   # ledger table
python3 "$S" render                                 # Sources: block
python3 "$S" verify draft.md                        # catch bad citations
```

`add` идемпотентен и нормализован по URL: одна и та же страница всегда возвращает один и тот же результат.
id в реестре, поэтому идентификаторы остаются стабильными на протяжении многих раундов поиска/извлечения.

## Краткий справочник

| Действие | Команда |
|---|---|
| Свежий реестр для новой задачи | `sources.py reset` |
| Зарегистрируйте источник, получите его идентификатор | `sources.py add <url> [--title T]` |
| Зарегистрируйте несколько одновременно | `sources.py add <url1> <url2> ...` |
| Зарегистрируйтесь из вывода инструмента JSON | `sources.py ingest results.json` |
| Прикрепите дословные доказательства к источнику | `sources.py quote <id> --text "exact wording" --from page.txt` |
| Показать книгу | `sources.py list [--json]` |
| Рендеринг блока «Источники» | `sources.py render [--style markdown\|plain\|footnotes\|bibtex\|evidence] [--only 1,3]` |
| Рендерите только то, что цитируется в проекте | `sources.py render --cited-in draft.md` |
| Переписать блок «Источники» черновика на место | `sources.py render --replace-in draft.md` |
| Проверьте цитаты проекта | `sources.py verify draft.md [--strict] [--min-coverage 0.6] [--evidence]` |

## Процедура

① **Сбросить реестр** в начале задачи, что приведет к обоснованному
ответ или документ. Пропустить сброс при продолжении работы, идентификаторы которой уже
в черновике — повторное использование реестра обеспечивает стабильность нумерации.

② **Зарегистрируйте каждый источник во время извлечения.** После каждого `web_search` /
`web_extract` / `browser_navigate` / fetch, передайте URL-адреса `sources.py add`
(или передать необработанный JSON через `sources.py ingest`). Сделайте это *перед* написанием
проза. Регистрация позже, по памяти, — это вариант неудачи, для которого существует этот навык.
предотвратить.

③ **Напишите «цитировать во время составления».** Поместите идентификатор(ы) в квадратных скобках сразу после
каждое предложение, которое поддерживает источник:

```
Ice floats because it is less dense than liquid water.[1][2]
```

- Нет места перед скобкой; каждый идентификатор в своих скобках.
- Макс. 3 идентификатора в предложении. Цитируйте каждое предложение, а не один дамп в конце.
- Из бухгалтерской книги вернулись только идентификаторы. Никогда не придумывайте идентификатор или URL-адрес.
- Утверждения, основанные на ваших собственных знаниях, не цитируются.
- Противоречивые источники: представьте оба показания, каждое со своим идентификатором.
- Приводить точные цифры, даты и имена в том виде, в каком их указывает источник; пробелы в флагах
  явно («источник для X не найден») вместо того, чтобы сглаживать их.

④ **Добавьте блок «Источники»** с помощью `sources.py render --cited-in <draft>`, чтобы
Сопоставление идентификатора → URL-адреса генерируется автоматически из реестра, а не перепечатывается.
Для целей без уценки выберите соответствующий `--style` и следуйте
`references/citation-formats.md` для размещения (сноски в docx, концевые сноски в
PDF/LaTeX, слайд «Источники» в колодах, постраничные списки источников в выводе вики).

⑤ **Проверка перед доставкой** — `sources.py verify <draft>` выходит с ненулевым значением
неизвестные идентификаторы, в блоке источников, который не согласуется с реестром, или (с
`--min-coverage`) о прозе, которая слишком редко цитируется. Исправьте и перезапустите.

⑥ **Ответы в чате** выполняются так же, как и черновик ответа: зарегистрируйтесь.
источники, цитируйте встроенную ссылку, заканчивайте визуализированным списком `Sources:`. Для краткого ответа
вы можете визуализировать блок из `sources.py render --only <ids>` вместо
запись в файл.

## Режим проверки фактов

Для работы, где читатель должен иметь возможность проверить цепочку — медицинскую, юридическую,
финансовые вопросы, безопасность, спорные претензии или когда пользователь запрашивает проверку фактов —
переход от цитат к доказательствам:

① **Прикрепите дословную цитату для каждого источника.** После извлечения страницы сохраните ее.
текст в файл и прикрепите предложения, содержащие каждое утверждение:

```bash
python3 "$S" quote 1 --text "Ice is about 9% less dense than liquid water." --from page1.txt
```

Цитата отклоняется, если она не указана дословно в тексте доказательства.
(нечувствителен к пробелам, регистру и разметке — встроенные ссылки, такие как
`_[ERAP1](https://…)_` в извлеченном тексте соответствует простой прозе, которую видит читатель),
поэтому перефраз или неправильно запомненная цифра не может маскироваться под свидетельство.
Копировать-вставить полученный текст; никогда не перепечатывайте. Процитируйте предложение как
читатель это видит — сопоставитель видит за вас разметку экстрактора, поэтому
вам не нужно воспроизводить синтаксис ссылок или экранированные звездочки в цитате.

② **Помечать заявления о знании модели с помощью `[unverified]`.** Заявление, несущее нагрузку.
вы не могли бы получить в качестве источника явный маркер вместо цитаты:

```
The refactor likely predates the 2.0 release.[unverified]
```

`verify --min-coverage` считает `[unverified]` предложений пройденными — цель
объявляется происхождение каждого утверждения, а не цитата в каждом предложении.
Если ключевое утверждение можно проверить, проверьте его; `[unverified]` за то, что искренне
не может быть, и в результатах проверки фактов преобладают маркеры `[unverified]`
следует сказать об этом в своем резюме.

③ **Перекрестная проверка спорных фактов со вторым независимым источником.** Когда два
источники не согласны, цитируют оба чтения со своими идентификаторами и цитатами и говорят
какой у вас вес и почему. Один источник сообщает; два независимых источника
подтверждение.

④ **Проверьте ворота доказательств и отобразите блок доказательств:**

```bash
python3 "$S" verify report.md --evidence --min-coverage 0.5
python3 "$S" render --style evidence --replace-in report.md
```

`--evidence` не проходит черновик, если к какому-либо цитируемому источнику не прикреплена цитата.
Стиль рендеринга `evidence` печатает цитаты каждого источника под его URL-адресом, поэтому
результат показывает претензию → источник → точный подтверждающий текст без каких-либо действий
вера. Используйте `--replace-in <draft>`, чтобы перезаписать существующий блок источников на месте.
(идемпотентный — можно безопасно запустить повторно после добавления дополнительных кавычек); `--cited-in` распечаток
вместо этого на стандартный вывод. Оба выдают заголовок `## Sources` (`--style plain` выдает
`Sources:`).

**Что имеет значение `--min-coverage`.** Покрытие составляет
`sentences with declared provenance / prose sentences`. Прозаическое предложение – это
непустой фрагмент строки длиной 4+ слов после блока «Источники», заголовки (`#`),
строки таблицы (`|`) и изолированный код удаляются; Маркеры кавычек удаляются.
Провенанс указывается либо цитатой `[n]`, либо маркером `[unverified]`.
поэтому предложение, содержащее оба пункта, засчитывается один раз. Сначала запустите `verify` без порогового значения
и прочитайте строку `info: stats:`, чтобы увидеть количество, прежде чем выбирать число.

## Подводные камни

- **Регистрация после записи.** Регистр должен заполняться на основе выходных данных инструмента.
  не реконструированный по черновику — это воссоздает именно галлюцинацию
  -URL рискует, нумерация удаляется.
– **Перенумерация в середине задачи.** Никогда не редактируйте идентификаторы вручную в черновике. Идентификаторы — это реестр
  личности; если в черновике цитируется `[4]`, `[4]` должен оставаться этим источником. Запустите `reset`
  только между задачами.
– **Повторный ввод URL-адресов в блок «Источники».** Всегда `render`. URL-адрес, набранный вручную
  является непроверенным утверждением.
– **Цитирование фрагмента поиска, как будто вы читаете страницу.** A `web_search`
  описание поддерживает только то, что в нем говорится буквально. Процитируйте извлеченную страницу
  когда требованию требуется тело — сначала `web_extract` его.
– **Чрезмерное цитирование.** Три идентификатора в предложении – это потолок; цитата на каждом
  Предложение делает текст нечитаемым и скрывает, какой источник несет нагрузку.
- **Ссылка на реестр в артефактах кода/конфигурации.** Комментарии к источнику относятся к
  прозаические результаты и заголовки документов, а не внутри сгенерированного кода.
- **Параллельные субагенты.** Каждый субагент имеет свой собственный рабочий каталог; точка
  их все в одном реестре с `--ledger` (или `HERMES_CITATION_LEDGER`), если их
  выходные данные объединяются, иначе их идентификаторы будут конфликтовать.
– **Цитирование из фрагмента, а не со страницы.** Должны быть доказательные цитаты.
  из извлеченного текста страницы, а не описания результатов поиска — `web_extract`
  сначала сохраните текст, затем `quote --from` этот файл.
- **Перефразируя в `quote --text`.** Дословная проверка отклонит его; тот
  исправление состоит в том, чтобы найти фактическое предложение, а не перефразировать его, пока что-то не совпадет.
- **Использование `[unverified]` в качестве аварийного люка.** Это редкое утверждение, что
  действительно не может быть получен; если большинство предложений содержат это, задача требует большего
  поиск, а не больше маркеров.
- **Ручное редактирование блока "Источники".** Используйте `render --replace-in <draft>`; нарезка
  сам файл рискует получить устаревший или дублированный блок, который `verify` затем пометит.

## Проверка

```bash
python3 "$S" verify report.md --strict --min-coverage 0.5
```

Зеленый цвет означает: каждый `[n]` в черновике существует в реестре, блок «Источники».
перечисляет именно цитируемые идентификаторы с URL-адресами реестра и цитируемую долю
исходные предложения соответствуют порогу. Прочтите предупреждения, даже если
код выхода равен 0 — нецитированные зарегистрированные источники обычно означают, что заявка утратила свою силу.
атрибуция во время редактирования.
