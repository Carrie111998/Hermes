# Библиотекарь сеансов

Управляйте библиотекой сеансов пользователя в диалоговом режиме: находите прошлые сеансы о
темы, обобщить то, что решили, осмысленно переименовать, разбить работу на
параллельные сеансы и предлагать устаревшие для архивации или удаления — и все это из
запрос на простом языке, например *"найдите мои сеансы о ценах на третий квартал, сохраните
полезные и удалите дубликаты."*

На основе оперативного управления сеансами Perplexity Computer (август 2026 г.):
агент запускает, организует и очищает собственную библиотеку сеансов пользователя и
всегда показывает план, прежде чем что-либо трогать.

## Когда использовать

- «Какие у меня сеансы по поводу Х?» / «Что мы решили насчет X?»
- «Переименуйте эти сеансы во что-нибудь значимое».
- «Очистить мою библиотеку сессий» / «архивировать устаревшие».
- «Разветвите эту сессию на продолжение, сосредоточенное на Y».
- «Разделите это на один сеанс для каждого билета» (см. «Параллельные рабочие процессы» ниже).

## Две поверхности

| Задача | Поверхность |
|---|---|
| Находите сессии по темам, читайте содержание, обобщайте решения | Инструмент `session_search` (FTS5 через хранилище сообщений) |
| Список/фильтр по метаданным (возраст, источник, стоимость, токены, рабочая область) | `hermes sessions list` / `stats` через терминал |
| Переименовать | `hermes sessions rename <session_id> <title...>` |
| Объемная мягкая кожа (двусторонняя) | `hermes sessions archive <filters>` |
| Удалить (разрушительное) | `hermes sessions delete` / `hermes sessions prune <filters>` |
| Экспортируйте, прежде чем удалять что-либо ценное | `hermes sessions export --session-id <id> --format md` |
| Продолжить работу на новом месте | `/branch` (разветвление текущего сеанса) или начните новый сеанс и процитируйте сводку |

## Процедура

① **Обнаружение.** Используйте `session_search(query=..., limit=5-10)` с темой.
ключевые слова; меняйте формулировку (название функции, симптом, название проекта). Для метаданных
свипы («сеансы старше 60 дней из телеграммы»), используйте
Вместо этого `hermes sessions list --source telegram --limit 50`.

② **Подведение итогов за сеанс.** Результат обнаружения: `bookend_start` (цель),
окно соответствия, и `bookend_end` (разрешение) обычно достаточно — просто выгрузите
полный сеанс (`session_search(session_id=...)`), когда пользователь запрашивает
решения в глубине. Сообщайте о каждом как: ссылка (форма `@session:`) — цель в одну строку —
однострочный результат.

③ **Планируйте, прежде чем действовать (ОБЯЗАТЕЛЬНО для всего, что мутирует).** Представьте
сначала спланируйте таблицу: какие сеансы во что переименовываются, какие архивируются,
которые предлагаются к удалению и почему (дубликаты какого хранителя, устаревшие,
пустой). Дождитесь разрешения пользователя. Исключение: однократное переименование пользователя
явно продиктованное, может быть сделано напрямую.

④ **Действуйте с помощью самого безопасного примитива.**
– Предпочитайте `archive` (двустороннюю мягкую кожу) `delete`/`prune`.
- Всегда сначала запускайте деструктивные команды с помощью `--dry-run` и показывайте результат,
  затем повторите запуск с помощью `--yes` после подтверждения.
– Прежде чем удалять что-либо значимое, предложите
  `hermes sessions export --format md` в качестве резервной копии.

⑤ **Отчет.** Применены переименования, сеансы заархивированы (количество + способ отмены:
заархивированные сеансы остаются в БД и обозначаются `--include-archived`),
что-нибудь экспортировано, что-нибудь пропущено и почему.

## Параллельные рабочие процессы

Для «одного сеанса на каждый билет, исследуйте каждый и отчитывайтесь»: НЕ пытайтесь
проводить другие живые сеансы. Используйте `delegate_task` с одной задачей на каждый рабочий поток —
каждый субагент автоматически запускается в своем сеансе, а затем синтезирует их
резюме. Упомяните, что стенограмма каждой делегации сама по себе доступна для поиска.
позже через `session_search`.

## Подводные камни

- **Никогда не удаляйте без пробного прогона + явного подтверждения в этом случае.
  разговор.** Постоянная фраза «навести порядок» — это право *предлагать*, а не
  обрезать.
– **`session_search` находит контент, а не метаданные.** Фильтры по возрасту, стоимости и источнику.
  жить в CLI; объединить оба, когда запрос их смешивает («старые сеансы
  о ценах»).
- **Названия совпадают с `/resume <title>`.** При переименовании сохранять названия.
  короткий, уникальный и удобный для префиксов; предупредить пользователя, если переименование конфликтует с
  существующее название.
- **В архиве ≠ удалено.** Архив скрывает сеансы только из списков по умолчанию.
  Скажи, какой ты сделал.
- **Ссылки на межпрофильные сеансы** (`@session:<profile>/<id>`) доступны только для чтения.
  из другого профиля; команды управления действуют на БД текущего профиля.

## Проверка

После завершения очистки повторно запустите запрос обнаружения и `hermes sessions list`
подтвердить, что библиотека соответствует плану (хранители представляют новые издания,
заархивированные исчезли из списка по умолчанию).
