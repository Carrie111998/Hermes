# Менеджер секретов Bitwarden

Извлекайте ключи API из [Bitwarden Secrets Manager](https://bitwarden.com/products/secrets-manager/) при запуске процесса вместо того, чтобы хранить их в виде открытого текста внутри `~/.hermes/.env`. Один секрет начальной загрузки (токен доступа к учетной записи компьютера) заменяет N ключей для каждого провайдера, а смена учетных данных становится одним изменением в веб-приложении Bitwarden.

## Как это работает

1. Вы создаете **учетную запись компьютера** в Bitwarden Secrets Manager, предоставляете ей доступ на чтение проекта и генерируете **токен доступа**.
2. Hermes сохраняет этот единственный токен в `~/.hermes/.env` как `BWS_ACCESS_TOKEN`.
3. Каждый раз при запуске `hermes` (или шлюза, или задания cron), после загрузки `~/.hermes/.env`, Hermes вызывает `bws secret list <project_id>` и устанавливает возвращенные ключи в `os.environ`.
4. По умолчанию Hermes **переопределяет** значения, уже имеющиеся в вашей среде, поэтому Bitwarden является источником истины — поверните ключ один раз в веб-приложении, и каждый процесс Hermes подберет его при следующем запуске. Переверните `override_existing: false` в конфигурации, если хотите, чтобы вместо этого победил `.env`.

Бинарный файл `bws` автоматически загружается в `~/.hermes/bin/` при первом использовании — ни `apt`, ни `brew`, ни `sudo`.

## Почему учетные записи компьютеров (и почему нет запроса 2FA)

Bitwarden Secrets Manager предназначен для неинтерактивных рабочих нагрузок: учетные записи компьютеров не могут быть защищены 2FA, поскольку в цикле нет человека. Токен доступа — это учетные данные. Любой, у кого он есть, может прочитать каждый секрет, к которому имеет доступ учетная запись компьютера, поэтому обращайтесь с ним как с ценным токеном на предъявителя — храните его в `.env` (а не `config.yaml`) и отзовите и восстановите его из веб-приложения Bitwarden, если он когда-либо утечет.

Вы настраиваете учетную запись компьютера *в веб-приложении*, к которой применяется обычная 2FA. После этого токен становится автономным.

## Настройка

### 1. Создайте учетную запись компьютера и токен доступа.

В [веб-приложении Bitwarden](https://vault.bitwarden.com) (или [vault.bitwarden.eu](https://vault.bitwarden.eu) для учетных записей ЕС):

1. Переключитесь на **Менеджер секретов** в переключателе продуктов.
2. Создайте или выберите **Проект** (например, «Ключи Гермеса»).
3. Добавьте ключи вашего провайдера в качестве секретов. Секрет **Name** становится именем переменной среды — используйте `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY` и т. д.
4. **Учетные записи компьютеров → Новая учетная запись компьютера → Моя машина Hermes** → вкладка **Проекты** → предоставить доступ для чтения к вашему проекту.
5. Вкладка **Токены доступа** → **Создать токен доступа** → **Срок действия **Никогда** не истекает (или выберите дату) → скопируйте токен (начинается с `0.`). Bitwarden не сможет получить его снова — сохраните копию.

Secrets Manager включен в уровень бесплатного пользования Bitwarden с ограничениями; для этого не нужен платный план.

### 2. Запустите мастер

```bash
hermes secrets bitwarden setup
```

Это будет:

1. Загрузите и подтвердите `bws v2.0.0` в `~/.hermes/bin/bws`.
2. Запросить токен доступа (ввод скрыт). Хранится в `~/.hermes/.env` как `BWS_ACCESS_TOKEN`.
3. Спросите, к какому региону Bitwarden принадлежит ваша учетная запись на компьютере — **Облако США**, **Облако ЕС** или **собственный/пользовательский URL**. Сохраняется в `config.yaml` как `secrets.bitwarden.server_url` и передается в `bws` как `BWS_SERVER_URL`.
4. Перечислите проекты, которые может видеть учетная запись компьютера; выберите один. Хранится в `config.yaml` как `secrets.bitwarden.project_id`.
5. Протестируйте секреты проекта и покажите, какие переменные окружения будут разрешены.
6. Переверните `secrets.bitwarden.enabled: true`.

Неинтерактивная настройка также поддерживается с помощью флагов:

```bash
hermes secrets bitwarden setup \
  --access-token "$BWS_ACCESS_TOKEN" \
  --server-url https://vault.bitwarden.eu \
  --project-id <project-uuid>
```

### 3. Подтвердите

```bash
hermes secrets bitwarden status
```

С этого момента каждый вызов `hermes` при запуске извлекает новые секреты. Вы увидите однострочное резюме в stderr, когда секреты впервые применяются в процессе.

## интерфейс командной строки

| Команда | Что он делает |
|---|---|
| `hermes secrets bitwarden setup` | Интерактивный мастер (установка двоичного файла, запрос токена, выбор проекта, тестовая выборка) |
| `hermes secrets bitwarden status` | Показать конфигурацию + двоичную версию + наличие/проверку токена |
| `hermes secrets bitwarden token` | Поменяйте токен доступа: проверьте новый токен на Bitwarden, затем сохраните его в `.env` |
| `hermes secrets bitwarden sync` | Пробный прогон: вытащите секреты сейчас и покажите, что будет применено |
| `hermes secrets bitwarden sync --apply` | Извлечение и экспорт в текущую среду оболочки |
| `hermes secrets bitwarden install` | Просто скачайте закрепленный двоичный файл `bws` (авторизация не требуется) |
| `hermes secrets bitwarden disable` | Перевернуть `enabled: false`; оставляет токен + идентификатор проекта на месте |

## Ротация просроченного или отозванного токена

Когда срок действия токена учетной записи компьютера истекает, он аннулируется или учетная запись удаляется, при запуске отображается:

```
Bitwarden Secrets Manager: Bitwarden rejected the machine-account access token (BWS_ACCESS_TOKEN) — it was likely revoked, expired, or belongs to another region.  (...)
Bitwarden Secrets Manager: → Run `hermes secrets bitwarden token` to paste a fresh access token ...
```

Исправьте это, не перезапуская весь мастер:

```bash
hermes secrets bitwarden token                     # masked prompt
hermes secrets bitwarden token --access-token 0.…  # non-interactive
```

Команда проверяет Bitwarden с помощью нового токена **прежде** записи чего-либо — отклоненный токен оставляет ваш текущий `.env` нетронутым. В случае успеха он сохраняет токен, очищает кэши выборки и предупреждает, если настроенный проект не виден для новой учетной записи компьютера.

## Конфигурация

Значения по умолчанию в `~/.hermes/config.yaml`:

```yaml
secrets:
  bitwarden:
    enabled: false
    access_token_env: BWS_ACCESS_TOKEN
    project_id: ""
    server_url: ""
    cache_ttl_seconds: 300
    encrypted_cache:
      enabled: false
      max_stale_seconds: 0
    override_existing: true
    auto_install: true
```

| Ключ | По умолчанию | Что он делает |
|---|---|---|
| `enabled` | `false` | Главный переключатель. Если это ложь, с Bitwarden никогда не связываются. |
| `access_token_env` | `BWS_ACCESS_TOKEN` | Имя переменной окружения, содержащее токен начальной загрузки. Измените это, если вы уже используете `BWS_ACCESS_TOKEN` для чего-то другого. |
| `project_id` | `""` | UUID проекта для синхронизации. |
| `server_url` | `""` | Регион Bitwarden или самостоятельная конечная точка. Пусто = `bws` по умолчанию (облако США, `https://vault.bitwarden.com`). Установите значение `https://vault.bitwarden.eu` для EU Cloud или свой собственный URL-адрес для самостоятельного размещения. Подключен к подпроцессу `bws` как `BWS_SERVER_URL`. |
| `cache_ttl_seconds` | `300` | Как долго результат выборки в процессе или с диска используется повторно. Установите значение `0`, чтобы отключить повторное использование свежего кэша. |
| `encrypted_cache.enabled` | `false` | Сохраните последнюю успешную выборку в зашифрованном кеше AES-GCM по адресу `~/.hermes/cache/bws_cache.enc.json`. |
| `encrypted_cache.max_stale_seconds` | `0` | Если зашифрованное кэширование включено, разрешите использование этого кэша только после сбоев сети или тайм-аута, вплоть до этого возраста. При сбоях аутентификации никогда не используются устаревшие секреты. Успешная зашифрованная запись удаляет устаревший открытый текст `cache/bws_cache.json`. |
| `override_existing` | `true` | Если это правда, значения Bitwarden перезаписывают все, что уже есть в env (поэтому вращение в веб-приложении фактически вступает в силу). Перейдите на `false`, если хотите, чтобы экспорт `.env` / оболочки выполнялся локально. |
| `auto_install` | `true` | Если это правда, `bws` автоматически загружается в `~/.hermes/bin/` при первом использовании. |

## Режимы отказа

Bitwarden никогда не блокирует стартап Hermes. Если что-то пойдет не так, вы увидите однострочное предупреждение в stderr, и Hermes продолжит работу с теми учетными данными, которые уже были у `.env`:

| Симптом | Причина | Исправить |
|---|---|---|
| `BWS_ACCESS_TOKEN is not set` | Включено в конфигурации, но токен удален из `.env` | Повторно запустить `hermes secrets bitwarden setup` |
| `Bitwarden rejected the machine-account access token … invalid_client` | Токен отозван, срок его действия истек, учетная запись компьютера удалена — или токен принадлежит другому региону (например, токен ЕС попадает в конечную точку идентификации в США) | Запустите `hermes secrets bitwarden token`, чтобы вставить новый токен; если регион не соответствует, повторно запустите настройку и выберите EU/self-hosted (или установите `secrets.bitwarden.server_url`) |
| `bws exited 1: invalid access token` | Токен отозван или ошибочен | Запустите `hermes secrets bitwarden token` с новым токеном |
| `bws timed out` | Сеть заблокирована или API Bitwarden работает медленно | Проверьте подключение к `api.bitwarden.com` (или вашему `server_url`) |
| `bws binary not available` | `auto_install: false` и `bws` не в PATH | Установите вручную с [github.com/bitwarden/sdk-sm/releases](https://github.com/bitwarden/sdk-sm/releases) или снова включите `auto_install` |
| `Checksum mismatch` | Загрузка повреждена или подделана | Повторный запуск, повторит попытку; если проблема не исчезнет, ​​сообщите о проблеме |

Предупреждения при запуске теперь включают строку исправления `→`, сообщающую, какая именно команда устраняет сбой.

## Примечания по безопасности

- Токен начальной загрузки (`BWS_ACCESS_TOKEN`) сам по себе является конфиденциальным — любой, у кого он есть, может прочитать каждый секрет, к которому имеет доступ учетная запись компьютера. Относитесь к нему так же, как и к любому другому ключу API.
— Hermes не позволит Bitwarden перезаписать сам загрузочный токен, даже с `override_existing: true`. Если вы сохраните `BWS_ACCESS_TOKEN` как секрет внутри проекта, он будет автоматически пропущен во время применения.
- Двоичная загрузка `bws` проверяется по опубликованной контрольной сумме SHA-256 из того же выпуска GitHub. Несоответствие прерывает установку.
- Закрепленная версия (`bws v2.0.0` на момент написания) обновляется через PR в этом репозитории — Hermes не обновляет автоматически `bws` до «последней», поскольку формы исходных выпусков могут измениться.

## Когда НЕ использовать это

- **Личные настройки для одного компьютера**, где `~/.hermes/.env` подходит. Вы меняете одни учетные данные на другие и добавляете сетевую зависимость при запуске.
- **Среды с воздушным зазором**, которые не могут достичь `api.bitwarden.com`.
- **CI/CD**, где уже настроен существующий механизм внедрения секретов (секреты GitHub Actions, Vault и т. д.) — выберите один путь, а не два.

Хорошим примером для этого являются парки из нескольких компьютеров, общие блоки разработки, шлюзовые VPS или любая конфигурация, в которой вам нужна централизованная ротация и отзыв в нескольких установках Hermes.
