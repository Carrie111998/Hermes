# Секретный источник помощника команды

Разрешите учетные данные, запустив собственную вспомогательную команду при запуске — подойдет любое секретное хранилище с CLI: `keepassxc-cli`, `secret-tool` (GNOME Keyring), `pass`, `gpg`, CLI Vaultwarden или сценарий, обрабатывающий env-файл tmpfs. Помощник печатает `KEY=VALUE` строк на стандартный вывод; Hermes применяет их через тот же оркестратор, что и [Bitwarden](./bitwarden) и [1Password](./onepassword), поэтому вы можете одновременно включить любую комбинацию источников.

## Как это работает

1. Вы настраиваете вспомогательную команду в `config.yaml` (никогда в `.env` — команда является конфигурационной, `.env` содержит значения).
2. При запуске, после загрузки `.env`, Hermes запускает помощник ОДИН РАЗ через `/bin/sh -c` и анализирует его стандартный вывод как объект dotenv.
3. Проанализированные ключи проходят стандартную лестницу приоритета: `.env`/shell win, если только `override_existing: true`; сопоставленные источники превосходят этот основной источник по спорным переменным; первая претензия выигрывает.

```yaml
secrets:
  command:
    enabled: true
    command: "cat /run/user/1000/hermes-secrets.env"
    # or any vault CLI that dumps KEY=VALUE lines:
    # command: "pass show hermes/env"
    # command: "secret-tool lookup service hermes-env"
```

## Конфигурация

| Ключ | По умолчанию | Что он делает |
|---|---|---|
| `enabled` | `false` | Главный переключатель. |
| `command` | `""` | Помощник запускается через `/bin/sh -c`; должен вывести `KEY=VALUE` строк на стандартный вывод. |
| `helper_timeout_seconds` | `3` | Жесткий тайм-аут для одного пробега помощника. Намеренно жестко — помощник должен быть быстрым и НЕинтерактивным (без подсказок разблокировки, без касаний и PIN-кода). |
| `override_existing` | `false` | Вспомогательные значения перезаписывают значения `.env`/shell. По умолчанию отключено (в отличие от Bitwarden/1Password), поскольку локальный помощник не является центральным органом ротации. |

## Модель безопасности

- Вспомогательная командная строка — это ВАША конфигурация — тот же уровень доверия, что и у файла `.env`, которым вы управляете.
- Выходной объем жестко ограничен 1 МБ; сбежавший помощник не может заблокировать запуск (группа процессов уничтожена по тайм-ауту).
- **stderr помощника отбрасывается** — диагностические данные CLI хранилища могут содержать секретный материал, поэтому они никогда не достигают выходных данных Hermes. Сбои регистрируются только в структурированных полях (код выхода/сигнал/ошибка), но не в командной строке.
— Значения, содержащие только пробелы, рассматриваются как «отсутствующие значения» — запись-заполнитель никогда не попадает в заголовок авторизации.
- Только для POSIX (требуется `/bin/sh`). В Windows источник сообщает, что он не настроен, и запуск продолжается.

## Режимы отказа

Запуск никогда не блокируется. Ошибки печатают одну строку плюс подсказку по исправлению `→`:

| Симптом | Причина | Исправить |
|---|---|---|
| `secrets.command.command is empty` | Включается без команды | Установите `secrets.command.command` в config.yaml |
| `helper command failed` | Ненулевой выход, тайм-аут, сбой появления | Запустите помощник вручную в оболочке, чтобы увидеть его реальную ошибку (Hermes намеренно отбрасывает свой stderr) |
| `helper output was not a KEY=VALUE map` | Помощник напечатал пустое значение или мусор | Заставить помощника выводить линии в форме точки |

## Когда использовать это, а не плагин

Источником команд является аварийный люк для хранилищ без встроенной интеграции. Если вам приходится заключать сложный танец CLI в длинный скрипт, рассмотрите вместо этого подходящий [плагин с секретным исходным кодом](/developer-guide/secret-source-plugin) — плагины получают кеширование, метки происхождения и типизированную конфигурацию.
