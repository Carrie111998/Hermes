#1Пароль

Разрешайте ключи API поставщика из [1Password](https://1password.com/) при запуске процесса вместо хранения их в виде открытого текста внутри `~/.hermes/.env`. Вы храните свои ключи как элементы 1Password и ссылаетесь на них с помощью `op://vault/item/field`; ротация учетных данных становится одним изменением в 1Password.

## Как это работает

1. Вы устанавливаете официальный [1Password CLI](https://developer.1password.com/docs/cli/get-started/) (`op`) и аутентифицируете его — либо с помощью **токена сервисной учетной записи** (автономные серверы), либо с помощью **интерактивного/настольного сеанса** (ваш ноутбук).
2. Вы сопоставляете имена переменных среды со ссылками `op://` в `~/.hermes/config.yaml`.
3. Каждый раз при запуске `hermes` (или шлюза, или задания cron) после загрузки `~/.hermes/.env` Hermes запускает `op read` для каждой ссылки и устанавливает разрешенные значения в `os.environ`.
4. По умолчанию Hermes **переопределяет** значения, уже имеющиеся в вашей среде, поэтому 1Password является источником истины — поменяйте учетные данные один раз, и каждый процесс Hermes подберет их при следующем запуске. Переверните `override_existing: false`, если хотите, чтобы вместо этого выиграл `.env`.

Hermes никогда не выполняет аутентификацию от вашего имени и никогда не загружает `op`: он обращается к вашему уже установленному, уже доверенному интерфейсу командной строки. Если `op` отсутствует, ваш сеанс заблокирован или ссылка неверна, Hermes выводит однострочное предупреждение и продолжает работу с теми учетными данными, которые уже были у `.env` — он никогда не блокирует запуск.

## Аутентификация

`op` поддерживает два неинтерактивных режима; Гермес работает с:

- **Служебные учетные записи** (рекомендуется для серверов/CI): создайте сервисную учетную запись в 1Password, предоставьте ей доступ на чтение к соответствующему хранилищу и экспортируйте ее токен как `OP_SERVICE_ACCOUNT_TOKEN` в `~/.hermes/.env`. Токен — это учетные данные — обращайтесь с ним как с любым другим токеном на предъявителя.
- **Настольные/интерактивные сеансы** (ноутбуки): запустите `op signin` (или включите интеграцию CLI в приложении 1Password). Hermes передает ваши переменные `OP_SESSION_*` дочернему процессу `op`. Ключ кэша 1Password включает в себя эти переменные сеанса, поэтому при входе в другую учетную запись никогда не будет использоваться значение, кэшированное под предыдущим идентификатором.

## Токен начальной загрузки

Когда вы проходите аутентификацию с помощью **токена сервисной учетной записи**, этот токен сам по себе является учетными данными начальной загрузки, которые необходимы Гермесу *прежде* того, как он сможет разрешить любую ссылку `op://`. Он должен присутствовать в `os.environ` каждого процесса, который раскрывает секреты, включая задания cron (`kanban.dispatch_in_gateway: false`), вызовы подпроцессов, запуски CLI, агенты запуска macOS и контейнеры Docker, а не только интерактивный шлюз. Сделать его доступным можно тремя способами в порядке приоритета:

1. **В `~/.hermes/.env` (рекомендуется).** `hermes secrets onepassword setup --token <token>` записывает токен в `~/.hermes/.env`, точно так же, как `BWS_ACCESS_TOKEN` Bitwarden. Поскольку `load_hermes_dotenv()` всегда загружает `.env`, токен доступен везде без каких-либо дополнительных настроек. Это самый простой надежный вариант.

2. **В `~/.hermes/.op.env` (gitignored).** Если вы предпочитаете хранить токен служебной учетной записи вне `.env` — например, чтобы `.env` можно было вернуть в частный репозиторий точечных файлов, в то время как токен остается вне контроля версий — поместите его в `~/.hermes/.op.env`:

   ```bash
   echo 'OP_SERVICE_ACCOUNT_TOKEN=ops_...' > ~/.hermes/.op.env
   chmod 600 ~/.hermes/.op.env
   ```

   Hermes автоматически загружает `.op.env` при запуске, **после** `.env` и **никогда** не переопределяет токен, уже присутствующий в среде. `.op.env` игнорируется git, поэтому токен никогда не попадает в зафиксированный файл.

3. **Через systemd `EnvironmentFile` (шлюз Linux).** Если вы запускаете шлюз под systemd, вы можете внедрить токен непосредственно в сервисную среду:

   ```ini
   [Service]
   EnvironmentFile=-/home/youruser/.hermes/.op.env
   ```

Токен, введенный таким образом, имеет приоритет — Hermes обнаруживает, что `OP_SERVICE_ACCOUNT_TOKEN` уже установлен, и полностью пропускает загрузку `.op.env`.

Если токен доступен только через интерактивную оболочку (`op signin`, `OP_SESSION_*` экспортируется в `.bashrc` и т. д.), он **не** будет унаследован заданиями cron или недавно созданными подпроцессами, и эти контексты будут регистрировать предупреждение и возвращаться к любым учетным данным, которые уже имеются в `.env`. Используйте один из трех вариантов выше для любой неинтерактивной рабочей нагрузки.

## Настройка

### 1. Установите и войдите в `op`.

Следуйте [руководству по началу работы с 1Password CLI] (https://developer.1password.com/docs/cli/get-started/). Убедитесь, что это работает:

```bash
op whoami
```

### 2. Включите интеграцию

```bash
hermes secrets onepassword setup
```

Это подтверждает, что `op` находится на `PATH` (или используйте `--binary-path`), записывает настройки вашей учетной записи/токена, проверяет наличие активного сеанса и переключает `secrets.onepassword.enabled: true`. Неинтерактивные флаги:

```bash
hermes secrets onepassword setup \
  --account my.1password.com \
  --token-env OP_SERVICE_ACCOUNT_TOKEN \
  --token "$OP_SERVICE_ACCOUNT_TOKEN"
```

### 3. Сопоставьте свои учетные данные

Формат ссылки: `op://<vault>/<item>/<field>`:

```bash
hermes secrets onepassword set OPENAI_API_KEY    "op://Private/OpenAI/api key"
hermes secrets onepassword set ANTHROPIC_API_KEY "op://Private/Anthropic/credential"
```

### 4. Предварительный просмотр и подтверждение

```bash
hermes secrets onepassword sync     # dry-run: resolve now, show what would apply
hermes secrets onepassword status   # config + binary + references + auth
```

С этого момента каждый вызов `hermes` разрешает ссылки при запуске. Вы увидите однострочное резюме в stderr, когда секреты впервые применяются в процессе.

## интерфейс командной строки

| Команда | Что он делает |
|---|---|
| `hermes secrets onepassword setup` | Проверьте `op`, установите переменную среды учетной записи/токена, включите |
| `hermes secrets onepassword status` | Показать настройки, двоичные файлы, аутентификацию и настроенные ссылки |
| `hermes secrets onepassword token` | Поменяйте токен сервисной учетной записи: подтвердите его с помощью `op whoami`, затем сохраните его в `.env` |
| `hermes secrets onepassword set ENV_VAR "op://…"` | Сопоставьте переменную окружения со ссылкой (сохраняется удаленной + проверенной) |
| `hermes secrets onepassword remove ENV_VAR` | Отбросить сопоставление |
| `hermes secrets onepassword sync` | Пробный прогон: разрешите ссылки сейчас и покажите, что можно применить |
| `hermes secrets onepassword sync --apply` | Разрешение и экспорт в текущую среду оболочки |
| `hermes secrets onepassword disable` | Перевернуть `enabled: false`; оставляет сопоставления на месте |

`op` и `1password` принимаются как псевдонимы для `onepassword`.

## Конфигурация

Значения по умолчанию в `~/.hermes/config.yaml`:

```yaml
secrets:
  onepassword:
    enabled: false
    env:
      OPENAI_API_KEY: "op://Private/OpenAI/api key"
      ANTHROPIC_API_KEY: "op://Private/Anthropic/credential"
    account: ""
    service_account_token_env: OP_SERVICE_ACCOUNT_TOKEN
    binary_path: ""
    cache_ttl_seconds: 300
    override_existing: true
```

| Ключ | По умолчанию | Что он делает |
|---|---|---|
| `enabled` | `false` | Главный переключатель. Если значение false, `op` никогда не вызывается. |
| `env` | `{}` | Сопоставление имени env-var → ссылка `op://vault/item/field`. Записи, имя которых не является допустимым именем env-var или значение которых не является ссылкой `op://`, пропускаются с предупреждением. |
| `account` | `""` | Сокращение учетной записи/адрес для входа передается как `op read --account`. Empty использует учетную запись `op` по умолчанию. |
| `service_account_token_env` | `OP_SERVICE_ACCOUNT_TOKEN` | Env var Hermes считывает токен сервисной учетной записи. Его значение экспортируется в дочерний элемент `op` как `OP_SERVICE_ACCOUNT_TOKEN` (ожидается имя `op`). Оставьте переменную неустановленной, чтобы использовать рабочий стол/интерактивный сеанс. |
| `binary_path` | `""` | Абсолютный путь к `op`. Если он установлен, он используется дословно, а `PATH` **не** проверяется — закрепите это, чтобы не доверять тому, что `op` появляется первым на `PATH`. |
| `cache_ttl_seconds` | `300` | Как долго разрешенные значения используются повторно (в процессе и на диске). Установите значение `0`, чтобы отключить **оба** уровня кэша — значения вообще не записываются на диск. |
| `override_existing` | `true` | Если это правда, разрешенные значения перезаписывают все, что уже есть в env (так что вращение вступает в силу). Переключитесь на `false`, чтобы экспорт `.env`/оболочки выиграл; затем эти ссылки пропускаются *до* вызова `op`. |

## Режимы отказа

1Password никогда не блокирует запуск Hermes. Если что-то пойдет не так, вы увидите однострочное предупреждение в stderr, и Гермес продолжит:

| Симптом | Причина | Исправить |
|---|---|---|
| `the op CLI was not found on PATH` | `op` не установлен/не находится в PATH | Установите CLI или установите `secrets.onepassword.binary_path` |
| `op read failed for 'op://…': …` | Сеанс заблокирован, срок действия токена истек или нет доступа к хранилищу | `op signin`, запустите `hermes secrets onepassword token`, чтобы заменить токен сервисной учетной записи, или предоставьте доступ к сервисной учетной записи |
| `op read returned an empty value for 'op://…'` | Поле, на которое есть ссылка, существует, но пусто | Исправьте элемент/поле в 1Password (пустое значение никогда не применяется — существующая переменная окружения остается нетронутой) |
| `… is not an op:// secret reference` | Значение сопоставления не является ссылкой `op://` | Переустановите его, используя правильную форму `op://vault/item/field` |
| `op read timed out` | Сеть заблокирована или 1Password работает медленно | Проверка подключения/интеграции настольного приложения |

Предупреждения при запуске теперь включают строку исправления `→`, сообщающую, какая именно команда устраняет сбой.

## Кэширование

Успешные полные запросы кэшируются внутри процесса и на диске под `<hermes_home>/cache/op_cache.json` (записываются атомарно, режим `0600`), поэтому последовательные кратковременные вызовы `hermes` не перезагружают `op` для каждой ссылки. Кэш:

- сохраняет только разрешенные секретные **значения** — никогда не токен сервисной учетной записи или какой-либо необработанный материал аутентификации (отпечаток аутентификации сохраняется в ключе кэша);
- становится недействительным при изменении токена, учетной записи, переменных `OP_SESSION_*` или набора ссылок;
- **не** записывается, когда при получении возникла какая-либо ошибка для каждой ссылки, поэтому временный сбой аутентификации не фиксируется для TTL;
- полностью отключен — читает *и* записывает — когда `cache_ttl_seconds: 0`.

## Примечания по безопасности

- Токен сервисной учетной записи 1Password может читать каждый секрет, к которому имеет доступ эта учетная запись. Сохраните его в `~/.hermes/.env` (не `config.yaml`) и отзовите + восстановите 1Password в случае утечки.
- Hermes отказывается позволить разрешенному значению перезаписать саму переменную env var токена, даже с `override_existing: true`.
- Дочерний процесс `op` получает минимальную среду из разрешенного списка (переменные аутентификации/сессии + `PATH`/`HOME`), а не копию полного `os.environ`, поэтому не все учетные данные поставщика post-dotenv наследуются дочерним процессом.
- Ссылки проверяются, чтобы они начинались с `op://`, и ссылка передается после признака завершения опции `--`, поэтому созданное значение не может быть проанализировано как флаг `op`.

## Когда НЕ использовать это

- **Личные настройки для одного компьютера**, где `~/.hermes/.env` подходит.
- **Среды с воздушным зазором**, в которых невозможно подключиться к 1Password.
- **CI/CD**, где уже подключен существующий механизм внедрения секретов — выберите один путь, а не два.

Хорошим примером для этого являются парки из нескольких компьютеров, общие блоки разработки, шлюзовые VPS или любое другое место, где вам нужна централизованная ротация и отзыв в нескольких установках Hermes.
