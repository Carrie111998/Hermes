# Вклад

Благодарим вас за вклад в развитие Hermes Agent! В этом руководстве рассказывается о настройке среды разработки, понимании кодовой базы и объединении вашего PR.

## Приоритеты вклада

Мы оцениваем вклад в следующем порядке:

1. **Исправлены ошибки** — сбои, некорректное поведение, потеря данных.
2. **Кроссплатформенная совместимость** — macOS, различные дистрибутивы Linux, WSL2.
3. **Усиление безопасности** — внедрение оболочки, быстрое внедрение, обход пути.
4. **Производительность и надежность** — логика повторных попыток, обработка ошибок, постепенное ухудшение качества.
5. **Новые навыки** — широко полезные (см. [Создание навыков](creating-skills.md))
6. **Новые инструменты** — нужны редко; большинство способностей должны быть навыками
7. **Документация** — исправления, пояснения, новые примеры.

## Общие пути вклада

- Создание собственного/локального инструмента без изменения ядра Hermes? Начните с [Создать плагин Hermes](../developer-guide/plugins/index.md)
- Создаете новый встроенный основной инструмент для самого Hermes? Начните с [Добавление инструментов](./adding-tools.md)
- Приобретение нового навыка? Начните с [Создание навыков](./creating-skills.md)
- Создаете нового поставщика логических выводов? Начните с [Добавление поставщиков](./adding-providers.md)

## Настройка разработки

### Предварительные условия

| Требование | Заметки |
| -------------------- | --------------------------------------------------------------------------------------------- |
| **Гит** | С установленным расширением `git-lfs` |
| **Питон 3.11–3.13** | uv установит его, если он отсутствует |
| **УФ** | Менеджер пакетов Fast Python ([install](https://docs.astral.sh/uv/)) |
| **Node.js 26+** | Необязательно — необходимо для инструментов браузера и моста WhatsApp (соответствует корневым движкам `package.json`) |

### Установка стандартным установщиком

Для большинства участников лучшая начальная загрузка разработки — это один и тот же путь пользователей.
Возьмите: запустите стандартный установщик, затем поработайте внутри клонированного им репозитория.
Установщик создает venv Hermes, подключает команду `hermes`, штампует
install для `hermes update` и клонирует полный проект git в
`$HERMES_HOME/hermes-agent` (обычно `~/.hermes/hermes-agent`). Это сохранит ваш
среда разработки в том же макете, CLI, средство обновления, ленивая зависимость
установщик, шлюз и документация предполагают.

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
cd "${HERMES_HOME:-$HOME/.hermes}/hermes-agent"

# Add dev/test extras on top of the standard install.
uv pip install -e ".[all,dev]"

# Optional: browser tools / docs site dependencies.
npm install
```

После этого создайте ветки и запустите тесты из этой проверки:

```bash
git checkout -b fix/description
scripts/run_tests.sh
```

Вы также можете запустить полностью изолированный экземпляр Hermes (одноразовый HERMES_HOME, отдельный Electron
userData, отдельное имя приложения Electron, чтобы избежать блокировки одного экземпляра):

```bash
scripts/dev-sandbox.sh python -m hermes_cli.main
scripts/dev-sandbox.sh --persistent python -m hermes_cli.main desktop  # state survives restarts, but lives in the worktree :)
```

### Резервное клонирование вручную

Используйте это только в том случае, если вы намеренно не хотите использовать макет управляемой установки Hermes.
(например, одноразовый клон внутри контейнера или задания CI). Если вы установите
таким образом убедитесь, что вы запускаете точку входа `hermes` из этого венва; управление
система `python3 -m hermes_cli.main` может использовать несвязанную систему Python
пакеты.

Создайте venv **вне** клонированного дерева исходного кода. Венв, который живет внутри
каталог, из которого работает агент, может быть уничтожен командой относительного пути
агент работает со своей собственной кассой (`rm -rf venv`, `uv venv venv` и т. д.),
который молча уничтожает работающую среду выполнения в середине сеанса. Храня его вне
дерево означает, что к нему не разрешается относительный путь из рабочей области.

```bash
git clone https://github.com/NousResearch/hermes-agent.git
cd hermes-agent

# Create venv with Python 3.11, OUTSIDE the source tree
uv venv ~/.hermes/venvs/hermes-dev --python 3.11
export VIRTUAL_ENV="$HOME/.hermes/venvs/hermes-dev"
export PATH="$VIRTUAL_ENV/bin:$PATH"

# Install with all extras (messaging, cron, CLI menus, dev tools)
uv pip install -e ".[all,dev]"

# Optional: browser tools
npm install
```

### Настройка для разработки

```bash
mkdir -p ~/.hermes/{cron,sessions,logs,memories,skills}
cp cli-config.yaml.example ~/.hermes/config.yaml
touch ~/.hermes/.env

# Add at minimum an LLM provider key:
echo 'OPENROUTER_API_KEY=sk-or-v1-your-key' >> ~/.hermes/.env
```

### Беги

```bash
# The standard installer already put `hermes` on PATH.
hermes doctor
hermes chat -q "Hello"
```

Если вы использовали резервное клонирование вручную, запустите `./hermes` из оформления заказа или
явно укажите символическую ссылку на venv этого клона:

```bash
mkdir -p ~/.local/bin
ln -sf "$(pwd)/venv/bin/hermes" ~/.local/bin/hermes
```

### Запуск тестов

```bash
scripts/run_tests.sh
```

## Стиль кода

- **PEP 8** с практическими исключениями (без строгого соблюдения длины строки)
- **Комментарии**: только при объяснении неочевидных намерений, компромиссов или особенностей API.
- **Обработка ошибок**: перехват определенных исключений. Используйте `logger.warning()`/`logger.error()` с `exc_info=True` для непредвиденных ошибок.
- **Кроссплатформенность**: никогда не предполагайте Unix (см. ниже).
- **Пути, безопасные для профиля**: никогда не кодируйте `~/.hermes` жестко — используйте `get_hermes_home()` из `hermes_constants` для путей кода и `display_hermes_home()` для сообщений, предназначенных для пользователей. Полные правила см. в [AGENTS.md](https://github.com/NousResearch/hermes-agent/blob/main/AGENTS.md#profiles-multi-instance-support).

## Межплатформенная совместимость

См. **[Поддержка платформы](../getting-started/platform-support.md)**. Собственный Windows использует Git Bash (из [Git для Windows](https://git-scm.com/download/win)) для команд оболочки. Для некоторых функций требуются примитивы ядра POSIX, и они являются закрытыми: для встроенной панели терминала PTY панели мониторинга (вкладка `/chat`) требуется POSIX PTY (Linux, macOS или WSL2). Если вы занимаетесь разработкой с интенсивным использованием Windows, запустите Windows-footgun lint (`scripts/check-windows-footguns.py`) перед отправкой.

При написании кода помните следующие правила:

- **Не добавляйте незащищенные ссылки `signal.SIGKILL`.** Это не определено в Windows. Либо используйте маршрут через `gateway.status.terminate_pid(pid, force=True)` (централизованный примитив, который выполняет `taskkill /T /F` в Windows и SIGKILL в POSIX), либо откажитесь от `getattr(signal, "SIGKILL", signal.SIGTERM)`.
- **Перехват `OSError` рядом с `ProcessLookupError` на зондах `os.kill(pid, 0)`.** Windows вызывает `OSError` (WinError 87, «неверный параметр») для уже исчезнувшего PID вместо `ProcessLookupError`.
- **Не заставляйте терминал использовать семантику POSIX.** `os.setsid`, `os.killpg`, `os.getpgid`, `os.fork` все поднимаются в Windows — заблокируйте их с помощью `if sys.platform != "win32":` или `if os.name != "nt":`.
- **Открывать файлы с явным `encoding="utf-8"`.** По умолчанию Python в Windows является системным языковым стандартом (часто cp1252), который вызывает моджибак или аварийно завершает работу при тексте, написанном не на латинице.
- **Используйте `pathlib.Path` / `os.path.join` — никогда не объединяйте вручную с `/`.** Это имеет меньшее значение для строк, которые возвращает нам ОС, и больше для строк, которые мы конструируем для передачи подпроцессам.

Ключевые шаблоны:

### 1. Кодировка файла

В некоторых средах файлы `.env` могут сохраняться в кодировках, отличных от UTF-8:

```python
try:
    load_dotenv(env_path)
except UnicodeDecodeError:
    load_dotenv(env_path, encoding="latin-1")
```

### 2. Управление процессами

`os.setsid()`, `os.killpg()` и обработка сигналов различаются на разных платформах:

```python
import platform
if platform.system() != "Windows":
    kwargs["preexec_fn"] = os.setsid
```

### 3. Разделители путей

Используйте `pathlib.Path` вместо объединения строк с `/`.

## Вопросы безопасности

У Гермеса есть доступ к терминалу. Безопасность имеет значение.

### Существующие средства защиты

| Слой | Реализация |
| ------------------------------- | --------------------------------------------------------------------------- |
| **Передача паролей Sudo** | Использует `shlex.quote()` для предотвращения внедрения оболочки |
| **Обнаружение опасных команд** | Шаблоны регулярных выражений в `tools/approval.py` с потоком одобрения пользователей |
| **Быстрое внедрение Cron** | Сканер блокирует шаблоны переопределения инструкций |
| **Создание списка запретов** | Защищенные пути разрешаются через `os.path.realpath()` для предотвращения обхода символических ссылок |
| **Навыки охраны** | Сканер безопасности для навыков, установленных в хабе |
| **Песочница выполнения кода** | Дочерний процесс запускается с удаленными ключами API |
| **Упрочнение контейнера** | Docker: все возможности отключены, повышение привилегий отсутствует, ограничения PID |

### Внесение кода, чувствительного к безопасности

- Всегда используйте `shlex.quote()` при интерполяции пользовательского ввода в команды оболочки.
– Разрешайте символические ссылки с помощью `os.path.realpath()` перед проверками контроля доступа.
- Не регистрируйте секреты
- Выявляйте широкие исключения, связанные с выполнением инструмента.
- Протестируйте на всех платформах, если ваши изменения затрагивают пути к файлам или процессы.

## Процесс запроса на включение

### Именование ветвей

```
fix/description        # Bug fixes
feat/description       # New features
docs/description       # Documentation
test/description       # Tests
refactor/description   # Code restructuring
```

### Перед отправкой

1. **Выполните тесты**: `scripts/run_tests.sh` для проверки четности CI. Используйте прямой `python -m pytest ...` только в том случае, если оболочка недоступна или вы намеренно выполняете отладку вне оболочки.
2. **Проверка вручную**. Запустите `hermes` и проверьте измененный путь кода.
3. **Проверьте влияние кроссплатформенности**. Рассмотрите macOS, Linux, WSL2 и родную версию Windows. Если вы коснетесь файлового ввода-вывода, управления процессами, обработки терминала, подпроцессов или сигналов, запустите `scripts/check-windows-footguns.py`.
4. **Сосредоточьтесь на PR**: одно логическое изменение на каждый PR.

### PR-описание

Включить:

- **Что** изменилось и **почему**
- **Как проверить** это
– **На каких платформах** вы тестировали
- Ссылаться на любые сопутствующие вопросы

### Сообщения о фиксации

Мы используем [Обычные коммиты](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>
```

| Тип | Использовать для |
| ---------- | ----------------------------- |
| `fix` | Исправления ошибок |
| `feat` | Новые возможности |
| `docs` | Документация |
| `test` | Тесты |
| `refactor` | Реструктуризация кода |
| `chore` | Сборка, CI, обновления зависимостей |

Области: `cli`, `gateway`, `tools`, `skills`, `agent`, `install`, `whatsapp`, `security`

Примеры:

```
fix(cli): prevent crash in save_config_value when model is a string
feat(gateway): add WhatsApp multi-user session isolation
fix(security): prevent shell injection in sudo password piping
```

### Контрольные списки проверки локального репозитория: `.agents/checks/*.md`

Проекты, созданные на основе Hermes (или проверенные им), могут хранить контрольные списки рецензентов в репозитории под `.agents/checks/`. Каждый файл представляет собой целенаправленный контрольный список с простой уценкой, который агент загружает перед проверкой изменения, касающегося соответствующей области:

```
.agents/
  checks/
    security.md        # e.g. "grep the diff for shell interpolation; check subprocess calls quote args"
    migrations.md      # e.g. "every schema change ships a backfill and a rollback note"
    public-api.md      # e.g. "exported signatures changed? flag for semver review"
```

Соглашения, благодаря которым они работают хорошо:

- **Одна проблема на файл**, названная в честь проблемы. Небольшие файлы читаются полностью; монолитный `checklist.md` просматривается.
- **Пишите проверки как проверяемые действия** («запустите X и подтвердите Y»), а не как стремление («код должен быть безопасным»).
- **Укажите триггер вверху** — к каким путям или типам изменений относится контрольный список — чтобы агент (или человек) мог дешево пропустить ненужные события.
— Держите их под контролем версий рядом с кодом, который они охраняют: они развиваются вместе с кодовой базой, а PR, меняющий правила, меняет контрольный список в том же диффе.

Когда вы просите Hermes просмотреть PR в репозитории, в котором есть `.agents/checks/`, скажите ему (или научите его с помощью навыка), чтобы он сначала прочитал соответствующие контрольные списки и составил отчет по ним. Это дает агентам проверки специфичную для проекта планку, которую не пропускают общие подсказки о проверке.

## Проблемы с отчетами

- Используйте [Проблемы GitHub](https://github.com/NousResearch/hermes-agent/issues)
- Включено: ОС, версия Python, версия Hermes (`hermes --version`), полная отслеживание ошибок.
- Включите шаги для воспроизведения
- Проверьте существующие проблемы, прежде чем создавать дубликаты.
- Об уязвимостях безопасности сообщайте лично.
