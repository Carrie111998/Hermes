# Создание плагина с секретным исходным кодом

Источники секретов преобразуют учетные данные поставщика из внешнего диспетчера секретов (хранилище, менеджер паролей, хранилище ключей ОС, пользовательский сценарий) в переменные среды при запуске процесса — после загрузки `~/.hermes/.env`, до того, как Hermes прочитает учетные данные. Bitwarden, 1Password и универсальный исходный код командного помощника, поставляемый в дереве; **все остальные серверные части являются плагинами**. В этом руководстве рассказывается о его создании.

:::совет
Пакетный набор намеренно закрыт, та же политика, что и у [поставщиков памяти](/developer-guide/memory-provider-plugin): PR, добавляющие новые серверные части хранилища под `agent/secret_sources/`, закрываются с помощью указателя на это руководство. Опубликуйте свой бэкэнд как отдельный репозиторий плагинов и поделитесь им в Nous Research Discord (`#plugins-skills-and-skins`).
:::

## Время начальной загрузки первого процесса

`load_hermes_dotenv()` часто запускается во время импорта **до** регистрации плагинов.
Затем Hermes повторно извлекает секреты после обнаружения плагина, если какой-либо из них **включен**.
Секретный источник плагина настроен. Включение использует источник
`is_enabled(cfg)` контракт; стандартная форма
`secrets.<name>.enabled: true`, при этом пользовательская активация продолжает поддерживаться.
Это закроет пробел в первом процессе «заменить Bitwarden на мое хранилище» (#64177).

- Повторное извлечение является идемпотентным и отказоустойчивым (никогда не блокирует запуск).
— Источники предоставляют переменные окружения только через оркестратор; нет **нет**
  API плагинов для сброса секретного хранилища других плагинов или всего пользователя за пределы
  что позволяет собственная конфигурация вашего источника.
- Чтение `os.environ` после загрузки возможно для любого внутрипроцессного кода —
  Граница доверия остается «включенные плагины запускаются с привилегиями агента».

## То, что принадлежит фреймворку, и то, что принадлежит вам

Оркестратор (`agent.secret_sources.registry.apply_all`) владеет всем, что чувствительно к безопасности и приоритету, поэтому серверная часть не может ошибиться:

| Рамочная владеет | Вы владеете |
|---|---|
| Упорядочение источников, сопоставленный или групповой приоритет | Получение значений из серверной части |
| Обработка конфликтов по принципу «первая претензия выигрывает» + предупреждения | Проверка формата справки |
| `override_existing` семантика (никогда не пересекает источники) | Разговор с вашим CLI/SDK/API |
| Защищенные токены начальной загрузки | Объявление того, какая переменная среды является вашим загрузочным токеном |
| Тайм-аут настенных часов для каждого источника | Поддержание `fetch()` достаточно быстрого |
| Происхождение каждого варианта + `(from X)` этикеток | Удобочитаемый человек `label` |
| `os.environ` пишет | Ничего — вы никогда не прикасаетесь к окружающей среде |

## Азбука секретного источника

Внедрите `agent.secret_sources.base.SecretSource`. Требуется один метод:

```python
from pathlib import Path

from agent.secret_sources.base import (
    ErrorKind,
    FetchResult,
    SecretSource,
    run_secret_cli,
)


class MyVaultSource(SecretSource):
    name = "myvault"          # config section key: secrets.myvault
    label = "My Vault"        # used in startup lines + provenance labels
    shape = "mapped"          # "mapped" (explicit VAR→ref map) or "bulk" (project dump)
    scheme = "mv"             # optional: unique URI scheme you own (mv://...)

    def fetch(self, cfg: dict, home_path: Path) -> FetchResult:
        """Resolve secrets. MUST NOT raise. MUST NOT prompt."""
        result = FetchResult()
        token = os.environ.get("MYVAULT_TOKEN", "").strip()
        if not token:
            result.error = "secrets.myvault.enabled is true but MYVAULT_TOKEN is not set."
            result.error_kind = ErrorKind.NOT_CONFIGURED
            return result

        try:
            proc = run_secret_cli(
                ["myvault-cli", "export", "--json"],
                allow_env=["MYVAULT_TOKEN"],   # ONLY your auth vars — never full os.environ
                timeout=30,
            )
        except RuntimeError as exc:           # spawn failure / timeout
            result.error = str(exc)
            result.error_kind = ErrorKind.BINARY_MISSING
            return result

        if proc.returncode != 0:
            result.error = f"myvault-cli exited {proc.returncode}: {proc.stderr[:200]}"
            result.error_kind = ErrorKind.AUTH_FAILED
            return result

        result.secrets = parse_your_output(proc.stdout)  # {ENV_VAR: value}
        return result

    def protected_env_vars(self, cfg: dict):
        # Your bootstrap token — no source (including yours) may ever overwrite it.
        return frozenset({"MYVAULT_TOKEN"})
```

### Правила контракта (принудительные, а не предложения)

- **`fetch()` никогда не повышает ставку.** Ошибки возникают в `result.error` + `result.error_kind`. Вызов вызова содержится оркестратором и сообщается как `INTERNAL` — нарушение контракта, а не функция.
- **`fetch()` никогда не запрашивает.** Запуск выполняется в контекстах, отличных от TTY (шлюз, cron, Docker). `run_secret_cli()` закрывает стандартный ввод, поэтому помощник по подсказке быстро дает сбой. Интерактивная аутентификация входит в процесс настройки CLI, а не в путь запуска.
- **Синхронизация в рамках бюджета.** Оркестратор устанавливает тайм-аут настенных часов (по умолчанию 120 с, настраивается пользователем через `secrets.<name>.timeout_seconds`). При его превышении сообщается `TIMEOUT`, и ваш результат аннулируется.
- ** Вы приносите; применяется оркестратор.** Верните сопоставление, которое вы *хотели бы* внести. Никогда не пишите `os.environ` самостоятельно — вы обойдете приоритет, обнаружение конфликтов и происхождение.
- **Версии API.** `SecretSource.api_version` по умолчанию использует текущий `SECRET_SOURCE_API_VERSION`. Реестр пропускает (с предупреждением) источники, созданные для другой версии, вместо того, чтобы привести к сбою при запуске.

### Выбор вашего `shape`

- `mapped` — пользователь явно привязывает имена env-var к ссылкам в конфигурации (например, карта `env:` 1Password). Самое сильное намерение: сопоставленные претензии превосходят массовые претензии по оспариваемым вариантам.
- `bulk` — вы неявно внедряете целый проект/папку секретов (например, Bitwarden BSM). Уступает сопоставленным источникам.

### Дополнительные крючки

| Метод | По умолчанию | Переопределить, когда |
|---|---|---|
| `is_enabled(cfg)` | `cfg.get("enabled")` | Пользовательская логика активации |
| `override_existing(cfg)` | `cfg.get("override_existing", False)` | Вам нужно другое значение по умолчанию (по умолчанию в обоих исходных кодах `True` для ротации) |
| `protected_env_vars(cfg)` | пустой | У вас есть токен начальной загрузки (почти наверняка есть) |
| `fetch_timeout_seconds(cfg)` | 120-е | Вашему бэкэнду нужен другой бюджет |
| `config_schema()` | `{}` | Объявить ключи конфигурации для поверхностей настройки |
| `remediation(kind, cfg)` | общие подсказки для каждого-`ErrorKind` | Вы хотите, чтобы предупреждения об ошибках указывали на вашу собственную команду исправления (например, исходные коды в комплекте возвращают `Run hermes secrets <name> token…` для `AUTH_FAILED`). Должно быть чистое отображение → отображение строк: нет ввода-вывода, никогда не повышается. Верните `""`, чтобы подавить подсказку. |

## Безопасность подпроцесса: используйте `run_secret_cli()`

Если ваша серверная часть использует интерфейс командной строки, используйте общий помощник вместо `subprocess.run` напрямую. Он предоставляет вам проверяемую позицию бесплатно: только argv (без `shell=True`), **минимальная дочерняя среда из разрешенного списка** (к моменту запуска источников `os.environ` содержит все учетные данные, известные Hermes — никогда не передавайте их дочернему процессу), `NO_COLOR` + очищенный по ANSI stderr, stdin закрыт, тайм-аут → очистить `RuntimeError`. Передавайте предоставленные пользователем ссылочные строки после терминатора `--` в вашем argv, чтобы они никогда не могли анализироваться как флаги.

## Регистрация

```python
# __init__.py
def register(ctx):
    ctx.register_secret_source(MyVaultSource())
```

Регистрация отклоняется (с предупреждением в журнале, никогда не происходит сбой) для: экземпляров, отличных от `SecretSource`, недопустимых/повторяющихся имен, `scheme`, которым владеет другой источник, неправильного `api_version` или `shape` за пределами `mapped`/`bulk`.

:::примечание
Обнаружение плагина выполняется позже при запуске, чем первый вызов `load_hermes_dotenv()`. Сразу после обнаружения Hermes повторно извлекает включенные секретные источники плагина (`reset_secret_source_cache()` + `load_hermes_dotenv()`), поэтому процесс обнаружения *действительно* подхватывает их — см. [Время начальной загрузки первого процесса](#first-process-bootstrap-timing) выше (#64177). Повторное извлечение происходит при отказе и пропускается, если ни один источник плагина не включен. Любой код, который читает `os.environ` во время импорта модуля плагина или `register(ctx)`, по-прежнему выполняется до повторной загрузки и не может зависеть от учетных данных, предоставленных тем же источником; сохраняйте сертифицированную работу внутри `fetch()`. Процессы шлюза, cron и субагента выполняют одну и ту же последовательность обнаружения/повторного запроса.
:::

## Пользователи настраивают его как любой другой источник

```yaml
secrets:
  sources: [myvault, bitwarden]   # optional ordering
  myvault:
    enabled: true
    # ... your config_schema keys
```

Приоритет нескольких источников, предупреждения о конфликтах и метки происхождения `(from My Vault)` работают автоматически — лестницу приоритетов см. в [документации по секретам для пользователей](/user-guide/secrets/).

## Проверка с помощью комплекта соответствия

Подклассифицируйте комплект из репозитория Hermes (`tests/secret_sources/conformance.py`) в тестах вашего плагина:

```python
import pytest
from tests.secret_sources.conformance import SecretSourceConformance

class TestMyVaultConformance(SecretSourceConformance):
    @pytest.fixture
    def source(self):
        return MyVaultSource()
```

Он проверяет правила, которые нарушают других людей при нарушении: никогда не поднимать ошибки при неправильной конфигурации, машиночитаемые типы ошибок, отключены по умолчанию, положительные таймауты, допустимые имена защищенных переменных и полный обход `apply_all()` туда и обратно. Зеленое соответствие — это полоса проверки для признания серверной части соответствующей контракту.

## Ссылка на тип ошибки

| Вид | Значение |
|---|---|
| `NOT_CONFIGURED` | Включено, но отсутствует токен/проект/карта |
| `BINARY_MISSING` | Помощник CLI не найден или не исполняемый файл |
| `AUTH_FAILED` / `AUTH_EXPIRED` | Плохие/истекшие учетные данные |
| `REF_INVALID` | Секретная ссылка не прошла проверку |
| `NETWORK` | Сбой на транспортном уровне |
| `EMPTY_VALUE` | Серверная часть ничего не вернула для ссылки — никогда не применяйте `""` вместо хороших учетных данных |
| `TIMEOUT` | Fetch превысил свой бюджет |
| `INTERNAL` | Что-нибудь еще (ошибка, неожиданная форма) |
