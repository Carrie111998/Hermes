# Сжатие и кэширование контекста

Агент Hermes использует двойную систему сжатия и кэширование подсказок Anthropic для
эффективно управляйте использованием контекстных окон во время длинных разговоров.

Исходные файлы: `agent/context_engine.py` (ABC), `agent/context_compressor.py` (движок по умолчанию),
`agent/prompt_caching.py`, `gateway/run.py` (гигиена сеанса), `run_agent.py` (поиск `_compress_context`)


## Подключаемый механизм контекста

Управление контекстом построено на основе `ContextEngine` ABC (`agent/context_engine.py`). Встроенный `ContextCompressor` является реализацией по умолчанию, но плагины могут заменить его альтернативными механизмами (например, управлением контекстом без потерь).

```yaml
context:
  engine: "compressor"    # default — built-in lossy summarization
  engine: "lcm"           # example — plugin providing lossless context
```

Двигатель отвечает за:
- Решение о том, когда должно сработать уплотнение (`should_compress()`)
- Выполнение уплотнения (`compress()`)
– При необходимости предоставление инструментов, которые агент может вызвать (например, `lcm_grep`).
- Отслеживание использования токена по ответам API.

Выбор осуществляется конфигурацией через `context.engine` в `config.yaml`. Порядок разрешения:
1. Проверьте каталог `plugins/context_engine/<name>/`.
2. Проверьте общую систему плагинов (`register_context_engine()`).
3. Вернитесь к встроенному `ContextCompressor`.

Механизмы плагинов **никогда не активируются автоматически** — пользователь должен явно указать `context.engine` для имени плагина. По умолчанию `"compressor"` всегда использует встроенный.

Настройте через `hermes plugins` → Плагины поставщика → Context Engine или отредактируйте `config.yaml` напрямую.

Для создания плагина контекстного механизма см. [Плагины контекстного механизма](/developer-guide/context-engine-plugin).

## Система двойного сжатия

Hermes имеет два отдельных слоя сжатия, которые работают независимо:

```
                     ┌──────────────────────────┐
  Incoming message   │   Gateway Session Hygiene │  Fires at 85% of context
  ─────────────────► │   (pre-agent, rough est.) │  Safety net for large sessions
                     └─────────────┬────────────┘
                                   │
                                   ▼
                     ┌──────────────────────────┐
                     │   Agent ContextCompressor │  Fires at 50% of context (default)
                     │   (in-loop, real tokens)  │  Normal context management
                     └──────────────────────────┘
```

### 1. Гигиена сеансов шлюза (порог 85 %)

Расположен в `gateway/run.py` (найдите `Session hygiene: auto-compress`). Это **сеть безопасности**, которая
запускается до того, как агент обработает сообщение. Это предотвращает сбои API при сеансах
становятся слишком большими между ходами (например, накопление за ночь в Telegram/Discord).

- **Порог**: фиксировано на уровне 85 % длины контекста модели.
- **Источник токена**: предпочитает фактические токены, сообщенные API с последнего хода; отступает
  к грубой оценке на основе символов (`estimate_messages_tokens_rough`)
- **Срабатывает**: только если `len(history) >= 4` и сжатие включены.
- **Цель**: перехват сеансов, которые вышли из-под компрессора агента.

Порог гигиены шлюза намеренно выше, чем порог компрессора агента.
Установка его на 50% (так же, как и для агента) приводила к преждевременному сжатию на каждом шагу.
в длительных сеансах шлюза.

### 2. Agent ContextCompressor (порог 50 %, настраивается)

Расположен в `agent/context_compressor.py`. Это **первичное сжатие
система**, которая работает внутри цикла инструментов агента и имеет доступ к точной,
Количество токенов, сообщаемое API.


## Конфигурация

Все настройки сжатия считываются из `config.yaml` по ключу `compression`:

```yaml
compression:
  enabled: true              # Enable/disable compression (default: true)
  threshold: 0.50            # Fraction of context window (default: 0.50 = 50%)
  # model_thresholds:        # Per-model threshold overrides (substring match,
  #   "glm-5.2": 0.40        # longest key wins). See "Per-model threshold
  #   "claude-sonnet": 0.35  # overrides" below.
  target_ratio: 0.20         # How much of threshold to keep as tail (default: 0.20)
  tail_mode: lean            # Tail retention policy: lean | legacy (default: lean)
  protect_last_n: 20         # Minimum protected tail messages (default: 20)
  min_tail_user_messages: 1  # Real user messages guaranteed in the tail (default: 1)
  codex_gpt55_autoraise: true  # gpt-5.5 on Codex OAuth: raise trigger to 85% (default: true)
  codex_gpt55_autoraise_notice: true  # Show the one-time autoraise notice (default: true)
  codex_app_server_auto: native  # native|hermes|off for Codex app-server thread compaction
  codex_responses_native: false  # gpt-5.6 on direct OpenAI/Codex: server-side compaction (opt-in)
  codex_responses_compact_threshold: 200000  # Server-side compaction trigger (input tokens)
  in_place: true             # Compact on the same session id, no rotation (default: true)

# Summarization model/provider configured under auxiliary:
auxiliary:
  compression:
    model: null              # Override model for summaries (default: auto-detect)
    provider: auto           # Provider: "auto", "openrouter", "nous", "main", etc.
    base_url: null           # Custom OpenAI-compatible endpoint
```

### Подробности параметра

| Параметр | По умолчанию | Диапазон | Описание |
|-----------|---------|-------|-------------|
| `threshold` | `0.50` | 0,0-1,0 | Сжатие срабатывает, когда токены подсказки ≥ `threshold × context_length` |
| `model_thresholds` | `{}` | карта | Переопределения `threshold` для каждой модели. Ключи сопоставляются по подстроке с именем модели (выигрывает самое длинное совпадение). Минимальный уровень малого контекста по-прежнему применяется сверху (см. ниже) |
| `target_ratio` | `0.20` | 0,10-0,80 | Управляет бюджетом токена защиты хвоста: `threshold_tokens × target_ratio` (только в устаревшем режиме — `lean` использует собственный зажим) |
| `tail_mode` | `lean` | `lean`, `legacy` | Политика сохранения хвоста. `legacy` сохраняет дословный хвост размером `target_ratio` (~100 тыс.+ токенов на моделях с большим окном). `lean` сохраняет зажатый хвост `2.5% × context window` (минимальное значение 10 КБ, ограничение 25 КБ) и вместо этого обеспечивает непрерывность сводки: фрагментированные дайджесты сжатой области, сохраняющие идентификаторы, механически извлекаемый индекс привязки (номера PR, SHA, пути, строки ошибок — регулярное выражение, никогда не перефразируемое), каждое реальное сообщение пользователя цитируется дословно (самый новый бюджет — первый) и указатель восстановления `session_search`, чтобы агент может повторно получить доступ к чему-либо, обобщенному. Результат для реальных сессий с 500 тысячами токенов: ~49 тысяч сохранено против ~162 тысяч, с более высоким отзывом в сочетании с восстановлением (см. `evals/compaction/results/`). Стоит несколько дополнительных вызовов сумматора на границе уплотнения. Результаты старых инструментов внутри постного хвоста понижаются до однострочных заглушек с указателем восстановления |
| `protect_last_n` | `20` | ≥1 | Всегда сохраняется минимальное количество последних сообщений |
| `min_tail_user_messages` | `1` | ≥1 | Минимальное количество РЕАЛЬНЫХ (действующих) пользовательских сообщений, которые гарантированно сохранятся в несжатом хвосте. `1` = существующая единственная привязка последнего пользователя (по умолчанию сохраняется поведение). Поднимите, например, `3`, чтобы сохранить дословно данные о трех последних реальных обращениях пользователей, даже если громоздкие выходные данные инструмента заполняют бюджет хвостовых токенов. Пустые эхо-сигналы платформы, передачи уплотнения и строки синтетического продолжения никогда не засчитываются в N. Гарантия выигрывает по бюджету хвостового токена — хвост может превысить бюджет, когда якорь тянет сокращение назад |
| `protect_first_n` | `3` | (жестко закодировано) | Системное приглашение + первый обмен всегда сохраняется |
| `idle_compact_after_seconds` | `0` | ≥0 секунд | Согласие: сжимать заранее, когда сеанс возобновляется после этого количества секунд бездействия (0 = отключено). Пропускается, если контекст ≤ порог × target_ratio; с отличием время восстановления/анти-трэш/защита замков |
| `codex_gpt55_autoraise` | `true` | бул | Поднимите триггер до 85 % для gpt-5.5 на маршруте OAuth Кодекса ChatGPT (см. ниже). Установите `false`, чтобы сохранить глобальный `threshold` |
| `codex_gpt55_autoraise_notice` | `true` | бул | Покажите одноразовое уведомление об автоматическом повышении Codex gpt-5.5. Установите `false`, чтобы сохранить автоподнятие на 85%, но отключить баннер |
| `codex_app_server_auto` | `native` | `native`, `hermes`, `off` | Режим сжатия потоков для сеансов сервера приложений Кодекса (см. ниже) |
| `codex_responses_native` | `false` | бул | Подпишитесь на серверное сжатие OpenAI в API ответов. Задействуется только для моделей семейства gpt-5.6 по прямому API OpenAI или по подписке ChatGPT Codex (см. ниже) |
| `codex_responses_compact_threshold` | `200000` | ≥1 жетонов | Триггер сжатия на стороне сервера во входных токенах. Ограничивается ниже локального порога сжатия во время запроса, поэтому сервер сначала сжимает |
| `in_place` | `true` | бул | Сжимать тот же идентификатор сеанса вместо перехода к новому (см. ниже) |

### Сжатие на месте (один стабильный идентификатор сеанса)

При использовании `compression.in_place: true` (по умолчанию) сжатие **перезаписывает список текущих сообщений с тем же идентификатором сеанса**: системное приглашение перестраивается, итоговая середина заменяется, а ходы предварительного уплотнения программно архивируются под тем же идентификатором (`active=0, compacted=1` в хранилище сеансов) - по-прежнему доступны для поиска через `session_search` и могут быть восстановлены, но никогда не удаляются. Нет цепочки `parent_session_id` и перенумерации `name #N`; один разговор сохраняет один надежный идентификатор на всю жизнь. Это устранило кластер ошибок ротации сеансов (потерянное состояние `/goal`, потерянные сеансы, пробелы в поиске через границы).

Потребители наблюдают за режимом, а не различают идентификаторы сеансов:

- Событие `session:compress` содержит `in_place: true/false` и `old_session_id` (пустую строку в режиме на месте, поскольку старого идентификатора нет).
— Шлюз переопределяет базовую обработку транскриптов на основе независимого от ротации флага `_last_compaction_in_place` агента, а не на основе разницы при изменении идентификатора.

Установите `in_place: false`, чтобы восстановить устаревший путь ротации, при котором каждое сжатие фиксирует новый идентификатор сеанса, связанный с предыдущим через `parent_session_id`.

### Переопределение пороговых значений для каждой модели

`compression.model_thresholds` позволяет запускать уплотнение в разных точках.
в зависимости от активной модели — полезно при переключении между моделями с очень
различные контекстные окна (например, 1М-контекстную модель можно сжать позже, а
Модель 128K должна сжиматься раньше):

```yaml
compression:
  threshold: 0.50
  model_thresholds:
    "glm-5.2": 0.40
    "glm-5.2-1M": 0.25
    "claude-sonnet": 0.35
```

Правила разрешения:

- Ключи **совпадают по подстрокам** с названием модели; самый **самый длинный
  выигрыш по соответствующему ключу** (`glm-5.2-1M` превосходит `glm-5.2` для модели `glm-5.2-1M`).
- Если ни один ключ не соответствует (или карта пуста), применяется глобальный `threshold`.
- Переопределение повторно разрешается при каждом переключении `/model`; переход на модель
  без соответствующего ключа возвращается к глобальному `threshold`.
- **Минимальный уровень малого контекста по-прежнему применяется поверх** переопределений (только повышение):
  модели с контекстными окнами ниже 512 КБ имеют минимальный уровень `0.75`, поэтому
  переопределение ниже этажа повышается до `0.75`, а переопределение выше него
  (например, `0.80`) выиграет.

Механизмы контекста плагина могут повторно использовать одну и ту же логику разрешения через
`from agent.context_compressor import resolve_model_threshold`; двигатели, которые
переопределить `update_model()` собственную политику сжатия и может игнорировать
карта.

### Автоподнятие порога Codex gpt-5.5

Серверная часть OAuth Кодекса ChatGPT жестко ограничивает gpt-5.5 в контекстном окне **272 КБ**.
(тот же фрагмент предоставляет 1,05 МБ для прямого API OpenAI и OpenRouter и 400 КБ для
GitHub второй пилот). При триггере по умолчанию 50% сжатие сработает при ~136K —
половина окна, которое модель может фактически использовать. Когда активным маршрутом является Codex
OAuth (`provider: openai-codex`) и модель gpt-5.5, Hermes поднимает
срабатывает до **85%** (~231 КБ) и показывает уведомление с командой отказа.
уведомление отображается один раз для каждого профиля — маркер под `$HERMES_HOME`
(`.codex_gpt55_autoraise_notice`) записывает, что он был запущен, поэтому повторный агент/сеанс
инициализации (например, каждое входящее сообщение шлюза) не отправляют его повторно; если подняли
порог позже изменится, он повторно уведомит один раз. Затрагивается только этот точный маршрут;
gpt-5.5 у любого другого провайдера сохраняет ваш глобальный `threshold`. Чтобы отказаться от
глобальное значение:

```bash
hermes config set compression.codex_gpt55_autoraise false
```

Чтобы сохранить автоподнятие 85%, но скрыть только однократное уведомление:

```bash
hermes config set compression.codex_gpt55_autoraise_notice false
```

### Варианты крупноконтекстного средства выбора Codex `-900k` (по желанию)

Серверная часть Кодекса ChatGPT *рекламирует* окно размером 272 КБ для gpt-5.4 и
gpt-5.6 (Сол/Терра/Луна), но фактически принимает ~911 тыс. входных токенов.
для учетных записей с подпиской ChatGPT (проверено в реальном времени, август 2026 г.). Гермес держит
**объявлено 272 КБ по умолчанию** для базовых заготовок — большее окно означает
больше токенов за запрос и гораздо более быстрое расходование подписки, поэтому
окно строго по согласию.

Чтобы использовать большое окно, выберите явный вариант `-900k` в `/model` (например,
`gpt-5.6-sol-900k`, `gpt-5.6-terra-900k`, `gpt-5.6-luna-900k`,
`gpt-5.4-900k`). Это псевдонимы со стороны Hermes: суффикс перед этим удаляется.
идентификатор модели отправляется на серверную часть, и их обрабатывает учет цен/использования.
в качестве базовой модели. Слизни, действительно обеспечивающие 272 КБ (gpt-5.5, gpt-5.4-mini)
не имеют варианта `-900k`.

Пороги уплотнения следуют за окном: базовые пули (272K) получают **85 %.
autoraise**, описанный выше, а варианты `-900k` сохраняют глобальный
`compression.threshold` (по умолчанию 50%, ~450К) — автоподнятие существует для остановки
трата небольшого окна, которое не нужно окну 900K.

### Сжатие потоков сервера приложений Codex

Сеансы сервера приложений Кодекса (`api_mode: codex_app_server` — интерфейс командной строки/агент Кодекса)
во время выполнения) отличаются от любого другого маршрута: агент кодекса владеет поддержкой
контекст потока, поэтому вспомогательный сумматор Гермеса не может его сжать — переписав
локальное зеркало стенограммы оставляет реальный поток неограниченным до тех пор, пока не будет жестко
сброс контекста. В этой среде выполнения сжатие осуществляется через собственный сервер приложений.
вместо этого механизм:

- Ручное сжатие (`/compress`) просит сервер приложений сжать поток.
  (`thread/compact/start`) и ожидает завершения очереди уплотнения.
- Автоматическое уплотнение контролируется `compression.codex_app_server_auto`:
  значение по умолчанию `native` позволяет серверу приложений решать, когда сжимать, а Hermes
  записывает результирующие события уплотнения (счетчики сжатия, сеансовые
  события). Установите `hermes`, чтобы разрешить срабатывание порога сжатия Hermes.
  сжатие сервера приложений или `off` для отключения автоматического запуска Hermes
  полное сжатие (кодекс все еще может сжимать изначально).

Локальная расшифровка Hermes никогда не перезаписывается в этой среде выполнения — записи state.db
граница уплотнения, в то время как видимый транскрипт остается нетронутым. Все остальные
маршруты (включая сеансы чата Codex OAuth) сохраняют компрессор сводных данных Hermes.

### Сжатие собственных ответов (gpt-5.6 при прямой подписке OpenAI/Codex)

API ответов OpenAI поддерживает сжатие на стороне сервера: когда запрос включает
`context_management: [{type: "compaction", compact_threshold: N}]` и
обработанный ввод пересекает N токенов, сервер сокращает старый контекст до непрозрачного
зашифрованный выходной элемент `compaction`. Гермес захватывает этот предмет в
существующее сообщение повтора сообщения помощника и отправляет его обратно при последующем
повороты, заменяющие обрезанную историю - воспоминания о дальних горизонтах без
сводный проход на стороне клиента и поддержка ZDR (`store: false`, нет
`previous_response_id`).

Подпишитесь с помощью `compression.codex_responses_native: true`. Ворота намеренно
узкий, перепроверяется при каждом запросе:

- **Модели:** только семейство gpt-5.6. Другие модели выходят из строя на стороне сервера, когда
  поле присутствует (gpt-5.1/5.2 возвращает HTTP 500 или останавливает поток — есть
  нет структурированного отказа в понижении версии, проверено в реальном времени в августе 2026 г.).
- **Маршруты**: `api.openai.com` (ключ API OpenAI) или серверная часть Кодекса ChatGPT.
  Только (подписка Кодекса OAuth). xAI, GitHub/Copilot, OpenRouter, реле и
  локальные серверы никогда не видят это поле.

Все остальное, касающееся сжатия, не изменилось: локальный компрессор остается
вооружен как резервный владелец (родной порог зажат ~8К токенов ниже
локальный триггер, чтобы сервер сначала сжимался), и структурированный поставщик
отклонение поля отключает собственное сжатие для сеанса и повторяет попытки
запрос без него. Переключение сеанса на неподходящую модель или маршрут
просто останавливает отправку поля — захваченные чекпоинты сбрасываются из
воспроизведение существующим межэмитентным средством защиты при изменении конечной точки.

### Вычисленные значения (для контекстной модели 200 000 по умолчанию)

```
context_length       = 200,000
threshold_tokens     = 200,000 × 0.50 = 100,000
tail_token_budget    = 100,000 × 0.20 = 20,000
max_summary_tokens   = min(200,000 × 0.05, 12,000) = 10,000
```

:::note Пороговое значение извлекается из контекстного окна модели MAIN.
`threshold_tokens` всегда равно `threshold × context_length`, где `context_length`
это контекстное окно **основной модели агента**, а не вспомогательное/сводное окно.
модели. В модели с 262 144 токенами по умолчанию `0.50` порог равен
`262,144 × 0.50 = 131,072`. Это число близко к обычному «контексту 128 КБ».
является совпадением процентов, а не признаком того, что окно вспомогательной модели
является триггером. Контекстное окно вспомогательной модели представляет собой отдельную проблему — см.
предупреждение «Длина контекста сводной модели» ниже о том, как оно влияет на
сводка может быть создана, а не при срабатывании сжатия.
:::


## Алгоритм сжатия

Метод `ContextCompressor.compress()` следует четырехэтапному алгоритму:

### Этап 1: обрезка результатов использования старых инструментов (дешево, без необходимости обращения в LLM)

Результаты старых инструментов (>200 символов) за пределами защищенного хвоста заменяются на:
```
[Old tool output cleared to save context space]
```

Это дешевый предварительный проход, который экономит значительные токены от многословного инструмента.
выходные данные (содержимое файла, вывод терминала, результаты поиска).

### Этап 2: определение границ

```
┌─────────────────────────────────────────────────────────────┐
│  Message list                                               │
│                                                             │
│  [0..2]  ← protect_first_n (system + first exchange)        │
│  [3..N]  ← middle turns → SUMMARIZED                        │
│  [N..end] ← tail (by token budget OR protect_last_n)        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Защита хвоста **основана на бюджете токенов**: идет назад от конца,
накопление токенов до исчерпания бюджета. Возвращается к фиксированному
`protect_last_n` учитывайте, если бюджет позволит защитить меньшее количество сообщений.

Границы выровнены, чтобы избежать разделения группtool_call/tool_result.
Метод `_align_boundary_backward()` проходит мимо последовательных результатов инструмента.
чтобы найти сообщение помощника для родителей, сохраняя группы нетронутыми.

### Этап 3: Создание структурированного резюме

:::warning Длина контекста сводной модели
Сводная модель должна иметь контекстное окно **по крайней мере такого же размера**, как и у основной модели агента. Вся средняя часть отправляется в сводную модель одним вызовом `call_llm(task="compression")`. Если контекст сводной модели меньше, API возвращает ошибку длины контекста — `_generate_summary()` улавливает ее, регистрирует предупреждение и возвращает `None`. Затем компрессор пропускает средние отрезки **без резюме**, молча теряя контекст разговора. Это наиболее распространенная причина ухудшения качества уплотнения.
:::

Средние витки суммируются с помощью вспомогательной ЛЛМ со структурированной
шаблон:

```
## Goal
[What the user is trying to accomplish]

## Constraints & Preferences
[User preferences, coding style, constraints, important decisions]

## Progress
### Done
[Completed work — specific file paths, commands run, results]
### In Progress
[Work currently underway]
### Blocked
[Any blockers or issues encountered]

## Key Decisions
[Important technical decisions and why]

## Relevant Files
[Files read, modified, or created — with brief note on each]

## Next Steps
[What needs to happen next]

## Critical Context
[Specific values, error messages, configuration details]
```

Суммарный бюджет зависит от объема сжимаемого контента:
- Формула: `content_tokens × 0.20` (константа `_SUMMARY_RATIO`)
- Минимум: 2000 токенов
- Максимум: `min(context_length × 0.05, 12,000)` токенов

### Этап 4. Сборка сжатых сообщений

Список сжатых сообщений:
1. Заголовочные сообщения (с примечанием, добавленным к системному приглашению при первом сжатии)
2. Сводное сообщение (роль выбрана во избежание последовательных нарушений одной и той же роли)
3. Хвостовые сообщения (без изменений)

Потерянные парыtool_call/tool_result очищаются с помощью `_sanitize_tool_pairs()`:
- Результаты инструмента ссылаются на удаленные вызовы → удалены.
- Вызовы инструментов, результаты которых были удалены → добавлен результат-заглушка

### Итеративное повторное сжатие

При последующих сжатиях предыдущая сводка передается в LLM с
инструкции **обновить** его, а не суммировать с нуля. Это сохраняет
информация по нескольким сжатиям — элементы перемещаются из состояния «В процессе» в состояние «Готово»,
добавляется новый прогресс и удаляется устаревшая информация.

Поле `_previous_summary` экземпляра компрессора хранит последнюю сводку.
текст для этой цели.

## Быстрое кэширование (антропное)

Источник: `agent/prompt_caching.py`

Снижает стоимость входных токенов примерно на 75% при многоходовых диалогах за счет кэширования
префикс разговора. Использует точки останова `cache_control` Anthropic.

### Стратегия: system_and_3

Anthropic допускает максимум 4 точки останова `cache_control` на запрос. Гермес
использует стратегию «system_and_3»:

```
Breakpoint 1: System prompt           (stable across all turns)
Breakpoint 2: 3rd-to-last non-system message  ─┐
Breakpoint 3: 2nd-to-last non-system message   ├─ Rolling window
Breakpoint 4: Last non-system message          ─┘
```

### Как это работает

`apply_anthropic_cache_control()` глубоко копирует сообщения и внедряет
`cache_control` маркеров:

```python
# Cache marker format
marker = {"type": "ephemeral"}
# Or for 1-hour TTL:
marker = {"type": "ephemeral", "ttl": "1h"}
```

Маркер применяется по-разному в зависимости от типа контента:

| Тип контента | Куда идет маркер |
|-------------|-------------------|
| Строковое содержимое | Преобразовано в `[{"type": "text", "text": ..., "cache_control": ...}]` |
| Содержимое списка | Добавлено в dict последнего элемента |
| Нет/пусто | Добавлен как `msg["cache_control"]` |
| Сообщения инструмента | Добавлен как `msg["cache_control"]` (только родной Anthropic) |

### Шаблоны проектирования с учетом кэша

1. **Стабильная системная подсказка**: системная подсказка имеет точку останова 1 и кэшируется
   все крутится. Не изменяйте его в середине разговора (сжатие добавляет примечание
   только при первом уплотнении).

2. **Порядок сообщений имеет значение**: попадания в кэш требуют сопоставления префиксов. Добавление или
   удаление сообщений в середине делает недействительным кеш для всего последующего.

3. **Взаимодействие с кэшем сжатия**: после сжатия кэш становится недействительным.
   для сжатой области, но кэш системных подсказок сохраняется. прокатка
   Окно из 3 сообщений восстанавливает кэширование в течение 1-2 ходов.

4. **Выбор TTL**: значение по умолчанию — `5m` (5 минут). Используйте `1h` для длительного выполнения
   сеансы, в которых пользователь делает перерывы между ходами.

5. **Идентификатор модели является частью ключа кэша**: кэши на стороне поставщика ограничены.
   к модели (и ключу учетной записи/API), обслуживающей запрос. Любой разговор в середине разговора
   изменение модели — явный переключатель `/model`, откат к основной модели или
   ротация пула учетных данных на другую учетную запись — означает следующий запрос
   получает ноль попаданий в кэш и перечитывает весь разговор без скидки
   входная цена. Это присуще тому, как работают кэши провайдеров, а не чему-то другому.
   Гермес может избежать; документация для пользователей по `/model`, резервным поставщикам и
   По этой причине пулы учетных данных содержат предупреждения о стоимости. Не добавляйте функции
   которые молча меняют модель или учетные данные в середине сеанса.

### Включение кэширования подсказок

Кэширование запросов автоматически включается, когда:
- Модель представляет собой модель Anthropic Claude (определяется по названию модели).
- Поставщик поддерживает `cache_control` (собственный Anthropic API или OpenRouter).

```yaml
# config.yaml — TTL is configurable (must be "5m" or "1h")
prompt_caching:
  cache_ttl: "5m"
```

CLI показывает статус кэширования при запуске:
```
💾 Prompt caching: ENABLED (Claude via OpenRouter, 5m TTL)
```


## Предупреждения о давлении контекста

Предупреждения о промежуточной нагрузке на контекст были удалены (см. блок итерационного бюджета в `run_agent.py`, в котором отмечается: «Нет предупреждений о промежуточной нагрузке — они заставляли модели преждевременно «отказываться» от сложных задач»). Сжатие срабатывает, когда токены подсказки достигают настроенного `compression.threshold` (по умолчанию 50%) без предварительного предупреждения; Гигиена сеанса шлюза действует как вторичная система безопасности в 85% контекстного окна модели.
