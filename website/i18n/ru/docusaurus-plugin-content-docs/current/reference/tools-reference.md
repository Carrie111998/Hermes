# Справочник по встроенным инструментам

На этой странице описаны встроенные инструменты Hermes, сгруппированные по наборам инструментов. Доступность зависит от платформы, учетных данных и включенных наборов инструментов.

**Быстрый подсчет (текущий реестр):** ~86 инструментов — 10 инструментов браузера (основные) + 2 инструмента браузера с поддержкой CDP, 4 файловых инструмента, 4 инструмента Home Assistant, 2 инструмента терминала (`terminal`, `process`), 11 инструментов настольного графического интерфейса (`read_terminal`, `close_terminal`, `open_preview`, `close_preview`, `read_preview`, `drive_preview`, `annotate_preview`, `read_window_below`, `focus_pane`, `react_to_message`, `tour` — только сеансы настольных приложений), 2 веб-инструмента, 5 инструментов Feishu, 7 инструментов Spotify (регистрируются встроенным плагином `spotify`), 5 инструментов Yuanbao, 12 инструментов канбана (регистрируются, когда диспетчер канбана создает агента), 3 инструмента проекта (сеансы рабочего стола/графического интерфейса), 2 инструмента Discord, 3 инструмента для работы с видео (`video_generate`, `xai_video_edit`, `xai_video_extend`) и несколько автономных инструментов (`memory`, `clarify`, `delegate_task`, `execute_code`, `cronjob`, `session_search`, `skill_view`/`skill_manage`/`skills_list`, `text_to_speech`, `image_generate`, `vision_analyze`, `video_analyze`, `todo`, `computer_use`, `x_search`).

:::совет Инструменты MCP
Помимо встроенных инструментов, Hermes может динамически загружать инструменты с серверов MCP. Инструменты MCP имеют префикс `mcp__<server>__` (например, `mcp__github__create_issue` для сервера `github` MCP). См. [Интеграция MCP](/user-guide/features/mcp) для настройки.
:::

## `clarify` набор инструментов

| Инструмент | Описание | Требуется среда |
|------|-------------|----------------------|
| `clarify` | Прежде чем продолжить, задайте пользователю вопрос, если вам нужны разъяснения, отзывы или решение. Поддерживает три режима: 1. **Множественный выбор с одним выбором** — до 4 вариантов; пользователь выбирает один или вводит свой собственный ответ, используя пятый вариант «Другое». 2. **Множественный выбор с множественным выбором** — `multi_select=true` отображает флажки и возвращает список выбранных вариантов. 3. **Открытый** — без выбора; пользователь вводит ответ в свободной форме. Варианты упорядочены в порядке приоритета, поэтому первый из них помечен `(Recommended)` на каждой поверхности и является выделенным по умолчанию; метка предназначена только для представления и удаляется из ответа, который читает агент. В классическом интерфейсе командной строки при множественном выборе используются флажки «Пробел для переключения»; на платформах обмена сообщениями без встроенного пользовательского интерфейса флажков пользователь отвечает цифрами, разделенными запятыми или пробелами (например, «1, 3») или текстом опции. | — |

### Задавать несколько вопросов одновременно

Инструмент `clarify` также принимает массив `questions` (2–5 независимых вопросов, каждый со своими собственными `choices` и `multi_select`), поэтому агент может объединить несколько запросов с разъяснениями в один запрос вместо того, чтобы задавать их последовательно. Результатом является массив `responses` в том же порядке, в который возвращается `id` каждого вопроса (если он указан).

Поведение на поверхности:

- **На рабочем столе** каждый вопрос отображается на одной карточке. Выбор и ввод ответов выполняются локально, а одна кнопка **Подтвердить и продолжить** (активируется, когда на каждый вопрос есть ответ) отправляет весь пакет. Постановочные ответы остаются доступными для редактирования до тех пор, пока это не будет подтверждено. Пропустить отменяет весь пакет.
- **TUI и CLI** отображают компактный список статусов (ответ на `✓` / активный `▸` / `·` в ожидании), в котором расширены только варианты выбора активного вопроса. Enter блокирует активный ответ и переходит к следующему вопросу без ответа; Tab перемещается между вопросами для ответа в любом порядке; Esc отменяет пакет.
- **Платформы обмена сообщениями** (Telegram, Discord и т. д.) возвращаются к тому, чтобы задавать вопросы по одному с помощью существующей подсказки, состоящей из одного вопроса. Если пользователь перестает отвечать, остальные вопросы не отправляются.

Если время ожидания запроса истекает на полпути, ответы, уже заблокированные пользователем, сохраняются: результат инструмента включает их плюс `"timed_out": true`, а записи без ответа остаются пустыми, чтобы агент мог отличить намеренный пропуск от отсутствующего пользователя.

## `kanban` набор инструментов

Регистрируется, когда агент либо (а) создается диспетчером канбана (набор окружения `HERMES_KANBAN_TASK`), либо (б) работает в профиле, который явно включает набор инструментов `kanban`. Работники, ограниченные задачами, используют инструменты жизненного цикла для выполнения назначенных им задач; Профили оркестратора дополнительно получают инструменты маршрутизации плат, такие как `kanban_list` и `kanban_unblock`. Полный рабочий процесс см. в разделе [Kanban Multi-Agent](/user-guide/features/kanban).

| Инструмент | Описание | Требуется среда |
|------|-------------|----------------------|
| `kanban_show` | Показать активную задачу канбана, назначенную этому работнику (название, описание, комментарии, зависимости). | набор инструментов `HERMES_KANBAN_TASK` или `kanban` |
| `kanban_list` | Список задач доски с фильтрами. Только для оркестратора; скрыто от рабочих задач, созданных диспетчером. | профиль с набором инструментов `kanban` |

### Туры

Инструмент `tour` обнаруживает свои собственные цели — вызывает `action='targets'` и возвращает каждый адресуемый элемент на экране с селектором, меткой и флагом `stable`. Стабильные селекторы отключают идентичность (`data-tour`, `id`, `data-testid`, `aria-label`) и выдерживают повторный рендеринг; позиционные пути `nth-child` этого не делают, поэтому стабильные пути сортируются в первую очередь, и им следует отдавать предпочтение.

Чтобы придать элементу собственный надежный дескриптор, разметьте его:

```html
<div data-tour="composer">…</div>
```

Дескрипторы применяются к **примитиву**, а не к месту вызова, поэтому нужно редактировать имя каждого экземпляра. Те, что уже существуют:

| Ручка | Что он называет |
|---|---|
| `overlay-nav` | левая навигация любого наложения маршрутов (настройки, cron, профили, агенты) |
| `nav-<id>` | одна строка в этой навигации — `nav-models`, `nav-appearance`, … |
| `field-<schemaKey>` | одна строка настроек по ее ключу конфигурации — `field-model`, `field-provider`, … |
| `page-tabs` | вкладки фильтров на любой странице `PageSearchShell` (артефакты, навыки, …) |
| `artifact-card` | карта артефакта в сетке |

При добавлении поверхности помечайте ее общий примитив таким же образом, а не помечайте экраны один за другим — это сохраняет небольшой словарный запас тура и предотвращает гниение селекторов.

Тот же движок поддерживает курируемые (неагентские) туры в настольном приложении, поэтому функция может предоставлять собственное пошаговое руководство:

```ts
import { startTour, showTourStep, stopTour } from '@/lib/tour'

startTour([
  { selector: '[data-tour="composer"]', title: 'Composer', text: 'Type here.' },
  { selector: '[data-tour="files"]', title: 'Files', text: 'Browse your project.' }
])
```

Шаг также может переместить приложение туда, где находится его цель, а тур возвращает все обратно, когда заканчивается:

```ts
startTour([
  { navigate: '/artifacts', selector: '[data-tour="page-tabs"]', title: 'Filters', text: '…' },
  { pane: 'sessions', selector: '[data-slot="sidebar"]', title: 'Sessions', text: '…' }
])
```

`navigate` принимает путь маршрута, а `pane` — имя панели рабочего стола. Оба запускаются при входе в шаг, ожидаются цели, которые монтируются поздно, и закрытие тура — любым маршрутом, включая Esc — возвращается туда, где он начался.

Передайте `'preview'` в качестве второго аргумента для запуска на странице в области предварительного просмотра вместо приложения.
