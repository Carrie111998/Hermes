# Справочник команд CLI

На этой странице описаны **команды терминала**, которые вы запускаете из своей оболочки.

Слэш-команды в чате см. в [Справочнике косых команд](./slash-commands.md).

## Глобальная точка входа

```bash
hermes [global-options] <command> [subcommand/options]
```

### Глобальные параметры

| Вариант | Описание |
|--------|-------------|
| `--version`, `-V` | Показать версию и выйти. |
| `--profile <name>`, `-p <name>` | Выберите, какой профиль Hermes использовать для этого вызова. Переопределяет фиксированное значение по умолчанию, установленное `hermes profile use`. |
| `--resume <session>`, `-r <session>` | Возобновите предыдущий сеанс по идентификатору или названию. Ключевое слово `latest` возобновляет самый последний сеанс (на уровне рабочей области, тот же поиск, что и `-c`). |
| `--continue [name]`, `-c [name]` | Возобновите самый последний сеанс или самый последний сеанс, соответствующий заголовку. |
| `--in <dir>` | Перед запуском или возобновлением измените номер на `<dir>`. Охватывает `--resume latest`/`-c` поиск в рабочей области этого каталога и сохраняет там сеанс (пропускает восстановление записанного-cwd). |
| `--worktree`, `-w` | Начните с изолированного рабочего дерева git для рабочих процессов параллельного агента. |
| `--yolo` | Обход запросов на одобрение опасных команд. |
| `--pass-session-id` | Включите идентификатор сеанса в системную подсказку агента. |
| `--ignore-user-config` | Игнорируйте `~/.hermes/config.yaml` и вернитесь к встроенным настройкам по умолчанию. Учетные данные в `.env` все еще загружены. |
| `--ignore-rules` | Пропустить автоматическое внедрение `AGENTS.md`, `SOUL.md`, `.cursorrules`, памяти и предварительно загруженных навыков. |
| `--tui` | Запустите [TUI](../user-guide/tui.md) вместо классического интерфейса командной строки. Эквивалент `HERMES_TUI=1`. Всегда побеждает `display.interface`. |
| `--cli` | Примените классический REPL Prompt_toolkit. Используйте это, чтобы переопределить `display.interface: tui` для одного вызова. |
| `--dev` | С помощью `--tui`: запустите исходные коды TypeScript напрямую через `tsx` вместо готового пакета (для участников TUI). |

## `hermes chat`

```bash
hermes chat [options]
```

Распространенные варианты:

| Вариант | Описание |
|--------|-------------|
| `-q`, `--query "..."` | Однократная неинтерактивная подсказка. |
| `--query-file PATH` | Считайте одноразовое приглашение из файла (`-` = stdin). Ничто не интерпретируется оболочкой, поэтому кавычки, `$(...)` и обратные кавычки поступают дословно — используйте это для программных или ненадежных тел сообщений (его используют DM товарищей по команде в режиме бота). Взаимоисключающе с `-q`. |
| `-m`, `--model <model>` | Переопределите модель для этого прогона. |
| `-t`, `--toolsets <csv>` | Включите набор наборов инструментов, разделенных запятыми. |
| `--provider <provider>` | Принудительно использовать провайдера: `auto`, `openrouter`, `nous`, `openai-codex`, `copilot-acp`, `copilot`, `anthropic`, `gemini`, `huggingface`, `novita` (псевдонимы `novita-ai`, `novitaai`), `openai-api`, `zai`, `kimi-coding`, `kimi-coding-cn`, `minimax`, `minimax-cn`, `minimax-oauth`, `kilocode`, `xiaomi`, `arcee`, `gmi`, `upstage` (псевдоним `solar`), `alibaba`, `alibaba-coding-plan` (псевдоним `alibaba_coding`), `deepseek`, `nvidia`, `ollama-cloud`, `xai` (псевдоним `grok`), `xai-oauth` (псевдоним `grok-oauth`), `qwen-oauth`, `bedrock`, `opencode-zen`, `opencode-go`, `opencode-free` (псевдонимы `free`, `opencode_free`; без ключа), `commandcode`, `commandcode-anthropic`, `ai-gateway`, `azure-foundry`, `lmstudio`, `stepfun`, `tencent-tokenhub` (псевдоним `tencent`, `tokenhub`). |
| `-s`, `--skills <name>` | Предварительно загрузите один или несколько навыков для сеанса (можно повторять или разделять запятыми). |
| `-v`, `--verbose` | Подробный вывод. |
| `-Q`, `--quiet` | Программный режим: запретить предварительный просмотр баннера/спиннера/инструмента. |
| `--image <path>` | Прикрепите локальное изображение к одному запросу. |
| `--resume <session>` / `--continue [name]` | Возобновите сеанс прямо с `chat`. |
| `--worktree` | Создайте изолированное рабочее дерево git для этого запуска. |
| `--checkpoints` | Включите контрольные точки файловой системы перед деструктивными изменениями файлов. |
| `--yolo` | Пропустить запросы на одобрение. |
| `--pass-session-id` | Передайте идентификатор сеанса в системную подсказку. |
| `--ignore-user-config` | Игнорируйте `~/.hermes/config.yaml` и используйте встроенные значения по умолчанию. Учетные данные в `.env` все еще загружены. Полезно для изолированных запусков CI, воспроизводимых отчетов об ошибках и сторонних интеграций. |
| `--ignore-rules` | Пропустите автоматическое внедрение `AGENTS.md`, `SOUL.md`, `.cursorrules`, постоянной памяти и предварительно загруженных навыков. Объедините его с `--ignore-user-config` для полностью изолированного запуска. |
| `--safe-mode` | Режим устранения неполадок: отключите ВСЕ настройки — пользовательскую конфигурацию, правила/внедрение памяти, плагины, перехватчики оболочки и серверы MCP (подразумеваются `--ignore-user-config` и `--ignore-rules`). Используйте, чтобы определить, связана ли проблема с вашей настройкой или с самим Гермесом. |
| `--source <tag>` | Тег источника сеанса для фильтрации (по умолчанию: `cli`). Используйте `tool` для сторонних интеграций, которые не должны отображаться в списках сеансов пользователей. |
| `--max-turns <N>` | Максимальное количество итераций вызова инструмента за ход разговора (по умолчанию: 500 или `agent.max_turns` в конфигурации). |

Примеры:

```bash
hermes
hermes chat -q "Summarize the latest PRs"
hermes chat --provider openrouter --model anthropic/claude-sonnet-4.6
hermes chat --toolsets web,terminal,skills
hermes chat --quiet -q "Return only JSON"
hermes chat --worktree -q "Review this repo and open a PR"
hermes chat --ignore-user-config --ignore-rules -q "Repro without my personal setup"
hermes chat --safe-mode -q "Is this bug mine or Hermes'?"
```

### `hermes -z <prompt>` — скриптовый одноразовый

Для программных вызывающих программ (сценарии оболочки, CI, cron, родительские процессы, передающие приглашение по конвейеру), `hermes -z` является самой чистой одноразовой точкой входа: **одно приглашение, окончательный текст ответа, больше ничего на стандартный вывод или стандартный поток ошибок.** Никакого баннера, никакого счетчика, никаких предварительных просмотров инструментов, никакой строки `Session:` — только окончательный ответ агента в виде обычного текста.

```bash
hermes -z "What's the capital of France?"
# → Paris.

# Parent scripts can cleanly capture the response:
answer=$(hermes -z "summarize this" < /path/to/file.txt)
```

Переопределения для каждого запуска (без мутации в `~/.hermes/config.yaml`):

| Флаг | Эквивалентная переменная окружения | Цель |
|---|---|---|
| `-m` / `--model <model>` | `HERMES_INFERENCE_MODEL` | Переопределить модель для этого прогона |
| `--provider <provider>` | _(нет)_ | Переопределить поставщика для этого запуска |
| `--usage-file <path>` | _(нет)_ | Напишите отчет об использовании JSON после запуска (см. ниже) |

```bash
hermes -z "…" --provider openrouter --model openai/gpt-5.5
# or:
HERMES_INFERENCE_MODEL=anthropic/claude-sonnet-4.6 hermes -z "…"
```

Тот же агент, те же инструменты, те же навыки — просто удаляются все интерактивные/косметические слои. Если вам также нужны выходные данные инструмента в расшифровке, используйте вместо этого `hermes chat -q`; `-z` явно означает «Мне нужен только окончательный ответ».

#### `--usage-file` — Отчет об использовании JSON для конвейеров

`hermes -z "…" --usage-file /path/report.json` записывает машиночитаемый отчет об использовании после запуска: `estimated_cost_usd`, `input_tokens` / `output_tokens` / `cache_read_tokens` / `cache_write_tokens` / `reasoning_tokens` / `total_tokens`, `api_calls`, `model`, `provider`, Флаги `session_id`, `service_tier` и `completed`/`failed`. Отчет составляется **даже в случае сбоя**, поэтому пакетные конвейеры всегда могут учитывать расходы. Это не имеет никакого эффекта за пределами `-z`/`--oneshot`, а запись о нарушении использования никогда не маскирует собственный результат выполнения.

```bash
hermes -z "summarize this repo" --usage-file /tmp/usage.json
jq .estimated_cost_usd /tmp/usage.json
```

## `hermes model`

Интерактивный провайдер + селектор модели. **Это команда для добавления новых поставщиков, настройки ключей API и запуска потоков OAuth.** Запускайте ее со своего терминала, а не из активного сеанса чата Hermes.

```bash
hermes model
```

Используйте это, если хотите:
- **добавить нового провайдера** (OpenRouter, Anthropic, Copilot, DeepSeek, custom и т. д.)
- войдите в провайдеры, поддерживающие OAuth (Anthropic, Copilot, Codex, Nous Portal)
- введите или обновите ключи API
- выбор из списков моделей конкретного поставщика
- настроить пользовательскую/автономную конечную точку
- сохранить новое значение по умолчанию в конфиге

:::предупреждение Модель Гермеса и /модель — почувствуйте разницу
**`hermes model`** (запускается с вашего терминала вне любого сеанса Hermes) — это **мастер полной настройки провайдера**. Он может добавлять новых поставщиков, запускать потоки OAuth, запрашивать ключи API и настраивать конечные точки.

**`/model`** (введенный в активном сеансе чата Hermes) может только **переключаться между поставщиками и моделями, которые вы уже настроили**. Он не может добавлять новых поставщиков, запускать OAuth или запрашивать ключи API.

**Если вам нужно добавить нового провайдера:** сначала выйдите из сеанса Hermes (`Ctrl+C` или `/quit`), а затем запустите `hermes model` из командной строки терминала.
:::

### `/model` косая черта (в середине сеанса)

Переключайтесь между уже настроенными моделями, не выходя из сеанса:

```
/model                              # Show current model and available options
/model claude-sonnet-4              # Switch model (auto-detects provider)
/model zai:glm-5                    # Switch provider and model
/model custom:qwen-2.5              # Use model on your custom endpoint
/model custom                       # Auto-detect model from custom endpoint
/model custom:local:qwen-2.5        # Use a named custom provider
/model openrouter:anthropic/claude-sonnet-4  # Switch back to cloud
```

По умолчанию изменения `/model` применяются **только к текущему сеансу**. Добавьте `--global`, чтобы сохранить изменения в `config.yaml` (или установите `model.persist_switch_by_default: true`, чтобы сохранить каждое изменение):

```
/model claude-sonnet-4 --global     # Switch and save as new default
```

:::info Что делать, если я вижу только модели OpenRouter?
Если вы настроили только OpenRouter, `/model` будет отображать только модели OpenRouter. Чтобы добавить другого провайдера (Anthropic, DeepSeek, Copilot и т. д.), выйдите из сеанса и запустите `hermes model` с терминала.
:::

При переключателе `--global` изменения поставщика и базового URL-адреса сохраняются в `config.yaml` вместе с моделью. При переключении с пользовательской конечной точки устаревший базовый URL-адрес очищается, чтобы предотвратить его утечку к другим поставщикам.

## `hermes send`

```bash
hermes send --to <target> "message text"
hermes send --to <target> --file <path>
echo "message" | hermes send --to <target>
hermes send --list [platform]
```

Отправьте одноразовое сообщение на настроенную платформу обмена сообщениями, не запуская цикл агента или шлюза. Повторно использует уже настроенные учетные данные шлюза (`~/.hermes/.env` + `~/.hermes/config.yaml`), поэтому сценарии эксплуатации, задания cron, перехватчики CI и демоны мониторинга могут публиковать обновления статуса без повторной реализации клиента REST каждой платформы.

Для платформ с токенами ботов (Telegram, Discord, Slack, Signal, SMS, WhatsApp-CloudAPI) работающий шлюз не требуется — `hermes send` обращается напрямую к конечной точке REST платформы. Платформам подключаемых модулей, которым требуется постоянный адаптер, по-прежнему требуется работающий шлюз.

| Вариант | Описание |
|--------|-------------|
| `-t`, `--to <TARGET>` | Цель доставки. Форматы: `platform` (используется домашний канал), `platform:chat_id`, `platform:chat_id:thread_id` или `platform:#channel-name`. Примеры: `telegram`, `telegram:-1001234567890`, `discord:#ops`, `slack:C0123ABCD`, `signal:+15551234567`. |
| `-f`, `--file <PATH>` | Прочитайте тело сообщения от `PATH` (только текстовые файлы — логи, отчеты, уценка). Передайте `-` для принудительного чтения со стандартного ввода. Чтобы отправить изображение или другой двоичный файл, используйте `MEDIA:<path>` (см. ниже). |
| `-s`, `--subject <LINE>` | Добавьте строку темы/заголовка перед телом сообщения. |
| `-l`, `--list [platform]` | Перечислите настроенные цели на всех платформах (или только на данной платформе). |
| `-q`, `--quiet` | Подавлять стандартный вывод в случае успеха — полезно в сценариях (полагайтесь только на код выхода). |
| `--json` | Выдавать необработанный результат JSON вместо удобочитаемого вывода. |

Если не указан ни позиционный аргумент `message`, ни `--file`, `hermes send` считывает из стандартного ввода, если это не TTY. Коды выхода: `0` при успехе, `1` при доставке/сбое серверной части, `2` при ошибках использования.

### Отправка изображений и других медиафайлов

`--file` предназначен только для *текстовых* тел. Чтобы доставить изображение, документ, видео или аудиофайл в виде вложения собственной платформы, укажите его в тексте сообщения с помощью директивы `MEDIA:<local_path>`:

```bash
hermes send --to telegram "MEDIA:/tmp/screenshot.png"
hermes send --to telegram "Build chart for today MEDIA:/tmp/chart.png"   # with caption
hermes send --to discord:#ops "MEDIA:/tmp/report.pdf"
```

По умолчанию файлы изображений отправляются в виде фотографий (такие платформы, как Telegram, повторно сжимают их). Добавьте `[[as_document]]` к сообщению, чтобы доставить его в виде вложенных несжатых файлов:

```bash
hermes send --to telegram "[[as_document]] MEDIA:/tmp/screenshot.png"
```

Примеры:

```bash
hermes send --to telegram "deploy finished"
echo "RAM 92%" | hermes send --to telegram:-1001234567890
hermes send --to discord:#ops --file /tmp/report.md
hermes send --to slack:#eng --subject "[CI]" --file build.log
hermes send --list                  # all platforms
hermes send --list telegram         # filter by platform
```



## `hermes peer`

```bash
hermes peer add <name> --url http://host:port --key <API_SERVER_KEY>
hermes peer list
hermes peer dm <peer>[/<agent>] "message"
hermes peer remove <name>
```

DM между роботами на разных машинах. Зарегистрируйте другой шлюз Hermes (любая машина
запуск платформы `api_server`) в качестве *peer*, а затем отправьте сообщение его агентам:
`hermes peer dm` разрешает канонический сеанс **бот-чата** удаленного агента.
через сервер API партнера, запускает там один оборот агента и печатает ответ
на стандартном выводе — межмашинный двойник локального
`hermes -p <bot> chat --in ~ -c "Bot Chat" …` команда обмена сообщениями для бота.

Только `<peer>` нацелен на главный агент однорангового шлюза;
`<peer>/<agent>` нацелен на именованный профиль на мультиплексированном одноранговом узле (маршрутизируется через
это зеркало `/p/<profile>/`).

| Подкоманда | Описание |
|--------|-------------|
| `add <name> --url <URL> [--key <KEY>] [--note TEXT]` | Зарегистрируйте или обновите партнера. URL-адрес ведет на `config.yaml` (`bot_peers`); ключ хранится как `HERMES_PEER_<NAME>_KEY` в `~/.hermes/.env`. |
| `list` | Перечислите одноранговые узлы и укажите, настроен ли для каждого из них ключ. |
| `dm <peer>[/<agent>] [message]` | Отправьте сообщение в канонический чат-бот равноправного агента и распечатайте ответ (`--json` для машиночитаемого вывода; сообщение возвращается на стандартный ввод). |
| `remove <name>` | Удалите пир из реестра (ключевая запись `.env` останется на месте). |

Когда зарегистрирован хотя бы один узел, протокол обмена сообщениями в режиме бота
(`agent.bot_mode_protocol`) автоматически обучается каждому каноническому чату-боту
включает список коллег и шаблон `hermes peer dm`, поэтому агенты обнаруживают
кросс-машинные товарищи по команде без правок SOUL. См.
[Режим бота](../user-guide/bot-mode.md).

Коды выхода: `0` при успехе, `1` при доставке/сбое узла, `2` при ошибках использования.

## `hermes kanban`

```bash
hermes kanban [--board <slug>] <action> [options]
```

Многопрофильная, многопроектная доска сотрудничества. Каждая установка может содержать множество досок (по одной на проект, репозиторий или домен); каждая плата представляет собой отдельную очередь со своей собственной базой данных SQLite и областью действия диспетчера. Новые установки начинаются с одной платы под названием `default`, чья база данных — `~/.hermes/kanban.db` для обратной совместимости; дополнительные доски доступны по адресу `~/.hermes/kanban/boards/<slug>/kanban.db`. Диспетчер, встроенный в шлюз, проверяет каждую доску за тик.

**Глобальные флаги (применяются ко всем действиям, указанным ниже):**

| Флаг | Цель |
|------|---------|
| `--board <slug>` | Работайте на конкретной доске. По умолчанию используется текущая плата (устанавливается через `hermes kanban boards switch`, переменную окружения `HERMES_KANBAN_BOARD` или `default`). |

**Это поверхность человека/сценариев.** Рабочие агенты, созданные диспетчером, управляют доской через специальный `kanban_*` [набор инструментов](/user-guide/features/kanban#how-workers-interact-with-the-board) (`kanban_show`, `kanban_complete`, `kanban_request_review`, `kanban_request_changes`, `kanban_block`, `kanban_create`, `kanban_link`, `kanban_comment`, `kanban_heartbeat`; профили оркестратора также получают `kanban_list` и `kanban_unblock`) вместо преобразования в `hermes kanban`. Работники закрепили `HERMES_KANBAN_BOARD` в своем окружении, поэтому они физически не могут видеть другие доски.

| Действие | Цель |
|--------|---------|
| `init` | Создайте `kanban.db`, если он отсутствует. Идемпотент. |
| `boards list` / `boards ls` | Перечислите все доски с количеством задач. `--json`, `--all` (включить в архив). |
| `boards create <slug>` | Создайте новую доску. Флаги: `--name`, `--description`, `--icon`, `--color`, `--switch` (сделать активными). Слизень шашлычный, автоопускаемый. |
| `boards switch <slug>` / `boards use` | Сохранять `<slug>` в качестве активной платы (записывать `~/.hermes/kanban/current`). |
| `boards show` / `boards current` | Распечатайте имя активной в данный момент доски, путь к базе данных и количество задач. |
| `boards rename <slug> "<name>"` | Измените отображаемое имя доски. Слизень неизменен. |
| `boards rm <slug>` | Архивировать (по умолчанию) или принудительно удалить доску. `--delete` пропускает этап архивирования. Архивированные доски перемещаются на `boards/_archived/<slug>-<ts>/`. Отказано для `default`. |
| `create "<title>"` | Создайте новую задачу на активной доске. Флаги: `--body`, `--assignee`, `--parent` (повторяемые), `--workspace scratch\|worktree\|dir:<path>`, `--tenant`, `--priority`, `--triage`, `--idempotency-key`, `--max-runtime`, `--max-retries`, `--skill` (повторяемые). |
| `list` / `ls` | Перечислите задачи на активной доске. Фильтруйте с помощью `--mine`, `--assignee`, `--status`, `--tenant`, `--archived`, `--json`. |
| `show <id>` | Показать задачу с комментариями и событиями. `--json` для машинного вывода. |
| `assign <id> <profile>` | Назначить или переназначить. Используйте `none`, чтобы отменить назначение. Отказано во время выполнения задачи. |
| `link <parent> <child>` | Добавьте зависимость. Обнаружен цикл. Обе задачи должны находиться на одной доске. |
| `unlink <parent> <child>` | Удалить зависимость. |
| `claim <id>` | Атомарно заявите готовую задачу. Печатает разрешенный путь к рабочей области. |
| `comment <id> "<text>"` | Добавить комментарий. Следующий рабочий процесс, заявивший задачу, считывает ее как часть своего ответа `kanban_show()`. |
| `complete <id>` | Отметить задачу как выполненную. Флаги: `--result`, `--summary`, `--metadata`. |
| `block <id> "<reason>"` | Отметить задачу, заблокированную из-за вмешательства человека. Также добавляет причину в виде комментария. |
| `request-review <id>` | Переместите задачу на `review` с передачей ее рецензенту, а НЕ блокировкой. Флаги: `--summary`, `--metadata`, `--reviewer` (переназначаются перед отправкой проверки). |
| `request-changes <id> <reason>` | Вердикт рецензента для активной проверки: закройте попытку проверки и направьте задачу обратно исходному исполнителю. |
| `reopen-review <id>...` | Отправьте задачи проверки обратно на предмет изменений (`review` → готово/сделать). Флаг: `--reason` (добавлен в виде комментария). |
| `schedule <id> "<reason>"` | В `scheduled` работает задержка/отслеживание парковки, поэтому он не отображается как блокирующий человек. |
| `unblock <id>` | Восстановите заблокированную задачу в исходную фазу (`review` или `ready`) или `todo`, пока зависимости остаются открытыми. |
| `archive <id>` | Скрыть из списка по умолчанию. `gc` удалит рабочие области. |
| `tail <id>` | Следите за потоком событий задачи. |
| `dispatch` | На активном табло проходит один диспетчер. Флаги: `--dry-run`, `--max N`, `--failure-limit N`, `--json`. |
| `context <id>` | Распечатайте полный контекст, который увидит работник (заголовок + текст + родительские результаты + комментарии). |
| `specify <id>` / `specify --all` | Конкретизируйте задачу сортировки столбцов в конкретную спецификацию (заголовок + тело с целью, подходом, критериями приемки) с помощью вспомогательного LLM, а затем продвиньте ее до `todo`. Флаги: `--tenant` (область `--all` для одного клиента), `--author`, `--json`. Настройте модель под `auxiliary.triage_specifier` в `config.yaml`. |
| `decompose <id>` / `decompose --all` | Распределите задачу в виде столбца сортировки в график дочерних задач, перенаправленных по профилям специалистов по описанию. Возвращается к продвижению одной задачи в стиле указания, когда LLM решает, что задача не выиграет от разветвления. Те же флаги, что и у `specify`. Настройте модель декомпозера под `auxiliary.kanban_decomposer` в `config.yaml`; `kanban.orchestrator_profile` контролирует только то, кто является владельцем задачи root/оркестрации после разветвления. Также запускается автоматически при каждом тике диспетчера, когда `kanban.auto_decompose: true` (по умолчанию). См. [Автоматическое и ручное оркестрирование](/user-guide/features/kanban#auto-vs-manual-orchestration). |
| `gc` | Удалите временные рабочие области для заархивированных задач. |

Примеры:

```bash
# Create a second board and put a task on it without switching away.
hermes kanban boards create atm10-server --name "ATM10 Server" --icon 🎮
hermes kanban --board atm10-server create "Restart server" --assignee ops

# Switch the active board for subsequent calls.
hermes kanban boards switch atm10-server
hermes kanban list                  # shows atm10-server tasks

# Archive a board (recoverable) or hard-delete it.
hermes kanban boards rm atm10-server
hermes kanban boards rm atm10-server --delete
```

Порядок разрешения платы (сначала наивысший приоритет): `--board <slug>` флаг → `HERMES_KANBAN_BOARD` env var → `~/.hermes/kanban/current` файл → `default`.

Все действия также доступны в виде команды с косой чертой в шлюзе (`/kanban …`) с той же поверхностью аргументов, включая подкоманды `boards` и флаг `--board`.

Полный дизайн — сравнение с Cline Kanban / Paperclip / NanoClaw / Gemini Enterprise, восемь шаблонов совместной работы, четыре пользовательские истории, доказательство корректности параллелизма — см. `docs/hermes-kanban-v1-spec.pdf` в репозитории или [руководство пользователя Kanban](/user-guide/features/kanban).

## `hermes egress`

Брандмауэр с внедрением исходящих учетных данных для изолированных программных сред удаленных терминалов. Обертывает демон [iron-proxy](https://github.com/ironsh/iron-proxy) — прокси-сервер, перехватывающий TLS, который заменяет непрозрачные токены прокси на реальные учетные данные восходящего API на границе сети, поэтому песочницы никогда не содержат реальных ключей. По умолчанию отключено; см. полную страницу [Выходной прокси](../user-guide/egress/iron-proxy.md) для настройки и архитектуры.

```bash
hermes egress install                  # download the pinned iron-proxy binary
hermes egress install --force          # re-download even if already installed

hermes egress setup                    # interactive wizard: CA, mappings, config
hermes egress setup --tunnel-port N    # override the tunnel listener port (default 9090)
hermes egress setup --from-bitwarden   # use Bitwarden Secrets Manager as credential source
hermes egress setup --no-bitwarden     # explicitly switch back to env-based credentials
hermes egress setup --rotate-tokens    # mint fresh proxy tokens (default preserves existing)

hermes egress start                    # spawn the managed proxy daemon
hermes egress stop                     # SIGTERM (then SIGKILL after 5s grace)
hermes egress restart                  # stop (if running) then start — needed for secret changes
hermes egress reload                   # hot-reload the ruleset in-place (no restart, no dropped
                                       #   connections) via the loopback management API

hermes egress status                   # binary + config + pid + listening + mappings
hermes egress status --show-tokens     # print proxy tokens in full (default: redacted)

hermes egress disable                  # flip proxy.enabled = false (does not stop a running proxy)
hermes egress config                   # print the path to proxy.yaml for inspection
```

### Общие потоки

```bash
# First-time setup
export OPENROUTER_API_KEY=…
hermes egress setup && hermes egress start
hermes config set terminal.backend docker   # if not already

# Switching credential source after the fact
hermes egress setup --from-bitwarden       # env → bitwarden
hermes egress setup --no-bitwarden         # bitwarden → env
# (just `setup` without either flag preserves the existing mode)

# Rotating all tokens (e.g. after a suspected token leak)
hermes egress setup --rotate-tokens    # setup offers to restart the running daemon for you
# (running sandboxes still hold old tokens; restart them too)

# Adding a new upstream
# Edit ~/.hermes/config.yaml proxy.extra_allowed_hosts: [api.example.com]
hermes egress setup
hermes egress restart                  # one-command apply (stop + start)
```

### Ярлыки диагностики

```bash
hermes egress status                     # current state in one view
cat ~/.hermes/proxy/proxy.yaml           # the rendered iron-proxy config
tail -20 ~/.hermes/proxy/iron-proxy.log  # daemon-level diagnostics
tail -f ~/.hermes/proxy/iron-proxy.log | jq  # daemon + per-request log (line-delimited JSON; v0.39 combines both streams)
```

Распространенные режимы сбоя и восстановления описаны в [Выходной прокси → Устранение неполадок](../user-guide/egress/iron-proxy.md#troubleshooting).

Управляйте динамическими подписками на веб-перехватчики для активации агентов, управляемых событиями. Требуется, чтобы платформа веб-перехватчиков была включена в конфигурации — если она не настроена, печатает инструкции по настройке.

| `remove` / `rm` | Удалить динамическую подписку. Статические маршруты из config.yaml не затрагиваются. |
| `test` | Отправьте тестовый POST, чтобы убедиться, что подписка работает. |

## `hermes debug`

```bash
hermes debug share [options]
```

Загрузите отчет об отладке (информация о системе + последние журналы) в службу вставки и получите общий URL-адрес. Полезно для быстрых запросов в службу поддержки — включает все, что нужно помощнику для диагностики вашей проблемы.

| Вариант | Описание |
|--------|-------------|
| `--lines <N>` | Количество строк журнала, включаемых в каждый файл журнала (по умолчанию: 200). |
| `--expire <days>` | Срок действия вставки в днях (по умолчанию: 7). |
| `--nous` | Загрузите во внутреннее хранилище диагностики Nous вместо публичной службы вставки. Используйте это, когда служба поддержки Nous запрашивает частный диагностический пакет. |
| `--local` | Распечатайте отчет локально, а не загружайте его. |
| `--no-redact` | Отключить редактирование секрета во время загрузки. По умолчанию загрузки редактируются. |

Отчет включает в себя информацию о системе (ОС, версию Python, версию Hermes), последний агент, шлюз, графический интерфейс/панель мониторинга и журналы рабочего стола (ограничение 512 КБ на файл), а также отредактированный статус ключа API. По умолчанию загрузки редактируются, поэтому секреты не включаются.

При загрузке по умолчанию используются общедоступные службы вставки, которые опробованы по порядку: Paste.rs, dpaste.com. `--nous` вместо этого загружает тот же пакет отладки в частное хранилище диагностики Nous; возвращенная ссылка для просмотра предназначена для команды Nous и автоматически удаляется через 14 дней.

### Примеры

```bash
hermes debug share              # Upload debug report, print URL
hermes debug share --lines 500  # Include more log lines
hermes debug share --expire 30  # Keep paste for 30 days
hermes debug share --nous       # Upload a private diagnostics bundle for Nous support
hermes debug share --local      # Print report to terminal (no upload)
```

## `hermes backup`

```bash
hermes backup [options]
```

Создайте zip-архив вашей конфигурации, навыков, сеансов и данных Hermes. Резервная копия исключает саму кодовую базу агента hermes и не включает в себя более ранние артефакты резервной копии (`backups/`, `state-snapshots/`) — каждый из них уже содержит свою собственную копию `state.db`.

| Вариант | Описание |
|--------|-------------|
| `-o`, `--output <path>` | Выходной путь для zip-файла (по умолчанию: `~/hermes-backup-<timestamp>.zip`). |
| `-q`, `--quick` | Быстрый снимок: только файлы критического состояния (config.yaml, state.db, .env, задания аутентификации, cron). Гораздо быстрее, чем полное резервное копирование. |
| `-l`, `--label <name>` | Метка снимка (используется только с `--quick`). |

Резервное копирование использует API `backup()` SQLite для безопасного копирования, поэтому оно работает правильно, даже когда Hermes работает (безопасный режим WAL).

**Что исключено из архива:**

- `*.db-wal`, `*.db-shm`, `*.db-journal` — дополнительные программы SQLite для WAL/разделяемой памяти/журнала. Файл `*.db` уже получил согласованный снимок через `sqlite3.backup()`; отправка вместе с ним живых колясок позволила бы восстановлению увидеть полузавершенное состояние.
- `checkpoints/` — кэширование траекторий для каждого сеанса. Хеш-код и генерация заново за сеанс; в любом случае не будет полностью перенесен на другую установку.
- Сам код `hermes-agent` (это резервная копия пользовательских данных, а не снимок репозитория).

### Примеры

```bash
hermes backup                           # Full backup to ~/hermes-backup-*.zip
hermes backup -o /tmp/hermes.zip        # Full backup to specific path
hermes backup --quick                   # Quick state-only snapshot
hermes backup --quick --label "pre-upgrade"  # Quick snapshot with label
```

## `hermes checkpoints`

```bash
hermes checkpoints [COMMAND]
```

Проверяйте и управляйте теневым хранилищем git по адресу `~/.hermes/checkpoints/` — уровнем хранения, лежащим в основе внутрисессионной команды `/rollback`. Безопасно работать в любое время; не требует запуска агента.

| Подкоманда | Описание |
|------------|-------------|
| `status` (по умолчанию) | Отображение общего размера, количества проектов и разбивки по проектам. Голый `hermes checkpoints` эквивалентен. |
| `list` | Псевдоним `status`. |
| `prune` | Принудительно провести очистку — удалить бесхозные и устаревшие проекты, выполнить сборку хранилища, установить ограничение размера. Игнорирует 24-часовой маркер идемпотентности. |
| `clear` | Удалить всю базу чекпоинтов. необратимый; запрашивает подтверждение, если только `-f`. |
| `clear-legacy` | Удалите только архивы `legacy-<timestamp>/`, созданные в результате миграции v1 → v2. |

### Параметры

| Вариант | Подкоманда | Описание |
|--------|------------|-------------|
| `--limit N` | `status`, `list` | Максимальное количество проектов в списке (по умолчанию 20). |
| `--retention-days N` | `prune` | Удалить проекты, `last_touch` которых старше N дней (по умолчанию 7). |
| `--max-size-mb N` | `prune` | После прохода «сиротский/устаревший» удаляйте самую старую фиксацию для каждого проекта до тех пор, пока общий размер хранилища не станет < N МБ (по умолчанию 500). |
| `--keep-orphans` | `prune` | Пропустить удаление проектов, рабочий каталог которых больше не существует. |
| `-f`, `--force` | `clear`, `clear-legacy` | Пропустите запрос подтверждения. |

### Примеры

```bash
hermes checkpoints                                  # status overview
hermes checkpoints prune --retention-days 3         # aggressive cleanup
hermes checkpoints prune --max-size-mb 200          # tighten size cap once
hermes checkpoints clear-legacy -f                  # drop v1 archive dirs
hermes checkpoints clear -f                         # wipe everything
```

См. [Контрольные точки и `/rollback`](../user-guide/checkpoints-and-rollback.md) для получения полной информации об архитектуре и командах сеанса.

## `hermes logs`

```bash
hermes logs [log_name] [options]
```

Просматривайте, отслеживайте и фильтруйте файлы журналов Hermes. Все журналы хранятся в `~/.hermes/logs/` (или `<profile>/logs/` для профилей не по умолчанию).

### Файлы журналов

| Имя | Файл | Что он фиксирует |
|------|------|-----------------|
| `agent` (по умолчанию) | `agent.log` | Вся деятельность агента — вызовы API, отправка инструментов, жизненный цикл сеанса (INFO и выше) |
| `errors` | `errors.log` | Только предупреждения и ошибки — отфильтрованное подмножество Agent.log |
| `gateway` | `gateway.log` | Активность шлюза обмена сообщениями — подключения к платформе, отправка сообщений, события веб-перехватчика |
| `gui` | `gui.log` | Панель управления/TUI-шлюз/PTY-мост/вебсокет события |
| `desktop` | `desktop.log` | Настольное приложение Electron — загрузка, вывод серверной части и последние обратные трассировки Python |

### Опции

| Вариант | Описание |
|--------|-------------|
| `log_name` | Какой журнал просматривать: `agent` (по умолчанию), `errors`, `gateway` или `list`, чтобы показать доступные файлы с указанием размеров. |
| `-n`, `--lines <N>` | Количество отображаемых строк (по умолчанию: 50). |
| `-f`, `--follow` | Следите за журналом в режиме реального времени, например `tail -f`. Нажмите Ctrl+C, чтобы остановить. |
| `--level <LEVEL>` | Минимальный уровень журнала для отображения: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
| `--session <ID>` | Фильтровать строки, содержащие подстроку идентификатора сеанса. |
| `--since <TIME>` | Показывать строки, относящиеся к относительному времени назад: `30m`, `1h`, `2d` и т. д. Поддерживается `s` (секунды), `m` (минуты), `h` (часы), `d` (дни). |
| `--component <NAME>` | Фильтровать по компонентам: `gateway`, `agent`, `tools`, `cli`, `cron`. |

### Примеры

```bash
# View the last 50 lines of agent.log (default)
hermes logs

# Follow agent.log in real time
hermes logs -f

# View the last 100 lines of gateway.log
hermes logs gateway -n 100

# Show only warnings and errors from the last hour
hermes logs --level WARNING --since 1h

# Filter by a specific session
hermes logs --session abc123

# Follow errors.log, starting from 30 minutes ago
hermes logs errors --since 30m -f

# List all log files with their sizes
hermes logs list
```

### Фильтрация

Фильтры можно комбинировать. Если активно несколько фильтров, для отображения строка журнала должна пройти **все** из них:

```bash
# WARNING+ lines from the last 2 hours containing session "tg-12345"
hermes logs --level WARNING --since 2h --session tg-12345
```

Строки без анализируемой метки времени включаются, когда `--since` активен (они могут быть строками продолжения многострочной записи журнала). Линии без обнаруживаемого уровня включаются, когда `--level` активен.

### Ротация журналов

Гермес использует Python `RotatingFileHandler`. Старые журналы ротируются автоматически — ищите `agent.log.1`, `agent.log.2` и т. д. Подкоманда `hermes logs list` показывает все файлы журналов, включая ротированные.


## `hermes prompt-size`

```bash
hermes prompt-size [--platform <name>] [--json]
```

Сообщает фиксированный оперативный бюджет для нового сеанса — то, что отправляется каждый раз.
Вызов API *перед* любым содержимым разговора. Полезно, когда нисходящий адаптер или
прокси имеет более ограниченный бюджет, чем контекстное окно модели, или когда вы
хочу увидеть, какой блок (индекс навыков, память, профиль) доминирует.

Он создает ту же системную подсказку, что и агент, а затем разбивает ее на части:

- **Общая подсказка системы** — полная подсказка (личность, руководство, навыки).
  индекс, контекстные файлы, память, профиль, временная метка).
- **Индекс навыков** — блок `<available_skills>`. Зачастую это самый крупный
  одиночный блок, когда установлено много навыков.
- **Память** и **профиль пользователя** — ваши снимки `MEMORY.md` / `USER.md`.
- **Уровни подсказок** — стабильные/контекстные/изменчивые, соответствуют слоям Hermes.
  запрос на удобство кэширования.
- **Схемы инструментов** — JSON для всех включенных инструментов (вторая половина
  фиксированная полезная нагрузка для каждого вызова).

Работает полностью автономно — без вызова API, работает без настроенных учетных данных.

```bash
# Human-readable breakdown for the CLI platform (default)
hermes prompt-size

# Simulate a messaging platform's prompt (different platform hint)
hermes prompt-size --platform telegram

# Machine-readable output for scripts
hermes prompt-size --json
```

:::совет
Индекс навыков и схемы инструментов масштабируются в зависимости от количества имеющихся у вас навыков и инструментов.
включен. Чтобы уменьшить приглашение, отключите неиспользуемые наборы инструментов (`hermes tools`) или
удалите ненужные вам навыки (`hermes skills`). Контекстные файлы (AGENTS.md,
.cursorrules) в вашем текущем каталоге также учитываются в общей сумме.
:::

| Подкоманда | Описание |
|------------|-------------|
| `browse` | Постраничный браузер для реестров навыков. |
| `search` | Поиск реестров навыков. |
| `install` | Установите навык. |
| `inspect` | Предварительный просмотр навыка без его установки. |
| `list` | Перечислите установленные навыки. |
| `check` | Проверьте установленные навыки концентратора на предмет обновлений исходной версии. |
| `update` | Переустановите навыки концентратора с изменениями, внесенными в исходную версию, если они доступны. |
| `audit` | Повторное сканирование установленных навыков хаба. |
| `uninstall` | Удаление навыка, установленного в хабе. |
| `reset` | Отключите связанный навык, помеченный как `user_modified`, очистив его запись в манифесте. При использовании `--restore` пользовательская копия также заменяется связанной версией. |
| `opt-out` | Не допускайте добавления объединенных навыков в активный профиль. Записывает маркер `.no-bundled-skills`, поэтому установщик `hermes update` и любая синхронизация пропускают заполнение связанных навыков. Безопасно по умолчанию — ничего на диске не трогается. С помощью `--remove` также удаляются уже имеющиеся связанные навыки, которые **немодифицированы** (навыки, отредактированные пользователем, установленные в хабе и написанные от руки, никогда не удаляются; сначала выполняется предварительный просмотр и подтверждение, `--yes` для пропуска). |
| `opt-in` | Отмените `opt-out`, удалив маркер `.no-bundled-skills`, чтобы объединенные навыки были снова использованы в следующем `hermes update`. С `--sync` немедленно повторите заполнение. |
| `publish` | Опубликовать навык в реестре. |
| `snapshot` | Экспорт/импорт конфигураций навыков. |
| `tap` | Управляйте пользовательскими источниками навыков. |
| `config` | Интерактивная настройка включения/выключения навыков в зависимости от платформы. |

Распространенные примеры:

```bash
hermes skills browse
hermes skills browse --source official
hermes skills search react --source skills-sh
hermes skills search https://mintlify.com/docs --source well-known
hermes skills inspect official/security/1password
hermes skills inspect skills-sh/vercel-labs/json-render/json-render-react
hermes skills install official/migration/openclaw-migration
hermes skills install skills-sh/anthropics/skills/pdf --force
hermes skills install https://sharethis.chat/SKILL.md                     # Direct URL (+ referenced support files)
hermes skills install https://example.com/SKILL.md --name my-skill        # Override name when frontmatter has none
hermes skills check
hermes skills update
hermes skills config
hermes skills reset google-workspace
hermes skills reset google-workspace --restore --yes
hermes skills opt-out                  # stop future bundled-skill seeding (nothing deleted)
hermes skills opt-out --remove --yes   # also delete UNMODIFIED bundled skills
hermes skills opt-in --sync            # undo: remove marker and re-seed now
```

Примечания:
- `--force` может переопределить неопасные блокировки политики для сторонних/общественных навыков.
- `--force` не отменяет вердикт сканирования `dangerous`.
- `--source skills-sh` выполняет поиск в общедоступном каталоге `skills.sh`.
- `--source well-known` позволяет указать Гермесу место, раскрывающее `/.well-known/skills/index.json`.
- `--source browse-sh` ищет в каталоге [browse.sh](https://browse.sh) более 200 навыков автоматизации браузеров для конкретных сайтов. Идентификаторы выглядят как `browse-sh/airbnb.com/search-listings-ddgioa`.
– При передаче URL-адреса `http(s)://…/*.md` устанавливается `SKILL.md`, а также файлы с явной ссылкой под `references/`, `templates/`, `scripts/`, `assets/` и `examples/`. Если во вступительной части нет `name:`, а фрагмент URL-адреса не является допустимым идентификатором, интерактивный терминал запрашивает имя; неинтерактивные поверхности (`/skills install` внутри TUI, платформы шлюза) вместо этого требуют `--name <x>`.

Хранение: `~/.hermes/skill-bundles/<slug>.yaml`. См. [Наборы навыков](../user-guide/features/skills.md#skill-bundles) для получения информации о схеме и поведении YAML.

## `hermes curator`

```bash
hermes curator <subcommand>
```

Куратор — это фоновая задача вспомогательной модели, которая периодически проверяет навыки, созданные агентом, удаляет устаревшие, объединяет дублирующиеся навыки и архивирует устаревшие навыки. Навыки, включенные в комплект и установленные в хабе, никогда не затрагиваются. Архивы подлежат восстановлению; автоудаление никогда не происходит.

| Подкоманда | Описание |
|------------|-------------|
| `status` | Показать статус куратора и статистику навыков |
| `run` | Запустить проверку куратора прямо сейчас (блокируется до завершения прохождения LLM) |
| `run --background` | Запустите проход LLM в фоновом потоке и немедленно вернитесь |
| `run --dry-run` | Только предварительный просмотр — создание отчета о проверке без изменений |
| `backup` | Сделайте вручную снимок tar.gz `~/.hermes/skills/` (куратор также делает снимки автоматически перед каждым реальным запуском) |
| `rollback` | Восстановить `~/.hermes/skills/` из снимка (по умолчанию — самый новый) |
| `rollback --list` | Список доступных снимков |
| `rollback --id <ts>` | Восстановить конкретный снимок по id |
| `rollback -y` | Пропустить запрос подтверждения |
| `pause` | Приостановить работу куратора до возобновления |
| `resume` | Резюме приостановленного куратора |
| `pin <skill>` | Закрепите навык, чтобы куратор никогда не переключал его автоматически |
| `unpin <skill>` | Открепить навык |
| `restore <skill>` | Восстановить заархивированный навык |
| `archive <skill>` | Архивировать навык вручную |
| `prune` | Вручную сокращайте навыки, которые куратор обычно подчищает |
| `list-archived` | Список заархивированных навыков (можно восстановить через `restore`) |

При новой установке первый запланированный проход откладывается на один полный `interval_hours` (по умолчанию 7 дней) — шлюз не будет выполнять курирование сразу после первого тика после `hermes update`. Используйте `hermes curator run --dry-run` для предварительного просмотра, прежде чем это произойдет.

См. [Куратор](../user-guide/features/curator.md) для ознакомления с поведением и конфигурацией.

## `hermes plugins`

```bash
hermes plugins [subcommand]
```

Унифицированное управление плагинами — общие плагины, поставщики памяти и контекстные механизмы в одном месте. Запуск `hermes plugins` без подкоманды открывает составной интерактивный экран с двумя разделами:

- **Общие плагины** — флажки с возможностью выбора нескольких вариантов включения/отключения установленных плагинов.
- **Плагины поставщика** — конфигурация с одним выбором для поставщика памяти и механизма контекста. Нажмите ENTER в категории, чтобы открыть окно выбора радио.

| Подкоманда | Описание |
|------------|-------------|
| *(нет)* | Составной интерактивный пользовательский интерфейс — общие переключатели плагинов + настройка плагина провайдера. |
| `install <identifier> [--force] [--ref COMMIT_SHA]` | Установите плагин по URL-адресу Git, `owner/repo` или простому индексному имени. Простые имена (без косой черты) разрешаются через индекс плагина сообщества в `owner/repo` плюс закрепленный индексом коммит; неоднозначные имена перечисляют кандидатов и уходят. `--ref` принимает только полный 40-символьный SHA фиксации, устанавливает именно эту неизменяемую версию и переопределяет любой индексный контакт. |
| `search [term] [--json] [--capability CAP] [--refresh]` | Выполните поиск по индексу плагинов сообщества (нечеткое совпадение по имени/описанию/тегам; для просмотра опустите `term`). Извлечено из `plugins.index_url` (по умолчанию: индекс плагина NousResearch), кэшировано под `~/.hermes/cache/` на 24 часа, возвращается к устаревшему кешу, а затем к пакетному начальному значению в автономном режиме. Проиндексировано ≠ проверено — включение подразумевает только проверку метаданных. |
| `update <name>` | Извлеките последние изменения для незакрепленного установленного плагина. Для перемещения закрепленные плагины необходимо переустановить с помощью `--force --ref <new-commit>`. |
| `remove <name>` (псевдонимы: `rm`, `uninstall`) | Удалить установленный плагин. |
| `enable <name>` | Включите отключенный плагин. |
| `disable <name>` | Отключите плагин, не удаляя его. |
| `list` (псевдоним: `ls`) | Список установленных плагинов с включенным/отключенным статусом. |
| `doctor [path-or-id] [--ci]` | Проверьте собственный плагин с помощью реального анализатора манифеста, загрузчика и пути регистрации. `--ci` завершает работу 1 при ошибке. |
| `pack install <path-or-url> [--force]` | Установите пакет плагинов (`hermes-pack.yaml`) — декларативный набор плагинов, каждый из которых привязан к точному 40-символьному SHA фиксации. Показывает экран обязательной проверки (каждый плагин, источник, закрепленную ссылку, заявленные возможности), запрашивает одно подтверждение содержимого пакета, затем запускает обычные закрепленные установки. Заявленные возможности каждого плагина по-прежнему проходят стандартное согласие каждого плагина — пакет никогда не предоставляет массовые разрешения. О частичных сбоях сообщается для каждого плагина; выходит из ненулевого значения, если какой-либо плагин вышел из строя. Только интерактивно (без `--yes`). |
| `pack export [--enabled-only] [--name NAME]` | Выдать пакет YAML на стандартный вывод из текущей установки: репо + точный SHA каждого установленного git плагина плюс очищенную несекретную конфигурацию `plugins.entries`. Плагины, предназначенные только для локального использования (без происхождения git), отображаются как предупреждающие комментарии, а не как устанавливаемые записи. Секреты, права доступа и шлюзы `allow_*` всегда удаляются. |
| `pack show <path-or-url>` | Пробный запуск: анализ, проверка и отображение пакета без какой-либо установки. |

Выбор плагина поставщика сохраняется в `config.yaml`:
- `memory.provider` — поставщик активной памяти (пусто = только встроенная)
- `context.engine` — механизм активного контекста (`"compressor"` = встроенный по умолчанию)

Общий список отключенных плагинов хранится в `config.yaml` под `plugins.disabled`.
При установке Git также записывается только канонический источник, точная установленная версия и
статус вывода в профиле локальной коляски `plugins/.install-metadata.json`. Это делает
не содержать конфигурацию плагина, значения среды, секреты или права доступа.

См. [Плагины](../user-guide/features/plugins.md) и [Создание плагина Hermes](../developer-guide/plugins/index.md).

## `hermes claw`

```bash
hermes claw migrate [options]
```

Перенесите настройки OpenClaw в Hermes. Читает из `~/.openclaw` (или пользовательского пути) и записывает в `~/.hermes`. Автоматически определяет устаревшие имена каталогов (`~/.clawdbot`, `~/.moltbot`) и имена файлов конфигурации (`clawdbot.json`, `moltbot.json`).

| Вариант | Описание |
|--------|-------------|
| `--dry-run` | Предварительный просмотр того, что будет перенесено, ничего не записывая. |
| `--preset <name>` | Предварительная настройка миграции: `full` (все совместимые настройки) или `user-data` (исключая конфигурацию инфраструктуры). Ни одна из предустановок не импортирует секреты — передайте `--migrate-secrets` явно. |
| `--overwrite` | Перезаписать существующие файлы Hermes в случае конфликтов (по умолчанию: отказаться от применения, если в плане есть конфликты). |
| `--migrate-secrets` | Включите ключи API в миграцию. Требуется даже для `--preset full`. |
| `--no-backup` | Пропустите zip-снимок `~/.hermes/` перед переносом (по умолчанию один архив с точкой восстановления записывается в `~/.hermes/backups/pre-migration-*.zip` перед применением; его можно восстановить с помощью `hermes import`). |
| `--source <path>` | Пользовательский каталог OpenClaw (по умолчанию: `~/.openclaw`). |
| `--workspace-target <path>` | Целевой каталог для инструкций рабочей области (AGENTS.md). |
| `--skill-conflict <mode>` | Обработка конфликтов имен навыков: `skip` (по умолчанию), `overwrite` или `rename`. |
| `--yes` | Пропустите запрос подтверждения. |

### Что будет перенесено

Миграция охватывает более 30 категорий личности, памяти, навыков, поставщиков моделей, платформ обмена сообщениями, поведения агентов, политик сеансов, серверов MCP, TTS и многого другого. Элементы либо **напрямую** импортируются** в эквиваленты Hermes, либо **архивируются** для проверки вручную.

**Непосредственный импорт:** SOUL.md, MEMORY.md, USER.md, AGENTS.md, навыки (4 исходных каталога), модель по умолчанию, пользовательские поставщики, серверы MCP, токены и списки разрешений платформы обмена сообщениями (Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Mattermost), настройки агента по умолчанию (обоснование, сжатие, человеческая задержка, часовой пояс, песочница), политики сброса сеанса, правила утверждения, TTS config, настройки браузера, настройки инструментов, тайм-аут выполнения, список разрешенных команд, конфигурация шлюза и ключи API из 3 источников.

**Архивировано для проверки вручную:** задания Cron, плагины, перехватчики/веб-перехватчики, серверная часть памяти (QMD), конфигурация реестра навыков, пользовательский интерфейс/идентификация, ведение журнала, настройка нескольких агентов, привязки каналов, IDENTITY.md, Tools.md, HEARTBEAT.md, BOOTSTRAP.md.

**Разрешение ключа API** проверяет три источника в порядке приоритета: значения конфигурации → `~/.openclaw/.env` → `auth-profiles.json`. Все поля токенов обрабатывают простые строки, шаблоны env (`${VAR}`) и объекты SecretRef.

Полное сопоставление ключей конфигурации, подробности обработки SecretRef и контрольный список после миграции см. в **[полном руководстве по миграции](../guides/migrate-from-openclaw.md)**.

### Примеры

```bash
# Preview what would be migrated
hermes claw migrate --dry-run

# Full migration (all compatible settings, no secrets)
hermes claw migrate --preset full

# Full migration including API keys
hermes claw migrate --preset full --migrate-secrets

# Migrate user data only (no secrets), overwrite conflicts
hermes claw migrate --preset user-data --overwrite

# Migrate from a custom OpenClaw path
hermes claw migrate --source /home/user/old-openclaw
```

## `hermes serve`

```bash
hermes serve [options]
```

Запустите **внутренний сервер** Hermes — шлюз JSON-RPC/WebSocket, к которому подключаются [настольное приложение](/user-guide/desktop) и удаленные клиенты. Это тот же сервер, на котором работает `hermes dashboard`, но **безголовый**: он никогда не открывает пользовательский интерфейс браузера. Настольное приложение запускает собственный сервер `hermes serve`; используйте эту команду напрямую, если вам нужен автономный сервер на удаленном хосте. Принимает те же параметры `--host` / `--port` / `--insecure` / `--skip-build` / `--stop` / `--status`, что и `hermes dashboard` ниже (привязка без обратной связи задействует тот же шлюз аутентификации). Требуется дополнительно `[web]`; встроенному сокету Chat дополнительно требуется `[pty]` на хосте POSIX.

**Конфликты портов:** если запрошенный порт (по умолчанию `9119`) уже занят другим процессом (например, вторым `hermes serve` или шлюзом), команда печатает машиночитаемую сторожевую строку `BACKEND_PORT_IN_USE port=<port>` в стандартный вывод, человеческую подсказку с указанием вероятного владельца, и завершает работу с кодом **75** (`EX_TEMPFAIL`) вместо общей ошибки — так скрипты и настольное приложение может отличить «порт занят» от «серверной части сломан». Передайте `--port 0`, чтобы привязать свободный временный порт (при успешной загрузке выбранный порт будет объявлен через `HERMES_BACKEND_READY port=<port>`).

| `rename <old> <new>` | Переименуйте профиль. |

| `import <archive> [--name NAME]` | Импортируйте профиль из архива `.tar.gz` (локальное восстановление). |
| `install <source> [--name N] [--alias] [--force] [-y]` | Установите дистрибутив профиля из URL-адреса git или локального каталога. |
| `update <name> [--force-config] [-y]` | Повторно вытащить раздачу; сохраняет пользовательские данные (память, сеансы, аутентификация). |
| `info <name>` | Показать манифест распространения профиля (версия, требования, источник). |

Примеры:

```bash
hermes profile list
hermes profile create work --clone
hermes profile use work
hermes profile alias work --name h-work
hermes profile export work -o work-backup.tar.gz
hermes profile import work-backup.tar.gz --name restored
hermes profile install github.com/user/my-distro --alias
hermes profile update work
hermes -p work chat -q "Hello from work profile"
```

## `hermes completion`

```bash
hermes completion [bash|zsh|fish]
```

Выведите сценарий завершения оболочки на стандартный вывод. Используйте выходные данные в своем профиле оболочки для завершения команд Hermes, подкоманд и имен профилей с помощью табуляции.

Примеры:

```bash
# Bash
hermes completion bash >> ~/.bashrc

# Zsh
hermes completion zsh >> ~/.zshrc

# Fish
hermes completion fish > ~/.config/fish/completions/hermes.fish
```

## `hermes update`

```bash
hermes update [--gateway] [--check] [--plan] [--no-backup] [--backup] [--yes]
```

Извлекает последний код `hermes-agent` и переустанавливает зависимости в управляемом венве, затем повторно запускает перехватчики после установки (серверы MCP, синхронизация навыков, завершение установки). Безопасно работать при живой установке. Используйте `--check`, чтобы узнать, находится ли ваша проверка за `origin/main` без установки.

`hermes update` извлекает настроенную ветку обновления (по умолчанию: `main`). Если ваша проверка находится в другой ветке, Hermes может проверить ветку обновления перед извлечением. Зафиксируйте работу ветки перед обновлением, если вы хотите оставить ее вне потока автоматического хранения обновлений.

| Вариант | Описание |
|--------|-------------|
| `--gateway` | Внутренний режим, используемый командой обмена сообщениями `/update`. Использует файловый IPC для подсказок и потоковой передачи хода выполнения вместо чтения из стандартного ввода терминала. Не флаг перезапуска шлюза. |
| `--check` | Проверьте, доступно ли обновление, не извлекая, не устанавливая зависимости и не перезапуская что-либо. |
| `--plan` | Распечатайте план обновления и выйдите, ничего не меняя: тип установки (git/Docker/Nix/apt), каждый запущенный сервис Hermes во всех профилях с его супервизором и версией работающего кода, а также способ перезапуска каждого из них. При установках, управляемых образом или пакетом, вместо этого сообщается правильная внешняя команда обновления. Только для чтения. |
| `--no-backup` | Пропустите все резервные копии перед обновлением для этого запуска (как быстрый снимок состояния, так и полный zip-архив), независимо от `updates.pre_update_backup`. |
| `--backup` | Создайте **полную** резервную копию перед обновлением для этого запуска: быстрый снимок состояния и полный архив `HERMES_HOME` (конфигурация, аутентификация, сеансы, навыки, данные сопряжения). Режим по умолчанию — `quick` — только упрощенный снимок состояния. Установите постоянный режим через `updates.pre_update_backup: quick | full | off` в `config.yaml`. |
| `--yes`, `-y` | Предположим, что да, для интерактивных подсказок, таких как миграция конфигурации и восстановление тайника. Ввод API-ключа пропускается; для них запустите `hermes config migrate` отдельно. |

Дополнительное поведение:

- **Перезапуск шлюза.** После успешного обновления Hermes пытается автоматически перезапустить все работающие профили шлюза, чтобы они получили новый код. Используйте `hermes gateway restart`, если хотите перезапустить шлюз без применения обновления.
- **Восстановление на этапе перезапуска.** Если этап перезапуска в процессе прерывается при импорте только что извлеченного дерева, профили контролируемого шлюза повторяются через чистый процесс Python. Только перезапуски, независимо подтвержденные systemd (`systemctl --user is-active`), считаются проверенными; перезапуск, который просто вышел из 0, записывается как `relaunch_attempted` и по-прежнему консервативно завершает обновление. Ручные шлюзы и среда выполнения обслуживания/панели мониторинга никогда не отключаются без разрешения на перезапуск; они записываются как пропущенные с указанием причины и остаются в отчете о незавершенном обновлении с точной командой перезапуска.
- **Квитанции об обновлении + проверка версии парка.** При каждом запуске на `~/.hermes/logs/update_receipts/` записывается машиночитаемая квитанция (план предварительного обновления парка, этапы, пропуски с причинами, результат перезапуска; `latest.json` указывает на самую новую версию). После фазы перезапуска средство обновления сверяет рабочий код каждого действующего шлюза с обновленной проверкой и печатает матрицу версий для каждого профиля; шлюз, все еще использующий код предварительного обновления, не выполняет обновление (выход 1) с помощью точной команды перезапуска.
- **Изменения в локальном исходном коде.** При установке git грязные отслеживаемые и неотслеживаемые файлы автоматически сохраняются перед извлечением или извлечением ветки (`git stash push --include-untracked`). Интерактивные обновления терминала запрашиваются перед восстановлением тайника. Неинтерактивные обновления восстанавливают его по умолчанию; задавайте `updates.non_interactive_local_changes: discard` только в управляемых установках, где изменения локального исходного кода должны быть удалены после успешного извлечения. Если возникает конфликт при восстановлении тайника или происходит сбой при извлечении, тайник остается на месте для восстановления вручную.
- **обмен файлов блокировки npm.** Перед сохранением или переключением веток Hermes максимально эффективно очищает отслеживаемые различия `package-lock.json`, созданные на этапах установки/сборки npm. Зафиксируйте или вручную сохраните намеренные изменения в файле блокировки перед запуском `hermes update`.
- **Снимок данных сопряжения.** Даже если `--backup` выключен, `hermes update` делает упрощенный снимок `~/.hermes/pairing/`, и комментарии Feishu регулируются до `git pull`. Вы можете откатить его с помощью `hermes backup restore --state pre-update`, если при извлечении перезаписывается файл, который вы редактировали.
- **Устаревшее предупреждение `hermes.service`.** Если Hermes обнаруживает предварительно переименованный системный модуль `hermes.service` (вместо текущего `hermes-gateway.service`), он печатает одноразовую подсказку о миграции, чтобы вы могли избежать проблем с циклическими изменениями.
- **Коды выхода.** `0` в случае успеха, `1` в случае ошибок извлечения, установки или после установки, `2` в случае непредвиденных изменений рабочего дерева, которые блокируют `git pull`.

## Команды обслуживания

| Команда | Описание |
|---------|-------------|
| `hermes --version` | Информация о версии для печати. |
| `hermes update` | Извлеките последние изменения и переустановите зависимости. |

| `hermes uninstall [--full] [--gui] [--dry-run] [--yes]` | Удалите Hermes, при необходимости удалив все настройки/данные. `--gui` удаляет только графический интерфейс чата на рабочем столе, оставляя агента нетронутым; `--full` также удаляет конфигурацию/данные; `--dry-run` печатает то, что должно быть удалено, ничего не меняя; `--yes` пропускает подсказки. |
