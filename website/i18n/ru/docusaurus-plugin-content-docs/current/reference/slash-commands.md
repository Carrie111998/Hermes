# Справочник по командам слэша

У Hermes есть две поверхности с косой чертой, обе управляются центральным `COMMAND_REGISTRY` в `hermes_cli/commands.py`:

- **Интерактивные слэш-команды CLI** — отправляются `cli.py` с автозаполнением из реестра.
- **Команды с косой чертой для обмена сообщениями** — отправляются `gateway/run.py`, с текстом справки и меню платформы, созданными из реестра.

Установленные навыки также отображаются в виде динамических команд косой черты на обеих поверхностях. Сюда входят встроенные навыки, такие как `/plan`, который открывает режим планирования и сохраняет планы уценки в `.hermes/plans/` относительно активной рабочей области или внутреннего рабочего каталога.

## Разрешения и разделение администратора/пользователя

Каждая платформа обмена сообщениями, поддерживающая список разрешений для каждого пользователя (Telegram, Discord, Slack, Matrix, Mattermost, Signal и т. д.), также поддерживает двухуровневое разделение команд с косой чертой: **администраторы** получают каждую зарегистрированную команду, **обычные пользователи** получают только имена, которые вы перечисляете в `user_allowed_commands` (плюс всегда разрешенный этаж `/help` и `/whoami`). Настройте `allow_admin_from` и `user_allowed_commands` (и эквиваленты для каждой группы `group_allow_admin_from` / `group_user_allowed_commands`) внутри блока `extra:` платформы в `~/.hermes/gateway-config.yaml`.

Примеры см. в документации для каждой платформы — структура одинакова для всех платформ:

- [Telegram](../user-guide/messaging/telegram.md#slash-command-access-control)
- [Discord](../user-guide/messaging/discord.md)
- [Slack](../user-guide/messaging/slack.md)
- [Матрица](../user-guide/messaging/matrix.md)
- [Mattermost](../user-guide/messaging/mattermost.md)
- [Сигнал](../user-guide/messaging/signal.md)

Если `allow_admin_from` не задан для области, эта область остается в неограниченном режиме обратной совместимости — каждый разрешенный пользователь может запускать любую команду.

## Интерактивные команды CLI с косой чертой

Введите `/` в CLI, чтобы открыть меню автозаполнения. Встроенные команды нечувствительны к регистру.

### Сеанс

| Команда | Описание |
|---------|-------------|
| `/new [name]` (псевдоним: `/reset`) | Начать новый сеанс (новый идентификатор сеанса + история). Необязательный `[name]` задает начальный заголовок сеанса, например. `/new my-experiment` открывает новый сеанс, уже названный `my-experiment`, поэтому его легко найти позже с помощью `/resume` или `/sessions`. Добавьте `now`, `--yes` или `-y`, чтобы пропустить модальное окно подтверждения — например. `/reset now`, `/new --yes my-experiment`. |
| `/clear` | Очистить экран и начать новый сеанс |
| `/history` | Показать историю разговоров (уважает `/timestamps`) |
| `/save` | Сохранить текущий разговор |
| `/prompt` (псевдоним: `/compose`) | Составьте следующее приглашение в `$EDITOR` (уценка) вместо встроенного ввода — полезно для длинных, многострочных или тщательно отформатированных приглашений. |
| `/retry` | Повторить последнее сообщение (повторно отправить агенту) |
| `/undo` | Удалить последний обмен пользователем/помощником |
| `/title` | Установите заголовок для текущего сеанса (использование: /title Имя моего сеанса) |
| `/compress [here [N] \| focus topic]` | Сжать контекст разговора вручную (очистить воспоминания + подвести итоги). `/compress here [N]` суммирует все, кроме самых последних обменов N (по умолчанию 2), сохраняется дословно — выберите свою собственную границу сжатия. Основная тема сужает то, что сохраняет полное резюме. |
| `/rollback` | Вывести список или восстановить контрольные точки файловой системы (использование: /rollback [число]) |
| `/diff [staged\|all\|session] [--stat] [path...]` | Показать изменения git в рабочем каталоге. По умолчанию: неиндексированные изменения плюс неотслеживаемые файлы. `staged` показывает, что подготовлено для фиксации, `all` — все, начиная с HEAD, а `session` — совокупные различия всего, что Гермес изменил здесь (начиная с самой ранней сохраненной базовой контрольной точки — требует включения контрольных точек; дополняет `/rollback diff <N>`). `--stat` печатает только сводку измененного файла; Аргументы пути ограничивают разницу. |
| `/snapshot [create\|restore <id>\|prune]` (псевдоним: `/snap`) | Создайте или восстановите снимки состояния конфигурации/состояния Hermes. `create [label]` сохраняет снимок, `restore <id>` возвращается к нему, `prune [N]` удаляет старые снимки или выводит список всех без аргументов. Восстановление базы данных записывается через API резервного копирования SQLite, поэтому живые процессы (шлюз, панель мониторинга) безопасно видят восстановленные данные; если этот путь завершается неудачно, в то время как другой процесс все еще удерживает базу данных открытой, восстановление отклоняется вместо риска повреждения — остановите держателя и повторите попытку. |
| `/stop` | Убить все запущенные фоновые процессы |
| `/queue <prompt>` (псевдоним: `/q`) | Поставьте запрос на следующий ход (не прерывает текущий ответ агента). |
| `/steer <prompt>` | Вставьте промежуточную заметку, которая поступает к агенту **после следующего вызова инструмента** — без прерываний и без нового обращения пользователя. Текст добавляется к содержимому последнего результата инструмента после завершения работы текущего инструмента, предоставляя агенту новый контекст без нарушения текущего цикла вызова инструмента. Используйте это, чтобы подтолкнуть направление в середине задачи (например, «сосредоточиться на модуле аутентификации», пока агент выполняет тесты). |
| `/goal <text>` | Установите постоянную цель, к которой Гермес стремится через повороты — наш взгляд на петлю Ральфа. После каждого хода модель вспомогательного судьи решает, достигнута ли цель; если нет, Гермес автоматически продолжает работу. Подкоманды: `/goal status`, `/goal pause`, `/goal resume`, `/goal clear`. Бюджет по умолчанию равен 20 ходам (`goals.max_turns`); любое сообщение реального пользователя прерывает цикл продолжения, и состояние сохраняется `/resume`. Полное описание см. в разделе [Постоянные цели](/user-guide/features/goals). |
| `/subgoal <text>` | Добавьте критерий, предоставленный пользователем, к активной цели в середине цикла. Подсказка о продолжении дословно отображает все подцели агенту, и судья учитывает их в своем вердикте «ГОТОВО/ПРОДОЛЖИТЬ» — так что цель не помечается как выполненная до тех пор, пока исходная цель **и** не будут достигнуты. Подкоманды: `/subgoal` (список), `/subgoal remove <N>`, `/subgoal clear`. Требуется активный `/goal`. |
| `/heartbeat every <interval> <prompt>` (псевдоним: `/hb`) | Установите повторяющийся запрос, который повторно входит в **этот сеанс** как обычный ход пользователя, когда он бездействует и истекает интервал (минимум 60 секунд; пропущенные тики объединяются). Подкоманды: `/heartbeat status`, `/heartbeat pause`, `/heartbeat resume`, `/heartbeat clear`. На уровне сеанса и в процессе — используйте `hermes cron` для устойчивых изолированных расписаний. См. раздел [Session Heartbeats](/user-guide/features/heartb

есть). |
| `/refine [focus]` | Запустите фоновую проверку памяти/самоусовершенствования навыков **сейчас**, вместо того, чтобы ждать автоматического триггера после хода. Необязательный фокусный текст направляет обзор (например, `/refine save the deploy workflow as a skill`). Запускается в фоновом режиме на основе снимка разговора — живой сеанс и кеш подсказок не затрагиваются; результаты сообщаются после завершения. |
| `/review [instructions]` | Создайте независимого субагента рецензента с полными привилегиями для проверки только что обсуждаемой работы — PR, кода, документации и любого артефакта, упомянутого в последних 10 сообщениях чата. Он проводит расследование в фоновом режиме (открывает PR, читает различия, запускает код), и его полный анализ повторно входит в этот сеанс как завершение фонового субагента, над которым может действовать основной агент. Закрепите специальную модель для обзора через `auxiliary.review` в config.yaml (по умолчанию — ваша основная модель). См. [Делегирование субагента](/user-guide/features/delegation#the-review-command). |
| `/moa <prompt>` | Запустите один запрос через предустановку по умолчанию [Mixture of Agents](/user-guide/features/mixture-of-agents), а затем восстановите текущую модель. Одноразовый — не меняет модель сеанса. |
| `/resume [name]` | Возобновить ранее названный сеанс |
| `/sessions` (псевдоним TUI: `/switch`) | Классический интерфейс командной строки: просматривайте и возобновляйте предыдущие сеансы в интерактивном средстве выбора. TUI: откройте переключатель живых сеансов для открытых в данный момент сеансов TUI. Используйте `/sessions new` в пользовательском интерфейсе, чтобы немедленно начать новый сеанс в реальном времени. |
| `/egress [status]` | Показать статус выходного прокси-сервера Docker — состояние включено/настроено/работает, источник учетных данных, сопоставления токенов, непокрытые поставщики и следующий шаг исправления. Работает в CLI, TUI, настольном чате и шлюзе обмена сообщениями. |
| `/redraw` | Принудительно перерисовать пользовательский интерфейс (восстанавливается после смещения терминала после изменения размера tmux, артефактов выбора мыши и т. д.) |
| `/status` | Отображение информации о сеансе — модели, поставщика, профиля, идентификатора сеанса, рабочего каталога, названия, созданных/обновленных временных меток, общего количества токенов, состояния работы агента — с последующим локальным блоком **Сводка сеанса** (количество недавних обращений пользователя/помощника, количество результатов инструментов, наиболее часто используемые инструменты, несколько последних обращений к файлам, последнее приглашение пользователя и последний ответ помощника). Резюме вычисляется локально на основе разговора в памяти; никакого вызова LLM, никакого воздействия на кэш подсказок. |
| `/context [all]` (псевдоним: `/ctx`) | Визуальная разбивка контекстных окон. В CLI/TUI: сетка блоков глифов 5×20 (каждая ячейка ≈ 1% окна модели) плюс приблизительная таблица для каждой категории — системное приглашение, определения инструментов, правила, индекс навыков, MCP, субагенты, память, разговор — в сравнении со свободным пространством. На платформах обмена сообщениями: индикатор использования с порогом/запасом автоматического сжатия, статистикой сжатия, совокупной пропускной способностью и той же таблицей категорий в виде обычного текста. `/context all` добавляет списки затрат для каждого навыка и набора инструментов (стоимость индекса и стоимость загрузки SKILL.md; токены схемы для каждого набора инструментов). Доступно только для чтения и вычисляется локально — без вызова LLM и без влияния на кэш подсказок. |
| `/agents` (псевдоним: `/tasks`) | Покажите активных агентов и выполняемые задачи в текущем сеансе. |
| `/background <prompt>` (псевдоним: `/bg`, `/btw`) | Запустите приглашение в отдельном фоновом сеансе. Агент обрабатывает ваше приглашение самостоятельно — ваша текущая сессия остается бесплатной для другой работы. Результаты отображаются в виде панели после завершения задачи. См. [Фоновые сеансы CLI](/user-guide/cli#background-sessions). |
| `/branch [name]` (псевдоним: `/fork`) | Разветвить текущий сеанс (исследовать другой путь) |
| `/worktree [new [name]\|list]` | **Только CLI.** Проверяйте или создавайте изолированные рабочие деревья git в середине сеанса (на основе `/worktree new` Copilot CLI). Голый `/worktree` показывает активное рабочее дерево; `/worktree list` перечисляет рабочие деревья репозитория; `/worktree new [name]` создает рабочее дерево под `.worktrees/` (ответвление от только что полученного удаленного совета в честь `worktree_sync`) и перенаправляет в него терминал сеанса и файловые инструменты. Именованные деревья используют ваше имя (ветвь `hermes/<name>`); безымянные получают случайный `hermes-<id>`. При выходе дерево сохраняется только в том случае, если оно имеет неотправленные коммиты — тот же жизненный цикл, что и `hermes -w`. См. [Git Worktrees](/user-guide/git-worktrees). |
| `/handoff <platform>` | **Только CLI.** Передайте текущий сеанс

платформа обмена сообщениями (Telegram, Discord, Slack, WhatsApp, Signal, Matrix). Шлюз немедленно подхватывает его, создает новый поток на платформах, которые поддерживают потоки (темы Telegram, потоки текстового канала Discord, потоки, привязанные к сообщениям Slack), повторно привязывает место назначения к вашему session_id CLI, чтобы воспроизводилась полная расшифровка с учетом ролей, и подделывает синтетический ход пользователя, чтобы агент подтвердил, что он работает на новом месте. В случае успеха ваш CLI завершает работу с подсказкой `/resume`; возобновите локально в любое время с помощью `/resume <title>`. Отказался на середине хода. Требуется, чтобы шлюз был запущен, а домашний канал настроен для целевой платформы (`/sethome` из целевого чата). См. [Кросс-платформенная передача](/user-guide/sessions#cross-platform-handoff). |
| `/journey [list\|delete <id>\|edit <id>]` (псевдонимы: `/learning`, `/memory-graph`) | Откройте шкалу обучения приобретенным навыкам и воспоминаниям. Работает в классическом интерфейсе командной строки, в виде оверлея TUI и в настольном приложении (панель «Звездная карта»). Недоступно на платформах обмена сообщениями. См. [Обучающее путешествие](/user-guide/features/memory#learning-journey-journey). |

### Конфигурация

| Команда | Описание |
|---------|-------------|
| `/config` | Показать текущую конфигурацию |
| `/model [model-name]` | Показать или изменить текущую модель. Поддерживается: `/model claude-sonnet-4`, `/model provider:model` (переключатель поставщиков), `/model custom:model` (пользовательская конечная точка), `/model custom:name:model` (именный пользовательский поставщик), `/model custom` (автоматическое определение из конечной точки) и определяемые пользователем псевдонимы (`/model fav`, `/model grok` — см. [Псевдонимы пользовательской модели](#custom-model-aliases)). Флаги: `--global` сохраняет изменения в config.yaml; `--session` принудительно поддерживает только сеанс; `--once` применяется только к следующему ходу; `--refresh` повторно извлекает список моделей поставщика; `--provider <name>` переключает серверную часть (только для сеанса, если только не `--global`). Простой `/model <name>` предназначен только для сеанса, если не установлен `model.persist_switch_by_default: true`. **Интерактивный инструмент выбора:** запуск `/model` без аргументов открывает окно выбора поставщика → модели; в списке моделей вы можете **ввести для нечеткой фильтрации** моделей (например, введите `grok`, чтобы сузить список до подходящих моделей), Backspace, чтобы обрезать фильтр, Esc, чтобы очистить его (или закрыть средство выбора). Выбор всегда сводится к одной конкретной модели — фильтр только сужает список, он никогда не угадывает. **Примечание.** `/model` может переключаться только между уже настроенными поставщиками. Чтобы добавить нового провайдера, выйдите из сеанса и запустите `hermes model` со своего терминала. **Примечание о стоимости:** переключение моделей в середине разговора сбрасывает кэш подсказок — ключ кэша включает модель, поэтому при следующем ходе вы перечитываете весь разговор по полной входной цене вместо кэшированной ставки со скидкой ~75 %. Ожидаемо и неизбежно, но об этом стоит знать во время длительных сессий. |
| `/codex-runtime [auto\|codex_app_server\|on\|off]` | Переключите необязательный [время выполнения сервера приложений Codex](../user-guide/features/codex-app-server-runtime) для моделей OpenAI/Codex. `auto` (по умолчанию) использует стандартные дополнения чата Hermes; `codex_app_server` переходит к подпроцессу `codex app-server` для встроенной оболочки, apply_patch, аутентификации по подписке ChatGPT и перенесенных плагинов Кодекса. Действует на следующем сеансе. |
| `/personality` | Установите предопределенную личность. `/personality none` (или `default`/`neutral`) очищает наложение и возвращает базовое поведение. |
| `/verbose` | Циклическое отображение хода работы инструмента: выключено → новое → все → подробное. Может быть [включено для обмена сообщениями](#notes) через конфигурацию. |
| `/focus [on\|off\|status]` | Переключить **представление фокуса** — режим ограниченного вывода только для отображения, в котором отображается только ваше приглашение и окончательный ответ. Компонует с помощью `/verbose`: при его включении прогресс инструмента привязывается к `off` и запоминается предыдущий режим, а `/focus off` восстанавливает его. Каждый ход заканчивается тусклой линией восстановления (`⋯ 7 tool lines hidden · /focus off to show`), а в строке состояния постоянно отображается значок `◉ focus`, поэтому вы всегда будете знать, что находитесь в уменьшенном виде. В модель ничего не передается иначе — детали скрыты и никогда не отбрасываются. |
| `/fast [normal\|fast\|status]` | Переключить быстрый режим — приоритетная обработка OpenAI / антропный быстрый режим. Опции: `normal`, `fast`, `status`. |

### Быстрые команды

Пользовательские быстрые команды сопоставляют короткую команду с косой чертой либо с командой оболочки, либо с другой командой с косой чертой. Настройте их в `~/.hermes/config.yaml`:

```yaml
quick_commands:
  status:
    type: exec
    command: systemctl status hermes-agent
  deploy:
    type: exec
    command: scripts/deploy.sh
  inbox:
    type: alias
    target: /gmail unread
```

Затем введите `/status`, `/deploy` или `/inbox` в интерфейсе командной строки или на платформе обмена сообщениями. Быстрые команды обрабатываются во время отправки и могут не отображаться во всех встроенных таблицах автозаполнения/справки.

Сочетания клавиш, состоящие только из строк, не поддерживаются в качестве быстрых команд. Добавьте в навык более длинные многоразовые подсказки или используйте `type: alias`, чтобы указать на существующую косую черту.

### Псевдонимы пользовательских моделей

Определите свои собственные короткие имена для часто используемых моделей, а затем обращайтесь к ним с помощью `/model <alias>` в CLI или на любой платформе обмена сообщениями. Псевдонимы работают одинаково как на переключателях только для сеанса (по умолчанию), так и на переключателях `--global`.

Поддерживаются два формата конфигурации:

**Полная форма** – укажите точную модель, поставщика и, при необходимости, базовый URL. Поместите это в `~/.hermes/config.yaml`:

```yaml
model_aliases:
  fav:
    model: claude-sonnet-4.6
    provider: anthropic
  grok:
    model: grok-4
    provider: x-ai
  ollama-qwen:
    model: qwen3-coder:30b
    provider: custom
    base_url: http://localhost:11434/v1
```

**Краткая форма** — `provider/model` в одной строке. Установить из оболочки без редактирования YAML:

```bash
hermes config set model.aliases.fav anthropic/claude-opus-4.6
hermes config set model.aliases.grok x-ai/grok-4
```

Затем в чате:

```
/model fav            # session-only
/model grok --global  # also persists current-model change to config.yaml
```

Псевдонимы пользователей имеют приоритет над встроенными короткими именами, поэтому присвоение псевдонимов `sonnet`, `kimi`, `opus` и т. д. затеняет встроенные. Имена псевдонимов не чувствительны к регистру.

### Разрешение псевдонимов

Команды поддерживают сопоставление префиксов: ввод `/h` преобразуется в `/help`, `/mod` преобразуется в `/model`. Если префикс неоднозначен (соответствует нескольким командам), побеждает первое совпадение в порядке реестра. Полные имена команд и зарегистрированные псевдонимы всегда имеют приоритет над совпадениями префиксов.

## Команды обмена сообщениями

> **Команды Slack thread (префикс `!`):**
> Сам Slack блокирует собственные команды слэша внутри потоков сообщений («/queue не поддерживается в потоках. Извините!») и никогда не доставляет их в Hermes. Внутри потока Slack вместо этого используйте префикс `!` — `!stop`, `!new`, `!status` — и шлюз отправляет его точно так же, как в форме косой черты. `@Hermes !stop` и `@Hermes /stop` также работают в потоках. Только первый токен проверяется на соответствие списку известных команд, поэтому сообщения типа `!nice work` передаются агенту без изменений. Подробности см. в разделе [Использование команд внутри потоков](/user-guide/messaging/slack#using-commands-inside-threads-the-cmd-prefix).

Шлюз обмена сообщениями поддерживает следующие встроенные команды в чатах Telegram, Discord, Slack, WhatsApp, Signal, Email, Home Assistant и Teams:

| Команда | Описание |
|---------|-------------|
| `/start` | Команда протокола платформы. Многие чат-платформы (Telegram, Discord и т. д.) автоматически отправляют `/start`, когда пользователь впервые открывает беседу с ботом. Гермес молча подтверждает пинг — ни ответа агента, ни сброса сеанса — поэтому рукопожатия при первом контакте не теряют ни одного хода. ## Примечания

- `/skin`, `/snapshot`, `/export`, `/import`, `/reload`, `/tools`, `/toolsets`, `/browser`, `/config`, `/cron`, `/platforms`, `/paste`, `/image`, `/statusbar`, `/battery`, `/focus`, `/plugins`, `/busy`, `/indicator`, `/wake`, `/journey`, `/redraw`, `/clear`, `/history`, `/save`, `/copy`, `/handoff`, `/prompt`, `/pet`, `/hatch`, `/timestamps`, `/subscription` и `/quit` — это команды **только CLI**.
- `/skills` предназначен **только для поиска/просмотра/установки через интерфейс командной строки**; его подкоманды проверки утверждения записи (`pending`, `approve`, `reject`, `diff`, `approval`) также работают на платформах обмена сообщениями, когда `skills.write_approval` включен. `/memory` работает на **обеих** поверхностях.
- `/verbose` по умолчанию **только CLI**, но его можно включить для платформ обмена сообщениями, установив `display.tool_progress_command: true` в `config.yaml`. При включении он переключает режим `display.tool_progress` и сохраняет настройки.
- `/focus` и `/verbose` имеют один путь подавления (`display.tool_progress`), поэтому они никогда не могут противоречить друг другу: `/focus on` закрепляет прогресс инструмента на `off` и сохраняет ваш режим под `display.focus_saved_tool_progress`; `/focus off` восстанавливает его; циклическое нажатие `/verbose` при включенном фокусе возвращает режим обратно и очищает значок фокуса. Представление «Фокус» предназначено только для отображения — оно никогда не меняет историю разговоров, системные приглашения или что-либо, отправленное в модель, поэтому оно не оказывает никакого влияния на кэш подсказок.
- `/sethome`, `/restart`, `/approve`, `/deny`, `/topic`, `/platform` и `/commands` — команды **только для обмена сообщениями**.
- `/status`, `/egress`, `/version`, `/whoami`, `/background`, `/queue`, `/steer`, `/voice`, `/reload-mcp`, `/reload-skills`, `/rollback`, `/diff`, `/debug`, `/fast`, `/approvals`, `/footer`, `/curator`, `/kanban`, `/topup`, `/suggestions`, `/blueprint`, `/learn`, `/init`, `/sessions` и `/yolo` работают в **как** CLI, так и в шлюзе обмена сообщениями.
- `/voice join`, `/voice channel` и `/voice leave` имеют смысл только в Discord.
- В TUI `/sessions` показывает сеансы в реальном времени в текущем процессе TUI. Используйте `/resume [name]` или `hermes --tui --resume <id-or-title>` для сохраненных или закрытых стенограмм.

## Запрос подтверждения для деструктивных команд

Интерфейс командной строки выдает запрос перед запуском команд с косой чертой, которые удаляют несохраненное состояние сеанса. Текущий деструктивный набор:

| Команда | Что это разрушает |
|---------|------------------|
| `/clear` | Очищает экран и запускает новый сеанс — текущий идентификатор сеанса и история в памяти исчезают. |
| `/new` / `/reset` | Запускает новый сеанс (новый идентификатор сеанса + пустая история). |
| `/undo` | Удаляет из истории последний обмен сообщениями между пользователем и помощником. |
| `/exit --delete` / `/quit --delete` | Выход **и** безвозвратно удаляет историю SQLite текущего сеанса и записи на диске. |

Для каждого из них интерфейс командной строки открывает модальное окно с тремя вариантами выбора: **Утвердить один раз** (на этот раз продолжить), **Всегда утверждать** (продолжить и сохранить `approvals.destructive_slash_confirm: false`, чтобы будущие деструктивные команды выполнялись без запроса) или **Отмена**.

**Внутренний пропуск:** добавьте `now`, `--yes` или `-y`, чтобы обойти модальное окно для одного вызова, например `/reset now`, `/new --yes my-session`, `/clear -y`, `/undo -y`. Полезно, когда модальное окно неправильно отображается на вашем терминале (см. [issue #30768](https://github.com/NousResearch/hermes-agent/issues/30768) для встроенного Windows PowerShell) или при написании сценариев для CLI.

Установите `approvals.destructive_slash_confirm: false` в `~/.hermes/config.yaml`, чтобы отключить подсказки глобально; установите его обратно на `true`, чтобы снова включить. Контекст см. в разделе [Безопасность — подтверждение команды деструктивной косой черты](../user-guide/security.md#dangerous-command-approval).
