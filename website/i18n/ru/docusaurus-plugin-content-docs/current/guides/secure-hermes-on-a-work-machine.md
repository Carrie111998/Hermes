# Запуск Hermes на личном или рабочем компьютере

Вы собираетесь запустить агент на машине, на которой живете — на личном ноутбуке или на рабочей станции, управляемой работодателем. Какая поза безопасна?

Короткий ответ: значения по умолчанию уже выполняют большую часть работы. Hermes поставляется с безопасностью по умолчанию, с моделью глубокоэшелонированной защиты, охватывающей утверждение команд, безопасность записи файлов и обработку учетных данных. На этой странице рассказывается о том, что включено в стандартную комплектацию, какие ручки следует затягивать на общей или рабочей машине, а также о том, как исправить ошибки, если они происходят. Каждый элемент управления здесь подробно описан в руководстве [Безопасность](/user-guide/security).

## Что уже защищают настройки по умолчанию

Свежая установка, без настройки — эти средства защиты активны:

**Опасные команды требуют одобрения.** Перед выполнением любой команды Hermes сверяет ее с тщательно подобранным списком опасных шаблонов — рекурсивное удаление, запись в `/etc/`, дисковые операции, соединение между каналом и оболочкой и т. д. По умолчанию `approvals.mode: smart` использует вспомогательный LLM для оценки риска: команды с низким уровнем риска автоматически одобряются только для этой команды, действительно опасные команды автоматически отклоняются, а неопределенные случаи переходят к запросу вручную.

**Запросы на утверждение не закрываются.** Если вы не отвечаете на запрос на утверждение в течение заданного времени (по умолчанию 300 секунд), команда **отклоняется**. Выход из-за стола никогда ничего молча не одобряет.

**Жесткий черный список — это всегда доступный этаж.** Некоторые команды — `rm -rf /`, разветвление бомб, обнуление физического диска — отклоняются **независимо** от режима одобрения, `--yolo` или явного «разрешать всегда». Черный список срабатывает еще до того, как уровень утверждения увидит команду, и флаг переопределения отсутствует.

**Запись файлов по конфиденциальным путям заблокирована.** Инструменты `write_file` и `patch` не могут работать с хранилищами учетных данных ОС (`~/.ssh/`, `~/.aws/`, `~/.kube/`, `/etc/sudoers`, `~/.netrc`), хранилищами учетных данных Hermes (`auth.json`, `.env`, данные сопряжения) или секретными файлами проекта (`.env`, `.env.local`, `.envrc`) в любом месте диска. Заблокированные записи немедленно возвращают ошибку — нет запроса на одобрение и возможности переопределить из пользовательского интерфейса чата.

**Секреты удаляются из выходных данных.** `security.redact_secrets` включен по умолчанию: шаблоны, которые выглядят как ключи API, токены и пароли в выходных данных инструмента, редактируются до того, как они попадают в контекст разговора и журналы.

**Ваши данные передаются только туда, куда вы указываете.** Вызовы API передаются **только поставщику LLM, которого вы настроили**. Агент Hermes не собирает телеметрию, данные об использовании или аналитику. Ваши разговоры, память и навыки хранятся локально в `~/.hermes/`. См. [Часто задаваемые вопросы](/reference/faq#is-my-data-sent-where).

:::информация
Есть еще кое-что под поверхностью — защита SSRF для всех инструментов с поддержкой URL-адресов, фильтрованные среды для подпроцессов MCP, сканирование контекстных файлов с быстрым внедрением. На странице [Безопасность](/user-guide/security) документируется каждый уровень.
:::

## Затяжка для общей или рабочей машины

На машине с данными о работодателе, производственными учетными данными или файлами других людей наложите их поверх значений по умолчанию.

### Переключить одобрение на ручное управление

Режим `smart` автоматически утверждает команды с низким уровнем риска. Если вы хотите увидеть каждую помеченную команду самостоятельно:

```yaml
approvals:
  mode: manual
```

Ручной режим всегда выдает запрос перед выполнением помеченной команды.

### Добавьте свои собственные правила запрета

`approvals.deny` — это список шаблонов, которые безоговорочно блокируют соответствующие команды терминала — даже под `--yolo`, `/yolo` или `mode: off`. Это редактируемый пользователем аналог встроенного жесткого черного списка. Используйте его, чтобы объявить вещи, которые никогда не должны запускаться на этой машине:

```yaml
approvals:
  deny:
    - "git push --force*"
    - "*curl*|*sh*"
    - "dd if=* of=/dev/*"
```

Шаблоны представляют собой нечувствительные к регистру [fnmatch](https://docs.python.org/3/library/fnmatch.html) glob, сопоставляемые со всем текстом команды, и сопоставление выполняется по тем же нормализованным/деобфусцированным вариантам, которые использует детектор опасных шаблонов, поэтому простые приемы цитирования не ускользают от правил. Всегда заключайте шаблоны в кавычки — пустой начальный `*` — это ошибка синтаксического анализа YAML. Изменения вступают в силу немедленно, перезагрузка не требуется. Подробности: [Пользовательские правила запрета](/user-guide/security#user-defined-deny-rules-approvalsdeny).

### Запись в файл песочницы

`HERMES_WRITE_SAFE_ROOT` ограничивает `write_file` и `patch` указанными вами префиксами каталогов — все, что находится за их пределами, жестко блокируется. Несколько корней разделяются `:` в Unix:

```bash
export HERMES_WRITE_SAFE_ROOT=/path/to/project:/home/you/.hermes
```

Конфиденциальные пути внутри безопасного корня по-прежнему заблокированы — указание на `$HOME` не позволяет записать `~/.ssh/id_rsa`.

:::осторожно
Не добавляйте это в `~/.hermes/.env` случайно. Если вы установите его только для каталога проекта, агент не сможет писать в `~/.hermes/cron/jobs.json`, навыки профиля или другое состояние Hermes за пределами этого префикса. Включите свой дом Hermes в качестве второго корня, как указано выше.
:::

### Перенести выполнение команды с хоста

Самая сильная изоляция — это вообще не запускать команды на вашем компьютере. Инструмент терминала поддерживает несколько [бэкэндов](/user-guide/features/tools#terminal-backends):

| Бэкэнд | Изоляция |
|---------|-----------|
| `local` | Нет — выполняется на хосте (применяются проверки на наличие опасных команд) |
| `docker` | Контейнер — сам контейнер является границей безопасности |
| `ssh` | Удаленная машина — сохраняет выполнение на отдельном сервере |

```yaml
terminal:
  backend: docker
  docker_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  docker_forward_env: []  # Explicit allowlist only; empty keeps secrets out of the container
```

Каждый контейнер Docker работает с усиленными настройками — все возможности Linux исключены (с минимальным набором надстроек), `no-new-privileges`, ограничение на количество процессов и монтирование tmpfs с ограниченным размером. При использовании серверной части контейнера разрушительные команды внутри контейнера не могут нанести вред хосту, поэтому проверки на наличие опасных команд там пропускаются.

Для `ssh` установите `terminal.backend: ssh` в `config.yaml` и укажите сведения об хосте через `TERMINAL_SSH_HOST`, `TERMINAL_SSH_USER` и `TERMINAL_SSH_KEY` в `~/.hermes/.env`. См. [Сетевая изоляция](/user-guide/security#network-isolation).

### Если обмен сообщениями включен: белые списки и сопряжение

Запускаете [шлюз](/user-guide/security#user-authorization-gateway) на этом компьютере? По умолчанию уже запрещено: если списки разрешенных не настроены и `GATEWAY_ALLOW_ALL_USERS` не установлен, **всем пользователям запрещено**. Держите это явно:

```bash
# ~/.hermes/.env
TELEGRAM_ALLOWED_USERS=123456789
GATEWAY_ALLOWED_USERS=123456789
```

Или используйте сопряжение DM вместо жесткого кодирования идентификаторов: неизвестные пользователи получают одноразовый код сопряжения, и вы подтверждаете их из CLI с помощью `hermes pairing approve <platform> <code>`. Никогда не устанавливайте `GATEWAY_ALLOW_ALL_USERS=true` на машине, которая вам важна.

## Уровень отмены: контрольные точки и `/rollback`

Ворота одобрения предотвращают повреждение; [контрольные точки](/user-guide/checkpoints-and-rollback) отмените его. Если этот параметр включен, Hermes автоматически создает снимки вашего проекта перед деструктивными операциями — `write_file`, `patch` и деструктивными командами терминала, такими как `rm`, `mv`, `sed -i` и `git reset` — в теневое хранилище git под `~/.hermes/checkpoints/store/`. Ваш реальный проект `.git` никогда не будет затронут.

Контрольно-пропускные пункты являются добровольными. Включить для каждого сеанса:

```bash
hermes chat --checkpoints
```

Или глобально:

```yaml
checkpoints:
  enabled: true
```

Затем в сеансе:

| Команда | Описание |
|---------|-------------|
| `/rollback` | Список всех контрольных точек со статистикой изменений |
| `/rollback diff <N>` | Предварительный просмотр того, что изменилось после контрольной точки N |
| `/rollback <N>` | Восстановить до контрольной точки N (также отменяет последний ход чата) |
| `/rollback <N> <file>` | Восстановить один файл с контрольной точки N |

:::совет
Предварительный просмотр с помощью `/rollback diff <N>` перед восстановлением и объединение контрольных точек с рабочими деревьями git для максимальной безопасности — каждый сеанс Hermes в отдельном рабочем дереве с контрольными точками в качестве дополнительного уровня.
:::

## Что представляет собой эта модель угроз и чем она не является

Будьте ясны в отношении того, от чего защищают эти средства контроля. Как сказано в руководстве [Безопасность](/user-guide/security#user-define-deny-rules-approvalsdeny):

> Правила запрета — это ограждение от честного, но неправильного агента, та же модель угроз, что и детектор опасных шаблонов. Они не являются «песочницей» против заведомо состязательного процесса — для этого используйте изолированный бэкэнд (Docker, Modal) или среду с ограниченным исходящим доступом.

То же самое относится и к средствам защиты от записи файлов: они применяются только к `write_file` и `patch`, тогда как инструмент `terminal` запускается от имени того же пользователя ОС. Список запретов уменьшает случайные повреждения и дает моделям четкий сигнал остановки; он не помещает в «песочницу» враждебный или скомпрометированный агент. Если вашим требованием является сдерживание, а не ограждение, ответом будет изолированная серверная часть терминала — это граница, предназначенная для этого.

## Осторожная стартовая конфигурация

Все вышеперечисленное в сборе. Настройте по вкусу в `~/.hermes/config.yaml`:

```yaml
approvals:
  mode: manual                  # See every flagged command yourself
  timeout: 300                  # Unanswered prompts are denied (fail-closed)
  deny:                         # Never-run list — survives even /yolo
    - "git push --force*"
    - "*curl*|*sh*"
    - "dd if=* of=/dev/*"

security:
  redact_secrets: true          # Already the default; stated here for clarity

checkpoints:
  enabled: true                 # Snapshot before destructive operations

terminal:
  backend: docker               # Or ssh — keep execution off the host
  docker_forward_env: []        # No host secrets inside the container
```

А в `~/.hermes/.env`, если вам нужна песочница для записи:

```bash
HERMES_WRITE_SAFE_ROOT=/path/to/project:/home/you/.hermes
```
