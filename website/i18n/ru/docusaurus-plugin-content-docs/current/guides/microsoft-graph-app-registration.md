# Зарегистрируйте приложение Microsoft Graph

Конвейер собраний Teams считывает стенограммы собраний, записи и связанные с ними артефакты из Microsoft Graph, используя проверку подлинности **только для приложения** (управитель) — без входа пользователя в систему и без интерактивного согласия для каждого собрания. Для этого требуется регистрация приложения Azure AD с разрешениями приложения, предоставленными администратором.

В этом руководстве рассматриваются:

1. Создание регистрации приложения
2. Создание секрета клиента
3. Предоставление разрешений Graph API, необходимых конвейеру
4. Согласие администратора на эти разрешения
5. (Необязательно) Назначение приложения конкретным пользователям с помощью политики доступа к приложению.

Чтобы завершить это, вам потребуются **права администратора клиента** (или администратор, который предоставит согласие от вашего имени). Добавьте в закладки собранные вами значения — в конце они попадают в `~/.hermes/.env`.

## Предварительные условия

- Клиент Microsoft 365 с лицензиями Teams Premium или Teams, который создает стенограммы и записи собраний.
— Доступ администратора к порталу Azure по адресу [entra.microsoft.com](https://entra.microsoft.com).
— Общедоступная конечная точка HTTPS для уведомлений об изменениях в графике (настраивается позже, на этапе прослушивания веб-перехватчика).

## Шаг 1. Создайте регистрацию приложения

1. Войдите на сайт [entra.microsoft.com](https://entra.microsoft.com) в качестве администратора клиента.
2. Перейдите в раздел **Идентификация → Приложения → Регистрация приложений**.
3. Нажмите **Новая регистрация**.
4. Заполните:
   - **Имя:** `Hermes Teams Meeting Pipeline` (или любое имя, которое вы узнаете).
   - **Поддерживаемые типы учетных записей:** *Учетные записи только в этом каталоге организации (один клиент)*.
   - **URI перенаправления:** оставьте пустым — проверка подлинности только для приложения не требуется.
5. Нажмите **Зарегистрироваться**.

Вы попадете на страницу обзора приложения. Скопируйте два значения:

- **Идентификатор приложения (клиента)** → `MSGRAPH_CLIENT_ID`
- **Идентификатор каталога (арендатора)** → `MSGRAPH_TENANT_ID`

## Шаг 2. Создайте секрет клиента

1. В левой панели навигации откройте **Сертификаты и секреты**.
2. Нажмите **Новый секрет клиента**.
3. **Описание:** `hermes-graph-secret`. **Срок действия**: выберите значение, соответствующее вашей политике ротации (обычно 6–24 месяца).
4. Нажмите **Добавить**.
5. Сразу скопируйте столбец **Значение** — он отображается только один раз. Это значение — `MSGRAPH_CLIENT_SECRET`.

> Столбец **Секретный идентификатор** не является секретом. Вам нужен столбец **Значение**.

## Шаг 3. Предоставление разрешений API графа

Конвейер использует минимально возможный набор разрешений приложения. Добавляйте только то, что вам нужно; каждый из них расширяет то, что приложение может читать в масштабе всего клиента.

1. На левой панели навигации откройте **Разрешения API**.
2. Нажмите **Добавить разрешение** → **Microsoft Graph** → **Разрешения приложения**.
3. Добавьте разрешения из таблицы ниже, соответствующие тому, что вы хотите, чтобы конвейер делал.
4. После добавления нажмите **Предоставить согласие администратора для `<your tenant>`**. Столбец «Состояние» должен стать зеленой галочкой для каждого разрешения.

### Требуется для кратких расшифровок

| Разрешение | Что позволяет приложение |
|------------|--------------------------|
| `OnlineMeetings.Read.All` | Чтение метаданных онлайн-совещания Teams (тема, участники, URL-адрес присоединения). |
| `OnlineMeetingTranscript.Read.All` | Прочтите стенограммы собраний, созданные Teams. |

### Требуется для резервной записи (когда расшифровка недоступна)

| Разрешение | Что позволяет приложение |
|------------|--------------------------|
| `OnlineMeetingRecording.Read.All` | Загрузите записи собраний Teams для автономной обработки STT. |
| `CallRecords.Read.All` | Разрешайте собрания из записей вызовов, когда известен только URL-адрес присоединения. |

### Требуется для доставки исходящей сводки (только в режиме графика)

Если `platforms.teams.extra.delivery_mode` — `graph`, конвейер публикует сводки в канал Teams или в чат через API Graph. Пропустите их, если вместо этого используете режим доставки `incoming_webhook`.

| Разрешение | Что позволяет приложение |
|------------|--------------------------|
| `ChannelMessage.Send` | Публикуйте сообщения в каналах Teams от имени приложения. |
| `Chat.ReadWrite.All` | Публикуйте сообщения в личных и групповых чатах (только если вы указали `chat_id` в качестве цели доставки). |

### Не рекомендуется

- `OnlineMeetings.ReadWrite.All` / `Chat.ReadWrite` без `.All` — шире, чем нужно конвейеру.
- Делегированные разрешения — конвейер использует поток только для приложений (клиентские учетные данные); делегированные разрешения не будут работать без входа пользователя.

## Шаг 4. (рекомендуется) Определите приложение с помощью политики доступа к приложению

По умолчанию разрешения приложения, такие как `OnlineMeetings.Read.All`, предоставляют приложению доступ к **каждому** собранию в клиенте. Для партнерских демонстрационных версий и арендаторов-разработчиков это нормально; для производства вы почти наверняка захотите ограничить собрания пользователей, которые приложение может читать.

Именно для этого Microsoft предоставляет **Политики доступа к приложениям** для Teams. Эта политика доступна только для PowerShell; для этого нет пользовательского интерфейса портала.

От администратора PowerShell с установленным и подключенным модулем MicrosoftTeams (`Connect-MicrosoftTeams`):

```powershell
# Create a policy scoped to the Hermes app
New-CsApplicationAccessPolicy `
  -Identity "Hermes-Meeting-Pipeline-Policy" `
  -AppIds "<MSGRAPH_CLIENT_ID>" `
  -Description "Restrict Hermes meeting pipeline to allow-listed users"

# Grant the policy to specific users whose meetings the pipeline may read
Grant-CsApplicationAccessPolicy `
  -PolicyName "Hermes-Meeting-Pipeline-Policy" `
  -Identity "alice@example.com"

Grant-CsApplicationAccessPolicy `
  -PolicyName "Hermes-Meeting-Pipeline-Policy" `
  -Identity "bob@example.com"
```

Распространение может занять до 30 минут после предоставления. Подтвердите с помощью:

```powershell
Test-CsApplicationAccessPolicy -Identity "alice@example.com" -AppId "<MSGRAPH_CLIENT_ID>"
```

Без этой политики **любые** собрания пользователей доступны для чтения — это то, что технически предоставляет разрешение. Не пропускайте этот шаг для производственного арендатора.

## Шаг 5. Запишите учетные данные в файл Env

Поместите три значения, которые вы собрали, в `~/.hermes/.env`:

```bash
MSGRAPH_TENANT_ID=<directory-tenant-id>
MSGRAPH_CLIENT_ID=<application-client-id>
MSGRAPH_CLIENT_SECRET=<client-secret-value>
```

Установите права доступа к файлу, чтобы только вы могли прочитать секрет:

```bash
chmod 600 ~/.hermes/.env
```

## Шаг 6. Проверка потока токенов

Hermes отправляет дымовой тест аутентификации Graph. Из вашей установки Hermes:

```python
python -c "
import asyncio
from tools.microsoft_graph_auth import MicrosoftGraphTokenProvider
provider = MicrosoftGraphTokenProvider.from_env()
token = asyncio.run(provider.get_access_token())
print('Token acquired, length:', len(token))
print(provider.inspect_token_health())
"
```

При успешном запуске печатается длинная строка токена и словарь работоспособности, показывающий `cached: True` и значение `expires_in_seconds`, близкое к 3600. При сбое возникает `MicrosoftGraphTokenError` с кодом ошибки Azure. Наиболее распространенные из них:

| Ошибка Azure | Значение | Исправить |
|-------------|---------|-----|
| `AADSTS7000215: Invalid client secret` | Секретное значение не соответствует или срок его действия истек. | Создайте новый секрет на шаге 2; обновить `.env`. |
| `AADSTS700016: Application not found` | Неправильный `MSGRAPH_CLIENT_ID` или неправильный арендатор. | Дважды проверьте, что значения из шага 1 взяты из того же приложения. |
| `AADSTS90002: Tenant not found` | Опечатка в `MSGRAPH_TENANT_ID`. | Скопируйте идентификатор каталога (клиента) из обзора приложения еще раз. |
| `insufficient_claims` во время вызова (не во время токена) | Токен приобретается, но Graph возвращает 401/403. | Вы пропустили шаг 3 получения согласия администратора или добавили разрешения, но не дали повторное согласие. Пересмотрите разрешения API и еще раз нажмите **Предоставить согласие администратора**. |

## Ротация секрета клиента

У секретов клиента Azure есть жесткий срок действия. До истечения срока действия вашего:

1. Создайте второй секрет клиента на шаге 2, не удаляя первый.
2. Обновите `MSGRAPH_CLIENT_SECRET` в `~/.hermes/.env`, указав новое значение.
3. Перезапустите шлюз, чтобы получить новый секрет: `hermes gateway restart`.
4. Проверьте дымовой тест, описанный выше.
5. Удалите старый секрет с портала Azure.

## Следующие шаги

Как только учетные данные будут проверены, продолжите:

- **Настройка прослушивателя веб-перехватчиков** — включите платформу шлюза `msgraph_webhook`, которая получает уведомления об изменении графика.
- **Конфигурация конвейера** — настройка среды выполнения конвейера собраний Teams и интерфейса командной строки оператора.
- **Исходящая доставка** – сводные данные пересылаются обратно в канал или чат Teams.

Эти страницы размещаются рядом с PR, которые добавляют соответствующую среду выполнения. Эта настройка учетных данных является отдельным обязательным условием, и ее можно безопасно выполнить заранее.
