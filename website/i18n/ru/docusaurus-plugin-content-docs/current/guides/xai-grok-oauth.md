# xAI Grok OAuth (SuperGrok / X Premium+)

Агент Hermes поддерживает xAI Grok через процесс входа в систему с использованием кода устройства OAuth в браузере для [accounts.x.ai](https://accounts.x.ai), используя либо **подписку SuperGrok** ([grok.com](https://x.ai/grok)) либо **подписку X Premium+** (связанную учетную запись X). Никакого `XAI_API_KEY` не требуется — войдите в систему один раз, и Hermes автоматически обновит ваш сеанс в фоновом режиме.

Когда вы входите в систему с учетной записью X с Премиум+, xAI автоматически связывает статус подписки с вашим сеансом xAI, поэтому поток OAuth работает так же, как и для прямых подписчиков SuperGrok.

Транспорт повторно использует адаптер `codex_responses` (xAI предоставляет конечную точку в стиле Responses), поэтому рассуждения, вызовы инструментов, потоковая передача и кэширование подсказок работают без каких-либо изменений адаптера.

Один и тот же токен носителя OAuth также повторно используется каждой поверхностью прямого доступа к xAI в Hermes — TTS, генерация изображений, генерация видео и транскрипция — поэтому один вход в систему охватывает все четыре.

## Обзор

| Товар | Значение |
|------|-------|
| Идентификатор провайдера | `xai-oauth` |
| Отображаемое имя | xAI Grok OAuth (SuperGrok / X Premium+) |
| Тип аутентификации | Код устройства браузера OAuth 2.0 |
| Транспорт | API ответов xAI (`codex_responses`) |
| Модель по умолчанию | `grok-4.6` |
| Конечная точка | `https://api.x.ai/v1` |
| Сервер аутентификации | `https://accounts.x.ai` |
| Требуется env var | Нет (`XAI_API_KEY` **не** используется для этого провайдера) |
| Подписка | [SuperGrok](https://x.ai/grok) или [X Premium+](https://x.com/i/premium_sign_up) — см. примечание ниже |

## Предварительные условия

- Питон 3.9+
- Установлен агент Гермес
- Активная подписка **SuperGrok** в вашей учетной записи xAI или** подписка **X Premium+** в учетной записи X, с которой вы входите в систему (xAI автоматически связывает подписку).
- Браузер доступен везде, где вы можете открыть распечатанный URL-адрес подтверждения.

::: предупреждение: xAI может ограничить доступ к API OAuth по уровням
Серверная часть xAI применяет собственный список разрешений на поверхности API OAuth и, как было замечено, отклоняет стандартных подписчиков SuperGrok с `HTTP 403` (см. проблему [#26847](https://github.com/NousResearch/hermes-agent/issues/26847)), даже если подписка в приложении активна. Если вход в OAuth в браузере успешен, но вывод возвращает 403, установите `XAI_API_KEY` и переключитесь на путь ключа API (`provider: xai`) — сегодня эта поверхность не подлежит такому же шлюзованию.
:::

## Быстрый старт

```bash
# Launch the provider and model picker
hermes model
# → Select "xAI Grok OAuth (SuperGrok / X Premium+)" from the provider list
# → Hermes opens or prints an accounts.x.ai verification URL
# → Enter the displayed code if prompted, then approve access in the browser
# → Pick a model (grok-4.6 is at the top)
# → Start chatting

hermes
```

После первого входа в систему учетные данные сохраняются в `~/.hermes/auth.json` и автоматически обновляются до истечения срока их действия.

## Вход в систему вручную

Вы можете инициировать вход в систему, не проходя через средство выбора модели:

```bash
hermes auth add xai-oauth
```

### Удаленные/безголовые сеансы

На серверах, контейнерах, консолях только для браузера (Cloud Shell, Codespaces, EC2 Instance Connect) или сеансах SSH, где Hermes не может открыть браузер локально, Hermes печатает URL-адрес проверки xAI и код пользователя. Откройте URL-адрес в любом браузере на своем ноутбуке или в облачной консоли, введите код, если будет предложено, и Hermes будет продолжать опрос, пока xAI не одобрит вход в систему. Никакого SSH-туннеля или локального прослушивателя обратного вызова не требуется.

```bash
hermes auth add xai-oauth --no-browser
# Open the printed verification URL in your browser.
```

Тот же поток кода устройства применяется, когда вы входите в систему с веб-панели или настольного приложения: Hermes показывает URL-адрес проверки и код пользователя, а затем проводит опрос в фоновом режиме, пока вы не одобрите доступ.

## Как работает вход в систему

1. Hermes запрашивает код устройства у `auth.x.ai`.
2. Вы открываете URL-адрес подтверждения, входите в систему, вводите отображаемый код, если будет предложено, и подтверждаете доступ.
3. Hermes опрашивает xAI до получения одобрения, затем сохраняет токены в `~/.hermes/auth.json`.
4. С этого момента Hermes обновляет токен доступа в фоновом режиме — вы остаетесь в системе до тех пор, пока не `hermes auth logout xai-oauth` или не отзовете доступ в настройках своей учетной записи xAI.

## Проверка статуса входа

```bash
hermes doctor
```

В разделе `◆ Auth Providers` будет показано текущее состояние каждого поставщика, включая `xai-oauth`.

## Переключение моделей

```bash
hermes model
# → Select "xAI Grok OAuth (SuperGrok / X Premium+)"
# → Pick from the model list (grok-4.6 is pinned to the top)
```

Или установите модель напрямую:

```bash
hermes config set model.default grok-4.6
hermes config set model.provider xai-oauth
```

## Справочник по конфигурации

После входа в систему `~/.hermes/config.yaml` будет содержать:

```yaml
model:
  default: grok-4.6
  provider: xai-oauth
  base_url: https://api.x.ai/v1
```

### Псевдонимы поставщиков

Все следующее приводит к `xai-oauth`:

```bash
hermes --provider xai-oauth        # canonical
hermes --provider grok-oauth       # alias
hermes --provider x-ai-oauth       # alias
hermes --provider xai-grok-oauth   # alias
```

## Инструменты Direct-to-xAI (TTS/изображение/видео/транскрипция/поиск X)

После входа в систему через OAuth каждый инструмент прямого доступа к xAI автоматически повторно использует один и тот же токен носителя — **отдельной настройки** не требуется, если только вы не предпочитаете использовать ключ API.

Чтобы выбрать серверную часть для каждого инструмента:

```bash
hermes tools
# → Text-to-Speech       → "xAI TTS"
# → Image Generation     → "xAI Grok Imagine (image)"
# → Video Generation     → "xAI Grok Imagine"
# → X (Twitter) Search   → "xAI Grok OAuth (SuperGrok / X Premium+)"
```

Если токены OAuth уже сохранены, сборщик подтверждает это и пропускает запрос учетных данных. Если ни OAuth, ни `XAI_API_KEY` не установлены, средство выбора предлагает меню с тремя вариантами: вход в систему OAuth, вставка ключа API или пропуск.

:::note Генерация видео отключена по умолчанию
По умолчанию набор инструментов `video_gen` отключен. Включите его в `hermes tools` → `🎬 Video Generation` (нажмите пробел), прежде чем агент сможет позвонить `video_generate`. В противном случае агент может вернуться к встроенному навыку ComfyUI, который также помечен для создания видео.
:::

:::note Поиск X автоматически включается при наличии учетных данных xAI.
Набор инструментов `x_search` автоматически включается всякий раз, когда настраиваются учетные данные xAI (токен OAuth SuperGrok / X Premium+ или `XAI_API_KEY`). Отключите явно через `hermes tools` → `🐦 X (Twitter) Search` (нажмите пробел), если вы этого не хотите. Инструмент маршрутизируется через встроенный API ответов `x_search` xAI — он работает с **либо** вашим логином SuperGrok / X Premium+ OAuth, либо с платным `XAI_API_KEY`, и предпочитает OAuth, когда оба настроены (использует вашу квоту подписки вместо расходов на API). Схема инструмента скрыта от модели, если учетные данные xAI не настроены, независимо от того, включен ли набор инструментов.
:::

## Устранение неполадок

### Срок действия токена истек — автоматический повторный вход не выполняется.

Hermes обновляет токен перед каждым сеансом и снова реагирует на ошибку 401. Если обновление завершается с ошибкой `invalid_grant` (токен обновления был отозван или учетная запись была заменена), Hermes вместо сбоя выдает типизированное сообщение повторной аутентификации.

Когда сбой обновления является окончательным (HTTP 4xx, `invalid_grant`, отозван грант и т. д.), Hermes помечает токен обновления как мертвый и помещает его в карантин локально — последующие вызовы пропускают обреченную попытку обновления вместо повторного воспроизведения одной и той же ошибки 401 снова и снова. Агент отображает одно сообщение «требуется повторная аутентификация» и не вмешивается, пока вы снова не войдете в систему.

**Исправление:** снова запустите `hermes auth add xai-oauth`, чтобы начать новый вход в систему. Карантин снимается при следующем успешном обмене.

### Время авторизации истекло

Утверждение кода устройства имеет ограниченный срок действия (xAI устанавливает `expires_in` в ответе кода устройства, обычно порядка десятков минут). Если вы не подтвердите вход вовремя, Hermes выдаст ошибку тайм-аута.

**Исправление:** повторно запустите `hermes auth add xai-oauth` (или `hermes model`). Поток начинается заново.

### Вход с удаленного сервера

В сеансах SSH или контейнере Hermes печатает URL-адрес проверки и код пользователя вместо открытия браузера. Откройте этот URL-адрес в браузере на своем ноутбуке или в облачной консоли — для xAI Grok OAuth переадресация порта SSH не требуется.

```bash
hermes auth add xai-oauth --no-browser
```

Информацию о поставщиках перенаправления обратной связи (Spotify, серверы MCP) см. в разделе [OAuth через SSH/удаленные хосты](./oauth-over-ssh.md).

### HTTP 403 после успешного входа в систему (уровень/права)

OAuth завершен в браузере, токены сохраняются, но вывод или обновление токена возвращает `HTTP 403` с сообщением, похожим на *"Вызывающий объект не имеет разрешения на выполнение указанной операции"*.

Это **не** проблема устаревших токенов — повторный запуск `hermes model` не изменит ситуацию. Было замечено, что серверная часть xAI ограничивает доступ к API OAuth определенным уровням SuperGrok, несмотря на активную подписку в приложении (проблема [#26847](https://github.com/NousResearch/hermes-agent/issues/26847)).

**Исправление:** установите `XAI_API_KEY` и переключитесь на путь API-ключа:

```bash
export XAI_API_KEY=xai-...
hermes config set model.provider xai
```

Или обновите подписку на странице [x.ai/grok](https://x.ai/grok), если требуется маршрут OAuth.

### Ошибка «Учетные данные xAI не найдены» во время выполнения

В хранилище аутентификации нет записи `xai-oauth` и не установлено `XAI_API_KEY`. Вы еще не вошли в систему, или файл учетных данных был удален.

**Исправление**: запустите `hermes model` и выберите поставщика OAuth xAI Grok или запустите `hermes auth add xai-oauth`.

## Выход из системы

Чтобы удалить все сохраненные учетные данные OAuth xAI Grok:

```bash
hermes auth logout xai-oauth
```

При этом очищается как одноэлементная запись OAuth в `auth.json`, так и все строки пула учетных данных для `xai-oauth`. Используйте `hermes auth remove xai-oauth <index|id|label>`, если вы хотите удалить только одну запись пула (запустите `hermes auth list xai-oauth`, чтобы увидеть их).
