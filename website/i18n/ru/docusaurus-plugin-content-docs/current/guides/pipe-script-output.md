# Вывод сценария на платформы обмена сообщениями

`hermes send` — это небольшой интерфейс командной строки с поддержкой сценариев, который отправляет сообщение любому
Платформа обмена сообщениями Hermes уже настроена. Думайте об этом как о
кроссплатформенный `curl` для уведомлений — вам не нужен работающий
шлюз, вам не нужен LLM и не нужно повторно вставлять токены ботов
в каждый из ваших сценариев.

Используйте его для:

- Мониторинг системы (память, диск, температура графического процессора, завершение длительного задания)
- Уведомления CI/CD (развертывание выполнено, сбой теста)
- Скрипты Cron, которые должны отправить вам результаты.
- Быстрые одноразовые сообщения с терминала
- Передача вывода любого инструмента куда угодно (`make | hermes send --to slack:#builds`)

Команда повторно использует те же учетные данные и адаптеры платформы, что и `hermes
шлюз` уже используется, поэтому второй поверхности конфигурации нет.
поддерживать.

---

## Быстрый старт

```bash
# Plain text to the home channel for a platform
hermes send --to telegram "deploy finished"

# Pipe in stdout from anything
echo "RAM 92%" | hermes send --to telegram:-1001234567890

# Send a file
hermes send --to discord:#ops --file /tmp/report.md

# Attach a subject/header line
hermes send --to slack:#eng --subject "[CI] build.log" --file build.log

# Thread target (Telegram topic, Discord thread)
hermes send --to telegram:-1001234567890:17585 "threaded reply"

# List every configured target
hermes send --list

# Filter by platform
hermes send --list telegram
```

## Справочник по аргументам

| Флаг | Описание |
|------|-------------|
| `-t, --to TARGET` | Место назначения. См. [целевые форматы](#target-formats). |
| `message` (позиционный) | Текст сообщения. Опустите чтение из `--file` или стандартного ввода. |
| `-f, --file PATH` | Прочитайте тело из файла. `--file -` вызывает стандартный ввод. |
| `-s, --subject LINE` | Добавьте строку заголовка/темы перед телом. |
| `-l, --list` | Список доступных целей. Дополнительный фильтр позиционной платформы. |
| `-q, --quiet` | Нет стандартного вывода в случае успеха (только код выхода — идеально для скриптов). |
| `--json` | Выдать необработанный результат отправки в формате JSON. |
| `-h, --help` | Показать встроенный текст справки. |

### Целевые форматы

| Формат | Пример | Значение |
|--------|---------|---------|
| `platform` | `telegram` | Отправить на настроенный домашний канал платформы |
| `platform:chat_id` | `telegram:-1001234567890` | Конкретный цифровой чат/группа/пользователь |
| `platform:chat_id:thread_id` | `telegram:-1001234567890:17585` | Конкретная тема или тема форума Telegram |
| `platform:#channel` | `discord:#ops` | Удобное для пользователя имя канала (сопоставляется с каталогом каналов) |
| `platform:+E164` | `signal:+15551234567` | Платформы с телефонной адресацией: Signal, SMS, WhatsApp |

Любая платформа Гермес поставляет адаптеры для работы в качестве мишени:
`telegram`, `discord`, `slack`, `signal`, `sms`, `whatsapp`, `matrix`,
`mattermost`, `feishu`, `dingtalk`, `wecom`, `weixin`, `email` и
другие.

### Коды выхода

| Код | Значение |
|------|---------|
| `0` | Отправить (или перечислить) удалось |
| `1` | Доставка не удалась на уровне платформы (аутентификация, разрешения, сеть) |
| `2` | Ошибка использования/аргумента/конфигурации |

Коды выхода соответствуют стандартному соглашению Unix, поэтому ваши сценарии могут
разветвляйтесь на них так же, как на `curl` или `grep`.

## Разрешение тела сообщения

`hermes send` разрешает тело сообщения в следующем порядке:

1. **Позиционный аргумент** — `hermes send --to telegram "hi"`
2. **`--file PATH`** — `hermes send --to telegram --file msg.txt`
3. **Конвейерный стандартный ввод** — `echo hi | hermes send --to telegram`

Когда stdin является TTY (без канала), Hermes **не** ждет ввода — вы будете
вместо этого получите явную ошибку использования. Это предотвращает зависание сценариев, если они
случайно опустить тело.

## Примеры из реальной жизни

### Мониторинг: оповещения о памяти/диске

Замените специальные вызовы `curl https://api.telegram.org/...` в своих сторожевых таймерах.
с одной переносной линией:

```bash
#!/usr/bin/env bash
ram_pct=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
if [ "$ram_pct" -ge 85 ]; then
  hermes send --to telegram --subject "⚠ MEMORY WARNING" \
    "RAM ${ram_pct}% on $(hostname)"
fi
```

Поскольку `hermes send` повторно использует вашу конфигурацию Hermes, тот же сценарий работает и на
любой хост, где установлен Hermes — не нужно экспортировать токены бота в
среду каждой машины вручную.

:::tip Не оповещать шлюз о себе
Для сторожевых таймеров, которые могут срабатывать, когда сам шлюз испытывает проблемы (OOM
оповещения, оповещения о переполнении диска), продолжайте использовать минимальный вызов `curl` вместо
`hermes send`. Если интерпретатор Python не может загрузиться из-за того, что окно
терзаясь, вы все равно хотите, чтобы это предупреждение погасло.
:::

### CI/CD: результаты сборки и тестирования

```bash
# In .github/workflows/deploy.yml or any CI script
if ./scripts/deploy.sh; then
  hermes send --to slack:#deploys "✅ ${CI_COMMIT_SHA:0:7} deployed"
else
  tail -n 100 deploy.log | hermes send \
    --to slack:#deploys --subject "❌ deploy failed"
  exit 1
fi
```

### Cron: ежедневный отчет

```bash
# Crontab entry
0 9 * * * /usr/local/bin/generate-metrics.sh \
  | /home/me/.hermes/bin/hermes send \
      --to telegram --subject "Daily metrics $(date +%Y-%m-%d)"
```

### Длительные задачи: проверка связи по завершении

```bash
./train.py --epochs 200 && \
  hermes send --to telegram "training done" || \
  hermes send --to telegram "training failed (exit $?)"
```

### Создание сценариев с помощью `--json` и `--quiet`

```bash
# Hard-fail a script if delivery fails; don't clutter logs on success
hermes send --to telegram --quiet "keepalive" || {
  echo "Telegram delivery failed" >&2
  exit 1
}

# Capture the message ID for later editing / threading
msg_id=$(hermes send --to discord:#ops --json "build started" \
  | jq -r .message_id)
```

## Нужен ли `hermes send` работающий шлюз?

**Обычно нет.** Для любой платформы бот-токенов — Telegram, Discord, Slack,
Signal, SMS, WhatsApp Cloud API и большинство других — вызовы `hermes send`
конечную точку REST платформы напрямую, используя учетные данные из
`~/.hermes/.env` и `~/.hermes/config.yaml`. Это отдельный подпроцесс
который завершается, как только сообщение будет доставлено.

Активный шлюз требуется только для **платформ плагинов**, которые полагаются на
постоянное подключение адаптера (например, специальный плагин, который сохраняет
долгоживущий WebSocket открыт). В этом случае вы получите явную ошибку
указывая на ворота; начните с `hermes gateway start` и повторите попытку.

## Перечисление и обнаружение целей

Прежде чем отправлять на конкретный канал, вы можете проверить, что доступно:

```bash
# Every target across every configured platform
hermes send --list

# Just Telegram targets
hermes send --list telegram

# Machine-readable
hermes send --list --json
```

Листинг построен на основе `~/.hermes/channel_directory.json`, который
шлюз обновляется каждые несколько минут во время работы. Если ты видишь
«Каналы еще не обнаружены», запустите шлюз один раз (`hermesшлюз
start`), чтобы он мог заполнить кеш.

Разрешены понятные человеку имена (`discord:#ops`, `slack:#engineering`).
против этого кэша во время отправки, поэтому вам не нужно запоминать числовые значения.
идентификаторы.

## Сравнение с другими подходами

| Подход | Мультиплатформенность | Повторно использует кредиты Гермеса | Нужен шлюз | Лучшее для |
|----------|----------------|---------------------|---------------|----------|
| `hermes send` | ✅ | ✅ | Нет (бот-токен) | Все ниже |
| Необработанный `curl` для каждой платформы | Каждый скрипт написан отдельно | Руководство | Нет | Критические наблюдатели |
| `cron` работа с `--deliver` | ✅ | ✅ | Нет | Запланированные задачи агента |

`hermes send` намеренно является самой простой поверхностью. Если вам нужно
агент решает, что сказать, запланировать задание cron — последнее задание агента
ответ автоматически доставляется настроенному целевому объекту `deliver:` (агент
больше не отправляет сообщения самостоятельно). Если вам нужен запланированный запуск контента, созданного LLM,
используйте `cronjob(action='create', prompt=...)` с `deliver='telegram:...'`.
Если вам просто нужно передать необработанную строку, используйте `hermes send`.
