# Управление облаком Hermes с помощью MCP

[Hermes Cloud](https://portal.nousresearch.com/cloud) запускает для вас размещенные экземпляры агента Hermes. Обычно вы управляете ими со страницы `/agents` в [Nous Portal](/integrations/nous-portal). Это руководство подключает ваш **локальный** агент Hermes к серверу MCP портала, так что вы можете управлять этими облачными экземплярами, просто спрашивая — «составьте список моих облачных агентов», «перезапустите остановленный», «чего мне это будет стоить» — не выходя из терминала.

Это стандартный сервер [MCP](/user-guide/features/mcp), размещенный на Nous Research и защищенный тем же логином OAuth, который вы уже используете для портала. После подключения Hermes получает два инструмента, которые он может вызывать от вашего имени.

## Что с этим можно сделать

После подключения модель сможет вызывать их в вашей организации Hermes Cloud:

| Попросите… | Под капотом |
|----------|----------------|
| «Составить список моих облачных агентов» | `agents` (список) |
| «Каков статус `<name>`?» | `agents` (получить/статус) |
| «Сколько примерно стоит этот экземпляр?» | `agents` (оценка_стоимости) |
| «Запуск/останов/перезапуск `<name>`» | `agent` (старт/стоп/перезапуск) |
| «Разверните новый экземпляр под названием `<name>`» | `agent` (создать) |
| «Уничтожить `<name>`» | `agent` (уничтожить) |
| «Обновите окружение/изображение на `<name>`» | `agent` (update_env/update_image) |

Каждый вызов выполняется в отношении **вашей** организации с вашим идентификатором Портала, и членство перепроверяется при каждом вызове — соединение может касаться только тех экземпляров, которыми вы уже управляете через веб-интерфейс.

## Предварительные условия

- Учетная запись [Nous Portal](/integrations/nous-portal) с доступом к [Hermes Cloud](https://portal.nousresearch.com/cloud) (хотя бы один экземпляр или возможность его создать).
- Установлена ​​поддержка MCP. Если вы использовали стандартный сценарий установки, он уже существует; иначе:

  ```bash
  cd ~/.hermes/hermes-agent
  uv pip install -e ".[mcp]"
  ```

Вам **не** не нужен отдельный ключ API или секрет клиента — сервер использует OAuth с PKCE, а вход в систему осуществляется через браузер.

## Шаг 1: добавьте сервер

```bash
hermes mcp add --url https://portal.nousresearch.com/mcp --auth oauth hermes-cloud
```

`--auth oauth` сообщает Hermes, что это HTTP-сервер, защищенный OAuth. При первом подключении Гермеса:

1. Автоматически обнаруживает конечные точки OAuth сервера (метаданные RFC 9728/8414).
2. Регистрирует себя в качестве клиента (динамическая регистрация клиента RFC 7591). Копирование не является секретом.
3. Открывает ваш браузер на Портале для входа и авторизации.
4. Сохраняет полученный токен в `~/.hermes/mcp-tokens/` и повторно использует его (обновление происходит автоматически).

### Выбор организации

Если ваша учетная запись на Портале принадлежит **более чем одной организации**, во время авторизации в браузере отображается **выбор организации** — выберите, какой организацией должно управлять это соединение. Выбор делается один раз, в браузере; в командной строке передавать нечего. Учетные записи одной организации пропускают этот шаг и привязываются автоматически.

Если вам когда-нибудь понадобится указать соединение с другой организацией, удалите и заново добавьте сервер (`hermes mcp remove hermes-cloud`, затем еще раз команду `add`) и выберите другую организацию в браузере.

## Шаг 2: проверьте подключение

```bash
hermes mcp test hermes-cloud
```

Затем запустите (или перезагрузите) сеанс:

```bash
hermes chat
```

```text
/reload-mcp
```

Задайте вопрос, доступный только для чтения, чтобы подтвердить, что инструменты работают:

```text
List my Hermes Cloud agents and their current status.
```

Вы должны получить обратно те же экземпляры, которые вы видите на странице `/agents` Портала.

## Шаг 3: используйте это

Вопросы только для чтения всегда безопасны:

```text
Which of my cloud agents is currently running, and roughly what is each one costing?
```

Действия жизненного цикла сопоставляются с простыми запросами:

```text
Restart the instance called research-bot.
```

```text
Create a new Hermes Cloud instance named scratch, then tell me when it's ready.
```

Hermes сообщает, что вернул каждый инструмент — список экземпляров, новый статус, сведения о созданном экземпляре — чтобы вы могли подтвердить выполнение действия.

## Конфигурация

После `hermes mcp add` сервер находится в `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  hermes-cloud:
    url: "https://portal.nousresearch.com/mcp"
    auth: oauth
```

Никакие учетные данные не передаются в `config.yaml` — токен OAuth хранится отдельно в `~/.hermes/mcp-tokens/`, точно так же, как токен обновления портала не входит в вашу конфигурацию.

### Ограничение поверхности инструмента

Сервер предоставляет инструменты чтения (`agents`) и изменения (`agent`). Если вы хотите, чтобы соединение было **только для чтения** — просматривайте и проверяйте, но никогда не запускайте/останавливайте/создавайте/уничтожайте – ограничьте его инструментом `agents`:

```yaml
mcp_servers:
  hermes-cloud:
    url: "https://portal.nousresearch.com/mcp"
    auth: oauth
    tools:
      include: [agents]
```

Запустите `/reload-mcp` после изменения конфигурации. См. [Использование MCP с Hermes](/guides/use-mcp-with-hermes) для получения полной модели фильтрации (`include`/`exclude`, `prompts`, `resources`).

## Устранение неполадок

### В браузере отображается средство выбора организации, и я не уверен, какую выбрать.

Вы принадлежите к нескольким организациям Портала. Выберите организацию, экземплярами Hermes Cloud которой вы хотите управлять через это соединение. Если вы не уверены, это организация, которой принадлежат экземпляры, которые вы видите на странице портала `/agents`. Вы можете повторно выбрать позже, удалив и повторно добавив сервер.

### «invalid_client» или «неизвестный клиент» при подключении

Сохраненная регистрация клиента больше не соответствует серверу (например, вы ранее подключались к другой среде). Очистите кэшированное состояние OAuth этого сервера и добавьте его заново:

```bash
hermes mcp remove hermes-cloud
rm -f ~/.hermes/mcp-tokens/hermes-cloud.*
hermes mcp add --url https://portal.nousresearch.com/mcp --auth oauth hermes-cloud
```

### Инструменты не отображаются после добавления сервера

Перезагрузите MCP внутри сеанса и еще раз проверьте:

```text
/reload-mcp
```

```text
Tell me which MCP-backed tools are available right now.
```

Если они по-прежнему отсутствуют, запустите `hermes mcp test hermes-cloud`, чтобы напрямую увидеть ошибку подключения.

### Он просит меня снова войти в систему

Токены OAuth обновляются автоматически, но если Портал аннулирует ваш сеанс (смена пароля, отзыв, истечение срока действия), следующий вызов попросит вас повторно авторизоваться. Повторно запустите команду `hermes mcp add` — поток браузера повторно создаст токен.

### Безголовый / SSH / удаленный хост

Обратный вызов браузера OAuth выполняется на компьютере, на котором работает Hermes. На удаленном хосте перенаправьте порт обратной связи через SSH — по той же схеме, что и для любого другого входа в систему OAuth. См. [OAuth через SSH/удаленные хосты](/guides/oauth-over-ssh).
