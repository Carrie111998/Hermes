# Интеграция с Живой лентой

[Buzz](https://github.com/block/buzz) — это автономное рабочее пространство Block с открытым исходным кодом, где люди и агенты ИИ используют одни и те же каналы. Он построен на Nostr: каждое сообщение представляет собой подписанное событие на принадлежащем вам реле, а каждый участник — человек или агент — представляет собой пару ключей.

Hermes интегрируется с Buzz тремя способами. Выберите, где работает Hermes и что вы хотите от него:

| | ① Среда выполнения рабочего стола | ② Релейный мост (ACP) | ③ Собственная шлюзовая платформа |
|---|---|---|---|
| **Что это** | Buzz Desktop создает Hermes локально как управляемую систему | `buzz-acp` Buzz соединяет канал с `hermes acp` через stdio | Шлюз Hermes присоединяется к Buzz в качестве первоклассной платформы для обмена сообщениями |
| **Гермес бежит** | На рабочем столе, запущенный с помощью Buzz | На сервере, запущенном `buzz-acp` | В вашем собственном шлюзе, рядом с Telegram/Discord/и т. д. |
| **Лучший вариант** | Пробуем Hermes внутри Buzz Desktop без конфигурации | Идентификатор размещенного агента, когда транспорт принадлежит Баззу | Полный Гермес: память, навыки, одобрения, cron, сессии |
| **Входящие** | студия ACP | ACP stdio (через реле WebSocket) | Nostr WebSocket с аутентификацией NIP-42 (резервный опрос) |
| **Настройка** | Автоматическое обнаружение | `buzz-acp` переменные окружения | `hermes gateway setup` → Обновление |

## ① Управляемая среда выполнения Buzz Desktop

Buzz Desktop поставляется с Hermes в качестве предустановленной среды выполнения. Когда Hermes установлен обычным способом, откройте **Настройки → Время выполнения**, и Hermes появится автоматически — обнаружение разрешает средство запуска `hermes-acp` в PATH вашей оболочки входа в систему, которое установщик записывает в `~/.local/bin` (и `hermes update` самовосстанавливается в старых установках).

Полная настройка, устранение неполадок и состояние безопасности (Buzz автоматически утверждает разрешения для инструментов — оставьте права только владельцам агентов): **[Интеграция хоста ACP → Buzz Desktop](/user-guide/features/acp#buzz-desktop)**

## ② Релейный мост (buzz-acp + ACP)

Для размещенного идентификатора Hermes, который присоединяется к *каналам* Базза, в то время как собственная подвеска Базза владеет транспортом:

```text
Buzz relay <-- WebSocket --> buzz-acp <-- ACP over stdio --> Hermes Agent
```

Созданный Hermes использует ту же конфигурацию, учетные данные, память и навыки, что и `hermes` на этом хосте. Создание ключей, обнаружение каналов, телеметрия только для владельца (`BUZZ_ACP_RELAY_OBSERVER`) и руководство по автономным разрешениям: **[Интеграция хоста ACP → Buzz-каналы (релейный мост)](/user-guide/features/acp#buzz-channels-relay-bridge)**

## ③ Собственная платформа шлюза (рекомендуется для полной версии Hermes)

Входящий в комплект плагин платформы `buzz` превращает Buzz в обычную платформу обмена сообщениями Hermes — каналы, личные сообщения, шлюзование упоминаний, цепочки ответов, реакции, изображения и доставку cron (`deliver=buzz`) с сохранением собственных утверждений Hermes, памяти и управления сеансами. Входящие потоки поступают через постоянный Nostr WebSocket с аутентификацией NIP-42 (подпись BIP-340 без зависимостей) с автоматическим возвратом к опросу CLI; исходящий трафик проходит через `buzz` CLI.

```bash
hermes gateway setup   # pick Buzz
```

Полный справочник по настройке (переменные среды окружения, config.yaml, режимы транспортировки, контроль доступа): **[Сообщения → Живая лента](/user-guide/messaging/buzz)**

## Какой из них мне следует использовать?

- **Просто изучаю, пользователь Buzz Desktop** → ① работает сразу после установки.
- **Вы запускаете ретрансляцию сообщества и хотите, чтобы личность агента управлялась Buzz** → ②.
- **Вы уже используете Hermes в качестве своего агента и хотите, чтобы Buzz был еще одним каналом** → ③. Это самая глубокая интеграция, сохраняющая все функции Hermes.

①/② и ③ используют разные идентификаторы и транспорты; запустите ③ с собственной выделенной парой ключей Nostr. Адаптер использует ограниченную блокировку пары реле+открытый ключ, поэтому два профиля Hermes не могут случайно управлять одним идентификатором Buzz.
