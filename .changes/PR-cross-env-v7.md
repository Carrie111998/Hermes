# fix(desktop): pin cross-env to ^7.0.3 so npm scripts work on POSIX shells

## What does this PR do?

Pins `cross-env` in `apps/desktop/package.json` to `^7.0.3` (last CJS release) instead
of the current `^10.1.0` (pure ESM). This restores compatibility with how npm invokes
scripts on POSIX shells (`/bin/sh`), which silently hangs `npm run pack` /
`npm run builder` on macOS/Linux because the ESM `.js` entry is not executable
as a shell script and `sh` chokes on the `import` syntax instead of failing fast.

`cross-env@7` is the maintainer-recommended fallback for non-Node invocations —
see the upstream README:

> NOTE : Version 8 of cross-env only supports Node.js 20 and higher, to use it
> on Node.js 18 or lower install version 7 `npm install --save-dev cross-env@7`

The maintainer has also marked `cross-env` as "done" — there will be no v11 fix
for this. v7 is the supported escape hatch for POSIX shell script usage.

## Reproduction (before fix)

```sh
$ cd apps/desktop
$ npm run pack -- --dir
...
> hermes@0.17.0 builder
> cross-env NODE_OPTIONS=--max-old-space-size=16384 node scripts/run-electron-builder.mjs --dir

sh: line 1: import: command not found
sh: line 1: syntax error near unexpected token `process.argv.slice'
```

The error message in `update.log` reports `Permission denied` (npm wraps the
shell error) and the npm script hangs without exiting, which is what users
experience as "the update is stuck on the desktop build step." Killing the
process leaves `node_modules/electron/dist` half-installed and the v0.17
`/Applications/Hermes.app` binary out of sync with the v0.19 backend, which
then surfaces as a separate "desktop can't start" symptom.

## After fix

```sh
$ npm run pack -- --dir
...
> hermes@0.17.0 builder
> cross-env NODE_OPTIONS=--max-old-space-size=16384 node scripts/run-electron-builder.mjs --dir

[run-electron-builder] no local electron dist; electron-builder will fetch via @electron/get (electronVersion + ELECTRON_MIRROR).
  • packaging       platform=darwin arch=arm64 electron=40.10.2 appOutDir=release/mac-arm64
  • downloaded      label=electron progress=100%
✓ built in 339ms
```

Verified on macOS 15.5 (arm64), Node v22.22.3, npm 10.9.8, electron-builder 26.15.3.

## Why pin to v7 instead of rewriting the scripts?

Considered alternatives and why I rejected them:

1. **Switch `cross-env …` invocations to `node --eval "process.env.X='Y'" …`**
   — Works but adds quoting headaches for values with spaces, plus four scripts
   in `package.json` would each need a careful rewrite. The 5-year-stable v7
   API is less risky.
2. **Upgrade to `cross-env@^11.x`** — doesn't exist. Maintainer has marked the
   project done (https://github.com/kentcdodds/cross-env/issues/257).
3. **Add `"script-shell": "bash"` to `.npmrc`** — works on local dev boxes but
   requires every contributor and every CI runner to have the same setting;
   fragile and easy to regress.
4. **Pin to v8** — same ESM problem; v8+ is what broke us.

`cross-env@^7.0.3` is the smallest, safest, most reviewable change. The
`cross-env` v7 README explicitly preserves the exact same command-line
interface, so no script rewrites are needed.

## Related Issue

Reported by users on macOS during `hermes update` (the desktop build step
silently hangs for 30+ minutes, then is killed). Tracked downstream as the
"NPM script stuck on cross-env / desktop rebuild hangs" symptom class.

## Changes Made

- `apps/desktop/package.json` — `"cross-env": "^10.1.0"` → `"^7.0.3"`
- `package-lock.json` — regenerated by `npm install` to match the new
  resolved version (8 packages removed/added transitively, no other
  resolution changes)

No script changes, no API changes, no behaviour change on Windows or any
platform where `npm run` already works today.

## How to Test

1. `cd apps/desktop && rm -rf node_modules/cross-env`
2. `npm install`
3. `npm run pack -- --dir` (or `npm run builder -- --help` for a fast
   smoke test that doesn't pull electron)
4. Observe that the `builder` step exits cleanly and does not hang on
   the cross-env invocation.

Cross-platform check: `cross-env@7` advertises support for npm ≥6,
yarn ≥1, node ≥10.14 — we run on node v22 in CI so this is well
within range.
