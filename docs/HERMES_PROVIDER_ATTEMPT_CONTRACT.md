# Hermes provider-attempt provenance contract

This fork adds a narrow producer-side contract for the model execution that
can lead to a discretionary `decision-submit` tool call.

## Producer boundary

The Hermes conversation/provider retry loop issues one immutable
`ProviderAttemptProvenance` record before each outer-loop provider dispatch.
The record contains:

- Hermes-owned `runtime_instance_id`, `session_id`, `task_id`, and `turn_id`
- logical `api_request_id`
- generated `provider_attempt_id` and per-request `attempt_index`
- retry snapshot
- actual provider and request model for that attempt
- producer-owned fallback state and generation/reason
- response model, outcome, and timestamps after completion

`provider_attempt_id` is generated by Hermes and is never accepted as an
argument from tool arguments, plugin kwargs, environment, files, sockets, PID,
or process ancestry. A retry or provider/model switch creates a new record.

The successful assistant response retains the immutable record internally.
Tool dispatch receives that exact record through the core dispatch context, and
the `tool_call_id` is bound to it before the observer event is emitted. An
unrelated later attempt cannot replace the response-bound record.

## Observer boundary

`pre_api_request`, `post_api_request`, and `post_tool_call` receive only
**detached dictionaries** (`*_observer` / `tool_call_provenance`). They are
observability projections. Plugin callback execution is not an authorization
boundary and must not be treated as attestation.

## Explicit non-goals

This patch does not create a Unix-socket, UID/PID, environment, pending-file,
first-observation, token-matching, or process-ancestry trust mechanism. It also
does not infer `fallback_used` from requested or observed provider/model names.

The frozen in-process record provides integrity against accidental mutation,
not cryptographic authenticity against arbitrary same-process Python code. If
the consumer is outside Hermes or is controlled by Violet, Hermes still needs
a lifecycle-bound authenticated handoff (or a signing key inaccessible to the
consumer). Until that boundary exists, Violet must reject these observer
projections and fail closed.

The local Relay callback is one dispatch callback in the inspected source.
Whether a separately deployed Relay implementation can perform additional
provider retries outside this Hermes loop is not established by this patch;
such retries must receive their own native attempt identity rather than reuse
this record.
