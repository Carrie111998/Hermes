Hermes Supercomputer

开源架构选型总览

这套文档把现有多租户隔离 spec 拆成 16 个可落地架构模块。每个模块都有主选开源方案、候选对比、为什么是它、落地设计、实施规划和验收标准。

模块数：16资料核对：2026-05-29范围：云端多租户 supercomputer
总原则
优先选择能形成明确隔离边界、可被审计、能和 Kubernetes/TokenRouter/OPA/Temporal 串起来的开源组件。Agent sandbox、provider key、tenant data、GPU worker 和 protected skill internals 必须各有独立边界。

模块入口

Edge Gateway / Realtime Ingress

推荐：Envoy Gateway + Envoy Proxy

统一承接浏览器 SSE/WebSocket/HTTP 请求，完成 TLS、JWT 校验、限流、外部授权、带宽限制、路由和会话流转发。

Identity / Tenant Access

推荐：Keycloak

负责 OIDC/OAuth2 登录、企业 IdP federation、客户端注册、用户身份令牌和可审计的身份生命周期。

Policy Engine / Authorization

推荐：Open Policy Agent (OPA)

作为统一 PDP，给 Edge、TokenRouter、Volume Mounter、egress proxy、K8s admission 和 Skill exfil filter 返回默认拒绝的策略判断。

Sandbox Runtime / Isolation

推荐：Kata Containers with Cloud Hypervisor profile

为不可信 terminal/tool execution 提供 microVM 级隔离，同时保留 Kubernetes 调度、镜像和 RuntimeClass 生态。

Workspace Volume Mounter / POSIX Data Isolation

推荐：JuiceFS CSI backed by object storage

把 tenant/workspace/project/session 的文件、memory、outputs 以 POSIX 文件系统形式挂进 sandbox，同时让底层容量和生命周期走对象存储。

TokenRouter / Secrets Boundary

推荐：Custom TokenRouter backed by OpenBao

TokenRouter 是业务边界；OpenBao 是密钥、动态凭证、transit crypto 和审计后端。Sandbox 永远拿不到真实 provider key。

Session / Job Orchestration

推荐：Temporal

承接 session lifecycle、sandbox attach、media job group、retry、timeout、compensation、human approval 和长任务状态恢复。

Event Bus / Realtime Fanout

推荐：NATS JetStream

处理 session 事件、tool progress、job status、worker heartbeat、轻量控制消息和可回放的事件流。

GPU Render Scheduling / Supercomputer Fabric

推荐：Kueue + NVIDIA GPU Operator

Kueue 做批量 AI/ML/GPU job admission、quota、borrowing/preemption；GPU Operator 管理 NVIDIA driver、device plugin、runtime 和监控组件。

Skill Workflow Runtime / Registry

推荐：LangGraph OSS library + custom Skill Registry

把 Skill 建模为路由、输入门、状态图、阶段执行、QA gate、失败恢复和可保护的内部资产，而不是 prompt 文本。

Guardrails / Exfiltration Defense

推荐：NVIDIA NeMo Guardrails + OPA + custom egress filters

对输入、输出、工具调用和外发通道做可编程 guardrails；OPA 做确定性 allow/deny；自研 egress filter 覆盖 chat/write_file/upload/terminal/archive。

Relational Data / Tenant Row Isolation

推荐：PostgreSQL with Row Level Security

保存 tenants、workspaces、projects、sessions、runs、tool_calls、jobs、assets、usage_events、audit_events 等强一致业务数据。

Object / Media Storage

推荐：Rook-Ceph RGW for production; MinIO only for dev/small private deployments

保存 uploads、generated media、job outputs、thumbnails、manifests、asset lineage 和长期归档。

Observability / Audit

推荐：OpenTelemetry + Grafana LGTM stack

统一采集 traces、metrics、logs、events，把 run_id/tool_call_id/job_id/tenant_id 串起来；审计日志另做 append-only 存储。

Service Mesh / Internal mTLS / Egress

推荐：Istio

在内部服务之间提供 mTLS、服务身份、授权策略和受控 egress gateway，支撑 TokenRouter/Job Manager/worker 的零信任通信。

Cloud Deployment / GitOps / Secrets Delivery

推荐：Argo CD + External Secrets Operator

把 Kubernetes desired state、策略 bundle、服务发布和 OpenBao/外部 secrets 到 K8s 的投递纳入可审计 GitOps 流程。

关键取舍

  • Sandbox 隔离选择 microVM 路线，普通 Docker 只可用于低风险内部服务，不能承载任意租户代码。
  • TokenRouter 必须自研，因为它是业务策略和 provider key 边界；OpenBao 只作为 secrets/crypto/audit 基座。
  • Temporal 和 NATS 分工：Temporal 负责真实长任务状态，NATS 负责实时事件和短期回放。
  • OPA 是统一策略决策点，NeMo Guardrails 只负责 LLM 应用层 rails，不能替代确定性的工具/egress 策略。
  • Rook-Ceph 是生产自托管存储主选；MinIO 保留为开发和小规模部署选项。
