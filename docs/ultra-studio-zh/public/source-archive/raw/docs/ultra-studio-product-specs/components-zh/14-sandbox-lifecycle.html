14 沙箱生命周期

管理每个任务的执行环境：创建、挂载文件、运行工具、暂停、唤醒、销毁。Atlas-only P0 可以先弱化，但不能把它当已经完整。

部分实现 Sandbox Lifecycle 阅读版 HTML
状态说明：部分实现：有真实底座，但产品合同还没完整接上。 本页是中文阅读版，英文 Markdown 仍是更细的审计原文。

已有实现证据

  • 已有 local/docker/modal/daytona/singularity/ssh 等 environment 后端。
  • 已有 terminal/session 相关抽象。
  • 代码证据：tools/environments/*、agent/runtime 相关模块。

主要缺口

  • 没有产品级 sandbox.create/attach/sleep/wake/destroy lifecycle。
  • session 与 sandbox id、task files、browser context 没有统一绑定。
  • 没有云模式隔离和 TokenRouter delegated token 注入。

P0 要做

  • 如果当前 MVP 只走 Atlas API，要明确标记 sandbox 不参与媒体生成。
  • 需要本地文件工具时，记录 cwd、session_id、文件访问边界。
  • 禁止把 API key 直接写进 sandbox 可读文件。

P1 / P2 后续

  • Cloud sandbox、sleep/wake、browser session、task filesystem、quota。
  • 和 TokenRouter、CometAPI、Files 页面集成。

验收点

  • 用户能知道当前任务是否用了 sandbox。
  • sandbox 错误不会被包装成普通生成失败。
  • 关闭任务后临时文件清理策略明确。
