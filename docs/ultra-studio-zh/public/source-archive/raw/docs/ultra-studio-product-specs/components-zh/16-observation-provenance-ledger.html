16 观察与溯源账本

记录每次生成、工具调用、观察结果、资产来源、QA 证据和决策链。它用来防止 agent 空口声称完成。

仅设计 Observation / Provenance Ledger 阅读版 HTML
状态说明：仅设计：文档已定义，代码里还没有可用实现。 本页是中文阅读版，英文 Markdown 仍是更细的审计原文。

已有实现证据

  • 已有部分 logs、insights、tool call records，但不是统一 ledger。
  • docs 要求 artifact/provenance ledgers。
  • 邻近实现分散在工具日志、session store、Atlas provider 返回。

主要缺口

  • 没有统一 observation/provenance 数据模型。
  • 没有 job_id -> asset_id -> prompt -> input_refs -> provider response 的完整链。
  • 没有 QA evidence 与最终结果绑定。

P0 要做

  • 先在 media_jobs 和 media_assets 上写足 provenance 字段。
  • 每个完成声明必须能指向 asset 或 observation。
  • 失败也要记录 provider error 和请求摘要。

P1 / P2 后续

  • 统一 ledger API、可视化时间线、导出、diff、审计模式。
  • 跨任务资产 lineage 图。

验收点

  • 用户问“这个视频怎么来的”，能查到输入、模型、prompt、时间和输出。
  • agent 不能只说完成但没有 artifact id。
  • QA 结论能区分观察事实和主观判断。
