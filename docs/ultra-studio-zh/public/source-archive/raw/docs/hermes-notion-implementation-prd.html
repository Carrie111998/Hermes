Hermes Notion Implementation PRD

把 Notion Hermes 设计落成 Ultra Studio Agent 的产品需求文档

这份 PRD 把 Notion 页面中的 Hermes、Skill、Prompt、Prompt enhance、Sandbox、TokenRouter、CometAPI、Soul ID、Element 和工具合约拆成可实现的产品模块。目标是指导当前 Hermes fork 做成 Atlas-first 创作型 Agent，而不是复刻外部系统的隐藏内部实现。

日期：2026-06-10 输入源：Notion Hermes 页面 + 本地同步文档 输出：HTML PRD 产品方向：Ultra Studio Agent
一页结论
要实现 Notion 里的 Hermes 设计，不能只做一个媒体生成插件。需要做一个分层产品：真实聊天 Agent、窄 Skill catalog、受保护 Skill references、结构化 Prompt 编译、Atlas 媒体工具、异步 job、项目资产库、TokenRouter 凭证边界、Sandbox 执行边界、审计与可观测性。

1. 背景与问题

当前 Hermes fork 已经具备 Atlas 图片/视频 provider、真实聊天面板雏形、基础 Skill 机制和 Ultra Studio 方向文档。但 Notion 中的目标系统不是“用户一句话 -> 直接调用模型”的简单链路，而是围绕 Skill、Reference、Prompt compiler、资产复用和安全边界构建的生产型 Agent。

用户侧问题

用户想在网页聊天里上传素材、让 Agent 判断该用哪个视频流程、生成真实图片/视频，并在后续任务里复用角色、产品、场景和历史结果。

Agent 侧问题

Agent 不能看到 87 个无关 Skill，也不能在没理解任务时直接生成。它需要 router、workflow Skill、QA 和 repair 机制。

平台侧问题

API key、资产权限、模型限额、生成 job、上传文件和内部 references 必须隔离，否则会出现串租户、泄露或假成功。

2. 目标与非目标

类别内容
产品目标 把 Hermes fork 魔改成一个 Atlas-first 创作型 Agent：网页聊天、上传素材、路由 Skill、真实生成、保存资产、复用 reference、展示 job 状态和媒体结果。
工程目标 建立清晰边界：Skill 是工作流层，工具是执行接口，Atlas provider 是模型适配层，资产服务是复用层，TokenRouter 是凭证/策略层。
安全目标 Skill 内部 references、用户上传 references、媒体生成 references 三者分离；普通用户无法导出内部 references；provider key 不进入沙箱或前端。
非目标 不照搬 Higgsfield 内部命名作为公开 API；不承诺复现外部系统隐藏模型效果；不做 fake demo；不把 CometAPI 长视频数据面放进第一阶段必做。

3. 证据来源与设计边界

来源可用结论实现处理
Notion 根页面 Hermes References 至少有三类含义；Hermes、Sandbox、TokenRouter、媒体后端边界不同。 进入架构边界和权限设计，不把所有 reference 混成一个字段。
Notion Skill / skill_view Skill 是路由、输入门槛、阶段编排和冷层资料加载，不是简单 prompt。 保留 `SKILL.md` + `references/` progressive disclosure；新增视频相关 skill。
Notion Prompt / Communication / Security 输出需要简洁、隐藏内部 ID/路径；长任务要有阶段状态；失败要明确环节。 前端和 Agent 回复都要显示人可读状态，隐藏 raw job_id/provider path。
Notion Prompt enhance Enhancer 是 prompt compiler 边界，根据 flow、inputs、image_refs 生成模型 prompt。 本地设计 `ultra_prompt_compile`，把 workflow plan 编译成 Atlas payload。
Notion Soul ID / Element 身份、角色、道具、场景应是持久化语义资产。 本地实现为 project asset references；底层训练可先 pending/unavailable，不假装支持。
Notion TokenRouter / CometAPI 控制面和媒体数据面要分离。 第一阶段做 TokenRouter-style policy/credential boundary；CometAPI 作为后续长视频/多模态预处理网关。

Notion API 于 2026-06-10 可访问根页面，页面当前包含 `Skill`、`Prompt`、`Sandbox`、`Prompt enhance`、`名次定义` 等新增子页。本 PRD 将这些作为设计线索，不把其中对外部平台内部实现的推断当成已验证事实。

4. 用户画像与核心场景

用户目标关键场景
创作者 / 运营 快速生成图片、短视频、广告素材和 motion design。 上传产品图或参考图，通过聊天生成视频，结果可预览、下载、复用。
品牌 / 内容团队 保持角色、产品、风格、Logo 和场景一致。 把生成结果保存为 Element 或参考资产，在下一条视频中复用。
Agent power user 使用真实 Hermes runtime，而不是静态 demo。 可以看到流式聊天、工具状态、Skill 路由、错误、历史会话和资产库。
平台 operator 验证生成链路可审计、可计费、可隔离。 从一次生成追踪到 session、run、tool call、TokenRouter decision、worker log、usage event。

5. 端到端用户流程

用户进入网页
  -> 新建或恢复 Creative Session
  -> 输入需求 / 上传图片视频
  -> workflow-router 判断 intent、asset roles、workflow_skill、missing fields
  -> 必要时只问一个关键问题
  -> 加载对应 Skill: infographic-md-flow / product / UGC / cinematic / repair / QA
  -> 结构化 plan + prompt compile
  -> 创建 Atlas media job
  -> UI 流式显示 thinking / routing / uploading / queued / rendering / finalizing
  -> 展示图片或视频结果
  -> 用户保存为 Element / 下载 / 继续迭代 / 复用为 reference

6. 功能需求

6.1 Web Chat 与 Live Panel

需求说明验收
真实聊天接入 网页不是 hardcoded demo；输入必须进入真实 Hermes Agent/gateway 会话。 问“你是什么模型”不会触发生成；普通聊天正常回复；生成请求才调用工具。
流式状态 至少支持 thinking、routing、uploading、planning、queued、creating、rendering、finalizing、complete、failed。 长任务期间页面不卡死；状态不只显示 working。
媒体展示 Assistant 返回 markdown 图片/视频链接时，前端要渲染成真实媒体卡片。 生成猫图能在前端显示图片；生成视频能播放或下载。
历史记录 左侧保留会话列表、标题、最近消息、状态、入口来源。 刷新页面后历史不丢；可点击恢复。
模型切换 输入区提供模型选择，但不占据过宽空间，不显示无意义 transport/session debug 卡。 用户可选可用模型；不可用模型给明确错误。

6.2 Upload / Attached References

需求说明验收
上传入口 Composer 左侧上传按钮支持 image/video/audio/PDF；上传后出现缩略卡。 用户能上传图片并在同一条 prompt 中引用它。
资产角色识别 上传素材被 router 分类为 foundation、logo、style_reference、source_video、ignore。 多图上传时，Agent 不会把 Logo 当作产品图或把 style ref 当 source。
安全引用 Agent 只看到受控 media id/URL，不暴露本地路径或对象存储内部 key。 回复中不出现本地绝对路径或内部 bucket key。

6.3 Skill Catalog 与 Workflow Routing

需求说明验收
窄目录 默认可见 Skill 只保留 Ultra Studio 相关：workflow-router、infographic-md-flow、media-qa、prompt-repair，后续再加 product/UGC/cinematic。 用户说“我要做视频”不会加载 ascii-video、comfyui、manim-video、youtube-content 等无关 skill。
Router 先行 所有媒体请求先经过 router，输出 intent、workflow_skill、missing、asset_roles、handoff。 没有明确需求时只问关键问题，不自动开始生成。
Skill 分层 SKILL.md 保存触发、流程、约束；复杂 schema、prompt compiler 输入、QA rubric 放 references。 主 prompt 不膨胀；深层资料只在需要步骤加载。

6.4 Prompt Compile / Enhance

需求说明验收
结构化输入 Agent 先生成 plan/shot/storyboard/asset roles，再交给 compiler 生成 Atlas prompt。 prompt compile 输入可审计，不是纯自然语言堆砌。
Flow 枚举 本地先支持 image-direct、video-direct、image-to-video、infographic-board、infographic-clip、repair。 未知 flow 返回 schema error，不静默 fallback。
Provider-aware Atlas 当前 video 不承诺多 reference conditioning；compiler 必须根据 model_catalog 限制裁剪输入。 多参考图时，系统会要求选择主 source 或说明只使用一个 image_url。

6.5 Media Job 与 Atlas Tool Layer

工具职责MVP 验收
ultra_asset_upload注册上传文件并返回 typed asset ref。上传图片后可作为 image-to-video source。
ultra_asset_list列出当前 project/session 可复用素材。只能看到有权限资产。
ultra_model_catalog返回 Atlas image/video 模型、输入限制、支持能力。前端模型选择和 router 使用同一目录。
ultra_prompt_compile把 workflow plan 编译成 provider payload。输出 schema 可测试。
ultra_media_job_create创建异步生成 job，内部调用 image/video provider。返回真实 job 状态，不 fake URL。
ultra_media_job_status轮询或订阅 job 状态。UI 能显示 queued/running/failed/completed。
ultra_media_asset_download把远端结果落到 project storage。生成结果可下载和复用。

6.6 Asset References: Soul ID / Element / Media

资产类型产品含义MVP 做法
media_input用户上传素材。完整支持上传、预览、引用、删除。
image_job / video_job生成结果引用。完整支持列表、预览、下载、reuse as reference。
element角色、道具、环境、产品等可复用语义资产。支持从上传或生成结果保存，状态 completed。
soul_id身份一致性资产。首版支持 create/status/list 的状态模型；无真实训练 provider 时返回 unavailable，不假装训练完成。

6.7 Security / TokenRouter / Sandbox

边界需求验收
Provider key API key 只在服务端或 vault；前端、sandbox、Agent prompt 都不能拿到。 日志、环境变量、上传文件中搜不到 provider key。
Asset ACL 任何 asset id 使用前都查 tenant/workspace/project/permission/status。 Tenant A 不能通过 prompt 注入 Tenant B 的 asset id。
Skill confidentiality 用户可见 metadata；内部 references 不可 bulk export。 通过 chat/file/terminal/export 索要 references 会被拒绝。
Sandbox egress 执行环境不能直接访问任意外网或 provider；需要受控 upload/tool channel。 沙箱内无真实外部 key；外传文件必须通过 artifact/upload gate。
Audit 所有生成、资产读取、reference 读取、TokenRouter decision 需要追踪。 失败 job 可回溯到 run、tool call、policy reason、worker log。

7. 信息架构与 UI 设计

区域设计要求不合理设计要避免
左侧导航 品牌区、New Session、历史记录、资产库入口、设置入口。品牌文案不溢出。 不要显示 transport/model/session debug 卡；不要让标题挤到主区域。
主聊天区 真实 message stream、媒体卡片、状态阶段、错误卡、question prompt。 不要未输入就自动生成；不要把工具 trace 当 assistant 正文。
Composer 上传按钮、文本输入、发送、紧凑模型选择；输入不卡顿。 不要让模型选择框横跨整个宽度；不要输入一长串时 re-render 全页面。
右侧 Inspector 当前 job、选中资产、生成参数、QA 分数、下载/复用动作。 不要显示空 Run 面板；空状态应收起或显示有用 CTA。
Asset Picker 按 upload、image、video、element、soul_id 分类；支持选择 source/logo/style ref。 不要让用户复制粘贴 asset id。

9.3 错误枚举

错误用户可见说明系统行为
provider_not_configured当前媒体 provider 未配置。停止，不重试，不切到 FAL 或 fake provider。
unsupported_capability当前模型不支持该输入模式。返回可选替代路径。
asset_not_authorized你无权使用该资产。拒绝生成并记录审计。
asset_not_ready该资产还在处理或训练中。展示状态，不生成。
quota_exceeded当前额度不足或并发已满。不调用 provider。
provider_failed生成服务返回错误。保留内部错误分类，用户看到脱敏说明。

11. 里程碑

阶段目标完成标准
M0: PRD 与边界冻结 完成本文档、确认 Notion 概念映射、本地命名、MVP 非目标。 团队确认不做 fake demo、不直接暴露外部 provider 命名、不把 CometAPI 放进首版必做。
M1: 窄 Skill Catalog 默认隐藏无关 Skill，保留 Ultra Studio catalog。 `skills_list` 只展示视频相关 Skill；“我要做视频”不会加载无关技能。
M2: 真实网页聊天 + 上传 聊天接入真实 Hermes，会话历史可恢复，支持上传和媒体渲染。 生成猫图能真实显示；上传图可作为 image-to-video source。
M3: Media Job Layer 新增 ultra media tools，封装 Atlas job、状态和资产落库。 job 状态流可见，失败有 typed error，结果可下载复用。
M4: Asset References Element/media_input/image_job/video_job 可创建、列表、复用；Soul ID 状态模型接入。 资产 picker 可选，权限和 not-ready 错误可见。
M5: Prompt Compile 把 workflow plan 编译成 provider-aware prompt payload。 infographic / direct video / repair 至少三条 flow 可测试。
M6: TokenRouter-style Boundary provider key 隔离、quota、asset ACL、audit。 沙箱无 key；跨租户 asset id 被拒绝；失败可追踪。

12. 验收清单

聊天行为
  • 普通问答不会触发生成。
  • 媒体请求先 route，再生成或澄清。
  • 流式状态不阻塞输入。
媒体结果
  • 图片在前端直接显示。
  • 视频可播放、下载、保存为资产。
  • provider 未配置时有 typed error。
Skill
  • 无关 Skill 默认隐藏。
  • Skill references 不能被批量导出。
  • router 输出可测试。
资产
  • 上传、生成结果、Element、Soul ID 类型分明。
  • ACL、status、lineage 生效。
  • 未授权 id 不能通过 prompt 使用。
安全
  • provider key 不进前端和沙箱。
  • 工具错误不被吞掉。
  • 所有高风险操作有审计记录。
UI
  • 品牌区不溢出。
  • 模型选择紧凑可用。
  • 空面板不显示无意义 debug。

13. 风险与开放问题

风险影响处理
Notion 中部分内容是推断或外部系统描述 误当生产事实会导致错误架构。 全部映射为本地目标设计，保留 evidence policy。
Atlas 当前模型能力限制 多参考图、Soul ID 训练、长视频分析可能无法真实支持。 通过 model_catalog 暴露能力，unsupported 明确失败。
旧 Skill 物理删除过早 破坏测试、文档或用户已有习惯。 先 disabled allowlist，再分批 archive/delete。
前端变成第二套假 chat 和 Hermes runtime 脱节。 必须接真实 gateway/agent；React 只做支持面板和媒体展示。
Prompt compile 质量不足 生成质量不稳定。 先实现可观测 schema 和 repair loop，再逐步优化 prompt 模板。
