Session / Job Orchestration

结论
Temporal 是该模块的主选型。Hermes 的媒体生成和 agent 任务不是普通队列任务：它们有长耗时、重试、超时、外部 side effect、状态流和失败恢复。Temporal 的 Durable Execution 正是这个问题域。

为什么选它

  • Hermes 的媒体生成和 agent 任务不是普通队列任务：它们有长耗时、重试、超时、外部 side effect、状态流和失败恢复。Temporal 的 Durable Execution 正是这个问题域。
  • 把工作流状态写在自研 DB + worker loop 容易产生重复执行、丢状态和重试不一致；Temporal 把这些故障语义变成平台能力。
  • Temporal 的 task queue 模型可以把 sandbox attach、GPU job、thumbnail、asset registration 拆成不同 worker pool。

候选方案对比

候选优势为什么不是主选
Celery/RQ简单，Python 生态成熟只解决任务派发，不解决长工作流状态、补偿、定时器和 determinism
Argo WorkflowsK8s 原生，适合批处理流水线交互式 session 和细粒度业务状态恢复不如 Temporal
Airflow适合数据调度不是低延迟用户交互和 per-session agent job 的最佳模型

Hermes 落地设计

  1. `SessionWorkflow`：create/resume session、sandbox schedule/attach、stream token、heartbeat、suspend。
  2. `MediaJobGroupWorkflow`：validate assets、reserve concurrency、publish work、wait worker result、register output、meter usage。
  3. 所有外部 side effect 放 Activity：TokenRouter call、object write、DB mutation、NATS publish；Activity 必须有 idempotency key。
  4. 业务 Postgres 存查询模型；Temporal history 存工作流真实执行历史，二者不能互相替代。

实施规划

  1. MVP：media job group 和 sandbox attach 两条 workflow。
  2. 第二阶段：跨 worker pool retries、compensation、manual intervention。
  3. 第三阶段：workflow replay tests、versioning strategy、multi-region failover 设计。

验收标准

  • Worker crash 后 job 不丢失，并从上一个已提交 activity 后恢复。
  • 重复 delivery 不会重复计费或覆盖错误 output_prefix。
  • 超过 timeout 的 job 被标记失败并返回 sanitized error。
