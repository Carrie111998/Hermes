结论
OpenTelemetry + Grafana LGTM stack 是该模块的主选型。Hermes 的故障排查横跨 Edge、Session、Sandbox、TokenRouter、Temporal、NATS、GPU worker、object storage。OpenTelemetry 是跨语言、跨后端的最低耦合采集标准。

为什么选它

  • Hermes 的故障排查横跨 Edge、Session、Sandbox、TokenRouter、Temporal、NATS、GPU worker、object storage。OpenTelemetry 是跨语言、跨后端的最低耦合采集标准。
  • Grafana LGTM 组合覆盖 metrics、logs、traces 和 dashboard，开源可自托管，适合早期先跑通。
  • 审计不能只依赖普通日志：普通日志可以采样/过期，audit_events 必须可查询、可保留、可导出。

候选优势为什么不是主选

Datadog/New Relic托管体验好不是开源优先，且租户/提示/文件相关数据要额外合规治理

Hermes 落地设计

  1. 所有服务 trace span 必须带 `tenant_id`、`workspace_id`、`project_id`、`session_id`、`run_id`、`tool_call_id` 或明确标记 global。
  2. 日志默认结构化 JSON，敏感字段在 SDK 层 redaction；禁止把 prompt 原文、provider key、protected skill content 写进普通日志。
  3. 审计事件写 Postgres/对象归档，不通过 Loki 作为唯一事实；Loki 只做运维日志。
  4. 建立 dashboard：sandbox cold start、TokenRouter deny、job duration、GPU utilization、queue depth、per-tenant spend。

实施规划

  1. MVP：OTel SDK + Collector + Prometheus/Grafana + structured logs。
  2. 第二阶段：Tempo traces、Loki logs、exemplars linking、tenant cost dashboards。
  3. 第三阶段：audit export、SLO burn alerts、redaction regression tests。

验收标准

  • 任意 failed media job 可从 job_id 追到 TokenRouter decision 和 worker log。
  • 日志扫描不能发现 provider key 或 protected skill path 内容。
  • 每次 tool_call touching infrastructure 都有 audit_events 记录。
