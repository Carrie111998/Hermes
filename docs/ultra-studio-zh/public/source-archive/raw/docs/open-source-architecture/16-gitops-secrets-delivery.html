总览上一项
结论
Argo CD + External Secrets Operator 是该模块的主选型。Hermes 组件多、命名空间多、node pool 多，手工 kubectl 会迅速失控。Argo CD 用 Git 作为 desired state，并持续对比 live state。

为什么选它

  • Hermes 组件多、命名空间多、node pool 多，手工 kubectl 会迅速失控。Argo CD 用 Git 作为 desired state，并持续对比 live state。
  • External Secrets Operator 把 OpenBao/secret backend 的值同步成 Kubernetes Secret，避免把明文 secret 放进 Git。
  • Flux 也可行，但 Argo CD 的 UI、diff、sync wave 和多应用可视化更适合早期团队协作审阅。

候选方案对比

候选优势为什么不是主选
Flux CDGitOps 纯粹、轻量可视化和产品化审阅体验不如 Argo CD 直接
Helm-only/manual deploy简单不能持续检测漂移，审计和回滚弱
Terraform for all Kubernetes resources基础设施强应用持续交付和 runtime drift 管理不如 GitOps controller

Hermes 落地设计

  1. 仓库分层：`infra/base`、`infra/envs/prod`、`apps/control-plane`、`apps/data-plane`、`policy-bundles`。
  2. Argo CD sync wave：CRD/operator -> storage/secrets -> mesh/gateway -> control plane -> workers -> dashboards。
  3. External Secrets 只同步运行时需要的最小 secrets；TokenRouter provider key 尽量不落成普通 K8s Secret，而由 TokenRouter runtime 从 OpenBao 拉取。
  4. 高风险变更如 OPA policy、TokenRouter deployment、sandbox RuntimeClass 需要人工 review gate。

实施规划

  1. MVP：Argo CD 管理 dev/staging，ESO 同步非 provider master secret。
  2. 第二阶段：prod sync windows、manual approval、image updater 或 promotion PR。
  3. 第三阶段：drift alert、policy-as-code CI、disaster recovery bootstrap runbook。

验收标准

  • 集群 live state 漂移会在 Argo CD 显示 OutOfSync。
  • Git 仓库不包含明文 secret。
  • 删除 ExternalSecret 后相关服务不会继续拿到过期高权限凭证。
