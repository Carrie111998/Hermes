Hermes 资产库 Go 后端设计

资产库后端是上传素材和生成结果的唯一状态源。上传、生成、复用、下载、加入合集、撤销删除都进入 Go 服务 assetd，并产出稳定 asset_id、对象存储、lineage、prompt 上下文、权限和审计记录。

第一版目标不是图库，也不是前端静态状态；它要跑通真实链路：上传或生成请求进入 Go Asset Service，落 MySQL/GORM、Redis 和阿里云 OSS，形成可被 Chat 和 Asset Library 复用的 typed asset。

架构选择

采用独立 Go 服务 assetd。登录、account、member、RBAC 以 KubeDL Console 后端为权威源；Dashboard/Gateway 通过签名身份桥代理资产 API 到 Go 服务。

Go assetd

Asset Service、MediaJob、Object Store、Search、ACL、Audit。

权限边界

KubeDL 是身份源；assetd 是资产 read/use/delete/revoke 的资源权限源。

P0 存储

MySQL/GORM + Redis + OSS media/result/temp buckets，直接对齐 aiproxy 的存储形态。

P2 迁移

多库拆分、vector index、durable worker；P0 存储基线保持 MySQL/Redis/OSS。

包职责
cmd/assetdcomposition root：读配置、建 DB、建 HTTP server、启动 worker、优雅关闭。
internal/domainAsset、MediaJob、Collection、SmartGroup、Reference、状态机、typed errors。无 DB/HTTP/provider。
internal/app上传、资产查询、合集、智能分组、mention、media job、引用创建。拥有事务边界。
internal/httpapiHTTP handler、JSON DTO、错误码映射。不能直接 SQL 或 provider。
internal/provider/atlasAtlas 请求、轮询、输出解析。provider 字段不泄露到公开 API。
internal/eventsoutbox、SSE/代理事件、事件序列化。
Go 规则：context.Context 只作为参数传递；handler 只做 transport 翻译；goroutine 必须有 owner、取消和 shutdown；接口定义在消费者侧。

核心模型

Asset

media_inputimage_jobvideo_jobelementcharacter

核心字段：asset_id、project、type、media_type、status、prompt、endpoint、model_route、object_key、thumbnail_key、owner、timestamps。

MediaJob

createdqueuedrunningsucceededfailed

provider submit 前先落库；只有真实输出落 object store 且 output asset 已创建，才能进入 succeeded。

Collection

静态成员表：collections + collection_members。删除合集不删除资产。

Smart Group

保存 query_json，打开时动态评估，不物化成员。无 embedding 时返回 semantic_pending。

数据库与对象存储

MySQL: asset_library primary DB, GORM
Redis: cache / distributed lock / active job set
OSS media bucket: upload source media
OSS result bucket: generated outputs and thumbnails
OSS temp bucket: transient provider transfer objects
MySQL

assets、media_jobs、collections、lineage、audit、outbox 等权威状态；GORM 管 migration 和事务。

Redis

缓存、分布式锁、active job set，对 sweeper/poller 做单实例推进保护。

OSS

media bucket 存上传，result bucket 存输出和缩略图，temp bucket 存 provider 中转。

MediaJob 生成流程

Validate

校验 input asset 的 use 权限和 ready 状态。

Create

插入 media_jobs(status=created)，记录 prompt、params、input refs。

Submit

Atlas adapter 提交请求，保存 provider job id。

Poll

worker 轮询状态；status/prediction URL 不能当输出。

Finalize

输出落 OSS result bucket，创建 output asset 和 lineage；只能由 worker 内部触发。

任意 ref 不合法则整体失败；prompt text 只给模型理解，不作为权限凭证。

KubeDL 身份桥、权限、审计

身份桥

KubeDL 校验 JWT/cookie、account member、RBAC 后，向 assetd 注入签名 account/user header。

资产权限

readuseupdatedeleterevoke

审计

asset.uploaded、asset.used、asset.downloaded、asset.revoked、media_job.succeeded。生成动作再进入 aiproxy 计费链路。

不允许 warning 后继续生成。输入 ref 有任何错误，必须在 provider submit 前 fail closed。

P0 / P1 / P2 路线

优先级工作完成标准
P0Go module + assetd HTTP server本地可启动，health check 可用。
P0MySQL/GORM + Redis + OSS资产、job、collection、上传和生成输出都有真实持久化。
P0Upload / Asset / Collection / Mention API上传返回 asset_id，Chat 可拿 structured ref。
P0MediaJob + Atlas adapterfake provider 成功创建 output asset。
P1Smart Group、Element/Character、FTS keywordspreview/save/evaluate 一致，ready 状态只来自真实完成。
P2多库拆分 / vector / durable worker通过同一 contract tests，job 可跨重启恢复。
