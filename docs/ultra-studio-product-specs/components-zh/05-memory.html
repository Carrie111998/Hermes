05 记忆系统

保存项目偏好、品牌设定、角色设定、用户选择和长期上下文。它要能被 agent 使用，也要能被用户审计。

部分实现 Memory 阅读版 HTML
状态说明：部分实现：有真实底座，但产品合同还没完整接上。 本页是中文阅读版，英文 Markdown 仍是更细的审计原文。

已有实现证据

  • 已有 MemoryStore、memory tool、provider 插件、prompt injection 和多 provider 架构。
  • 已有 honcho、mem0、supermemory 等 memory provider 插件。
  • 代码证据：agent/memory*、tools/memory*、plugins/memory/*。

主要缺口

  • 没有 Ultra Memory 页面。
  • 没有项目记忆、创作偏好、角色记忆的清晰 UI 分层。
  • 没有 memory citation 在生成结果和会话中的一致展示。

P0 要做

  • Memory 导航页至少能显示当前 memory 是否启用、provider、最近条目或空态。
  • 生成时用到的 memory 需要能在结果上看到引用线索。
  • 用户可以禁用某条错误记忆或关闭本会话 memory 注入。

P1 / P2 后续

  • 品牌记忆、角色记忆、项目记忆、团队记忆的独立命名空间。
  • Memory diff、回滚、审核和过期策略。

验收点

  • Memory 关闭时 agent 不应声称读取了长期记忆。
  • Memory provider 错误要明确暴露。
  • 错误记忆可被用户定位和移除。
