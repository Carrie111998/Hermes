15 人工审批网关

对高风险动作、付费调用、删除、外发、重试消耗等操作做明确审批。要可恢复、可审计。

部分实现 Human Approval Gateway 阅读版 HTML
状态说明：部分实现：有真实底座，但产品合同还没完整接上。 本页是中文阅读版，英文 Markdown 仍是更细的审计原文。

已有实现证据

  • 已有 approval 和 clarify 机制，chat UI 有 pending prompt cards。
  • 已有 sudo/secret prompt 相关 UI。
  • 代码证据：tools/clarify_tool.py、PendingPromptPanel.tsx、tui_gateway/server.py。

主要缺口

  • 当前审批偏内存态，刷新后不稳定。
  • spec 的 approve/edit/reject/respond 与代码的 once/session/deny 不一致。
  • 没有 durable decision record 和审批作用域。

P0 要做

  • 生成前如有高成本或破坏性动作，显示明确审批卡。
  • 审批决定写入 session/job record。
  • 刷新后 pending approval 可恢复或明确过期。

P1 / P2 后续

  • 团队审批、预算审批、policy-based auto approve、审计导出。
  • 编辑参数后再批准。

验收点

  • 未经批准不会删除资产或消耗高成本任务。
  • 审批失败/过期有明确提示。
  • 每个 approval 能追踪到触发工具和用户选择。
