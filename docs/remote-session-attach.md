# Remote Session Attach

Hermes can **live-attach to sessions running on another Hermes instance** over
a private network (VPN, SSH tunnel, LAN). A desktop client or CLI watches and
drives the host's running sessions in real time — no SSH into the host, no
profile copy, no OAuth setup.

This complements the static profile distribution (`hermes profile install`):
profiles copy *configuration*, remote attach streams *live work*.

## Concepts

- **Host** — the Hermes instance whose sessions are being watched. It runs the
  API server (`platforms.api_server`, default port `8642`) with remote attach
  enabled (set `API_SERVER_KEY`; the host generates pairing codes with it).
- **Client** — the Hermes Desktop app or CLI that attaches to the host.
- **Pairing code** — a 6-character, single-use code generated by the host,
  valid 10 minutes. Redeeming it yields a **24-hour scoped attach token**
  (Bearer, scope `remote`). The static `API_SERVER_KEY` is accepted as a
  fallback wherever an attach token is.
- **Attach token** — a 24h Bearer token, scoped to `/api/remote/*` only. It
  cannot touch any other API surface.
- **Live-only** — the client streams live events and writes nothing locally.
  The session stays authoritative on the host; history is available via
  `/api/sessions/{id}/messages`.

## CLI usage

```bash
# On the host: generate a 6-character pairing code (valid 10 min, one use)
hermes remote pair

# On the client: pair with the host (host[:port], default port 8642)
hermes remote attach <host> --code XXXXXX

# On the client: list the host's running sessions
hermes remote sessions

# Optional: name the saved connection and target it later
hermes remote attach <host> --code XXXXXX --name lab
hermes remote sessions lab
```

The attach token is saved in `config.yaml` under `remote.connections.<name>`
(`host`, `port`, `token`, `expires_at`). An expired or invalid token produces a
clear error telling you to re-pair.

## Desktop usage

1. Open the **Remote sessions** view (sidebar → Remote, route `/remote`).
2. If no saved connection: enter host, port (default `8642`) and the 6-character
   pairing code, then **Connect**.
3. Connected view lists the host's sessions (id, title, status, updated time)
   with **Refresh**. Choose **Attach** on a session to stream it live.
4. The attached view shows the live event log (`session.message`,
   `session.tool_call`, `session.status`) and a composer to send input to the
   session (`Enter` to send).
5. The connection (host/port/token/expiry) persists across restarts and
   auto-reconnects while the token is valid. A dropped stream retries up to
   3 times (500 ms / 1.5 s / 4 s backoff) before surfacing an error. If the
   remote session ends, the view auto-detaches with a message.
6. **Disconnect** clears the saved token and stops streaming.

## Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `POST` | `/api/remote/pair/code` | `API_SERVER_KEY` | Generate a 6-char single-use code (10 min) |
| `POST` | `/api/remote/pair` | none (the code is the credential) | Redeem a code for a 24h scoped token |
| `GET` | `/api/remote/sessions` | attach token or key | List open sessions + hostname/profile |
| `GET` | `/api/remote/sessions/{id}/events` | attach token or key | SSE stream: `session.message`, `session.tool_call`, `session.status` |
| `POST` | `/api/remote/sessions/{id}/chat` | attach token or key | Send a message to a session |

Notes:

- `POST /api/remote/pair` needs **no** static key — the pairing code itself is
  the credential (a remote client only possesses the code). Brute-force
  protection comes from the failure rate limit.
- `POST /api/remote/sessions/{id}/chat` routes through the same agent
  admission path as `/api/sessions/{id}/chat` (shutdown draining works), but
  authenticates with the remote attach token.
- SSE events are redacted **server-side** before broadcast
  (`redact_sensitive_text`, force mode) so secrets never leave the host.
  The Desktop client additionally redacts defensively before rendering.

## Security model

- **Short-lived codes**: 6 chars, 10 min, single use. Redeeming a code mints a
  24h token; five consecutive failures invalidate the code.
- **Scoped tokens**: attach tokens carry `scope: "remote"` and expire after
  24h; expired tokens are pruned and rejected.
- **Transport (TLS)**: the attach channel is plain **HTTP** (SSE over the
  loopback listener, default port `8642`) unless you configure the host with a
  TLS-terminating reverse-proxy and point the client at an `https://` URL.
  **Never expose the host's API port to the public internet over plain HTTP**
  — a bearer token sent in clear text over public transport lets anyone who
  sniffs the link replay it. Mount the channel over the private network
  (Tailscale, WireGuard, LAN) or a TLS proxy. In practice the designed
  threat model is: private network transport + short-lived scoped token.
- **Token at rest (CLI)**: the CLI saves the attach token in `config.yaml`
  under `remote.connections.<name>` (see above). If the client machine is
  multi-user or untrusted, protect `config.yaml` so other local users can't
  read the token.
- **Token at rest (Desktop)**: the Desktop client persists the connection
  (host/port/token/expiry) in Electron's `localStorage`
  (`hermes.desktop.remote-attach`). `localStorage` is **not** encrypted,
  so a local XSS or same-machine malware that reads the renderer's storage
  could recover the token until it expires. Mitigations that bound this:
  the token is scoped to `/api/remote/*` only (it cannot touch any other API
  surface), it expires after 24h, and a 401 clears it immediately. For
  higher-assurance environments, prefer the CLI (config file with `chmod`)
  or back the Desktop connection with OS-keychain storage when your runtime
  exposes a `secureTokenStorage` bridge (`safeStorage`).
- **No new surface**: reuses the existing API server (loopback listener by
  default), the existing session store, and the existing redaction utilities.
- **No new env vars**: configuration stays in `config.yaml` / platform config.

## Non-goals (v1)

- No local session mirroring on the client (streaming is live-only).
- No new wire protocol — plain HTTP/SSE over the existing API server.
- No changes to plugins or the core model tool schema.

## Implementation notes

- Server: `gateway/platforms/api_server.py` (`_handle_remote_*` handlers,
  `_check_remote_auth`, subscriber registry per session id).
- CLI: `hermes_cli/subcommands/remote.py` (`pair`, `attach`, `sessions`).
- Desktop store: `apps/desktop/src/store/remote-session.ts`.
- Desktop UI: `apps/desktop/src/app/remote/`.
- Tests: `tests/gateway/test_api_server_remote.py` (unit),
  `tests/gateway/test_api_server_remote_e2e.py` (real HTTP/SSE on an ephemeral
  port), `tests/hermes_cli/test_remote.py`, desktop store/UI tests.
