# 会话守卫 v1.0

## 组件架构

```
┌─ 桌面左下角 ────────────────────────────────────┐
│  ▓▓▓▓▓▓▓▓▓▓▓▓  15% 1/3   ← 三段渐变色进度条      │
│  蓝(未压缩) → 黄(1次后) → 红(2次后，≥80%脉冲)   │
└──────────────────────────────────────────────────┘
          ▲
          │ 桌面插件 plugin.js → RPC 查询 session 状态
          │
┌─ 对话内 ────────────────────────────────────────┐
│  🔴 [会话守卫强制提醒] ...  ← 第 3 次压缩注入    │
└──────────────────────────────────────────────────┘
          ▲
          │ SessionGuardEngine (Python 插件)
```

**桌面进度条**：Hermes 左下角始终显示 `X% N/3`。百分比是 token 用量，N/3 是当前巡逻轮次。
- 🔵 蓝色期（0 次压缩）：正常监测
- 🟡 黄色期（1 次压缩后）：百分比归零重新监测
- 🔴 红色期（2 次压缩后）：百分比 ≥80% 时脉冲警告

**对话提醒**：第 3 次压缩时引擎在对话中注入强制提醒消息。之后每次压缩都重复提醒。

## 桌面进度条使用说明

- **开启**：Settings → Plugins → 找到"会话守卫" → 打开开关
- **关闭**：同上，关闭开关即可
- **进度条位置**：桌面左下角状态栏
- **悬停提示**：鼠标悬停显示 token 用量、当前阶段、压缩次数

## 触发条件

当对话中看到以下格式的消息时，会话守卫已被触发：

```
🔴 [会话守卫强制提醒 - 第 3 次压缩] 当前会话已超过建议的压缩上限...
```

**一旦看到此消息，必须在本次回复中执行以下流程，不得跳过。**

## 行为流程

### 第一步：先正常回复用户

不要因为提醒而中断正常回复。先完成用户当前问题的回答。

### 第二步：在回复末尾附加强制提醒

格式如下（严格遵循）：

```
---
> ⚠️ **会话已达压缩上限（第 N 次压缩）**
> 早期对话细节可能已被压缩丢失。建议立即执行以下操作：
> 1. 输入「总结」生成当前进度总结
> 2. 将总结内容复制到新会话
> 3. 执行 `/clear` 新建会话继续工作
```

### 第三步：引导新建会话

总结生成完毕后，告诉用户：

> ✅ 总结完毕。执行 `/clear` 即可新建会话，然后把总结内容粘贴给新会话继续工作。

## 注意事项

1. **这是强制提醒** — 不要询问用户是否同意，直接建议执行总结和新建会话。
2. **提醒只在末尾** — 不要插在回复中间打断用户阅读。
3. **如果用户在忙** — 用户正在紧张调试或连续操作时，完成当前任务后再提醒。
4. **新会话后** — 用户新建会话（/clear）后，压缩计数器自动归零。
5. **每次压缩都提醒** — 第 3 次及之后的每次自动压缩都会触发提醒，不要因为之前提醒过就跳过。
