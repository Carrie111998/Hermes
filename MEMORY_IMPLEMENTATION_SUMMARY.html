三、运行机制

Agent conversation
        │  tool schema 只有在 enabled=true 且 workspace_id 合法时出现
        ▼
team_memory_search(query, category)
        │
        ├─ SQLite FTS5：英文/数字 prefix + BM25
        ├─ CJK fallback：有界 LIKE，仍受 workspace/project/review/expiry 过滤
        └─ 独立 metrics.db：记录 variant、latency、result count、session/task id

Operator CLI ── add/replace/delete/migrate ──► reviewed shared_memory.db
                                             ▲
Frontend / Backend / DevOps profiles 只有显式相同 database_path + workspace_id 才共享

工具 schema 在会话创建时确定。关闭 flag 后，新 Hermes 进程不会暴露工具；不会热修改正在运行会话的工具表，因此不破坏 prompt cache 前缀和工具快照稳定性。

四、回滚方式

  1. 在相关 profile 的 config.yaml 中设置 team_memory.enabled: false，启动新 Hermes 进程。
  2. 确认新进程的工具 schema 中不存在 team_memory_search；不重建正在运行的会话，不重启无关 gateway。
  3. 如需清除 Stage 1 数据，执行 hermes team-memory uninstall --yes。这只删除当前解析到的 team-memory DB 和 metrics DB。
  4. 配置恢复前先解析 YAML，再执行 hermes dump 和插件/CLI smoke。
