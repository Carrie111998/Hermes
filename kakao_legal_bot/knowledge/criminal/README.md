# 범죄구성요건 데이터

**원본은 변호사님의 엑셀입니다.** 엑셀을 고치신 뒤 변환기를 돌리면 이 폴더의
JSONL 이 다시 만들어집니다 — JSONL 을 직접 고치지 마세요.

```bash
python -m kakao_legal_bot.app.criminal_import 형사데이터.xlsx
python -m kakao_legal_bot.app.criminal --check      # 배포 전 점검
```

    형법각론.jsonl     형법 각칙의 죄 (168개) — 각칙의 장(章)으로 분야가 잡힙니다
    특별형법.jsonl     특별형법 (65개, 20개 법률)
    학교폭력.jsonl     학폭위 조치·보호조치 — 범죄가 아니라 **행정조치**라 따로 둡니다
    별칭.json          상담자의 일상어 → 죄명 연결표 ("몰카" → 카메라등이용촬영)

`별칭.json` 은 변환할 때 JSONL 에 합쳐집니다. 새 일상어 표현을 발견하시면
여기에 한 줄 더하고 변환기를 다시 돌리시면 됩니다.

변환 규칙 — **모르는 것을 아는 척하지 않습니다**:

- 엑셀 `미수·예비` 에 조문이 있으면 처벌 근거로, "미수 없음"이면 불처벌로,
  "일반칙"·"검토"·"확인"이면 **모름(null)** — 봇이 "확인 필요"라고 답합니다.
- `법정형` 의 "…원문 확인"은 법정형이 아니라 지시문이므로 비워 두고,
  봇에게 "법정형을 인용하지 말라"고 함께 전달합니다.
- `검증등급` A → 검증완료, B·C → 미검증(답변에 "변호사 확인 필요"가 붙음).

한 줄에 죄명 하나이고, `#` 또는 `//` 로 시작하는 줄은 주석입니다.

민사와 같은 흐름입니다 — **죄명을 먼저 확정**하고, 그 죄의
**구성요건요소**를 기준으로 6하원칙 질문을 만듭니다.

## 왜 JSONL 인가

미수·예비음모·상습범·과실범 처벌 여부는 **일반론으로 답하면 안 되는**
항목입니다. 죄마다 처벌규정이 있는지가 다르고, 없으면 처벌할 수 없습니다.
그래서 이것들을 자유 서술이 아니라 **필드**로 두었습니다.

세 가지 값을 구분합니다. 이 구분이 이 파일의 핵심입니다.

| 적는 법 | 봇이 하는 말 |
|---|---|
| `{"처벌": true, "근거": "형법 제342조"}` | "처벌 (형법 제342조)" |
| `{"처벌": false, "근거": ""}` | "처벌규정 없음 → 처벌 불가" |
| `{"처벌": null}` 또는 필드 자체를 생략 | "확인 필요 — 단정하지 말 것" |

**확실하지 않으면 `null` 로 두세요.** `false` 는 "규정이 없다"는 단정입니다.
`null` 이면 봇은 처벌된다고도 안 된다고도 하지 않고 변호사 확인을 권합니다.

## 스키마

```json
{
  "죄명": "절도",
  "별칭": ["훔쳤", "가져갔", "도둑"],
  "법률": "형법",
  "조문": "제329조",
  "법정형": "6년 이하의 징역 또는 1천만원 이하의 벌금",
  "보호법익": "재물에 대한 소유권 및 점유",
  "객관적_구성요건": ["타인의 재물일 것", "절취 — 점유자의 의사에 반하여 점유를 배제하고 자기 점유로 옮길 것"],
  "주관적_구성요건": ["고의", "불법영득의사"],
  "미수": { "처벌": true, "근거": "형법 제342조" },
  "예비음모": { "처벌": false, "근거": "" },
  "상습범": { "처벌": true, "근거": "형법 제332조" },
  "과실범": { "처벌": false, "근거": "" },
  "친고죄": false,
  "반의사불벌죄": false,
  "공소시효": "7년",
  "질문항목": [
    "언제, 어디서 가져갔는지",
    "무엇을 (물건 특정 — 종류·수량·가액)",
    "그 물건을 누가 점유하고 있었는지",
    "어떻게 가져갔는지 (문을 열었는지, 잠금장치가 있었는지)",
    "돌려줄 생각이 있었는지"
  ],
  "검증": "미검증"
}
```

### 필드 설명

| 필드 | 뜻 |
|---|---|
| `죄명` | 고소장에 쓰는 정식 죄명 |
| `별칭` | 상담자가 쓰는 일상어. "훔쳤어요" → 절도 |
| `법률` · `조문` | 형법 / 특별형법 이름과 조문 |
| `객관적_구성요건` | 하나라도 빠지면 죄가 안 됩니다. **질문의 기준** |
| `주관적_구성요건` | 고의·목적·불법영득의사 등 |
| `미수` `예비음모` `상습범` `과실범` | **처벌규정이 있는지**와 근거조문. 위 3값 규칙대로 |
| `친고죄` `반의사불벌죄` | `true`/`false`, 모르면 `null`. 고소기간·처벌불원 의사가 절차를 좌우합니다 |
| `공소시효` | 기간 도과 여부를 먼저 봐야 합니다 |
| `질문항목` | 그 죄에서 반드시 물어야 할 것. 구성요건에 대응시켜 씁니다 |
| `검증` | `검증완료` / `미검증`. **미검증이면 봇이 경고를 함께 답합니다** |

## 채우실 때

- **조문 번호가 확실한 것만** `검증완료` 로 표시해 주세요. 나머지는 `미검증`
  으로 두시면 봇이 답변에 "변호사 확인 필요"를 붙입니다.
- 특별형법(폭력행위처벌법, 성폭력처벌법, 정보통신망법, 도로교통법,
  교통사고처리특례법, 사기·횡령의 특경법 가중 등)은 `법률` 만 다르게 적으면
  같은 스키마로 들어갑니다.
- 가중·감경 규정(누범, 특경법 이득액 기준 등)은 `질문항목` 에 "이득액이
  5억 이상인지" 같은 형태로 넣어두시면 봇이 그걸 물어봅니다.

## 확인

```bash
python -m kakao_legal_bot.app.criminal --check      # 스키마 검사 (배포 전 필수)
python -m kakao_legal_bot.app.criminal --list       # 죄명·조문 목록
python -m kakao_legal_bot.app.criminal --show 절도  # 봇이 실제로 보는 내용 그대로
python -m kakao_legal_bot.app.criminal --match "돈을 안 갚고 도망갔어요"
```

`--check` 는 JSON 오류, 죄명 중복, 조문·구성요건 누락을 잡고 미검증 항목을
세어 줍니다. 오류가 있으면 종료코드가 1이라 CI 에 그대로 걸 수 있습니다.
