# 공기계로 모아 돌리기 — 루팅 없이 (에뮬레이터 대체)

안 쓰는 실물 폰(예: 갤럭시 S25 공기계)에 듀얼번호 카카오톡을 올려 모아의
"몸"으로 쓰는 방법입니다. **루팅하지 않습니다** — 최신 갤럭시를 루팅하면
Knox 보안칩이 영구 훼손되고(0x1 표시), 삼성페이·은행앱이 막히며 보증도
날아갑니다. 그 대신 안드로이드의 공식 **알림 읽기 / 알림 답장** 기능으로
동작하는 메신저봇R을 씁니다.

```
상담자 카톡 ── 카카오 서버 ──> 공기계 카카오톡(듀얼번호 계정)
                                 │ 알림 발생
                                 ▼
                          메신저봇R + moa_phone_bridge.js
                                 │ ① 웹훅 전송(나가는 방향만)
                                 ▼
                          Railway 서버 (모아 두뇌)
                                 │ ② 답변을 큐에 적재
                                 ▼
                          브리지가 2초마다 큐를 당겨와
                          알림 답장으로 방에 전송
```

폰이 **나가는 방향으로만** 통신하므로 공유기·유심 데이터 어느 쪽이든
그대로 됩니다. 터널·포트포워딩·PC 전부 불필요합니다.

## 에뮬레이터+Iris 방식과 뭐가 다른가

| | 공기계 + 메신저봇R (이 문서) | 에뮬레이터 + Iris |
|---|---|---|
| 루팅 | 불필요 | 필요 |
| PC 상시 가동 | 불필요 (폰만 충전) | 필요 |
| 계정 인상 | 실물 기기라 자연스러움 | 봇 티가 남 |
| 메시지 읽기 | **알림으로만** — 알림이 꺼지면 실명 | 카톡 DB 직접 (전부 보임) |
| 사진·파일 | 내용 못 읽음 ("사진을 보냈습니다"만) | 제한적으로 가능 |
| 과거 대화 백필 | 불가 | 가능 (/query) |

1차 가동에는 이 방식이 더 간단하고 안전합니다. 서버 코드는 두 방식 모두
같은 것을 쓰므로, 나중에 에뮬레이터로 갈아타도 재배포만 하면 됩니다.

## 준비물

- 공기계 (듀얼번호 eSIM 개통 + 카카오톡 로그인·오픈프로필 연결 완료 상태)
- Railway 서버 배포 완료 (`/health` 200 — LAUNCH.md 1단계)
- 폰의 상시 인터넷 (사무실 와이파이 또는 eSIM 데이터)

## 1. 폰 쪽 기본 설정 (10분, 가장 중요)

이 방식의 눈은 **알림**입니다. 알림이 안 뜨면 모아는 장님이 됩니다.

1. **카카오톡 알림**: 설정 → 알림 → 켜기, **미리보기(내용 표시) 반드시 켜기**.
   잠금화면에도 내용 표시. 방별 알림 끄기 금지.
2. **방해금지 모드 끄기**, 무음이어도 알림 자체는 뜨게.
3. **배터리 최적화 제외**: 설정 → 배터리 → 백그라운드 사용 제한 →
   메신저봇R과 카카오톡을 "제한 없음"으로. 삼성의 "미사용 앱 절전"
   목록에서도 둘을 제외.
4. **화면 꺼짐과 무관하게 동작**하지만, Wi-Fi 절전 옵션이 있으면 끄기.
5. 이 폰에서 **봇 계정의 채팅방을 열어 읽지 마세요.** 화면에 열려 있는
   방은 알림이 안 떠서 그 메시지를 놓칩니다. 상담 내용 확인은 변호사님
   개인 폰(알림 방)과 업무 대시보드로 하시면 됩니다.

## 2. 메신저봇R 설치

1. 메신저봇R APK 설치 (플레이스토어에 없으면 공식 배포처의 최신 APK).
   설치 시 "출처를 알 수 없는 앱" 허용이 필요합니다.
2. 첫 실행 → **알림 접근 권한 허용** (설정 → 알림 → 알림 접근).
3. 앱에서 감시할 메신저로 **카카오톡** 선택.

## 3. 브리지 스크립트 넣기

1. 메신저봇R → ＋ (새 봇) → 이름 `moa` → 언어 "자바스크립트(API2)".
2. `kakao_legal_bot/relay/moa_phone_bridge.js` 내용 전체를 붙여넣기.
3. 파일 맨 위 CONFIG 세 줄을 Railway Variables 와 **똑같이**:
   ```js
   var SERVER = "https://<앱이름>.up.railway.app";
   var WEBHOOK_SECRET = "<IRIS_WEBHOOK_SECRET 값>";
   var OUTBOX_TOKEN = "<OUTBOX_TOKEN 값>";
   ```
4. 저장 → 컴파일(⟳) → 봇 전원 ON (초록색).

## 4. 서버 환경변수 (Railway)

```
IRIS_SEND_MODE=poll        # 폰이 큐를 당겨가는 방식 — 이 한 줄이 핵심
# IRIS_BASE_URL 은 비워둡니다 (폰에는 서버가 접속할 주소가 없습니다)
```

나머지는 LAUNCH.md 1단계 그대로. 저장하면 자동 재배포됩니다.

## 5. 확인 (2분)

1. 다른 폰에서 봇 계정에 "테스트"라고 보내기.
2. 공기계에 알림이 뜨고 → 몇 초 안에 답장이 그 방에 달리면 성공.
3. 안 되면 순서대로: 공기계 알림이 떴는가(1단계 문제) → 메신저봇R 로그에
   `moa:` 에러가 있는가(CONFIG 값 문제) → Railway 로그에 이벤트가
   찍히는가(주소·시크릿 문제) → `/health` 의 `outbox_queued` 가 줄지 않고
   쌓이는가(답장 전송 실패 — 알림 미리보기 꺼짐이 흔한 원인).

## 이 방식의 한계 (알고 쓰기)

- **알림이 곧 수신입니다.** 알림을 지우는 건 괜찮지만, 방을 열어 읽거나
  알림을 끄면 그 방 메시지를 놓칩니다. 카톡 앱 강제종료도 금지.
- **사진·문서 파일은 카톡으로는 내용을 못 읽습니다.** "사진을 보냈습니다"
  라는 알림 문구만 서버로 갑니다. 대신 봇이 그 순간 **전용 자료 접수
  링크**(`/u/<방토큰>`)를 자동 안내하고, 상담자가 올리면 즉시 변호사
  카톡 알림 + 실시간 방 화면(`/admin/rooms/<방>`)에서 열람됩니다.
  (`PUBLIC_BASE_URL` 이 설정되어 있어야 링크가 만들어집니다.)
- **입장 피드가 안 보일 수 있습니다.** 상담자가 방에 들어오기만 하고 말이
  없으면 알림이 없어, 환영 인사는 첫 메시지에 반응해 나갑니다.
- **재부팅 후** 메신저봇R이 자동 시작되는지 확인하세요 (앱 설정에 부팅 시
  시작 옵션). 충전기에 꽂아두고, 한 달에 한 번쯤 재부팅해 주면 좋습니다.
- **약관 위험은 동일합니다.** 알림 답장 방식이 DB 를 읽는 것보다는 온건
  하지만, 자동응답 자체가 카카오 약관과 긴장 관계인 것은 같습니다. 그래서
  본 계정이 아닌 듀얼번호 계정으로 돌리는 것입니다.
- 폰을 들고 다니셔도 됩니다 — 데이터만 끊기지 않으면. 다만 사무실에
  충전기 꽂아 두는 쪽이 배터리·수신 안정성 면에서 낫습니다.
